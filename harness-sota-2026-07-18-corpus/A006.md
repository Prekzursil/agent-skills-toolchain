# A006 — coherence audit of `rules/common/fan-out-contract.md`

Date: 2026-07-19 UTC  
Subject snapshot: `/local_disk0/codexwork/bundle` (read-only)  
Audited rule: `/local_disk0/codexwork/bundle/claude/rules/common/fan-out-contract.md`

## Executive verdict

The fan-out contract contains valuable, directly measured requirements, but it is not a coherent executable contract yet. It is a postmortem-derived checklist with three different problems:

1. **Its normative location has no defined precedence.** `AGENTS.md` ranks the user, safety, the cross-tool `AGENTS.md` contract, project governance, and third-party defaults, but never places standalone `~/.claude/rules/common/*.md` files (`claude/AGENTS.md:115-131`). Therefore, §10 does not decide whether this file outranks `CLAUDE.md`, another common rule, or a skill. Picking a winner silently would violate §10.
2. **Most of its MUSTs have no matching gate.** The wired Task/Workflow pre-hook launches monitors and registers work, but does not validate the twelve prompt fields (`claude/hooks/_dispatch/manifest.json:182-226`). The TaskCompleted/SubagentStop path checks generic completion language and extremely short output, not the contracted artifact, evidence block, word cap, inline `UNVERIFIED`, lens-specific evidence, or reviewer inputs (`agents/harness/modules.py:2054-2090`, `agents/harness/modules.py:2384-2396`). This is **almost certain (90-99%)**, because both independently wired hook paths—shared dispatcher in `settings.json` and local dispatcher manifest—were read, and neither implements those fields (`claude/settings.json:139-149`, `claude/settings.json:419-469`, `claude/hooks/_dispatch/manifest.json:182-226`).
3. **One hook actively certifies less than the rule demands.** A normal Task record always has `expected_artifact: None` (`claude/hooks/bg-registry/register.py:67-99`), and `done_marker.py` marks every synchronous Task done merely because the turn ended (`claude/hooks/bg-registry/done_marker.py:41-60`). That directly conflicts with the rule's “`Test-Path` every contracted output BEFORE reading any digest” requirement (`claude/rules/common/fan-out-contract.md:70-71`).

Behavior is correspondingly partial. The rule's own measurement says enumerated Sherman-Kent bands achieved 20/21 adoption, while bare `NATIVE-vs-BUILD` achieved only 7/21 (`fan-out-contract.md:12-15`); 51/127 `UNVERIFIED` tags were misplaced near the end (`fan-out-contract.md:17-23`); and 87% of file anchors plus 100% of URLs died at the digest boundary (`fan-out-contract.md:74-75`). Those are not edge cases: they identify exactly the fields that remain ungated.

The distilled corpus cannot independently recompute those prompt/output compliance rates. Its metadata says it contains exact aggregate counts and capped samples (`inputs/corpus.json:2-11`), but it has no fan-out-contract compliance section. It does corroborate that fan-out is heavily used—1,745 Agent calls and 876 Workflow calls (`inputs/corpus.json:119-124`, `inputs/corpus.json:9369-9373`)—and that strict structured-output enforcement is fragile: 846/3,694 errors, including 294 missing `kg_triples`/`confidence` fields (`inputs/corpus.json:8964-8992`). The corpus `hooks` section is explicitly detector-broken (`inputs/corpus.json:13260-13261`) and was treated as no data, exactly as instructed; no conclusion below uses hook-fire counts.

## Precedence finding

`AGENTS.md` §10 is explicit only for five layers (`claude/AGENTS.md:115-131`). The target is neither the `AGENTS.md` cross-tool contract nor obviously project/repo governance or a third-party skill. `rules/README.md` adds a different scheme—language-specific rules override common rules (`claude/rules/README.md:93-104`)—but does not position either kind against `AGENTS.md`, `CLAUDE.md`, hooks, or skills.

Accordingly:

- where the target conflicts with `AGENTS.md`, I apply `AGENTS.md` as the higher layer;
- where it conflicts with `CLAUDE.md`, another common rule, a hook, or a skill, §10 **does not resolve the collision**;
- a more specific rule is not silently chosen merely because it is more specific. That policy appears in `rules/README.md` only for language-specific versus common rules, not common-versus-common (`rules/README.md:93-104`).

## Consolidated resolution design

### Proposal P1 — versioned fan-out envelope

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Define:

```text
FANOUT-CONTRACT:v1
run_id, unit_id, lens_type, contract_version
artifact_root, artifact_path, output_format
preamble_hash, grounding_pack_hash, launched_at
terminal_state, artifact_bytes, artifact_hash
digest_body_words, evidence_anchors[], unverified_count
validator_state, validator_errors[]
```

The prompt linter checks presence/version/hash; the receipt validator checks the file and content. It does not require a second orchestrator runtime, vector store, durable-execution engine, trained critic, SaaS, or guardrail framework. It rides existing PreToolUse, TaskCompleted, SubagentStop, and Stop events (`settings.json:139-149`, `settings.json:419-504`). This passes the anti-overfit gate.

It is **very likely (80-90%)** to address the observed omissions because the contract's own controlled comparison says explicit prompt element presence dominated compliance (`fan-out-contract.md:3-15`). Whether every native event exposes all envelope fields is **UNVERIFIED — experiment: capture redacted sample payloads for Task/Workflow PreToolUse, SubagentStart/Stop, and TaskCompleted, then map fields before implementation**.

### Proposal P2 — one canonical receipt predicate

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** A contracted result is usable only when:

1. terminal state is `SUCCESS` or `FAILED`, never a background/job receipt;
2. declared file exists and is a regular nonempty file;
3. file parses as declared;
4. deterministic content lint passes (word bounds, evidence anchors, inline caveats, lens evidence rule);
5. artifact hash/size is recorded after validation.

This replaces `Test-Path`, one-byte “complete,” and schema-only success with one predicate. It is **almost certain (90-99%)** to prevent the already demonstrated turn-ended-without-artifact false completion because that state fails steps 2-5.

### Proposal P3 — fail soft, repair once

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Contract failure marks the unit `INVALID` and emits one typed repair request; it does not exit 2, relaunch blindly, or regenerate a valid artifact. This matches `AGENTS.md`'s inject-not-block policy for nondangerous guidance (`AGENTS.md:64-70`) and two-strikes pivot (`AGENTS.md:51-57`). It is **likely (55-80%)** to outperform a strict StructuredOutput fan-out because the corpus's 22.9% schema failure rate is high, but an A/B workflow run is required before claiming a numeric improvement.

## Alternatives considered and rejected

1. **Rely on the Markdown rule alone.** Rejected: its own data shows zero inheritance for omitted honesty fields (`fan-out-contract.md:3-15`) and current hooks do not validate it.
2. **Put every rich field in StructuredOutput.** Rejected as the primary mechanism: 846/3,694 errors and missing-field failures dominate (`corpus.json:8964-8992`). A minimal transport envelope remains appropriate.
3. **Hard-block Task/Workflow launch on any missing field.** Rejected: nondangerous guidance must inject rather than exit 2 (`AGENTS.md:64-70`), and false-positive guards are a confirmed live defect (`INPUT-known-harness-defects.md:9-82`).
4. **Create a new orchestration service/durable engine.** Rejected by the anti-overfit gate and unnecessary because all needed native events are already wired (`settings.json:139-149`, `settings.json:419-504`).
5. **Treat native tool output as the artifact.** Rejected for contracted work: the rule's 3/3 nonexistent-file digest incident (`fan-out-contract.md:70-71`) shows that an in-context claim is not a durable receipt.
6. **Choose the more specific rule silently.** Rejected because §10 explicitly requires surfacing same-level conflicts (`AGENTS.md:129-131`) and does not place standalone common rules.
