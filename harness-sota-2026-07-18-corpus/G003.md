# G003 — Blind spot: survivorship bias

## Executive verdict

The corpus is not a census of this owner's agent work. It is a high-quality census of the JSONL files that survived under one Claude Code directory at one mining pass. Three different holes must not be collapsed into one number:

1. **Recorded elsewhere but omitted from the corpus:** Codex has its own session store, and `mine.py` never reads it. At a filesystem-mtime snapshot aligned to the corpus file's write time, 1,024 Codex JSONLs / 883,467,299 bytes sat outside the miner's root. That is approximately 8.09% of the combined Claude-plus-Codex transcript-file count and 7.26% of bytes in that aligned snapshot (probe E4). This estimate is **likely (55-80%) a lower bound**, because filtering on final file mtime excludes files created before the cutoff but appended afterward; the settling experiment is to reconstruct creation time from each Codex `session_meta.timestamp` and Claude first record rather than filesystem mtime. The current Codex store contains 1,258 JSONLs / 1,027,285,417 bytes (E4), all still outside `corpus.json` by construction (E1).
2. **Prompted sessions whose transcript no longer survives:** Claude's independent prompt history names 309 session IDs. Only 133 join to a surviving top-level transcript; 176 IDs, carrying 760 prompt-history rows, do not. The detector found known-present IDs and rejected a synthetic negative control before reporting the 176 (E2). A second, mechanically independent SessionEnd-ledger join found only 18 of 915 distinct 16-character session tokens in any surviving Claude transcript and found 897 without a transcript, after its known-positive control succeeded (E3). The two populations are not safely additive because the ledger stores only a 16-character prefix and covers a different window. It is **very likely (80-90%) that material Claude session traces have been deleted, relocated, or never durably created**, because both prompt history and terminal ledger receipts independently point to session identities absent from the transcript tree. Which of deletion, relocation, or pre-transcript startup failure dominates is **UNVERIFIED; the settling experiment is a read-only inventory of historical backup/cleanup logs plus a disposable launch/crash/cleanup lifecycle test keyed by a full UUID**.
3. **Failure-heavy work omitted disproportionately:** the omitted Codex store contains 75 transcripts whose last native event is explicitly `turn_aborted`; only 962/1,258 end in `task_complete`, and 221 have some other terminal tail (E5). User-originated sessions are 413 complete, 23 explicitly aborted, and 85 other-tail out of 521; subagents are 544 complete and 48 explicitly aborted out of 725, with additional ambiguous tails (E5). Therefore the corpus excludes at least 75 explicit abort traces, not merely successful work. It is **almost certain (90-99%) that the current corpus understates interruption/abort behavior**, because its root excludes the entire store in which those native terminal markers were counted, with zero parse failures (E1, E5).

There is no defensible single percentage for “all work ever missing.” The strongest bounded answer is:

- known omitted-at-cutoff: approximately **8.09% of transcript files / 7.26% of transcript bytes** in the two provider stores measured here;
- known non-surviving Claude identities in the still-retained prompt-history window: **176/309 (56.96%) session IDs**, representing **760/5,951 (12.77%) prompt rows**;
- known explicit aborts outside the corpus now: **75/1,258 (5.96%) Codex transcript files**, including **23/521 (4.41%) user-originated** and **48/725 (6.62%) subagent-originated** files;
- confirmed abandoned branches: **zero**; candidates requiring ownership/outcome reconciliation: **9 local branches, 24 unique commits not reachable from `origin/main`, 6 ahead worktrees, and 5 dirty worktrees** in the scoped repository snapshot (E8). Treating these as abandoned would be detector overreach.

The practical conclusion is **very likely (80-90%) that the corpus's apparent reliability rates are optimistic for whole-harness reliability**, because a whole provider plus explicit aborts are omitted and non-surviving Claude identities are numerous. The magnitude of error-rate inflation is **UNVERIFIED; the settling experiment is to ingest Codex and lifecycle manifests, stratify by terminal state, then recompute tool error/retry rates for completed, aborted, crashed, and unknown cohorts separately**. It is possible that aborted work contains fewer tool calls rather than more; no direction or correction factor should be invented before that experiment.

## Scope and definitions

This unit inspected only survivorship and coverage boundaries. It did not redo the corpus's per-tool reliability analysis, verify neighboring audit claims wholesale, or modify the subject harness.

“Missing” has four meanings here:

| Class | Meaning | Can this unit count it? |
|---|---|---|
| Corpus omission | A trace exists locally but `corpus.json` did not mine it | Yes, by root and file inventory |
| Raw-store non-survival | Another durable index names a session but no transcript remains | Yes, within the index's retention window |
| In-transcript incomplete work | A transcript survives but has an abort/ambiguous tail | Yes for native explicit markers; partially for ambiguous tails |
| Zero-trace work | Process died before any history, transcript, hook, branch, or OS receipt | No; by definition no current passive detector can count it |

The last row is the irreducible blind spot. Any numeric “all work ever” estimate that includes zero-trace work without prospective write-ahead instrumentation would be fabricated.

### E6 — OS crash evidence, not a lost-work count

Windows Application event ID 1000 was queried over the available 120-day request window. The detector first found 133 application events and printed a known-present unrelated `GUBootService.exe` crash, validating access and event parsing. It then found five target-name matches in the retained log: four `codex.exe` faults on 2026-07-12 (exception `0xc0000409`) and one `codex-code-mode-host.exe` fault on 2026-07-18 (exception `0x80000003`).

It is **almost certain (90-99%) that four Codex application processes faulted**, because Windows recorded the executable path, process ID, exception, and report ID. It is only **roughly even (45-55%) that each fault destroyed unrecoverable task work**, because session files may have been flushed incrementally and the code-mode host is a component rather than necessarily the parent UI. Exact session linkage is **UNVERIFIED; the settling experiment is to correlate WER `application start time`/PID and crash time with full Codex session intervals and terminal turn IDs**.

This detector cannot see `Stop-Process`, Task Manager termination, power loss, terminal closure, OOM kills without WER, or a process killed before logger initialization. No absence claim is made for those classes. Enabling Windows process-creation/termination auditing or wrapping provider launches with an existing `longrun`-style receipt would be required prospectively.

It is **very likely (80-90%) that this stratification will materially change harness prioritization**, because explicit aborts and an entire provider are presently absent; evidence is E4-E6. ## Recommendations

### R1 — CONFIG (settings/JSON only): restore the existing Claude SessionEnd registration

Restore the already-written `hooks/session-end/end.py` registration from a reviewed current source, preserving its fail-open behavior. Do not blindly copy the whole dated settings backup. It is **almost certain (90-99%) this will restore prospective terminal receipts**, because the script exists, the historical registration points to it, and the ledger stopped when live registration disappeared (E7). Regression tests must exercise `prompt_input_exit`, `other`, `resume`, malformed stdin, and disabled mode.

### R2 — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus): add a write-ahead lifecycle manifest and reconciler

On existing SessionStart, atomically write `{provider, full_session_id, parent_id, cwd, branch, worktree, start_ts, pid}`. On terminal events, append rather than overwrite `{end_ts, native_reason, last_turn_id}`. At the next SessionStart, reconcile stale open manifests against process existence, provider transcript tails, WER events, and Git state; classify only `complete | aborted | crashed | killed-observed | stale-unknown`. It is **very likely (80-90%) this will bound future zero-trace loss**, because the start receipt is written before substantive work and uses existing lifecycle hooks; evidence is the current SessionStart registration and the demonstrated terminal-receipt gap. Crash-before-SessionStart remains outside coverage.

Do not put raw prompts or model output in this manifest. This is objective continuity metadata and belongs beside the existing event ledger, not in semantic memory.

### R3 — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus): make the corpus multi-provider and outcome-stratified

Extend the deterministic miner with an explicit source manifest for Claude top-level, Claude subagent, Codex user, Codex subagent, workflow, and ledger records. Preserve source/provider fields. For Codex, join native `task_started`/`task_complete`/`turn_aborted` by turn ID; for Claude, use lifecycle receipts plus conservative `unknown` rather than guessing from a last record. Emit denominators and parse failures for every source.

It is **almost certain (90-99%) this removes the measured provider omission**, because E1 identifies the single-root target construction and E4 identifies the omitted store. It is **likely (55-80%) that outcome stratification changes reliability rankings**, because 75 explicit abort traces and 221 ambiguous tails are currently excluded; the recomputation is the settling experiment.

### R4 — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus): reconcile Git residues without deleting them

At SessionEnd and recovery SessionStart, record branch, HEAD, dirty-file count, worktree path, upstream, PR/remote ref if locally knowable, and task/session ownership. Report branch-only commits and dirty trees as `active | delivered | superseded | salvage-candidate | unknown`. Never auto-delete a worktree or branch from this detector.

It is **very likely (80-90%) this will distinguish abandonment from active parallel work**, because E8 shows the present inventory changes within minutes and current Git facts already provide most fields. Ownership linkage is the missing discriminator. This also directly avoids repeating the unsafe inference that “unmerged” means “abandoned.”

### R5 — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus): publish a coverage contract with known-positive controls

Every corpus build should fail its *coverage report* (not the user's work) when any declared provider root is unreadable, when a known fixture session cannot be joined, when terminal-marker counts unexpectedly drop to zero, or when observed source totals differ from inventory totals. Store `source_files_seen`, `source_files_failed`, `records_bad`, `records_oversized`, `outcome_unknown`, oldest/newest timestamps, and the control IDs by provider.

It is **almost certain (90-99%) this would have caught both the Codex omission and the nonexistent outcome implementation**, because the source manifest would demand a Codex denominator and the outcome control would demand a classified known-complete and known-aborted fixture (E1, E5).

## Anti-overfit gate

All five proposals ride existing configuration, hook, event-ledger, transcript-mining, and Git buses. None introduces a second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. R2 is a small write-ahead receipt plus reconciliation, not a durable workflow engine: it observes lifecycle and preserves `unknown`; it does not schedule, retry, or resume work. R4 reports state and never manages branch lifecycle destructively.

The minimal architecture is deliberate: one provider-source manifest, one small lifecycle record, native terminal markers where available, and conservative unknowns. Adding a daemon would not recover pre-instrumentation zero-trace work and is not justified by this evidence.

## Alternatives considered and rejected

1. **Infer crashes from Claude's final JSONL record.** Rejected. A full top-level scan showed many trailing metadata types (`last-prompt`, `ai-title`, `permission-mode`, attachments), and an inspected `last-prompt` file had an `assistant/end_turn` record after it. “Last line != end_turn” is not a terminal-state detector.
2. **Treat every non-`task_complete` Codex tail as failure.** Rejected. `token_count`, message, reasoning, and tool-call records can trail valid work or represent live append state. Only native `turn_aborted` is counted as explicit abort.
3. **Add history-missing IDs and ledger-missing prefixes.** Rejected. The identifiers and retention windows differ, and ledger IDs are truncated. The two are independent corroboration, not disjoint populations.
4. **Call unmerged branches abandoned.** Rejected. The worktree/branch roster changed during this unit, tips are fresh, and some have remote refs. Ownership and terminal disposition are required.
5. **Use Windows Event 1000 as a complete kill detector.** Rejected. It sees application faults, not all process termination modes. Four `codex.exe` faults are evidence of four crash episodes, not four proven lost tasks.
6. **Report no target crashes after a text search of current debug logs.** Rejected. The first debug/log search had a valid known-present `session` control but returned zero crash-pattern files; the independent Windows event log then found five target crashes. The debug directory held only three recent files, so the zero was detector coverage, not reality.
7. **Use the first event-ledger prefix join result.** Rejected and corrected. An initial exact-prefix hashtable used the wrong assumed prefix length and returned zero known-present matches. Inspecting the hook showed `session_id[:16]`; a `StartsWith` join then found 18 controls. No absence claim uses the invalid probe.
