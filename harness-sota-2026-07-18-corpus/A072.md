## Collision register

### C1 — TypeScript formatter mandate versus project-native formatter rule

- **Artifacts and exact lines:**
  - `rules/typescript/hooks.md:14-18`: “Configure in `~/.claude/settings.json`” and “**Prettier**:
    Auto-format JS/TS files after edit.”
  - `rules/web/hooks.md:17-39`: “Prefer project-local tooling,” “use the project's existing
    formatter entrypoint,” shows `pnpm prettier`, permits `yarn`/`npm exec`, and forbids remote
    one-off execution.
- **Class:** CONTRADICTION (plus overlapping redundancy).
- **Why:** both rules apply to the same four extensions. One names Prettier as the formatter; the
  other makes the repository’s existing formatter authoritative. A Biome- or other formatter-owned
  repository cannot obey both literally. The TypeScript rule also omits the important local-tooling
  constraint.
- **Precedence:** unresolved. Both are same-level rule files and §10 supplies no language-rule versus
  web-rule tie-break.
- **Specific resolution — NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Delete the formatter bullet from the
  TypeScript hook file and make it point to one shared JS/TS hook policy: invoke the repo-owned
  formatter command when present, otherwise emit a typed `SKIPPED:no-project-formatter` result. This
  consolidation is **very likely (80-90%)** to remove divergent instructions because the overlapping
  frontmatter and contradictory formatter selection are explicit; the remaining uncertainty is how
  Claude merges same-level path rules.

### C2 — Unqualified `tsc` versus a specified repo-local typecheck command

- **Artifacts and exact lines:**

  - `rules/web/hooks.md:57-71`: matcher `Write|Edit`, command `pnpm tsc --noEmit --pretty false`.
- **Class:** REDUNDANCY with conflicting operational detail.
- **Why:** the latter specifies package manager, non-emitting mode, output mode, and tool matchers;

  restriction.
- **Specific resolution — NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Retain one rule requiring the repository’s

  never require a PATH-global bare `tsc`. This is **very likely (80-90%)** to improve determinism,
  based on the web rule already encoding repo ownership and `--noEmit`; exact command discovery is
  repository-dependent.

## Consolidated resolution design

### R1 — one JS/TS quality policy

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Replace the overlapping TypeScript and web hook
prose with one canonical policy referenced by both path scopes. It must define:

1. project-root discovery and monorepo package selection;

4. production versus test/example console policy;
5. typed `PASS|FAIL|SKIPPED|DEGRADED` receipts;
6. soft PostToolUse diagnostics consistent with AGENTS §6;
7. a >60-second route through the existing `longrun` mechanism.

This is **almost certain (90-99%)** to remove the documented same-level ambiguity, because it creates
one source of truth rather than relying on an absent precedence rule.

### R2 — one small edit-quality rider, not four independent hooks

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Extend or replace
`per-edit-check` with one project-aware rider that:

- records changed JS/TS paths;
- formats through an existing repo command when safely resolvable;
- issues immediate bounded syntax/console diagnostics;
- deduplicates project typechecks and performs them at the chosen boundary;
- emits typed receipts for missing tools, unsupported layouts, timeouts, and failures.

This is **likely (55-80%)** to be simpler and more observable than re-enabling four plugin hooks,
based on the already-consolidated dispatcher and the active per-edit registration. **UNVERIFIED — a
