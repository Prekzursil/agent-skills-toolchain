# A025 — Coherence audit of `~/.claude/rules/csharp/testing.md`

## Executive result

The 46-line C# testing rule is not a coherent executable contract. Its framework and organization advice is mostly compatible with the rest of the readable harness, but its fixed `80%+` line-coverage target conflicts with the common threshold SSOT and with repeatedly observed owner requirements for 100% line/branch coverage. Its strongest inherited requirements—test-first sequencing, unit/integration/E2E coverage, threshold verification, and proactive use of `tdd-guide`—are not mechanized for C#. The nominal C# hook rule promises `dotnet format`, `dotnet build`, and `dotnet test --no-build`, while the active settings and per-edit hook implement none of them. The one wired completion-time E2E check is JavaScript/Python-shaped, does not recognize `dotnet test` as a broad E2E runner, and depends on a Bash-result ledger writer that is absent from both active registration paths.

I found **nine reportable collisions**: one CONTRADICTION, one REDUNDANCY, four UNENFORCED, one UNRULED, and two STALE. I did not find a verified skills collision because the remote bundle contains neither `claude/skills/` nor `agents/skills/`; that required audit lane is **UNVERIFIED — the settling experiment is to run the exact skill scan in the Windows subject tree and preserve all matching `SKILL.md` files**. I do not silently interpret the missing bundle directories as “no skill collision.”

The highest-value resolution is a small consolidation, not a new testing runtime: make `.coverage-thresholds.json` the only numeric authority, make the rule describe C#-specific evidence rather than repeat common mandates, repair the existing dispatcher/ledger wire, and add C# signatures to the existing evidence hooks. This is **very likely (80-90%)**, based on the direct rule/config mismatches and the fact that all proposed enforcement rides the existing rule/hook bus, to remove the contradictions without adding orchestration complexity. The remaining uncertainty is whether repo-local CI already supplies some of the missing enforcement; the bundle does not contain those repositories.

## Collision register

### C01 — Fixed 80% target defeats the threshold SSOT

**Class:** CONTRADICTION

**Artifacts and exact text:**

- `claude/rules/csharp/testing.md:42-46`: “Target 80%+ line coverage” and run CI tests with coverage where available.
- `claude/rules/common/testing.md:23-24`: minimum coverage is per `.coverage-thresholds.json`, “100% on metaswarm; 80%+ where none is defined.”
- `claude/rules/common/testing.md:32-38`: mandatory workflow ends by verifying that SSOT, using 80% only if none exists.
- The same SSOT language is repeated in workflow/review gates at `claude/rules/common/development-workflow.md:43-48` and `claude/rules/common/code-review.md:47-57,91-99`.

**Why this collides:** A reader following the language-specific override rule at `claude/rules/README.md:93-99` can reasonably treat C#’s unconditional 80% as the C# override, thereby relaxing a defined 100% threshold. “Target” does not say “floor only when no repo threshold exists,” and it only names line coverage, while the observed governance frequently demands line and branch coverage. AGENTS §10 resolves this only when the threshold is repo governance; in a repo with no threshold, the common and C# texts are redundant defaults. In a repo with a threshold, project governance wins. Same-level wording remains incoherent and should not require a precedence calculation.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** Replace target line 44 with: “Coverage is governed only by the repository’s `.coverage-thresholds.json`; if absent, use the common 80%+ line floor. Do not weaken a defined line or branch threshold.” Delete duplicate fallback numbers from other C# text. This is a rule-bus edit, not a new service. It is **almost certain (90-99%)**, because every existing common reference already names the same SSOT, to remove the numeric ambiguity.
