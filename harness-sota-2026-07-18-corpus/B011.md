# B011 — Groundedness engineering: hallucination detectors

**Unit:** B011  
**Date:** 2026-07-19  
**Scope:** Published hallucination-detection methods and their practical fit to the artifacts this harness already produces. Read-only analysis of the unpacked subject; only this artifact was written.

## Executive verdict

Hallucination cannot be eliminated. No detector surveyed establishes anything close to that, and several detect only one mechanism of falsehood. The achievable design target here is narrower: make every load-bearing claim point to inspectable evidence, cheaply reject broken pointers and stale or irrelevant receipts, and selectively ask a semantic checker whether the cited evidence actually entails the claim. A detector result is a suspicion or an evidence-state classification, never proof that the claim is true.

The best practical stack for this owner is:

1. deterministic referential-integrity checks over citations, commands, tool results, hashes, and freshness;
2. claim-level semantic entailment only for grounded artifacts whose evidence is already local or cited;
3. fresh retrieval or independent re-derivation only for load-bearing claims left unsupported;
4. disagreement/uncertainty signals only to choose which claims receive the expensive checks.

This is **very likely (80-90%)** the best architecture for this harness because (a) it consumes artifacts already produced by the shared ledger and research workflows, (b) published FActScore/SAFE results support atomic claim evaluation, (c) the local live record demonstrates that lexical use/mention errors are harmful, and (d) it does not add a rejected orchestration or critic runtime. The exact local advantage is **UNVERIFIED — the experiment that settles it is the labeled shadow replay in “Evaluation and rollout” below**.

Do **not** install a universal prose-scanning “hallucination guard,” do not majority-vote open-ended conclusions, do not convert verbal confidence into truth, and do not let an LLM entailment verdict discard a successful tool result. The local defect record shows three lexical guards confusing mention with use and negation with assertion (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:9-22`), plus a tool sentinel classifying an `ok: true` result as failed from a field name containing `timedout` (`:54-76`). That is direct evidence that false alarms are not merely irritating here; they can corrupt later reasoning.

## What “hallucination” means operationally here

The word collapses several different failures that require different detectors:

| Failure class | Example in this workspace | Best available signal | What the signal cannot prove |
|---|---|---|---|
| Fabricated provenance | `path:line` does not exist; a fan-out artifact is missing | deterministic resolution | that an existing source supports the prose |
| Unsupported inference | citation exists but does not entail the claim | claim/evidence entailment | global truth when the source itself is wrong |
| Contradicted claim | source or tool result says the opposite | semantic contradiction plus exact source | that no other source supports a qualified version |
| Stale evidence | green result predates the mutation or refers to another revision | sequence/hash/fingerprint binding | adequacy of the test |
| Wrong-but-consistent anchor | every downstream step reuses the same false offset/premise | independent re-derivation | correctness if both derivations share the same hidden error |
| Arbitrary confabulation | repeated samples disagree semantically | SelfCheck/semantic entropy | systematic falsehoods on which samples agree |
| Overconfidence | assertive language despite weak evidence | confidence/evidence mismatch | truth or falsehood itself |
| Citation/source error | source is unreliable, stale, or a search snippet | source-quality and date checks | semantic support on its own |

This decomposition matters. Farquhar et al. explicitly scope semantic entropy to “confabulations,” meaning arbitrary answers sensitive to sampling, and distinguish them from systematic misconceptions or deceptive behavior. A consistency detector that is useful for the former is blind to a stable false premise. Conversely, a citation pointer checker catches fabricated locations but not a perfectly valid citation that says the opposite.

## Survey and practical judgment

### 1. Deterministic provenance and receipt checks

This is not usually marketed as a hallucination detector, but it is the highest-precision detector available here. Resolve each cited local path and line, URL/DOI, artifact contract, ledger event, command fingerprint, revision hash, and freshness relation. A broken pointer is objectively broken; a green result older than a mutation is objectively stale. The fan-out contract's 3/3 nonexistent-file digests (`fan-out-contract.md:68-73`) shows immediate applicability.

**Practicality:** excellent. The required artifacts already exist, and the shared ledger already implements freshness and fingerprints.  
**Cost per claim:** effectively zero model calls; file/ledger lookups only.  
**Catch fraction here:** **UNVERIFIED — likely (55-80%) to catch a large fraction of fabricated-provenance and stale-receipt claims, based on the 3/3 nonexistent artifact incident and the existing ledger fields; label at least 50 examples of each class to settle it.** It will catch essentially none of the valid-pointer/non-entailment class.  
**False-positive rate here:** **UNVERIFIED — very likely (80-90%) to be below a semantic model judge if the rule is limited to exact pointer/freshness predicates, because those predicates do not interpret prose; replay known valid aliases, origin/main-only paths, generated files, Windows short paths, and line-shifted citations to settle it.**  
**Decision:** foundation and the only portion eligible to block publication automatically after calibration.

### 2. Atomic fact decomposition plus entailment against supplied evidence

FActScore decomposes long text into atomic facts and measures the percentage supported by a reliable knowledge source. Its paper reports an automated estimator with less than 2% error on its biography setting. SAFE similarly decomposes long-form output, searches for each fact, and judges support; on roughly 16,000 facts it agreed with crowd labels 72%, and on 100 randomly sampled disagreements it won 76% of adjudications. SAFE reported cost more than 20 times lower than human annotation. These are strong demonstrations that claim-level checking is more informative than one holistic “is this answer grounded?” score.

For this harness, retrieval is often unnecessary: research artifacts already contain URLs and local audits contain `path:line` anchors. The practical transformation is `atomic claim -> cited span/receipt -> supported | contradicted | insufficient`, with a short reason. The cited span must be loaded by deterministic code, not supplied from the claim text.

**Practicality:** high for Markdown findings, audits, research reports, fan-in digests, completion summaries, and memory notes with citations; lower for aesthetic/ideation prose.  
**Cost per claim:** one claim-extraction call per artifact plus entailment claims batched against their small cited spans; no web call for local evidence. Exact dollars/tokens are provider- and prompt-dependent and **UNVERIFIED — replay 100 artifacts while logging input/output tokens and latency to settle them**.  
**Catch fraction here:** **UNVERIFIED — likely (55-80%) to catch unsupported or contradicted load-bearing claims that have explicit evidence pointers, because the candidate evidence is constrained; a blinded local claim set settles it.** Claims omitted by the atomizer and errors in the source remain misses.  
**False-positive rate here:** **UNVERIFIED — roughly even (45-55%) whether an uncalibrated entailment judge can meet this workspace's necessary low false-alarm threshold, because SAFE's 72% crowd agreement is not precision and the task differs; a supported-claim-heavy local evaluation settles it.**  
**Decision:** best semantic method, but advisory until local precision is measured. Never conflate `insufficient` with `false`.

### 3. Search-augmented fact checking

SAFE shows the frontier pattern: decompose, issue targeted searches, reason over results. This is useful when an open-domain claim has no supplied evidence. It is less attractive as a universal pass because search can fail, snippets can omit qualifiers, sources disagree, and the corpus records WebFetch errors independently of truth. Search absence is not evidence of falsehood.

**Practicality:** medium, limited to factual research outputs and externally checkable time-sensitive claims. It is inappropriate for claims about private code, UI behavior, or unpublished binaries.  
**Cost per claim:** at least one search and usually one judge call per claim, potentially multiple retrievals; substantially above supplied-evidence entailment.  
**Catch fraction here:** **UNVERIFIED — likely (55-80%) for well-formed public factual claims with discoverable sources, using SAFE's results as task-adjacent evidence; a 100-claim public-fact subset settles transfer.**  
**False-positive rate here:** **UNVERIFIED — likely (55-80%) too high for blocking when search returns no evidence, because retrieval failure and factual falsehood are observationally confounded; paired known-present/known-absent source controls settle it.**  
**Decision:** escalation lane for selected unsupported public claims, never a global Stop hook and never “not found = false.”

### 4. SelfCheckGPT and sample disagreement

SelfCheckGPT samples multiple passages from a black-box model and scores consistency without an external database. On WikiBio it outperformed grey-box baselines in sentence AUC-PR and passage correlation; the paper's table reports different performance by scoring variant, so “SelfCheckGPT” is not one operating point. Its premise is useful: arbitrary hallucinations tend to vary across samples.

The limitation is decisive here: agents can reproduce an orchestrator-authored false constraint or a wrong offset consistently. The live brief records precisely such propagation. Agreement detects instability, not truth. It also spends multiple generations to evaluate prose for which the harness often already has direct evidence.

**Practicality:** low as a default, medium only for unsupported, high-value claims where no source or executable oracle exists.  
**Cost per claim:** SelfCheck-style methods require several additional samples plus comparison; five samples imply roughly five-generation overhead before scoring.  
**Catch fraction here:** **UNVERIFIED — unlikely (20-45%) for the total false-claim mix because stable false premises and shared prompts remain invisible; replay seeded arbitrary and systematic errors separately to settle it.**  
**False-positive rate here:** **UNVERIFIED — unlikely (20-45%) to be acceptable without domain calibration, because legitimate open-ended answers can differ; measure precision on paraphrastic, underspecified, and multi-answer tasks.**  
**Decision:** disagreement may trigger evidence collection or human review. Never let agreement certify correctness.

### 5. Self-consistency voting

Wang et al. reported large accuracy gains from sampling reasoning paths and majority voting on canonical-answer reasoning benchmarks: +17.9 points on GSM8K, +11.0 on SVAMP, and +12.2 on AQuA in the reported setup. Adaptive-Consistency later reduced sampling by up to 7.9 times with an average accuracy loss below 0.1% across 17 reasoning/code datasets and three models.

That is an answer-selection method, not a general hallucination detector. Voting is coherent only when outputs collapse to a small, canonical answer space or candidates face an executable oracle. “Three agents cited the same claim” is especially weak when all received the same false preamble. The local fan-out contract explicitly says a specific probe wins over agent count when verdicts split (`fan-out-contract.md:76-77`).

**Practicality:** medium for bounded numerical answers and patches selected by tests; very low for reports, designs, root-cause narratives, or source interpretation.  
**Cost per claim:** multiple full solutions; adaptive stopping can reduce this but does not remove comparison cost.  
**Catch fraction here:** **UNVERIFIED — unlikely (20-45%) over the owner's mixed artifacts, because most claims lack canonical answer equivalence; a task-stratified replay settles it.**  
**False-positive rate here:** not meaningful if used for selection; if used to call minority claims false, **UNVERIFIED — likely (55-80%) unacceptably high on multi-answer/open-ended tasks; human-labeled alternative-correct answers settle it.**  
**Decision:** keep outside the general groundedness detector. Use only behind task allowlists and hard cost caps.

### 6. Semantic entropy

Semantic entropy clusters multiple generations by meaning and measures uncertainty over semantic alternatives. Farquhar et al. report that it detects confabulations better than naive lexical or token-probability uncertainty across their QA settings, and test a longer biography setting. The method's conceptual advantage over raw disagreement is paraphrase invariance. Its limits are equally important: it still needs multiple generations and an entailment/clustering operation, and the paper scopes it to arbitrary confabulations, not stable falsehoods.

**Practicality:** low for routine agent artifacts; medium as an offline research experiment for unsupported QA-like claims.  
**Cost per claim:** the paper describes sampling multiple answers and semantic clustering; later Semantic Entropy Probes work motivates probes by describing conventional semantic entropy as roughly 5–10x compute. A hidden-state probe is not practical with closed API models and would be a trained critic-like component rejected by the anti-overfit gate.  
**Catch fraction here:** **UNVERIFIED — unlikely (20-45%) across all false claims, for the same systematic-error blind spot as SelfCheck; seed arbitrary versus stable falsehoods to settle it.**  
**False-positive rate here:** **UNVERIFIED — roughly even (45-55%) whether a threshold calibrated on QA/biographies transfers to long technical artifacts; local calibration curves settle it.**  
**Decision:** research-only; no production threshold.

### 7. Verbalized confidence and black-box uncertainty probes

Xiong et al. studied verbal confidence, response sampling, and consistency across five dataset types and five LLMs. They found verbalized confidence overconfident, no method consistently best, and difficult/professional tasks still challenging; their example white-box versus black-box AUROC gap was 0.605 versus 0.522. Therefore a confidence phrase or invented percentage is not a truth signal.

The current shared harness explicitly recognizes any percentage, the word `confidence`, or an evidence-like token as satisfying a “band” regex (`/local_disk0/codexwork/bundle/agents/harness/modules.py:2044-2049`) and tells the agent to state a band such as ~70% (`:2251-2265`). That can improve honesty vocabulary, but it cannot detect hallucination.

**Practicality:** medium as a routing feature, zero as proof.  
**Cost per claim:** near zero for existing prose markers; multiple samples if consistency is added.  
**Catch fraction here:** **UNVERIFIED — very unlikely (5-20%) for false claims if used alone, because fluent overconfidence and honest uncertainty overlap; a calibration set with reliability diagrams settles it.**  
**False-positive rate here:** **UNVERIFIED — likely (55-80%) unacceptably high if “high confidence + no citation” is treated as false or “low confidence” as wrong; compare confidence bins to adjudicated correctness.**  
**Decision:** use evidence state (`verified`, `supported`, `insufficient`, `contradicted`) and the next check, not a percentage detector.

### 8. Intrinsic self-correction and same-model critics

Huang et al. found that models struggle to self-correct reasoning without external feedback and can degrade after revision. An instruction to “double-check yourself” therefore does not create an independent signal. A same-context critic can still identify candidate issues, but its result must be checked against source or execution evidence.

**Practicality:** low as a detector; medium as a cheap hypothesis generator.  
**Cost per claim:** another model pass, often over the full artifact.  
**Catch fraction here:** **UNVERIFIED — unlikely (20-45%) for false claims without external evidence, based on the controlled self-correction result and the owner's wrong-but-consistent failures; paired same-context versus fresh-evidence replay settles it.**  
**False-positive rate here:** **UNVERIFIED — likely (55-80%) too high for blocking because critics can invent defects; blinded adjudication settles it.**  
**Decision:** advisory only. A trained critic, reward model, or general guardrail framework is explicitly excluded by the anti-overfit gate.

## Recommended design: Evidence-State Verifier — UNVERIFIED local operating point

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

The recommendation inherits **UNVERIFIED** because no local labeled groundedness set currently establishes its precision, recall, or cost. The experiment that settles the premise is the shadow replay specified below. The structural components, however, reuse verified local interfaces: Stop/PostToolUse dispatch (`settings.json:310-320`, `:484-503`), typed/fresh receipts (`ledger.py:98-121`, `:1093-1117`), and citation-rich Markdown artifacts (`fan-out-contract.md:49-52`, `:74-83`).

### Input contract

Do not require a large strict JSON response from every agent. StructuredOutput has a 22.9% measured error rate in the pinned corpus, and research findings naturally vary in cardinality. Continue producing normal Markdown, but adopt one lightweight evidence convention for grounded artifacts:

```text
Claim: <one load-bearing proposition>
Evidence: <path:line | URL/DOI | ledger receipt id/fingerprint | tool-result id>
State: <verified-executable | source-supported | inference | unknown>
```

This convention is for load-bearing findings and completion claims, not every sentence. Existing prose outside it remains eligible for a model claim-extraction pass during shadow evaluation; omission is itself measurable coverage, not an automatic violation.

### Stage A — deterministic evidence resolution

For every declared claim:

1. Parse the pointer by type; never regex the entire prose body for danger words.
2. Resolve local `path:line` and ensure the cited line/span exists in the declared revision/access method.
3. Resolve artifact contracts with exact existence, nonempty-size, and optional hash checks.
4. Resolve receipt IDs and require structured status, claim-family match, post-mutation freshness, and exact failure fingerprint for “fixed.” Remove the generic success-word fallback from evidence eligible for completion.
5. For URLs/DOIs, record resolvable/unresolvable and retrieval timestamp. Do not call unresolvable false; classify `evidence_unavailable`.
6. Run a known-positive control in each detector family before concluding absence, matching the already-established local rule (`INPUT-known-harness-defects.md:111-129`).

Output states are `pointer_valid`, `pointer_invalid`, `stale`, `wrong_receipt_class`, `evidence_unavailable`, or `no_pointer`. None except a structurally invalid pointer asserts that the prose is false.

**Expected catch/cost/false-positive operating point:** **UNVERIFIED — very likely (80-90%) that this stage has the best precision/cost tradeoff because it evaluates exact machine predicates and uses no model; the shadow replay plus matched known-positive controls settles it.** It costs local I/O per claim and should remain subsecond per ordinary artifact, but that latency is **UNVERIFIED — benchmark 1,000 pointers on the Windows host to settle it**.

### Stage B — bounded semantic entailment

Run only when Stage A produced a valid evidence span and the artifact is marked GROUNDED. Give a judge exactly: atomic claim, cited span, relevant qualifier/date/revision, and three labels:

* `SUPPORTED`: the span entails the full claim;
* `CONTRADICTED`: the span entails an incompatible proposition;
* `INSUFFICIENT`: neither.

Require a minimal rationale locating the decisive words, but do not treat the rationale as a second signal. Batch several independent claim/span pairs in one loose response or a simple flat schema; do not use deep nested fan-out schemas. `INSUFFICIENT` triggers “add evidence, narrow, or label inference,” never a falsehood accusation. `CONTRADICTED` triggers a review with both claim and source visible. The semantic judge cannot mark a tool call failed or discard its output.

**Expected catch/cost/false-positive operating point:** **UNVERIFIED — likely (55-80%) to catch valid-pointer/non-entailment errors at one batched judge pass per artifact, drawing on FActScore and SAFE but not assuming transfer; the labeled replay settles it.** It remains advisory until supported-claim precision reaches the rollout threshold below.

### Stage C — selective escalation

For a load-bearing `no_pointer`, `evidence_unavailable`, or high-cost `INSUFFICIENT` claim, choose exactly one task-matched escalation:

* public/time-sensitive fact -> targeted search with source date and independent known-present retrieval control;
* code behavior -> smallest executable test or static source probe;
* RE address/offset -> fresh-context re-derivation from the binary, not reuse of the cited note;
* canonical QA/numeric result without a source -> bounded adaptive consistency, disagreement only;
* subjective recommendation -> label as judgment and evaluate its premises, not its taste.

This is routing over existing tools, not a new autonomous fact-checking service.

**Expected value:** **UNVERIFIED — likely (55-80%) to reduce review cost relative to checking every claim because deterministic failures and unsupported load-bearing claims are a minority of prose; log the actual escalation rate and cost per caught false claim to settle it.**

### Stage D — presentation and authority

Emit one compact table after the artifact, not repeated Stop-hook nagging:

| Claim ID | Evidence state | Detector | Action |
|---|---|---|---|
| C1 | pointer invalid | deterministic | repair citation |
| C2 | insufficient | semantic/advisory | narrow or add evidence |
| C3 | contradicted | semantic/advisory | human/source review |
| C4 | supported | semantic/advisory | no action |

Authority rules:

* Deterministic pointer/freshness failures may block a “verified” label after calibration; they do not block saving the artifact.
* Semantic verdicts are advisory and never mutate/discard source artifacts.
* Disagreement and uncertainty only prioritize review.
* A tool's structured `ok/status/exit` fields outrank substring matches in field names or prose.
* Silence means “not checked” unless detector coverage is explicitly complete; it never means “grounded.”
* Every absent/broken conclusion requires a known-positive detector control and a mechanically independent second signal.

## Proposals rejected or constrained

### Reject universal regex hallucination guard

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus), but REJECT.** Local evidence already shows use/mention, negation, field-name/value and self-documentation false alarms (`INPUT-known-harness-defects.md:9-41`, `:54-76`). Tuning trigger phrases does not add semantic discrimination.

### Reject majority vote over reports or agent councils

**NATIVE-vs-BUILD: NATIVE (Claude Code already does this; we just enable it), but REJECT for truth certification.** Shared false premises induce correlated agreement, and open-ended outputs do not have a canonical answer. Native fan-out remains useful for independent evidence collection or diverse hypotheses.

### Reject semantic entropy in the production Stop path

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification), and REJECT.** Multiple sampling plus semantic clustering is too expensive relative to direct evidence already present, detects only confabulation-like instability, and would create a second scoring runtime. It is acceptable only as an offline experiment using existing calls, not infrastructure.

### Reject hidden-state semantic-entropy probes

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification), and REJECT.** Closed frontier APIs do not expose the required hidden states, training/calibration creates a trained verifier component, and transfer to new models/tasks would require continuing maintenance. This explicitly reintroduces a rejected trained critic without local evidence.

### Reject automatic correction by an entailment judge

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus), but REJECT automatic mutation.** Even SAFE's reported 72% agreement is far below the standard for silently rewriting claims. The judge may propose a correction alongside the original evidence; executable or human review accepts it.

### Constrain search-augmented checking

**NATIVE-vs-BUILD: NATIVE (Claude Code already does this; we just enable it).** Use only on unsupported public facts selected by risk/cost. A failed search becomes `evidence_unavailable`, not contradiction. Always validate the retrieval detector on a known-present page first.

## Evaluation and rollout: the experiment that settles all UNVERIFIED operating claims

### Dataset

Do not treat the 2,268 owner-correction candidates as labels; the corpus itself says its smoke sample was 41/41 false positive. Build a stratified claim set from artifacts already produced:

* 75 research/audit claims with valid supporting citations;
* 75 research/audit claims with valid pointers but insufficient or contradictory spans;
* 50 completion claims paired with fresh, stale, wrong-class, or prose-only receipts;
* 50 fan-out artifact/digest claims, including known existent and nonexistent outputs;
* 25 RE anchors, split between fresh independent derivation and reused wrong anchors;
* 25 benign near-misses: quotations, negations, examples, code fences, field names with false values, and prose documenting detector triggers.

Seeded mutations may supply rare error classes, but keep originals and mutations blinded and report them separately. Two humans independently label atomicity, support/contradiction, evidence quality, and load-bearing status; adjudicate disagreements. If two human labels are infeasible, one human plus an executable/source oracle qualifies only where that oracle directly decides the claim.

### Compared systems

At matched artifact sets, compare:

1. current lexical claim/honest-signal behavior;
2. deterministic Stage A only;
3. Stage A + one entailment judge;
4. Stage A + heterogeneous second judge only on first-judge flags;
5. SelfCheck with five samples on the unsupported subset;
6. semantic entropy on the same small unsupported subset, research-only;
7. human/source adjudication as reference.

### Required metrics

Report per claim class and overall:

* false-claim recall: false/unsupported claims caught divided by all false/unsupported claims;
* alert precision: true detector flags divided by all flags;
* benign false-positive rate;
* `SUPPORTED -> alert` rate, especially quotations/negations/near-misses;
* `CONTRADICTED -> silent` rate;
* atomization coverage: load-bearing claims extracted divided by labeled load-bearing claims;
* cost and latency per checked claim;
* cost per true unsupported claim caught;
* escalation rate and human-review minutes;
* correct-to-wrong revision count (must be zero for a non-mutating detector);
* detector abstention/`evidence_unavailable` rate;
* calibration by artifact type, model, and evidence type.

A single accuracy number is forbidden: because supported claims will dominate normal traffic, a detector can appear accurate by staying silent, while a recall-heavy detector can destroy utility through false alarms.

### Promotion policy — UNVERIFIED thresholds
