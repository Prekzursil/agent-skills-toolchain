## Detailed adjudication

### C1 — false inheritance boundary (**STALE**)

`perl/patterns.md:11` claims an extension relationship. The common file's frontmatter enumerates Python, JS/TS, Go, Rust, Java, Ruby, PHP, C/C++, C#, Swift, Kotlin, and shell, but no Perl (`common/patterns.md:2-19`). Meanwhile, the rule-tree documentation says common rules are required and language directories extend them (`README.md:8-20,28-29`). Thus a Perl edit loads the Perl target but not the claimed parent, assuming Claude Code honors the declared path globs.

That last loader-behavior premise is **very likely (80-90%)**, supported by the explicit frontmatter and the README's installation model, but **UNVERIFIED** on this Linux node; the settling experiment is a Claude Code instruction-load trace using a known `.pm` file and a known common-only marker. The structural mismatch exists regardless: the two declared scopes do not overlap.

Resolution confidence is **very likely (80-90%)** that adding the five Perl globs restores the intended inheritance, because the common repository abstraction at `common/patterns.md:37-43` and the Perl specialization at `perl/patterns.md:13-27` are compatible. Evidence: both demand a storage-independent interface; the Perl rule merely names implementations.

### C2 — target example violates the all-attributes constraint (**CONTRADICTION**)

The collision is literal. `perl/coding-style.md:21` says Types::Standard applies to “all attributes,” while `perl/patterns.md:21` creates `dbh` without `isa`. Both files have identical five-extension frontmatter (`perl/coding-style.md:1-8`; `perl/patterns.md:1-8`), so neither can be dismissed as out of scope.

AGENTS §10 does not resolve this same-level conflict. The resolution should make executable examples obey standing rules. It is **almost certain (90-99%)** that adding an appropriate constraint removes this textual contradiction, based on the exact missing `isa` field; selecting the best constraint for both DBI and DBIx::Class is **UNVERIFIED**, and the settling experiment is to compile and instantiate the revised sample against both backends under the supported Perl version.

### C3 — DTO policy has two owners (**REDUNDANCY**)

The target limits the mandate to DTO/value-object classes (`patterns.md:30-42`); coding style applies the same stack to all attributes (`coding-style.md:19-23`). These are compatible today, but the target's own repository example already demonstrates how duplicates drift: the broader rule says every attribute is typed while the neighboring example is not.

It is **very likely (80-90%)** that a single normative owner plus linked examples reduces future drift, based on this observed divergence between `patterns.md:21` and `coding-style.md:21`. This is a documentation/configuration repair, not a new mechanism.

### C4 — file-I/O requirement has two strictness levels (**REDUNDANCY**)

Security owns “three-arg open only” (`security.md:29-32`); patterns adds unconditional `autodie` (`patterns.md:44-47`) but immediately demonstrates a Path::Tiny call rather than `open` (`patterns.md:49-53`). There is no direct logical conflict if “open” means only explicit built-in calls, but that qualification is not written. The different strictness and split ownership make the operational rule ambiguous.

The proposed wording retains explicit error handling as an alternative because unconditional `autodie` can be inappropriate in code that deliberately handles `open` failure. That design judgment is **likely (55-80%)**, based on the target's resource-management intent and the security file's narrower safety invariant; it is **UNVERIFIED** against owner/project conventions, and the settling experiment is to sample existing owner Perl repositories for intentionally handled `open` failures and their local policy files.

The settings wire `per-edit-check/check.py` for Edit/Write/MultiEdit (`settings.json:333-342`) plus a generic dispatcher (`settings.json:344-353`). The per-edit implementation documents only Python, JS, JSON, YAML, and explicit TS/Rust skips (`check.py:8-17`); its dispatcher handles those extensions and returns empty for everything else (`check.py:151-170`). All five Perl extensions therefore reach the silent fallback.

Independent token scanning found no target-specific Perl policy code in the hook/shared-harness source. The detector controls and exact output are recorded above.
