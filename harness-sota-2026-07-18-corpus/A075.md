# A075 — coherence audit of `~/.claude/rules/typescript/testing.md`

## Executive verdict

The 18-line TypeScript/JavaScript testing rule is not a self-contained policy. Its line 10 delegates to `common/testing.md`, its line 14 selects Playwright for critical user flows, and its line 18 names `e2e-runner` as support. That small surface collides with the harness in seven material ways:

1. the named runner reverses the rule's framework preference (Playwright required versus Agent Browser preferred);
2. the named TDD authority hard-codes an 80% four-metric threshold while the inherited rule makes `.coverage-thresholds.json` the SSOT and says metaswarm is 100%;
3. overlapping web rules repeat the Playwright policy;
4. common workflow and review rules repeat the inherited coverage policy in three places;
5. active hooks do not enforce test-first order, the three required test types, the configured coverage threshold, or use of either named agent;
6. the E2E completion hook enforces the stronger, unruled requirement that every declared journey spec be run in the current turn while also accepting Cypress, Nightwatch, Vitest/Jest E2E, and other non-Playwright evidence; and
7. that journey hook relies on a command ledger whose writer is not registered in either active hook registry in the unpacked subject.

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** The most defensible replacement is a single risk-scoped testing contract plus thin language adapters: repository test configuration owns frameworks and numerical thresholds; the global rule owns required evidence; hooks verify only completion claims and the configured gate result. This is **very likely (80-90%)** to reduce contradiction and policy drift because the present copies and divergent authorities are directly visible at the cited lines, while the remaining uncertainty is whether project-local governance outside the unpacked subject already supplies a stricter policy.

This unit did **not** verify skill-body coherence. The remote bundle has neither `/local_disk0/codexwork/bundle/claude/skills` nor `/local_disk0/codexwork/bundle/agents/skills`; the command `find .../claude/skills .../agents/skills -maxdepth 1 -type f` returned two `No such file or directory` errors.
