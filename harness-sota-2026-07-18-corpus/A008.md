## Executive conclusion

`common/hooks.md` is not a coherent contract for the hook system that is actually installed. It is a 36-line legacy fragment that mixes three unrelated subjects: a three-event hook taxonomy, permission-mode advice, and instructions for a retired task tool. The installed settings contain eighteen hook event families and several blocking/mutating enforcement mechanisms; the governing `AGENTS.md` supplies the crucial block-versus-inject law; language rules demand format/lint/type-check hooks that the active settings do not provide; and the measured corpus shows that `TodoWrite` is effectively dead while its replacements are heavily used.

The highest-impact collisions are:

1. **Permission contradiction:** `common/hooks.md:17-21` says to use auto-accept cautiously, disable it for exploratory work, and never use dangerous permission bypass. Active `settings.json:64-75,693` denies only a few file reads, sets `defaultMode` to `bypassPermissions`, grants whole-drive access, and suppresses the dangerous-mode prompt. The rule is not being followed by configuration.
2. **Illegal non-dangerous blocks:** the higher-precedence `AGENTS.md:64-70` permits exit-2 blocking only for irreversible/dangerous actions. The active PostToolUse per-edit checker returns exit 2 for ordinary syntax errors (`per-edit-check/check.py:18-24,225-231`), the file-scope hook returns exit 2 for an out-of-scope path (`file-scope/check.py:8-10,119-136`), and the optional test-tamper mode blocks a commit for test-diff heuristics (`test-tamper-guard/guard.py:9-17,295-313`). 3. **Retired tool instruction:** `common/hooks.md:23-36` requires `TodoWrite`; corpus lines 3631-3634 record one call, one error, while lines 95-98 and 111-114 record 3,710 `TaskUpdate` calls and 2,181 `TaskCreate` calls. This is a badly written/stale rule, not agent refusal.
