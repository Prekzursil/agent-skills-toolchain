# C002 — Context lifecycle: re-derivable versus genuinely lost

## Executive verdict

The harness currently conflates three problems:

1. durability — whether information survives a context boundary anywhere;
2. reachability — whether the next agent can cheaply find what survived; and
3. activation — whether the minimum necessary part is put back in the inference window.

That conflation wastes capture budget. Repository state, git objects, files, transcripts, tool logs, ledger events, and vault notes are already durable sources. Copying their bodies into .remember/now.md, a compaction checkpoint, a session file, and a second memory plane does not rescue lost context; it creates competing caches.

The only genuinely lost class is semantic state that existed solely in the model's working state or in an unrecorded volatile environment: the selected next action, an unspoken load-bearing assumption or rationale, the chosen interpretation of ambiguous owner input, an unlogged observation, and the relationship between evidence and the conclusion drawn from it.

The best replacement policy is therefore a continuation delta, not a conversation recap: capture only window-only semantic deltas; represent re-derivable material by typed pointers, hashes, freshness predicates, and omitted counts; restore the delta first; re-read or recompute pointed evidence only when the current step requires it.

I am very likely (80-90%) that this split will reduce continuity-token cost without reducing recoverability, because the implementation currently copies scratch text and separately replays ledger facts, while Claude supplies a durable transcript path at the lifecycle boundary. The exact local effect is UNVERIFIED; the settling experiment is the paired compact/resume replay in §11, measuring continuation success, stale-fact errors, injected tokens, and recovery latency.

No second orchestrator, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed. Every proposal rides the existing hook dispatcher, event ledger, filesystem, git, transcript, and basic-memory surfaces.

## 3. Lifecycle model and admission test

Use four states:

| State | Definition | Correct action |
|---|---|---|
| Active | In the current inference window | Keep only for immediate decision value |
| Durable and addressable | On disk or in an authoritative external record with a stable pointer | Store pointer/hash/freshness predicate; fetch just in time |
| Durable but unaddressed | On disk but lacking usable pointer, index, or provenance | Repair addressing; do not duplicate the body |
| Window-only or volatile | No durable source can reproduce the semantic value after the boundary | Capture a minimal typed semantic delta |

For each candidate field:

1. Authoritative-source test: is the exact fact already in a repo file, git object, transcript span, ledger event, task registry, log, or canonical note?
2. Recomputation test: can it be reproduced from retained inputs under an explicit environment/version predicate?
3. Volatility test: will the source change or vanish before recovery?
4. Semantic-delta test: did the agent add a decision, rationale, assumption, falsifier, mapping, priority, or next-action choice not represented by the sources?
5. Safety test: is capture forbidden or harmful (secret, credential, raw fetched instruction, hidden chain of thought, large raw output)?

If 1 or 2 passes, retain a pointer and validation predicate. If 3 or 4 passes and 5 does not, capture the smallest typed statement. If 5 passes, retain neither body nor secret; at most keep a safe existence/authority marker.

## 4. Re-derivable context

### 4.1 Repository and filesystem

Re-derivable while a referenced snapshot remains available:

- current file contents and directory inventory;
- committed history, trees, tags, commit messages, and revision diffs;
- worktree diff/untracked inventory at capture time if later writes cannot overwrite the only copy;
- symbol maps, dependency graphs, searches, line counts, and static-analysis summaries;
- manifests, lockfiles, configuration, schemas, tests, and file-change lists.

Do not copy bodies into a checkpoint. Record repo root identity, HEAD, base, dirty bit, diff hash, and untracked-manifest hash, then rerun the narrow query. The manual checkpoint command already uses git stash/commit plus a log (/local_disk0/codexwork/bundle/claude/commands/checkpoint.md:9-21).

Qualification: an unsaved editor buffer is not disk state. A mutable worktree is addressable now but not historically re-derivable after later writes unless pinned by commit, stash, patch artifact, or content hash.

### 4.2 Transcript and tool events

Claude payloads provide transcript_path and subagent payloads provide agent_transcript_path ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)). Normally addressable rather than lost are exact owner wording/authorization, visible tool calls and retained outputs, command/error/retry order, assistant reports, and subagent final messages.

The checkpoint should store transcript identity plus bounded offsets/hashes, not copy conversation prose. UNVERIFIED: this installation retains every required tool-result body, especially oversized/truncated results; the settling experiment emits a known marker before and inside a large result, compacts, resumes, and verifies byte-for-byte availability through transcript_path without using live context.

Claude documents that hook-injected context is saved and replayed on resume, meaning timestamps and SHAs can become stale; SessionStart reruns and can refresh them ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)). Checkpoints should therefore carry freshness predicates, not replay mutable bodies.

### 4.3 Executable evidence

Test/build/lint/typecheck outcomes are re-derivable only when source tree, argv, cwd, toolchain/dependencies, named environment requirements, and fixtures are pinned. Capture a receipt and reproduction pointer, not stdout.

If predicates are not pinned, preserve the historical observation as a short receipt: observed_at, exit code, argv fingerprint, artifact/log pointer, and environment fingerprint. A later rerun does not prove the earlier environment.

### 4.4 Materialized plans and external artifacts

Plan files, issues, task registries, todos, backlogs, and .remember state files are durable data. A delta needs only selected item ID, source version, and an unrecorded selection rationale.

A web/API/GUI observation is historically addressable when its response, screenshot, export, or log is saved with timestamp and provenance. The live state may change; retain an evidence pointer and validity horizon, not a duplicate body.

## 5. Genuinely lost or volatile context

Only these deserve automatic durable capture when not already materialized:

1. Consequential decision and rationale: decision, accepted tradeoff, rejected alternative, evidence pointers, authority, valid_as_of, supersession. The ledger policy already identifies “the why hooks cannot see” as manual semantic input (/local_disk0/codexwork/bundle/claude/AGENTS.md:28-34).
2. Active load-bearing assumption and falsifier: statement, required confidence band, evidence pointers, discriminating check. Do not save all brainstorming.
3. Exact next action and done criterion: the source checkpoint stores goal/decisions/failures/scratch but not typed phase, next action, or done criterion (/local_disk0/codexwork/bundle/agents/harness/modules.py:1488-1513).
4. Interpretation of ambiguous owner input: interpreted scope, alternatives not chosen, confirmation pointer. Never turn an unconfirmed inference into an owner preference.
5. Negative semantic conclusion: why approach X cannot work under constraint Y unless Z changes, with evidence pointers; raw attempts remain elsewhere.
6. Volatile operational handle: unsaved editor buffer, GUI/debugger state, transient job, live process without registry, expiring permission, or unlogged external observation. Save only a safe handle, timestamp, validity horizon, log pointer, and reacquisition step. Never save credentials.
7. Cross-source mapping: relations among task ID, receipt, files, and constraint when no source already records the mapping.

What must remain lost: hidden chain-of-thought, free-form monologue, raw secrets, fetched pages, raw stdout/stderr, full diffs, binaries, large logs, and speculative branches that affected no decision. Losing them from active context is desirable. Anthropic recommends the smallest high-signal context and describes compaction plus structured note-taking as complementary techniques ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

## 6. Current harness diagnosis

### 6.1 Scratch is copied without classification

SanitizedCheckpointModule reads up to 32,768 characters from .remember/now.md, redacts to 4,096, and embeds it as UNTRUSTED (/local_disk0/codexwork/bundle/agents/harness/modules.py:1464-1471,1511-1512). The older standalone snapshot separately copies now.md and retains 40 versions (/local_disk0/codexwork/bundle/claude/hooks/precompact-snapshot/snapshot.ps1:37-48).

Active settings route PreCompact to the shared dispatcher, not that standalone script (/local_disk0/codexwork/bundle/claude/settings.json:380-390), so I do not claim both run live. Both implementations nevertheless exhibit the design pattern: arbitrary scratch is capture material without classifying whether sections already exist in git, transcript, ledger, log, or task state.

### 6.2 Goal durability preserves a mutable prefix

Every ordinary prompt of at least 12 characters can replace the active goal (/local_disk0/codexwork/bundle/agents/harness/modules.py:1318-1338); storage truncates to 500 characters (/local_disk0/codexwork/bundle/agents/harness/ledger.py:1019-1028); PostCompact reinjects that prefix (/local_disk0/codexwork/bundle/agents/harness/modules.py:1362-1378). This can preserve a follow-up while omitting original scope, acceptance, or authority.

Original words remain addressable in transcript. What is genuinely missing is a semantic split between immutable root contract and current-turn intent.

### 6.3 Writer without deterministic checkpoint reader

The writer creates timestamped files and globally keeps the newest 100 (/local_disk0/codexwork/bundle/agents/harness/modules.py:1515-1527). Recovery reads ledger plus goal, not checkpoint files (/local_disk0/codexwork/bundle/agents/harness/modules.py:973-1003). Claude prose asks the model to search basic-memory manually (/local_disk0/codexwork/bundle/claude/CLAUDE.md:5-11).

This is a reachability defect, not proof of loss. Audit A05 independently made the same source distinction and left runtime payloads as a gap (/local_disk0/codexwork/bundle/inputs/audit-findings/A05.md:15-24).

### 6.4 Global textual truncation ignores semantic priority

The module assembles goal, decisions, failures, then scratch and applies one global max_chars truncation (/local_disk0/codexwork/bundle/agents/harness/modules.py:1488-1517). Retention depends on textual order, with no omitted counts or section hashes.

### 6.5 Competing semantic planes

Codex enables native memory use/generation even with external context (/local_disk0/codexwork/bundle/codex/config.toml:392-395) and enables basic-memory (/local_disk0/codexwork/bundle/codex/config.toml:473-476). Claude calls basic-memory canonical and distinguishes the event ledger (/local_disk0/codexwork/bundle/claude/AGENTS.md:85-91).

UNVERIFIED: actual contradictory recall between the two planes is unmeasured; the settling experiment is a canary fact updated and superseded in basic-memory, followed by blinded Claude/Codex recall with provenance logging before changing configuration.

### 6.6 Exhaustive manual sessions are not automatic compaction schemas

/save-session says “capture everything,” including modified files, discussions, attempts, decisions, file state, blockers, and next step (/local_disk0/codexwork/bundle/claude/commands/save-session.md:5-25,68-180). That is defensible for owner-reviewed narrative handoff, but much is re-derivable and it should not define automatic PreCompact capture.

## 7. Target continuation-delta schema

One bounded, versioned record per provider/project/session/compact sequence:

~~~yaml
schema: continuation-delta/v1
identity: {provider, project_key, session_hash, checkpoint_seq, observed_at}
root_contract:
  transcript_ref: {path_hash, offset_or_message_id, content_hash}
  objective: bounded semantic statement
  acceptance: [bounded criterion]
  constraints: [hard constraint]
  authority: allowed/forbidden boundary
current_delta:
  phase: bounded label
  next_action: one executable action
  done_when: one falsifiable condition
  decisions: [{statement, rationale, evidence_refs, valid_as_of, supersedes}]
  assumptions: [{statement, confidence_band, evidence_refs, falsifier}]
  unresolved: [{failure_or_question, preconditions, next_check, evidence_refs}]
  volatile_handles: [{kind, safe_id, artifact_ref, valid_until, reacquire}]
pointers:
  repo: {root_hash, head, base, dirty, diff_hash, untracked_manifest_hash}
  transcript: {path_hash, through_offset, tail_hash}
  ledger: {project, seq, state_hash}
  tasks: [{id, state_version}]
  artifacts: [{path_hash, content_hash, role}]
verification:
  receipts: [{class, argv_hash, exit, observed_at, artifact_ref, source_fingerprint}]
omissions: {decisions, assumptions, unresolved}
supersedes: prior_checkpoint_id
~~~

Never include transcript spans, raw output, file bodies, full diffs, fetched material, secrets, or hidden reasoning. Missing required fields become explicit unknowns plus a settling check. Quotas prioritize root contract/authority, blocker/next action, decisions/assumptions, verification, pointers, then advisory material.

## 8. Proposals

### Proposal 1 — Typed continuation delta

NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).

Replace scratch-body inclusion in SanitizedCheckpointModule with §7's schema. Populate pointers mechanically. Require agent-authored content only for decision/rationale, assumption/falsifier, phase, exact next action, and done criterion at phase seams or Stop; PreCompact snapshots atomically.

This is very likely (80-90%) to reduce redundant checkpoint content because source definitely embeds scratch plus duplicated ledger summaries. The reduction is UNVERIFIED; the settling experiment shadow-serializes both formats over at least 100 real compactions and reports bytes, unique semantics, pointer resolution, and outcomes.

### Proposal 2 — Immutable root contract versus turn intent

NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).

Extend the per-session goal record to root_contract_ref, root_contract_summary, current_turn_intent, and revision_reason. Set root once from the first substantial task; only explicit owner replacement changes it. Later prompts update intent or append a confirmed revision.

This is almost certain (90-99%) to prevent the deterministic 12-character-overwrite/500-character-prefix failure for newly captured sessions because the write paths are explicit. Outcome gain is UNVERIFIED; settle with a compact/resume test whose hard constraints occur after character 500, followed by a long status question.

### Proposal 3 — Validate pointers and re-derive just in time

NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).

On SessionStart(compact/resume/clear), select the highest valid nonsuperseded same-session delta; validate project, transcript tail, ledger sequence, HEAD/diff, and artifacts. Inject only root contract, phase, next action, blockers, and stale-pointer warnings. Recompute file/diff/test/map data only when required.

This is very likely (80-90%) to close the inspected writer/reader gap because the native event and dispatcher exist. Provider event ordering is UNVERIFIED; settle with disposable Claude and Codex traces for manual compact, auto compact, resume, and clear, asserting exactly-once restoration and deadline compliance.

### Proposal 4 — Declarative admission policy

NATIVE-vs-BUILD: CONFIG (settings/JSON only).

Configure deny_body for transcript/stdout/log/diff/file/fetched/binary/secret/reasoning; pointer_only for git/file/task/receipt/transcript/ledger/artifact; semantic_only for decision, rationale, assumption, falsifier, interpreted scope, negative conclusion, next action, done criterion, and volatile handle; add hard budgets, provenance, validity, and omission counters.

This is very likely (80-90%) to constrain growth because admission is deterministic. False-negative rate is UNVERIFIED; settle with a shadow classifier over owner-labeled fields, penalizing redundant capture separately from missed continuation state.

### Proposal 5 — Refresh mutable facts at native SessionStart

NATIVE-vs-BUILD: NATIVE (Claude Code already does this; we just enable it).

Refresh HEAD, dirty state, live jobs, task status, and other mutable facts at SessionStart. Preserve older values only as historical receipts. Claude documents that mid-session injections replay and may be stale, while SessionStart reruns ([hooks reference](https://code.claude.com/docs/en/hooks)).

This is almost certain (90-99%) to prevent a stale injected SHA/timestamp being represented as current when refresh succeeds. Cross-provider parity is UNVERIFIED; settle with Proposal 3's trace plus a repo mutation between stop and resume.

### Proposal 6 — UNVERIFIED: prune Codex's duplicate semantic plane after a canary

If §6.5's canary confirms divergent or provenance-free recall, disable Codex native memory or at least set disable_on_external_context=true, leaving basic-memory as cross-provider semantic authority. Do not prune before measurement: the vault is unavailable here and contradiction frequency is unknown.

It is likely (55-80%) one authority reduces stale/contradictory injection, based on simultaneous configuration and distinct scope. Net quality is UNVERIFIED; settle with a held-out crossover comparing basic-memory-only, native-only, and both on evidence, currentness, provenance, latency, and tokens.

### Proposal 7 — Keep narrative sessions manual

NATIVE-vs-BUILD: CONFIG (settings/JSON only).

Keep /save-session as explicit, owner-reviewed narrative handoff; mark it noncanonical and prevent automatic PreCompact from importing the full body. Link decisions and next step to typed records where useful.

## 9. Preserve, replace, reject

Preserve native lifecycle events, shared dispatcher, per-session isolation, basic-memory subject to canary/liveness evaluation, raw artifacts off-window, and git/filesystem authority.

Replace scratch-copy checkpoints with continuation deltas; mutable goal prefix with root contract plus intent; global truncation with section quotas/omission counts; manual checkpoint search with deterministic validated restore; replayed mutable facts with refresh.

Reject a new vector DB/KG, durable-execution runtime, full transcript/scratch injection, “capture everything and summarize later,” universal LLM summaries as ground truth, and hidden-reasoning capture.

## 10. Anti-overfit gate

Every proposal uses existing buses. Proposals 1-3 extend one module and ledger records; Proposal 4 is policy; Proposal 5 is an already registered native event; Proposals 6-7 are configuration/pruning. No rejected component is reintroduced.

continuation-delta/v1 is not a new store or runtime: it is one bounded record written by the existing checkpoint hook to the existing state/vault path and restored through the existing dispatcher. Complexity is admitted only for window-only semantics. Everything else is a pointer.

## 11. Settling experiment: lifecycle join

This must run on the Windows box against disposable projects and privacy-safe metadata.

### Instrumentation

Record provider/version/project/session hashes; lifecycle event and source; monotonic event/checkpoint sequence; transcript path hash/offset/tail hash; root message offset/hash; HEAD/base/diff hash/dirty bit; ledger sequence/state hash; checkpoint schema/bytes/field and omission counts; pointer validation; restored bytes. Record no bodies, secrets, raw prompts, or raw output.

Prove the detector with a known-positive manual compact and known-positive note. Cross-check event counts using hook log and independent transcript/session lifecycle markers.

### Task matrix

1. clean coding task;
2. dirty worktree plus untracked artifact;
3. research with volatile web/API evidence;
4. background job and log pointer;
5. multi-agent task and task IDs;
6. hard constraint after character 500;
7. superseded decision/failure;
8. missing required field;
9. stale HEAD between stop/resume;
10. oversized result retained only in transcript/log.

Randomize full-history, current-checkpoint, and continuation-delta restoration into fresh contexts where feasible.

### Outcomes

Measure acceptance satisfied, exact-next-action continuation without owner re-explanation, constraint retention, stale/superseded errors, pointer resolution, redundant bytes, unique semantics, injected tokens, restore latency, corrections within five turns, and hook error/deadline rate.

Ship only if noninferior on task success/constraint retention, no worse on stale-fact error, and materially lower on injected bytes. Exact thresholds are UNVERIFIED; pre-register them from baseline rather than inventing percentages.

## Final recommendation

Adopt one rule: durable evidence gets a pointer; window-only semantics get a typed delta; secrets, raw payloads, and hidden reasoning get neither.

Build that rule into the existing checkpoint module, separate immutable root contract from current intent, and restore through native SessionStart with freshness validation. Measure in shadow mode against real compactions before pruning legacy capture or the duplicate Codex memory plane.

This direction is very likely (80-90%) to be the minimal architecture that addresses actual context loss rather than storage anxiety, because it reuses every existing bus and directly removes the scratch-copy, mutable-prefix, and writer-without-deterministic-reader defects. Its effect size remains UNVERIFIED; only §11's Windows lifecycle join can settle it.
