# X087 — Mechanism design → finite-horizon context allocation

**Unit:** X087  
**Lens:** cross-domain ideation, deliberately not grounded in the local repository  
**Research date:** 2026-07-19  
**Bottom line:** The strongest transferable mechanism is a **strictly proper scoring rule**, but only as an experimental elicitation-and-calibration layer around context decisions. It is **not** valid to describe the context window as a VCG/procurement auction: fragments are not self-interested sellers, token costs are mostly public, and the value of a fragment is endogenous, complementary, delayed, and usually counterfactual. The proper-scoring-rule analogy partially transfers because a producer can state a probabilistic forecast before an outcome. It fails as a truthfulness theorem because an LLM invocation is not necessarily an expected-utility maximizer and because keeping a fragment changes whether “use” is observable. The build recommendation is therefore gated on a randomized shadow-archive experiment which creates scoreable outcomes and measures decision regret.

## 1. Question and scope

The target problem is not merely “rank snippets by relevance now.” It is sequential allocation under a hard token budget: decide which instructions, facts, hypotheses, tool results, plans, and provenance should remain available over an unknown future horizon, while later decisions and observations depend on earlier retention choices.

This unit asks what mechanism design contributes beyond ordinary retrieval and knapsack optimization. It does **not** inspect the owner’s harness or claim that any particular local mechanism exists or is absent. That is intentional: the unit brief reserves repository grounding for neighboring units.

## 2. Candidate mechanisms considered

### 2.1 VCG or a budget-feasible procurement auction — reject as the core analogy

In its own field, a procurement auction has a buyer seeking items or services from strategic sellers with private costs. Singer’s budget-feasible model asks for a truthful, individually rational allocation/payment rule whose total payments do not exceed a hard budget, while approximately maximizing the buyer’s value over selected subsets. For monotone submodular valuations, bounded approximation is possible; for unrestricted value functions the budget constraint can make approximation arbitrarily bad ([Singer, “Budget Feasible Mechanisms,” 2010](https://arxiv.org/abs/1002.2334); [FOCS paper PDF](https://ieee-focs.org/FOCS-2010-Papers/Budget-Feasible-Mechanisms.pdf)).

The tempting translation is:

* context fragments = sellers/items;
* token lengths = private costs/bids;
* context-window size = procurement budget;
* downstream task success = buyer value;
* inclusion = winning the auction.

That translation fails at the mechanism-design layer. Token length is directly measurable rather than privately known. A fragment has no independent preference over selection or payment. There is no monetary transfer that makes truthful bidding a dominant strategy. A model-generated “importance bid” is a prediction, not a seller’s private cost. Without strategic agents, VCG payments and threshold payments solve a problem that is not present. What remains after removing sellers, bids, and payments is budgeted subset selection—knapsack/submodular optimization—not an incentive-compatible auction.

There is also a structural mismatch in the value function. Context contains both substitutes (two summaries of the same log) and strong complements (an error plus the command and environment that explain it). Singer’s positive approximation result relies on monotone submodularity/diminishing marginal value, while arbitrary complementarities are exactly where that guarantee does not follow. It is **likely (55-80%)**, based on ordinary dependency structure in agent traces rather than a measurement of this owner’s traces, that context value violates monotone submodularity often enough to make the auction theorem an unsafe design premise.

**Verdict:** Do not build “token currency,” fragment bidding, VCG payments, or a simulated context market. Those names would add mechanism theater without the assumptions that supply the theorem. This rejection also satisfies the anti-overfit gate: a second orchestration or market runtime is neither necessary nor justified.

### 2.2 Peer prediction / Bayesian truth serum — reject for the first implementation

Peer-prediction mechanisms elicit information when ground truth cannot be directly verified by rewarding agreement patterns between correlated private signals. Later information-theoretic work describes payments based on mutual information between one participant’s signal and a peer’s signal and proves truth-telling properties under explicit assumptions ([Kong and Schoenebeck, “An Information Theoretic Framework for Designing Information Elicitation Mechanisms That Reward Truth-telling,” 2016](https://arxiv.org/abs/1605.01021); [authors’ overview](https://schoeneb.people.si.umich.edu/papers/Framework.html)).

The context translation would ask several agents to report which fragments will matter, then reward reports that predict peers’ reports. This is unsafe as the first borrow. Agents often share the same model, prompt, retrieved evidence, and correlated blind spots; peer agreement can therefore reward a common error. More importantly, agreement is not downstream usefulness. Multiple agents can coordinate—deliberately or through common training—on verbose, salient, or conventional context.

It is **very likely (80-90%)**, based on the shared-model/shared-prompt correlation and the cited mechanisms’ reliance on correlated but meaningfully distinct private signals, that naive peer scoring would overstate evidence independence in a homogeneous agent harness. Testing genuinely heterogeneous models or independently sampled evidence could change that conclusion, but this unit does not recommend paying that complexity cost before direct outcome auditing is attempted.

**Verdict:** Keep peer prediction as a later research branch only if independent signals can be demonstrated. Do not use peer agreement as a proxy for context value.

### 2.3 Strictly proper scoring rules — bounded transfer

This is the one candidate that survives, but with narrower claims than “we solved context allocation.”

## 3. The source mechanism in its own field

A scoring rule assigns a numerical score to a probabilistic forecast after an outcome materializes. Let a forecaster report probability \(q\) for a binary event \(Y\in\{0,1\}\). A score \(S(q,Y)\) is **proper** when a forecaster whose actual belief is \(p\) maximizes expected score by reporting \(q=p\); it is **strictly proper** when that maximizer is unique. Gneiting and Raftery give this definition on general probability spaces, characterize classes of strictly proper rules, and connect them to convex functions, entropy, information measures, and Bregman divergences ([University of Washington report and abstract](https://stat.uw.edu/research/tech-reports/strictly-proper-scoring-rules-prediction-and-estimation); [JASA article DOI](https://doi.org/10.1198/016214506000001437); [paper PDF](https://www.eecs.harvard.edu/cs286r/courses/fall12/papers/Gneiting07.pdf)). Savage’s earlier elicitation treatment relates proper scoring rules to economic devices and subjective probability ([Savage, “Elicitation of Personal Probabilities and Expectations,” 1971](https://www.tandfonline.com/doi/abs/10.1080/01621459.1971.10482346)).

For example, using a loss convention, the binary Brier loss is

\[
L(q,y)=(q-y)^2.
\]

If the true event probability is \(p\), expected loss is

\[
\mathbb{E}[L(q,Y)] = p(q-1)^2+(1-p)q^2 = (q-p)^2+p(1-p),
\]

which is uniquely minimized at \(q=p\). The quadratic term makes exaggerating a 0.6 belief as 0.99 costly across repeated resolved events. A logarithmic loss, \(-y\log q-(1-y)\log(1-q)\), is also strictly proper but is unbounded for confident predictions assigned zero probability. Brier loss is preferable for an initial harness experiment because its bounded range limits the influence of single rare or mislabeled resolutions; this is a design judgment, not a theorem about this harness.

The source-field guarantee is conditional. It assumes, among other things:

1. the scored event and resolution rule are specified before the report;
2. the event later resolves and the outcome is observable;
3. the forecaster maximizes expected score (or a compatible affine utility); and
4. the forecaster cannot alter the event-generation or resolution process after reporting.

Risk preferences and decision-dependent outcomes matter. Properness under expected monetary payoff does not automatically survive arbitrary risk aversion ([Peysakhovich and Plagborg-Møller, “A note on proper scoring rules and risk aversion”](https://www.sciencedirect.com/science/article/pii/S0165176512002984)). This qualification is central to the translation, not a footnote.

## 4. Concrete translation: a context forecast contract

Instead of allowing context producers to say “important,” “critical,” or “remember this,” require a small, typed forecast when they nominate a fragment for retention. The producer reports facts that can later be evaluated:

```text
fragment_id: content hash
kind: instruction | decision | observation | hypothesis | tool-result | provenance
token_cost: measured
resolution_horizon: next_8_actions | current_task | cross_task
p_needed: probability that a defined downstream event will require this fragment
loss_if_missing: bounded ordinal class (1, 3, 10), chosen before outcome
dependencies: fragment IDs needed jointly
expiry_condition: explicit event or horizon
producer: model/skill/hook identity and version
```

“Needed” must not mean “the model mentioned it.” A resolution event should be operational, for example:

* an owner correction cites the omitted fact;
* a test/tool failure is attributable to an omitted constraint;
* the agent retrieves the fragment from the shadow archive before succeeding;
* an evaluator answering from the full trace identifies the fragment as necessary under a predeclared rubric;
* a later action explicitly depends on the fragment’s stable ID and provenance.

The broker may eventually estimate a per-fragment retention value such as

\[
\widehat{V_i}=\operatorname{Calibrate}_{producer,kind,horizon}(p_{needed,i})\times loss_i,
\]

then select under a token budget while honoring hard constraints (system/owner instructions, safety invariants, and dependency closure). Crucially, this formula is only a candidate policy. It is not justified until forecasts are calibrated and the selection-induced censoring described below is measured.

The mechanism-design contribution is not the multiplication or knapsack step. It is the **precommitment to a forecast, a resolution rule, and a score that makes probabilistic honesty optimal under the source assumptions**. This replaces unscored rhetorical salience with an auditable claim.

## 5. What it could catch that common relevance ranking misses

The following are target-level failure classes, not claims about the local harness:

1. **Confidence inflation.** A producer labels many fragments “critical.” Repeated Brier scores expose whether its 0.9 forecasts resolve near 0.9 or near 0.2. It is **very likely (80-90%)**, based on the algebra of the Brier rule when outcomes are validly observed, that repeated overstatement would be visible as poor calibration.

2. **Stale commitments.** A decision receives a high short-horizon forecast but its explicit expiry condition fires. The broker can evict it without relying on lexical recency alone. It is **likely (55-80%)**, based on the typed horizon/expiry representation but not yet on a harness experiment, that this would reduce stale-context persistence.

3. **Quiet but consequential constraints.** A short low-salience instruction with high estimated miss-loss can beat a long, topically similar transcript. It is **likely (55-80%)**, based on separating probability from consequence, that the schema would surface some rare/high-impact items that similarity-only ranking suppresses.

4. **Producer-specific miscalibration.** Tool outputs, planners, summarizers, and models can be calibrated separately by kind and horizon. A producer that is accurate about immediate tool reuse but poor about cross-task memory need not receive one global trust weight. It is **very likely (80-90%)**, conditional on enough resolved events per stratum, that stratified reliability diagrams would expose such differences; sparse strata are a known practical limit.

5. **Self-confirming retention metrics.** “Kept and later mentioned” rewards fragments partly because keeping them made them mentionable. Randomized audits can reveal cases in which an evicted item was later retrieved or judged necessary. It is **almost certain (90-99%)**, from the selective-label structure described in Section 6 and not from local data, that raw use counts alone cannot distinguish usefulness from exposure.

6. **Complement loss.** Explicit dependency IDs can prevent keeping an error message while evicting the command, environment, or instruction required to interpret it. It is **likely (55-80%)**, based on enforcing dependency closure, that declared complements would survive together; undeclared dependencies remain invisible.

7. **Goodhart drift.** Once high `p_needed` wins context, producers may learn or be prompted to emit high probabilities. Proper scoring makes that costly only if scores affect a producer that responds to the score and outcomes are exogenous. The audit would at least show score inflation even when it cannot prevent it.

## 6. The decisive disanalogy: the outcome is selected by the mechanism

The central problem is selective labels. If a fragment is kept, the model can read and cite it; if it is evicted, ordinary logs cannot show whether it would have been useful. The decision determines which outcomes are observed. This matches the selective-label problem in which, for example, repayment is observable only after a loan is granted; learning only from observed labels produces a selected sample ([Kilbertus et al., “Fair Decisions Despite Imperfect Predictions,” 2019](https://arxiv.org/abs/1902.02979); [Lakkaraju et al., “The Selective Labels Problem,” 2017/2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC5958915/)).

For context, “used” is worse than merely censored:

* inclusion can cause use by priming the model;
* exclusion can cause failure, retrieval, workaround, or silent forgetting;
* a successful task does not establish that every retained fragment caused success;
* a failed task does not identify which absent fragment would have prevented failure;
* fragments interact, so their marginal values depend on the selected set;
* summarization changes the treatment rather than simply selecting it.

Therefore, scoring `p_needed` against `mentioned_after_inclusion` is not a proper scoring implementation. The resolution variable is endogenous to the allocation. A producer can obtain good scores by predicting salience or self-citation rather than counterfactual necessity. This is a causal Goodhart failure: optimizing the proxy changes the process that generated its correlation with the goal. Manheim and Garrabrant distinguish regressional, extremal, causal, and adversarial Goodhart mechanisms and emphasize that overoptimization can make a previously useful metric harmful ([“Categorizing Variants of Goodhart’s Law,” 2018](https://arxiv.org/abs/1803.04585); [authors’ summary](https://intelligence.org/2018/03/27/categorizing-goodhart/)).

There is a second disanalogy: an LLM call has no persistent balance sheet and need not maximize expected future Brier score. Merely printing a score after a run supplies no incentive. Scoring rules can still be used as statistically principled losses to train or select a context predictor offline, or as feedback included in future prompts, but strict incentive compatibility does not follow. It is **unlikely (20-45%)**, based on the lack of persistent utility and without an experiment on model behavior, that displaying scores alone would materially calibrate an untrained base model over a long horizon.

There is a third disanalogy: the forecast target is underspecified. “Will be needed” depends on the task policy, available tools, retrieval latency, acceptable risk, and alternative context. A fact can be unnecessary under one plan and essential under another. Strict propriety applies only after a single event definition is fixed; it cannot decide which construct the harness ought to value.

## 7. Recommendation — UNVERIFIED: run Experiment X087-A before policy activation

**UNVERIFIED — Experiment X087-A (Randomized Shadow Context Trial) is required to settle whether scoreable context-necessity outcomes can be generated with acceptable noise.**

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Build one narrow audit hook or script, not a broker daemon. It should ride the existing pre-compaction/context-assembly and post-task/evaluation bus and append JSONL records to an experiment log. No second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed.

The experiment:

1. At each eligible context-assembly boundary, hash candidate fragments and record token cost, producer, kind, horizon, `p_needed`, bounded `loss_if_missing`, dependencies, and the proposed keep/evict decision.
2. Preserve all candidates in a **shadow archive outside the model-visible prompt** for the duration of the trial. This is an audit store, not durable semantic memory; plain content-addressed files or JSONL are sufficient.
3. Define hard pins that are never randomized: system/owner instructions, security/safety constraints, current user request, and any item whose omission could cause irreversible external action. Experiment only on ordinary working context.
4. In a small eligible stratum, randomly flip marginal keep/evict decisions near the policy threshold. Log the assignment probability. Randomization is essential because it supplies variation independent of the forecast and enables inverse-propensity or paired comparisons.
5. Expose an explicit `retrieve_shadow(fragment_id or query)` path. Retrieval is observable evidence that excluded context became useful, although retrieval alone is not proof of counterfactual necessity.
6. At predeclared horizons, resolve multiple outcome fields rather than one proxy: explicit retrieval; attributable owner correction; test/tool failure tied to omitted information; full-trace evaluator judgment; task success; latency/token overhead. Keep these fields separate.
7. Compute Brier loss and reliability diagrams by producer × kind × horizon. Also estimate downstream regret between randomized arms. Do not feed scores into live selection during the measurement phase.
8. Manually adjudicate a stratified sample of positive and negative resolutions, blinded to the forecast where practical. Record inter-rater disagreement rather than forcing consensus.
9. Predeclare activation gates: sufficient sample size; acceptable label agreement; no material increase in severe failures; calibration improvement over simple baselines; and downstream task benefit net of token/retrieval cost.

The shadow archive is necessary because it preserves what the model did not see and permits later retrieval or evaluator inspection. Randomization is necessary because a deterministic selector creates selective labels. Neither eliminates all counterfactual ambiguity, but together they create a materially stronger signal than post-hoc self-citation.

It is **likely (55-80%)**, based on established selective-label methodology and the availability of pre-decision forecasts, that X087-A would reveal whether some producer/kind/horizon forecasts are calibratable. It is only **roughly even (45-55%)**, because “necessity” is policy-dependent and complement-heavy, that calibrated fragment-level forecasts would improve end-to-end task success after token and retrieval costs. These are explicitly forward-looking estimates; X087-A is the settling experiment.

## 8. Activation policy if and only if X087-A passes

**UNVERIFIED — Experiment X087-B (Silent Replay Selection Trial) must settle whether calibrated forecasts improve held-out context choices before live enforcement.**

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** If X087-A produces reliable labels, configure the existing context assembly path to consume calibration tables and emit a proposed selection in shadow mode. Do not add a new runtime.

Use a lexicographic policy rather than a single maximized score:

1. pin non-negotiable instructions and irreversible-action constraints;
2. maintain dependency closure for selected items;
3. allocate a small reserve for exploration/audit and for emergency retrieval;
4. select remaining items using calibrated expected miss-loss per token, with diversity or coverage constraints;
5. retain provenance pointers even when payloads are summarized;
6. compare the proposed selection against the existing policy on held-out traces without changing the live prompt.

Do not collapse outcomes into a single “context quality” KPI. Maintain a scorecard: calibration, severe omission rate, retrievals, task success, token spend, latency, owner corrections, and evaluator disagreement. This is the Goodhart defense: no one proxy gets unilateral control, and randomized audits continue after activation.

It is **likely (55-80%)**, conditional on X087-A finding stable calibration and X087-B beating baselines, that a calibrated expected-miss-loss feature would be useful as one input to the existing selector. It is **very unlikely (5-20%)**, based on the endogeneity and complementarity arguments above, that it would safely serve as the sole selection objective.

## 9. Baselines and falsification criteria

The idea earns complexity only if it beats cheap baselines. X087-A/X087-B should compare against:

* recency with hard instruction pins;
* lexical or embedding relevance per token;
* simple hand-set type quotas;
* a model ranking candidates without probabilities;
* a model assigning probabilities but no scoring/calibration;
* an oracle-style full-trace evaluator used only for retrospective upper-bound analysis.

Falsify the proposal, and stop, if any of the following occurs:

* outcome labels have low agreement or cannot be specified without looking at forecasts;
* randomized omission causes unacceptable severe failures even in the eligible low-risk stratum;
* forecasts collapse to a narrow probability range and fail to discriminate outcomes;
* calibration does not transfer across tasks, models, or horizons;
* a recency/relevance baseline matches downstream performance at lower complexity;
* the scorer rewards mention/self-citation without reducing corrections or failures;
* dependency interactions dominate fragment-level effects;
* audit and retrieval overhead consumes the token/latency savings.

It is **likely (55-80%)**, based on the strong structural disanalogies, that at least one naive formulation—especially scoring against later mention—would fail these tests. That failure would be useful: it prevents an attractive mechanism-design metaphor from hardening into unjustified architecture.

## 10. Goodhart analysis of the proposed mechanism itself

The scorer is also a target and must be threat-modeled.

### Regressional Goodhart

Selecting only the highest predicted values amplifies forecast noise. Mitigation: calibrate out of sample, shrink sparse strata toward base rates, and retain exploration. The effectiveness of shrinkage here is **likely (55-80%)**, supported by standard calibration logic but UNVERIFIED for this target; X087-A’s held-out reliability analysis settles it.

### Extremal Goodhart

The highest scores may arise in task regimes unlike the calibration set. Mitigation: require minimum support, display uncertainty intervals, and fall back to simple pins/recency out of distribution. It is **very likely (80-90%)**, based on distribution-shift logic and the cited Goodhart taxonomy, that unbounded extrapolation from sparse strata would be unsafe.

### Causal Goodhart

Keeping a fragment causes it to be read and cited, corrupting “use” as a label. Mitigation: shadow archive, randomized assignment, distinct outcome fields, and no training on self-citation alone. It is **almost certain (90-99%)**, from the decision-dependent observation structure, that this mitigation is necessary; it is **unlikely (20-45%)**, because causal identification remains incomplete with interacting fragments, that it fully resolves the issue.

### Adversarial Goodhart

A context producer could maximize retention by emitting inflated forecasts, splitting one fact into many fragments, attaching itself as a dependency, or predicting the evaluator’s rubric. Mitigation: score at the producer and episode level, deduplicate content hashes, cap total nominated tokens, penalize dependency cycles, blind adjudicators, and rotate outcome audits. It is **likely (55-80%)**, based on these obvious gaming channels, that a sufficiently optimized producer would find a loophole in any fixed single metric.

## 11. Why this is minimal rather than timid

The proposal is ambitious in measurement but small in architecture. It changes context claims from adjectives into resolved probabilistic contracts, introduces randomized causal audits, preserves excluded evidence for counterfactual inspection, and makes producer-specific calibration measurable. Yet it does not replace the harness with a context economy or a new memory service.

This meets the anti-overfit gate:

* it rides existing hook/skill/MCP boundaries;
* the first build is one append-only audit hook/script under roughly 200 lines;
* storage is plain JSONL/content-addressed files, not a vector DB or KG;
* selection remains in the existing context path;
* activation occurs only after silent replay beats simple baselines;
* failure of the experiment leads to deletion/non-activation, not escalation into a larger runtime.

A radical replacement is not supported by this lens. The source mechanism supplies a disciplined experiment and a scoring loss, not a context operating system.

## 12. Final assessment

**Transfer verdict: partial, conditional, and worth testing.**

The portion that transfers is precise: before allocation, elicit probabilistic claims about operationally defined future events; after independently observable resolution, use a strictly proper score to measure calibration; compare producers and horizons; use calibrated forecasts only as one bounded input under a token budget.

The portion that does not transfer is equally important: there is no truthful procurement auction without strategic sellers and private costs; there is no strict-propriety guarantee when the allocation determines the outcome, when the producer cannot be said to maximize score, or when “needed” lacks a fixed resolution rule. Calling an LLM’s importance number a bid does not create incentive compatibility.

The recommended research path is **BUILD-SMALL**, experimental, and reversible. It is **likely (55-80%)**, on the combined evidence from proper scoring rules and selective-label research, to produce useful calibration diagnostics. It is only **roughly even (45-55%)**, pending X087-A and X087-B, to improve live long-horizon context allocation enough to justify permanent complexity. That uncertainty is the correct output of the analogy rather than a reason to force a stronger conclusion.
