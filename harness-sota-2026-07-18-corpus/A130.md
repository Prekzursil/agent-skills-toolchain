## Finding 1 — `/context-budget` calculates against the wrong configured window

### Both authorities, verbatim

Command authority, `C:\Users\Prekzursil\.claude\commands\context-budget.md:22-26`:

> Run the **context-budget** skill (`skills/context-budget/SKILL.md`) with the following inputs:
>
> 1. Pass `--verbose` flag if present in `$ARGUMENTS`
> 2. Assume a 200K context window (Claude Sonnet default) unless the user specifies otherwise
> 3. Follow the skill's four phases: Inventory → Classify → Detect Issues → Report

Settings authority, `C:\Users\Prekzursil\.claude\settings.json:77-80`:

> "model": "opus[1m]",
> "fallbackModel": [
>   "claude-sonnet-5"
> ]

Settings authority, `C:\Users\Prekzursil\.claude\settings.json:684-687`:

> "outputStyle": "Honest",
> "effortLevel": "xhigh",
> "autoCompactWindow": 1000000,
> "autoUpdatesChannel": "latest",

### Concrete collision

Invoke `/context-budget` without an explicit window. The command mandates a 200K denominator. The configured starting model is `opus[1m]`, for which Claude Code’s current model documentation defines a 1,000,000-token context window. The command therefore reports every fixed token cost as five times its actual percentage of the configured context window. For example, a 20,000-token inventory is reported as 10% instead of 2%. Threshold-based recommendations can consequently fire when the configured session has ample room.

This is not merely a stale explanatory label. Line 25 is an imperative input to the skill and directly changes its calculations. The settings and command independently state the effective context basis, and they disagree.

### Which wins at runtime

**The settings/runtime model wins for the actual API context; the command wins inside the generated audit report.** Claude Code starts a new ordinary session on the `model` setting unless a higher-priority launch/session selection applies. Official docs identify `opus[1m]` as the one-million-token alias. Loading `/context-budget`, however, injects the command’s instruction into the model context, so the report uses 200K unless the user overrides it. The result is a split-brain runtime: one-million-token execution with a 200K accounting report.

Resumed sessions and explicit `/model`, `--model`, or `ANTHROPIC_MODEL` selections can override the settings start value. That does not rescue the command; it demonstrates why any hard-coded model/window assumption in the command is the wrong authority.

### Minimal resolution

**NATIVE (Claude Code already does this; we just enable it).** Replace only `commands/context-budget.md:25` with:

> 2. Read the active model and context-window size from `/status` or `/context`; use that runtime value. If it cannot be determined, ask the user rather than assuming 200K.

If `/status` or `/context` output is not programmatically available to the skill, use this minimally weaker text:

> 2. Read `model` from `~/.claude/settings.json` and resolve its documented context size; explicit session model selections override settings. If the active session model cannot be determined, label the denominator UNVERIFIED and ask the user.

The first edit is preferred because it removes duplicate authority rather than synchronizing a second constant. It rides the native command/skill bus and adds no component. It passes the anti-overfit gate.

Confidence: **almost certain (90-99%)**, based on the exact command imperative, exact settings model, settings’ matching 1,000,000 value, and official model-alias documentation. The residual uncertainty is only whether an individual invocation has a higher-priority session model override; that changes the correct denominator but never makes the hard-coded 200K authority sound.

## Finding 2 — `/pm2` requires a port source that permissions forbid reading

### Both authorities, verbatim

Command authority, `C:\Users\Prekzursil\.claude\commands\pm2.md:29`:

> **Port Detection Priority**: User specified > .env > config file > scripts args > default port

Settings authority, `C:\Users\Prekzursil\.claude\settings.json:64-71`:

> "deny": [
>   "Read(./.env)",
>   "Read(**/.env)",
>   "Read(**/*.pem)",
>   "Read(**/*.credentials*)"
> ],
> "ask": [],
> "defaultMode": "bypassPermissions",

The settings also globally allow `Read` and `Bash` at `settings.json:30` and `settings.json:35`, but deny-first evaluation makes those broad allows irrelevant to `.env`.

### Concrete collision

Invoke `/pm2` in a repository whose service port exists only in `.env`, with no port in the user arguments. The command says `.env` is the next source and must outrank config, script arguments, and defaults. A normal `Read(.env)` call is denied. Current Claude Code also recognizes ordinary Bash readers such as `cat`, `head`, `tail`, and `sed` and applies Read denies to them. The command cannot fulfill its stated detection priority through the normal file-reading paths.

This collision actually arises whenever `.env` is the sole or highest-priority non-user port source; it is not hypothetical configuration overlap. It can yield either a blocked call or a silently wrong fallback port, depending on whether the model treats the denial as terminal or continues down the priority chain.

### Which wins at runtime

**The settings deny wins.** Anthropic documents deny-before-ask-before-allow evaluation and states that permission rules are enforced by Claude Code rather than by prompt instructions. `bypassPermissions` skips prompts; it does not override explicit deny rules. Thus `/pm2` cannot authorize the prohibited read.

An arbitrary subprocess could evade a Read deny according to the official limitation on recognized file access. That is not a legitimate winner for the command: relying on an evasion would defeat the credential boundary and create a more severe harness defect.

### Minimal resolution

**CONFIG (settings/JSON only)** would mean removing the `.env` deny, but that would weaken a global secret-control boundary merely to support one convenience command. I reject that edit.

**BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** The actual minimal safe edit is prose-only and substantially below the tag’s ceiling: replace `commands/pm2.md:29` with:

> **Port Detection Priority**: User specified > `.env.example` / `.env.sample` > config file > scripts args > default port. Never read `.env`; if only `.env` can supply the port, ask the user for the port.

This resolves the duplicate authority in favor of the existing security boundary, remains on the command bus, and introduces no runtime. It passes the anti-overfit gate.

Confidence: **almost certain (90-99%)**, supported independently by the exact command priority, the two `.env` deny patterns, the configured bypass mode, and official deny/runtime documentation.

Settings say Claude Code should enable `metaswarm@metaswarm-marketplace`; the command’s path-only detector declares the components absent and executes `npx metaswarm install`. ### Which wins at runtime

There are two runtime phases:

1. **Claude Code plugin loading:** settings/plugin registry wins. Official docs define `enabledPlugins` as the enablement control and `claude plugin list` as the installed/version/source/enable-status inventory.
2. **The `/metaswarm-setup` decision after invocation:** the command’s Glob branch wins because the model is explicitly told to use that path as the install test. It can therefore contradict the already-loaded plugin state and invoke the independent npm installer.

This is precisely duplicate authority: the platform registry controls loading, while a prompt-level directory convention independently controls “installed” truth.

### Minimal resolution

**NATIVE (Claude Code already does this; we just enable it).** Replace `metaswarm-setup.md:17-30` with a native registry check:

If installed but disabled, ask before running `claude plugin enable metaswarm@metaswarm-marketplace`. If absent, ask before running `claude plugin install metaswarm@metaswarm-marketplace`. Do not infer marketplace-plugin state from `.claude/plugins/metaswarm/`, and do not run `npx metaswarm install` for a marketplace installation.

This removes the legacy directory as an authority and uses Claude Code’s existing plugin bus. It introduces no new runtime and passes the anti-overfit gate.
