It does **not** mean that the cited text entails the finding.

## Sampling and detector contract

### Population

The syntactic census scanned all 136 supplied finding files and extracted 3,691 path-like backtick citations from 131 files. The other five files may contain commands, URLs, or prose evidence but no token matching this unit’s `file:line` grammar; no claim is made that they contain no evidence.

The extraction grammar was:

```regex
`([^`\n]+?):(\d+(?:-\d+)?(?:,\d+(?:-\d+)?)*)`
```

A match was retained as path-like only if the path portion contained a slash/backslash or ended in a plausible filename extension. This intentionally accepts compact line sets such as `file.py:50-99,725-798`. It intentionally does not infer bare shorthand such as a later ```:75``` token, prose command output, URL anchors, Git revisions, or a path outside backticks. Consequently, 3,691 is an extraction population, not a count of every evidentiary reference.

## Failure modes

### 1. Line-number drift — confirmed

Three records in the 74-record boundary sample are confirmed stale at their literal lines.

**Agent-mail drift.** B10 claims that `.codex/config.toml:596-598` enables `agent-mail` at `/local_disk0/codexwork/bundle/inputs/audit-findings/B10.md:28-35`. Those current lines define disabled Semgrep at `/local_disk0/codexwork/bundle/codex/config.toml:596-600`; the intended `agent-mail` block exists at `/local_disk0/codexwork/bundle/codex/config.toml:617-619`. This is almost certain (90-99%) line-number drift rather than an invented feature because the claimed URL and server name both exist 21 lines later in the same file.

**Thread-count drift.** B16 says `.codex/config.toml:122-124` enables eight threads at `/local_disk0/codexwork/bundle/inputs/audit-findings/B16.md:64-67`. Those lines contain `current_time_reminder`, `item_ids`, and a blank line at `/local_disk0/codexwork/bundle/codex/config.toml:122-124`; `multi_agent_v2` and `max_concurrent_threads_per_session = 8` exist at `/local_disk0/codexwork/bundle/codex/config.toml:125-127`. This is almost certain (90-99%) three-line drift because the exact claimed key/value pair is adjacent.

**Mixed memory citation drift.** D18 claims that `.codex/config.toml:103,380-383,461-464` enables memories, generation, and Basic Memory at `/local_disk0/codexwork/bundle/inputs/audit-findings/D18.md:9-12`. Line 103 does enable `memories`; however, image generation is at `/local_disk0/codexwork/bundle/codex/config.toml:114`, lines 380-383 are plugin entries, lines 461-464 are a blank line plus GitHub connector approval entries, and Basic Memory begins at `/local_disk0/codexwork/bundle/codex/config.toml:473`. This record is only partially located correctly. It is very likely (80-90%) multi-edit drift because all named concepts still exist in the same file, but the absence of a source revision prevents proving when the mismatch arose.

An additional drift case outside the 74-record boundary sample was discovered while testing failure classification: A27 cites the Codex Semgrep block at lines 575-579 (`/local_disk0/codexwork/bundle/inputs/audit-findings/A27.md:56-63`), but those current lines define Frida (`/local_disk0/codexwork/bundle/codex/config.toml:575-579`) and Semgrep is at 596-600. This corroborates repeated drift within the same mutable TOML file; it is not added to the 3/74 numerator because it was found outside the predeclared boundary sample.

Cost: the drift detector reads the cited file and, on anchor mismatch, searches that one file for quoted identifiers. It catches moved line ranges at O(file size) per unique file. Exact false-positive rate for an anchor mismatch is zero if the artifact declares the literal expected anchor; an automatically inferred anchor can false-fire on paraphrase or repeated keys, so those cases must be reported as ambiguous rather than failed.

### 2. Wrong line — confirmed, but cause is not identifiable

At evaluation time the stale examples above are wrong-line citations: a reader opening the literal ranges sees unrelated configuration. The available evidence cannot partition “wrong when authored” from “correct when authored, later drifted,” because findings cite a mutable absolute path with no Git commit, file hash, modification timestamp, or quoted anchor. Calling them hallucinations would exceed the evidence.

The resolver therefore needs two distinct statuses:

- `LINE_EXISTS_ANCHOR_MISMATCH`: the line exists, but required anchor text does not.
- `ANCHOR_RELOCATED`: the required anchor occurs uniquely elsewhere in the same revision.

The second status preserves useful evidence while making the stale pointer visible. A generic `PASS` for any in-bounds line is demonstrably unsound.

### 3. Moved or mirrored file — candidates, not confirmed moves

Of the 345 mapped-but-absent sample records, a conservative suffix search found 12 unique candidate destinations; one two-component `hooks.json` match was rejected as provider-ambiguous, leaving 11 strong relocation/mirror candidates. Examples include:

- Canonical `source\agent-skills-toolchain\hooks\semantic-router\route.py:295-336` cited at `/local_disk0/codexwork/bundle/inputs/audit-findings/A24.md:25`, with a matching three-component live path at `/local_disk0/codexwork/bundle/claude/hooks/semantic-router/route.py:295-336`.
- Canonical `source\agent-skills-toolchain\hooks\per-edit-check\check.py` cited at `/local_disk0/codexwork/bundle/inputs/audit-findings/A36.md:76`, with the live mirror at `/local_disk0/codexwork/bundle/claude/hooks/per-edit-check/check.py:8-16` and `:151-169`.
- Canonical `source\agent-skills-toolchain\hooks\harness-bench\test_bench.py` cited at `/local_disk0/codexwork/bundle/inputs/audit-findings/F08.md:25`, with the live path at `/local_disk0/codexwork/bundle/claude/hooks/harness-bench/test_bench.py:4-8`.

These are **UNVERIFIED mirror candidates**: the experiment that settles identity is to obtain the canonical repository snapshot at the finding’s revision and compare SHA-256 (or Git blob IDs) to the live files. A matching suffix alone is not identity, and a deployed copy can be newer or older than canonical source. None is counted as resolved.

Cost: suffix relocation is cheap, but generic filenames create false candidates. In this sample, a two-component suffix rule proposed `claude/hooks/hooks.json` for a versioned plugin’s `hooks/hooks.json`, an obviously unsafe provider/version collapse. Requiring at least three stable trailing components eliminated that observed false match; UNVERIFIED false-positive rate for the three-component rule, with the settling experiment being hash comparison over every proposed source/destination pair.

### 4. Invented path — zero confirmed; 333 unresolved/no-suffix records

The sample has 333 mapped-but-absent records with no unique two-to-four-component suffix destination in the bundle. **Zero are classified as invented.** Many cite deliberately unshipped categories such as credential stores, transcripts, session rollouts, skill trees, backups, state ledgers, or the entirely absent canonical repository. For example, F01 cites Codex history and Claude project transcripts at `/local_disk0/codexwork/bundle/inputs/audit-findings/F01.md:20-22`; those sensitive trees are not in the bundle, so their absence cannot adjudicate the claims.

UNVERIFIED whether any of the 333 paths were invented; the settling experiment is a revision-aware Windows-side `Test-Path -LiteralPath` plus `git cat-file -e <revision>:<repo-relative-path>` for repository citations, followed by a parent-directory inventory when absent. Even that experiment establishes existence, not whether the cited content supports the claim.

Cost: a complete-source existence test is essentially free. On this incomplete bundle, treating absence as invention would have a potentially enormous false-positive count—up to all 333 no-suffix cases—so the resolver must emit `SNAPSHOT_UNAVAILABLE` rather than `PATH_INVENTED` when coverage metadata does not assert that the parent tree is complete.

### 5. Unresolvable shorthand and parser ambiguity

Ninety-nine sample records were relative or otherwise non-absolute. Some are legitimate context-dependent shorthands (for example a subsequent `tests\...:line` after an absolute path); others are false-positive path shapes such as an IP address ending in `:port`. This unit excludes them from the strict absolute denominator rather than guessing a base path.

A production resolver needs a Markdown-aware citation grammar that carries forward a base path only within the same evidence clause and rejects URL/host/port patterns. UNVERIFIED accuracy of such context carry-forward; the settling experiment is a hand-labeled set of all 99 sample records scored for precision and recall before enabling automatic resolution.

## Semantic groundedness ceiling

Mechanical citation health has four layers:

1. **Path existence:** does the referenced artifact exist in the declared snapshot?
2. **Location validity:** do the referenced lines exist?
3. **Anchor identity:** do those lines contain the identifiers or quoted content the finding says they contain?
4. **Claim support:** does the evidence, possibly with other cited evidence, logically support the natural-language claim?

This unit measures layers 1–2 for the full syntactic census and primary sample, and samples obvious failures at layer 3. It does not claim a layer-4 entailment score. A path can exist, a line can be valid, and an anchor can be present while the conclusion remains misleading—for example through omitted context, negation, version mismatch, cherry-picked output, or a non-independent corroborating signal.

Therefore the honest target is **detectability, not elimination**:

- A path resolver catches nonexistent and unpackaged evidence, but not a plausible wrong claim.
- A line-bound checker catches out-of-range pointers, but not stale pointers whose line numbers remain valid.
- An anchor checker catches many stale pointers, but not a citation that quotes the right token in the wrong semantic context.
- A model or rule-based entailment checker can triage possible non-support, but introduces judgment errors and correlated hallucination. It cannot be the sole verifier.
- A revision-pinned artifact package makes later re-resolution reproducible, but it does not make the original interpretation correct.

## Proposals

### Proposal 1 — revision-pinned citation receipt: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

Add a small local citation-check script invoked by the existing completion/verification hook bus. For every citation it emits a receipt containing:

```json
{
  "source_finding": "B10.md:31",
  "target_logical_root": "CODEX",
  "target_relative_path": "config.toml",
  "source_revision_or_snapshot_id": "...",
  "target_sha256": "...",
  "requested_lines": "596-598",
  "anchor": "mcp_servers.\"agent-mail\"",
  "status": "ANCHOR_RELOCATED",
  "resolved_lines": "617-619"
}
```

It catches exact-path absence, line overflow, hash/revision mismatch, and unique anchor relocation. It does not catch invalid inference from valid text. Runtime cost is one read/hash per unique cited file plus small JSON output. It is **likely (55-80%)** that a first implementation fits under 200 lines because path normalization, line parsing, SHA-256, and exact/unique anchor search are standard-library operations; the evidence is the deliberately narrow contract above. UNVERIFIED hook payload and best insertion point; the settling experiment is to capture one real completion-hook input and confirm it contains the output artifact path before selecting Stop versus a verification command.

False-positive policy: path/line/hash checks have zero semantic false positives relative to the declared snapshot, while anchor inference must return `AMBIGUOUS` rather than failure when the anchor is absent, repeated, or synthesized from prose. No automatic claim rejection follows from `AMBIGUOUS`.

### Proposal 2 — bundle coverage manifest and tri-state absence: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

Extend the existing batch bundle producer to write a coverage manifest with included logical roots, excluded patterns, source revision/snapshot timestamp, file count, and a path/SHA-256 list. The resolver then emits `ABSENT_IN_COMPLETE_ROOT`, `SNAPSHOT_UNAVAILABLE`, or `PRESENT`; it never converts the second status to “invented.”

This catches the exact ambiguity that currently affects 345 sample citations and blocks the false inference that the unshipped 157-file repository citation set is hallucinated. It does not catch a path invented inside an explicitly excluded tree. Cost is one linear directory walk at packaging time and a compact manifest. It is **very likely (80-90%)** to prevent the largest false-positive class in this unit because every current missing citation can then be conditioned on declared coverage; evidence is the observed difference between 56.4% strict portability and 74.6% supplied-root-conditional resolution. UNVERIFIED manifest size and Windows collection time; the settling experiment is to generate it once on the source box and record elapsed time and compressed bytes.

### Proposal 3 — require anchors for mutable non-repository files: CONFIG (settings/JSON only)

Change audit-unit output instructions so a citation to a mutable configuration, JSONL, settings file, or transcript must include either a short quoted anchor or a content digest; repository citations must include a Git revision. Example: `CODEX/config.toml@sha256:<prefix>:617-619 anchor='[mcp_servers."agent-mail"]'`.

This catches the B10, B16, A27, and D18 drift class at review time. It does not catch a semantically irrelevant but correctly quoted anchor. Author cost is a short anchor per cited region; machine cost is negligible. It is **very likely (80-90%)** that explicit anchors improve drift detectability because all four confirmed examples retain their intended token elsewhere in the current file; the evidence is the exact relocations documented above. UNVERIFIED compliance and token overhead across agents; the settling experiment is a 20-unit A/B run measuring anchor-field compliance, additional tokens, resolver pass rate, and author correction rate.

### Proposal 4 — semantic review remains sampled and independent: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

After mechanical checks, randomly sample mechanically green citations for human or fresh-context review of claim support. Record `SUPPORTED`, `PARTIAL`, `UNSUPPORTED`, or `INDETERMINATE`, with the evidence excerpt included. Do not let the authoring agent grade its own claim as the only signal.

This catches contextual mismatch, negation, and overclaim that path/line/anchor checks cannot. It costs reviewer/model tokens proportional to sample size and has a nonzero judgment false-positive rate. It is **likely (55-80%)** that a small stratified sample finds high-value semantic defects without turning the harness into a critic runtime; evidence is that a 74-record boundary scan found three obvious location mismatches after all 553 exact pointers passed line bounds. UNVERIFIED semantic-review false-positive rate; the settling experiment is double-blind adjudication of 100 citations by two independent reviewers, reporting agreement and resolving disagreements manually.

### Anti-overfit gate

All four proposals ride the existing batch, hook, or verification bus. They do not introduce a second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. No `BUILD-LARGE` component is justified by this baseline. A compact resolver plus manifest is preferable because stronger models do not remove filesystem drift, while an elaborate semantic-critic service would add correlated judgment failure without proving truth.

## Acceptance baseline for later resolver work

A later unit may claim improvement only if it reruns the same seed/sample and publishes all denominators. Minimum acceptance report:

1. `N_files_available`, roster by prefix, and missing expected files.
2. `N_extracted`, `N_absolute`, `N_relative`, and parser version.
3. Exact-path, in-bounds-line, anchor-match, anchor-relocated, ambiguous, snapshot-unavailable, and confirmed-unsupported counts.
4. Resolution rates both strict and coverage-conditional.
5. Known-positive controls and one known-negative/drift fixture.
6. False-positive rate on a hand-labeled citation set; do not call `SNAPSHOT_UNAVAILABLE` a citation failure.
7. Source revision/hash so line drift is reproducible.

## Reproduction

The following is a compact equivalent of the resolver used for the baseline. It is read-only and uses no third-party package:

```python
import collections, pathlib, random, re

ROOT = pathlib.Path("/local_disk0/codexwork/bundle")
FINDINGS = ROOT / "inputs/audit-findings"
PAT = re.compile(r"`([^`\\n]+?):(\\d+(?:-\\d+)?(?:,\\d+(?:-\\d+)?)*)`")
MAPS = [
    (r"C:\Users\Prekzursil\.claude", ROOT / "claude"),
    (r"C:\Users\Prekzursil\.agents\harness", ROOT / "agents/harness"),
    (r"C:\Users\Prekzursil\.codex", ROOT / "codex"),
    (r"C:\Users\Prekzursil\source\agent-skills-toolchain", ROOT / "repo"),
]
QUOTAS = {"A": 12, "B": 6, "C": 6, "D": 9, "E": 5, "F": 4}

population = sorted(FINDINGS.glob("[A-F][0-9][0-9].md"))
groups = collections.defaultdict(list)
for path in population:
    groups[path.stem[0]].append(path)
rng = random.Random(20260719)
sample = sorted(sum((sorted(rng.sample(groups[k], q)) for k, q in QUOTAS.items()), []))

counts = collections.Counter()
for source in sample:
    text = source.read_text(errors="replace")
    for match in PAT.finditer(text):
        raw, locator = match.groups()
        if not (re.search(r"\.[A-Za-z0-9_-]{1,8}$", raw) or "\\" in raw or "/" in raw):
            continue
        counts["pathlike"] += 1
        mapped = None
        for windows_root, local_root in MAPS:
            if raw.lower().startswith(windows_root.lower() + "\\"):
                relative = raw[len(windows_root):].lstrip("\\").replace("\\", "/")
                mapped = local_root / relative
                break
        if mapped is None:
            counts["unmapped"] += 1
            continue
        endpoints = [int(n) for part in locator.split(",") for n in part.split("-")]
        if not mapped.is_file():
            counts["missing_exact"] += 1
            continue
```
