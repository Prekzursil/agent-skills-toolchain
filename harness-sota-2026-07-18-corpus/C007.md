# C007 — Context lifecycle and session-start context budget

## Executive verdict

The harness has two materially different context-budget states.

1. **Codex skill discovery is currently collapsed.** The exact model-visible packet in the current Codex 0.144.6 session contains 287 skills, 21,823 characters, and **zero descriptions**. A mechanically independent Codex SQLite renderer record from 2026-07-19 reports 505 eligible skills, 280 included, 225 omitted, with all 505 descriptions truncated. This is an active routing defect, not a source-size estimate. Confidence: **almost certain (90-99%)** — the direct model-visible prompt and renderer telemetry are independent runtime signals and agree on the failure mode.

2. **Claude's latest component-level native measurement (2026-07-12, Claude Code 2.1.207) ranked active session context as memory files 21.3k tokens, skills 19.8k, system tools 9.2k, system prompt 4k, custom agents 2.4k, and active MCP tools 2.2k.** It separately reported 421.1k tokens of deferred MCP schemas and 12.7k of deferred system tools; those deferred schemas were not counted against free active context. Confidence: **almost certain (90-99%)** — these are Claude Code's own `/context` values captured in the real transcript, not four-characters-per-token conversions.

3. **Claude's exact current component split is UNVERIFIED; a fresh Claude Code 2.1.215 `/context all` immediately after the first prompt would settle it.** The current minimal canary answered a 17-character prompt with 766,574 cache-creation input tokens, but API-accounted/cache tokens are not interchangeable with model-active context: Anthropic documents that deferred tool definitions are sent in the request but excluded from the initial system prompt and context until discovered. The canary proves a huge request prefix/accounting surface; it does not identify which parts occupy the active window. Confidence: **almost certain (90-99%)** on the 766,574-token observation and **roughly even (45-55%)** on whether most of it occupied active context — the transcript gives the aggregate, while official deferred-tool semantics prevent attribution.

4. **The prior “skill overflow caused naïve sessions” diagnosis is only partly verified.** Historical overflow itself is real: a 2026-06-04 Claude `skill_listing` contains 1,217 entries, of which 1,206 are name-only, and the real vault records an earlier `/doctor` warning that 329 skill descriptions were dropped. However, “caused naïve sessions” remains **UNVERIFIED; a randomized routing A/B over representative tasks, comparing useful-description visibility with skill selection and owner corrections, would settle causality.** The corpus has capability counts but no paired session-quality outcome for this hypothesis. Confidence that overflow impaired discoverability: **very likely (80-90%)** — trigger semantics were absent. Confidence that it was the principal cause of naïve behavior: **likely (55-80%)** — the mechanism and owner observation align, but no causal experiment exists.

5. **Memory replay is not the dominant fresh-start consumer.** In the current 2.1.215 fresh canary, all `SessionStart` additional context totaled 4,027 characters: 623 characters of health/open-loop replay, 3,276 characters of a full `using-superpowers` bootstrap, and 128 characters of a metaswarm reminder. The actual objective replay was therefore much smaller than the 21.3k-token always-loaded memory-file category measured by `/context`. On a resume/compact path, objective-ledger plus health/open-loop replay reached 3,251 characters in one real event. Confidence: **almost certain (90-99%)** — payload boundaries and lengths were parsed from `hook_additional_context` records.

The highest-leverage architecture is therefore not a second router, a vector/KG memory, or a new orchestration runtime. It is to restore useful native skill descriptions, reduce always-loaded native memory, prove full MCP deferral with a fresh canary, and cap duplicate hook additions on the existing settings/skill/hook buses.

### Token terms kept separate

This distinction is necessary because the host exposes three different quantities:

- **Active context tokens:** content Claude Code `/context` says occupies the model's usable context window.
- **Deferred-schema tokens:** the size Claude Code reports for schemas discoverable through tool search but not active until selected.
- **API input/cache tokens:** `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` in the response usage block. These are exact request-accounting numbers, but they cannot be assumed to equal active context when deferred tools are present.

For Codex component rows, `o200k_base` counts are labeled **local tokenizer proxy**. The only exact server-side Codex number available is the aggregate first-call `input_tokens`. Codex's own skill renderer separately uses an approximate bytes/4 budget; that budget is a runtime fact but is not billed-token equivalence.

## Context lifecycle model

1. **Before first prompt:** system prompt, output style, global/project CLAUDE/AGENTS, unscoped rules, native auto memory, skill names/descriptions, MCP names/server instructions, always-loaded tools, and custom-agent metadata enter or are registered with the request.
2. **SessionStart:** external hooks run; only returned `additionalContext` enters the model. Current clean-start payload is 4,027 characters, mostly an eager skill bootstrap.
3. **First UserPromptSubmit:** bounded lexical memory recall may add roughly 0.5-1.3k characters in observed orchestration turns.
4. **Tool discovery:** deferred tool schema enters context only when tool search returns its reference.
5. **Skill invocation:** full skill body loads on demand; it is a different budget from the startup listing.
6. **File reads:** path-scoped rules/nested instructions load when their trigger path is read.
7. **Compaction:** system/output style survive; root CLAUDE/unscoped rules/auto memory re-inject; invoked skill bodies re-inject under caps; path-scoped rules wait for a new matching read.
8. **Resume/clear:** SessionStart replay may include more ledger/open-loop text than a fresh start; today it lacks a measured percentile budget.

This lifecycle explains why “shrink CLAUDE.md” alone is insufficient and why “MCP has 421k tokens” is also misleading: different components enter at different times and through different accounting paths.
