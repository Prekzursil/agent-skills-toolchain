# X071 — Epidemiology → trust calibration

**Unit:** X071  
**Lens:** epidemiologic surveillance, case definitions, diagnostic-test accuracy, base-rate reasoning  
**Target:** knowing how much to believe a given agent output, conditional on agent and task type  
**Research date:** 2026-07-19  
**Scope discipline:** This is an external ideation lens. I did not inspect or make claims about the local harness implementation. The corpus facts in the brief are treated as pinned inputs, but the design below is not a local-repo audit.

## Bottom line

The borrow transfers, but only in a constrained form. The useful mechanism is **two-stage, stratified output surveillance**:

1. define a stable, operational “case” of a materially unreliable output;
2. run a cheap, deliberately sensitive screen over outputs;
3. independently verify a probability sample of both screen-positive and screen-negative outputs against a stronger reference procedure;
4. estimate sensitivity, specificity, positive predictive value (PPV), negative predictive value (NPV), and defect prevalence separately by agent × task family × consequentiality tier; and
5. expose the quantity the next decision actually needs: `P(materially correct | this agent, this task family, evidence class, current period)`, with a sample count and interval—not a single global reputation number.

This is **very likely (80-90%)** to produce materially better trust estimates than counting visible errors and owner corrections alone, because epidemiology’s central contribution here is to measure false negatives by verifying some apparently healthy cases; the CDC’s canonical surveillance table explicitly includes both missed cases and false alarms, whereas an error log observes mainly detected failures ([CDC, characteristics of well-conducted surveillance](https://archive.cdc.gov/www_cdc_gov/csels/dsepd/ss1978/lesson5/appendixa.html)). The exact improvement is **UNVERIFIED—settle it with the 8-week shadow-mode experiment specified below**, so no enforcement should be based on the new estimates before that experiment.

The transfer is not a license to call correctness “disease,” treat a model grader as ground truth, or assign an agent a timeless health score. Agent outputs are adaptive, task distributions move, many outcomes are graded rather than binary, and verification can share the same model failure. Those disanalogies determine the design.

## 1. What epidemiology has already solved

### 1.1 Surveillance uses operational case definitions, not intuition

In its own field, surveillance needs comparable counts across reporters, places, and time. A surveillance case definition supplies uniform criteria for classifying whether an event counts. CDC states that a common case definition standardizes the cases of interest; clinical criteria can later be supplemented by more specific laboratory findings ([CDC, outbreak and case definitions](https://www.cdc.gov/urdo/php/surveillance/outbreak-case-definitions.html)). CDC also warns that surveillance definitions are not the same thing as individual clinical diagnosis: they exist for consistent population monitoring ([CDC, 2026 tularemia case-definition note](https://ndc.services.cdc.gov/case-definitions/tularemia/)). That separation matters: the classification optimized for monitoring need not be the final decision procedure for one patient.

Field investigations commonly start with a broad definition to maximize sensitivity, then optimize specificity as evidence accumulates ([CDC Field Epidemiology Manual, field investigation](https://www.cdc.gov/field-epi-manual/php/chapters/field-investigation.html)). Thus “suspected,” “probable,” and “confirmed” are not rhetorical confidence adjectives; they encode which predeclared evidence criteria have been met.

**Translation.** Define the surveillance event as a **materially unreliable output episode**, not “an agent made a mistake.” The unit is one agent handoff or final output evaluated against the task’s declared acceptance criteria. A candidate definition:

- **Suspected unreliable:** one mechanically checkable contradiction, failed required check, unsupported consequential factual claim, missing required deliverable, or downstream rejection signal.
- **Probable unreliable:** suspected criteria plus a second mechanically independent signal, or an independent reviewer reproduces the defect without seeing the screen result.
- **Confirmed unreliable:** the output fails a predeclared reference procedure tied to the task—tests/build for code, source reconciliation for research, schema/constraint validation for structured work, or owner acceptance criteria plus artifact inspection for bespoke work.
- **Indeterminate:** reference evidence is absent, internally inconsistent, or cannot adjudicate the criterion. Indeterminate is retained, never silently converted to correct.

This case definition measures output episodes, not personalities. It also keeps “style disagreement,” “recoverable process error,” and “material outcome error” distinct.

### 1.2 Surveillance evaluates the detector, not merely the detected cases

Epidemiology represents detection with a 2×2 table:

| | Reference event present | Reference event absent |
|---|---:|---:|
| Surveillance says present | true positive (TP) | false positive (FP) |
| Surveillance says absent | false negative (FN) | true negative (TN) |

From this, sensitivity is `TP/(TP+FN)`, specificity is `TN/(FP+TN)`, PPV is `TP/(TP+FP)`, and NPV is `TN/(FN+TN)`. CDC presents these exact surveillance quantities and explains that poor PPV wastes investigation effort on false alarms ([CDC, surveillance characteristics and formulas](https://archive.cdc.gov/www_cdc_gov/csels/dsepd/ss1978/lesson5/appendixa.html)). Updated CDC guidance evaluates usefulness alongside simplicity, flexibility, data quality, acceptability, sensitivity, PPV, representativeness, timeliness, and stability—not accuracy in isolation ([CDC, Updated Guidelines for Evaluating Public Health Surveillance Systems](https://www.cdc.gov/MMWr/preview/MMWRhtml/rr5013a1.htm)).

**Translation.** The harness’s cheap screen is the **index test**; the stronger audit is the **reference standard**. The screen might combine existing signals such as test failure, citation/source mismatch, contradiction between claimed completion and artifact state, or a downstream correction. Its performance must itself be measured. A high alert count can mean high defect prevalence, an over-sensitive detector, or both. A low alert count can mean reliable work, low sensitivity, or missing observation. The 2×2 table forces those possibilities apart.

The crucial operational move is to audit some screen-negatives. Without that, `FN` is structurally unobservable and “no alert” cannot be calibrated as reassurance.

### 1.3 Predictive value is conditional on the base rate

In its own field, sensitivity and specificity do not answer the user-facing question “given this result, how much should I believe it?” PPV does, and PPV depends on prevalence (the prior probability) as well as sensitivity and specificity. The National Academies’ NCBI text gives the Bayes relationship and states that predictive value depends on the prior probability in the tested group ([NCBI Bookshelf, measures of diagnostic performance](https://www.ncbi.nlm.nih.gov/books/NBK605677/)). CDC likewise says surveillance PPV reflects case-definition sensitivity and specificity **and** prevalence in the population under surveillance ([CDC, updated surveillance guidelines PDF](https://www.cdc.gov/mmwr/pdf/rr/rr5013.pdf)).

The practical consequence is stark. Using CDC’s published example, at 5% prevalence a test with 90% sensitivity and 95% specificity has only 49% PPV ([CDC, interim antibody-testing guidance](https://stacks.cdc.gov/view/cdc/91257/cdc_91257_DS1.pdf)). A detector can look “95% specific” yet produce more false than true alerts when the event is uncommon.

**Translation.** An agent-level average is not a trust estimate for the next output. The relevant base rate is conditional on at least:

`agent × task family × consequentiality × evidence class × current time window`.

For example, “agent A is 94% reliable” improperly mixes routine file edits, unfamiliar legal synthesis, and long-running shell orchestration. The useful result is closer to: “For this agent’s recent repo-edit episodes with executable tests and no screen alert, the audited NPV is X (interval Y; audited n=Z).” Where data are sparse, the harness must show “insufficient evidence” or use explicitly labeled partial pooling; it must not fill gaps with the global mean and present the result as local evidence.

### 1.4 Sentinel surveillance economizes, but representativeness is a first-class limitation

Epidemiology cannot confirm every person continuously, so it uses selected sites or samples. This buys timeliness and affordability but can sacrifice population representativeness. WHO’s HIV guidance explicitly says convenience-selected sentinel sites yield valid site-level estimates, not statistically representative national or subnational estimates ([WHO, HIV surveillance based on routine programme data](https://iris.who.int/bitstream/10665/197864/1/9789241509725_eng.pdf)). CDC similarly treats representativeness as a distinct surveillance attribute, not something guaranteed by volume ([CDC, Updated Guidelines](https://www.cdc.gov/MMWr/preview/MMWRhtml/rr5013a1.htm)).

**Translation.** Verification should be a **stratified probability sample**, not “audit the weird-looking outputs.” Oversample high-consequence and rare task families, but retain known inclusion probabilities so estimates can be weighted. Always include a random slice of screen-negatives. Convenience audits of controversial failures are useful for debugging but cannot estimate trust.

### 1.5 Diagnostic-accuracy work has named the evaluation biases

Diagnostic accuracy is estimated by comparing an index test with the best available reference standard on the same participants. QUADAS-2 identifies four bias domains: participant selection, index test, reference standard, and flow/timing ([Whiting et al., QUADAS-2](https://doi.org/10.7326/0003-4819-155-8-201110180-00009)). STARD requires reporting recruitment, thresholds, blinding, missing/indeterminate handling, participant flow, the interval between index and reference procedures, the cross-tabulation, uncertainty, and generalizability ([Cohen et al., STARD explanation](https://pmc.ncbi.nlm.nih.gov/articles/PMC5128957/)). STARD also emphasizes that sensitivity and specificity are not immutable properties; they vary with setting, case spectrum, prior testing, and the reference definition ([Bossuyt et al., STARD 2015](https://doi.org/10.1148/RADIOL.2015151516)).

**Translation.** Agent trust evaluation has direct analogues:

| Diagnostic-accuracy bias | Agent-harness failure | Required control |
|---|---|---|
| Selection bias | auditing only failures, escalations, or easy-to-grade tasks | probability sampling within declared strata; report inclusion rates |
| Index-test leakage | screen sees later owner correction or reference verdict | timestamp features; evaluate prospective and retrospective screens separately |
| Reference-standard bias | model grader shares the producer’s blind spot | task-native evidence first; independent adjudicator; record reference type |
| Differential verification | positives get deep review, negatives get a cursory glance | same minimum reference protocol in both groups, or report separate procedures |
| Flow/timing bias | repository or external state changes before audit | snapshot evidence or verify promptly; record delay |
| Spectrum shift | calibration from routine tasks applied to novel/high-stakes tasks | task-family strata, drift windows, and “out of calibration domain” |
| Excluding indeterminates | ambiguous cases disappear, inflating apparent accuracy | retain and report indeterminate rate and reasons |

### Proposal A — UNVERIFIED: Output Surveillance Record — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Emit one append-only record at each agent handoff/finalization:

```json
{
  "episode_id": "...",
  "agent_id": "...",
  "task_family": "repo_edit|research|shell_ops|structured_output|...",
  "consequence": "low|medium|high",
  "declared_acceptance_checks": ["..."],
  "screen_result": "positive|negative|indeterminate",
  "screen_signals": ["..."],
  "evidence_class": "none|self_report|artifact|executable|independent_source",
  "reference_selected": true,
  "reference_result": "unreliable|reliable|indeterminate|pending",
  "reference_type": "...",
  "timestamps": {"output": "...", "screen": "...", "reference": "..."},
  "sampling_probability": 0.0,
  "case_definition_version": "..."
}
```

Use a versioned vocabulary; never rewrite historical categories when a definition changes. This component is **very likely (80-90%)** to be feasible as a small bus-riding addition because it is a bounded event record and sampler, not a new runtime; that feasibility estimate is **UNVERIFIED—settle it with a line-counted spike against the actual hook payload and storage interface**.

### Proposal B — UNVERIFIED: Two-stage verification sampler — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

At episode completion:

1. Run a cheap suspected-case screen.
2. Select episodes for reference verification with a recorded probability. Suggested shadow-mode starting policy: 100% of high-consequence screen-positives; 20% of other positives; 5% of negatives; and a floor per rare agent × task cell. These are design seeds, **not evidence-based optimal rates**.
3. Verify against task-native evidence without showing the adjudicator the screen classification where feasible.
4. Store all four cells, indeterminates, sampling weights, and audit delay.

The sampling-rate recommendation is **UNVERIFIED—settle it by measuring weekly audit cost and the width of the NPV/defect-prevalence intervals under 2%, 5%, 10%, and 20% negative sampling**. It is **likely (55-80%)** that a modest negative sample will expose materially important silent failures because screen-negative auditing is precisely the missing observation needed to populate `FN`; the wide band reflects unknown local defect prevalence and clustering.

### Proposal C — UNVERIFIED: Conditional trust card — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

For each agent × task-family cell, publish:

- audited reliability among all sampled episodes, with a 95% interval;
- screen sensitivity, specificity, PPV, NPV, and indeterminate rate;
- raw and weighted denominators;
- evidence-class mix and reference-standard mix;
- case-definition version and time window;
- drift comparison with the previous window; and
- explicit `INSUFFICIENT EVIDENCE` / `OUT OF CALIBRATION DOMAIN` states.

For sparse cells, use a Beta-binomial estimate only after documenting the pooling hierarchy, and always expose the direct cell count. A simple starting display can use Jeffreys’ interval or a Beta(0.5, 0.5) posterior for binary adjudicated outcomes; do not let mathematical polish hide reference-standard weakness.

This is **very likely (80-90%)** to prevent more category errors than a global leaderboard because predictive value is base-rate dependent and diagnostic performance varies across case spectra, as the CDC and STARD sources above establish. Whether users act on the richer card correctly is **UNVERIFIED—settle it with a blinded decision study comparing routing/escalation choices made with a global score versus the conditional card**.

### Proposal D — UNVERIFIED: Trust-aware routing as a later policy — **CONFIG (settings/JSON only)**

Do not block or reroute work during initial data collection. After validation, a small policy table may require additional evidence when a cell’s lower reliability bound is below a consequence-specific threshold, or when the episode is outside the calibration domain. The policy should respond to evidence scarcity by escalating verification, not by labeling the agent bad.

Automatic routing benefit is **UNVERIFIED—settle it with a prospective A/B test measuring escaped material defects, verification cost, latency, and owner overrides**. It is only **likely (55-80%)** to improve net outcomes because extra checking can catch failures but can also add correlated reviewers, latency, and false reassurance.

## 3. What this would catch that ordinary reliability logs miss

The following are expected catches, not claims about the current implementation:

1. **Silent false reassurance.** An output passes cheap checks but fails independent reference verification. This is the `FN` cell, invisible if only alerts are reviewed. Catching some such cases is **almost certain (90-99%)** if their prevalence is nonzero and negative outputs are sampled long enough; the evidence is the sampling design itself, while the remaining uncertainty is the unknown prevalence and sample size.
2. **Noisy detector mistaken for bad agent.** Many alerts are false positives, revealed by low PPV despite high raw alert volume. This is **very likely (80-90%)** to occur for at least some low-base-rate strata because PPV mathematically falls as event prevalence falls at fixed sensitivity/specificity; CDC’s 5%-prevalence example demonstrates the mechanism.
3. **Task-conditional weakness hidden by an average.** A strong global agent score masks poor performance in a rare task family. Detection is **likely (55-80%)** once minimum stratum sampling exists; uncertainty remains because the real heterogeneity is unknown. STARD’s documented spectrum dependence supplies the structural evidence.
4. **Evaluator blind spot.** A screen and a model-based reference agree but task-native evidence disagrees. This is **likely (55-80%)** in some reasoning-heavy strata if producer and evaluator share architecture or context; this premise is **UNVERIFIED—settle it by comparing same-model, different-model, and task-native adjudication on the same random episodes**.
5. **Definition drift masquerading as agent drift.** Reliability changes exactly when the failure case definition or reference procedure changes. Versioned definitions and segmented estimates reveal this mechanically. This catch is **very likely (80-90%)** whenever a substantive definition change occurs because the version boundary is stored with each record.
6. **Verification selection bias.** Apparent reliability differs between convenience-reviewed episodes and weighted probability-sampled episodes. Detecting a discrepancy is **roughly even (45-55%)** because local selection effects are unknown; WHO’s warning about convenience sentinel sites is the field evidence motivating the check.

## 4. Adversarial stress test of the analogy

### Disanalogy 1: “Truth” is often not a stable biological state

Disease status is imperfectly observed, but many agent tasks are even less determinate: design quality is multi-objective, requirements evolve, and owner preference can legitimately change. Binarizing all outcomes would manufacture precision. Therefore the transfer applies only where acceptance criteria and a defensible reference procedure exist. Else the outcome must be `indeterminate`, multi-axis, or excluded from numerical calibration with an explanation.

**Verdict:** serious limitation, not fatal. Surveillance already distinguishes its operational definition from clinical truth, but agent harnesses must be even more explicit about normative judgments.

### Disanalogy 2: Agents adapt to measurement

Pathogens evolve and reporting behavior changes, but agents can directly optimize against a visible rubric within minutes. A fixed screen may invite metric gaming: passing tests without satisfying intent, citation padding, or choosing easy tasks. Therefore screen features cannot be treated as the outcome, and calibration windows must be time-bounded.

The claim that gaming will materially occur is **UNVERIFIED—settle it with a red-team trial in which agents receive versus do not receive the screen rubric and compare reference-confirmed reliability**; it is **likely (55-80%)** because optimizing proxy measures is a general consequence of exposing them, but no local rate is known.

### Disanalogy 3: Errors are clustered, not independent cases

One bad dependency, prompt, environment outage, or shared misconception can create many correlated output failures. Naive binomial intervals will be too narrow if episodes are treated as independent. Group records by session, tool incident, model/prompt version, and shared upstream evidence; use cluster-robust or block-bootstrap uncertainty when volume justifies it.

Material clustering is **very likely (80-90%)** in an agent harness because repeated episodes share models, prompts, tools, and sessions; the causal sharing is observable by design, though its magnitude is **UNVERIFIED—settle it by estimating intracluster correlation by session and fingerprint**.

### Disanalogy 4: The reference standard may be another fallible agent

Laboratory gold standards can also err, and diagnostic-accuracy methodology explicitly treats reference-standard bias as a core domain. In agent evaluation, the danger is stronger: producer and grader may share training, prompt framing, or source omissions. “Two agents agree” is not mechanically independent evidence.

**Verdict:** the analogy strengthens the warning. Prefer executable/task-native evidence; record reference type; blind adjudication; and triangulate unresolved high-consequence cases. Never report an agent’s calibration as ground truth without reference-standard provenance.

### Disanalogy 5: Prevalence is partly policy-created

Which agent receives which task is not random. Routing hard tasks toward strong agents can make strong agents look worse, while routing easy tasks toward weak agents can make them look better. Thus observed defect prevalence is conditional on assignment policy. Per-task stratification helps but does not remove unmeasured difficulty confounding.

**Verdict:** fatal to causal agent ranking, but not to conditional prediction under the current routing policy. The trust card must say “observed reliability on assigned episodes,” not “intrinsic agent ability.” Causal comparison between agents requires randomized or carefully matched assignments, which this proposal does not assume.

### Disanalogy 6: Costs of false positives and false negatives vary enormously

Missing a typo and missing a destructive production command are not exchangeable cases. Epidemiology handles different surveillance objectives and action thresholds; the harness likewise needs consequence tiers and decision-specific thresholds. A single “accuracy” objective is invalid.

**Overall transfer verdict:** **very likely (80-90%)** that the measurement architecture transfers usefully; evidence is the exact structural match among an imperfect screen, a costlier reference procedure, unobserved missed cases, selection bias, and base-rate-dependent interpretation. It is **almost certainly not (1-5%)** valid to transfer the biological metaphor, assume a perfect reference standard, or infer intrinsic agent quality from observational surveillance; the evidence is the disanalogies above and the diagnostic-accuracy literature’s own warnings about selection, reference, spectrum, and flow/timing bias.

## 5. Minimal experiment that can falsify the proposal

### UNVERIFIED: Eight-week shadow mode — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

This recommendation is **UNVERIFIED—this experiment is the settlement mechanism**.

**Pre-register before collection:**

- episode unit and material-error case definition;
- 4–8 coarse task families, not hundreds of sparse labels;
- consequence tiers;
- screen features and threshold;
- reference procedure per task family;
- sampling probabilities, including negative sampling;
- primary outcomes: weighted material-defect prevalence, screen sensitivity/PPV/NPV, escaped high-consequence defects, verification minutes per episode;
- secondary outcomes: indeterminate rate, inter-adjudicator disagreement, delay, owner override;
- failure criteria for the proposal.

**Controls:**

- Demonstrate that the detector can find a seeded known-present defect before interpreting zero alerts.
- Audit randomly selected screen-negatives as a mechanically distinct signal from the screen.
- Blind reference adjudicators to screen status where feasible.
- Re-adjudicate a random subset with a second, mechanically independent method: e.g. executable evidence versus human/source audit, not the same grader rerun.
- Preserve all indeterminates and missing reference outcomes.
- Compare convenience-selected audits with probability-sampled estimates.
- Report results by agent × task family only where denominators support them; otherwise report pooled exploratory results with an explicit applicability warning.

**Falsification/stop conditions:**

Stop or redesign if (a) a defensible reference procedure cannot be defined for most consequential task families; (b) adjudicator disagreement remains high after criteria revision; (c) negative sampling finds too few cases to produce decision-useful intervals at an affordable cost; (d) conditional cards do not improve routing judgments in the blinded decision study; or (e) added verification costs exceed the avoided-defect cost. These conditions prevent the epidemiology analogy from becoming an unfalsifiable bureaucracy.

The experiment is **likely (55-80%)** to determine whether the design is operationally useful within eight weeks, because it directly measures misses, false alarms, cost, and decision impact; the band is wide because episode volume and reference-review capacity are unknown.

## 6. Anti-overfit gate and rejected expansions

This design passes the stated anti-overfit gate:

- It rides the existing hook/skill/MCP bus.
- The record emitter, sampler, summary calculation, and policy table can each remain small.
- It does not introduce a second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.
- It measures whether additional verification earns its cost before enabling enforcement.

Explicitly rejected:

- **Global Elo/reputation score:** loses task base rates, consequence, reference quality, and time drift.
- **Always use a panel of agents:** correlated agreement is not independent truth and creates recurring cost.
- **Train a trust critic:** prohibited overfit component; it also turns the screen into another opaque index test requiring its own surveillance.
- **Vector/KG memory of every failure:** unnecessary for the 2×2 measurement problem and explicitly rejected by the architecture gate.
- **Full durable workflow runtime:** the proposal needs event emission and sampling, not another scheduler.
- **Audit only owner corrections:** convenience selection cannot estimate false negatives or represent the output population.
- **Audit every output:** cost-prohibitive and unnecessary if probability sampling yields useful intervals.

## 7. Decision recommendation

Adopt the **experiment**, not the score. Build the smallest possible shadow-mode event record and stratified verifier, pre-register a material-output case definition, and learn whether screen-negative auditing changes decisions. Do not expose a global agent rank. Do not automate routing until reference quality, selection, uncertainty, and decision benefit are demonstrated.

This recommendation is **very likely (80-90%)** to be the correct next step because it is reversible, bus-native, directly tests the transfer’s distinctive value (measuring missed cases), and contains explicit stop conditions. Its net production benefit remains **UNVERIFIED—settle it with the eight-week shadow experiment and prospective routing A/B test**, so the recommendation is for measurement infrastructure and validation only.
