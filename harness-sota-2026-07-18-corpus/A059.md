# A059 — Coherence audit of `~/.claude/rules/python/security.md`

Date: 2026-07-19  
Unit: A059  
Mode: read-only audit of the unpacked subject at `/local_disk0/codexwork/bundle`; the only durable write made by this unit is this artifact.

## Executive verdict

`rules/python/security.md` is short, understandable, and aligned with the highest-priority security floor on its secret-loading example. It is not, however, a coherent executable policy. I found **eight reportable collisions**:

1. one inherited contradiction over whether an approved secret manager is allowed;
2. one redundant three-layer restatement of the secret rule;
3. one unresolved Bandit scan-scope contradiction (`src/` versus `.`);
4. one Bandit requirement with no enforcement or evidence-producing gate;
5. one no-hardcoded-secret requirement whose shared hard block is opt-in and off by default;
6. one credential-read enforcement that has no corresponding rule; and
7. one direct contradiction between the permanent `.env` permission deny and two hooks that say the owner disabled that same behavior by default; and
8. one stale shared-harness invariant claiming that conditional security paths are blocked.

The most important result is not that Bandit is missing. It is that the harness mixes three distinct security concepts without naming their boundaries: **application secret acquisition**, **whether the model may inspect credential files**, and **whether generated source is scanned for literal secrets**. The target governs the first, settings/hooks govern the second, and the third is claimed by the common rule but only conditionally enforced. That ambiguity makes apparently compatible sentences produce incompatible operating behavior.

The measured corpus does **not** settle whether agents actually ran Bandit or obeyed the environment-variable example. Its successful Bash arguments are not retained in the distilled schema. It does establish that `python-reviewer` was invoked 13 times, `security-reviewer` 18 times, and the Semgrep findings MCP tool 31 times, but none of those counts proves Bandit compliance (`inputs/corpus.json:1`, JSON pointers `/capability_use/agents_invoked/python-reviewer`, `/capability_use/agents_invoked/security-reviewer`, and `/capability_use/mcp_tools_used/mcp__plugin_semgrep_semgrep__semgrep_findings`; extraction command and output are recorded below).

**Artifacts and exact lines**

The target happens to use the higher-rule path, so its example is valid; its inherited alternative is not.

**Precedence result**

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing rule bus)**

Keep the Python `os.environ[...]` example as one approved implementation, not the only channel. It is **very likely (80-90%)** that this removes the semantic fork without weakening the no-hardcode invariant, because both currently named acquisition mechanisms remain runtime channels and the validation requirement remains unchanged (`claude/AGENTS.md:95`; `claude/rules/common/security.md:40-42`).
