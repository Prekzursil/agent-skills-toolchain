# B003 — Groundedness engineering: quote fidelity

## Verdict

Hallucination cannot be eliminated. A quote-fidelity mechanism that promises otherwise is dishonest. The useful, bounded target is narrower: when an agent presents text as an exact quotation from a file, make a mismatch, an inaccessible source, an ambiguous anchor, or later source drift mechanically visible before the artifact is accepted.

The recommended design is an **attested-quote contract plus a deterministic verifier**. A quote author identifies the source and, when possible, the immutable revision in a small JSON marker immediately before a fenced `quote` block. The verifier re-reads the named source; compares exact Unicode text after *only* newline normalization; checks the immutable snapshot and current working copy separately; and emits one of `PASS`, `RELOCATED`, `AMBIGUOUS`, `MISQUOTE`, `SOURCE_DRIFT`, `MISMATCH_OR_DRIFT`, `SOURCE_UNAVAILABLE`, or `INVALID_DECLARATION`. It prints a bounded diff for actionable failures. It does not use an LLM, embeddings, fuzzy similarity, or “meaning” classification.

This achieves the right asymmetry:

* For a **registered** quote whose source is readable, the detector is almost certain (90-99%) to catch a character-changing paraphrase presented as verbatim; evidence is exact substring comparison and the 12-case executable probe recorded below. The residual uncertainty is implementation defects, encoding edge cases, or a source changing concurrently with the read.
* The total fraction of all false claims caught is **UNVERIFIED — the experiment that settles it is a blinded audit of at least 300 real artifacts, labeling false claims by class and whether each was registered as a quote**. The corpus contains no labeled quote-fidelity population, so giving an overall recall percentage would fabricate precision.
* On correctly registered exact quotes, a false-positive rate below 0.5% is likely (55-80%) after the specified shadow calibration; evidence is the intentionally strict scope, newline-only normalization, non-blocking treatment of ambiguity/unavailability, and the statistical release gate of zero false failures in at least 600 clean quotes. This is still **UNVERIFIED — replay 600 clean, owner-adjudicated quotes on the Windows host to settle it**.
* Cost per checked 110,000-byte source was 0.166 ms in a small Linux in-memory prototype (100 iterations in this unit). Windows filesystem and antivirus cost are **UNVERIFIED — benchmark 1,000 registered quotes over the owner's real NTFS source-size distribution to settle it**. With per-run source caching, sub-10-ms median cost per quote is very likely (80-90%); evidence is the measured CPU cost and one source read amortized across quotes, but the Windows I/O experiment remains required.

The mechanism should ship shadow-first and only block completion on high-certainty states after calibration. It must never block on an unregistered piece of punctuation, fuzzy similarity, an unreachable file, an ambiguous duplicate, a moved-but-still-exact quote, or a source that changed without a resolvable historical snapshot. That boundary is the main defense against repeating this harness's measured false-fire class.

### 1.2 Confirmed local failure mode: use/mention confusion

The known-defects input is directly load-bearing. ### 1.5 Frontier/native research

Current first-party Claude Code documentation confirms the native primitives: tool-event matchers select `tool_name`; `PostToolUse` receives the original tool input and response; hooks can return `additionalContext`; and `Stop` can return a top-level `decision: "block"` with a reason. The same documentation gives a `Write|Edit` file-lint hook example and warns that `PostToolUse` runs after effects have happened. Source: [Claude Code hooks reference](https://code.claude.com/docs/en/hooks). The guide describes hooks as deterministic lifecycle automation and places edit and finish-time validation on that native bus: [Automate workflows with hooks](https://code.claude.com/docs/en/hooks-guide).

For anchoring, the W3C Web Annotation Data Model's `TextQuoteSelector` requires an `exact` copy and recommends immediate `prefix` and `suffix` context to distinguish duplicate occurrences. It also defines text position selectors but warns that textual selection is normalized and uses Unicode code points: [W3C Web Annotation Data Model, Text Quote Selector](https://www.w3.org/TR/annotation-model/#text-quote-selector). The proposed schema borrows only `exact/prefix/suffix`; it does not import JSON-LD or an annotation service.

GitHub's first-party documentation explains why branch URLs are not sufficient provenance and recommends commit IDs for permanent file/line links: [Getting permanent links to files](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files) and [Creating a permanent link to a code snippet](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-a-permanent-link-to-a-code-snippet). This supports the split between `snapshot` truth and `current` truth.

CommonMark defines block structure before inline structure and gives fenced code blocks a grammar distinct from paragraphs, block quotations, and inline code: [CommonMark 0.31.2](https://spec.commonmark.org/current/). A small state parser for one explicit marker plus the immediately following fenced block is therefore preferable to regexing arbitrary Markdown prose.

Claude Code now also offers prompt- and agent-based hooks ([hooks reference](https://code.claude.com/docs/en/hooks)), but using an LLM hook for literal equality is rejected: it adds tokens, latency and nondeterministic judgments to a problem solvable byte-for-byte.

## 2. What is and is not a quote-fidelity claim

The detector's unit is an **attested exact quote**, not a sentence, citation, claim, or arbitrary pair of quote marks.

In scope:

1. A block explicitly presented as verbatim file content.
2. Its declared source identity.
3. Whether the block occurs exactly in the snapshot and/or current source.
4. Whether the same exact span moved, duplicated, became ambiguous, or disappeared.
5. Whether prefix/suffix context changed enough to make a retained sentence misleading in its new context.

Out of scope:

1. Whether a correct quote supports the surrounding interpretation.
2. Cherry-picking, material omission outside the bounded prefix/suffix, or a true sentence quoted from an untrustworthy file.
3. Unsupported paraphrases that are clearly labeled as paraphrases.
4. Unsupported factual claims with no quote.
5. Web content unless it has first been captured as an immutable, readable local source or content-addressed response.
6. OCR, PDFs, images, notebooks' rendered output, generated UI, or database rows without a canonical text serialization.
7. Deliberate collusion where an agent edits both source and artifact to make a false statement true. Revision comparison can expose some such changes; the detector is not an authorization or tamper-proof system.

Calling any of these eliminated would violate the framing. The practical value is that an exact-quote claim acquires a cheap, inspectable receipt and failures become typed rather than silently plausible.

## 3. Quote Contract v1

### 3.1 Human-readable syntax

The canonical form is a JSON HTML comment immediately followed by a fenced block whose info string is exactly `quote`:

````markdown
<!-- quote-source {"path":"src/parser.py","revision":"git:4f6c...","line_hint":81,"prefix":"def parse(","suffix":"return node"} -->
```quote
raise ParseError("unexpected token")
```
````

Rules:

* The marker and fence must be adjacent except for whitespace. This prevents a marker in explanatory prose from attaching to a distant example.
* `path` is required. It is resolved relative to the artifact's declared source root, not process `cwd`, unless absolute paths are explicitly allowlisted.
* `revision` is optional but strongly preferred. `git:<full-commit>` identifies the snapshot; `worktree:<sha256>` records the bytes observed at authorship for a non-Git or dirty file. Short Git SHAs are invalid because they may cease to be unique.
* `line_hint` is optional and advisory. Exact text is the primary selector. A stale line with a unique exact match produces `RELOCATED`, not a false failure.
* `prefix` and `suffix` are optional bounded context selectors, at most 80 Unicode code points each. They disambiguate duplicates and detect nearby contextual drift. They are not included in the displayed quotation.
* The quote body is the literal content between the opening and closing fence after removing exactly one syntactic newline immediately after the opening fence and one immediately before the closing fence. The opening fence must be longer than every consecutive backtick run in the body; the checker validates this.
* Multiple omissions are represented as multiple individually attested quote blocks. An inserted `...` or `…` inside a block is literal and fails unless the source contains it. This avoids fuzzy “ellipsis semantics.”
* The checker normalizes CRLF and lone CR to LF. It performs no trimming, whitespace folding, case folding, smart-quote substitution, tab expansion, or Unicode NFC/NFKC normalization. Those transformations would hide precisely the drift being checked.
* The source decoder accepts UTF-8/UTF-8-BOM and BOM-declared UTF-16LE/BE. Other encodings return `SOURCE_UNAVAILABLE(encoding)` rather than replacement-decoding into a false mismatch.
* The rendered artifact may introduce prose before or after the block, but paraphrases must not use this marker.

The JSON marker is intentionally verbose. It is syntactically unambiguous, parseable with Python's standard library, invisible in normal Markdown rendering, and unlikely to occur accidentally. A quoted example of the syntax inside a normal fence does not activate because the parser tracks outer fence state. This known-positive/known-negative distinction is essential given the defect report.

### 3.2 Why not ordinary blockquotes or quotation marks

Ordinary `>` blocks contain epigraphs, user prompts, hypothetical output, translated text, and prose copied from remote sources. Inline straight and curly quotes also denote UI labels, identifiers, sarcasm, and mentioned phrases. Treating all of them as verifiable file quotations would recreate use/mention confusion and yield a high false-positive rate.

The structured contract sacrifices automatic coverage for precision. This trade is deliberate. The overall benefit is likely (55-80%) to exceed punctuation scanning because false alarms are costly in this workspace and the helper can generate declarations mechanically; evidence is the 8+ confirmed false fires and displaced-write regression in `INPUT-known-harness-defects.md:9-41,100-102`. Adoption is **UNVERIFIED — the settling experiment is a two-week shadow run measuring registered exact quotes divided by all human-labeled file quotations in a stratified artifact sample**.

### 3.3 Source identity and two clocks

Every check considers two possible source states:

* **Snapshot state:** the declared immutable Git commit or captured content digest at the time of quotation.
* **Current state:** the file re-read from the current filesystem at validation time.

These answer different questions. Snapshot state asks “was the artifact faithful when authored?” Current state asks “is it still faithful to what readers see now?” A commit-pinned quote can remain historically correct while being stale for the current tree. Reporting only one collapses provenance and freshness.

For `git:<commit>`, the verifier must retrieve the file without switching the worktree, using an argv-array subprocess equivalent to `git show <full-commit>:<repo-relative-path> --` only after separately validating the commit and path. It must not invoke a shell. For non-Git sources, `worktree:<sha256>` proves only whether current bytes equal the recorded observation; it does not recover historical bytes. Therefore a disappeared quote with a changed non-Git hash is `MISMATCH_OR_DRIFT`, never confidently “source drift.”

## 4. Deterministic algorithm

### 4.1 Discovery

1. Receive an explicitly named artifact path from one of three sources, in precedence order:
   * `tool_input.file_path` after `Write|Edit|MultiEdit|apply_patch`;
   * a run manifest's exact artifact path;
   * an explicit `quotecheck <artifact>` invocation.
2. Do not parse shell command text to guess written paths. That would reproduce the payload-scanning defect and mishandle shell quoting.
3. Accept only regular Markdown/text files under configured artifact roots. Resolve the real path; reject device paths, network shares unless explicitly enabled, and symlink escapes.
4. Enforce default limits: artifact <= 2 MiB, <= 200 declarations, each displayed quote <= 16 KiB, each source <= 32 MiB unless explicitly raised. Limit failures are typed `UNVERIFIED_LIMIT`, not evidence that the quote is false.
5. Run a built-in known-positive parser fixture and known-negative “marker inside an outer code fence” fixture. If either fails, emit `DETECTOR_INVALID` and make no absence or success claim.

### 4.2 Parsing

Use a line-state parser, not one multiline regex:

1. Track CommonMark-style fenced blocks.
2. Outside any fence, recognize exactly `<!-- quote-source `, parse the remaining payload as one JSON object, and require the exact closing ` -->`.
3. Require the next nonempty line to open a fence with info string `quote`.
4. Find a valid closing fence of the same character and at least the opening length.
5. Preserve body bytes except the syntactic boundary newlines, then newline-normalize.
6. Validate schema keys/types and reject unknown keys in v1. Strictness here is safe because invalid declarations are reported as invalid declarations, not false content.

The schema should remain tiny:

```json
{
  "path": "string, required",
  "revision": "git:<40+ hex> | worktree:sha256:<64 hex>, optional",
  "line_hint": "positive integer, optional",
  "prefix": "<=80 code points, optional",
  "suffix": "<=80 code points, optional"
}
```

### 4.3 Verification and classification

For each declaration:

1. Canonicalize and allowlist the source path. Do not echo unrestricted source content on failure.
2. Read/decode current source once per `(realpath, size, mtime_ns)` and compute SHA-256 over raw bytes. Cache for the run.
3. If a Git revision is present, locate the repository, validate full commit syntax, and read the snapshot version using an argv array. Cache by `(repo, commit, path)`.
4. Search normalized Unicode text for exact quote occurrences. Search is literal, not regex.
5. When `prefix`/`suffix` exist, retain only matches whose immediate bounded context agrees exactly.
6. Convert match offsets to 1-based Unicode-code-point line numbers for display.
7. Classify snapshot and current independently, then combine:

| Snapshot | Current | Result | Meaning/action |
|---|---|---|---|
| exact unique | exact unique at hint | `PASS` | Faithful and current. |
| exact unique | exact unique elsewhere | `RELOCATED` | Text still exact; update location metadata. Advisory only. |
| exact one/many | multiple unresolved | `AMBIGUOUS` | Exact text exists but identity is unclear; add context/hint. Advisory only. |
| exact | absent | `SOURCE_DRIFT` | Historically faithful but stale now. High-certainty failure for a current-state artifact. |
| absent | absent and current raw hash equals declared observed hash | `MISQUOTE` | Source did not change since the recorded observation and quote is not present. |
| no recoverable snapshot | absent and hash changed/unknown | `MISMATCH_OR_DRIFT` | Cannot honestly distinguish original misquote from later drift. |
| absent snapshot | exact current | `INVALID_REVISION_QUOTE` | Current text exists but not in the claimed snapshot. Fix revision or claim. |
| unreadable/outside allowlist | unknown | `SOURCE_UNAVAILABLE` | Verification not performed; never call it false or pass. |
| malformed marker/fence | unknown | `INVALID_DECLARATION` | Fix contract. |

If the exact quote remains but declared prefix/suffix changes, return `CONTEXT_DRIFT`, not `PASS`. Context drift is a true mechanical observation, but whether it invalidates the interpretation is semantic; advise by default.

### 4.4 Bounded diagnostics

A failure report contains:

```text
QUOTE-FIDELITY MISQUOTE artifact.md:74 quote=qf-7
source=src/parser.py revision=worktree:sha256:…
expected exact quote not found; source bytes match declared observed hash
nearest line-window candidate: L81-L81 similarity=diagnostic-only
diff (max 8 lines / 800 chars):
- raise ParseError("unexpected tokens")
+ raise ParseError("unexpected token")
```

The nearest-candidate search is diagnostic only and may use `difflib.SequenceMatcher` over bounded line windows. It must never turn a mismatch into a pass, choose a source, or decide meaning. Omit it for secret-like paths or if redaction changes the diagnostic. The dispatcher already bounds and redacts injected context (`dispatcher.py:280-285`); the module should additionally emit hashes and line numbers rather than broad source excerpts.

### 4.5 Receipts

Persist a compact receipt per quote:

```json
{
  "schema":"quote-fidelity/v1",
  "artifact":"…",
  "artifact_sha256":"…",
  "quote_id":"qf-7",
  "source":"…",
  "source_revision":"git:…",
  "current_source_sha256":"…",
  "snapshot":"pass",
  "current":"source_drift",
  "result":"SOURCE_DRIFT",
  "checked_at":"…",
  "checker_version":"…"
}
```

The receipt is valid only for the exact artifact hash and source state. A later artifact or source edit invalidates it automatically. Record the result on the existing event ledger or bounded quote-check state file; do not create a database.

## 5. Integration design

### Proposal A — Reuse the existing lifecycle bus

**Tag: NATIVE (Claude Code already does this; we just enable it)**

Use native `PostToolUse` feedback after an artifact edit and native `Stop`/`TaskCompleted` completion control. The native hook reference supports these inputs/outputs, and the local shared registration already routes them (`registration.py:17-54`; `settings.json:310-320,458-503`). This is almost certain (90-99%) to avoid a second orchestration runtime because no new transport or daemon is needed; evidence is the complete local event/model/adapter/dispatcher chain.

Post-edit checking gives the cheapest repair loop. Stop-time checking protects against source drift after the artifact was first written and catches an artifact assembled over multiple edits. `stop_hook_active` must make any block one-shot, matching the existing claim module's anti-loop rule (`modules.py:2054-2067`).

### Proposal B — One standard-library `quotecheck.py` checker/emitter

**Tag: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Build one Python file with two modes:

* `quotecheck emit SOURCE [--revision REV] [--start-line N --end-line M]` prints a correctly fenced declaration and exact source text. This removes copy/paste and escaping errors.
* `quotecheck verify ARTIFACT [--json] [--current-required]` parses, verifies and emits receipts.

The same pure functions are called by a thin dispatcher module. Keeping parsing, source reading, classification and CLI output below roughly 200 substantive lines is likely (55-80%); evidence is the small schema and standard-library operations, but this is **UNVERIFIED — implement and count nonblank/noncomment lines while retaining the full test suite to settle it**. If robust Git repository discovery, Windows path policy and receipt persistence push the core above 200 lines, split adapters from the pure checker without changing the BUILD-SMALL architecture; do not relax tests to hit a line target.

This helper should be preferred over hand-authoring quote blocks. For a requested line range, it can automatically choose a fence longer than any body backtick run, record full Git revision when the file is clean/tracked, and record current SHA-256 otherwise. It must re-read after generation and verify its own emitted block before returning success.

### Proposal C — Minimal registration and artifact scoping

**Tag: CONFIG (settings/JSON only)**

Register the checker only for file-writing tool events and the completion boundary. Use the native `if`/matcher support where the installed host accepts it; otherwise filter `tool_name` and `tool_input.file_path` inside the checker, as the existing per-edit checker does (`per-edit-check/check.py:189-209`). The initial scope is files that either:

1. contain a valid `quote-source` declaration; or
2. are explicitly listed in the run's artifact manifest.

Do not recursively scan the workspace. Do not parse Bash or PowerShell bodies for output redirections. Shell-authored artifacts remain visible only when registered in a run manifest or explicitly passed to `quotecheck`. This is a deliberate coverage gap, not a reason to add a shell parser.

Whether the owner's installed Windows Claude version supports the current documented `if: "Edit(*.md)"` form is **UNVERIFIED — run `/hooks`, then a sanitized `Write` fixture with a path-qualified `if` rule and inspect one hook event to settle it**. The recommendation does not depend on that feature because in-hook path filtering is already demonstrated locally.

### Proposal D — Shadow telemetry and a one-shot deterministic completion gate

**Tag: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Add `quote_fidelity` to the existing staging/telemetry vocabulary and emit only counters plus receipt identifiers: declarations, pass, relocated, ambiguous, mismatch, drift, unavailable, invalid, duration, and bytes read. Never persist quote text or arbitrary source excerpts in telemetry.

Rollout modes:

* `SHADOW`: record, do not inject.
* `ADVISE`: inject one consolidated message after an edit or at Stop.
* `ENFORCE`: one-shot Stop/TaskCompleted block only for `MISQUOTE`, `SOURCE_DRIFT` when the task claims current-state truth, `INVALID_REVISION_QUOTE`, or `INVALID_DECLARATION` in an explicitly registered artifact.

`AMBIGUOUS`, `RELOCATED`, `SOURCE_UNAVAILABLE`, `UNVERIFIED_LIMIT`, and `MISMATCH_OR_DRIFT` never hard-block by default. They are evidence gaps, not proven falsehoods. A manual strict CI mode may fail them when a project explicitly adopts that contract.

### Anti-overfit gate

All four proposals ride the native hook/shared-dispatcher/file-skill bus. They introduce no second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. There is no BUILD-LARGE proposal. The design is one deterministic parser/checker, a tiny marker schema, existing hook registration, and bounded receipts. It remains useful as models improve because literal source equality does not depend on model capability.

Both are **UNVERIFIED — red-team paired source/artifact edits to settle them**. | Revision lookup/diff. | Do not call a current exact match “historically true” without snapshot provenance. |
| Source unavailable | No truth catch claimed. Result is `SOURCE_UNAVAILABLE`. | Bounded failed open/read. | Treating unavailable as mismatch would be a false positive; never do so. |

No aggregate “fraction of false claims caught” is reported because the class mixture and registration adoption are unknown. The correct dashboard keeps at least four denominators:

1. recall on seeded false **registered quotes**;
2. false-failure rate on clean registered quotes;
3. registration coverage among human-labeled file quotations;
4. fraction of *all* artifact false claims that are quote-fidelity claims.

Multiplying (1) × (3) × (4) estimates overall false-claim recall only after all are measured. Conflating them would make a perfect checker look universally protective.

## 8. Adversarial and edge-case handling

### 8.1 Use/mention and self-documentation

Required fixtures:

1. A real marker plus quote block is detected.
2. The same marker inside a larger ordinary code fence is not detected.
3. A prose sentence naming `<!-- quote-source` is not detected.
4. A Markdown table containing escaped marker text is not detected.
5. A quoted bug report containing a complete marker and fence remains inert when nested in an outer fence.
6. A valid declaration after that example is still detected, proving the parser did not stay stuck in fence state.

The checker may say “zero declarations” only if fixtures 1 and 6 pass in the same executable/version. This satisfies the known-positive-control rule mechanically.

### 8.2 Newlines, Unicode and whitespace

CRLF/LF normalization avoids platform-only false failures. All other differences remain visible. Unicode is compared by code point after decoding, with no normalization: visually identical composed/decomposed strings can differ. That strictness is intentional for a verbatim claim, but owner adjudication may find decomposed filesystem text common. Supporting NFC would lower false positives but also permit a non-verbatim pass; therefore any future `normalization:"NFC"` must be explicit in the declaration and separately calibrated.

### 8.3 Duplicate text

A common word or line may occur many times. Exact membership alone proves the text exists somewhere, not that the cited occurrence is right. Prefix/suffix and line hint disambiguate. If multiple candidates remain, the result is `AMBIGUOUS`; it is never silently assigned to the nearest line.

### 8.4 Moving and refactoring

If the exact text moves, report `RELOCATED` with old hint and current line. This is not a false quote. If the snapshot path disappears but Git rename detection finds an exact blob/path candidate, suggesting a new path is likely (55-80%) to reduce repair cost; evidence is Git history availability, but automated rename following is **UNVERIFIED — replay 100 rename/refactor histories and measure unique resolution and false attribution**. Keep rename following advisory and out of v1 if it threatens the line budget.

### 8.5 Concurrent changes and torn reads

Stat source `(size, mtime_ns)` before and after reading. If it changes, retry once; if it changes again, return `SOURCE_RACING` and advise, never mismatch. A Stop recheck then obtains a stable view. This is likely (55-80%) to prevent most transient false mismatches in ordinary editor/git activity; evidence is detection of observable file metadata changes, but **UNVERIFIED — stress test parallel writers on NTFS to settle race coverage**.

### 8.6 Paths and secrets

Resolve paths against explicit roots. Deny `..` escapes after realpath resolution, device names, ADS syntax on Windows unless explicitly supported, and sources under credential/config secret roots. Do not follow URLs. Do not include more than eight diff lines/800 characters, and pass diagnostics through the existing redactor. A malicious artifact can name a sensitive local file; source allowlisting prevents turning verification into a file-exfiltration oracle.

### 8.7 Generated/minified/binary sources

Return `UNVERIFIED_LIMIT` for oversized sources and `SOURCE_UNAVAILABLE(binary/encoding)` for NUL-bearing or unsupported encodings. Provide a manual opt-in with an explicit higher limit. Never replacement-decode binary data and produce a misleading diff.

### 8.8 Artifact changed after receipt

Every receipt binds the artifact SHA-256. Completion verification recomputes it; mismatch invalidates all prior quote receipts and triggers a fresh check. Source-cache keys include revision or current file metadata, and the final receipt stores source SHA-256. This makes a stale green receipt cheap to detect.

## 9. Calibration and rollout plan

### Phase 0 — offline golden suite

Build at least these fixture families:

* 50 exact quotes across LF/CRLF, BOMs, tabs, trailing spaces, non-ASCII and embedded backticks;
* 50 one-character/case/space/punctuation paraphrases;
* 30 source-drift cases with a resolvable Git snapshot;
* 20 moved quotes;
* 20 duplicates with/without prefix/suffix/hints;
* 30 use/mention negatives, including the defect-report self-documentation pattern;
* 20 invalid/unavailable/path-escape/large/binary cases;
* 20 race and artifact-after-receipt cases.

All expected states are human-authored before implementation output is viewed. Parser fuzzing with arbitrary Markdown should assert “never crash, never read an undeclared source, never pass malformed declarations.”

### Phase 1 — shadow on real artifacts

Run for at least two weeks or 600 clean registered quotes, whichever is later. Sample every non-pass plus 10% of passes for owner adjudication. Track:

* `true_misquote`, `true_drift`, `benign_relocation`, `ambiguous`, `checker_bug`, `false_failure`, `unavailable`;
* check milliseconds, source bytes, cache hit;
* registered quote count and human-labeled unregistered file-quote count;
* repair action and whether the agent corrected, reclassified as paraphrase, or proved the detector wrong.

With zero false failures in 600 clean quotes, the simple rule-of-three 95% upper bound is approximately 0.5%. This bound applies only to the sampled distribution. If even one detector message tells an agent to discard a successful source read, enforcement is reset; diagnostics must never replace original tool output.

### Phase 2 — advise

Advise on all typed non-pass states in one consolidated message, at most once per artifact hash. Measure correction acceptance and repeat-warning rate. Promote only states with precision >=99% and owner-confirmed usefulness. The 99% target is a design threshold, not a measured claim.

### Phase 3 — narrow enforce

One-shot block only explicitly registered deliverables on:

* `MISQUOTE` with unchanged observed source hash;
* `SOURCE_DRIFT` with a resolvable snapshot that passed;
* `INVALID_REVISION_QUOTE`;
* malformed Quote Contract declarations.

Do not enforce `CONTEXT_DRIFT` until a separate labeled set reaches the same precision target. Do not enforce unregistered quote heuristics at all. If false failures exceed 0.5% in a rolling 600-clean-quote window, automatically demote to shadow/advice.

### Success and sunset criteria

The check earns permanence only if all hold:

1. seeded registered-quote recall >=99%;
2. clean registered-quote false-failure <=0.5% with the confidence condition above;
3. median cached cost <=10 ms/quote and p95 artifact check <=200 ms on Windows;
4. at least 80% of human-labeled file quotations become registered after the emitter is introduced;
5. at least one true mismatch/drift is caught per 500 registered quotes, or the measured cost is negligible enough that the owner explicitly retains it.

Thresholds 3-5 are policy choices and **UNVERIFIED — the Windows shadow experiment supplies their observed values and the owner decides retention**. If adoption remains low, improve emitter ergonomics or retire the always-on hook; do not widen to punctuation scanning to manufacture fires.

## 10. Rejected alternatives and dead ends

### Scan every quotation mark or Markdown blockquote

Rejected. It cannot distinguish file quotation from mention, UI label, hypothetical text, translation or epigraph. The known defects demonstrate this exact architectural failure (`INPUT-known-harness-defects.md:9-41`). A high-fire detector would be worse than none.

### Fuzzy similarity as acceptance

Rejected. A one-word negation, number, operator or modal can invert meaning while retaining high similarity. Fuzzy matching may nominate a bounded diff candidate, never pass a quote.

### LLM/prompt/agent hook as the primary verifier

Rejected. Claude Code natively supports these hooks, but exactness is deterministic. A model adds tokens, latency, model drift and false positives, and can itself paraphrase. Semantic support checking is a separate escalated task after exact fidelity passes.

### Require only `path:line` citations

Rejected as sufficient proof. Lines move; branch content changes; a line number does not bind quoted text. It remains a useful hint and human link, but exact text plus snapshot/current state is stronger.

### Store only a hash of the quote

Rejected. The artifact already displays the quote, so hashing it proves only self-consistency. The verifier must re-read the source. A source-file hash helps classify drift but cannot recover a prior non-Git version.

### Copy entire source snapshots into a new evidence store

Rejected. Git already supplies immutable snapshots for tracked content; copying sources duplicates storage and creates a privacy surface. For non-Git content, return honest ambiguity or require an explicit content-addressed capture. No vector DB/KG/evidence service is justified.

### Parse shell commands to discover artifacts

Rejected. Bash/PowerShell quoting and redirection semantics are complex; Bash already has 1,631 unmatched-quote EOF failures in the measured ground truth, and payload scanning caused confirmed false fires. Use explicit manifests or the checker CLI.

### Block immediately because the check is “deterministic”

Rejected. Deterministic code can still have parser, encoding, path and race bugs. The workspace has 12+ guard false fires and a successful result was marked failed. Shadow calibration is mandatory despite the exact core predicate.

1. the fixture runner reports the expected state for every case; and
2. an independent end-to-end hook fixture writes an artifact, observes native hook output/receipt, changes the source, and observes the expected transition.

## 12. Gaps and required experiments

1. **Real prevalence/adoption:** UNVERIFIED — label at least 300 real artifacts for all exact file quotations and false-claim classes. This settles registration coverage and overall recall; the corpus cannot.
2. **Windows hook payload parity:** UNVERIFIED — capture sanitized `PostToolUse`, `TaskCompleted`, and `Stop` payloads for Claude and Codex and verify artifact path/final-message fields. Static adapters show intended mapping, not runtime parity.
3. **Shell-authored discovery:** no safe automatic discovery is established. Explicit manifest/CLI coverage must be measured. A shell parser is not recommended.
4. **Encoding distribution:** UNVERIFIED — inventory BOM/encoding metadata (not contents) for quoted source files in the shadow set. This decides whether UTF-8 plus BOM-declared UTF-16 is sufficient.
5. **Git dirty/non-Git provenance:** immutable recovery is unavailable from a bare SHA-256. Test whether emitting exact quotes primarily from clean Git revisions fits owner workflows; otherwise design an explicitly authorized content-addressed capture, still without a daemon/database.
6. **Context-selector value:** UNVERIFIED — mutate surrounding context in 300 real quotes and have the owner label whether meaning changed. This settles `CONTEXT_DRIFT` precision and whether it ever graduates from advice.
7. **Performance:** UNVERIFIED on Windows — replay 1,000 quotes over the real size/path distribution, cold and warm cache, with antivirus active; measure median/p95/timeout.
8. **Existing implementation elsewhere:** not established. The supplied harness tree has no located quote-fidelity module after a bounded term search whose control found `ClaimWarningModule`, but Windows-only/origin-only paths were not exhaustively available. Before building, search the live subject and `origin/main` for `quote-source|quote.?fidelity|TextQuoteSelector|SOURCE_DRIFT` and inspect any hit.
9. **Native `if` support on installed version:** UNVERIFIED — exercise `/hooks` and a path-qualified fixture. In-hook filtering is the fallback and avoids dependence.
10. **Audit live counts:** C11's live warning counts were not reproduced on this remote snapshot. They are not required for the recommendation.

## 13. Final recommendation

Adopt Quote Contract v1 and build the one-file deterministic checker/emitter on the existing PostToolUse/Stop/shared-dispatcher bus. Start with exact membership, snapshot-versus-current classification, newline-only normalization, bounded diagnostics, source allowlists, artifact/source hashes, and known-positive parser controls. Ship in shadow, measure registered recall, clean false failures, registration coverage, Windows cost and repair usefulness, then enforce only the narrow proven states.

This is ambitious in the useful direction: it turns an unverifiable rhetorical convention into a typed evidence receipt and distinguishes original misquotation from later drift when provenance permits. It is deliberately modest in architecture. It cannot eliminate hallucination, cannot validate interpretations, and cannot protect quotes that agents decline to register. Those limits are features of an honest detector, not reasons to pretend a semantic guard can do more.
