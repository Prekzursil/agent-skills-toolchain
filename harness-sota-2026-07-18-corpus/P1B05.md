**Unit:** P1B05  
**Subsystem:** user slash commands  
**Subject:** `C:\Users\Prekzursil\.claude\commands`  
**Observed:** 2026-07-18 on Windows, Claude Code `2.1.214` (`claude --version` returned exactly that)  
**Scope boundary:** inventory, correctness, staleness, and overlap with skills. This unit did not modify the subject, install anything, invoke destructive command bodies, or audit neighboring hook/agent/skill subsystems except for bounded dependency checks.

## Executive verdict

**Overall: DEGRADED, with a large BREAKING tail.** The directory is not a coherent current command layer. It is a 271,439-byte, 8,180-line accumulation of at least three generations: generic prompt recipes, Metaswarm commands, and newer thin wrappers around canonical skills/local tools. Of 71 files, this audit assigns **19 healthy, 21 degrading, and 31 breaking** item verdicts. “Breaking” means the named file cannot deliver its advertised behavior in the observed installation, is unreachable because a higher-precedence command/skill owns the name, or requires a dependency proven absent. “Degrading” means it remains usable but materially misroutes, duplicates a better current facility, carries stale claims, or lacks an executable/state contract.

This aggregate verdict is **almost certain (90-99%)** because it combines (1) a complete `rg --files` inventory, (2) direct line-by-line inspection of all 71 files, (3) independent `Test-Path` and `rg --files` dependency checks with known-present controls, (4) installed-version output, (5) current official Claude Code precedence/command documentation, and (6) corpus capability counts. The residual uncertainty is runtime dispatch behavior for a few plugin/native collisions that was not tested interactively; those are marked **UNVERIFIED** inline.

The highest-impact facts are:

1. **Six local names are shadowed or reserved in the current runtime.** `plan.md` and `status.md` collide with fixed native commands; `code-review.md` and `verify.md` collide with bundled skills; `grill-me-extensive.md` and `multi-ai-mingle.md` collide with same-name personal skills under `~/.claude/skills`. Claude documents that a skill takes precedence over a same-name command and lists `/plan`, `/status`, `/code-review`, and `/verify` as current built-in/bundled facilities: <https://code.claude.com/docs/en/slash-commands#where-skills-live>, <https://code.claude.com/docs/en/commands>. `settings.json` has neither `disableBundledSkills` nor a `skillOverrides` object (both `rg` and Python JSON membership checks returned absent; the same probes found the known-present `enabledPlugins` key). Thus the local file content is not the effective behavior for these names. The shadowing conclusion is **very likely (80-90%)**; an interactive `/plan`, `/status`, `/verify`, `/code-review`, `/grill-me-extensive`, and `/multi-ai-mingle` trace with prompt-expansion logging would raise it to near certainty.
2. **Five `multi-*` commands are hard-broken.** `multi-backend.md:35,50,68-70`, `multi-execute.md:26,41,59,87-88`, and `multi-workflow.md:39,54,75-77` require `~/.claude/bin/codeagent-wrapper` and `~/.claude/.ccg/prompts/{codex,gemini}`. `Test-Path` returned false for all three targets, while the same probe returned true for known-present `~/.local/bin/codexmon.ps1`; a separate bounded filesystem search also found no target. This confirms audit claim B08 with mechanically independent signals. `multi-frontend.md` and `multi-plan.md` use the same call contract. Confidence: **almost certain (90-99%)**.
3. **Delegation targets are missing across several families.** The `context-budget`, `create-issue`, `pr-shepherd`, `handling-pr-comments`, `rules-distill`, `design-review-gate`, `plan-review-gate`, and `orchestrated-execution` skill paths all returned false by `Test-Path`; a separate `rg --files` search returned `NO_MATCH` while successfully finding known-present `prompt-optimizer` and `multi-ai-mingle`. `review-design.md:27-32` requires five reviewer agents, and all five exact local agent files were absent, while the same probe found known-present `architect`, `planner`, and `python-reviewer`. Confidence: **almost certain (90-99%)**.
4. **Metadata is sparse and unsafe by default.** Only 33/71 files begin with YAML frontmatter and have a `description`; 38 rely on the first Markdown paragraph as the listing fallback. Only `setup-pm.md:2-3` sets `disable-model-invocation: true`, even though many commands mutate repositories, create issues, start daemons, or install/update tools. Claude documents that descriptions are always listed to the model by default, the first paragraph is used when absent, and side-effecting task skills should use `disable-model-invocation: true`: <https://code.claude.com/docs/en/slash-commands#configure-skills>. This is a direct count, not an inference.
5. **The command set is overwhelmingly old relative to a fast-moving runtime.** File dates group as 14 on 2026-03-30, 44 on 2026-04-05, and only 13 modified afterward. Modification time alone does not prove semantic staleness, but it correctly identifies the two mass-import cohorts. The actual stale semantics are independently demonstrated by native `/btw`, `/plan`, `/status`, `/verify`, `/code-review`, `/rewind`, `/loop`, `/autofix-pr`, `/context`, and session capabilities documented for installed Claude Code 2.1.214.
6. **Measured use is extremely concentrated.** The corpus says `files_seen=11633`, `files_failed=0`, `lines_bad=1` (`corpus.json:2-10`), and records only a small subset among `capability_use.skills_invoked`: `self-reflect=18`, `review-design=10`, `brainstorm=3`, `learn-eval=2`, `context-budget=2`, `prompt-optimize=2`, and one each for `codex-monitor`, `rules-distill`, `update`, and `start-task` (`corpus.json:13265-13344`). This detector mixes skills and command expansions, so it is evidence of observed capability-name use, **not** a command-only invocation census. No absence conclusion is drawn from it.

## Health rubric

* **HEALTHY:** invocable/effective in the observed installation, internally coherent, and has no material stale or missing dependency found. Cosmetic metadata gaps may remain.
* **DEGRADING:** still usable, but an incorrect claim, ambiguous execution contract, unnecessary overlap, portability flaw, or stale routing materially reduces reliability.
* **BREAKING:** advertised core behavior cannot execute, the file is unreachable/shadowed, or a mandatory dependency is proven missing.

Cosmetic findings do not change an otherwise healthy item. Degrading and breaking grades cite the evidence that determines severity.

## Cross-cutting correctness and staleness findings

### F1 — Shadowed files create false maintenance and false assurance

Severity: **breaking for the six files; degrading for portfolio comprehension.**

The six collisions are `code-review`, `verify`, `plan`, `status`, `grill-me-extensive`, and `multi-ai-mingle`. Official precedence is explicit for skill-vs-command. Fixed native command precedence over same-name custom files is **UNVERIFIED** by an interactive expansion trace; the local version plus docs make it **very likely (80-90%)** that fixed `/plan` and `/status` win. Experiment: enable `UserPromptSubmit`/`UserPromptExpansion` logging in a disposable session and invoke each name once, recording which content appears.

This matters because maintainers can edit a file and believe they changed behavior when they changed an inert artifact. It also makes corpus capability-name counts ambiguous: `codex-monitor=1` may be a command expansion, while `review-design=10` could be command/skill depending on the period.

### F2 — The April multi-model family is a dead architecture island

Severity: **breaking.**

`multi-backend`, `multi-execute`, `multi-frontend`, `multi-plan`, and `multi-workflow` are not five independent commands; they are copies of one retired wrapper/`.ccg` architecture. The absent targets and repeated Gemini authority text prove the family shares one failure. Current capabilities already provide native subagents, official Codex MCP fan-out, the `multi-ai-mingle` skill, and native `/batch`. Keeping the dead family increases selection ambiguity without a usable rail.

### F3 — Command wrappers point to three incompatible ownership models

Severity: **breaking/degrading depending item.**

There are:

* Correct cross-tool wrappers (`grill-me`, `grill-with-docs`) pointing at `~/.agents/skills` plus a shared workflow.
* Correct local-tool wrappers (`compute-monitor`, `cs`, `mcp-gui`, `agent-monitor`) pointing at verified stable scripts.
* Broken plugin-derived wrappers that assume `${CLAUDE_PLUGIN_ROOT}` or project-relative `scripts/` even though they live as user commands (`claw`, `harness-audit`, `evolve`, `projects`, `instinct-*`, `promote`).

The last group was apparently copied from ECC plugin commands without preserving the plugin-root resolver. `skill-health` and `sessions` demonstrate the resolver pattern that would have been required (`skill-health.md:15-31`; `sessions.md:29-33`).

### F4 — Commands are listed to the model too aggressively

Severity: **degrading.**

Only one of 71 is manual-only. Current docs explicitly recommend `disable-model-invocation: true` for deploy/commit/side-effect workflows. At minimum, installers/updaters, issue/PR mutators, PM2 setup, checkpoint/rollback, loop launchers, session writers, and multi-agent orchestrators should not be auto-selected. The 38 no-description files also inject fallback first paragraphs into skill discovery; earlier audit A24 measured 3,662 fallback characters across 38 items. This unit independently confirms the count 38 but did not independently reproduce the 3,662-character total.

### F5 — Parallel memory/session systems are stale against the owner contract

Severity: **degrading.**

`prime`, `learn`, `learn-eval`, `self-reflect`, `save-session`, `resume-session`, and `sessions` write/read `.beads`, loose learned Markdown, or `~/.claude/sessions` instead of consistently using canonical basic-memory plus the shared event ledger/native transcript. The owner contract explicitly says basic-memory is canonical semantic memory and the ledger is objective history. These commands can surface conflicting “current” facts after compaction.

### F6 — Current native facilities subsume much of the generic prompt layer

Severity: **degrading, not an automatic deletion verdict.**

Native `/btw`, `/context`, `/plan`, `/verify`, `/code-review`, `/loop`, `/rewind`, `/autofix-pr`, `/batch`, `/subtask`, `/tasks`, and session branching/resume now cover functions that did not exist or were weaker when the March/April cohort was written. Some custom commands remain useful because they add owner-specific semantics (named Git checkpoints, workflow-agent monitoring, local compute descriptors). The correct decision is therefore capability-by-capability consolidation, not blind replacement.

## Proposal inputs for design/build phases

These are scoped recommendations, not changes performed by this ground unit. Every proposal rides the existing native command/skill/hook bus and passes the anti-overfit gate; none introduces a second orchestration runtime, vector DB/KG, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

Add `disable-model-invocation: true` to any retained command that installs/updates, creates GitHub objects, starts daemons/loops, writes global memory, changes PM2 configuration, or restores checkpoints. It is **very likely (80-90%)** to reduce accidental selection; official docs explicitly recommend the flag for side-effecting task content.

## Alternatives considered and rejected

1. **Repair every legacy command in place.** Rejected because current skills/native commands already own many capabilities, and repairing five `.ccg` copies would preserve a retired architecture and selection ambiguity.
2. **Delete all 71 commands.** Rejected because verified local operator fronts (`compute-monitor`, `cs`, `mcp-gui`, `agent-monitor`), compact recipes (`quality-gate`, `test-coverage`, `update-docs/codemaps`), and intentional cross-tool bridges still add value.
3. **Build a new command daemon/registry.** Rejected by the anti-overfit gate. Claude’s skill discovery, frontmatter, hooks, and MCP bus already provide the needed lifecycle.
4. **Treat all no-frontmatter files as broken.** Rejected because current Claude explicitly supports first-paragraph fallback and optional frontmatter. Missing descriptions are a context/selection defect, not a parse failure.
5. **Treat corpus non-use as proof of deadness.** Rejected because the corpus detector reports capability names, not a complete command-only invocation ledger, and command/skill collisions make attribution ambiguous.
6. **Delete custom rollback because native rewind exists.** Rejected because native checkpointing does not cover Bash/external changes; the existing edit-checkpoint hook may preserve owner-specific value. Only its stale claim and overlap should be corrected.
