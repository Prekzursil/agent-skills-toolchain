# A005 — coherence audit: `rules/common/development-workflow.md`

## Scope and verdict

This unit audited the complete 58-line rule at `/local_disk0/codexwork/bundle/claude/rules/common/development-workflow.md:1-58` against the supplied rule tree, the supplied Claude agent definitions, the local and shared hook implementations and their active registration documents, `settings.json`, `CLAUDE.md`, `AGENTS.md`, and the measured corpus. The subject tree was read-only; this artifact is the only file written.

The rule is not a coherent executable contract. It is a second, partially divergent copy of policies already held by `testing.md`, `code-review.md`, `git-workflow.md`, the live agent roster, and hooks. Its fixed agent names contradict the roster-routing rule; its plan requirements contradict the planner's own activation threshold and output contract; its coverage fallback contradicts the `tdd-guide` agent; its HIGH-severity policy contradicts both the review rule and reviewer agent; and its source-extension frontmatter prevents a purportedly general development workflow from applying to several languages that the installed rule tree explicitly supports. Most of the workflow is advisory-only, while unrelated syntax and test-tamper hooks enforce extra gates that the rule does not disclose.

The strongest resolution is full replacement of this file, not incremental accretion. **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Replace it with a short task-proportional workflow that owns only phase ordering and delegates each phase's details to one canonical artifact. This is **very likely (80-90%)** to reduce collisions because five conflicts below come from duplicated thresholds or duplicated role names, while `rules/common/agents.md:3`, `rules/common/testing.md:23-49`, `rules/common/code-review.md:71-99`, and `rules/common/git-workflow.md:23-38` already provide the canonical buses. A controlled instruction-load plus feature-task replay (defined under “Acceptance experiment”) settles the remaining effectiveness uncertainty.

This replacement passes the anti-overfit gate: it uses Claude's existing rule-loading, live roster/`/start-task`, existing agent definitions, existing hooks, and the shared receipt ledger. It adds no second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. No previously rejected component is reintroduced.

## Precedence applied

`AGENTS.md` is the higher shared contract. Its order is user/permissions, security and safety, the cross-tool contract, project/repo governance, then third-party skill/plugin defaults (`claude/AGENTS.md:115-131`). The following consequences were applied rather than silently choosing a side:

- A user instruction can bypass the workflow. The target's word “mandatory” at `development-workflow.md:29` cannot override an explicit in-session instruction under `AGENTS.md:121`.
- The target cannot authorize a dangerous push. Security remains higher, including explicit approval for force-pushing main/master (`AGENTS.md:93-106,121-126`).
- Common rule files are project/repo governance beneath the cross-tool contract. A hook that blocks a non-dangerous syntax error conflicts with the higher §6 rule even if a lower rule prefers clean syntax.
- The rule README separately says language-specific rules override common rules (`rules/README.md:93-104`). That resolves common-versus-language idiom differences, but it does not resolve conflicts between two files in `rules/common/`, or between a local common rule and a local agent definition. `AGENTS.md` classifies third-party skill/plugin defaults but does not classify user-local agent markdown. Those same-level/local-agent conflicts are explicitly reported as unresolved by precedence.
