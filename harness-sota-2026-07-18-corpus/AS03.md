# AS03 — coherence sweep: commands versus skills

## Scope, method, and detector controls

This unit inspected all 71 Markdown files in the supplied command snapshot at `/local_disk0/codexwork/bundle/claude/commands/`. The subject was read-only; the only write is this artifact. The remote bundle does not include the live Windows `~/.claude/skills` or `~/.agents/skills` trees. A bounded `find ... -name SKILL.md` did detect the known-present control `/local_disk0/codexwork/bundle/claude/hooks/no-force-push/SKILL.md`, proving that the filename detector can find a `SKILL.md`; it found no skill catalog payload. A separate directory inventory shows that the bundle has `claude/{agents,commands,hooks,rules}` but no `claude/skills` or `agents/skills` directory. Those two observations share the same unpacked snapshot, so they are not mechanically independent enough to claim that any skill is absent on the Windows subject. Accordingly, this report uses the earlier audit inventories as claims/evidence about the live skill roots, labels unresolved live-path questions inline, and never converts snapshot omission into a live absence claim.

The most useful pinned inventory is the earlier bounded exact-name comparison: Claude had 75 direct skills, of which 54 also existed in `.agents/skills`; it prints both full sets and states that every counted entry had a direct `SKILL.md` (`inputs/audit-findings/B03.md:24-30`). The command-context audit independently measured `command_files=71`, `shadowed_by_skill=2`, and `unique_commands=69` (`inputs/audit-findings/A24.md:63-69`). Intersecting the 71 bundled command basenames with B03's complete 75-name Claude list yields exactly two names: `grill-me-extensive` and `multi-ai-mingle`. This reproduces A24's independently reported shadow count of two and is the basis for the exact-shadow conclusion below.

Classification vocabulary:

- **thin wrapper**: the command chiefly selects a skill/agent/external executable and passes intent;
- **operator adapter**: a useful explicit entry point for a monitor, CLI, or state operation, not a competing skill body;
- **standalone command**: the Markdown itself is the workflow implementation;
- **stale/broken**: it names an absent/moved dependency, is explicitly superseded, or materially conflicts with the current skill/hook bus.

Proposal tags use the required values verbatim. No proposal introduces a second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. Where an existing command *is* a second runtime, the resolution is retirement.

## Executive verdict

The command surface is not a clean compatibility layer. It contains two safe exact-name shadows, a useful set of operator adapters, but also multiple generations of metaswarm setup/update/task orchestration and several large standalone prompts that duplicate skills or agents. The clearest breaking defect is `/context-budget`: the command delegates all work to `skills/context-budget/SKILL.md` (`claude/commands/context-budget.md:20-29`), while a prior bounded Windows check found that target false in all three canonical roots (`inputs/audit-findings/D13.md:39-45`). The clearest moved-path defect is `/self-reflect`: its relative BEADS assets were absent from the defined repo/workroot and copies were found only in nested metaswarm bundles (`inputs/audit-findings/E01.md:39-45`). The clearest stale collision is `/update` explicitly saying it replaces `/metaswarm-update-version` while that 67-line old command remains installed (`claude/commands/update.md:20-24`; `claude/commands/metaswarm-update-version.md:1-17`).

It is **almost certain (90-99%)**, based on the exact 71-command inventory, the complete 75-skill name list, and the independently matching shadow count, that the only direct personal-root command/skill name shadows at the captured Windows state were `grill-me-extensive` and `multi-ai-mingle`. It is **very likely (80-90%)**, based on explicit delegation in both command bodies and the absence of competing logic, that removing those two redundant command files after an invocation smoke test would preserve behavior. Host precedence and plugin-added entries are **UNVERIFIED**; a disposable Claude config followed by `/help`, explicit invocation of both names, and a captured selected source would settle precedence before deletion.

These are not safe intentional aliases: they encode different installation authorities.

Specific resolution — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**: keep `/setup` and `/update` as short namespaced-skill wrappers; delete `/metaswarm-setup` and `/metaswarm-update-version`; add one tombstone sentence for one release if discoverability is required. This is **almost certain (90-99%)** to remove contradictory npm-versus-marketplace behavior because the replacement declaration and both old npm execution paths are explicit.
