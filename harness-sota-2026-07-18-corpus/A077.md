# A077 — Coherence audit of `rules/web/design-quality.md`

## Verdict

The rule is directionally consistent with the other supplied web rules, but it is not coherent with the mechanism that is supposed to operationalize it. The rule says that style direction, palette, typography, references, and relevant design skills are chosen **before frontend code** (`claude/rules/web/design-quality.md:47-53`). The active shared harness instead (a) injects a substantially stronger Figma-first workflow that the rule never states, (b) uses a fallback drift threshold of five style-file edits, and (c) deliberately exempts subagents (`agents/harness/modules.py:2423-2455,2476-2487,2515-2548`). The target's aesthetic output requirements—its banned patterns, “at least four” qualities, and screenshot-believability test—have no corresponding active evaluator in either hook bus (`claude/rules/web/design-quality.md:21-45,69-75`; `claude/settings.json:81-210,484-505`; `claude/hooks/_dispatch/manifest.json:72-227`).

The most defensible classification is therefore:

- the **workflow part is contradicted in timing and under-specified relative to the live hook**;
- the **quality gate is badly written for enforcement** because key predicates are subjective and “at least four” has no rationale or evidence contract;
- the **current requirement is unenforced**, not proven wrong;
- the corpus cannot score aesthetic compliance, so it does not establish that the rule is followed or violated.

It is **very likely (80-90%)**, based on the pre-code mandate at `design-quality.md:47-53`, the fifth-edit fallback at `modules.py:2515-2548`, and the lack of a visual-quality check in both active hook registries, that agents can produce several iterations of UI without the harness establishing compliance with the rule. This is a mechanism claim, not a claim about the quality of any particular shipped UI.

## Collision register

### C1 — CONTRADICTION: “before code” versus a fifth-edit drift gate

**Artifacts and exact lines**

- `claude/rules/web/design-quality.md:47-53`: before writing frontend code, choose a style direction, palette, typography, real references, and relevant skills.
- `agents/harness/modules.py:2515-2519`: the hook describes its detector as a mid-task fallback and counts style-file writes/edits.
- `agents/harness/modules.py:2520-2538`: it accepts `Write|Edit|MultiEdit|NotebookEdit`, increments `style_edits`, and returns success while the count is below five.
- `agents/harness/modules.py:2539-2548`: only at the fifth matching edit does it inject “CODE-FIRST DRIFT”.

Exact conflicting text:

> `design-quality.md:47-53` — “Before Writing Frontend Code” … “Pick a specific style direction” … “Define a palette intentionally” … “Choose typography deliberately” … “Gather at least a small set of real references.”
>
> `modules.py:2515-2519,2534-2545` — “Count style-file Write/Edit; if >=5 with no design tool seen this session, inject ONCE” … `if count < 5: ... return HookResult.success()` … “CODE-FIRST DRIFT: {count} style-file edits”.

**Why this collides**

The hook's fallback permits four style edits before enforcing a rule whose stated deadline is before the first frontend edit. The ordinary prompt path can remind earlier when the prompt matches `_DESIGN_INTENT` (`modules.py:2490-2513`), so this is not a claim that every design request waits five edits. It is a precise mismatch for continued plans, vague prompts, and any intent missed by the regex—the exact cases the fallback says it exists to catch.

Section 10 does not say whether the path rule or hook wins. Treating the hook threshold as an implementation detail silently weakens the rule.

**Specific resolution (UNVERIFIED) — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Replace the edit-count gate with a state transition: on a design-intent prompt, record `design_required`; before the first style-file write, inject once if no accepted design-direction receipt exists. Retain a low-noise fallback for continuation prompts, but make it trigger on the first qualifying style edit and phrase it as a request for a design-direction decision, not mandatory Figma usage. Add fixtures for explicit minor CSS fixes, user-supplied finished designs, generated-code edits, and continuing a previously approved direction. This is **likely (55-80%)** to align timing without excessive noise, based on the existing per-session state and prompt/edit machinery at `modules.py:2458-2548`; **UNVERIFIED — settle by replaying a labeled set of real UI prompts and measuring false-injection and missed-preflight rates before changing the live threshold.**

Anti-overfit gate: this edits the existing module and state bus. It adds no runtime, database, critic, SaaS, or guardrail framework.
