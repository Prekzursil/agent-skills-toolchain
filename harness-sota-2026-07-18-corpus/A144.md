## Runtime semantics that are verified generally, but cannot be instantiated here

It further states that denylist matches block a server and nothing overrides such a match, while allow/deny policy can filter even managed servers.

These are runtime rules, not evidence that the owner has any particular managed file, duplicate server, or policy entry. Applying them to an absent file would be inference beyond the evidence.

These pairs look contradictory only if “allowed” is incorrectly treated as “mounted.” It is not. If another MCP source supplies the same logical service, the permission can still be relevant. If no source supplies it, the rule is dormant. The concrete X/NOT-X collision therefore never arises from these texts alone.
