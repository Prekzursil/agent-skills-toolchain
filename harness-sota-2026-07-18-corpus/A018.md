### Runtime-loading and precedence evidence

The audit does not assume that agent files and rules are isolated. Current official Claude Code documentation says a non-fork custom subagent starts with (a) its own system prompt and (b) the `CLAUDE.md`/project-rules hierarchy loaded by the main conversation ([Create custom subagents, lines 756-765](https://code.claude.com/docs/en/sub-agents)). It also says rules load every session or when a matching file is opened, and path-scoped rules apply when matching files are being worked on ([How Claude remembers your project, lines 226-259](https://code.claude.com/docs/en/memory)). Thus each collision below has an actual joint-loading path; path-scoped findings state that path explicitly.

For textual conflicts, the agent body is the subagent's system prompt while rule content is delivered through the normal memory/rules message flow. Official docs explicitly say CLAUDE/rule content is a user message after the system prompt and is not enforced configuration; conflicting memory instructions can be selected inconsistently ([How Claude remembers your project, lines 403-411](https://code.claude.com/docs/en/memory)). Therefore the agent-side instruction is the higher message-level authority, but the practical outcome is not a deterministic safety control. It is **very likely (80-90%) that the agent-side directive dominates each direct textual collision**, based on the documented system-prompt versus user-message placement; the residual uncertainty is model adherence, not file loading. **UNVERIFIED on the pinned Windows binary:** an exact live transcript showing which text the installed binary injects was unavailable because `claude` is absent on this Linux node and the Windows instruction log is not in the bundle. The settling experiment is an `InstructionsLoaded` trace plus one controlled invocation per conflicting agent, recording the subagent transcript under `~/.claude/projects/.../subagents/`.

For model fields, runtime precedence is deterministic: current docs resolve `CLAUDE_CODE_SUBAGENT_MODEL`, then per-invocation model, then agent `model` frontmatter, then the main model ([Create custom subagents, lines 332-347](https://code.claude.com/docs/en/sub-agents)). The supplied `settings.json:4-20` has no `CLAUDE_CODE_SUBAGENT_MODEL`, so absent an unseen process environment or per-invocation override, the agent frontmatter wins.
