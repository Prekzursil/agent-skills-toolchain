## Executive result

The testing rule is not a coherent executable contract. Its useful center is the project-owned coverage threshold plus RED–GREEN–REFACTOR, but four different layers weaken or distort that center:

1. The rule says all three test types are always required, while its own `tdd-guide` says E2E is required only on critical paths.
2. The rule names `.coverage-thresholds.json` as the single source of truth, while the referenced agent and five language rules restate a fixed 80% target. Those copies are already semantically stale whenever a project threshold is higher (the rule itself says metaswarm is 100%).
3. The mechanical gates do not enforce test-first development, test topology, or the configured threshold. The only TDD-specific commit hook is Bash-only, commit-time, fail-open, and warning-only by default.
4. The shared completion-claim gate treats **one** fresh generic `test` receipt as enough support for the family `tests_pass`; that can support the phrase “all tests pass” even when only a targeted test ran.

The behavioral corpus reinforces the coherence problem. Its validated capability-use detector found 1,745 `Agent` calls and 1,158 `general-purpose` calls but zero `tdd-guide` and zero `e2e-runner` calls. It also found 41,809 `Write`+`Edit` calls. It is therefore **very likely (80-90%)** that the proactive-agent clauses are not operational habits; evidence is the exact zero counts in two named agent categories against the known-present `general-purpose` control, plus the large edit volume. This is not proof that no TDD occurred without those agents.

The corpus cannot establish chronological RED-before-implementation behavior or achieved coverage because the distilled tool rows omit Bash/PowerShell command arguments and sequencing. **UNVERIFIED: whether the code changes generally followed RED–GREEN–REFACTOR or met repository thresholds; settle by querying the raw JSONL for each mutation’s preceding/following test command and parsing fresh coverage artifacts per repo.** The corpus `hooks` section is explicitly broken and is treated as no data, exactly as required.

The best resolution is evolution, not a replacement runtime: make one risk-scoped testing contract authoritative, have agents point to it instead of copying thresholds, and make the existing receipt/hook bus distinguish targeted tests, full suites, coverage, and E2E. No second orchestrator, vector store, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed.

## Behavior versus rule: bad writing, wrong policy, or unenforceability

### Badly written

- “Test Types (ALL required)” (`testing.md:25`) fails to express applicability, while its own description and agent restrict E2E to critical flows.

### Wrong

- Fixed 80% copies are wrong whenever the project SSOT is higher; the target itself supplies metaswarm=100 as a concrete counterexample (`testing.md:23` versus `tdd-guide.md:39`).

### Unenforceable as written

- Chronological TDD is intent-sensitive and the current hooks see edits, commands, or commits—not a reliable semantic “test describes the next implementation” relation.
- “All types” cannot be enforced until applicability and task scope are represented.
- Coverage cannot be enforced from a generic `test` receipt; it requires a coverage receipt carrying actual threshold/metric results.
- Proactive agent use is advisory and has neither a router trigger nor a completion receipt.

### Higher-precedence override, not a lower-rule violation
