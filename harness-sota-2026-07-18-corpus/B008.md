# B008 — Groundedness engineering: confidence calibration

Date: 2026-07-19  
Unit: B008  
Subject access: read-only unpacked bundle at `/local_disk0/codexwork/bundle`  
Artifact scope: design and measurement specification only; no subject files or configuration were changed.

## Executive verdict

The harness mandates Sherman–Kent words, but it does not currently calibrate them. It checks the *shape* of a hedge, not whether forecasts assigned a band later resolve inside that band. The direct implementation accepts any percentage, the word `confidence`, or a generic evidence-looking token as sufficient form (`/local_disk0/codexwork/bundle/agents/harness/modules.py:2044-2049`), and its response is only a same-turn nudge (`modules.py:2251-2265`). Its regression test proves that the phrase `~80% confidence, tests cited` silences the nudge without testing the evidence or recording an outcome (`/local_disk0/codexwork/bundle/agents/harness/tests/test_modules.py:1839-1853`).

The right replacement is not a more elaborate prose matcher. It is a small forecast ledger on the existing hook/event-ledger bus: record a falsifiable atomic event, the mandated band, a predeclared resolution rule and evidence pointers *before* the outcome; append the outcome later; then report the observed hit rate and a binomial uncertainty interval for each band. A band is not shown to be calibrated merely because its point estimate lies inside the advertised range. “Calibrated at current precision” requires its full uncertainty interval to lie inside the range. “Miscalibrated” requires the full interval to lie outside, followed by the same-direction result on a later holdout cohort before changing behavior.

This design cannot eliminate hallucination. No calibration system can turn one self-reported probability into a truth oracle. Its achievable functions are narrower: make unsupported forecast claims machine-enumerable, make systematic over/underconfidence detectable after outcomes arrive, and make the cost and false-positive rate of any intervention measurable. Xiong et al. found verbalized LLM confidence generally overconfident and no elicitation method consistently best, especially on difficult professional tasks ([ICLR 2024 primary paper](https://proceedings.iclr.cc/paper_files/paper/2024/hash/6733cf15e10e2cd1d59af033c3bb8507-Abstract-Conference.html)). Long-form calibration also requires claim-level treatment rather than one correctness label for a whole answer ([Huang et al., EMNLP 2024](https://aclanthology.org/2024.findings-emnlp.785/)).

The recommended mechanism is **very likely (80-90%)** to produce useful local calibration measurements after enough resolved, non-duplicated forecasts accumulate. Evidence: the subject already has a cross-provider append-only event ledger and active Stop dispatcher wiring (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:468-487,817-880`; `/local_disk0/codexwork/bundle/claude/settings.json:484-503`), while binomial outcome rates and proper scores are standard forecast-verification methods. The remaining uncertainty is local capture rate, resolution yield, dependence between forecasts, and hook latency; the shadow pilot in §11 settles those rather than assuming them.

## 2. Statistical target: what “calibrated” means

For an atomic proposition recorded before its resolution, let `Y=1` if the proposition resolves true and `Y=0` if false. The band always refers to `P(Y=1)`. Negative wording must be normalized into an explicit proposition so polarity cannot silently invert the score.

Use exactly the owner-mandated vocabulary and ranges:

| Band | Probability interval for `Y=1` |
|---|---:|
| almost certain | 0.90-0.99 |
| very likely | 0.80-0.90 |
| likely | 0.55-0.80 |
| roughly even | 0.45-0.55 |
| unlikely | 0.20-0.45 |
| very unlikely | 0.05-0.20 |
| almost certainly not | 0.01-0.05 |

For each band `b`, among resolved and eligible predictions compute:

`n_b = count`, `k_b = sum(Y)`, and `r_b = k_b / n_b`.

Report `r_b` with a 95% Wilson binomial interval. NIST documents Wilson intervals for binomial proportions and warns that naive normal approximations are not accurate for small samples ([NIST/SEMATECH handbook](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)).

Status rules:

- **INSUFFICIENT:** no outcomes, or the Wilson interval is wider than the advertised band. Show counts; make no calibration claim.
- **COMPATIBLE, NOT ESTABLISHED:** the Wilson interval overlaps the advertised band but is not wholly contained by it.
- **CALIBRATED AT CURRENT PRECISION:** the entire Wilson interval lies within the advertised band, capture-quality gates pass, and the result is not contradicted in required strata.
- **OVERCONFIDENT:** the Wilson interval lies wholly below the band.
- **UNDERCONFIDENT:** the Wilson interval lies wholly above the band.
- **DRIFT/CONFLICT:** aggregate and task/model/time strata point in materially different directions.

The “full interval inside” rule is intentionally conservative. Merely observing 67% correct for `likely (55-80%)` is not enough when `n` is tiny. At each band midpoint, approximate minimum independent counts for a Wilson interval no wider than the band are: almost certain 109, very likely 195, likely 52, roughly even 381, unlikely 52, very unlikely 74, and almost certainly not 302. These values were computed locally by enumerating `n`, rounding midpoint successes, and applying the Wilson formula. They are planning indicators, not universal sample-size guarantees; clustering and rates near band boundaries require more data.

Calibration is not sufficient for usefulness. A forecaster that always reports the base rate can be calibrated but uninformative. Proper scoring rules evaluate probability forecasts against realized outcomes and incentivize honest probabilities in expectation ([Gneiting & Raftery, JASA 2007 / University of Washington primary page](https://stat.uw.edu/research/tech-reports/strictly-proper-scoring-rules-prediction-and-estimation-revised)). Therefore the dashboard also reports:

1. exact-probability Brier loss `(p-Y)^2`, if the private card field `p_exact` is present;
2. log loss, clipped only by the mandated outer limits, as a secondary extreme-error diagnostic;
3. resolution/sharpness: distribution of issued bands and improvement versus a frozen prior-window base-rate forecast;
4. a reliability diagram using the seven fixed semantic bands, never data-chosen bins;
5. calibration by model snapshot, provider, task family, forecast horizon, evidence state, and stake tier.

`p_exact` is measurement, not evidence. It is kept out of normal prose to avoid precision theater, must fall inside the selected band, and must never make a claim more trusted at decision time. If `p_exact` is omitted, do **not** invent a midpoint. Report only band calibration and an interval of possible Brier loss: for `Y=1`, `[(1-u)^2,(1-l)^2]`; for `Y=0`, `[l^2,u^2]`. A midpoint score would falsely pretend that a range forecast was a point forecast.

Do not optimize an ECE number. Fixed-bin calibration error can be shown descriptively, but recent work demonstrates defects and incentive problems in common ECE estimators ([Chidambaram et al., ICML 2024](https://proceedings.mlr.press/v235/chidambaram24a.html)); a 2026 COLT paper further shows that familiar sample calibration measures can reward misreporting and proposes a truthful batch alternative ([Hartline, Hu & Wu, COLT 2026](https://proceedings.mlr.press/v336/hartline26a.html)). The primary evidence remains the per-band table, proper score, and held-out behavior.

## 3. The forecast record

### Proposal A — explicit prediction cards on the existing ledger

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Only decision-relevant, forward-looking uncertainty becomes a card. Ordinary factual statements backed by a current source, stylistic preferences, and harmless conversational hedges do not. A card is valid only if it is atomic, binary, falsifiable, time-bounded, and has a predeclared resolution rule.

Suggested additive event schema:

```json
{
  "kind": "prediction",
  "prediction_id": "sha256(canonical fields)",
  "created_ts": "UTC timestamp supplied by ledger",
  "provider": "claude|codex|agy",
  "model_snapshot": "exact model/version when available",
  "session_id": "sanitized id",
  "turn_id": "host turn id",
  "task_family": "code|ops|research|re|science|planning|other",
  "stake": "low|medium|high",
  "claim": "one positive-polarity proposition",
  "band": "likely",
  "band_lo": 0.55,
  "band_hi": 0.80,
  "p_exact_private": 0.68,
  "evidence_state": "DIRECT|INFERRED|UNVERIFIED",
  "evidence_refs": ["ledger:seq:123", "path:line", "url"],
  "resolution_rule": "exact observable predicate fixed before outcome",
  "resolver": "receipt|command|external-source|human",
  "resolve_after": "UTC timestamp or triggering event",
  "resolve_by": "UTC timestamp",
  "prediction_cluster_id": "shared originating proposition",
  "source_fingerprint": "commit/config/input hash where applicable"
}
```

Resolution is a second append, never an edit:

```json
{
  "kind": "prediction_resolution",
  "prediction_id": "...",
  "outcome": "TRUE|FALSE|INVALID|UNRESOLVED",
  "resolved_ts": "...",
  "oracle_refs": ["ledger:seq:456", "artifact hash", "authoritative URL"],
  "resolver_version": "...",
  "notes": "bounded reason"
}
```

`INVALID` means the card was ambiguous, its target changed, or its resolution rule was defective. `UNRESOLVED` means the deadline passed without enough evidence. Neither enters calibration denominators; both remain visible as authoring/resolution failures. Deleting them would create survivorship bias.

The card parser must accept only a reserved structured block produced for this purpose, not search arbitrary prose for the seven words. A document discussing “likely” or quoting the schema is not a card. This directly avoids the recorded use-vs-mention class (`INPUT-known-harness-defects.md:9-48`). It also means capture recall must be measured separately; high syntactic precision is not permission to assume all eligible claims were captured.

It is **very likely (80-90%)** that an additive `prediction`/`prediction_resolution` event can be implemented without a new store. Evidence: `EventLedger.append` already accepts arbitrary sanitized fields and appends them under a lock (`ledger.py:817-880`). UNVERIFIED is the Windows live latency and contention of the extra append; experiment P2 in §11 measures p50/p95/p99 hook delta and lock failures on the actual box before promotion.

## 4. Independence, leakage, and drift

Fan-out can repeat one originating claim across many agents. Counting each copy would manufacture confidence and falsely narrow Wilson intervals. Use `prediction_cluster_id` and one of two conservative policies:

- primary report: first pre-outcome prediction per cluster only;
- sensitivity report: all cards with equal total weight per cluster.

Never score a forecast created after any outcome evidence. Store creation sequence, evidence sequence, and source fingerprint; reject temporally contaminated cards.

Do not pool across silent model upgrades. `model_snapshot` is a cohort boundary. If an exact snapshot is unavailable, split at observed CLI/provider configuration changes and label the cohort version unknown. Report provider and task-family strata before any aggregate conclusion. An aggregate can look calibrated while code forecasts are underconfident and science forecasts overconfident.

Forecast horizons also differ. Report at least `same-turn`, `<24h`, `1-7d`, `8-30d`, and `>30d`; do not compare unresolved long-horizon cards with quickly resolved short-horizon cards. Show Kaplan-style “resolution yield by age” only as a censoring diagnostic, not as correctness.

Before declaring a band broken, require two mechanically independent signals:

1. discovery window: Wilson interval wholly outside its band, with capture-quality gates passing;
2. a later, frozen holdout window or a separate task-family cohort showing the same direction.

Changing the prompt or mapping invalidates the old intervention cohort. Preserve old forecasts; start a new versioned cohort.

## 5. Detector economics: the required scorecard

Calibration is retrospective. It catches no individual false claim before its outcome merely because the claim says `likely`. The evidence validator and oracle resolver are the claim-level detectors; the calibration report detects systematic mismatch. These must not be conflated.

For every component report the following confusion matrix against a blinded manual or objective adjudication sample:

- `TP`: detector flags a genuinely unsupported/false claim in its stated scope;
- `FP`: detector flags a supported/true claim, a mention/quote, or a semantically irrelevant item;
- `FN`: eligible unsupported/false claim not flagged;
- `TN`: eligible supported/true claim correctly silent.

Metrics:

- false-claim catch fraction (recall): `TP/(TP+FN)`;
- false-positive rate: `FP/(FP+TN)`;
- alert precision: `TP/(TP+FP)`;
- cost per eligible claim: added hook milliseconds + tokens + human adjudication seconds, divided by audited eligible claims;
- cost per caught false claim: total cost divided by `TP`;
- resolution yield: `(TRUE+FALSE)/(all due cards)`;
- invalid-card rate and overdue-unresolved rate;
- capture precision and capture recall for prediction cards;
- accepted-case error and coverage if confidence later routes abstention/verification.

Component expectations and honest unknowns:

| Component | False claims caught | Expected false-positive mechanism | Cost | Current evidence |
|---|---|---|---|---|
| Explicit-card schema validator | Only malformed/unsupported *marked* predictions | Parser mistakes a quoted card for a real card | one parse + append | Catch fraction UNVERIFIED; P3. Reserved framing makes low FP **very likely (80-90%)**, supported by avoiding arbitrary prose and the known-defect use/mention mechanism. |
| Evidence-reference existence check | Missing/nonexistent/late references | Existing reference is semantically irrelevant | ledger lookup | Semantic catch fraction UNVERIFIED; P5 relevance labels. |
| Exact outcome resolver | False marked predictions with a matching oracle | weak/wrong oracle, changed source, polarity error | command/receipt or human check | Auto-resolve rate UNVERIFIED; P4. |
| Per-band calibration alert | False predictions concentrated in an overconfident cohort, retrospectively | sampling noise, correlated duplicates, drift, selective resolution | batch computation | No claim-level real-time catch; Wilson + holdout controls cohort false alarms. |
| Current prose regex | Unknown | use/mention, negation, unrelated tool/evidence word | Stop hook and possible nudge | Local code proves permissive syntax; live precision is NO DATA because corpus hook detector is broken. |

A detector with a high false-positive rate must not be promoted. Given this workspace's confirmed false-fire history, the deployment acceptance target is deliberately stringent: zero user-facing action in shadow; at least 300 stratified candidate/noncandidate messages; lower 95% confidence bound on precision above 99% for any deterministic card parser; measured semantic false-positive rate below 1%; and no promotion if an alert ever tells the agent to discard a successful tool result. These are design acceptance thresholds, not claims about current performance.

Recall is measured on a separate manually labeled sample, because a parser can achieve perfect precision by capturing nothing. The known-positive control is a syntactically valid card; the known-negative controls include this report, a quoted card, a negated claim, a Markdown table, and the exact successful sentinel payload pattern described in `INPUT-known-harness-defects.md:63-72`.

## 7. Decision rules after data exist

1. Do not rewrite the owner's seven verbal ranges from the same sample used to diagnose them.
2. If a band is over/underconfident in discovery and later holdout, first show the defect by model/task/evidence strata.
3. If mismatch is stable across strata, calibrate a *private decision probability* on a frozen training window and evaluate it on a later window. Preserve the owner-facing word and disclose the empirical mapping in reports.
4. If mismatch is task-specific, do not create a global remap; improve evidence acquisition or use a task-specific mapping only after adequate samples.
5. If a new model snapshot begins, inherit no statistical guarantee. Prior cohorts are context, not calibration evidence for the new model.
6. Never interpret “calibrated” as “true,” “supported,” or “safe.” A 90% band is expected to contain false claims; that is what 90% means.

An automatic abstention or verification threshold is **unlikely (20-45%)** to be justified from the first heterogeneous local cohort. Evidence: the owner's tasks span multiple domains and model versions, Xiong et al. found difficult-task failure prediction poor, and the prior audit found no local calibration set (`D02.md:63-75`). Any such recommendation remains UNVERIFIED until P7 freezes a calibration cohort and demonstrates accepted-case error and coverage on a later exchangeable cohort. KnowNo's finite-sample coverage result used 400 i.i.d. calibration scenarios and assumes future examples come from the same distribution ([Ren et al., CoRL 2023](https://proceedings.mlr.press/v229/ren23a/ren23a.pdf)); this workspace cannot silently assume that condition.

## 8. Anti-overfit gate

All retained proposals ride the existing behavior-contract, dispatcher, Stop/TaskCompleted, typed-receipt, scheduler, and append-only ledger buses. They add no second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

Rejected alternatives:

- **LLM judge every claim:** rejected. It adds a semantic false-positive source and makes one model's unsupported judgment the oracle for another. Audit D02 documents critic hallucinations and narrow transfer (`/local_disk0/codexwork/bundle/inputs/audit-findings/D02.md:47-53`).
- **Regex every hedge in every response:** rejected. It directly repeats the confirmed use-vs-mention and negation failures (`INPUT-known-harness-defects.md:9-48`).
- **Vector/KG memory of claims:** rejected. Exact IDs, JSONL and bounded reports suffice; this is an explicitly rejected component.
- **New calibration daemon/service:** rejected. Resolution can be opportunistic or scheduled on the existing bus.
- **Majority vote as confidence:** rejected. Correlated agents can repeat the same fabricated constraint; the known defects show an orchestrator-authored false constraint propagated to roughly 15 prompts (`INPUT-known-harness-defects.md:151-161`).
- **Midpoint-only Brier score:** rejected. It converts a range into false precision and can rank reports by an arbitrary representative.
- **Declare success when empirical frequency falls in range:** rejected. Sampling uncertainty, duplication, drift and selective resolution can all manufacture that appearance.

## 9. Failure modes the implementation must test

1. **Use vs mention:** this artifact and quoted JSON must produce zero cards.
2. **Negation/polarity:** “unlikely that X fails” must not be silently scored as `P(X succeeds)` without explicit normalization.
3. **Conjunction:** “tests pass and deployment works” must be rejected or split.
4. **Tautology/vagueness:** “the approach will probably be fine” has no oracle and is invalid.
5. **Outcome leakage:** cards created after a test result are rejected.
6. **Duplicate fan-out:** repeated inherited predictions share a cluster and do not increase primary `n`.
7. **Changed target:** a new commit/config after prediction either uses the predeclared semantics or marks the card invalid; it never silently resolves against a different artifact.
8. **Wrong oracle:** a generic successful command cannot resolve a task-specific claim.
9. **Two-signal predicates:** absence/broken/done resolutions lack status until two independent signals and a known-positive control exist.
10. **Censoring:** unresolved and invalid cards remain in coverage reports.
11. **Model drift:** new model/config starts a new cohort.
12. **Band boundary:** exact numeric values at shared endpoints use one documented deterministic canonicalization.
13. **Failed hook:** prediction content remains user-visible even if logging fails; fail-open, with a telemetry error counter.
14. **Secret/path handling:** evidence references use existing sanitizer behavior and never store credential values.
15. **Successful-result sentinel regression:** a field named like an error with value false and `ok:true` remains success.

## 10. Minimal implementation shape

One bounded module can contain:

```text
parse_explicit_cards(last_assistant_message) -> cards
validate_card(card, event, ledger) -> valid | reasons
append_prediction(valid_card)
append_resolution(prediction_id, outcome, oracle_refs)
report(cutoff, model, task, horizon) -> markdown + json
```

Do not put resolution/network work in Stop. Stop only validates and appends explicit cards. Batch reporting and due-resolution checks use an on-demand command or existing native scheduler. The JSONL schema is additive; no rewrite or migration is required for old events. A schema version and resolver version make future changes auditable.

The implementation is **likely (55-80%)** to fit the BUILD-SMALL bound for capture, validation, append, and a basic report if Wilson arithmetic remains stdlib-only. Evidence: existing append and dispatcher plumbing already exist; the unknown is cross-provider payload normalization and the amount of automated resolver integration. If it exceeds roughly 200 lines, split report/resolver into a command on the same bus; do not escalate to BUILD-LARGE.
