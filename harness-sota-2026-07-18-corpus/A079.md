This is **almost certain (90-99%)** to eliminate irrelevant rule loading because the incompatible extensions are explicitly present at lines 7-11 and the proposed scoping removes them. ### C3 — STALE: rollback is mandatory even when the named library says it is conditional

**Artifacts and exact lines**

- `~/.claude/rules/web/patterns.md:55` names TanStack Query.
- `~/.claude/rules/web/patterns.md:80-85` unconditionally requires snapshot, optimistic update, rollback on failure, and visible feedback.
- Current [TanStack Query optimistic-update guidance](https://tanstack.com/query/latest/docs/framework/react/guides/optimistic-updates) documents two variants: UI-only optimistic display, which does not require cache rollback, and direct cache mutation, where refetch often reverts state and an explicit rollback is useful when refetch cannot.

**Collision.** The rule describes one older/direct-cache recipe as universal. It can force unnecessary cache mutation and rollback code even when a simpler pending-variables UI is sufficient. No harness precedence rule resolves disagreement with the rule's named tool's current semantics.

**Specific resolution — NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Rewrite as: prefer UI-only pending state when the optimistic result is local; when mutating shared cache, cancel conflicting refetches, snapshot, update, restore or refetch on failure, invalidate on settle, and show error/retry feedback. Require rollback only when cache is directly changed and refetch is not a sufficient recovery path.

This is **very likely (80-90%)** to reduce needless rollback machinery because the official library documents a simpler no-rollback path; the exact frequency in this owner's projects is **UNVERIFIED — settle it by classifying 30 recent optimistic mutations as UI-only versus shared-cache and replaying failure tests.**

## 8. Consolidated replacement text design

This is a design, not a write to the subject.

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Replace the current one-size-fits-all file with the following shape:

1. **Scope:** component-bearing framework files only; separate React addendum from Vue/Svelte; no CSS/SCSS/HTML or backend-only TS/JS.
2. **State ownership invariant:** remote cache, local interaction, URL/shareable navigation, and form state are distinct; do not mirror authoritative remote data into a client store; derive rather than synchronize computable values.
3. **Selection rule:** use the project's established framework-native library. List tools only as examples under the correct role. Put tRPC under typed API transport.
4. **Composition rule:** choose composition when it clarifies the public API; use subtree context for shared interaction semantics; do not convert prop depth alone into global state.
5. **Data rule:** parallelize independent requests; preserve dependencies; prefetch only with a concrete likelihood/cost rationale; cancel obsolete work where supported.
6. **Optimistic rule:** choose UI-only pending display for local presentation; for shared-cache writes, cancel conflicts, snapshot, reconcile by restore/refetch, invalidate, and expose error/retry state.
7. **Acceptance evidence:** keyboard/focus test for headless widgets, URL round-trip for shareable state, mutation failure test, and a trace/assertion for material waterfalls.

This proposal passes the anti-overfit gate: it rides native rule loading, project test commands, and existing review flow. It introduces no second orchestration runtime, vector/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework.
