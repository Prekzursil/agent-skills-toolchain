## Why no runtime winner or minimal edit is reported

The task requires, for every conflict, both the concrete collision and the side that wins **at runtime**. Static command text alone cannot answer either. In particular:

1. A permission entry is not a server registration.
2. A Codex-plane TOML registration is not necessarily a Claude-plane registration.
3. A conditional “if available” reference does not collide when its fallback is actually taken.
4. A plugin may supply a server/tool absent from user-scope JSON.
5. Claude Code loads MCP state at session startup according to the command’s own claim at `/local_disk0/codexwork/bundle/claude/commands/mcp-gui.md:16`; determining precedence needs the effective live inventory, not an invented merge order.

Accordingly, no “minimal edit” can be responsibly selected. Editing a command may be wrong if a plugin is authoritative; editing MCP JSON may be wrong if the command is obsolete; and either may be unnecessary if the reference is explicitly optional.
