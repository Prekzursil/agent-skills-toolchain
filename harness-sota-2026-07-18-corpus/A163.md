# A163 — Coherence audit: behavior contracts / stale references

## Verdict

I found **three actionable stale references** in the deployed behavior-contract surface:

1. `~/.claude/AGENTS.md` links to a rationale/flag guide that is not deployed beside either copy of the cross-tool contract.
2. `~/.claude/CLAUDE.md` says a user-scoped MCP registration is mounted in `~/.claude/settings.json`; Claude Code actually stores user-scoped MCP servers in `~/.claude.json`.
3. `~/.claude/CLAUDE.md` routes Codex review through `codex-rescue` and `/codex:review`, but the deployed local command/agent inventory provides neither route and the current Codex adapter explicitly prohibits `/codex:*`.

Finding 1 is a documentation dead end. Finding 2 sends troubleshooting to the wrong file. Finding 3 is the operationally important collision: it selects a retired adapter path in exactly the review situation described by the contract.

I also found a **stale cross-provider replica**: `/local_disk0/codexwork/bundle/codex/AGENTS.md` is an 85-line older contract while `/local_disk0/codexwork/bundle/claude/AGENTS.md` is 140 lines. That is real contract drift, but it is not itself a stale *reference* of the requested kind, so I record it under collateral observations rather than inflate the finding count.

Confidence: **almost certain (90-99%)**, based on (a) complete line-by-line reads of all three contract files, (b) mechanical resolution of every Markdown link, (c) complete deployed local agent/command inventories, (d) current adapter text, (e) the distilled corpus's independent capability-use detector, and (f) current official Claude Code documentation. The residual 1-10% is because this Linux snapshot does not include the live Windows `~/.claude.json`, plugin cache, `~/.local`, or source repository, and therefore cannot execute `/memory`, `/skills`, `/agents`, or `claude mcp list` against the owner's live host.

Claude Code does not natively read `AGENTS.md`; it reads it here because `CLAUDE.md:3` imports it. Current official documentation says `@path` imports are expanded at launch, relative to the importing file, and specifically recommends a `CLAUDE.md` containing `@AGENTS.md` for this use case: https://code.claude.com/docs/en/memory . Thus both texts enter the same runtime context.

That documentation also says imported/user/project instruction files are additive and that contradictory instructions may be reconciled by the model rather than deterministically overridden. Therefore `AGENTS.md:115-131` is a **behavioral instruction about precedence**, not a host-enforced precedence mechanism. For the findings below I identify the actual runtime winner by the host's resolver/discovery behavior (file exists, MCP scope storage, command/agent discovery), not by assuming that the prose hierarchy enforces itself.
