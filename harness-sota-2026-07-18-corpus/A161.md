## Runtime precedence: what was and was not verified

No runtime winner is claimed. This is not merely because the Linux node lacks Windows paths: a valid precedence test needs the current files loaded into a fresh Claude session. The prior F09 unit itself did not perform that probe (`F09.md:88-91`). Static contract precedence at `claude/AGENTS.md:115-131` governs instruction layers as prose; it is not mechanically equivalent to MCP configuration merge/exclusivity or tool injection.

For each eventual candidate, a settling runtime experiment must be collision-specific and read-only:

1. Hash and line-number the exact current managed, user, project, and enabled plugin MCP sources without printing secret values.
2. Start a fully closed/fresh Claude session in two controlled working directories: one where the project `.mcp.json` applies and one where it does not.
3. Capture `claude mcp list` and `claude mcp get <candidate>` with names, source scope, transport, and status only.
4. Capture the prompt-time tool catalog for the candidate. “Connected” is not enough to prove injection; `/local_disk0/codexwork/bundle/inputs/audit-findings/B04.md:31-37` records a historical case where connected account connectors and project-disabled state disagreed.
5. Exercise one harmless, deterministic candidate call (for example a names-only memory health/read probe) and record which definition/endpoint handled it.
6. Only then apply the contract's instruction-precedence rule to behavioral text. MCP config source precedence and behavioral instruction precedence must be reported separately.

It is **very likely (80-90%)** that this experiment will distinguish declaration, connection, and prompt-time injection, because each is observed through a different mechanism (file parse, native MCP status, and live tool catalog). Evidence: the historical B04 discrepancy at `/local_disk0/codexwork/bundle/inputs/audit-findings/B04.md:31-37` demonstrates why status alone is insufficient. The residual 10-20% covers undocumented connector/plugin resolution and session caching. **UNVERIFIED:** restarting after clearing no state, then repeating the names-only catalog in a second fresh session, would test caching/reproducibility.
