# B007 — Groundedness: end-to-end provenance chain

## Executive verdict

The harness should make **atomic claims**, rather than reports or digests, the unit of synthesis. Every atomic claim should carry stable edges back through (1) the unit that authored it, (2) the exact normalized tool event that acquired its evidence, and (3) a content-addressed source anchor identifying the file/URL snapshot and exact span. Fan-in should operate on those IDs and the final Markdown renderer should generate citations from validated edges; a synthesizer should never be asked to copy `file:line` strings or URLs out of free prose.

This design does **not** eliminate hallucination. It makes several hallucination and evidence-loss classes detectable: invented pointers, mutated sources, missing unit lineage, citations dropped during digestion, and—less reliably—real sources that do not support the attached claim. It does not prove that a source is true, complete, independent, current, or correctly interpreted. A model can still attach a valid source to an unsupported inference; that requires a separate claim-versus-evidence review and can still be misclassified.

The core can ride the existing provider-neutral dispatcher, append-only ledger, artifact files, and native lifecycle hooks. No second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework is justified.

The most important finding is **almost certain (90-99%)**: provenance must survive as machine-readable IDs rather than citation-shaped prose. Evidence: the pinned fan-out measurement reports 87% of `file:line` references and 100% of URLs dying at the digest boundary, and the prior E14 unit records the same measurement plus 3/3 plausible digests for nonexistent files at `/local_disk0/codexwork/bundle/inputs/audit-findings/E14.md:10-17`. The original Windows `fan-out-contract.md` is not in the unpacked bundle, so this unit can trace that measurement only to the pinned brief and the E14 audit artifact, not to the underlying experiment log; this limitation is recorded again under GAPS.

This unit ran on the Linux job node. The Windows subject paths named in the brief do not exist here. The subject subset available at `/local_disk0/codexwork/bundle` was treated read-only. I wrote only this artifact.

## Grounded diagnosis of the present boundary

### 1. The normalized event envelope cannot yet express a causal evidence chain

This is **almost certain (90-99%)** from two mechanically independent representations. The Python `HookEvent` contains provider, event, session, turn, cwd, tool, message/prompt/source/trigger, and agent, but no stable event ID, parent event ID, work-unit ID, timestamp, or source-material references (`/local_disk0/codexwork/bundle/agents/harness/models.py:10-42`). Independently, the strict JSON Schema enumerates the same fields, sets `additionalProperties: false`, and has no provenance fields (`/local_disk0/codexwork/bundle/agents/harness/schemas/hook-event.schema.json:5-55`). The detector can find known-present `session_id` and `tool.id` in both representations, so the negative check is controlled rather than a blind zero-hit search.

The adapter maps a task summary into `last_assistant_message` and maps task/teammate IDs into the agent envelope (`/local_disk0/codexwork/bundle/agents/harness/adapters.py:91-145`). It does not turn that summary into atomic claims or evidence edges. A prior audit reached the same conclusion from the Windows live tree (`/local_disk0/codexwork/bundle/inputs/audit-findings/C20.md:15-21`), but the bundled code above is the direct evidence used here.

### 2. Terminal telemetry drops even the correlation that the event envelope has

This is **almost certain (90-99%)** from implementation and output shape. `_record_terminal` persists timestamp, terminal status, provider, event, action, reason, latency, and failed module names, but not session, turn, tool call, agent, parent, or work unit (`/local_disk0/codexwork/bundle/agents/harness/dispatcher.py:483-515`). The known-positive control is that `provider` and `event` are present in the emitted record at lines 496-503; correlation fields are absent from the complete literal at lines 496-507. A previous unit independently reported this same terminal-correlation loss (`/local_disk0/codexwork/bundle/inputs/audit-findings/D14.md:37-44`).

### 3. The ledger is already a viable pointer/receipt lane, but not a complete evidence store

This is **almost certain (90-99%)**. The ledger creates monotonic sequence numbers and timestamps, can derive a deterministic event ID from a caller-supplied dedupe key, accepts additive sanitized fields, appends JSONL, flushes, and `fsync`s (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:817-880`). It already documents and stores a `derived_from` provenance edge (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:860-866`). It also has typed receipt classes and claim-to-receipt mappings (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:87-128`) and freshness checks based on receipt sequence versus last mutation (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:1065-1117`).

However, its sanitizer bounds lists and strings (`/local_disk0/codexwork/bundle/agents/harness/ledger.py:80-84`), so full tool results, source excerpts, and reports do not belong inline. The correct use is a small ledger event pointing to a digest-bound artifact bundle, not duplicating the whole bundle in the ledger.

### 4. The hook bus already exposes the necessary lifecycle moments

This is **almost certain (90-99%)** as a static capability statement, not a historical-firing claim. Registration includes `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart`, `SubagentStop`, `TaskCreated`, and `TaskCompleted` (`/local_disk0/codexwork/bundle/agents/harness/registration.py:17-34`), with 2-5 second hook timeouts (`/local_disk0/codexwork/bundle/agents/harness/registration.py:36-52`). The dispatcher normalizes once and runs an ordered list of composable modules (`/local_disk0/codexwork/bundle/agents/harness/dispatcher.py:235-285`). These are direct integration points. The broken corpus detector prevents any conclusion about how often those hooks historically fired.

### 5. Strict structured output is the wrong acquisition boundary for citation-rich fan-out

This is **almost certain (90-99%)** for this corpus. `StructuredOutput` produced 846 errors in 3,694 calls (22.9%), with 294 failures from one required-property mismatch (`/local_disk0/codexwork/bundle/inputs/corpus.json:8964-8984`). Official Claude documentation says native citations and structured outputs are incompatible: enabling citations on a document while setting strict output format returns HTTP 400 ([Claude citations documentation](https://platform.claude.com/docs/en/build-with-claude/citations)). A prior audit therefore recommended loose cited evidence collection followed by a separate strict normalization step (`/local_disk0/codexwork/bundle/inputs/audit-findings/D26.md:23-29`). The design below follows that separation.

## Design principles

1. **Claim first.** Split findings into atomic, independently supportable propositions. Recommendations, observations, inferences, and assumptions are distinct claim types.
2. **Pointers are data, not prose.** A citation displayed to a human is rendered from a validated `anchor_id`; it is not copied from a model-authored string.
3. **Evidence is immutable by identity.** A locator says where content was found; a digest says what bytes were observed. Both are required.
4. **Tool-side minting.** Event IDs, hashes, byte counts, timestamps, and source spans are minted or checked by harness code. The model may select evidence, but may not assert that a tool ran or a digest matched.
5. **Provenance and truth are separate.** A perfect chain proves “unit U derived claim C from observed bytes B through call T.” It does not prove B is accurate or that B entails C.
6. **Abstention is a valid terminal.** `NOT_ENOUGH_EVIDENCE`, `CONFLICTED`, `STALE`, and `UNAVAILABLE` must survive fan-in rather than being filtered away.
7. **Keep raw evidence out of prompt context after acquisition.** Persist the sidecar; inject only bounded excerpts and IDs needed for the current verification.
8. **Provenance of provenance.** Validator identity, version, policy digest, inputs, and verdict are themselves records. W3C PROV explicitly models entities, activities, agents, derivations, and bundles, including bundles as provenance of provenance ([W3C PROV-DM](https://www.w3.org/TR/prov-dm/)).

## Canonical data structure: Provenance Bundle v1

Use one directory per run or work unit:

```text
provenance/<run_id>/
  manifest.json
  events.jsonl
  anchors.jsonl
  claims.jsonl
  validations.jsonl
  synthesis.json
  excerpts/<sha256>.txt       # optional, bounded, policy-controlled
  final.md
```

This is a file-oriented interchange artifact, not a new database. The ledger receives only `run_id`, work-unit status, bundle path, manifest digest, and validation summary.

### A. Run manifest

```json
{
  "schema": "provenance-bundle/v1",
  "run_id": "run_20260719_30bd50d4",
  "objective_sha256": "sha256:...",
  "created_at": "2026-07-19T12:34:56.123456Z",
  "producer": {"harness_version": "git:...", "policy_sha256": "sha256:..."},
  "expected_units": ["B001", "B002", "B007"],
  "units": {
    "B007": {
      "status": "complete",
      "artifact": "/.../B007.md",
      "artifact_sha256": "sha256:...",
      "claims_sha256": "sha256:..."
    }
  },
  "completeness": {
    "all_units_terminal": true,
    "all_claims_have_unit": true,
    "all_evidence_edges_resolve": true,
    "all_materials_captured": false
  }
}
```

`completeness` is an explicit assertion, not inferred from an empty array. This borrows the useful SLSA distinction between provenance existing and materials being complete; SLSA treats provenance as verifiable information about where, when, and how an artifact was produced and requires consumers to actually verify attestations ([SLSA provenance](https://slsa.dev/spec/v1.2/provenance), [SLSA source verification](https://slsa.dev/spec/v1.2/verifying-source)). It does **not** claim SLSA compliance.

### B. Tool event

```json
{
  "v": 1,
  "event_id": "evt_01J...",
  "trace_id": "run_20260719_30bd50d4",
  "parent_event_id": "evt_01J_parent",
  "unit_id": "B007",
  "work_unit_id": "P3-coverage/B007",
  "provider": "codex",
  "session_id_hash": "sha256:...",
  "turn_id": "turn_17",
  "agent_id": "agent_B007",
  "ts": "2026-07-19T12:34:56.123456Z",
  "event": "PostToolUse",
  "tool": {
    "name": "exec_command",
    "call_id": "call_abc",
    "invocation_sha256": "sha256:...",
    "result_sha256": "sha256:...",
    "status": "pass",
    "exit_code": 0,
    "elapsed_ms": 42
  },
  "materials": ["src_01J..."]
}
```

`trace_id` is the run/work-unit causal domain; `parent_event_id` handles a single causal parent; a separate `linked_event_ids` array should be allowed for joins/fan-in. This follows, without importing an observability stack, the OpenTelemetry invariant that a child span shares a trace ID with its parent and can also carry links ([OpenTelemetry Trace API](https://opentelemetry.io/docs/specs/otel/trace/api/)). Store hashes of potentially sensitive session/invocation data and allow an explicit redaction marker; never pretend a redacted field is complete.

### C. Source anchor

```json
{
  "v": 1,
  "anchor_id": "src_01J...",
  "unit_id": "B007",
  "observed_by_event_id": "evt_01J...",
  "kind": "local_file",
  "display_locator": "C:/Users/Prekzursil/.agents/harness/models.py",
  "resolved_locator": "/local_disk0/codexwork/bundle/agents/harness/models.py",
  "snapshot": {
    "sha256": "sha256:...",
    "bytes": 2611,
    "mtime": "2026-07-18T07:59:42Z"
  },
  "span": {
    "line_start": 26,
    "line_end": 39,
    "byte_start": 418,
    "byte_end": 782,
    "excerpt_sha256": "sha256:..."
  },
  "availability": "captured",
  "redaction": "none"
}
```

For URLs, use `kind: web`, put the requested URL in `display_locator`, the final redirect URL in `resolved_locator`, and add retrieval timestamp, HTTP status, MIME type, ETag/Last-Modified when present, response-body digest, and a page/block/character locator. For Git content, record repository URI, revision, path, and blob digest. For command output, record the result digest and a line/byte span in the captured output. A `file:line` alone is insufficient because files move; a digest alone is insufficient because it does not help a human find the cited passage.

Only bounded excerpts needed to reproduce a citation should be copied into `excerpts/`. Full source retention is policy-dependent; secrets and licensed/private documents may permit hashes and locators but forbid copied bytes. In that case set `availability: locator_only` and validation must not claim content re-openability.

### D. Atomic claim

```json
{
  "v": 1,
  "claim_id": "clm_01J...",
  "unit_id": "B007",
  "work_unit_id": "P3-coverage/B007",
  "ordinal": "F4.c2",
  "text": "The normalized event envelope lacks a causal parent identifier.",
  "claim_type": "observed",
  "stance": "assert",
  "confidence_band": "almost certain (90-99%)",
  "confidence_basis": "Python model and strict schema agree.",
  "native_build": "CONFIG (settings/JSON only)",
  "unverified": null,
  "evidence": [
    {"anchor_id": "src_01J...", "relation": "supports", "role": "primary"}
  ],
  "derived_from_claim_ids": [],
  "verification": {
    "pointer": "PASS",
    "integrity": "PASS",
    "entailment": "UNREVIEWED",
    "reviewer": null
  },
  "valid_as_of": "2026-07-19T12:34:56Z"
}
```

Required `claim_type` values: `observed`, `inference`, `proposal`, `assumption`, `measurement`, `quotation`. Required evidence relations: `supports`, `refutes`, `qualifies`, `motivates`, `tests`. `stance` keeps support and refutation from being collapsed by text similarity. `derived_from_claim_ids` preserves intellectual lineage through summaries and synthesis.

An `observed` or `measurement` claim needs at least one grounded anchor. An `inference` needs grounded anchors and/or grounded parent claims plus an explicit reasoning note. A `proposal` needs at least one `motivates` edge; it must not masquerade as an observed fact. An `assumption` may have no supporting evidence, but must carry `UNVERIFIED`, the settling experiment, and downstream dependents. These are schema invariants, not truth guarantees.

### E. Validation receipt

```json
{
  "v": 1,
  "validation_id": "val_01J...",
  "claim_id": "clm_01J...",
  "validator": {"kind": "deterministic", "version": "provcheck/1", "sha256": "sha256:..."},
  "policy_sha256": "sha256:...",
  "checked_at": "2026-07-19T12:40:00Z",
  "checks": {
    "schema": "PASS",
    "unit_lineage": "PASS",
    "event_resolves": "PASS",
    "anchor_resolves": "PASS",
    "snapshot_digest": "PASS",
    "span_matches": "PASS",
    "semantic_support": "NOT_RUN"
  },
  "verdict": "STRUCTURALLY_GROUNDED",
  "input_manifest_sha256": "sha256:..."
}
```

Never overload `PASS` across different burdens of proof. `STRUCTURALLY_GROUNDED` means all referenced objects exist and the anchored bytes match. `SUPPORTED` additionally means a semantic reviewer judged the evidence sufficient. Neither means the source itself is true.

### F. Synthesis map

```json
{
  "synthesis_id": "syn_01J...",
  "output_sha256": "sha256:...",
  "rendered_claims": [
    {
      "render_id": "r17",
      "text": "...",
      "derived_from_claim_ids": ["clm_B007_04", "clm_E014_01"],
      "display_anchor_ids": ["src_models_26_39"],
      "disposition": "included"
    }
  ],
  "omissions": [
    {"claim_id": "clm_X", "reason": "REFUTED"}
  ]
}
```

The final renderer resolves `display_anchor_ids` into clickable `path:line` citations or URLs after validation. If an ID fails, it prints `[BROKEN-PROVENANCE: src_...]` and fails the release gate; it does not silently drop the citation. Every final factual sentence or bullet must map to at least one source claim. Pure transitions and explicitly labeled opinions may be exempt, with the exemption represented as data.

## End-to-end lifecycle

### Stage 0 — Freeze the run contract

At dispatch, mint `run_id` and `work_unit_id`, hash the exact objective/prompt/policy, list expected unit IDs, and write `manifest.json`. Provider and model are lineage attributes, not evidence.

This catches fabricated or swapped briefs only if the received prompt is captured and later compared. It does not tell the child that an orchestrator-authored “fact” is true. Known defect D4 shows the orchestrator can fabricate a constraint and propagate it (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:151-160`), so brief assertions should become `assumption` claims unless linked to evidence IDs.

### Stage 1 — Acquire evidence and mint anchors

On successful reads/searches/fetches/commands, the PostToolUse module records a tool event and source-material metadata. The acquisition helper computes digests and line/byte maps from returned bytes. For local files, capture both the owner-facing Windows path and the actually resolved path/revision. For web content, capture the final URL and response digest.

Native Claude citations may be enabled only during evidence-collection calls. Official docs say they return structured page/character/block pointers and that `cited_text` is not billed as output text, but they are incompatible with strict JSON output ([Claude citations documentation](https://platform.claude.com/docs/en/build-with-claude/citations)). Native pointers reduce fabricated-location risk; they do not establish semantic entailment.

### Stage 2 — Unit authors atomic claims

The unit writes normal exhaustive Markdown plus `claims.jsonl`, or writes annotated Markdown that a deterministic parser converts. Each claim cites anchor IDs, not raw locators. The sidecar is validated before the unit may declare complete. Malformed claims are quarantined and the unit remains `partial`; the system does not `filter(Boolean)` away failed children.

Atomic decomposition has direct research precedent. FActScore evaluates long-form output by decomposing it into atomic facts and checking each against a reliable source ([FActScore paper](https://aclanthology.org/2023.emnlp-main.741/)). The transfer from biography factuality to this owner's mixed coding/research workload is **likely (55-80%)**, because atomicity is domain-general but the paper's labeled evaluation domain is not; a local benchmark described below must settle actual precision and cost.

### Stage 3 — Deterministic structural validation

Before fan-in, run these checks without a model:

1. Parse every JSONL row and reject unknown major schema versions.
2. Assert every expected unit is terminal or explicitly missing/timed out.
3. Assert every claim has exactly one producing unit/work unit.
4. Resolve every evidence edge to an anchor.
5. Resolve every anchor to its acquiring tool event.
6. Resolve every event to the same run/work unit, or to an explicit cross-unit link.
7. Re-open available sources, hash bytes, and validate line/byte span and excerpt digest.
8. Reject timestamps later than validation, impossible line ranges, duplicate IDs with unequal content, path escapes, and digests with unsupported algorithms.
9. Recompute the manifest digest and append a validation receipt.

This stage catches broken/corrupted chains. It cannot decide whether the passage supports the claim.

### Stage 4 — Semantic support review, selectively

Run semantic review only for load-bearing claims: claims driving a recommendation, safety/risk claims, claims with conflicts, claims based on inference, and a sample of low-stakes observations. Give the reviewer only the atomic claim, bounded raw excerpts, source metadata, and explicit reversal question—never the unit's persuasive report. Verdicts are `SUPPORTED`, `REFUTED`, or `NOT_ENOUGH_EVIDENCE`; disagreement routes to human adjudication or remains unresolved.

Automated semantic review is advisory. SAFE similarly decomposes long-form answers into facts, searches, and judges support, but reported only 72% agreement with crowd labels across roughly 16,000 facts and won 76% of a 100-case disagreement adjudication sample, as summarized in the prior audit (`/local_disk0/codexwork/bundle/inputs/audit-findings/B20.md:64-70`) and published in the [SAFE paper](https://proceedings.neurips.cc/paper_files/paper/2024/hash/937ae0e83eb08d2cb8627fe1def8c751-Abstract-Conference.html). That is evidence for usefulness, not correctness authority.

### Stage 5 — Claim-preserving fan-in

Normalize and cluster claims, but never merge records destructively. Exact fingerprints may auto-group identical facts. Similarity may nominate candidate clusters only. A canonical synthesis claim retains all member claim IDs, evidence edges, stances, contradictions, and shared-lineage groups. Raw mention count and independent evidence-group count remain separate; agreement is not converted into a probability.

The existing dispatcher only deduplicates exact cleaned context strings (`/local_disk0/codexwork/bundle/agents/harness/dispatcher.py:255-285`), while a prior integration unit explicitly recommends preserving `member_claim_ids`, evidence, duplicates, derivation, and supersession (`/local_disk0/codexwork/bundle/inputs/audit-findings/C20.md:31-45`). W3C PROV's entities/activities/agents/derivation/bundles supply vocabulary, not a reason to build a graph database ([W3C PROV-DM](https://www.w3.org/TR/prov-dm/)).

### Stage 6 — Render, audit, and gate the final synthesis

The model drafts synthesis using claim IDs. A deterministic renderer attaches display citations from validated anchor records and emits `synthesis.json`. The release check reparses `final.md` into factual claim spans and requires a mapping for each; unmatched factual spans become `UNATTRIBUTED`, not silently accepted. Final artifact hash, synthesis-map hash, manifest hash, and validator receipt are appended to the existing ledger.

The release rule should be:

```text
ALLOW final delivery when:
  all expected units are terminal or explicitly declared missing
  AND all included factual claims have valid unit -> event -> anchor chains
  AND no load-bearing claim is REFUTED, STALE, or CONFLICTED
  AND every required UNVERIFIED premise and settling experiment remains inline
else:
  deliver as PARTIAL with a machine-rendered provenance gap table
```

### Honest ceiling

Hallucination cannot be eliminated. Even a cryptographically intact chain can faithfully preserve a wrong inference. The chain establishes **who/what derived which bytes through which action**, not whether reality agrees with those bytes. Specifically:

- A malicious or mistaken source can be perfectly provenance-bearing.
- A model can cite the correct passage while reversing a qualifier or scope.
- Atomic decomposition can omit a proposition or split it incorrectly.
- A semantic verifier can hallucinate support or refutation.
- Two agents can appear independent while sharing model priors or upstream evidence.
- Redaction and unavailable sources create intentionally incomplete chains.
- Hook failure can prevent acquisition events from being recorded; absence of an event is not proof that no call occurred unless hook completeness is independently demonstrated.

The correct product promise is: **“unsupported and broken chains become observable and reviewable at a measured rate,”** never “hallucination-free.”

## Cost model

### Storage

A representative minified record measured on this job node was 709 bytes for a tool event, 634 bytes for a source anchor, and 655 bytes for a claim; the three plus newlines total 2,001 bytes. Command: a Node `JSON.stringify`/`Buffer.byteLength` measurement over the concrete v1 examples in this report, executed 2026-07-19. This is a sizing sample, not a production distribution.

Let:

```text
E = grounded tool events
S = distinct source snapshots/spans
C = atomic claims
X = retained excerpt bytes

metadata_bytes ≈ 709E + 634S + 655C + manifests/validation overhead
total_bytes ≈ metadata_bytes + X
```

For 100 units × 20 claims, assuming 15 evidence acquisitions and 15 distinct anchors per unit, metadata is approximately `709*1500 + 634*1500 + 655*2000 = 3.32 MB`, before excerpts and validation receipts. This numerical scenario is **likely (55-80%)** to be within a factor of two for similarly shaped research runs because it uses actual serialized examples but unmeasured production cardinalities; the settling experiment is to instrument one full 100-unit shadow run. At a bounded average 1 KiB retained excerpt per anchor, add about 1.5 MB. Full fetched pages/tool outputs would dominate storage and should not be retained by default.

Content-addressed deduplication should key identical source snapshots and excerpts by SHA-256. The expected storage reduction is **UNVERIFIED**; measure distinct digest count versus anchor count on shadow runs rather than asserting a percentage.

### Latency and compute

- Tool-side hashing is linear in bytes already read. For ordinary code/text reads it is **very likely (80-90%)** to remain below the existing 2-second PostToolUse timeout because SHA-256 and line indexing are local and the source bytes are already available; this is **UNVERIFIED** for very large outputs, settled by p50/p95/p99 timing over the corpus-shaped fixture set. Large blobs must be size-capped or hashed asynchronously after recording `PENDING`, without blocking the hook.
- JSONL append is one small local write per event/anchor/claim. The ledger already flushes and `fsync`s per append (`ledger.py:868-875`), so duplicating that pattern for every token or output chunk would be expensive; record only terminal tool events and batch claim rows per unit.
- Deterministic validation is O(records + bytes rehashed). It requires no tokens.
- Semantic validation is the dominant variable cost. If every claim is reviewed, token and latency cost scale with C. Selective review of load-bearing/conflicted/inference claims is **likely (55-80%)** to preserve most safety value at materially lower cost, based on the concentration of decision risk rather than a local benchmark; this premise is **UNVERIFIED**, settled by comparing all-claim versus selective review on the labeled set.
- Native citations add some input-token overhead for prompt/chunking while cited text is not billed as output, according to official docs ([Claude citations documentation](https://platform.claude.com/docs/en/build-with-claude/citations)). No local quality or dollar improvement is known.

### Human cost

Humans review only `CONFLICTED`, `NOT_ENOUGH_EVIDENCE`, structurally valid but high-stakes semantic judgments, and sampled passes used for calibration. The review UI can be plain Markdown: claim, excerpt, locator, unit, tool call, verifier verdict, and one-click disposition. A bespoke UI is not required for v1.

## Anti-overfit gate

All counted proposals ride existing mechanisms:

- lifecycle capture: existing shared hook registration and dispatcher;
- durable small events: existing append-only ledger;
- large/inspectable content: normal artifact files;
- model review: existing skill/agent lane;

No rejected component is reintroduced. If the claim graph is called a “knowledge graph,” that is a category mistake: it is a per-run JSONL interchange bundle with explicit edges, not a query/runtime substrate or durable semantic memory.

## Rejected alternatives and dead ends

### “Require better citations in every prompt”

Rejected as the core mechanism. The pinned fan-out measurement says references die at the digest boundary even when units produced them; prompt compliance cannot preserve data that fan-in discards. Prompts remain useful for claim selection, but the chain must be a validated sidecar.

### “Store every transcript/tool output forever”

Rejected. It has high privacy and storage cost, makes verification search-heavy, and still does not link individual claims to passages. Store small event metadata and bounded evidence excerpts; keep existing transcripts under their existing retention policy.

### “One giant strict JSON response from every research worker”

Rejected. It couples acquisition, citations, variable-cardinality findings, and normalization into the corpus's second-worst reliability surface. Native citations cannot coexist with strict output format in Claude's API. Loose acquisition followed by one strict normalization/validation boundary is more robust.

### “A verifier model guarantees groundedness”

Rejected as false. SAFE's reported human agreement is useful but far from perfect. Model review remains evidence, not authority; it must abstain and expose disagreement.

### “Use only hashes”

Rejected. Hashes detect mutation but are not human-readable locators and do not identify the supporting span. Use locator + snapshot digest + exact span + optional excerpt.

### “Use only file:line and URL strings”

Rejected. Paths move, files mutate, pages change, redirects occur, and models can fabricate plausible strings. Bind display locators to observed bytes and acquiring tool events.

### “Deploy W3C PROV, OpenTelemetry, SLSA, or a graph database wholesale”

Rejected. Their concepts are useful; their full platforms/specification obligations exceed this need. A small local schema borrows entity/activity/agent/derivation/bundle vocabulary, trace linkage, and digest/material completeness while staying on the existing bus.

## Decision summary

Build the minimum enforceable chain:

```text
final rendered claim
  -> synthesis member claim ID(s)
  -> producing unit/work-unit ID
  -> evidence edge(s)
  -> source anchor(s)
  -> acquiring tool event(s)
  -> immutable source snapshot/span digest(s)
  -> validator receipt(s), themselves digest-bound
```

Make structural validation deterministic and semantic support abstaining/advisory. Persist JSONL sidecars and ledger pointers, not a new service. Enable native citations only in the narrow evidence-acquisition lane. Measure reference survival and false blocks in shadow mode before enforcement.

The expected impact is **very likely (80-90%)** to be large for citation survival and fabricated-pointer detectability because those failures become referential-integrity violations rather than prose-quality problems. The impact on truthfulness is only **likely (55-80%)**, because provenance cannot correct false sources or guarantee entailment; that claim is **UNVERIFIED**, and the Phase 3/4 labeled A/B experiments are what would settle it.
