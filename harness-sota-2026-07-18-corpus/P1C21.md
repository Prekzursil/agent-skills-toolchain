# P1C21 — Normalized audit findings: D01–D04

## Scope and method

This unit normalizes the 32 findings in `D01.md`, `D02.md`, `D03.md`, and `D04.md`. It does **not** verify any citation against the subject files or external sources. “Evidence supports claim” therefore means only that, if the cited evidence is accepted as described, it is internally relevant and sufficient for the normalized claim. `SUPPORTED` means the cited material directly supports the material parts of the claim; `PARTIAL` means it supports only part of the claim, leaves a transfer/generalization gap, or uses an absence detector whose controls are incomplete; `UNSUPPORTED` means it does not support the claim as stated.

All proposed effects remain **UNVERIFIED** until the settling experiment named inline in each claim is run. Mechanism tags are normalization metadata, not endorsements: **NATIVE** means Claude Code already provides the mechanism and it only needs enabling; **CONFIG** means settings/JSON/instruction policy only; **BUILD-SMALL** means an estimated <~200-line change on the existing hook/skill/MCP bus; **BUILD-LARGE** means a new service/runtime. The size assignments are **likely (55-80%)**, based only on each finding's described integration surface; inspecting the implementation diff would settle them.

No normalized proposal requires a second orchestration runtime, vector/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework. D03-F05 is the sole adjacent case: it discusses an offline GEPA optimizer, is tagged `BUILD-LARGE`, and explicitly keeps it research-only rather than adding it to the production harness.
