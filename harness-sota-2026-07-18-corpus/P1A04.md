# P1A04 — Corpus axis: StructuredOutput

## Executive ruling — UNVERIFIED current-version effect size

The standing guidance is directionally correct and should replace the current absolute rule that every fan-in must use a closed, multi-field schema.

For broad, open-ended research/audit/red-team lenses whose output is read by a human or concatenated into a later synthesis prompt, use plain text by default. If the native Workflow API needs a parsed object at that boundary, use one required prose field, `{findings_markdown: string}`, with no nested findings schema. Keep strict schemas for small, invariant, machine-consumed control decisions such as `{verdict, blocking}`.

This is not an argument against StructuredOutput. It is an argument for putting schema strictness at the stable control boundary rather than around variable narrative payloads.

Confidence: **very likely (80-90%)**, because (1) the corpus shows 606 identifiable schema-validation failures, 564/606 (93.1%) of which are missing-required-property failures; (2) decisive raw traces show long broad outputs repeatedly being placed into one string/XML-like serialization instead of the requested sibling fields; (3) the same traces show tiny native JSON objects succeeding; and (4) strict validation demonstrably catches and repairs real wrong-type and stray-key errors in compact outputs. The exact failure-rate reduction from `{findings_markdown:string}` is **UNVERIFIED**; settle it with the A/B fixture experiment in §9 on the currently installed Claude Code 2.1.214.

The prompt's “294x schema mismatch” must be corrected: 294 is one fingerprint—missing `kg_triples` and `confidence`—not the total identifiable schema-mismatch count. The corpus contains 606 schema-mismatch events across 31 fingerprints. It also exposes 66 malformed-JSON StructuredOutput events across nine fingerprints. Those 672 classified events account for 79.4% of StructuredOutput's 846 errors; the corpus cannot assign the remaining 174 errors to a shape from the data it retains.

## 4. Root-cause model

### Root cause A — schema/task mismatch at broad narrative fan-out

Broad research output has variable cardinality, field relevance, citation form, and section depth. The schemas impose fixed required arrays and sometimes closed nested objects before any consumer has normalized the content. The model often responds by generating a prose/XML representation of the desired object rather than native tool arguments. Missing-required errors are then a symptom of transport collapse, not missing research.

Evidence: GABBR1 and anticipatory-lens raw sequences; 564 missing-required events; current `agentic-repair-reliability.js:20-30,38-41`, which requires a closed lens plus closed three-field findings for six open-ended lenses.

### Root cause B — defaultable narrative fields are marked required

`mustFix=[]`, optional research arrays, and absent-per-page categories are safe to default in code, but are required in the schema. The downstream programs already use `|| []`, optional chaining, or `.filter(Boolean)`, proving that the data plane treats some “required” fields as optional while the validator does not.

Evidence: `phenibut-program-build-wf_27298efb-dc9.js:148-150`; the R5 manifest's `review && review.mustFix`; licensing descriptions that prescribe the sentinel string `"none"` for absent categories at `schrodinger-license-docs-read-wf_94d14c9a-5b3.js:36-44`.

### Root cause C — invalid JSON/tool argument serialization is a distinct failure class

At least 66 corpus events are explicitly malformed JSON, and the licensing outlier has 68 raw failed calls across several fingerprints. Loosening nested schema shapes reduces the incentive and surface for complex serialization, but it does not make invalid JSON valid. Plain text avoids this tool boundary; one-string StructuredOutput does not.

### Root cause D — silent degradation at fan-in multiplies the cost

`.filter(Boolean)` lets a broad Workflow complete after dropping failed lenses. This turns a visible schema error into invisible coverage loss. A 17-page reader returned only 16 per-page previews, while the parent still completed. The problem is not only retry cost; it is false completeness.

### Not supported — “the validator is randomly rejecting valid JSON”

The decisive dominant trace does not show valid native JSON being rejected. It shows one string containing XML-like pseudo-fields being rejected, followed by a tiny native object succeeding. The additional-property and wrong-type traces also show correct validator behavior. A historical runtime bug did exist: the local changelog says 2.1.89 fixed a StructuredOutput schema-cache bug causing about 50% failure when multiple schemas were used (`C:\Users\Prekzursil\.claude\cache\changelog.md:2426-2438`). But the main cited failures ran on later versions (2.1.170-2.1.195), so that earlier cache bug cannot explain them all.

Claude Code 2.1.187 also fixed indefinite re-calls after successful StructuredOutput and follow-up structured-return behavior (`changelog.md:561-572`). The 2.1.183 GABBR1 trace predates that fix; the 2.1.195 `mustFix` and `findings` traces postdate it and still fail to native-call the required sibling fields. Therefore retry-loop length is version-sensitive, but broad schema-shape failure persisted after the retry fix.

## 5. Ruling on the standing guidance — UNVERIFIED current-version A/B

### Adopt with one refinement

The `gem-hunt` skill says broad/deep lenses should use “a single `findings_markdown` string field, or plain-text agents” because shape-varying output burns the retry cap (`C:\Users\Prekzursil\.claude\skills\gem-hunt\SKILL.md:90-96`). The generic `workflow-authoring` skill contradicts it by saying to always pass a schema and require a closed schema on every fan-in (`C:\Users\Prekzursil\.claude\skills\workflow-authoring\SKILL.md:55-56,129-139,283-287`).

Rule:

1. **Broad narrative lens, no direct machine branch:** plain text.
2. **Broad narrative lens, Workflow must return a parsed object:** `{findings_markdown:string}` only.
3. **Mixed control + narrative:** a tiny strict control envelope, e.g. `{verdict: enum, blocking: boolean, findings_markdown?: string}`. Only the fields actually used to branch are required.
4. **Stable normalized record:** strict schema is appropriate after a separate normalization step, especially for finite enums, identifiers, booleans, and compact arrays with invariant item shapes.
5. **Citation-bearing research:** retain Markdown/plain text. Do not trade evidence quality for early JSON normalization.

The refinement is that plain text should precede the one-field schema in the preference order. The raw licensing case proves that a single long JSON string can still fail JSON parsing, whereas plain text bypasses StructuredOutput entirely.

Confidence: **very likely (80-90%)** that this rule reduces failures and preserves more research content, based on the failure distribution and raw shape transitions. The exact comparative rate on current 2.1.214 is **UNVERIFIED**; the settling experiment is §9.

## 8. Alternatives considered and rejected

### Keep strict schemas everywhere and improve prompts

Rejected. The raw models repeatedly stated they were fixing the payload while continuing to place fields inside one string. More prose instructions do not change the boundary's mismatch between variable narrative content and fixed nested data. It also preserves silent `.filter(Boolean)` loss.

### Remove StructuredOutput everywhere

Rejected. The wrong-type and additional-property positive controls show useful, fast repairs. Machine gates need typed finite decisions; parsing a verdict from prose would move errors downstream and make them harder to detect.

### Make all fields optional but keep the large closed object

Rejected as incomplete. It would reduce missing-required errors but still invites pseudo-serialization, malformed JSON, additional-property failures, and silent partial objects. Optionality is appropriate only after shrinking the boundary to machine-relevant fields.

### Add a schema-repair model/service

Rejected by the anti-overfit gate. It adds latency and a new failure surface to repair a contract that should not exist at broad narrative fan-out. Native retry plus late compact normalization is sufficient.

### Blame payload size alone

Rejected as unproven. The GABBR1 agent itself inferred a size cutoff, but the decisive evidence is representation: failed calls contain XML-like fields inside one string, while the accepted calls are native JSON objects. Size may influence model serialization behavior, but no byte-threshold experiment was run. Any size-threshold claim is **UNVERIFIED**; a byte-sweep fixture would settle it.
