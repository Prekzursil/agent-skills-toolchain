## 2. Runtime rule verified independently

Current official Claude Code documentation states that subagents inherit main-session internal and MCP tools by default, but a `tools` frontmatter field acts as an allowlist; its example explicitly says an agent restricted to built-ins cannot use MCP tools. It also documents MCP server-level patterns (`mcp__<server>` or `mcp__<server>__*`) and a separate `mcpServers` field for referencing configured servers or defining an inline server. Source: [Claude Code subagents documentation](https://code.claude.com/docs/en/sub-agents), sections “Choose tools” and “Scope MCP servers to a subagent” (retrieved 2026-07-19).

This is mechanically independent of the local text: it establishes which text wins at runtime. The local frontmatter allowlist wins over prose instructions inside the agent body. MCP availability in the parent is necessary but not sufficient when the agent declares a restrictive `tools:` field.

Official documentation further says managed settings restrictions apply to every subagent and, as of v2.1.153, enterprise managed-MCP restrictions cover subagent-declared servers. Thus a minimal agent edit cannot bypass an enterprise denial. Source: the same official page, “Scope MCP servers to a subagent.”
