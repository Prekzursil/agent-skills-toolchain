# B010 — Groundedness Engineering: Evidence-Chain

**Unit:** B010  
**Date:** 2026-07-19  
**Scope:** Multi-hop provenance for claims produced by agents; trace conclusions to primary evidence; detect circular citation between sibling agents.  
**Operating constraint:** read-only inspection of `/local_disk0/codexwork/bundle`; this report is the only write.  
**Non-negotiable framing:** hallucination cannot be eliminated. The attainable objective is to make unsupported claims detectable and cheap to catch, while keeping false-positive harm low.

## Executive verdict

Build a **thin claim-evidence DAG on the existing shared event-ledger and hook bus**, not another orchestration runtime, memory system, graph database, or guardrail framework. A final conclusion should carry a stable claim ID and one or more explicit support bundles. Each bundle is an AND-set of evidence or antecedent claims; the bundles are alternatives (OR). Primary evidence is an immutable, resolvable source span or executable receipt. A sibling's prose is another claim, never primary evidence.

The core acceptance algorithm is a monotone least fixed point:

1. resolve and hash-check primary evidence;
2. seed only resolved primary evidence nodes;
3. promote a claim when every member of at least one support bundle is already grounded and the claim-to-evidence relation has the required support verdict;
4. iterate until no status changes;
5. anything left is `UNSUPPORTED`, `CIRCULAR_ONLY`, `MISSING`, `MUTATED`, `CONTRADICTED`, or `UNCHECKED`, never silently `VERIFIED`.

This makes a pure `Agent A -> Agent B -> Agent A` citation loop unable to bootstrap itself. It also avoids a damaging false positive: if A and B cite one another but A additionally has a valid independent primary-evidence bundle, the circular edges are reported but the independently grounded claim is not rejected.

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** The append-only ledger already accepts additive fields and `derived_from` lists (`agents/harness/ledger.py:851-880`), and its taint reader already scans those edges (`agents/harness/ledger.py:1186-1215`). The missing work is a compact claim record, a resolver, and a graph validator. It is **likely (55-80%)** that the production implementation can remain below roughly 200 non-test lines because the storage, provider adapters, session IDs, sequencing, hashing utilities, and dispatcher already exist; evidence is the small integration surface just cited. This size estimate is **UNVERIFIED**; settle it with a spike that implements the schema, three resolvers, fixed-point evaluation, and one hook adapter while counting non-test source lines.

The proposed engine does not determine truth. It deterministically checks pointer integrity, provenance reachability, graph circularity, freshness, and receipt identity. It can only probabilistically assess whether prose evidence semantically entails a claim. A citation may support a false statement because the source itself is false; a source can be authoritative but stale; a correct conclusion can be uncited. The UI and ledger must therefore say `grounded in <evidence>`, not `true`.

### 1.3 Operational constraints learned from known defects

The proposed detector must not scan arbitrary prose for magic words. Four detector families have already confused use with mention, including a tool sentinel that told the agent to discard a successful result because a JSON field name contained `timedout` while its value was false (`inputs/INPUT-known-harness-defects.md:9-82`). That incident changes the safety priority: **false blocking is a correctness failure, not merely annoyance**.

Absence claims must carry a known-positive control. Seven wrong conclusions arose from unvalidated probes, and a later capability detector's known-positive controls isolated the actual broken half (`inputs/INPUT-known-harness-defects.md:111-129`). The evidence-chain resolver therefore reports detector health alongside verdicts: `control_resolved`, `targets_attempted`, `resolver_errors`, and `coverage`. No `MISSING` or `CIRCULAR_ONLY` result is eligible to block if the resolver's known-positive fixture did not resolve in the same run.

Orchestrator-authored “ground truth” is itself a claim. A fabricated Write-tool constraint propagated into about 15 agent prompts and moved writes to a substantially less reliable shell route (`inputs/INPUT-known-harness-defects.md:151-161`). Consequently, prompt facts get `source_kind: orchestrator_claim`, not `primary`, and require the same resolvable evidence as leaf-agent claims.

## 2. Frontier grounding

The design borrows semantics, not infrastructure, from established provenance standards:

* W3C PROV distinguishes Entity, Activity, and Agent and provides `wasDerivedFrom`, `used`, `wasGeneratedBy`, responsibility, quotation, revision, and primary-source relationships. It explicitly supports provenance chains and named bundles ([W3C PROV-O](https://www.w3.org/TR/prov-o/)). This supports keeping the claim, the evidence snapshot, and the producing agent/activity distinct.
* W3C PROV validation builds an event-order graph and declares an instance invalid when a cycle contains a “strictly precedes” edge ([W3C PROV-CONSTRAINTS, §6.1](https://www.w3.org/2012/10/prov-constraints)). This supports explicit cycle analysis, but not the stronger assertion that every provenance cycle is semantically invalid. The design below therefore reports all sibling SCCs but rejects only support that is circular-only or violates production order.
* SLSA defines provenance as verifiable information describing where, when, and how an artifact was produced; its verification guidance emphasizes that provenance has value only when checked against expectations ([SLSA provenance](https://slsa.dev/spec/v1.2/provenance), [verifying artifacts](https://slsa.dev/spec/v1.2/verifying-artifacts)). SLSA also deliberately does not make build levels transitive, to keep adoption tractable ([SLSA FAQ](https://slsa.dev/spec/v1.2/faq)). The transferable lesson is to record each hop and verify policy at the consumer, not to pretend that a trusted parent automatically makes every transitive dependency trusted.
* SAFE decomposes long responses into self-contained facts, searches for each, and labels support. On its study it agreed with 72% of human annotations, won 76% of a random 100-case disagreement sample, and was reported as over 20× cheaper than human annotation ([Long-form factuality, NeurIPS 2024, p.1](https://proceedings.neurips.cc/paper_files/paper/2024/file/937ae0e83eb08d2cb8627fe1def8c751-Paper-Conference.pdf)). This is evidence that claim decomposition can make checking economical; it is also evidence that an automated semantic judge is not infallible.
* ALCE separates fluency, correctness, and citation quality; even its best ELI5 systems lacked complete citation support 50% of the time ([ALCE, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/)). This supports separate completeness and correctness statuses rather than one green badge.
* Anthropic's research-agent guidance separately evaluates groundedness, coverage, and source quality and says LLM rubrics should be repeatedly calibrated to expert judgment ([Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). That matches this design's three axes and shadow-first semantic judge.
* Claude's native citations provide document/page/character/block pointers and structured citation blocks, but citations and structured outputs cannot be used in the same request ([Claude citations documentation](https://platform.claude.com/docs/en/build-with-claude/citations)). Therefore native citations belong on evidence-collection calls; strict normalization, if needed, occurs in a separate local step.

These sources do **not** justify a claim that the proposed engine catches a known percentage of hallucinations in this owner's workloads. No matched local claim-level gold set exists in the pinned inputs. Any numeric recall or false-positive target below is an experiment gate, not a forecasted result.

## 3. The evidence-chain data model

### 3.1 Keep three relations separate

1. **`influenced_by` / existing `derived_from`:** provenance and taint. It says the producer consumed another item. It does not say the item proves the claim.
2. **`support_sets`:** an explicit argument relation. Each inner list is conjunctive; outer lists are alternatives. Example: `[[source_A, source_B], [receipt_C]]` means A and B together support the claim, or C independently supports it.
3. **`contradicted_by`:** explicit contrary evidence. Contradiction is not modeled by absence of support.

Overloading `derived_from` as “supports” would launder mere influence into evidence. W3C PROV's derivation relation is provenance, not textual entailment; the local ledger's current use is taint propagation (`agents/harness/ledger.py:1186-1215`).

### 3.2 Minimal records

```json
{
  "schema_version": 1,
  "kind": "claim",
  "claim_id": "clm:sha256:...",
  "run_id": "...",
  "producer": {"provider":"codex","agent_id":"B010","artifact":"...","artifact_sha256":"..."},
  "ordinal": 17,
  "text": "The normalized hook schema has no claim projection.",
  "claim_kind": "observation|inference|recommendation|forecast|owner_intent",
  "load_bearing": true,
  "support_sets": [["ev:sha256:...", "clm:sha256:..."]],
  "influenced_by": ["clm:sha256:..."],
  "contradicted_by": [],
  "confidence_band": "almost certain",
  "unverified_experiment": null
}
```

```json
{
  "schema_version": 1,
  "kind": "evidence",
  "evidence_id": "ev:sha256:...",
  "source_kind": "local_span|tool_receipt|web_snapshot|native_citation|owner_statement|sibling_claim",
  "locator": "/abs/path/file.py:851",
  "retrieved_at": "2026-07-19T...Z",
  "content_sha256": "...",
  "span": {"start_line":851,"end_line":866,"span_sha256":"..."},
  "authority": "primary|secondary|owner_authority|unknown",
  "resolver": "local-v1",
  "resolver_control": "ev:known-present:..."
}
```

IDs are content-derived. A claim ID hashes schema version, run, producer artifact hash, ordinal, and exact claim text. An evidence ID hashes source kind, canonical locator, snapshot digest, and span. This makes mutation visible rather than silently re-pointing an old citation to new bytes. The full text remains in the record for auditability; normalization is not used to merge distinct numeric/path claims.

`owner_statement` is primary authority for the owner's intent, preference, authorization, or report of their own experience. It is not primary evidence for an external technical fact. `sibling_claim` is always a claim reference, never an evidence seed. An audit finding is likewise a secondary claim until its concrete source pointer is independently resolved.

### 3.3 Evidence grades are orthogonal

Every claim reports four separate states:

| Axis | Values | Meaning |
|---|---|---|
| Pointer integrity | `RESOLVED`, `MISSING`, `MUTATED`, `MALFORMED` | Can the cited bytes/receipt be retrieved and hash-checked? |
| Support relation | `EXACT`, `EXECUTABLE`, `ENTAILED`, `PARTIAL`, `CONTRADICTS`, `UNCHECKED` | Does the evidence actually warrant this claim? |
| Source role | `PRIMARY`, `SECONDARY`, `OWNER_AUTHORITY`, `SIBLING`, `UNKNOWN` | How close is the source to the fact? |
| Chain result | `GROUNDED`, `UNSUPPORTED`, `CIRCULAR_ONLY`, `DISPUTED`, `STALE`, `UNCHECKED` | Does an acceptable independent support bundle reach primary evidence? |

No axis upgrades another. A resolvable URL is not necessarily supportive. An entailing secondary source is not primary. A primary source can contradict the claim. A grounded claim is not guaranteed true.

### 3.4 Primary evidence resolvers

* **Local source span:** canonical absolute path plus file SHA-256, line or byte range, and span hash. If inside Git, also record repo root and commit/worktree state; a dirty file is allowed but must be pinned by bytes.
* **Executable receipt:** provider, session/turn, tool-call ID, canonicalized argv/tool input hash, result hash, exit/status, start/end time, cwd, relevant artifact hash, and mutation floor. Reuse typed receipt classes and freshness in `ledger.py:1093-1163`.
* **Web/document evidence:** canonical URL or document ID, retrieval timestamp, response/content hash, and exact character/page/block span. A URL without captured bytes is `RESOLVED_LIVE` at best and cannot prove what an earlier agent saw.
* **Native Claude citation:** preserve the returned structured pointer and map its document/block index to the input document's hash. Native citations prevent a pointer to a document that was not provided, but semantic support still needs evaluation.
* **User/owner statement:** immutable transcript event ID/hash and bounded text span; scope authority to intent or firsthand statement.

Secret-bearing evidence should store a salted/redacted span plus a privileged resolver reference, not raw secrets in the ledger. The existing ledger sanitizes additive fields (`ledger.py:860-866`), so the resolver must preserve that boundary.

## 4. Circular sibling-citation detection

### 4.1 Deterministic graph pass

Construct directed edges from each claim to every member of every support bundle. Run Tarjan's strongly connected components algorithm (or ordinary DFS coloring) over claim-to-claim edges:

* a self-loop or SCC of size greater than one is `cycle_present=true`;
* record the exact cycle path and producer IDs;
* do not count any claim inside that SCC as a primary seed;
* evaluate groundedness by least fixed point from resolvable primary evidence outside the SCC;
* if no acceptable support bundle for a claim becomes grounded, and all candidate bundles depend on its own SCC, classify `CIRCULAR_ONLY`;
* if another independent bundle grounds it, classify `GROUNDED_WITH_CYCLE_WARNING` and retain the cycle as provenance debt, not a block.

This is more precise than “reject every cycle.” W3C's validity rule rejects cycles containing a strict temporal-precedence edge, not every cyclic relation. Sibling agents can legitimately quote each other's independently evidenced observations during synthesis. What is invalid as evidence is self-support with no grounded exit.

### 4.2 Temporal and independence checks

Each edge records the cited node's creation sequence and artifact digest. An agent cannot claim it read a sibling artifact created later; such an edge is `IMPOSSIBLE_ORDER`. Two agents that cite the same orchestrator premise are one evidence lineage, not two corroborating signals. Independence is therefore computed from **terminal evidence roots**, not agent count:

```text
independent_roots(claim) = unique(primary evidence IDs reachable through valid support bundles)
```

Two siblings with the same root yield `root_count=1`. Two mechanically different primary roots—such as a schema read and a runtime event—yield `root_count=2`. This directly encodes the local rule that re-running the same broken probe is not independent (`claude/rules/common/fan-out-contract.md:25-31`).

### 4.3 Hyperedges prevent “one citation clears a compound conclusion”

A conclusion like “the hook is wired and effective” contains at least two atomic claims. Claim decomposition should make them separate. If a genuinely conjunctive inference remains, its support bundle lists every prerequisite. The fixed-point promotion requires all members of one bundle. This corrects the current ANY-of union risk described in `inputs/audit-findings/C11.md:10-26` without assuming that merely adding more citations improves truth.

## 5. Proposals

### Proposal 1 — CONFIG: require a loose claim sidecar at fan-in

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Add a fan-out contract field requiring each grounded unit to emit an adjacent `claims.ndjson` or a fenced `EVIDENCE-CHAIN` section after its human-readable artifact. Each row is one atomic load-bearing claim with stable pointers. Do not require nested `StructuredOutput` from every leaf: the corpus measured 22.9% errors for that tool, and Claude native citations are incompatible with structured outputs. Validate/normalize once at fan-in.

The sidecar should be mandatory only for load-bearing factual claims and recommendations; ordinary conversational text is not exhaustively atomized. This avoids turning every adjective into a finding. Leaves commit their artifact and sidecar before seeing sibling conclusions; reducers can then add explicit inference claims without rewriting leaf provenance.

It is **very likely (80-90%)** that explicit claim rows catch more missing citations than parsing arbitrary final prose because rows make omission syntactically visible and ALCE/SAFE both operate claim-wise; evidence is the cited studies plus the measured failure of regex guards on prose. The magnitude is **UNVERIFIED**; settle it by annotating 200 load-bearing claims from completed audit artifacts and comparing manual coverage against (a) regex extraction, (b) LLM extraction, and (c) author-emitted rows.

### Proposal 2 — BUILD-SMALL: ledger-backed evidence resolver and fixed-point validator

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Extend ledger events with `claim_id`, `support_sets`, `evidence_id`, `producer_artifact_sha`, and resolution status. Add three pure resolvers first: local span, ledger receipt, and web/native document span. Add the SCC/fixed-point pass. Emit one bounded summary at `TaskCompleted`/`Stop`; write full details to the existing artifact/ledger, not into repeated nag text.

Deterministic failures (`MISSING`, `MUTATED`, impossible order, circular-only) may eventually gate high-stakes promotion, but only after the detector's known-positive control passes. Semantic `PARTIAL`/`ENTAILED` labels remain advisory until calibrated. Existing `derived_from` remains the taint/influence edge; do not silently change its semantics.

It is **almost certain (90-99%)** that SCC detection catches explicit sibling citation cycles represented in complete sidecars, because cycle detection on a finite directed graph is deterministic; evidence is the explicit edge model and standard graph algorithm. It is only **likely (55-80%)** to catch circular support expressed in prose or omitted from sidecars, because it cannot inspect an edge that was never recorded. The completeness premise is **UNVERIFIED**; settle it with seeded fixtures containing explicit, paraphrased, omitted, and indirect A→B→C→A loops.

### Proposal 3 — NATIVE: use Claude citations only in evidence-collection lanes

**NATIVE-vs-BUILD: NATIVE (Claude Code already does this; we just enable it).**

For document/PDF/search-result collection calls, enable native citations and map page/character/block pointers to evidence IDs. Feed the cited prose to a separate normalization/verification step. Do not combine citations with structured output in one API call; official documentation says that combination returns HTTP 400.

Native citation pointers are **very likely (80-90%)** to reduce fabricated or malformed document pointers in those lanes because the API restricts citations to provided documents and returns structured locations; evidence is Anthropic's citation contract. Improvement in semantic support is **UNVERIFIED**; settle it with a blinded A/B on owner-domain documents, manually labeling pointer validity, citation completeness, and entailment per claim.

### Proposal 4 — BUILD-SMALL: semantic support judge in shadow, never a truth oracle

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

After deterministic resolution, send only `(atomic claim, exact cited spans, required qualifiers)` to an isolated support judge. It returns `ENTAILED | PARTIAL | CONTRADICTS | UNCLEAR` and a decisive span. It must not see sibling votes or the fluent full report. Start in shadow; never let `ENTAILED` grant done. A `CONTRADICTS` or `PARTIAL` flag becomes blocking only if independently reproduced by an executable check or human review under a calibrated policy.

SAFE's 72% agreement with human annotations and 76% win rate on its 100 sampled disagreements show useful but imperfect performance. Anthropic explicitly recommends frequent calibration of LLM research rubrics. Therefore it is **likely (55-80%)** that a narrow claim/span judge catches a useful fraction of citation laundering at tolerable review cost, but this is **UNVERIFIED** for this owner's technical/reverse-engineering corpus; settle it with a stratified, provenance-blinded human set and report precision, recall, false BLOCK rate, abstention, tokens, and latency.

### Proposal 5 — CONFIG: risk-tiered enforcement and compact user surface

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

## 6. Evaluation: fraction caught, cost per claim, false-positive rate

No proposal should ship on “looks reasonable.” Build a gold set with at least these strata:

1. direct supported claim;
2. correct but uncited claim;
3. cited span irrelevant to claim;
4. citation supports only part of an over-broad claim;
5. source contradicts claim;
6. source supports claim but is secondary/stale;
7. A→B→A and A→B→C→A circular-only chains;
8. cycle plus independent primary support;
9. shared-root pseudo-corroboration;
10. two mechanically independent roots;
11. mutated local file after citation;
12. impossible future-sibling citation;
13. compound claim with only one conjunct supported;
14. code/prose mention controls from the known defects;
15. a resolver outage with a known-positive control.

Measure at claim level:

```text
unsupported_recall = caught_unsupported / all_gold_unsupported
false_positive_rate = supported_claims_flagged / all_gold_supported
false_block_rate = supported_claims_blocked / all_gold_supported
cycle_recall = caught_circular_only / all_gold_circular_only
cycle_precision = caught_circular_only / all_predicted_circular_only
cost_per_claim = (model tokens * price + compute + review seconds * labor rate) / claims_checked
cost_per_true_catch = total_cost / true_unsupported_caught
coverage = load_bearing_claims_with_sidecar_rows / gold_load_bearing_claims
resolver_health = known_positive_controls_resolved / controls_attempted
```

Report pointer and semantic stages separately. A high overall precision can hide a semantic judge that generates most false blocks. Also report by domain and claim kind: executable coding claims, local static facts, web facts, scientific synthesis, reverse-engineering inference, and forecasts.

### UNVERIFIED acceptance thresholds — calibrate, do not assume

The thresholds below are policy proposals, not measured capabilities:

* deterministic pointer/cycle layer: `false_block_rate = 0` on all known supported controls, `cycle_recall = 100%` on explicit seeded cycles, resolver health `=100%` in the same run;
* semantic shadow layer: precision at least 95% before any interruptive warning, with Wilson lower bound reported; no blocking on semantic judgment alone;
* author-side coverage: at least 90% of manually labeled load-bearing claims represented before treating missing rows as a completeness signal;
* cost: p50 deterministic validation below 10 ms/claim locally and semantic checking selectively routed so cost per true catch beats sampled human review.

These thresholds are **UNVERIFIED** and would be settled by a 200-claim stratified pilot plus the seeded fixture suite above. It is **roughly even (45-55%)** whether 95% semantic precision is achievable across this owner's mixed domains without domain-specific routing; evidence for uncertainty is SAFE's imperfect human agreement and the absence of a local gold set. Failure to meet the threshold means remain shadow-only, not tune the labels until the benchmark passes.

## 7. Rollout and falsification plan

1. **Offline fixtures:** implement no hooks yet. Validate IDs, hash mutation, AND/OR bundles, SCCs, fixed-point grounding, future-edge detection, and known-positive resolver controls.
2. **Historical shadow replay:** parse a stratified set of existing audit artifacts. Because author sidecars do not exist historically, measure extraction coverage separately and do not confuse parser misses with unsupported claims.
3. **Prospective author sidecars:** enable on grounded audit/research lanes only. Collect artifacts without warnings.
4. **Human labeling:** blind reviewers to producer/provider and adjudicate disagreements. Capture whether each flag would have changed an owner-facing conclusion.
5. **Advise:** show one compact summary only when deterministic resolver controls pass. Semantic results remain expandable shadow metadata.
6. **Enforce narrowly:** permit deterministic blocking only for promotion of load-bearing high-stakes claims with missing/mutated/circular-only support. Never block ordinary task completion solely because an LLM support judge disagrees.
7. **Regression monitoring:** replay the known false fires and track false-block rate by release. Auto-demote to shadow on any confirmed supported-claim block.

## 8. Alternatives considered

### Reject: a second provenance database or knowledge graph

A graph database is unnecessary for bounded run artifacts. The ledger already stores additive events and bounded scans; the required graph fits in memory per run. A vector DB/KG memory is explicitly a previously rejected component. Adding one would create another synchronization and provenance problem. This proposal passes the anti-overfit gate by riding the existing ledger and artifact bus.

### Reject: “every sentence must have a citation”

This produces noisy atomicity, penalizes connective prose, and invites citation count gaming. Scope to load-bearing factual claims, recommendations, and forecasts. ALCE separates citation quality from answer correctness; more citations are not inherently better.

### Reject: URL/file:line syntax alone

A pointer can resolve yet not support the proposition, and mutable locations can change. Store exact snapshot/span hashes and a support verdict. URLs without captured bytes are insufficient for historical chain-of-custody.

### Reject: block on an LLM entailment judge

SAFE is useful but not perfect; local regex guards have already corrupted successful evidence. Semantic review must be calibrated and advisory. Executable receipts or human adjudication carry blocking force.

### Reject: reject every SCC

That would falsely reject a claim that has an independent grounded path plus a harmless mutual reference. Report the cycle; reject only circular-only support or impossible temporal order.

### Reject: trust agent consensus as independent corroboration

Agents can inherit the same false orchestrator premise. Count unique terminal evidence roots and mechanically different probes, not votes. The local fan-out evidence explicitly shows two agents “confirmed” a false fact by re-running the same broken detector (`fan-out-contract.md:25-31,74-83`).

### Reject: cryptographic signing in the MVP

Content hashes provide mutation detection but not signer authenticity. Adding key management before the basic claim graph has measured value would expand scope and operational burden. If threat modeling later includes malicious ledger writers, in-toto/SLSA-style signed attestations become a separate, justified phase. It is **unlikely (20-45%)** that signing is the highest-value first move because the measured incidents are unsupported propagation and false detectors, not demonstrated ledger forgery; evidence is the known-defects file. This prioritization is **UNVERIFIED**; a focused threat model and tamper incident review would settle it.
