## Executive verdict

The rules subsystem is **structurally organized but operationally unhealthy**. The current tree has 85 files: 83 `.md` files that Claude Code can discover (82 actual rules plus an intentionally nonmatching README) and two inert backup files. The active markdown totals 5,841 lines and 166,781 bytes; including backups, the directory totals 5,952 lines and 173,822 bytes. Seventy-seven of the 82 actual rules are path-scoped and five are always loaded. This census is exact from a recursive `Get-ChildItem` plus line/byte count over the live directory.

The primary failure is not that the files fail to exist. It is that rule *authority, applicability, and runtime truth are mixed together*:

1. `common/hooks.md` is breaking at its point of use: it names only 3 of 18 configured hook events and recommends `TodoWrite`, which the corpus records once with one error, while `TaskCreate` and `TaskUpdate` have 2,181 and 3,710 calls. `web/hooks.md` is also breaking at its point of use because all five JSON examples omit the required nested `hooks` handler array and `type: "command"` field (`web/hooks.md:25-36,43-54,59-70,95-106,113-123`). Current Claude documentation and the live configuration independently show the three-level schema (`C:\Users\Prekzursil\.claude\settings.json:322-342`; https://code.claude.com/docs/en/hooks#configuration).
2. Common code policy is mis-scoped. Eight common code/workflow files contain `**/*.sh` but zero contain `**/*.ps1`, although PowerShell is the primary shell and the toolchain has high-impact `.ps1` scripts. The common globs also omit Dart and Perl entirely and omit secondary source/config extensions such as `.hpp`, `.pyi`, `.kts`, `.csx`, CSS, HTML, Vue, and Svelte. The language files merely link to common files; Markdown links do not import or activate another rule. Claude Code loads a path rule when a matching file is read (https://code.claude.com/docs/en/memory#path-specific-rules).
3. The common rules contain direct policy conflicts. `common/coding-style.md:23-33` says mutation is CRITICAL and "ALWAYS" forbidden, while Go functional options mutate a server (`golang/patterns.md:13-25`), Rust permits `let mut` when required (`rust/coding-style.md:17-20`), Kotlin permits `var` when required (`kotlin/coding-style.md:15-18`), Java permits mutable state when required (`java/coding-style.md:17-20`), Swift actors mutate storage (`swift/patterns.md:36-46`), and Python's own patterns show a mutable dataclass (`python/patterns.md:20-29`). The README claims language-specific precedence and promises common "Language note" markers (`README.md:93-110`), but the README is deliberately never loaded and no common rule contains such a marker. Claude's own documentation warns that contradictory instructions may be selected arbitrarily (https://code.claude.com/docs/en/memory#write-effective-instructions).
4. Cross-references have rotted. Thirty distinct `See skill: ...` targets occur in the rule tree. Only `python-testing`, `security-review`, and `tdd-workflow` exist under Claude's direct user-skill root; none of the other 27 appears in the eight enabled plugin skill roots. `typescript/security.md:26-28` additionally calls `security-reviewer` a skill even though it is an agent. These are stale/wrong pointers, not evidence that users ignored good guidance.
5. The corpus contradicts the broad workflow mandates. The rules require planner, TDD, code-review, security, build-repair, TypeScript-review, and E2E agents in multiple places, but the capability census records 1,158 `general-purpose` invocations versus `planner=28`, `code-reviewer=29`, `security-reviewer=18`, `python-reviewer=13`, `build-error-resolver=2`, and zero observed `tdd-guide`, `typescript-reviewer`, or `e2e-runner`. It is **likely (55-80%)**, based on those counts plus 41,809 Write/Edit calls, that the universal named-agent workflow is poorly adhered to. This inference is **UNVERIFIED** because the corpus does not join agent invocations to qualifying code-change triggers; the settling experiment is a trigger-conditioned join of edits/commits to subsequent agent calls. The likely cause is badly written, over-broad ritual plus prose-only enforcement, not that TDD or review are intrinsically wrong.
6. `windows-shell.md` contains high-value, corpus-relevant safety rules, but one high-authority explanation is false: `^` is not PowerShell's escape/continuation character. Microsoft documents the backtick as both escape and line-continuation character (https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_special_characters?view=powershell-7.6), and a local probe passed literal `HEAD^` unchanged and successfully ran `git rev-parse HEAD^`. Quoting `HEAD^{commit}` remains a safe workaround; the mechanism is braces/script-block parsing, not caret escaping.
7. Context cost is material and uneven. The five always-loaded rules cost 20,122 bytes before project instructions. A Python path selects 19 rules / 38,515 bytes; a TypeScript path selects 26 rules / 57,708 bytes because common, TypeScript, and all seven web rules overlap; a Dart path selects 10 rules / 44,230 bytes but receives none of the path-scoped common rules; a PowerShell path receives only the five always-loaded rules / 20,122 bytes. It is **very likely (80-90%)** that this asymmetry reduces adherence on TypeScript-heavy work, based on the exact fan-in and Claude's documentation that longer instructions reduce adherence (`memory` documentation lines 166-173). The size-to-error causal effect is **UNVERIFIED**; an `InstructionsLoaded` trace plus paired representative sessions would settle it.

Overall severity: **high / degrading**, with two **breaking-at-point-of-use** files (`common/hooks.md`, `web/hooks.md`) and one materially false high-authority shell claim. The subsystem should not be discarded wholesale: path-scoping is already native, the recent fan-out/single-signal/cross-vendor rules encode valuable measured failures, and 83 source/live files are currently byte-identical. The right design direction is consolidation and activation repair on the existing rules/hooks/skills bus, not another runtime.

## Severity-ranked findings

### F1 — `common/hooks.md` and `web/hooks.md` give obsolete/invalid runtime instructions — breaking

`common/hooks.md:9-13` reduces the hook system to PreToolUse, PostToolUse, and Stop, hiding 15 currently registered events and newer documented events such as `InstructionsLoaded`, `PostToolBatch`, and `StopFailure`. Lines 23-29 direct agents to `TodoWrite`. Corpus P7 independently shows that this tool path is dead while Task tools are heavily used.

`web/hooks.md` is worse: its five settings examples put `command` directly on the matcher group. Claude Code 2.1.214 requires event -> matcher group -> inner `hooks` array -> typed handler. Live settings demonstrate the required schema at `settings.json:322-342`, and current first-party docs show it at https://code.claude.com/docs/en/hooks#configuration. The examples also rely on `$FILE_PATH`, but current command hooks receive JSON on stdin and the rules do not define that environment variable (`web/hooks.md:31,49,81`).

Confidence: **almost certain (90-99%)**, supported by rule text, installed version, live accepted schema, vendor schema, and corpus tool counts.

Why ignored versus wrong: `TodoWrite` and the JSON schema are **wrong/stale**, not merely badly phrased. Agents cannot comply successfully. The three-event list is incomplete rather than false.
