# F001 — Frontier research: agent memory architectures and consolidation

**Unit:** F001  
**Research date:** 2026-07-19  
**Scope:** persistent memory for tool-using/coding agents, with emphasis on formation, consolidation, retrieval, provenance, forgetting, and cross-session recovery. This is frontier research and architecture advice, not a build.  
**Evidence policy:** primary papers, official documentation, and real repositories are cited inline. Harness facts come from the pinned corpus or earlier audit artifacts and remain audit *claims* unless the pinned brief itself declares them measured ground truth. The corpus `hooks` section is not used because the brief declares its detector broken.

## Executive verdict

The field has established a small set of mechanisms, not a winning “memory architecture.” Persisted raw history, bounded working context, retrieval over external state, lossy summaries backed by recoverable source material, explicit updates/supersession, and task-level evaluation are well supported across peer-reviewed benchmarks and shipped systems. Long context alone is not reliable memory: position sensitivity is experimentally established, and both LoCoMo and LongMemEval show substantial deficits on temporal, multi-session, update, and abstention tasks ([Lost in the Middle](https://arxiv.org/abs/2307.03172), [LoCoMo, ACL 2024](https://aclanthology.org/2024.acl-long.747/), [LongMemEval, ICLR 2025 repository](https://github.com/xiaowu0162/LongMemEval)).

What is *not* established is that an anthropomorphic hierarchy, autonomous knowledge graph, forgetting curve, “memory operating system,” or continuously self-rewriting store is generally superior. A-MEM and MemoryOS are serious peer-reviewed systems, but their results establish performance in their experimental settings, not a universally superior substrate ([A-MEM, NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html), [MemoryOS, EMNLP 2025](https://aclanthology.org/2025.emnlp-main.1318/)). Mem0 reports attractive quality, latency, and token numbers, but the paper is authored by the vendor, evaluates primarily on LoCoMo, and the graph variant improves its own base by only about 2% in the reported overall judge score; that is evidence to test graph memory, not evidence to install another graph system ([Mem0 paper](https://arxiv.org/abs/2504.19413)).

For this owner, full replacement is not supported. The harness already has the more defensible substrate: an append-only, locked shared ledger; a file-first, human-auditable Basic Memory vault with lexical, vector, and hybrid search; cross-provider pre-compaction checkpoints; and an existing hook/dispatcher bus. Audit evidence identifies semantic isolation and retrieval-efficiency defects, not absence of memory infrastructure: `B15.md:49-63` finds one cross-provider ledger with guarded appends; `B14.md:50-72` finds 88 indexed Claude/Codex compaction checkpoints and an operational Basic Memory HTTP endpoint; `A07.md:71-85` finds a costly full-scan recall path and explicitly identifies the existing dispatcher as the consolidation bus. Basic Memory itself documents Markdown as the source of truth and its database as a secondary index, which is a better failure/recovery boundary than an opaque new service ([Basic Memory technical architecture](https://docs.basicmemory.com/reference/technical-information), [semantic search modes](https://docs.basicmemory.com/concepts/semantic-search)).

The recommended frontier move is therefore **selective architectural replacement inside the current buses**: replace unscoped, unprovenanced, full-scan recall and free-form consolidation with typed, evidence-linked, scope-aware memory formation; keep raw receipts immutable; consolidate at lifecycle boundaries; retrieve with bounded hybrid candidate generation plus deterministic filters; and promote changes only when held-out replay beats the current harness. This is ambitious because it changes the memory contract end-to-end, but it does not add a second runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

## Definitions and evidence threshold

“Memory” is overloaded. This report distinguishes:

1. **Working/context memory:** material in the current model context, including current conversation, tool results, instructions, and a small startup index.
2. **Episodic evidence:** immutable or append-only records of what occurred—turns, tool receipts, failures, decisions, milestones, checkpoints—with identity and time.
3. **Semantic memory:** consolidated facts, preferences, decisions, constraints, and explanations derived from one or more episodes.
4. **Procedural memory:** reusable, executable guidance—skills, commands, verified workflows, and environment-specific gotchas.
5. **Prospective state:** open goals, commitments, pending checks, and triggers for future action.

The semantic/episodic/procedural taxonomy is a useful design vocabulary, not an empirical law of LLM systems. CoALA is a conceptual synthesis that explicitly proposes modular memory and memory actions; it does not prove that mirroring human cognitive categories improves agents ([CoALA](https://arxiv.org/abs/2309.02427)). “Established” below requires at least two mechanically independent signals such as peer-reviewed task results plus an independently shipped implementation, or consistent results across independent benchmarks. One paper, one vendor benchmark, or one leaderboard is “promising,” even when peer reviewed.

# 1. Established

## 1.1 Persistent external state is necessary once useful history exceeds context

An LLM can only use out-of-context information after some system retrieves or reintroduces it. MemGPT states this boundary explicitly and evaluates tiered external context in document analysis and multi-session chat; OpenAI’s Agents SDK ships persisted sessions and a compaction wrapper; Claude Code ships project instructions and auto memory as two cross-session mechanisms ([MemGPT](https://arxiv.org/abs/2310.08560), [OpenAI Agents SDK sessions](https://openai.github.io/openai-agents-python/sessions/), [Claude Code memory](https://code.claude.com/docs/en/memory)). The shipped APIs prove operational adoption, not that their default policies are optimal.

The harness implication is narrow: durable state is not optional for multi-session work, but a new service is optional. This harness already persists raw state and semantic notes; replacing them must clear a higher bar than showing that persistence helps.

## 1.2 Long context is a working-memory tier, not a durable-memory substitute

“Lost in the Middle” found large position-dependent performance changes in multi-document QA and key-value retrieval, including degradation when relevant material sits in the middle of long contexts ([paper](https://arxiv.org/abs/2307.03172)). LoCoMo contains roughly 600-turn, 16K-token conversations over as many as 32 sessions and reports that long-context and RAG improve results but remain substantially below human performance on long-range temporal and causal understanding ([ACL paper](https://aclanthology.org/2024.acl-long.747/)). LongMemEval supplies 500 questions across extraction, multi-session reasoning, updates, temporal reasoning, and abstention; its repository distinguishes 115K-token and roughly 500-session histories and includes full-context and retrieval baselines ([official repository](https://github.com/xiaowu0162/LongMemEval)).

This establishes two design constraints: context should contain a bounded working set, and evaluation must place evidence at varied positions and across compaction/session boundaries. It does **not** establish one fixed top-k or context size across tasks.

## 1.3 Summarization is useful and lossy; summaries need source escape hatches

MemGPT directly describes recursive summarization as lossy and argues that repeated compression creates holes; its alternative retains external context that can be paged back in ([MemGPT, §2–3](https://arxiv.org/abs/2310.08560)). OpenAI’s Agents SDK now ships `OpenAIResponsesCompactionSession`, while its sandbox memory beta uses two stages—conversation extraction followed by layout consolidation—and preserves conversation summaries/raw extracts for the consolidation agent ([session compaction](https://openai.github.io/openai-agents-python/sessions/), [sandbox agent memory beta](https://openai.github.io/openai-agents-python/sandbox/memory/)). Claude Code’s native auto memory similarly loads only a bounded `MEMORY.md` index and leaves topic files for on-demand reads ([Claude Code memory](https://code.claude.com/docs/en/memory)).

The common, established pattern is hierarchical *representation*: a small index/summary points to detailed source. The biological or OS metaphor is incidental. The evidence supports reversible drill-down, not autonomous overwriting of the only copy.

## 1.4 Retrieval quality depends on indexing granularity, time, updates, and abstention—not semantic similarity alone

LongMemEval decomposes system design into indexing, retrieval, and reading; its reported successful interventions include session decomposition, fact-augmented keys, and time-aware query expansion, across question types that explicitly include knowledge updates and abstention ([paper abstract](https://arxiv.org/abs/2410.10813), [official code/data](https://github.com/xiaowu0162/LongMemEval)). LoCoMo independently shows persistent difficulty in temporal and causal reasoning even when RAG is used ([ACL 2024](https://aclanthology.org/2024.acl-long.747/)). Basic Memory already indexes notes lexically and semantically and exposes text, vector, and hybrid modes; therefore this harness does not need a new vector database merely to obtain hybrid retrieval ([Basic Memory semantic search](https://docs.basicmemory.com/concepts/semantic-search)).

The established conclusion is that retrieval must include deterministic metadata filters and update semantics in addition to similarity. There is no established universal retriever: exact identifiers, paths, commands, dates, and negations often favor lexical/structured matching, while paraphrases favor semantic matching.

## 1.5 Memory writes and reads must be separately observable

A fluent correct or incorrect answer does not reveal whether the system failed to capture, consolidate, retrieve, or use evidence. MemoryAgentBench evaluates four distinct competencies—accurate retrieval, test-time learning, long-range understanding, and selective forgetting—and reports that current methods do not master all four ([ICLR 2026 paper/repository](https://github.com/HUST-AI-HYZ/MemoryAgentBench)). LongMemEval likewise separates indexing, retrieval, and reading choices ([paper](https://arxiv.org/abs/2410.10813)). This is post-2025 evidence, but it strengthens an older systems principle: stage-level receipts are needed to diagnose failure.

For this harness, the pinned corpus’s broken hook detector reinforces the same point internally: “zero observed hooks” was detector failure, not evidence of no hooks. A memory evaluation that scores only final answers would repeat that epistemic error.

## 1.6 Immutable episodes plus derived semantic/procedural artifacts are safer than destructive consolidation

Reflexion stores verbal feedback in an episodic buffer and shows gains across sequential decision making, coding, and reasoning, with ablations over feedback sources and incorporation methods ([NeurIPS 2023](https://papers.nips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)). Generative Agents stores an observation stream, derives reflections, and retrieves observations/reflections for planning; its ablations show observation, planning, and reflection all affect judged believability in its simulation ([paper](https://arxiv.org/abs/2304.03442)). These tasks differ markedly, so the common result is the value of retaining episodes while deriving reusable abstractions, not the optimality of either reflection prompt.

The harness already follows the sound half of this pattern: audit `B15.md:49-63` reports a locked append-only project ledger, while `B14.md:50-56` reports indexed pre-compaction checkpoint artifacts. The defect is that derived/replayed records lack adequate scope and provenance (`B15.md:9-31`), not that raw episodes should be replaced.

## 1.7 Human-auditable storage and explicit lifecycle controls are operationally mature

Claude Code stores native auto memory as plain Markdown with a small startup index; users can inspect, edit, or delete it, and path-scoped rules load on demand ([official docs](https://code.claude.com/docs/en/memory)). Basic Memory is file-first Markdown with a secondary database index and explicitly supports text/vector/hybrid search through MCP ([technical architecture](https://docs.basicmemory.com/reference/technical-information), [GitHub repository](https://github.com/basicmachines-co/basic-memory)). OpenAI’s Agents SDK exposes session `get_items`, `add_items`, `pop_item`, and `clear_session`, and warns not to layer client-managed sessions on server-managed continuation ([official sessions docs](https://openai.github.io/openai-agents-python/sessions/)).

The established operational lesson is that inspectability, deletion, isolation, and a single source of truth matter as much as retrieval scores. Layering overlapping session/memory mechanisms without an ownership contract is specifically discouraged by the OpenAI API design and is already a local harness problem: audit `B14.md:42-48` finds Codex native memories active alongside the cross-provider Basic Memory vault.

## 1.8 Persistent memory creates a durable trust boundary

PoisonedRAG demonstrates that knowledge corruption can steer RAG answers, establishing that retrieved external text is an integrity boundary even before autonomous memory writes ([USENIX Security 2025 paper](https://www.usenix.org/system/files/usenixsecurity25-zou-poisonedrag.pdf)). Agent-specific memory-poisoning studies became much stronger in 2026; because they are recent, this report does not use their attack rates as prevalence estimates, but multiple independent papers now demonstrate query-only or indirect content being written, later retrieved, and used ([systematic memory-poisoning preprint](https://arxiv.org/abs/2606.04329), [MemIncept, ICML 2026](https://openreview.net/forum?id=1YNrlSSRsk), [Visual Inception, ACL 2026](https://aclanthology.org/2026.acl-long.954/)).

The established claim is the threat mechanism, not any one attack-success percentage. Content from webpages, tool outputs, repositories, email, or other agents must not silently become trusted procedural policy. Memory needs source identity, trust class, and promotion rules.

# 2. Promising but unproven

## 2.1 Dynamic linked-note consolidation (A-MEM)

**Confidence: likely (55-80%) to improve some multi-hop and temporal recall over flat notes, given A-MEM’s six-backbone LoCoMo results, DialSim comparison, and ablation of link generation/memory evolution; unlikely (20-45%) to justify a new graph runtime here, because this harness’s Basic Memory already supports explicit links plus hybrid search and A-MEM does not establish gains on this owner’s coding/research workloads** ([A-MEM paper and tables](https://papers.neurips.cc/paper_files/paper/2025/file/19909c36f51abc4856b4560aff3d36d6-Paper-Conference.pdf), [Basic Memory knowledge format](https://docs.basicmemory.com/concepts/knowledge-format)).

A-MEM is not hype by default: it is peer reviewed, releases code, uses multiple foundation models, and includes component ablations. The unproven step is generalization from conversational QA/simulation to concurrent coding agents, and whether LLM-generated links outperform cheap lexical/hybrid candidates after equalizing model calls and latency.

## 2.2 Hierarchical short/mid/long-term stores (MemGPT, MemoryOS, LightMem-like systems)

**Confidence: likely (55-80%) that coarse-to-fine representation can reduce context tokens while preserving useful recall, because MemGPT, MemoryOS, A-MEM, and shipped Claude/OpenAI memory independently use a small visible tier plus external detail; roughly even (45-55%) that three named tiers outperform this harness’s simpler raw-ledger → consolidated-note → bounded-context pipeline, because tier names do not specify the write, eviction, conflict, or retrieval policy** ([MemGPT](https://arxiv.org/abs/2310.08560), [MemoryOS](https://aclanthology.org/2025.emnlp-main.1318/), [Claude native index/topic-file design](https://code.claude.com/docs/en/memory), [OpenAI sandbox consolidation](https://openai.github.io/openai-agents-python/sandbox/memory/)).

The valuable frontier idea is coarse-to-fine access. The unproven idea is that an OS analogy or heat/FIFO mechanism is the right policy for heterogeneous agent evidence.

## 2.3 Autonomous reflection and experience-to-procedure promotion

**Confidence: likely (55-80%) that verified feedback distilled into compact lessons can reduce repeated mistakes on recurring task families, given Reflexion’s cross-task results and the harness’s 5,692 error fingerprints/2,268 owner-correction candidates; unlikely (20-45%) that unrestricted self-reflection improves reliability, because a model can consolidate its own false diagnosis and the cited results rely on task feedback, tests, or evaluators** ([Reflexion](https://papers.nips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html); pinned corpus `/local_disk0/codexwork/bundle/inputs/corpus.json` `_meta` plus owner-supplied counts).

The key discriminator is objective feedback. “Test failed with fingerprint X, changed precondition Y, then test passed” is promotable evidence. “I think approach X is better” is at most a candidate note until independently verified.

## 2.4 Time-aware decay, selective forgetting, and rehearsal

**Confidence: roughly even (45-55%) that explicit decay improves this harness, because benchmarks show update/forgetting is a real competency but do not establish one decay function; very likely (80-90%) that hard deletion based only on age would destroy valuable rare facts, because paths, owner preferences, and environment gotchas can remain valid despite infrequent access** ([LongMemEval update/abstention tasks](https://github.com/xiaowu0162/LongMemEval), [MemoryAgentBench selective forgetting](https://github.com/HUST-AI-HYZ/MemoryAgentBench)).

Use status and supersession before decay. Recency may adjust rank among equally relevant active records; it should not erase provenance or replace explicit validity intervals. Biological “forgetting curves” are metaphors until evaluated against the harness’s recurrence distribution.

## 2.5 Learned or agentic memory policies

**Confidence: likely (55-80%) that learned write/read policies can beat static policies on the training/evaluation distribution, given 2026 AgeMem and MemoryAgentBench results; very unlikely (5-20%) that training such a policy is the best next step for this owner, because it reintroduces a trained policy/critic-like component, adds model coupling, and has no held-out evidence on this harness** ([AgeMem, ACL 2026](https://aclanthology.org/2026.acl-long.981/), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)).

These are post-2025 frontier results and receive lower weight: there has been little time for independent replication, operational failure reports, or model-generation turnover. They belong in a future bake-off, not the default architecture.

## 2.6 Agent-workflow memory and environment-specific “gotchas”

**Confidence: likely (55-80%) that compact, verified workflows are higher-value for coding agents than broad conversational biography, because LongMemEval-V2 explicitly targets workflow knowledge, environment gotchas, state dynamics, and premise awareness over web-agent trajectories; roughly even (45-55%) that its reported methods transfer to Windows coding work until the harness runs a same-task replay** ([LongMemEval-V2 paper](https://arxiv.org/abs/2605.12493), [official repository](https://github.com/xiaowu0162/LongMemEval-V2)).

This post-2025 benchmark is unusually aligned with the owner’s use case, but remains too new to call established. Its taxonomy is immediately useful for evaluation design.

## 2.7 Scale-conditioned and stage-conditioned evaluation

**Confidence: very likely (80-90%) that fixed-snapshot memory scores overstate production reliability, because irrelevant history grows, retrieval budgets bind, and a correct answer can bypass memory; evidence includes the 2026 scale-conditioned evaluation’s observed degradation and MemoryAgentBench’s separation of competencies, tempered by their limited replication time** ([scale-conditioned evaluation](https://arxiv.org/abs/2605.07313), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)).

This is promising methodology rather than a memory component. The harness should emulate it cheaply by adding distractor history and logging capture/retrieval/use separately.

# 3. Hype, and the tell that gives it away

## 3.1 “Never forgets,” “universal memory,” “production-ready,” or “memory OS” as a performance claim

The tell is a universal product adjective attached to one or two benchmark settings. Mem0’s paper title says “Production-Ready” while the evidence highlighted in its abstract is primarily LoCoMo plus latency/token comparison to full context; Letta’s repository says agents “learn and self-improve”; Basic Memory’s README says “never forgets.” These are product/project descriptions, not independently replicated universal guarantees ([Mem0](https://arxiv.org/abs/2504.19413), [Letta repository](https://github.com/letta-ai/letta), [Basic Memory repository](https://github.com/basicmachines-co/basic-memory)). Treat the mechanisms as candidates and the adjectives as marketing.

## 3.2 Brain analogies presented in place of an operational contract

The tell is naming a hippocampus, forgetting curve, reflection, sleep, subconscious, or short/mid/long-term tier without specifying: what is written; source trust; identity/scope; conflict semantics; deletion; retrieval budget; and a task-level ablation. CoALA itself is careful to present a conceptual framework, while MemGPT’s useful contribution is explicit data movement between visible and external context—not proof that an LLM is an operating system ([CoALA](https://arxiv.org/abs/2309.02427), [MemGPT](https://arxiv.org/abs/2310.08560)).

## 3.3 Knowledge graphs by default

The tell is reporting graph structure or attractive visualization rather than equal-budget downstream task success. Mem0’s abstract says its graph variant is only around 2% above base Mem0 overall, while A-MEM’s stronger result relies on both rich note construction and dynamic evolution, so the graph alone is not identified as the causal benefit ([Mem0](https://arxiv.org/abs/2504.19413), [A-MEM ablations](https://papers.neurips.cc/paper_files/paper/2025/file/19909c36f51abc4856b4560aff3d36d6-Paper-Conference.pdf)). For this harness, explicit Markdown links already exist in Basic Memory; adding Neo4j/Graphiti/another graph daemon would duplicate capability before a controlled test ([Basic Memory knowledge format](https://docs.basicmemory.com/concepts/knowledge-format)).

## 3.4 A single LoCoMo or LongMemEval leaderboard number

The tell is omitting dataset version, oracle versus real retrieval, backbone, judge, prompts, top-k, latency, token budget, and whether the run is deterministic. LongMemEval’s official repository records a September 2025 data cleanup, and its oracle file contains only evidence sessions; scores across versions/modes are not directly comparable ([official repository](https://github.com/xiaowu0162/LongMemEval)). A repository currently claims 96.2% “real retrieval” while also labeling the benchmark file “oracle dataset,” a wording conflict that requires reproduction rather than belief ([claiming repository](https://github.com/JordanMcCann/agentmemory)).

## 3.5 LLM-as-judge uplift without retrieval and evidence receipts

The tell is a final naturalness/correctness score with no proof the relevant memory was captured, retrieved, and causally used. LoCoMo includes lexical overlap metrics and later systems often add LLM judges; MemoryAgentBench exists precisely because final outcomes do not cover accurate retrieval, test-time learning, long-range understanding, and selective forgetting ([LoCoMo](https://aclanthology.org/2024.acl-long.747/), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)). A memory system can answer from pretrained knowledge, guess, or be helped by a judge bias.

## 3.6 “Self-evolving” memory without monotonic evidence or rollback

The tell is allowing new model-generated notes to rewrite old context without storing the old version, derivation edges, or a contradiction receipt. A-MEM explicitly updates contextual representations of historical memories; that is a plausible research mechanism but a dangerous production default if the source episode is discarded ([A-MEM](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html)). Safe evolution is append + supersede + evaluate, not silent mutation.

## 3.7 Retrieval accuracy with no poisoning or privacy evaluation

The tell is aggressive automatic writes from untrusted content and no source trust field. Recent independent attack work demonstrates delayed poisoning across write, retrieval, and action stages; this report does not treat the new studies’ exact attack rates as prevalence estimates, but omission of the threat model is no longer defensible ([systematic study](https://arxiv.org/abs/2606.04329), [MemIncept](https://openreview.net/forum?id=1YNrlSSRsk), [Visual Inception](https://aclanthology.org/2026.acl-long.954/)).

# 4. Specific things this harness should adopt

## 4.0 Decision rule for all proposals

Every accepted proposal below rides the existing shared ledger, hook dispatcher, skill/Markdown plane, or Basic Memory MCP. None introduces a rejected second orchestrator, vector DB/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework. Any expected outcome is given an honesty confidence band. “Done” means passing the acceptance experiment, not merely landing code.

## 4.1 Keep Basic Memory as the canonical semantic store and the shared ledger as canonical episodic evidence — **CONFIG (settings/JSON only)**

Declare one ownership contract:

- raw tool/turn/goal/checkpoint events live in the append-only shared ledger/checkpoint directories;
- consolidated project facts, decisions, preferences, failure lessons, and workflow notes live in Basic Memory Markdown;
- CLAUDE.md/AGENTS.md/rules/skills remain procedural instruction surfaces, not automatically generated semantic truth;
- provider-native memories are caches or disabled writers, never canonical cross-provider facts.

Why this harness: audit `B15.md:49-63` reports the ledger already mixes Claude/Codex records under guarded appends; `B14.md:50-72` reports shared indexed checkpoints and a supervised Basic Memory endpoint; Basic Memory documents file-first Markdown with the database only a secondary index ([technical docs](https://docs.basicmemory.com/reference/technical-information)). This is a strong recoverability boundary.

**Expected outcome: very likely (80-90%) to reduce contradictory cross-provider state, because the current audit directly identifies a second Codex-native memory plane at `B14.md:42-48` and OpenAI’s official SDK warns against layering overlapping session-continuation mechanisms. Evidence: local audit plus [OpenAI session strategy](https://openai.github.io/openai-agents-python/running_agents/).**

**Acceptance:** for one seeded fact and one correction, enumerate every enabled memory writer; prove only the canonical semantic writer persists the fact, both Claude and Codex retrieve the correction, and the superseded value is not injected as active.

**Anti-overfit gate:** passes. It removes ambiguity and duplicate state rather than adding a component.

## 4.2 Persist scope, provenance, validity, and derivation on every memory-bearing record — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Minimum envelope:

```text
record_id, project_id, workspace/worktree_id, provider, session_id, turn_id,
kind, scope(project|workspace|session|user), created_at_utc,
source_type(user|tool|agent|web|file|test), source_ref, trust_class,
valid_from, valid_until, status(active|superseded|retracted|candidate),
supersedes[], derived_from[], content_hash
```

Do not require every field from every producer; require identity/time/source fields before a record can clear a verification gate or become an active project fact. Preserve unknown explicitly rather than treating empty `turn_id` as wildcard.

Why now: `B15.md:9-31` claims session identity is dropped, empty turn IDs match all turns, project replay injects other sessions’ notes, and goal files lack project/provider fields. `B15.md:41-47` claims legacy local timestamps can misorder UTC events. These are concrete correctness defects, not speculative frontier features.

**Expected outcome: almost certain (90-99%) to prevent the specifically demonstrated structural cross-session match once queries require matching scope, because the complete local append/query data flow was audited and 200 sampled events lacked the fields (`B15.md:9-15`). The 1-10% residual covers producer bugs and intentionally project-scoped records.**

**Acceptance:** use two independent signals: (1) schema/record inspection shows IDs and UTC; (2) a two-process Claude/Codex fixture writes conflicting goals and receipts in one cwd, then proves neither session can satisfy the other’s completion gate. Also seed a known cross-project record to validate that the detector finds known-present contamination before asserting absence.

**Anti-overfit gate:** passes. This extends the current models/ledger; no new store or runtime.

## 4.3 Add evidence-preserving consolidation at Stop/idle/PreCompact, not per tool call — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — UNVERIFIED correction-candidate utility; experiment: label 200 candidates and replay held-out later sessions**

Consolidate only high-signal candidates:

- explicit owner corrections/preferences;
- decisions with rationale and rejected alternatives;
- failures with stable fingerprint, discriminating diagnosis, and subsequent verified outcome;
- environment gotchas supported by command/tool receipts;
- milestones/open loops that change future action;
- repeated patterns supported by at least two independent episodes.

The consolidator emits or updates a Basic Memory Markdown note with `derived_from` pointers and `status`; it never deletes ledger episodes. Contradictions append a new version and mark the earlier semantic claim superseded/retracted. A model-written lesson without objective feedback remains `candidate` and is excluded from automatic procedural injection.

Trigger it at existing lifecycle boundaries so the agent sees a coherent episode and ordinary tool calls do not pay extra latency. OpenAI’s beta memory similarly performs extraction then consolidation when the sandbox session closes, while Claude’s native auto memory uses a bounded index plus topic files ([OpenAI sandbox memory](https://openai.github.io/openai-agents-python/sandbox/memory/), [Claude memory](https://code.claude.com/docs/en/memory)).

**Expected outcome: likely (55-80%) to reduce repeated-error exploration and post-compaction loss, based on Reflexion’s verified-feedback gains and this corpus’s large correction/fingerprint pool; the range is broad because the owner’s candidates have not been labeled for durable usefulness ([Reflexion](https://papers.nips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)).**

**UNVERIFIED premise:** the pinned 2,268 owner-correction candidates contain enough true, reusable corrections to beat current recall. The settling experiment is to stratify and human-label 200 candidates for correctness, recurrence, scope, and future utility, then replay held-out later sessions with and without promoted notes.

**Acceptance:** no recommendation is injected unless its `derived_from` receipt exists; retraction leaves raw evidence readable; 100 seeded contradictory updates return the latest active value and can explain the supersession chain; hook p95 does not materially regress.

**Anti-overfit gate:** passes. This is one reducer on the existing dispatcher/MCP plane, not a subconscious agent or daemon.

## 4.4 Replace full-vault prompt-time scans with bounded hybrid candidate retrieval and source drill-down — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Retrieval order:

1. deterministic filters: project/workspace/session scope, active status, trust class, validity interval;
2. exact identifiers and lexical/BM25 candidates for paths, commands, symbols, error fingerprints, dates, and quoted phrases;
3. semantic candidates for paraphrase/concept recall;
4. reciprocal-rank or similarly simple fusion, with recency only as a bounded tie/weak feature;
5. return 3–8 compact notes/abstracts with IDs and evidence pointers;
6. allow the agent to dereference the source episode/note when detail is needed.

Do not build a new vector DB or graph: Basic Memory already supports text/vector/hybrid search ([official semantic-search docs](https://docs.basicmemory.com/concepts/semantic-search)). Audit `A07.md:71-77` claims the current hook reparses a 923 KB/422-note index on every eligible prompt and proposes exact token-to-note postings on the existing index builder; that is the local fast-path defect. **Expected outcome: very likely (80-90%) to cut prompt-hook parsing work because candidate postings avoid loading all note metadata; likely (55-80%) to improve downstream precision at fixed context because hybrid retrieval covers exact and semantic cases. **Acceptance:** benchmark exact-path, paraphrase, temporal-update, contradiction, abstention, and distractor-growth cases. Report capture recall, retrieval recall@k/precision@k, answer accuracy, p50/p95 latency, retrieved tokens, and false-injection rate. **Anti-overfit gate:** passes. It uses the existing lexical builder and Basic Memory index; no vector/KG service is added.

Implement a trust lattice, not a new guardrail framework:

- objective tool/test receipt: eligible evidence, not instruction;
- agent inference/reflection: candidate only until corroborated;
- web/email/document/repository content: untrusted content; never procedural policy merely because it says “remember”;
- other-agent output: attributed proposal/evidence, not owner authority.

On retrieval, render memory in a delimited data block with source/trust/status and instruct the model that retrieved content cannot override system/developer/user authority. High-impact procedural promotion requires either owner approval or two mechanically independent objective receipts. Retraction must be available without deleting the source episode.

**Expected outcome: likely (55-80%) to reduce persistent prompt-injection/poisoning risk, supported by multiple recent attack demonstrations; not “very likely” because general defenses remain under-evaluated and the 2026 literature is new** ([systematic memory poisoning](https://arxiv.org/abs/2606.04329), [MemIncept](https://openreview.net/forum?id=1YNrlSSRsk), [Visual Inception](https://aclanthology.org/2026.acl-long.954/)).

# 5. Design synthesis: the smallest architecture that captures the frontier

```text
provider hooks / MCP / skills
          |
          v
  existing normalized dispatcher
          |
          +--> append immutable scoped episode + receipt
          |       (source, trust, UTC, project/provider/session/turn)
          |
          +--> Stop / idle / PreCompact candidate reducer
          |       |
          |       +--> candidate semantic/procedural/open-loop record
          |       +--> derive_from raw IDs; append/supersede, never erase
          |       +--> Basic Memory Markdown (canonical semantic store)
          |
prompt / resume / task boundary
          |
          +--> deterministic scope/status/trust/time filters
          +--> lexical exact + existing semantic search
          +--> bounded fused notes with evidence IDs
          +--> optional source drill-down
          |
          v
       model working context

all stages --> existing local receipts/telemetry --> held-out replay gate
```

This architecture deliberately separates four concerns:

- **formation:** did the event enter memory with correct identity and trust?
- **consolidation:** did a derived note faithfully preserve evidence, updates, and uncertainty?
- **retrieval:** did the system return the right active evidence under a bounded budget?
- **application:** did the agent use it correctly without letting data override authority?

It also makes “forgetting” explicit: working context evicts freely; derived notes can become superseded/retracted/expired; raw evidence remains until an owner retention policy deletes it. No Ebbinghaus constant is required.

# 6. Alternatives considered and why they lost

## Full-context-only — **CONFIG (settings/JSON only) — REJECTED AS DEFAULT**

Rejected as the durable design. It is simple and can be a powerful oracle/baseline, but long-context position effects and benchmark deficits are established, cost grows with history, and it provides no cross-session truth/update contract ([Lost in the Middle](https://arxiv.org/abs/2307.03172), [LongMemEval](https://arxiv.org/abs/2410.10813)). Keep it as an evaluation upper/reference lane where context permits.

## Vector-only RAG — **CONFIG (settings/JSON only) — REJECTED AS SOLE RETRIEVER**

Rejected as the sole retriever. It misses exact operational identifiers and does not by itself encode scope, time, negation, supersession, or trust. Basic Memory already supports hybrid search, so vector-only would be a regression in available signals ([Basic Memory semantic search](https://docs.basicmemory.com/concepts/semantic-search)).

## Knowledge-graph-first memory — **BUILD-LARGE (new daemon/service/runtime -- needs its own justification) — REJECTED BY ANTI-OVERFIT GATE**

Rejected as default. Explicit typed links are useful and already available in Markdown; a graph database adds no demonstrated local benefit. Mem0’s modest reported graph-over-base increment and A-MEM’s entangled note/link/evolution mechanism do not isolate a graph DB as the win ([Mem0](https://arxiv.org/abs/2504.19413), [A-MEM](https://papers.neurips.cc/paper_files/paper/2025/file/19909c36f51abc4856b4560aff3d36d6-Paper-Conference.pdf)).

## Continuous every-turn consolidation — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — REJECTED CADENCE**

Rejected. It adds latency/cost, repeatedly exposes the store to model drift, and makes transient conversation look durable. Shipped OpenAI sandbox memory consolidates at conversation/session close, supporting lifecycle batching as a real operational alternative ([official beta docs](https://openai.github.io/openai-agents-python/sandbox/memory/)).

## Automatic promotion of reflections into skills/rules — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — REJECTED WITHOUT OBJECTIVE RECEIPTS**

Rejected. Reflexion’s gains rely on feedback signals; self-generated diagnosis is not independent evidence ([NeurIPS 2023](https://papers.nips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)). Candidate lessons may be tested, then promoted through the existing skill/rule workflow with rollback.

## Biological decay — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — UNVERIFIED; experiment: replay explicit supersession versus candidate decay functions**

Rejected pending replay. Update, selective forgetting, and scale are real problems, but no universal decay curve is established for agent harness facts. Explicit supersession, validity, scope, and bounded ranking are more inspectable and testable ([LongMemEval](https://github.com/xiaowu0162/LongMemEval), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)).
