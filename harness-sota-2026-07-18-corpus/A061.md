# A061 — Coherence audit: `~/.claude/rules/rust/coding-style.md`

## Executive result

The Rust coding-style rule is not coherent as an operational contract. I found **seven confirmed
collisions**: three same-rule-layer contradictions, one duplicated organization rule, one
formatter/linter requirement that is not enforced, one stale Rust hook document claiming missing
automation, and one stop-time Rust reachability policy that has no matching normative rule. The referenced
`rust-patterns` skill is present in the supplied current skill-router index, but the remote bundle
omits the skill body; consequently skill-content collision checking is **UNVERIFIED; the settling
experiment is to read the live Windows `~/.claude/skills/rust-patterns/SKILL.md` (or the exact indexed
plugin path) and compare each imperative against the target.**

The highest-impact defect is mechanical: the rule requires `cargo fmt` and Clippy
(`claude/rules/rust/coding-style.md:11-12`), and the Rust hook rule says edits are automatically
formatted and checked (`claude/rules/rust/hooks.md:10-16`), but the only directly wired per-edit

evidence about whether agents voluntarily run Cargo commands.

## Precedence applied

second, the cross-tool contract third, project governance fourth, and third-party defaults fifth
(`claude/AGENTS.md:115-128`). It further says same-level conflicts must be surfaced, not silently

The rule-pack README supplies an internal specific-over-general rule: language-specific rules take

(`claude/rules/README.md:106-110`), but the absolute immutability and error-handling clauses have no
such note (`claude/rules/common/coding-style.md:23-33`, `:43-49`).

Consequently, I apply the README to determine the intended winner—Rust-specific wording wins—but
also apply AGENTS §10 by reporting the runtime-visible conflict. The precedence documents resolve
the intended outcome but do not make the simultaneously loaded prose coherent.

## Collision register

### C1 — Absolute no-mutation rule versus idiomatic required mutation

**Artifacts and exact lines**

* `claude/rules/common/coding-style.md:23-31`: “ALWAYS create new objects, NEVER mutate existing
  ones.”
* `claude/rules/common/coding-style.md:61-68`: completion checklist includes “No mutation.”
* `claude/rules/rust/coding-style.md:16-22`: use `let` by default but use `let mut` when mutation is
  required; prefer returning new values.
* Confirming same-language example: `claude/rules/rust/patterns.md:115-127` deliberately uses
  `mut self` in an ownership-consuming builder.

**Class:** `CONTRADICTION`.

**Precedence:** the non-loaded rule README intends the Rust-specific rule to win
(`claude/rules/README.md:93-104`), while AGENTS §10 requires this same-layer collision to be surfaced
(`claude/AGENTS.md:129-131`). AGENTS §10 alone does not select between the two rule files.

**Diagnosis:** the common rule is badly written, not the Rust exception. “Never mutate” cannot
coexist with an explicit “when mutation is required” allowance and the builder example. The Rust
rule still expresses the useful default without outlawing ordinary local mutation.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** replace
the common absolute with “prefer immutable data at shared/state boundaries; use local mutation when
it is clearer, more efficient, or idiomatic,” add the README-prescribed language note, and change
the checklist from “No mutation” to “No unjustified shared or externally visible mutation.” Add one
sentence to the Rust rule explicitly stating that required local mutation overrides the common
default. This is **very likely (80-90%)** to eliminate contradictory agent guidance because both
conflicting imperatives and the completion checklist would then state the same boundary; evidence is
the three quoted rule locations and the existing builder example.

### C2 — “Handle at every level” versus idiomatic propagation with `?`

**Artifacts and exact lines**

* `claude/rules/common/coding-style.md:43-49`: “ALWAYS handle errors comprehensively” and “Handle
  errors explicitly at every level.”
* `claude/rules/rust/coding-style.md:74-80`: use `Result<T,E>` and `?` for propagation; use typed
  library errors and application context.
* The target demonstrates two levels of `?` propagation without local recovery at
  `claude/rules/rust/coding-style.md:92-100`.

**Class:** `CONTRADICTION` (semantic ambiguity with contradictory literal readings).

**Precedence:** intended specific-over-general priority makes the Rust propagation instruction win
(`claude/rules/README.md:93-99`), but AGENTS §10 does not independently resolve two global rule files
and requires disclosure (`claude/AGENTS.md:129-131`).

**Diagnosis:** the common rule is badly written. Propagation is explicit error handling in Rust, but
“at every level” can be read as requiring local interception and can induce redundant map/log/rethrow
layers. The target's “never unwrap in production” and context guidance already preserve failures.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** rewrite
the common line as “At each layer, deliberately handle, translate, or propagate errors; never swallow
them,” and retain the existing user-facing/logging requirements. Add “propagation with `?` satisfies
the common rule” to the Rust section. This is **almost certain (90-99%)** to remove the literal
contradiction because the replacement expressly includes the operation shown in the Rust example;
evidence is `common/coding-style.md:45-49` versus `rust/coding-style.md:76-80`.

### C3 — Absolute “no hardcoded values” checklist versus required Rust literals

**Artifacts and exact lines**

* `claude/rules/common/coding-style.md:59-68`: the completion checklist requires “No hardcoded
  values (use constants or config).” Because the common frontmatter includes `**/*.rs`
  (`claude/rules/common/coding-style.md:1-20`), this is loaded for Rust.
* `claude/rules/rust/coding-style.md:83-100`: the target’s approved error definitions and context
  calls necessarily contain stable literal messages such as `"failed to read config: {0}"` and
  `"failed to parse {path}"`.

**Class:** `CONTRADICTION` as literally written.

**Precedence:** the Rust examples are the more specific same-rule-pack guidance under
`claude/rules/README.md:93-99`; AGENTS §10 itself does not order these same-level rule files and says
to surface the collision (`claude/AGENTS.md:129-131`).

**Diagnosis:** the common checklist is badly written. Constants/config are appropriate for tunable
operational values and domain constants. Extracting every diagnostic string into a constant does
not remove the kind of environment-dependent “hardcode” the checklist is evidently trying to
prevent. The target’s error strings are not
secret material and do not collide with the higher security floor at `claude/AGENTS.md:93-102`.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** change
the common checklist item to “No unexplained magic numbers, environment-specific endpoints, secrets,
or tunable operational values embedded in logic; named constants/config used where change or reuse
is expected.” This is **almost certain (90-99%)** to remove the literal collision while preserving
the intended review check because it distinguishes diagnostic text from operational configuration;
evidence is the common absolute and the target’s approved literal-bearing examples at the cited
lines.

### C4 — Domain organization is duplicated in common and Rust rules

**Artifacts and exact lines**

* `claude/rules/common/coding-style.md:35-41`: files should be small and organized by
  feature/domain, not type, with 200-400 lines typical and 800 maximum.
* `claude/rules/rust/coding-style.md:122-141`: “Organize by domain, not by type,” followed by a Rust
  module tree.

**Class:** `REDUNDANCY`.

There is no threshold conflict: the Rust rule supplies no competing file-size threshold. The
duplication is nevertheless maintenance-sensitive because a future edit can silently produce a
different organization policy.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** replace
the Rust imperative with “Apply the common domain-organization rule using Rust modules as follows,”
retain the useful tree, and leave the sole normative wording and thresholds in common. This is
**very likely (80-90%)** to reduce future drift because there will be one normative statement and one
language-specific example; evidence is the near-verbatim wording at the cited lines.

### C5 — Required Rust formatting/linting is documented as automated but is not wired

**Artifacts and exact lines**

* `claude/rules/rust/coding-style.md:9-14`: rustfmt is “for enforcement,” always run `cargo fmt`
  before committing, and run `cargo clippy -- -D warnings`; indent and width rely on rustfmt.
* `claude/rules/rust/hooks.md:10-16`: configure PostToolUse hooks to auto-run `cargo fmt`, `cargo
  clippy`, and `cargo check` after Rust edits.
* `claude/settings.json:333-354`: PostToolUse wires the per-edit validator and generic dispatcher.
* `claude/hooks/per-edit-check/check.py:8-24` and `:151-170`: documented dispatch covers several
  formats but explicitly skips `.rs` because Cargo is considered too heavy.
* `claude/hooks/_dispatch/manifest.json:144-180`: the PostToolUse dispatcher contains no Rust
  formatter, linter, or checker.

**Class:** `UNENFORCED`.

**Precedence:** no higher rule relaxes the Cargo requirements. AGENTS §6 says non-dangerous guidance
must inject rather than block and hook errors must fail open (`claude/AGENTS.md:64-70`), so an
enforcement design must be a nudge/receipt rather than a blocking per-edit hook. The existing
per-edit skip is therefore a performance choice, not permission to claim the requirement is
enforced.

**Diagnosis:** this requirement is badly wired. Formatting and linting are mechanically testable;
the defect is not that prose cannot be enforced. Running three workspace-wide Cargo operations
after every individual edit is also inconsistent with the harness's deliberate loop-avoidance: the
stop validator explains why per-edit validators can wake degenerate edit/fix loops
(`claude/hooks/edit-validate/validate-stop.py:1-21`).

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** amend
`rust/hooks.md` so it describes actual policy, then add a debounced Stop or pre-completion Rust
receipt check that (a) detects edited `.rs`/Cargo files, (b) finds the nearest workspace root, (c)
runs `cargo fmt --check` and `cargo clippy -- -D warnings` once per final edit generation, and (d)
injects failures with exit 0 in accordance with AGENTS §6. Keep `cargo check` only if the project has
no fresher build/test receipt, because Clippy already checks compilation. Do not auto-modify files in
the hook; formatting mutations should remain an explicit agent action. This is **likely (55-80%)**
to improve compliance without edit-loop regressions because it moves work from every edit to one
debounced boundary and uses the existing hook bus; evidence is the explicit `.rs` skip, existing Stop
loop guards, and AGENTS §6. The uncertainty is Cargo workspace cost on the owner's real repositories;
the settling experiment is a shadow-mode run over 20 Rust editing turns measuring p50/p95 runtime,
timeouts, duplicate nudges, and incremental-cache behavior before activation.

**Alternative considered:** enabling the disabled Rust Analyzer plugin
(`claude/settings.json:559`) is **likely (55-80%)** to add some editor diagnostics if the plugin is
healthy, based on its declared analyzer role, but it would not prove rustfmt or the specified
`-D warnings` Clippy gate. **UNVERIFIED; the settling experiment is to enable it in an isolated Rust
fixture and record its diagnostics and commands.** It therefore is not the proposed resolution.

### C7 — Stop-time reachability policy applies to Rust but is not stated by the rule pack

**Artifacts and exact lines**

* `claude/hooks/_dispatch/manifest.json:72-105` actively registers `wire-check/check.py` on Stop.
* `claude/hooks/wire-check/check.py:4-17` says it flags newly added exported symbols referenced zero
  times and duplicate-version names, injecting a reachability question at Stop.
* `claude/hooks/wire-check/check.py:53-74` includes `.rs` in its source extensions, while
  `claude/hooks/wire-check/check.py:79-100` recognizes Rust `struct` and `trait` definitions through
  its generic top-level-definition pattern and version suffixes through `_VERSUF`.
* `claude/rules/rust/coding-style.md:143-147` governs visibility (`pub` only for public API), but
  neither it nor the full common-rule search states that a new Rust public symbol must already have an
  in-repository reference or that `_v2`/`_new` naming is prohibited. The nearest target language is
  about API intent, not reachability.

The rule-absence detector had two mechanically independent signals and positive controls: a full
search of `claude/rules/**/*.md` found the known-present target `pub` rule and domain-organization
rule but no dead-code/reachability/version-authority imperative; a separate search of
`claude/CLAUDE.md` plus both supplied `AGENTS.md` files found their known-present security and
precedence terms but no such coding policy. Independently, the executable manifest/code pair proves
the reachability mechanism itself is present. The absence claim is limited to the supplied normative
surfaces, not omitted live skill bodies.

**Class:** `UNRULED`.

**Precedence:** no instruction-precedence winner exists because one side is executable mechanism,
not competing prose. AGENTS §10 does not resolve unruled enforcement; AGENTS §6 does constrain it to
inject-only because zero-reference heuristics are not dangerous operations
(`claude/AGENTS.md:64-70`). The hook complies with that constraint by explicitly never blocking
(`claude/hooks/wire-check/check.py:15-17`).

**Diagnosis:** the mechanism is unruled, not necessarily wrong. In particular, an intentionally new
public Rust API can legitimately have zero in-repository references, a limitation the hook itself
acknowledges (`claude/hooks/wire-check/check.py:15-17`). Without a written policy, the model cannot
distinguish an advisory question from a completion requirement or cite the intended public-API
exception.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** add one
common code-review rule: “New non-API source symbols must be wired or explicitly identified as
intentional extension/public API; version-suffixed replacements must explain which prior path remains
authoritative.” Link the wire-check message to that rule and include the target’s `pub` exception in
the injected text. Keep it exit-0 advisory. This is **very likely (80-90%)** to align rule and
mechanism because it documents exactly the two conditions the active scanner asks about while
preserving legitimate Rust public APIs; evidence is the manifest registration, scanner contract, and
target visibility rule cited above.
