# X121 — Cross-domain borrow: forensic science → agent memory

**Unit:** X121  
**Lens:** contamination control, blind/double-blind protocols, and proficiency testing  
**Target:** what an agent should remember across sessions, when it should forget, and how it should detect staleness  
**Research date:** 2026-07-19 UTC  
**Scope discipline:** external research and design only. Per the unit instruction, I did not inspect the local harness, corpus, audit findings, or subject repository. Consequently, statements about what the current harness does or misses are not conclusions here; they are marked **UNVERIFIED** with an experiment that could settle them.

## Executive result

The borrow transfers, but only in a deliberately narrow form.

The transferable structure is a quality system with three independent controls:

1. **Contamination control:** preserve the source and processing history of every durable memory; separate trusted observations from agent-generated interpretation; use blanks/canaries and a catalogue of known contaminant signatures to detect unintended ingress.
2. **Sequential unmasking and blind verification:** make an initial task/evidence assessment before exposing an agent to potentially biasing historical conclusions; reveal relevant memory in a controlled order; record revisions; occasionally obtain a genuinely independent second assessment for consequential, subjective decisions.
3. **Blind proficiency testing:** inject realistic, known-truth memory cases through the ordinary memory pipeline without telling the working agent which cases are tests, then score whether it retrieved, rejected, superseded, or quarantined them correctly.

The central design recommendation is a small **Memory Evidence Envelope + staged retrieval hook + blind canary suite**, riding the existing memory/hook/skill bus. It is not a second agent runtime, memory graph, vector database, trained critic, guardrail framework, or observability service.

**Transfer confidence:** **very likely (80-90%)** that provenance envelopes plus blind pipeline tests expose important memory-quality failures that ordinary happy-path tests miss. Evidence: forensic blind tests exercise the normal end-to-end pipeline and avoid test-aware changes in behaviour, while declared tests can yield different error rates; the direct software-harness effect remains **UNVERIFIED** until Experiment X121-E3 runs ([Mejia, Cuellar & Salyards 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/)).

**Transfer confidence:** **likely (55-80%)** that staged memory exposure reduces anchoring on stale or self-generated prior conclusions in ambiguous agent work. Evidence: task-irrelevant context and the order of task-relevant information affect forensic judgments, and LSU-E operationalizes sequencing and revision documentation; agent-specific effect size remains **UNVERIFIED** until Experiment X121-E2 runs ([Dror et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC8866671/)).

**Non-transfer conclusion:** it is **very unlikely (5-20%)** that DNA-style elimination matching alone can establish that a semantic memory is false or stale. DNA contamination has matchable physical profiles; two semantically similar statements can have different truth conditions, and a unique-looking memory can still be wrong. Evidence for the source mechanism is the regulator's use of personnel, manufacturer, blank-control, and environmental profiles in elimination databases; the disanalogy is logical rather than empirical ([Forensic Science Regulator Code, §92.11](https://www.gov.uk/government/publications/forensic-science-activities-statutory-code-of-practice-version-2/forensic-science-activities-statutory-code-of-practice-version-2-accessible)).

## 1. What forensic science has actually solved

### 1.1 Contamination control is prevention **plus** detection **plus** trace-back

In forensic DNA work, contamination is not treated as a problem solved by telling practitioners to be careful. The control system layers:

- controlled clean areas and directional movement between pre-PCR and post-PCR work;
- forensic-grade consumables and batch controls;
- negative controls that should contain no target material;
- environmental monitoring;
- elimination profiles for people and supply-chain participants who could contribute DNA;
- retention of unexplained contaminant profiles; and
- incident investigation that works backward through the process to find source and extent.

The UK Forensic Science Regulator's laboratory guidance describes separation between pre- and post-PCR areas and access controls for DNA-clean areas ([FSR-GUI-0018, §§5.2.3-5.2.5](https://www.gov.uk/government/publications/dna-contamination-controls-laboratory/dna-contamination-controls-laboratory-accessible)). The same guidance says profiles should be checked against local and central elimination databases before submission or reporting, permits retention of unexplained contaminant profiles, and specifies a backward, step-by-step investigation when contamination is suspected ([FSR-GUI-0018, §§8.4-9.2](https://assets.publishing.service.gov.uk/media/65379d521bf90d000dd844c6/FSR-GUI-0018_-_contamination_controls_-_lab_final.pdf)).

The statutory code requires local elimination databases to include profiles detected in reagent batch tests, blank/no-template controls, and environmental monitoring, not only staff profiles ([Forensic Science Regulator Code, §§92.11.2-92.11.4](https://www.gov.uk/government/publications/forensic-science-activities-statutory-code-of-practice-version-2/forensic-science-activities-statutory-code-of-practice-version-2-accessible)). NIST defines a DNA negative control as a mechanism for detecting contamination introduced by reagents, disposables, or handling errors that could affect samples in the same run ([NIST OSAC Lexicon: Negative Control](https://www.nist.gov/glossary-term/36651)). The regulator also defines environmental monitoring as regular DNA testing used to determine whether cleaning was effective, and defines an “unsourced DNA profile” rather than assuming every contaminant can be attributed ([FSR-GUI-0019](https://www.gov.uk/government/publications/contamination-detection-dna-elimination-samples-fsr-gui-0019/contamination-detection-dna-elimination-samples-accessible)).

The important solved mechanism is therefore not “deduplicate a database.” It is **chain-of-custody metadata + compartmentalization + negative controls + known-source elimination + investigation of unknowns**.

### 1.2 Context management controls when information may influence judgment

Forensic examiners often need contextual information, but some context can bias subjective interpretation. A blanket blindfold is impractical because task-relevant information may be necessary. The field developed several more precise mechanisms:

- A **case-manager model** allows an intake person to see the whole case while giving the examiner only information needed for the analytical task.
- **Linear Sequential Unmasking (LSU)** requires examination and documentation of questioned/trace material before exposure to reference material or potentially suggestive context.
- **LSU-Expanded (LSU-E)** prioritizes information using relevance, objectivity, and biasing power, then records what was seen, when it was seen, and why a conclusion changed.
- **Blind re-examination/verification** gives a second examiner the material without the first examiner's findings or conclusion.

The NIJ project summary identifies the case-manager model, sequential unmasking, and blind re-examination as three practical approaches to contextual bias ([NIJ, *Developing Effective Methods for Addressing Contextual Bias in Forensic Science*](https://www.ojp.gov/library/publications/developing-effective-methods-addressing-contextual-bias-forensic-science)). The original LSU proposal says trace evidence is examined in isolation from reference material, confidence is recorded, and a high-confidence judgment that changes after reference exposure warrants special scrutiny or blind review ([NIJ abstract of Dror et al. 2015](https://nij.ojp.gov/library/publications/letter-editor-context-management-toolbox-linear-sequential-unmasking-lsu)).

The practical LSU-E paper makes the procedure concrete: screen incoming information, evaluate objectivity/relevance/biasing power, document initial analysis before later information, and document and justify revisions after unmasking ([Dror et al. 2022, §§3-4](https://pmc.ncbi.nlm.nih.gov/articles/PMC8866671/)). It also reports an essential limitation: LSU was designed for pattern comparison, addresses bias rather than all sources of noise, and flexible implementations can vary in effectiveness when protocols are underspecified ([Dror et al. 2022, §§3-4](https://pmc.ncbi.nlm.nih.gov/articles/PMC8866671/)).

NIST defines blind verification as a subsequent examiner having no knowledge of another examiner's decisions, conclusions, or supporting observations ([NIST OSAC Lexicon: Blind Verification](https://www.nist.gov/glossary-term/41466)). The UK code goes further operationally: blind checks are required in specified circumstances involving consequential subjective findings, the degree of independence must be recorded, and procedures must define how work is selected and presented for blind checking ([Forensic Science Regulator Code, §§20.2.4-20.2.10](https://www.gov.uk/government/publications/forensic-science-activities-statutory-code-of-practice-version-2/forensic-science-activities-statutory-code-of-practice-version-2-accessible)). NISTIR 8282 distinguishes blinded re-examination from **double-blind re-examination**, where the second examiner is also unaware that an initial examination occurred ([NISTIR 8282, *Report of the NIST Expert Working Group on Human Factors in Forensic Document Examination*](https://nvlpubs.nist.gov/nistpubs/ir/2020/NIST.IR.8282.pdf)).

### 1.3 Proficiency testing uses known truth; blind proficiency testing tests ordinary behaviour

NIST defines proficiency testing as evaluation against pre-established criteria through inter- or intralaboratory comparison ([NIST OSAC Lexicon: Proficiency Testing](https://www.nist.gov/glossary-term/29976)). In a declared test, analysts know they are being evaluated. In a blind test, a known-truth sample enters through the normal intake and analysis pipeline as if it were casework, and the analyst learns it was a test only afterward.

That difference matters. Mejia, Cuellar, and Salyards report that blind tests:

- must resemble real cases;
- can exercise the entire pipeline;
- avoid behaviour changes caused by knowing one is being tested; and
- can expose operational gaps and forms of misconduct that declared tests may not.

They also report studies in drug and blood-lead laboratories where blind and declared tests produced different error rates, and they document real implementation obstacles: realistic test construction, accidental unblinding, cost, safe interception before external release, and the need to prevent test DNA/fingerprints from entering national databases ([Mejia, Cuellar & Salyards 2020, §§1-5](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/)). A separate implementation report describes a laboratory program explicitly designed to test the system from evidence receipt through report release ([Miller et al. 2020, PubMed abstract](https://pubmed.ncbi.nlm.nih.gov/31922611/)).

Blind verification and blind proficiency testing answer different questions:

| Mechanism | Ground truth known? | Main question |
|---|---:|---|
| Blind verification | Usually no | Do two independent assessments agree? |
| Blind proficiency test | Yes | Did the live process reach the correct known result? |
| Double-blind re-examination | Usually no | Does an unaware second assessment corroborate the first without even knowing it is a check? |

Agreement is not accuracy. Mejia et al. explicitly note that blind verification measures consistency when ground truth is unknown, not correctness ([Mejia, Cuellar & Salyards 2020, §2](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/)).

## 2. Structural mapping to agent memory

### 2.1 The mapping that holds

| Forensic-science object | Agent-memory analogue | Shared structure |
|---|---|---|
| Evidence item | Candidate durable memory | An input may be altered, misattributed, or mixed during processing. |
| Chain of custody | Source/provenance envelope | Later users need to know origin, transformations, timestamps, and handlers. |
| Clean/dirty areas | Trusted observation / derived inference / untrusted content compartments | Material with different contamination risk should not silently mix. |
| Negative control | Memory canary that should never be retrieved or promoted | A known-absent signal detects unintended ingress or leakage. |
| Elimination database | Catalogue of known generated boilerplate, test canaries, revoked IDs, and superseded memory IDs | A match can identify a known non-evidentiary source. |
| Environmental monitoring | Periodic retrieval scans and blind cases | Controls must be tested continuously, not assumed effective after installation. |
| Questioned evidence before reference | Current task/evidence assessment before prior conclusion | Later context can anchor an ambiguous judgment. |
| LSU-E unmask order | Retrieve objective constraints and primary-source facts before historical interpretations | Relevant information is staged rather than globally hidden. |
| Blind verification | Independent second pass without the first answer or memory-derived conclusion | Independence is preserved for a high-impact subjective judgment. |
| Blind proficiency sample | Disguised known-truth memory case in ordinary traffic | Tests actual intake, storage, retrieval, supersession, and output interception. |

Both domains have a pipeline in which an input is acquired, labelled, transformed, stored, selected, interpreted, and reported. Errors can arise at every transition. Both also have an observer whose later judgment can be anchored by prior conclusions. That common causal structure—not the surface vocabulary—is why the borrow is usable.

**Transfer confidence:** **very likely (80-90%)** that provenance and compartment boundaries transfer at the mechanism level. Evidence: the forensic controls explicitly combine process history, physical separation, blanks, and source elimination; software memory records have even more readily captured timestamps and identifiers. The expected reduction in this owner’s failure rate remains **UNVERIFIED** until Experiment X121-E1 runs.

### 2.2 The mapping that fails

The analogy fails in at least eight important ways:

1. **DNA contamination is material; memory contamination is semantic.** A matching staff DNA profile is strong source evidence. A phrase match may be quotation, coincidence, paraphrase, or a correct conclusion. Therefore, the elimination catalogue may label provenance, but must not pronounce semantic truth.
2. **A forensic sample is intentionally preserved; memory should often decay or be deleted.** Durable retention is not inherently desirable for credentials, temporary paths, transient task state, or a revoked owner preference.
3. **Agent memory can change the environment it describes.** A remembered instruction may cause the agent to edit the very file or setting that would validate the memory. Revalidation must occur before action when stakes warrant it.
4. **The owner is an authority, not contamination.** A current direct owner instruction must not be masked because it could bias the agent; it defines the task. Historical owner preferences may still become stale or scoped.
5. **Safety and authorization constraints are not optional context.** They must be available before planning. Sequential unmasking must never hide current permission boundaries, security policy, privacy constraints, or destructive-action limits.
6. **The same memory can be correct in one scope and false in another.** “Use pnpm” can be true for one repository and false globally. Source alone is insufficient; scope and applicability are first-class.
7. **Forensic ground truth is manufactured for proficiency tests; real memory truth is often open-ended.** Blind tests can validate known cases and invariants, not certify every remembered proposition.
8. **Repeated blind synthetic cases can train test recognition.** Test diversity and rotation are necessary, and a passing suite cannot be equated with field reliability.

**Adversarial verdict:** **almost certain (90-99%)** that a literal DNA-elimination-database implementation would overclaim what string or embedding similarity establishes. Evidence: forensic elimination works because the compared profile is a source marker under a defined biological assay; semantic memory lacks that identity relation. Therefore this unit rejects “semantic contaminant matching decides truth.”

## 3. Proposed harness changes

Every proposal below rides the existing memory/hook/skill bus and passes the anti-overfit gate. None introduces a second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

### Proposal 1 — Memory Evidence Envelope — **UNVERIFIED (settling experiment: X121-E1 admission/retrieval fault-injection test)** — **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Make every candidate durable memory an append-only envelope rather than an unlabelled sentence. The minimum fields are:

```json
{
  "memory_id": "immutable-id",
  "claim": "The repository uses pnpm.",
  "claim_kind": "observed|owner_instruction|derived|external|test_canary",
  "source": {
    "locator": "path, message id, command id, or URL",
    "captured_at": "RFC3339 timestamp",
    "content_fingerprint": "hash when applicable",
    "quoted_basis": "small decisive excerpt or structured result"
  },
  "scope": ["owner", "workspace/repo", "branch", "task-type"],
  "validity": {
    "state": "active|quarantined|superseded|expired|revoked|test-only",
    "not_before": null,
    "review_after": "RFC3339 timestamp or null",
    "recheck_triggers": ["branch_changed", "dependency_file_changed"],
    "supersedes": [],
    "superseded_by": null
  },
  "sensitivity": "normal|private|secret-never-store",
  "confidence_basis": "direct owner statement / observed file / inference",
  "transform_history": ["captured", "summarized", "owner-confirmed"]
}
```

Admission rules:

1. Do not persist secrets, raw credentials, transient command output, one-off task state, or content whose retention has not been authorized.
2. Store direct observation separately from agent inference. A summary may point to its source envelope but may not replace it.
3. A current owner correction supersedes the old record by ID; do not rewrite history and do not leave both records “active.”
4. A scoped fact must never silently widen scope during summarization.
5. Missing provenance means `quarantined`, not active.
6. Retrieval of `expired` or trigger-invalidated records requires revalidation against the authoritative source before the claim can guide action.
7. User-requested forgetting creates a non-content tombstone sufficient to prevent re-import, then removes the sensitive payload according to the platform’s deletion semantics.

This catches failure classes that an unstructured memory string cannot make mechanically visible:

- a conclusion copied from an earlier agent answer with no primary basis;
- a repository-local convention applied globally;
- an old preference remaining active after an owner correction;
- a fact surviving a dependency or branch change that invalidates it;
- a secret or test canary being promoted to ordinary durable memory;
- a summary that drops uncertainty or source scope.

**Expected effect:** **very likely (80-90%)** that the envelope makes provenance loss, supersession failures, and scope widening detectable as schema/policy violations. Evidence: forensic contamination systems make sources, blanks, environmental profiles, and retention/investigation rules explicit; the owner-specific incidence is **UNVERIFIED** until X121-E1 injects those faults through the actual memory bus.

**Implementation restraint:** use the existing memory store’s metadata capability or an adjacent flat JSON/JSONL record. Do not add embeddings, a graph, or a new database merely to implement these fields. If the existing memory substrate cannot store metadata, the first experiment should use a sidecar keyed by `memory_id`, not replace the substrate.

### Proposal 2 — Three-zone memory handling with negative controls — **UNVERIFIED (settling experiment: X121-E1 fault injection plus canary non-retrieval test)** — **NATIVE-vs-BUILD: CONFIG (settings/JSON only)**

Define three logical zones through record state and policy, not new infrastructure:

- **Evidence zone:** direct owner instructions, primary-source observations, and records with complete provenance.
- **Interpretation zone:** agent summaries, hypotheses, inferred preferences, and compressed lessons. These remain explicitly derived and link to evidence records.
- **Quarantine/test zone:** missing-source imports, conflicting claims, revoked/superseded records, and proficiency canaries.

Add two controls:

1. A **blank canary** is a unique, harmless token in a record marked `test-only` and scoped so ordinary retrieval must never return it. Its appearance in normal context or output is a contamination signal.
2. A **known-source catalogue** contains exact IDs/fingerprints for canaries, generated boilerplate, revoked imports, and superseded records. It can answer “where did this come from?” It must not answer “is this proposition true?”

A detector is not accepted merely because it reports zero leaks. It must first retrieve a deliberately known-present control from the quarantine/test zone, then demonstrate non-retrieval of the blank canary through the normal production query path. Those are mechanically independent signals: positive detector capability and negative live-path behaviour.

**Expected effect:** **likely (55-80%)** that zones plus blanks expose cross-zone retrieval and accidental test-memory promotion. Evidence: negative controls detect assay contamination and elimination databases attribute known contaminant sources; the semantic-policy implementation is **UNVERIFIED** until the positive control and ordinary-query canary test both run.

### Proposal 3 — Sequential memory unmasking for subjective decisions — **UNVERIFIED (settling experiment: X121-E2 randomized stale-anchor trial)** — **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Apply staged retrieval only to tasks containing a consequential subjective judgment, such as diagnosis, architecture choice, incident cause, or review verdict. Do not apply it to simple preference recall, explicit owner instructions, safety controls, authorization, or purely factual lookup.

The sequence is:

1. **Always-visible control context:** current owner request, authorization boundary, safety/privacy policy, workspace identity, and task scope.
2. **Independent first record:** the agent states the question, current observable evidence, initial hypotheses, and uncertainty without historical agent conclusions. This is a compact internal worksheet, not a user-facing extra essay.
3. **Objective memory:** reveal direct owner instructions and primary-source observations relevant to the task, ordered by scope match and freshness.
4. **Derived memory:** reveal summaries, prior diagnoses, earlier architectural preferences, and other potentially anchoring interpretations.
5. **Revision record:** if the conclusion changes, record which memory changed it and whether that record was revalidated. High-confidence reversals triggered only by derived memory are flagged for source checking.
6. **Selective blind verification:** for a high-impact, subjective conclusion, run a second pass that sees the task, current evidence, and objective memory but not the first conclusion or derived historical conclusion. Reveal the first conclusion only after the second pass commits its result.

The gate should be sparse. A task qualifies only when both are true:

- the decision is subjective or evidence is ambiguous; and
- an error would cause a material action, durable memory update, or consequential recommendation.

**Expected effect:** **likely (55-80%)** that staging reduces stale-memory anchoring without materially impairing routine personalization. Evidence: LSU-E reports that order and biasing power matter and recommends independent analysis before reference/context exposure; transfer to LLM agents and latency cost are **UNVERIFIED** until X121-E2 compares staged and ordinary retrieval on the same randomized tasks.

**Why not always blind?** It is **very likely (80-90%)** that always-on masking would harm task performance because some memories are constitutive instructions or necessary technical facts, not optional context. Evidence: LSU-E itself ranks information by relevance and sequences access rather than banning all context ([Dror et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC8866671/)).

**Why not routinely double-blind?** A second model invocation unaware that any prior assessment exists can be useful for rare, high-impact reviews, but making it universal would duplicate cost and still would not provide truth when both passes share the same model and evidence. It is **unlikely (20-45%)** that universal double-blind re-examination provides enough incremental value over selective blind verification plus known-truth tests to justify its cost. Evidence: forensic sources distinguish agreement checks from known-truth proficiency and warn that blind verification measures consistency, not accuracy ([NISTIR 8282](https://nvlpubs.nist.gov/nistpubs/ir/2020/NIST.IR.8282.pdf); [Mejia et al. 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/)). The harness-specific cost-benefit remains **UNVERIFIED** until a selective double-blind arm is included in X121-E2.

### Proposal 4 — Retrieval-time staleness and forgetting policy — **UNVERIFIED (settling experiment: X121-E1 temporal/supersession matrix)** — **NATIVE-vs-BUILD: CONFIG (settings/JSON only)**

Do not assign one universal time-to-live. Freshness depends on claim type and invalidation events:

| Memory kind | Default treatment | Revalidation trigger | Forget/delete treatment |
|---|---|---|---|
| Explicit stable owner preference | Active until corrected; periodically reconfirm only when material | contradictory current instruction; scope mismatch | delete on owner request; preserve only non-content anti-reimport tombstone if permitted |
| Authorization or permission | Session/task scoped unless explicitly durable | every new task; scope/target change | expire automatically |
| Repository fact | Active only in recorded repo/branch scope | branch change; relevant file fingerprint change; failed source lookup | quarantine after source disappearance, then age out |
| Tool/API capability | Short review interval | version/config/plugin change; invocation failure | supersede old capability record after verification |
| External fact | Review interval based on volatility | retrieval for consequential use; newer authoritative source | retain historical value only when history matters |
| Prior diagnosis or plan | Derived, not authoritative | new evidence; environment change; elapsed task boundary | expire from active retrieval after task completion unless promoted with evidence |
| Secret | Never store | n/a | immediate removal if accidentally captured, plus incident handling |
| Correction | New record supersedes named old ID | every retrieval of either ID | retain audit metadata without retaining forbidden payload |

“Expired” should mean **not eligible to guide action without revalidation**, not immediate erasure. “Revoked” should mean **must not be used**. “Superseded” should mean **historically retained but inactive**. “Delete/forget” should be reserved for owner request, privacy/retention requirements, secrets, test cleanup, or content with no continuing legitimate purpose.

Staleness detection order:

1. check explicit state (`revoked`, `superseded`, `expired`);
2. check scope identity;
3. check event triggers and content fingerprint;
4. for material actions, re-read the authoritative source;
5. if the source is unavailable, quarantine rather than silently refreshing the timestamp;
6. log the independent source result that reactivated the memory.

**Expected effect:** **very likely (80-90%)** that event-based invalidation catches stale repository/tool facts earlier than age-only expiry. Evidence: these facts change when identifiable dependencies change; the relative gain and correct default intervals are **UNVERIFIED** until X121-E1 varies file, branch, version, source availability, and elapsed time independently.

### Proposal 5 — Blind Memory Proficiency Suite — **UNVERIFIED (settling experiment: X121-E3 disguised end-to-end proficiency pilot)** — **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Build a small test-case scheduler on the existing hook bus. A test controller marks cases in metadata invisible to the working agent, submits them through the ordinary memory admission/retrieval path, intercepts them before any external side effect or durable production write, and scores deterministic invariants.

Initial case families:

1. **Supersession:** store `preference=A`, then a current owner-shaped correction `preference=B`; expected result is B with A inactive.
2. **Scope trap:** store a convention for repository R1, query in R2; expected result is non-retrieval or explicit scope warning.
3. **Expired fact:** store a time-sensitive tool capability beyond `review_after`; expected result is revalidation or quarantine, never unqualified use.
4. **Dependency change:** change the fingerprint of the authoritative file; expected result is invalidation before action.
5. **Derived-as-evidence trap:** store an agent summary without source; expected result is quarantine and no promotion.
6. **Conflict:** present two authoritative-looking but incompatible records; expected result is surfaced conflict, not silent merge.
7. **Blank leakage:** plant a test-only canary; expected result is no ordinary retrieval and no user-visible emission.
8. **Forgetting:** revoke/delete a test record; expected result is absent payload plus a functional anti-reimport control where policy permits.
9. **Stale anchor:** plant an attractive obsolete diagnosis before ambiguous current evidence; expected result is independent assessment and explicit revision if later unmasked memory changes it.
10. **Secret admission:** present a synthetic credential-shaped value; expected result is refusal to persist and safe redaction in logs.

The controller knows ground truth; the working agent does not know which case is a test. A deterministic scorer should also not see the agent's hidden reasoning—only the structured retrieval/admission events and final observable decision. Human test administrators need not be double-blind when the scorer is mechanical and expected outcomes are precommitted. For subjective cases, randomize labels and have an evaluator unaware of condition score a predeclared rubric.

Safety controls:

- synthetic identities, repositories, and secrets only;
- a hard test namespace and `test-only` state;
- interception before network messages, commits, config writes, or user-facing output;
- automatic cleanup verified by both store enumeration and failed retrieval;
- a known-present control proving the cleanup detector can see a planted record;
- low test frequency and rotating surface forms so the agent cannot trivially identify test cases;
- no punitive per-case use; aggregate failures by pipeline stage.

Metrics:

- stale-use rate;
- wrong-scope retrieval rate;
- superseded-memory use rate;
- provenance-loss admission rate;
- blank-canary leakage rate;
- conflict-suppression rate;
- secret-persistence rate;
- revalidation success/fail-closed rate;
- test discovery rate;
- latency and token overhead;
- stage attribution: intake, storage, retrieval, reasoning, output, or cleanup.

A blind test pass is not proof that the memory system is correct. Test cases must resemble actual memory traffic, and easy or recognizable tests overestimate performance. This limitation directly mirrors forensic proficiency-test concerns that declared tests change examiner behaviour and that test material can be unrepresentative ([Mejia et al. 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/); [Kukucka et al. 2023](https://pubmed.ncbi.nlm.nih.gov/36870700/)).

**Expected effect:** **very likely (80-90%)** that blind tests reveal at least some failures hidden by declared unit tests if the production memory path differs from the test path or the agent behaves differently when warned. Evidence: blind forensic tests exercise ordinary workflow and empirical studies found differences from declared tests; the presence and size of that gap in this harness are **UNVERIFIED** until X121-E3 runs.

## 4. Experiments that settle the unverified premises

### X121-E1 — Admission, contamination, staleness, and forgetting matrix

**Question:** Does the envelope/policy detect bad provenance, wrong scope, supersession, changed dependencies, and forbidden retention without suppressing valid memory?

**Design:** Construct at least 100 synthetic memory events balanced across valid and invalid cases. Cross claim kind, scope, provenance completeness, state, age, source availability, dependency fingerprint, and sensitivity. Precommit expected admission/retrieval state. Run through the real memory API, not a test-only parser.

**Independent signals per claimed failure or success:**

1. the externally observed retrieval/action result; and
2. the store/audit transition showing the expected state and source check.

Before accepting any “zero leak” result, prove the detector finds a known-present canary in the same storage layer. Before claiming deletion, prove both payload absence by enumeration and retrieval failure through the normal query path; these are mechanically different fields/paths.

**Decision threshold:** adopt the schema only if it materially reduces injected stale/scope/provenance errors with no more than a predeclared false-quarantine budget. Exact thresholds should be set from baseline prevalence; choosing them now without baseline data would be false precision.

### X121-E2 — Randomized sequential-unmasking trial

**Question:** Does staged retrieval reduce anchoring on stale derived memory, and at what cost?

**Design:** Build matched ambiguous tasks with current primary evidence and a prior-memory conclusion. Randomize tasks among: no historical memory, all memory at once, staged objective-then-derived memory, blind second pass, and double-blind second pass. Independently randomize whether the prior conclusion is correct, stale, or irrelevant. Score against constructed ground truth where possible and a blinded rubric otherwise.

**Primary outcomes:** error against ground truth, unjustified adherence to stale conclusion, justified revision rate, source revalidation rate, latency, and tokens. Separately measure failure to apply a valid current owner preference; this guards against over-masking.

**Decision threshold:** enable staging only for task categories where the confidence interval shows a useful error reduction without an unacceptable loss of instruction adherence or latency. A global rollout from a pooled average would overfit heterogeneous tasks.

### X121-E3 — Disguised end-to-end memory proficiency pilot

**Question:** Does the live harness behave differently on declared versus disguised memory tests, and where do failures occur?

**Design:** Run paired declared and disguised cases from Proposal 5 through ordinary hooks. Keep the working agent blind to condition. Intercept all side effects. Rotate case phrasing and timing. Pre-register expected structured outcomes and score mechanically.

**Validity checks:** measure whether the agent guessed test status; compare test feature distributions with sampled ordinary memory events; report each pipeline stage separately. A realistic-looking test that bypasses actual admission or retrieval is invalid.

**Decision threshold:** retain blind testing if it finds failures not found by declared tests, or provides materially different rate estimates, at acceptable operational risk. If declared and blind outcomes are equivalent within a predeclared bound and the path is demonstrably identical, prefer the simpler declared suite.

## 6. Anti-overfit gate and rejected alternatives

### Accepted architecture

The accepted architecture is intentionally small:

```text
existing memory intake
    -> envelope/state policy
    -> existing store
    -> staged retrieval only when gated
    -> ordinary agent work
    -> revision/source-check event

existing hook bus
    -> occasional synthetic blind case
    -> side-effect interceptor
    -> deterministic scorer
```

It adds metadata, a few state transitions, a task gate, and a test hook. It does not replace the owner’s harness or create a competing scheduler.

### Rejected: vector database or knowledge graph for provenance

**Decision:** reject. Exact identifiers, source locators, state, and fingerprints solve the proposed provenance problem. Semantic retrieval may already exist, but it is not required by this design. A new vector/graph layer would add synchronization and deletion semantics without making truth decidable.

**Confidence:** **almost certain (90-99%)** that a new vector DB/KG is unnecessary for the minimum experiment. Evidence: every acceptance criterion above is expressible through keyed metadata and ordinary retrieval; no criterion requires graph traversal or nearest-neighbour search.

### Rejected: always-on second agent or trained critic

**Decision:** reject. Blind verification is useful selectively, but agreement between two correlated model passes is not ground truth. Known-truth proficiency cases provide a stronger test for the failure classes in scope.

**Confidence:** **very likely (80-90%)** that selective blind passes plus deterministic known-truth tests offer a better complexity/assurance tradeoff than an always-on critic. Evidence: forensic sources explicitly distinguish verification consistency from proficiency accuracy; the harness-specific economics remain **UNVERIFIED** until X121-E2 measures cost and incremental errors found.

### Rejected: universal fixed TTL

**Decision:** reject. A credential should never be stored, a task plan should expire quickly, an explicit stable preference may remain until corrected, and a repository fact should invalidate on a branch/file event. One TTL cannot express those distinct semantics.

**Confidence:** **almost certain (90-99%)** that one global TTL is structurally inadequate because the counterexamples have incompatible required retention behaviour.

### Rejected: contamination score from phrase/embedding similarity

**Decision:** reject as a truth mechanism. Similarity can support investigation or source attribution but cannot establish falsity, staleness, or unauthorized origin.

**Confidence:** **almost certain (90-99%)** that semantic similarity alone cannot support those conclusions; this follows from the existence of true paraphrases, false paraphrases, quotations, and coincidentally similar claims.

### Rejected: masking owner intent and safety policy

**Decision:** reject categorically. The goal of sequential unmasking is to protect an evidentiary judgment from irrelevant or prematurely suggestive context, not to withhold the task definition or operational boundary.

**Confidence:** **almost certain (90-99%)** that masking current authorization or safety constraints creates unacceptable risk because those constraints define which actions are permissible before any analysis begins.

## 7. Failure modes of the proposed borrow

Even the accepted narrow borrow can fail:

1. **Metadata theatre:** envelopes are populated with vague sources or copied timestamps, creating the appearance of provenance without evidence.
2. **Quarantine accumulation:** ambiguous records are never resolved or deleted, and retrieval pressure eventually encourages bypasses.
3. **Unmasking leakage:** the first-pass context indirectly contains the old conclusion through summaries, tool output, filenames, or task wording.
4. **Shared-model correlation:** a blind second pass is independent in information exposure but not independent in training, model biases, or tool environment.
5. **Canary overfitting:** fixed synthetic tokens become recognizable and the system learns to suppress tests rather than control contamination.
6. **Unsafe test escape:** a proficiency case reaches a real external system or durable production memory.
7. **False source authority:** a fresh authoritative source can still be wrong; freshness and provenance are not truth guarantees.
8. **Deletion ambiguity:** tombstones useful for preventing re-import can themselves conflict with a strict request to erase all traces. Policy must distinguish payload deletion from minimal compliance/audit metadata and follow the owner/platform requirement.
9. **Over-masking personalization:** delaying stable owner preferences can make the agent less useful without improving epistemic quality.
10. **Metric gaming:** aggregate pass rates can conceal a severe but rare leakage or secret-retention failure. Report safety-critical classes separately.

**Residual-risk assessment:** **likely (55-80%)** that at least one of metadata theatre, unmasking leakage, or recognizable canaries appears in an initial implementation. Evidence: LSU-E reports implementation variance when procedures are flexible, while blind proficiency literature documents realistic-submission and accidental-unblinding difficulties ([Dror et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC8866671/); [Mejia et al. 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7552087/)).

## 9. Bottom line

Forensic science contributes a useful answer to the memory problem, but it is not “store more evidence forever.” Its deeper answer is:

- preserve provenance;
- prevent risky sources from silently mixing;
- use known-absent controls to reveal leakage;
- expose context in an order that protects independent observation;
- distinguish independent agreement from known-truth accuracy;
- test the full ordinary pipeline with disguised, realistic cases; and
- investigate unknown contamination rather than forcing attribution.

Translated to an agent harness, that becomes a small evidence envelope, explicit lifecycle states, event-triggered revalidation, selective sequential unmasking, and blind known-truth memory cases. The analogy does **not** justify semantic contaminant matching, universal blinding, indefinite retention, a new memory database, or an always-on critic.

The highest-value first move is X121-E1 followed by X121-E3. **Very likely (80-90%)**, if the current memory path has provenance, scope, supersession, or test-path gaps, those experiments expose them with less architectural risk than replacing the memory runtime.
