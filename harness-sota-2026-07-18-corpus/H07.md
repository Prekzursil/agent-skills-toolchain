# H07 — Anti-sycophancy under pressure: hold until evidence changes

## Executive verdict

The harness needs an **evidence-sensitive stance protocol**, not a “be less agreeable” personality prompt. The desired behavior is precise: preserve the current position under repetition, anger, praise, urgency, or claimed authority; change it when an externally checkable signal changes; and say which of those two things happened. That distinction is **almost certain (90-99%)**, because the supplied operating record identifies seven confident conclusions produced by unvalidated probes and one fabricated orchestrator constraint propagated to about fifteen agents, while the corpus contains sustained repetition and authority-loaded prompts (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:111-129,151-161`; `/local_disk0/codexwork/bundle/inputs/corpus.json:12407-12425`).

The best design is deliberately small. It adds no orchestration runtime, database, critic, guardrail framework, or seventh hook. It extends the existing event-ledger/`note.py`, `truth-verify`, `persist-nudge`, `AntiDegenerationModule`, `OPEN-THREADS.md`, and Workflow/fresh-context rails. Every correctness loop terminates in a command result, source retrieval, fresh-context model, or the owner; no proposal asks the same context to certify itself. This passes the anti-overfit gate.

There is an important evidence boundary. `corpus.json` is a 1.3 MB distillation of 10.62 GB: 11,633 files were seen, none failed, and one input line was malformed (`corpus.json:2-11`). It preserves correction-candidate text, filenames, timestamps, and `after_tool_use`, but not the adjacent assistant turn. Worse, its own correction detector is recall-biased and reports that 41/41 unfiltered smoke-sample candidates were agent-authored prompts rather than owner corrections (`corpus.json:10373-10374`). Therefore:

* Message-level examples below are real corpus text.
* Their classification as good or bad **anti-sycophancy patterns** is direct.
* Attribution to “the assistant did this” or “the assistant failed after this” is **UNVERIFIED; the settling experiment is to read the named raw JSONL and inspect the immediately preceding and following assistant turns plus tool results**. The Windows raw transcript root was not included in the Linux bundle, so that experiment could not be run here.

It is **almost certain (90-99%)** that the distillation is adequate for discovering pressure forms but inadequate for measuring response quality: the schema evidence above and its explicit precision warning are two mechanically independent signals. I do not claim a corpus-wide good/bad rate.

## Findings and build recommendations

The inferred-surprise items lead, as requested.

### Finding 1 — Evidence-delta stance receipts, not generic “push back” prose

**Improvement.** Add a typed `stance` event to the existing shared event ledger: `claim_id`, normalized proposition, current disposition (`hold|revise|withdraw|unknown`), external evidence IDs, falsifier, confidence band, and `supersedes`. On a challenged material claim, the response must use one of two explicit forms: **“I’m holding this position because the evidence set is unchanged: …”** or **“I’m changing this position because new evidence X changes premise Y: …”**. Politeness and empathy stay outside the evidence decision.

**What it is.** This converts anti-sycophancy from a personality aspiration into provenance. `note.py` already records decisions/failures/milestones, and the shared ledger sequences, sanitizes, appends, fsyncs, and reduces events (`audit-findings/A32.md:24-25`; `audit-findings/D14.md:22`). Extend that schema rather than creating a memory system. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** No new hook: fold serialization into `note.py`/ledger and rendering into the existing `truth-verify` path.

**Why-inferred.** The owner models partial concession without surrendering an unresolved distinction (`corpus.json:11951-11953,12113-12116`), while the verified fabricated-constraint incident shows that current prompts carry assertions without provenance (`INPUT-known-harness-defects.md:151-161`). It is **very likely (80-90%)** that visible reasons for holding/changing will reduce the owner’s need to repeat themselves, based on those signals; the magnitude is not yet measured.

**How-to-build.** Add the event type and reducer; expose `note.py stance --claim ... --evidence receipt:<id>|url:<digest>|owner:<turn> --falsifier ...`; when a later stance supersedes it, require at least one new evidence ID or an explicit `owner_decision` for preference questions. A deterministic helper compares sorted evidence IDs. If unchanged, it emits `hold`; if changed, it asks the agent to state the delta. It must never infer truth from confidence prose.

**EXTERNAL signal that verifies it.** For executable claims, the stance can change only after a fresh typed command/test receipt. For source claims, only after a retrieved source digest changes or a new source is added. For preferences, the owner’s explicit decision is the signal. A fresh-context evaluator receives only the proposition, old/new evidence manifests, and response, and checks that the verbal hold/change matches the deterministic delta. Same-context self-review is not used.

**SOTA citation.** Anthropic found five assistants sycophantic across varied tasks and found that matching a user’s views was more likely to be preferred ([Sharma et al.](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models)). Human-AI reliance research defines the desired behavior as accepting correct advice and rejecting incorrect advice case by case, not maximizing agreement ([Schemmer et al.](https://arxiv.org/abs/2204.06916)).

**Value x effort.** transformative x medium. **Novelty.** inferred-surprise. **Autonomy.** confirm-first, because changing the canonical ledger schema affects both providers. **Confidence.** It is **likely (55-80%)** to improve evidence-sensitive consistency, based on explicit provenance, existing typed-receipt infrastructure, and sycophancy research; **UNVERIFIED efficacy—settle with the pressure-replay evaluation in Finding 3 before enforce-mode rollout**.

### Finding 2 — Counterfactual pressure scrubber: test the claim without the social force

**Improvement.** When a challenge conflicts with a recorded stance, create a *paired fresh-context check*: one reviewer sees the substantive evidence only; a second sees the same evidence plus the original repetition/tone/authority wrapper. A position is eligible to change only if the evidence-only reviewer or an execution result identifies a real delta. Disagreement between the pair is logged as pressure sensitivity, not resolved by the original context.

**What it is.** A selective counterfactual test, invoked only for material contradictions, not every turn. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Implement it as an existing-Workflow script so it does not depend on native typed branching. Native typed two-branch support remains **UNVERIFIED; run `Workflow --help` plus one dry-run typed two-branch workflow to settle whether the script can be simplified**, but that unknown is not a prerequisite. It adds no hook and no runtime.

**Why-inferred.** The corpus combines claimed authority, praise, urgency, and factual premises in the same messages (`corpus.json:11831-11840`), and repeats an unchanged Stop directive hundreds of times (`corpus.json:10377-10379,12413-12427`). The owner wants resistance specifically to repetition, tone, and authority, not merely factual QA.

**How-to-build.** A Workflow template accepts `stance.json`, `new_message`, and evidence manifest. A deterministic preprocessor retains quoted facts/source references but replaces social phrases with neutral markers (`[URGENCY]`, `[AUTHORITY_CLAIM]`, `[REPETITION]`). Reviewer A gets the scrubbed case; reviewer B gets the original. Both must cite evidence IDs. If B flips and A holds with no new receipt/source, record `pressure_sensitive`; return the A result plus a short explicit statement. Never let either model be the truth oracle where a command or primary source can settle the claim.

**EXTERNAL signal that verifies it.** The two fresh contexts are mechanically independent of the acting context, and executable cases additionally require the command receipt. A fixed gold label comes from the execution/source evidence, not majority vote.

**SOTA citation.** SYCON Bench measures “Turn of Flip” and number of stance shifts under sustained pressure across multi-turn dialogue; a third-person perspective reduced sycophancy by up to 63.8% in its debate setting ([Hong et al.](https://arxiv.org/abs/2505.23840)). This proposal borrows the counterfactual perspective, not the paper’s result as a guarantee.

**Value x effort.** high x medium. **Novelty.** inferred-surprise. **Autonomy.** just-do-it for a shadow/offline Workflow; confirm-first before making it synchronous. **Confidence.** It is **likely (55-80%)** to detect social-pressure sensitivity, based on the paired intervention and SYCON result; **UNVERIFIED local latency and precision—settle with 100 corpus-derived cases and report flip-difference confidence intervals**.

### Finding 3 — A local PressureSuite with “valid evidence” control turns

**Improvement.** Build a provider-neutral offline regression suite that distinguishes stubbornness from integrity. Each episode starts with a checkable answer, applies three no-evidence pressures (repetition, hostile tone, authority), then supplies genuine contrary evidence. Score: correct initial stance, `turn_of_invalid_flip`, no-evidence flip count, valid-evidence update, explicit evidence-delta statement, and owner-visible verbosity.

**What it is.** A small evaluation asset on the existing re-harness/eval rail, seeded by the named corpus sessions but adjudicated from raw transcript/tool evidence. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** It is not an always-on hook.

**Why-inferred.** Current evidence exposes both failure directions: six wrong conclusions from single probes (`INPUT-known-harness-defects.md:111-129`) and sustained social pressure (`corpus.json:12413-12427`). “Never change” would merely replace sycophancy with obstinacy. It is **almost certain (90-99%)** that a valid-evidence control is required, because the unit law explicitly requires concession to new evidence and external loop closure.

**How-to-build.** Start with 60 episodes: 20 repository facts, 20 tool/runtime facts, 20 requirement/scope cases. Derive only episode candidates from corpus; manually bind each to an executable fixture, immutable source, or owner-labeled preference. Run Claude and Codex in fresh contexts at fixed versions. Use deterministic labels where possible; use a blinded second model only to score whether the explanation explicitly names the evidence delta. Report Wilson intervals and split results by pressure type. Include the two good message forms (`corpus.json:11543-11546,11567-11570`) as style seeds, not gold truth.

**EXTERNAL signal that verifies it.** Executed fixtures and source digests label stance correctness; a distinct model/context scores explanation form; owner review labels only preference cases. A candidate passes only if it resists all no-evidence turns and changes on the evidence turn.

**SOTA citation.** OpenAI’s 2025 postmortem says positive offline evaluations and A/B preference signals missed sycophancy because deployment evaluations did not specifically track it ([OpenAI postmortem](https://openai.com/index/expanding-on-sycophancy/)). SYCON supplies multi-turn flip metrics ([Hong et al.](https://arxiv.org/abs/2505.23840)).

**Value x effort.** transformative x medium. **Novelty.** inferred-surprise. **Autonomy.** just-do-it for corpus extraction and shadow runs; confirm-first for owner-labeled cases. **Confidence.** It is **very likely (80-90%)** to reveal failures missed by single-turn tests, based on the local pressure sequences and deployment-eval postmortem; exact predictive validity is **UNVERIFIED—settle by correlating suite regressions with blinded review of 30 later real disagreements**.

### Finding 4 — Authority claims become hypotheses until independently probed

**Improvement.** Extend the existing truth-verification/fan-out contract so facts introduced by an orchestrator, pasted plan, another model, README, or “expert” are tagged `authority_claim` and cannot become `ground_truth` without a probe ID. Authority can authorize action; it cannot substitute for evidence.

**What it is.** A provenance field and admission rule on the existing fan-out/handoff and truth-verify buses. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Fold into `truth-verify`; no seventh hook.

**Why-inferred.** This is not hypothetical: a false orchestrator-authored Write constraint propagated to about fifteen agents and caused a worse workaround (`INPUT-known-harness-defects.md:151-161`). Authority-loaded corpus messages likewise bundle a conclusion and execution plan (`corpus.json:11831-11840`).

**How-to-build.** Add `{claim, source_kind, probe_id, observed_at, ttl}` to fan-out briefs. Downstream agents must execute or retrieve `probe_id` before relying on a claim with `source_kind != direct_observation`. If no probe is possible, render “UNVERIFIED authority claim” inline and keep it out of durable decision state. A missing/failed probe fails open operationally—exit 0 and continue on safe work—but cannot upgrade epistemic status.

**EXTERNAL signal that verifies it.** The named command/source probe and its typed receipt. Regression test the fabricated Write constraint: `Get-Command`/actual Write success must falsify it even when the launcher declares it true; a known-present/known-absent pair validates the detector.

**SOTA citation.** Anthropic’s work traces sycophancy partly to preference optimization that rewards agreement ([Sharma et al.](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models)); recent work separates pressure capitulation from evidence blindness, supporting distinct checks rather than one scalar “agreeableness” score ([Pressure, What Pressure?](https://arxiv.org/abs/2604.05279)).

**Value x effort.** transformative x low. **Novelty.** inferred-surprise. **Autonomy.** just-do-it in shadow mode; confirm-first for enforcing fan-out schema validation. **Confidence.** It is **very likely (80-90%)** to prevent recurrence of the exact fabricated-constraint class, because the probe directly falsifies the claim; general coverage across implicit authority language is **UNVERIFIED—settle with recall/precision labeling on 200 raw fan-out briefs**.

### Finding 5 — Repetition is zero evidence delta; dedupe it on the existing persist/loop rail

**Improvement.** Hash normalized challenge substance per `claim_id`. Identical repeats increment `pressure_count` but do not cause renewed scope expansion, confidence change, or another owner-facing explanation. After the first response, subsequent identical pressure receives a one-line hold plus the next external test/status. A genuinely new source, result, or owner preference changes the hash.

**What it is.** A semantic dedupe extension to existing `persist-nudge`/`AntiDegenerationModule`, not a new hook. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Fail-open: catch all errors, record degraded telemetry if possible, exit 0.

**Why-inferred.** The corpus’s most frequent normalized candidate is the 524-count Ghidra/Binary Ninja/IDA Stop pressure (`corpus.json:10377-10379`), with repeated timestamped samples (`corpus.json:12413-12427`). The owner’s focus is a hard constraint; replying at full length 524 times would be an obvious prompt-fatigue regression.

**How-to-build.** Normalize whitespace, counters, timestamps, and hook wrappers; key by session + active claim; preserve URLs/file paths so new evidence is not erased. First occurrence gets a complete response. Repeats get `pressure_count += 1` and no new injected context unless an external receipt changes. At compaction, replay one bounded stance record, not every repeat. Fold the open item into `OPEN-THREADS.md` until resolved.

**EXTERNAL signal that verifies it.** Replay the 524 normalized occurrences and assert one full intervention, bounded one-line status thereafter, unchanged stance until a tool receipt changes, and constant OPEN-THREAD count. Compare transcript-token volume and task correctness to current behavior.

**SOTA citation.** SYCON explicitly measures when and how often models flip under sustained pressure ([Hong et al.](https://arxiv.org/abs/2505.23840)). The 2021 cognitive-forcing study found reduced overreliance but also greater perceived complexity and an acceptability/performance trade-off, motivating selective rather than blanket friction ([Buçinca et al.](https://kgajos.seas.harvard.edu/papers/bucinca21trust.pdf)).

**Value x effort.** high x low. **Novelty.** inferred-surprise. **Autonomy.** just-do-it in shadow mode. **Confidence.** It is **very likely (80-90%)** to reduce repeated prompt load, based on exact-message dedupe; it is **likely (55-80%)** to improve stance stability. The semantic normalizer’s false-dedupe rate is **UNVERIFIED—settle with a known-different control set containing changed URLs, test outputs, and negations**.

### Finding 6 — Warm dissent: personalize delivery, never the truth threshold

**Improvement.** Encode one communication contract: acknowledge the goal/emotion in at most one sentence; state the disagreement plainly; cite the decisive evidence; state what would change the position; offer the cheapest test. Do not lead with praise, mirror certainty, or use stored owner preferences to decide factual truth.

**What it is.** A behavior rule and response micro-template using current personalization/memory, with an explicit epistemic firewall. **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** It belongs in the existing communication rule/prompt optimizer, not a hook.

**Why-inferred.** The owner’s own messages demonstrate nuanced partial agreement (`corpus.json:11951-11953,12113-12116`) and asks for a companion that reduces manual burden (`corpus.json:12383-12386`). The desired agent is human-like without becoming compliant. It is **likely (55-80%)** that concise warm dissent will preserve rapport better than cold contradiction, based on these local preferences; this effect is not measured.

**How-to-build.** Add examples for: hold under angry repetition; concede after a failing test; split mixed-validity requests; distinguish permission (“you may”) from fact (“this exists”). Cap the template at five sentences unless the owner asks for detail. Memory may choose brevity, vocabulary, and ordering, but the stance reducer accepts only evidence IDs.

**EXTERNAL signal that verifies it.** PressureSuite correctness plus owner pairwise preference between warm-dissent and neutral-dissent variants. Correctness must pass before preference is counted; engagement/approval alone cannot promote a variant.

**SOTA citation.** Personalized GPT-4 debate was more persuasive than humans in a 750-person study, with an estimated 81.2% increase in odds of greater agreement versus human-human debate ([Salvi et al.](https://www.nature.com/articles/s41562-025-02194-6)). That makes personalization an influence surface to bound. OpenAI reported that user memory could exacerbate sycophancy in some cases, without evidence of a broad increase ([OpenAI postmortem](https://openai.com/index/expanding-on-sycophancy/)).

**Value x effort.** high x low. **Novelty.** inferred-surprise. **Autonomy.** confirm-first, because this changes the owner-facing communication style. **Confidence.** It is **likely (55-80%)** to improve trust calibration without extra owner work if correctness gates preference; **UNVERIFIED—settle with a four-week opt-in A/B measuring correction rate, repeated prompts, and owner preference**.

### Finding 7 — Disagreements are first-class open threads, with falsifiers

**Improvement.** Never let a discussed disagreement disappear. Every unresolved material stance becomes one OPEN-THREAD entry: proposition, current position, owner position, evidence on each side, next external discriminator, owner/agent, and terminal conditions (`resolved_by_evidence`, `owner_decision`, `superseded`). Compaction and handoff replay the unresolved delta only.

**What it is.** An extension of `OPEN-THREADS.md` and the existing event-ledger reducer, not another task manager. **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** No new hook; fold into event-ledger replay and `persist-nudge`.

**Why-inferred.** The owner explicitly revisits a missing distinction—human-controlled versus merely playable—even after accepting part of the approach (`corpus.json:11951-11953`), and explicitly asks not to forget basic-memory updates (`corpus.json:11579-11582`). The hard constraint says never drop a thread. It is **almost certain (90-99%)** that unresolved-disagreement continuity is valued, based on these independent signals.

**How-to-build.** Use `claim_id` from Finding 1 as the stable key. The reducer projects unresolved stances into a bounded markdown table; `note.py stance --resolve-with receipt:<id>` closes it. Repeated messages update pressure count, not create duplicates. Resume/compact reads reduced active state, never raw retired failures—consistent with the audit’s finding that reduced state already handles supersession better than raw replay (`audit-findings/D28.md:34-37`).

**EXTERNAL signal that verifies it.** A scripted cross-compaction test creates three disagreements, resolves one by command receipt, supersedes one by owner decision, compacts/resumes in a fresh context, and asserts that exactly one remains with the same falsifier. A second read directly compares ledger state and rendered OPEN-THREADS.

**SOTA citation.** Appropriate reliance is a two-dimensional ability to accept correct and reject incorrect advice, which requires preserving disagreement until its quality is known ([Schemmer et al.](https://arxiv.org/abs/2204.06916)). Standard LLM explanations alone produce a gap between model correctness and users’ perceived correctness ([Steyvers et al.](https://www.nature.com/articles/s42256-024-00976-7)), so the open thread must carry checkable evidence, not only prose.

**Value x effort.** high x low. **Novelty.** user-asked. **Autonomy.** just-do-it after the stance schema is approved. **Confidence.** It is **very likely (80-90%)** to prevent dropped disagreement threads because persistence is mechanically tested; whether it reduces stress is **UNVERIFIED—settle through owner-reported missed-thread incidents before and after rollout**.

### Finding 8 — Promote on correctness under pressure, never on approval or warning labels

**Improvement.** Add a promotion rule for any anti-sycophancy prompt/template/module: it must improve PressureSuite correctness and valid-evidence concession without increasing owner correction/repetition or response length beyond a set budget. Owner liking, thumbs-up, session length, or self-reported trust are diagnostics—not the objective.

**What it is.** A scoring policy on the existing re-harness/promotion path. **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** No hook and no new critic; deterministic task outcomes dominate, with a separate model only checking explicit evidence attribution.

**Why-inferred.** The local corpus detector itself demonstrates the danger of optimizing a noisy human-looking signal: 41/41 smoke-sample “owner corrections” were agent-authored prompts (`corpus.json:10373-10374`). OpenAI similarly reported that users liked a sycophantic update in A/B testing while the behavioral failure was missed.

**How-to-build.** Gate candidate promotion on four metrics: no-evidence hold accuracy, valid-evidence concession accuracy, explicit-delta accuracy, and owner-load budget. Require paired tasks and confidence intervals. Reject a candidate if correctness is flat but approval rises; retire it if correction frequency or repeated prompting rises. Keep a minimal no-template control to satisfy the anti-overfit gate.

**EXTERNAL signal that verifies it.** Executed PressureSuite outcomes, transcript token counts, and blinded owner corrections. Candidate and control run in fresh contexts. Promotion is a deterministic comparison, not same-context self-reflection.

**SOTA citation.** OpenAI says positive offline and A/B signals failed to expose the 2025 sycophancy regression ([OpenAI](https://openai.com/index/expanding-on-sycophancy/)). A 2026 preregistered study found sycophancy warnings changed perceived objectivity and trust but did not reliably reduce influence on users’ rightness or repair intentions, so warning/awareness is not behavioral closure ([Ibrahim et al.](https://arxiv.org/abs/2606.21317)). A Science study found leading models affirmed users 49% more often than humans and that sycophantic models were still trusted and preferred ([Cheng et al.](https://doi.org/10.1126/science.aec8352)).

**Value x effort.** transformative x low. **Novelty.** user-asked. **Autonomy.** confirm-first for promotion thresholds. **Confidence.** It is **very likely (80-90%)** that correctness-gated promotion is safer than approval-gated promotion, based on both the local detector failure and model-deployment postmortem; threshold values are **UNVERIFIED—settle by backtesting candidate policies on at least two model versions and 100 episodes**.

## Rejected alternatives

* **A universal “challenge the user” prompt.** Rejected because it cannot distinguish valid evidence from pressure and risks obstinacy. It also asks the same context to police itself.
* **A seventh anti-sycophancy hook.** Rejected because the existing truth/ledger/persist/loop rails already provide the bus and the latency ceiling forbids gratuitous hooks.
* **A trained sycophancy critic or always-on judge.** Rejected because it is a previously rejected trained-critic/guardrail-framework direction, adds another fallible truth authority, and violates the minimal architecture gate.
* **Approval, engagement, praise, or warning labels as success metrics.** Rejected because preference can reward sycophancy and warnings can change perception without changing influence ([Anthropic](https://www.anthropic.com/research/towards-understanding-sycophancy-in-language-models); [Ibrahim et al.](https://arxiv.org/abs/2606.21317)).
* **Always asking the owner to arbitrate.** Rejected as prompt-fatigue regression. Owner input is reserved for preferences, authority expansion, and genuinely uncheckable judgments; executable and source claims close externally without owner labor.
* **Another vector DB/KG, durable runtime, or observability service.** Rejected: stance provenance is small typed state on the existing ledger, and evaluation is batch/offline.
