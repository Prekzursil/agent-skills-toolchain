## Executive verdict

I found **six current collision classes** in the unpacked subject: (1) repository-specific coverage thresholds versus the TDD agent's fixed 80%; (2) language-specific test commands versus the TDD agent's unconditional npm commands; (3) the common HIGH-severity review disposition versus the Python and TypeScript reviewers' blocking disposition; (4) a generic rule that routes every language's build failure to a TypeScript/Node-only resolver; (5) a mandatory `longrun` wrapper versus the Codex agent's expressly permitted direct invocation; and (6) a parent-facing security-review delegation rule that becomes impossible inside the very reviewer subagents that inherit it. I also found a native model pin on the edit-capable loop orchestrator that bypasses the stated Opus-for-orchestration policy before prose rules can affect model resolution.

That is seven findings, with the two TDD defects separated because their collision situations and fixes differ. The first five and the security handoff are direct text collisions. The model-routing finding is a configuration-versus-prose collision.

The runtime winner is not inferred from file ordering. Claude Code documents two mechanically distinct facts: a custom subagent receives its own body as its **system prompt**, while `CLAUDE.md`/rules load as memory/context; and memory instructions are delivered as a **user message**, not as the system prompt. It also documents the native model-resolution chain separately. Thus, when an agent-body command and a loaded rule cannot both be satisfied, the **agent body wins by instruction authority**; when `model:` conflicts with prose, the native model field wins at spawn. Sources: [Create custom subagents — “What loads at startup”](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup), [How Claude remembers your project — troubleshooting](https://code.claude.com/docs/en/memory#troubleshoot-memory-issues), and [Create custom subagents — choose a model](https://code.claude.com/docs/en/sub-agents#choose-a-model).

This runtime conclusion is **almost certain (90-99%)** because the current official documentation independently specifies both sides of the authority boundary and the model-resolution order. A live Windows canary was not possible on this Linux job node: `command -v claude` returned no executable. Therefore, **UNVERIFIED actual adherence frequency** for each collision would be settled by a Windows canary that invokes the named agent on the concrete collision fixture and captures `/memory`, `/agents`, the SubagentStart trace, and the agent's first command. The audit claims a deterministic configuration conflict and effective authority, not a measured frequency of model obedience.

## Runtime mechanics used to decide “which wins”

1. Rules without `paths` load at launch; rules with `paths` load when Claude reads a matching file. All `.md` files are recursively discovered. Official evidence: [Organize rules with `.claude/rules/`](https://code.claude.com/docs/en/memory#organize-rules-with-clauderules).
2. Custom subagents receive their agent body as their system prompt, their delegation task, and the memory hierarchy. Explore and Plan are exceptions; none of the seven findings uses those built-ins. Official evidence: [What loads at startup](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup).
3. Claude Code says memory is context, not enforced configuration, and says contradictory memory rules may be selected arbitrarily. It also says memory is delivered as a user message. Official evidence: [Write effective instructions](https://code.claude.com/docs/en/memory#write-effective-instructions) and [Troubleshoot memory issues](https://code.claude.com/docs/en/memory#troubleshoot-memory-issues).
4. The documented model-resolution order is environment override, per-invocation model, agent `model:` frontmatter, then main model. Memory prose is not a resolution tier. Official evidence: [Choose a model](https://code.claude.com/docs/en/sub-agents#choose-a-model).
5. Custom subagents cannot spawn subagents. This is independently visible locally because the reviewer tool allowlists omit `Agent`, and documented by [Control subagent capabilities](https://code.claude.com/docs/en/sub-agents#control-subagent-capabilities).

These are runtime-mechanism signals, not a re-reading of the conflicting prose. They establish why the losing text can be present yet ineffective.

The program-level anti-overfit gate does ban introducing a vector DB/KG memory into this harness without justification, but this unit's comparison scope is rules versus agents and the architect example alone does not establish a runtime collision.

8. **Reviewer output examples versus JSON handoff envelopes:** the reviewer agents' later mandatory handoff envelope can contain the earlier finding fields.
