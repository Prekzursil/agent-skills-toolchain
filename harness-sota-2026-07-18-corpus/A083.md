## Finding 2 — `/rollback` advertises a Git operation that does not restore the checkpoint

Severity: **high** for tracked files with post-checkpoint edits. This remains broken even after Finding 1 is wired.

Confidence: **almost certain (90-99%)**, based on the exact generated checkpoint object and direct Git execution in a disposable repository. Git-version-specific message wording may vary, but the tested merge collision and unchanged post-edit content are concrete.

### Both sides, verbatim

Command, `~/.claude/commands/rollback.md:28-37`:

> - `git-stash` — the `restore` sha is a stash-create snapshot of the whole dirty
>   tree at that turn. Inspect, then apply:
>   ```bash
>   git -C <repo> stash show -p <restore_sha>      # preview the snapshot
>   git -C <repo> stash apply <restore_sha>        # restore working-tree state
>   # or restore ONE file from the snapshot:
>   git -C <repo> checkout <restore_sha> -- <path>
>   ```
>   The snapshot is also tagged `refs/claude-checkpoints/<turn>` (GC-safe).

Hook behavior, `~/.claude/hooks/edit-checkpoints/checkpoint.py:124-143`:

> rc, out, _ = _run_git(repo, "stash", "create", f"claude-checkpoint turn={turn}")
> if rc == 0 and out:
>     sha = out.splitlines()[-1].strip()
>     ref = f"refs/claude-checkpoints/{turn}"
>     _run_git(repo, "update-ref", ref, sha)
>     kind, restore = "git-stash", sha
> else:
>     # Clean tree (no dirty changes) -> the restore point is just HEAD.
>     rc2, head, _ = _run_git(repo, "rev-parse", "HEAD")
>     kind, restore = "git-head-clean", (head if rc2 == 0 else "")
> return {
>     "ts": time.time(),
>     "turn": turn,
>     "type": kind,
>     "repo": repo,
>     "restore": restore,
>     "trigger_file": file_path,
> }

The collision is conceptual and operational: the hook captures the *pre-edit dirty tree* as a stash-like commit, then the command tries to merge/apply that snapshot onto the *post-edit dirty tree*. That is not a rewind operation.

### Concrete runtime experiment

Disposable sequence:

1. Commit `f.txt = base`.
2. Change it to `pre-edit`.
3. Invoke the actual checkpoint hook, which records a `git-stash` SHA.
4. Change it to `post-edit`.
5. Execute the command's advertised `git stash apply <sha>`.

Observed:

```text
stash-apply-rc 1
error: Your local changes to the following files would be overwritten by merge:
        f.txt
Please commit your changes or stash them before you merge.
Aborting
--- content after advertised stash apply ---
     1  post-edit
```

The positive-control alternative from the same command was then executed:

```text
git -C <repo> checkout <restore_sha> -- f.txt
--- content after per-file checkout ---
     1  pre-edit
```

This uses two mechanically different signals: Git's nonzero exit/error and a direct content read. The positive-control checkout proves the saved SHA actually contains the desired pre-edit content.

### Which side wins at runtime

Git wins. The hook has supplied a valid snapshot, but `stash apply` invokes merge semantics against the current dirty tree. In the tested normal same-file collision, Git aborts and retains `post-edit`; the prose comment `# restore working-tree state` does not change that behavior.

### Minimal resolution — CONFIG (command Markdown only)

Remove `git stash apply <restore_sha>` as the recommended rollback operation. Make the already-tested per-file source restore the primary operation, after preview and explicit confirmation. If whole-repository rollback is retained, specify a destructive, confirmation-gated source restore that is tested against staged, unstaged, deleted, renamed, and untracked cases; do not label merge/apply as rewind.

The per-file edit is **almost certain (90-99%)** to fix the demonstrated tracked-file case because it restored the exact pre-edit bytes in the direct probe. A fully correct whole-tree recipe is **UNVERIFIED; settle it with a matrix test covering staged/unstaged changes, new files, deletions, renames, same-basename paths, and multiple repos before documenting one.** Therefore a whole-tree recommendation should remain absent until that experiment passes.

Anti-overfit gate: passes. This is a command-text correction using Git already employed by the hook. No new component is introduced.
