# X182 — Cross-domain borrow: experimental design → trust calibration

## Executive finding

The borrow transfers, but only if the harness treats trust as an **empirical, versioned, outcome-specific estimate** rather than as an intrinsic property of an agent. The useful import is not any single technique. It is the experimental-design stack:

1. preregister the claim, sampling plan, endpoints, exclusions, stopping rule, and analysis before seeing evaluation outcomes;
2. power each agent × task-type comparison for a decision-relevant failure rate or performance difference;
3. blind outcome assessment and, where possible, the analyst to agent identity and condition;
4. run prespecified positive and negative controls through the same evaluation pipeline;
5. publish uncertainty, protocol deviations, control results, and freshness with every trust estimate.

**Transfer judgment: very likely (80-90%)** that this stack would materially improve *evaluation-time* trust calibration for stable, versioned agents on repeatable task families. Evidence: each mechanism attacks an evaluator-side failure mode that exists independently of biology—outcome-contingent analysis, inadequate sensitivity, identity-influenced assessment, and shared-pipeline bias—and those mechanisms have explicit analogues in the proposed evaluation pipeline. Experimental-design authorities separately recognize prespecification, blinded assessment, adequate power, and controls as validity mechanisms ([Center for Open Science preregistration guidance](https://www.cos.io/initiatives/prereg), [Cochrane risk-of-bias guidance](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08), [Lipsitch, Tchetgen Tchetgen, and Cohen 2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC3053408/), [Vogt et al. 2020 on design and power](https://pmc.ncbi.nlm.nih.gov/articles/PMC7425741/)).

**Transfer judgment: unlikely (20-45%)** that the same stack, by itself, produces a durable or universally portable “trust score.” Evidence: experimental inference is conditional on the sampled population, intervention, outcome definition, measurement process, and implementation fidelity; an agent’s model version, prompt, tools, permissions, context, and task distribution are all analogous moving parts. Cochrane likewise assesses bias for a *specific result*, not a permanent quality of a trial or intervention, and says risk can differ by outcome ([Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)).

Therefore the recommended object is a **calibration passport**, not a leaderboard score: a set of per-agent-build × task-family × outcome estimates with intervals, control status, protocol hash, evaluation date, and explicit unsupported regions.

## What experimental design has already solved

### 1. Preregistration: separate planned tests from discoveries made after seeing results

#### How it works in its own field

Preregistration creates a time-stamped research plan before outcome inspection. The plan identifies hypotheses, outcomes, sampling, exclusions, stopping, and analyses. The key epistemic move is not banning adaptation; it is making outcome-contingent choices visible. The Center for Open Science says the aim of a pre-analysis plan is to avoid analytical decisions contingent on observed results. It recommends split samples for exploration versus confirmation, transparent change documents after registration, and conditional IF–THEN decision trees when analysis depends on assumption checks ([COS preregistration guidance](https://www.cos.io/initiatives/prereg)).

This addresses researcher degrees of freedom: choosing a favorable endpoint, subgroup, exclusion, stopping point, or test after seeing the data can make an exploratory pattern look confirmatory. Cochrane operationalizes the same concern as “bias in selection of the reported result”: assessors ask whether analysis followed a prespecified plan finalized before unblinded outcome data, and whether a reported number was selected from multiple measurements or analyses because of the results ([Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)).

Preregistration does **not** certify that the hypothesis, metric, sample, or model is good. COS explicitly calls a registration a plan, not a prison, allows documented deviations, and warns that preregistration with already-observed data has additional validity challenges ([COS preregistration guidance](https://www.cos.io/initiatives/prereg)). It turns undisclosed flexibility into inspectable provenance; it is not a truth machine.

#### Translation to trust calibration

The direct analogue is an immutable **evaluation protocol manifest** created before candidate outputs are scored. It would include:

- exact agent build identity: model snapshot/version, system and developer prompts by content hash, tool inventory and versions, permissions, decoding settings, memory/context policy, and harness revision;
- the claim being tested, such as “build A’s upper 95% bound on materially wrong answers is below 2% for repository-localized Python bug fixes under this tool policy”;
- task taxonomy and sampling frame, including inclusion probabilities and deduplication rules;
- primary endpoints and loss weights, with “materially wrong,” abstention, evidence quality, unsafe action, and task completion defined before scoring;
- comparator, if any, and the randomization or pairing scheme;
- minimum effect or maximum tolerable defect rate, alpha, desired power, sample-size calculation, multiplicity policy, and stopping rule;
- treatment of tool errors, timeouts, retries, missing grades, partial completions, and post-randomization exclusions;
- grader rubric, adjudication rule, blinding fields, control tasks, and criteria that invalidate the run;
- planned subgroup estimates and the exact rule for labeling any later analysis exploratory;
- manifest hash, creation time, evaluator versions, and append-only amendments.

This catches benchmark gardening: silently dropping hard tasks, changing “success” after results, selecting a favorable grader, stopping after a lucky streak, laundering first-attempt failures through retries, and promoting a post-hoc subgroup win to a general capability claim.

### 2. Power analysis: design the study to resolve the decision that matters

#### How it works in its own field

Power is the probability that a test rejects a false null hypothesis under a specified alternative. Prospective power analysis connects the meaningful effect size, outcome variance or event rate, false-positive threshold, false-negative tolerance, and sample size. Vogt et al. show the standard relationship among alpha, power, standardized effect size, and required sample size, and emphasize that smaller effects require more observations ([Vogt et al., 2020](https://pmc.ncbi.nlm.nih.gov/articles/PMC7425741/)). A statistical primer on clinical study planning likewise identifies significance level, Type II error/power, effect size, and sample size as coupled design inputs ([“Sample size and power calculations—why, when and how?”](https://pmc.ncbi.nlm.nih.gov/articles/PMC6005113/)).

The important lesson for trust is that “we saw no failure” is not the same as “failure is rare.” With independent Bernoulli trials, the probability of seeing at least one failure when the true failure probability is `p` is `1 - (1-p)^n`. Thus 59 independent trials give about a 95% chance of seeing at least one failure if `p = 0.05`; this arithmetic is a design illustration, not a recommended universal threshold. Conversely, estimating a rate precisely usually needs far more trials than merely detecting one failure. Correlated or duplicated tasks reduce effective information, so nominal `n` can be misleading.

Power calculations do not rescue a biased endpoint or unrepresentative sample. They quantify sensitivity under assumptions. A large, precisely estimated benchmark can still be irrelevant to production.

#### Translation to trust calibration

Power must be planned **per decision-relevant cell**, not for an aggregate leaderboard. A cell is at least:

`agent build × task family × consequence class × operating condition`

Examples of operating condition include context length band, tool availability, repository familiarity, and whether external retrieval is required. The protocol should specify either:

- a maximum tolerable defect rate to bound, or
- a smallest practically important paired difference against the incumbent to detect.

The report should show the observed count, denominator, interval, missingness, effective sample assumptions, and whether the planned information target was met. An underpowered cell must remain **unknown/inconclusive**, not inherit the agent’s global mean. Repeated variants from one base task should be treated as a cluster or evaluated with a clustered/bootstrap design rather than counted as fully independent observations.

This catches false reassurance from five clean examples, false condemnation from one noisy failure, Simpson’s-paradox-like aggregation across easy and hard task mixtures, and claims of “no difference” that are merely low-sensitivity tests.

### 3. Blinding: prevent knowledge of condition from changing conduct or measurement

#### How it works in its own field

Blinding withholds treatment assignment from participants, personnel, outcome assessors, or analysts whose behavior or judgment could be influenced by it. Cochrane distinguishes allocation concealment, which prevents selection bias before assignment, from blinding, which prevents bias after assignment. Its risk-of-bias questions explicitly ask whether assessors knew the intervention and whether that knowledge could influence outcome assessment ([Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)). FDA guidance similarly treats randomization and blinding as central tools for reducing trial bias while acknowledging that full blinding is sometimes infeasible ([FDA open-label trial considerations](https://www.fda.gov/science-research/fda-science-forum/considerations-open-label-clinical-trials-design-conduct-and-analysis)).

Blinding is role-specific and can fail. Calling a study “double blind” does not identify who was blind; side effects or recognizable outputs may reveal assignment. Cochrane therefore recommends reasoning about who knew what and whether the outcome could be influenced, rather than treating a blinding label as magic ([Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)).

#### Translation to trust calibration

For subjective or mixed grading, present graders with normalized candidate artifacts in randomized order while hiding agent/model name, cost, latency, declared confidence, prior reputation, and whether the output is the incumbent. Preserve only information necessary to judge the task. Score before unblinding. Where tool traces are essential, use two stages: grade the deliverable first while identity-blind, then inspect a redacted trace for process/safety endpoints, and finally unblind for attribution.

Blind the primary analyst to condition labels (`A`, `B`, …) until the prespecified analysis table is frozen. Do not let an agent grade its own answer as the sole outcome measure. Measure blinding integrity by asking graders to guess condition and record cues; a high identification rate does not automatically invalidate objective endpoints, but it weakens claims for judgment-sensitive outcomes.

This catches brand/prestige bias, incumbent favoritism, confirmation bias after expensive runs, harsher grading of a disliked model, halo effects from polished prose, and analytical choices made to favor a known condition.

### 4. Negative and positive controls: test the validity detector inside the same pipeline

#### How they work in their own field

A negative control recreates the suspected bias pathway while removing the hypothesized causal mechanism. Lipsitch and colleagues define its essential purpose as reproducing a condition that cannot involve the proposed mechanism but is likely to share the same sources of bias. An unexpected association then signals confounding, selection, measurement, or analytic error ([Lipsitch, Tchetgen Tchetgen, and Cohen, 2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC3053408/)).

The structural requirement is crucial. A negative-control outcome should share the relevant common causes of the real outcome but not be caused by the exposure; a negative-control exposure should share the relevant common causes of the real exposure but not cause the outcome. Approximate comparability creates both false alarms and false reassurance. The authors call negative controls sensitive but blunt: failure can reveal bias without identifying its source or magnitude, and a clean control does not rule out bias pathways the control does not share ([Lipsitch et al., 2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC3053408/)).

Laboratory positive controls complement this logic: a condition known to produce a signal checks that the assay can detect one. For harness evaluation, that distinction matters. A pipeline that gives every answer a pass has “clean” negative controls only if the controls were badly chosen; known-good and known-bad sentinels establish basic grader sensitivity in both directions.

#### Translation to trust calibration

Embed controls indistinguishably among primary evaluation items and score them through the identical path:

- **Known-bad answer controls:** take a real task and inject a minimally edited but materially wrong artifact, preserving style and length. The grader must reject it. This is a positive control for defect detection, despite the artifact itself being a negative example.
- **Known-good answer controls:** use independently verified solutions and ensure the evaluator accepts them. This detects graders that maximize apparent vigilance by rejecting everything.
- **Identity-placebo controls:** present the exact same output twice under blinded randomized IDs. Any systematic score difference after identity is revealed indicates evaluator or analysis leakage; before reveal, disagreement estimates grader noise.
- **Mechanism-removed controls:** for evidence-grounded tasks, substitute a citation that is topically plausible but does not support the claim; for code tasks, substitute a patch that satisfies superficial style but deliberately leaves the targeted failing test broken. These share presentation cues with real candidates while removing the claimed correctness mechanism.
- **Impossible-premise/abstention controls:** supply tasks whose requested fact or file is provably absent from the sealed evaluation fixture. Passing requires an explicit evidence-bounded abstention, not fabrication. This tests whether apparent helpfulness is being mistaken for reliability.
- **Pipeline contamination controls:** insert unique canary facts or task variants that are absent from allowed context; correct reproduction can signal leakage. Interpretation requires care because accidental inference or memorization may mimic leakage.

The run should fail closed—or at minimum lose confirmatory status—when prespecified control error exceeds tolerance. Controls must be task-family matched; a citation control says little about a code executor, and a syntax-broken patch is too easy to diagnose evaluator sensitivity to subtle semantic faults.

This catches graders that reward fluency over correctness, answer-key leakage, label leakage, indiscriminate pass/fail behavior, inability to recognize justified abstention, and shared pipeline bugs that inflate every candidate equally.

## What this would catch that ordinary trust signals miss

The following are target failure classes, not claims of verified local absence:

1. **Outcome switching:** a benchmark is announced as correctness but reported on style or completion after correctness disappoints. A hashed manifest exposes the switch.
2. **Retry laundering:** the public score counts eventual success while production routing assumes first-attempt reliability. A preregistered retry estimand prevents the denominator from changing silently.
3. **Easy-task mixture inflation:** a global 95% pass rate is driven by high-volume low-risk tasks while a rare destructive task family is unsupported. Stratified cells and `UNKNOWN` prevent inheritance.
4. **False “no difference”:** two agents look equal because there were too few paired trials to detect the chosen material difference. The information target labels the result inconclusive.
5. **Prestige-biased grading:** identical quality receives different scores because graders know which model produced it. Blinded IDs and identity-placebo duplicates expose the pathway.
6. **Fluency-as-correctness:** polished but false answers pass. Mechanism-removed, style-matched controls test whether the evaluator notices the missing correctness mechanism.
7. **Evaluator polarity failure:** a grader accepts or rejects nearly everything. Known-good and known-bad controls expose both directions.
8. **Leakage:** an agent or grader reproduces a sealed canary. A contamination control flags that the observed performance may not be independent.
9. **Hallucination hidden by answerable benchmarks:** an agent looks strong only because every prompt has an answer. Impossible-premise controls directly measure evidence-bounded abstention.
10. **Stale evidence:** a model, prompt, tool, or permission change leaves the old trust score attached to a new causal package. Build hashes invalidate the cell.
11. **Missingness bias:** timeouts or ungradeable artifacts disappear from the denominator. The protocol specifies missing-outcome handling and the ledger reports missingness; Cochrane warns that missingness related to true outcomes can bias estimates ([Cochrane Handbook, Chapter 8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08)).
12. **Evaluator drift:** grader updates change the measurement instrument. Evaluator versioning, anchor controls, and repeated blinded sentinels make the discontinuity visible.

## Adversarial analysis of the analogy

### Structural correspondences that do transfer

| Experimental design | Agent trust calibration | Why the structure matches |
|---|---|---|
| intervention/condition | versioned agent configuration | both are the assigned mechanism whose outcome is measured |
| experimental unit | task instance or paired task execution | both are units receiving a condition, subject to sampling and dependence assumptions |
| endpoint | correctness, material defect, unsafe action, abstention, latency | both require a prespecified operational definition and measurement process |
| assessor | test oracle, human grader, judge model, adjudicator | both can introduce differential measurement error |
| population | production task distribution | both delimit where estimates can generalize |
| protocol deviation | prompt/tool/retry/exclusion change | both can change the estimand after assignment |
| negative control | mechanism-removed but pipeline-matched sentinel | both remove the hypothesized mechanism while preserving a suspected bias route |

**Correspondence assessment: very likely (80-90%)** for evaluator-side bias and uncertainty. Evidence: the mappings preserve the causal roles required by the cited mechanisms, especially outcome assessment, prespecification, and shared-path controls.

### Disanalogies that prevent a full transfer

1. **The “treatment” is adaptive.** An agent changes behavior with context, tools, memory, and evaluator-visible cues. A drug lot does not read the protocol and strategically react to it. Benchmark awareness and prompt adaptation can violate stable-treatment assumptions.

2. **Tasks are not exchangeable patients.** Software bugs, research questions, and destructive operations have heavy-tailed difficulty and radically different loss. Convenience benchmark sampling does not justify production prevalence estimates.

3. **Outcomes are partly constructed by the evaluator.** Many clinical outcomes have independent physical anchors; agent correctness often depends on incomplete rubrics, mutable repositories, or another model’s judgment. Blinding cannot repair a bad oracle.

4. **Interference is common.** Agents share caches, repositories, memories, and external services; one run can change the environment seen by another. This violates independence and can contaminate paired comparisons.

5. **Version turnover is fast.** A calibrated model/prompt/tool package may be replaced before a well-powered rare-event study finishes. The evidence has a short half-life.

6. **Adversarial optimization targets the test.** Once the benchmark or controls become known, developers and agents can optimize to them. Clinical trials also face gaming, but an inference-capable agent can recognize task templates directly.

7. **Rare catastrophic failures dominate some decisions.** No practical benchmark sample can establish extremely low catastrophic-failure probabilities solely by observing zero events. Mechanistic safeguards and mandatory verification remain necessary.

8. **Blinding is often porous.** Model-specific phrasing, trace formats, tool choices, and refusal styles can reveal identity. Objective tests reduce this concern; subjective grades remain vulnerable.

9. **Negative controls are hard to match.** Removing correctness often makes an answer obviously broken or changes difficulty. If the control does not share the same evaluator bias pathway, a pass is falsely reassuring. Lipsitch et al. explicitly warn that imperfect comparability creates false positives and false negatives ([Lipsitch et al., 2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC3053408/)).

10. **Trust is a decision, not merely a rate.** The same 2% failure estimate may be acceptable for drafting prose and intolerable for an irreversible operation. Experimental evidence must be joined to consequence-specific policy.

These disanalogies are why the proposal stops at a scoped calibration passport. **It is almost certainly not (1-5%) appropriate** to certify an agent as universally “trusted” from this machinery alone. Evidence: task heterogeneity, adaptive configurations, measurement error, drift, and rare-event limits each independently break that inference.

## Validation plan for the UNVERIFIED recommendation

This is the experiment that would settle whether the borrow adds decision value in this harness:

### Phase 0 — exploratory pilot

Use historical or synthetic tasks only to refine taxonomy, rubric, control construction, variance/event-rate assumptions, and operational feasibility. Label all findings exploratory. Freeze none of these data into the confirmatory analysis. COS explicitly recommends separating exploration from a held-out confirmation sample ([COS preregistration guidance](https://www.cos.io/initiatives/prereg)).

### Phase 1 — preregistered shadow study

Choose two version-frozen agent configurations and at least three structurally different families: one objectively executable (for example, code with sealed tests), one evidence-grounded research family, and one judgment-heavy writing/planning family. Before revealing outcomes:

- seal the manifest;
- define paired sampling from a prospective production-like queue or a genuinely held-out fixture set;
- select the task-family loss and practical difference/failure threshold;
- calculate sample needs and define clustering;
- embed matched bidirectional and negative controls;
- randomize opaque IDs and blind graders/analyst;
- specify missingness, retries, exclusions, multiplicity, and stopping;
- define what would count as success for the calibration passport: better prospective separation of safe-autonomy versus verification-needed cases, without unacceptable escalation load.

### Phase 2 — prospective routing comparison

Run the passport policy in shadow mode beside the incumbent trust/routing signal. Do not let it affect actions. On a later held-out stream, compare:

- material failure rate within “autonomous” recommendations;
- false reassurance: failures routed as high trust;
- unnecessary escalation rate;
- abstention quality;
- calibration by cell (predicted interval versus observed outcomes);
- control failure and blinding-integrity rates;
- behavior under stale or unsupported cells.

### Phase 3 — falsification criteria

Reject or redesign the borrow if any preregistered condition holds, including:

- matched controls do not predict evaluator failures on primary items;
- graders identify agent condition well above the planned blinding threshold and subjective results change materially after accounting for guessed identity;
- task cells drift faster than enough evidence can accumulate;
- intervals remain too wide for routing decisions at feasible sample sizes;
- passport routing does not improve prospective failure/escalation tradeoffs over the incumbent;
- protocol overhead causes task selection so unrepresentative that external validity worsens.

**Validation outlook: roughly even (45-55%)** that a first shadow implementation would meet all operational success criteria without redesign. Evidence: the component methods are mature, but matched control construction, task sampling, rare-event power, evaluator validity, and version half-life are unresolved for this specific harness. This intentionally conservative band is the reason to shadow-test rather than deploy on conceptual appeal.

## Failure containment and interpretation rules

- A failed negative control invalidates the affected inference; it does not prove which candidate is bad.
- A clean negative control only rules against bias pathways the control was designed and powered to share.
- A failed positive control means the evaluation instrument lacks demonstrated sensitivity; primary nulls are inconclusive.
- A statistically detectable difference is not automatically decision-relevant; use the preregistered loss threshold.
- An unsupported or stale cell is `UNKNOWN`, never “low trust” and never “high trust.” Unknown is an evidence state, not an agent judgment.
- Exploratory findings may generate the next protocol but may not silently update a confirmatory passport cell.
- Any model, system prompt, tool policy, permission, memory, evaluator, or material harness change requires an explicit transportability decision; default to a new build identity for changes plausibly affecting the endpoint.
- Do not average task cells unless the target task mixture and weights were defined before seeing outcomes.
- Do not use agent self-reported confidence as the trust estimate. It may be recorded as a predictor and separately calibrated, but ground truth must come from external outcomes.

## Alternatives considered and rejected

### One global Elo/leaderboard score

Rejected because it hides outcome, task mixture, consequence, uncertainty, and version drift. It is useful for competition ranking, not for deciding whether to believe a particular output.

### Majority vote or debate as trust

Rejected as the primary calibration mechanism. Correlated agents can agree on the same error, and voting measures consensus rather than correctness. It can be an intervention tested inside the protocol, not the validity standard.

### Agent self-confidence

Rejected as the ground truth. Self-confidence can be miscalibrated, strategically expressed, or prompt-sensitive. It is an experimental covariate whose calibration must itself be estimated per task family.

### Always require a second agent

Rejected as universal policy because it ignores consequence and correlated error and can double cost without independent evidence. The passport may recommend independent verification where uncertainty or loss warrants it.

### Large bespoke evaluation platform

Rejected by the anti-overfit gate. The necessary mechanisms are manifests, randomized redaction, fixtures, interval calculations, and a routing lookup; all can ride the existing bus. A new daemon or observability service has no demonstrated necessity here.

### Trust learned from all historical telemetry without a held-out protocol

Rejected for confirmatory claims. Historical telemetry is valuable for hypothesis generation and task taxonomy, but outcome-aware selection, changing versions, missingness, and unknown sampling make it vulnerable to precisely the biases preregistration addresses. It can inform priors or pilots only if that use is declared before confirmation.

## Bottom line

Experimental design contributes a powerful discipline to trust calibration: **precommit what belief would mean, collect enough matched evidence to resolve it, prevent identity from contaminating measurement, and test the evaluator with controls that share its failure pathways**. The analogy is valid for scoped empirical claims about a frozen agent configuration on a defined task population. It fails when stretched into a permanent, global trait.

The most ambitious defensible design is therefore not a more elaborate autonomous critic. It is a compact, falsifiable calibration layer attached to the existing harness bus: protocol manifest, blinded evaluation, matched controls, powered per-cell intervals, and loss-aware shadow routing. If the shadow experiment cannot outperform the incumbent under prospective outcomes, reject the borrow rather than institutionalizing experimental theater.
