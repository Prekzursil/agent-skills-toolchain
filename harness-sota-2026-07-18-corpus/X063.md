# X063 — Cross-domain borrow: epidemiology → agent-claim verification

## Executive result

The epidemiological mechanism that transfers is **two-phase, base-rate-aware surveillance under an operational case definition**, especially the correction for **partial verification bias**. The useful borrow is not the loose metaphor “claims are diseases.” It is a mature answer to a concrete resource problem: a cheap but imperfect screen can be applied to everyone, while an expensive reference procedure is applied to all or most screen-positive cases **and to a probability sample of screen-negative cases**. Known selection probabilities then permit population-level estimates of missed cases rather than pretending that unreviewed negatives are true negatives.

Applied to an agent harness, the target condition is a materially false or unsupported atomic claim; the “index test” is cheap automated verification; and the reference procedure is a claim-type-specific, independently executed truth test. Every high-risk or screen-positive claim is escalated, but a stratified random sample of claims the screen passed is escalated too. The latter is the crucial move: it reveals silent false negatives and makes detector sensitivity measurable without a human reading everything.

**Transfer verdict:** this mechanism transfers, but only for claims whose truth condition and reference procedure can be specified. It is **very likely (80-90%)** to reveal materially different verifier performance than “audit only alerts,” because partial-verification literature identifies selection on the index result as a source of biased accuracy estimates, and both FDA guidance and a diagnostic-accuracy methods paper prescribe reference testing of a subset of screen negatives ([FDA diagnostic-test guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/statistical-guidance-reporting-results-studies-evaluating-diagnostic-tests-guidance-industry-and-fda); [Biesheuvel et al., 2022, PubMed](https://pubmed.ncbi.nlm.nih.gov/35124189/)). The size of that difference in this owner's harness is **UNVERIFIED; settle it with Experiment E1, the prospective two-phase claim audit defined below**.

This is not a proposal for a second orchestration runtime, vector database, trained critic, or external observability system. It is a small protocol and accounting layer riding the existing hook/skill/tool bus.

## 1. What epidemiology solved in its own field

### 1.1 Operational case definitions make heterogeneous observations countable

Public-health surveillance does not begin by asking each observer for an unconstrained opinion. It specifies an operational case definition. WHO defines a surveillance case definition as diagnostic criteria—clinical, laboratory, or a combination, potentially including person, place, and time—that must be met to count an individual as a case; it also warns that a surveillance case definition need not be the same as an ordinary clinical definition ([WHO IHR glossary](https://ihrbenchmark.who.int/document/glossary)). CDC says common case definitions standardize cases and commonly stratify certainty as suspected, probable, and confirmed ([CDC outbreak and case definitions](https://www.cdc.gov/urdo/php/surveillance/outbreak-case-definitions.html)). CDC further explains that the definition used for surveillance can differ from clinical diagnosis or an outbreak-investigation definition because it is an operational device for reliable recognition and counting ([CDC Principles of Epidemiology, Lesson 5 §3](https://archive.cdc.gov/www_cdc_gov/csels/dsepd/ss1978/lesson5/section3.html)).

This solves two problems. First, observers report comparable units. Second, “case” does not imply metaphysical certainty: different evidence thresholds can be visible in the label rather than collapsed into one confident answer.

### 1.2 A surveillance system is a classifier, so measure both what it finds and what it misses

Epidemiology evaluates surveillance using the same 2×2 structure as diagnostic testing:

| | Target condition present | Target condition absent |
|---|---:|---:|
| Surveillance says positive | true positive A | false positive B |
| Surveillance says negative | false negative C | true negative D |

Sensitivity is `A/(A+C)`, specificity is `D/(B+D)`, and positive predictive value (PPV; CDC calls it PVP) is `A/(A+B)` ([CDC surveillance appendix and table](https://archive.cdc.gov/www_cdc_gov/csels/dsepd/ss1978/lesson5/appendixa.html)). CDC’s evaluation guidance is explicit that sensitivity means the fraction of actual cases detected, whereas PPV is the fraction of reported cases that truly are cases; low PPV wastes investigation resources and can create pseudo-outbreaks ([CDC Updated Guidelines for Evaluating Public Health Surveillance Systems](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)).

The base rate matters. CDC states that PPV reflects the case definition’s sensitivity and specificity **and the prevalence of the event** ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)). For example, at 1% prevalence, a screen with 90% sensitivity and 95% specificity has PPV:

`(0.90 × 0.01) / ((0.90 × 0.01) + (0.05 × 0.99)) = 15.4%`.

Thus a detector that looks impressive in isolation can send more than five false alerts for every true alert in a low-prevalence stream. This is base-rate reasoning, not an argument to ignore rare serious cases: it is an argument to set escalation policy from expected loss and measured prevalence rather than a single global “accuracy” score.

### 1.3 Partial verification bias: auditing only screen positives hides misses

The reference standard—biopsy, culture, longitudinal diagnosis, or another accepted procedure—is often too costly or burdensome to apply to every person. A tempting design applies it only when the inexpensive index test is positive. That makes verification depend on the very test being evaluated. The resulting verified subset cannot reveal most false negatives and gives biased performance estimates. This is **partial verification bias** (also called work-up bias).

A 2022 diagnostic-accuracy methods paper defines the bias as the situation in which a positive index result makes application of the reference standard more likely. Its design remedy is to reference-test every index-positive participant and a random sample of index-negative participants ([Biesheuvel et al., 2022](https://pubmed.ncbi.nlm.nih.gov/35124189/)). The Cochrane diagnostic-test handbook states that random selection for the reference standard—either over the whole sample or separately within positive and negative strata—can yield unbiased overall performance estimates when analysis compensates for the sampling plan ([Cochrane DTA Handbook, Chapter 9](https://methods.cochrane.org/sdt/sites/methods.cochrane.org.sdt/files/uploads/ch09_Oct09.pdf)). FDA likewise recommends partial/two-stage studies when universal reference testing is impractical, with estimates adjusted for verification bias; importantly, FDA says resolving only discrepant results is not valid and at least a subset of concordant cases must also be resolved ([FDA guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/statistical-guidance-reporting-results-studies-evaluating-diagnostic-tests-guidance-industry-and-fda)).

The estimator is conceptually simple. If stratum `h` has reference-audit probability `π_h`, each audited item represents `1/π_h` items in that stratum. Weighted counts estimate A, B, C, and D for the full population. Exact confidence intervals or survey-design variance estimates must accompany point estimates; otherwise a tiny audit sample creates false precision.

The important distinction is:

* operational verification directs effort toward likely cases;
* probability verification reserves some effort for apparent noncases so the surveillance system itself remains measurable.

### 1.4 Independence and the reference standard matter

Two agreeing tests are not necessarily two independent signals. If both consume the same erroneous chart, use the same biomarker, or one result influences interpretation of the other, agreement can merely reproduce shared error. QUADAS-2 asks whether the reference standard is likely to classify the target condition correctly and whether it was interpreted without knowledge of the index test; it asks the symmetric blinding question for the index test ([QUADAS-2 form](https://www.ncbi.nlm.nih.gov/books/NBK305110/bin/10-45-04-app8.pdf)). FDA recommends constructing a reference standard independently from analysis of the new diagnostic test, ideally before data collection ([FDA guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/statistical-guidance-reporting-results-studies-evaluating-diagnostic-tests-guidance-industry-and-fda)).

Nor should agreement be mislabeled as truth. FDA says that without an available or constructible reference standard, unbiased sensitivity and specificity cannot be computed; the appropriate output is agreement with the comparative method, with confidence intervals, not diagnostic accuracy ([FDA guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/statistical-guidance-reporting-results-studies-evaluating-diagnostic-tests-guidance-industry-and-fda)). This limitation is central to the translation below.

### 1.5 Surveillance is continuous and must validate its detector

Surveillance is not a one-off benchmark. WHO defines it as systematic ongoing collection, collation, analysis, and timely dissemination for action ([WHO IHR surveillance benchmark](https://ihrbenchmark.who.int/document/10-surveillance?locale=en)). CDC’s system-evaluation framework includes simplicity, flexibility, acceptability, sensitivity, PPV, representativeness, and timeliness, and explicitly notes trade-offs: increasing sensitivity can reduce PPV or make a system less simple and timely ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)).

Epidemiologists also validate outbreak detectors with known signals. CDC’s High-Fidelity Injection Detectability Experiments inject simulated outbreaks into real background surveillance data to characterize sensitivity, specificity, and timeliness across outbreak types and sizes ([CDC HiFIDE](https://www.cdc.gov/mmwr/preview/mmwrhtml/su5401a15.htm)). This is a detector control: failure to report cases is interpretable only after demonstrating that the pipeline detects known-present cases.

## 2. Concrete translation to an agent harness

### 2.1 Proposal — claim case definitions and a claim line list

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add a post-response hook or response-contract adapter that emits a JSONL “claim line list.” It does not store embeddings or orchestrate agents. Each record contains:

* `claim_id` and exact output span;
* an atomic, normalized proposition (not a paragraph);
* claim class: repository state, command outcome, external fact, arithmetic, behavioral prediction, subjective recommendation, or synthesis;
* subject, scope, and as-of time;
* consequence tier if wrong;
* evidence locator(s) and evidence family;
* verifier/index-test result;
* case status: `unassessed`, `suspected_false`, `probable_false`, `confirmed_false`, `supported`, or `unresolved`;
* reference procedure used, audit-selection probability, and audit result.

The case definition must be pre-specified per claim class. Example for “file X contains setting Y”: `confirmed_false` requires (1) resolving the exact repository/ref and path and (2) an independent content read showing the proposition false. A parser failure is only `suspected_false`; it is not evidence the file or setting is absent. Example for “command succeeded”: exit status plus the promised artifact/state transition is stronger than either alone. Example for a future prediction: no current reference standard exists, so status remains `unresolved` until the stated horizon; a second model’s agreement cannot promote it to `supported`.

It is **likely (55-80%)** that atomizing claims and attaching scope/time will reduce ambiguous “verified” judgments, because surveillance case definitions improve standardization and comparability in their native field ([WHO glossary](https://ihrbenchmark.who.int/document/glossary); [CDC case definitions](https://www.cdc.gov/urdo/php/surveillance/outbreak-case-definitions.html)). The magnitude for agent outputs is **UNVERIFIED; settle it with Experiment E0 by having blinded adjudicators apply the proposed versus current rubric to the same 200 claims and compare inter-rater agreement and adjudication time**.

### 2.2 Proposal — cheap universal screen plus stratified two-phase reference audit [UNVERIFIED premise: affordable reference procedures cover enough high-value claim classes; settle with Experiment E0 procedure-coverage inventory]

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Run cheap index checks on every eligible atomic claim, then select reference audits as follows:

1. Audit all catastrophic-consequence claims when a deterministic reference procedure exists.
2. Audit all index-positive claims above an escalation threshold.
3. Independently draw a reproducible probability sample from index-negative claims, stratified by claim class, consequence, tool/source, and agent/model/version.
4. Keep every stratum’s selection probability nonzero. Log the random seed and `π_h` before outcomes are known.
5. Apply a claim-type-specific reference procedure that does not consume the agent’s conclusion as evidence.
6. Weight audited outcomes by `1/π_h` to estimate prevalence, sensitivity, specificity, PPV, and false-negative rate for the defined claim population. Publish numerators, denominators, intervals, unresolved counts, and stratum coverage—not a single “verification score.”

Illustrative reference procedures:

| Claim type | Cheap index test | Independent reference procedure |
|---|---|---|
| Local file/repo fact | citation/path parser; existence check | fresh read of exact bytes at resolved ref plus semantic predicate |
| Command success / task done | exit code and log-pattern check | inspect promised postcondition through a different interface or run an acceptance test |
| Arithmetic/tabular claim | syntax/range checks | deterministic recomputation from cited inputs |
| External current fact | URL/date/domain checks | retrieve authoritative primary source independently and evaluate exact proposition/as-of date |
| Code behavior | static heuristic or generated test | isolated execution against precommitted oracle tests, including counterexamples |
| Subjective recommendation | rubric and provenance checks | no truth reference; label as judgment and audit evidence completeness only |

This is **very likely (80-90%)** to estimate silent false negatives more honestly than reviewing alerts alone, conditional on random sampling within logged strata, because the design is the direct analogue of the recommended remedy for partial verification bias ([Biesheuvel et al.](https://pubmed.ncbi.nlm.nih.gov/35124189/); [Cochrane DTA Handbook](https://methods.cochrane.org/sdt/sites/methods.cochrane.org.sdt/files/uploads/ch09_Oct09.pdf)). Actual sensitivity and cost in this harness are **UNVERIFIED; settle them with Experiment E1**.

### 2.3 Proposal — evidence-family independence rule

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Define evidence-family IDs and prohibit promotion to `confirmed` merely because two signals share the same failure source. Examples:

* two LLM judges reading the same agent transcript are one semantic-review family, not two mechanically independent signals;
* two shell commands using the same path expansion are one resolution family;
* a tool’s success string and the agent’s paraphrase of that string are one signal;
* an exit code and an independently observed state transition are different families;
* a repository content read and a passing behavior-level acceptance test are different families, though neither alone proves all interpretations of a broad claim.

The policy should require a reference procedure where one exists. “Two signals” is a fallback evidence threshold, not a magic replacement for truth. It is **likely (55-80%)** that explicit evidence families will prevent correlated self-confirmation, because QUADAS-2 and FDA both treat knowledge/dependence between index and reference assessment as a bias risk ([QUADAS-2](https://www.ncbi.nlm.nih.gov/books/NBK305110/bin/10-45-04-app8.pdf); [FDA guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/statistical-guidance-reporting-results-studies-evaluating-diagnostic-tests-guidance-industry-and-fda)). Whether the proposed family taxonomy captures the dominant correlations is **UNVERIFIED; settle it with Experiment E2 by injecting shared-source errors and measuring joint misses across nominally separate checks**.

### 2.4 Proposal — base-rate- and consequence-aware escalation

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Maintain estimated false-claim prevalence and the 2×2 table by claim stratum. Choose escalation thresholds from expected loss:

`escalate when P(false | screen evidence, stratum) × consequence(false) > reference-audit cost`.

Do not use a universal confidence cutoff. Low-prevalence, low-consequence strata need higher-specificity alerts to preserve reviewer attention; rare catastrophic claims can justify escalation at low posterior probability. Report PPV beside recall so a flood of false alarms cannot masquerade as rigor.

It is **likely (55-80%)** that this will reduce wasted escalations at a fixed detection burden, because PPV depends on prevalence and CDC identifies low PPV as a cause of unnecessary investigations ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)). The loss values and attainable savings are **UNVERIFIED; settle them with Experiment E3, a preregistered replay comparing fixed-threshold and loss-based policies at equal weighted false-negative cost**.

### 2.5 Proposal — detector controls and sentinel claim packs

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Before interpreting “zero false claims,” run a small, versioned sentinel pack containing known-present errors and known-true controls through the full production path. Include quoting failures, wrong ref/path, stale-date facts, fabricated citations, success-with-missing-postcondition, arithmetic errors, and semantically broad claims supported only by narrow evidence. Vary surface form while preserving the known truth. Record detection, stage reached, latency, and whether the reference procedure—not merely the cheap screen—recovered the injected condition.

This directly copies HiFIDE’s use of injected known events in real background data ([CDC HiFIDE](https://www.cdc.gov/mmwr/preview/mmwrhtml/su5401a15.htm)). It is **very likely (80-90%)** to distinguish a quiet stream from a dead detector when the injected case traverses the identical production path, because a known-positive end-to-end control tests detectability rather than inferring it from natural event counts. Representativeness of any fixed pack is **UNVERIFIED; settle it with Experiment E4 by rotating mutations drawn from newly reference-confirmed production errors and tracking performance separately on frozen versus refreshed sentinels**.

### 2.6 Proposal — surveillance dashboard as an artifact, not an observability platform

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Produce a local periodic Markdown/JSON report from the line list:

* weighted prevalence and false-negative estimates with intervals;
* PPV, sensitivity, specificity, and unresolved rate by stratum;
* audit probability and effective sample size by stratum;
* sentinel-control detection and latency;
* verifier/version changes annotated on the timeline;
* disagreement and reference-procedure failure rates;
* cost per confirmed error and review minutes consumed.

Trend interpretation must be conditional on stable definitions and ascertainment. CDC warns that changed awareness, diagnostic tests, or surveillance methods can change sensitivity and create apparent trends that are artifacts ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)). The report therefore versions the claim definition, screen, reference procedure, and sampling policy with every metric.

It is **likely (55-80%)** that stratified, version-annotated reporting will reveal regressions hidden by aggregate pass rates, because surveillance guidance explicitly evaluates sensitivity by source/condition/time and warns about method-change artifacts ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)). Which strata are sufficiently populated is **UNVERIFIED; settle it during E1 by reporting effective sample size and suppressing estimates whose preregistered precision target is unmet**.

## 3. What this would catch that ordinary agent verification misses

1. **False negatives behind a clean dashboard.** Random audit of screen negatives supplies observed missed cases; alert-only review cannot.
2. **Verifier self-confirmation.** Blinded, claim-type reference procedures expose the difference between independent truth evidence and another model agreeing with the first model.
3. **Base-rate alert floods.** PPV by stratum reveals a detector that catches rare problems but consumes nearly all review on false positives.
4. **Broken detectors mistaken for safe operation.** Known-present sentinel errors must traverse the production path before absence of detected errors is interpretable.
5. **Scope and time laundering.** A cited statement true for one version, path, date, or population cannot automatically confirm a broader claim because scope and as-of time are fields in the case definition.
6. **“Done” inferred from process evidence.** A successful command is an index signal; an independently observed postcondition or acceptance test is the reference procedure.
7. **Metric drift after harness changes.** Versioned case definitions and ascertainment policies prevent an apparent improvement caused only by a narrower definition or lower audit intensity.
8. **Unknowns disguised as confirmations.** Claims without a defensible reference standard remain `unresolved`; agreement is reported as agreement.

Items 1–8 are expected catches, not measured properties of the current harness. Collectively they are **likely (55-80%)** to occur at least once in a sufficiently diverse prospective run because each corresponds to a recognized surveillance/test-evaluation bias or measurement artifact in the cited sources. Their current frequencies are **UNVERIFIED; Experiment E1 is the settling test**.

## 4. Prospective experiments that settle the unverified premises

### E0 — reference-procedure coverage and case-definition reliability

Sample 200 claims across task and consequence strata before looking at verifier outcomes. Two blinded adjudicators independently atomize and classify them under the proposed definitions; a third resolves disagreements. Record inter-rater agreement, time, and the fraction with a feasible reference procedure. Predefine a minimum acceptable agreement and coverage threshold before scoring. If high-value claims mostly lack reference procedures, stop: the design cannot honestly report accuracy for them.

### E1 — two-phase prospective claim audit (decisive experiment)

For a fixed run window:

1. enumerate the eligible claim population before audit;
2. freeze claim definitions, index checks, strata, audit probabilities, and random seed;
3. reference-audit every high-consequence/index-positive claim plus a probability sample of index negatives in every material stratum;
4. keep reference auditors blind to index verdict where operationally possible;
5. compute weighted A/B/C/D counts, intervals, unresolved rate, review cost, and effective sample size;
6. compare the measured false-negative estimate with the naive alert-only estimate;
7. preserve all failures, including inability to execute a reference procedure.

Success is not “the verifier found no errors.” Success is an estimable confusion matrix for eligible claims, an explicit unresolved population, and a cost curve. If a reference standard does not exist, report agreement only.

### E2 — correlated-error challenge

Inject errors that are shared across evidence sources: stale mirrored documentation, an incorrect path alias, a deceptive success string, two judges given the same false premise, and an acceptance test generated from the flawed implementation. Measure whether evidence-family rules prevent false confirmation. This tests the independence taxonomy rather than assuming differently named tools are independent.

### E3 — base-rate escalation replay

Replay identical indexed claims under (a) a global score threshold and (b) stratum prevalence × consequence policy. Hold reference results fixed. Compare review volume, weighted missed-error cost, PPV, and time-to-escalation. Do not tune and evaluate on the same replay window.

### E4 — sentinel detectability and anti-overfit

Maintain a frozen sentinel set for longitudinal comparability and a refreshed set derived from newly confirmed production errors. A detector must pass both. Frozen-only improvement with refreshed-set stagnation is evidence of sentinel overfit, not broad verification improvement.

## 5. Adversarial analysis: where the analogy breaks

### 5.1 “False claim” is often not a stable biological target condition

Disease status is not always simple, but many diagnostic studies can at least define a target condition independent of the test. Agent claims may be vague, normative, counterfactual, future-facing, or dependent on rapidly changing external state. Atomization and as-of timestamps reduce ambiguity; they do not eliminate it. Therefore the harness must not compute “sensitivity to falsehood” over subjective recommendations or unresolved predictions as though a gold standard existed.

### 5.2 The reference procedure can be fallible or circular

A second LLM, another web page copying the same source, or tests generated from the implementation can share the original error. Epidemiology calls attention to imperfect reference standards, incorporation bias, and non-blinded interpretation; the translation must do the same. Where only an imperfect comparator exists, the honest metric is agreement, not truth accuracy, following FDA guidance.

### 5.3 Claims are clustered and adaptive

Claims within one response share premises and citations, so they are not independent observations. An agent may also adapt to known checks. Naive binomial intervals will be too narrow, and a public sentinel pack can become a teaching set. Sampling and variance estimation should treat response/task as clusters; sentinel tests require both frozen and refreshed portions. The adequacy of cluster-adjusted precision at realistic volume is **UNVERIFIED; settle it in E1 with task-cluster bootstrap or survey-design intervals and report the resulting effective sample size**.

### 5.4 Verification may change the world being verified

A medical reference test usually measures a condition; an agent verifier may rerun commands that mutate state, fetch a page that changed, or “verify” completion by completing the missing work itself. Reference procedures must be read-only or isolated where possible, preserve pre-verification state, and distinguish observation from repair. Whether all important operational claims can be checked non-mutatively is **UNVERIFIED; E0 must inventory mutation risk per reference procedure**.

### 5.5 Representativeness is not automatic

Sentinel tasks and sampled claims describe only their defined population. They cannot justify “the harness is reliable” across unseen domains, tools, languages, or adversarial tasks. Epidemiological surveillance itself treats representativeness as a distinct system attribute ([CDC updated guidelines](https://www.cdc.gov/mmwr/preview/mmwrhtml/rr5013a1.htm)). All estimates must name the eligible population and strata; out-of-frame claims are a gap, not assumed negatives.

### 5.6 Rare catastrophic errors defeat simple sampling economics

A probability sample sized for common factual mistakes can miss extremely rare destructive errors. Consequence-weighted mandatory verification is needed for predefined catastrophic classes, even when the base rate is low. This is a policy overlay, not something sensitivity/specificity alone decides. The correct catastrophic-class definition and audit budget are **UNVERIFIED; settle them by owner loss elicitation plus red-team injection, not by fitting historical frequency alone**.

### 5.7 The analogy does not justify epidemiological theater

Renaming a verifier “surveillance,” drawing a 2×2 table without sampling negatives, or calling two correlated LLM votes independent adds no rigor. Nor does a dashboard compensate for an absent reference standard. The mechanism transfers only if the harness logs its claim population, samples apparent negatives with known nonzero probability, uses independent reference procedures where available, and reports unresolved cases honestly.

## 6. Anti-overfit and architecture gate

All six proposals pass the stated anti-overfit gate:

* they ride existing response hooks, skills, tool execution, and flat artifacts;
* the only persistent data is append-only JSONL plus a derived report;
* no second orchestration runtime is introduced;
* no vector database, knowledge graph, durable-execution engine, trained critic, guardrail framework, or observability SaaS is introduced;
* claim-class rules and sampling probabilities are configuration, not a growing agent bureaucracy;
* deterministic reference procedures are preferred over extra model calls;
* every aggregate metric can be recomputed from the line list.

The minimal viable implementation is the claim schema, stratified sampler, weighted 2×2 report, and sentinel control runner. If that cannot demonstrate useful detection per unit cost in E1, do not expand it. It is **likely (55-80%)** that this minimal layer can remain below roughly 200 lines per component because each component is simple parsing/sampling/accounting on the existing bus; this size estimate is **UNVERIFIED; settle it with a spike that implements only E1 and counts non-test source lines**.

## 7. Decision

Adopt the mechanism experimentally, not rhetorically. The core transfer is structurally sound because both domains have (a) a large stream of candidate units, (b) an imperfect cheap detector, (c) a more expensive reference procedure available for at least some units, (d) asymmetric costs of false positives and false negatives, and (e) a need to estimate unseen misses without exhaustive review. It fails wherever (c) is absent or where the claim population cannot be defined.

The go/no-go criterion should be empirical: proceed beyond a spike only if E0 finds adequate reference-procedure coverage in owner-important strata and E1 produces useful-width false-negative estimates at acceptable audit cost. This recommendation is **likely (55-80%)** to improve epistemic honesty even if it does not improve raw task success, because it forces unknowns, selection probabilities, reference limitations, and detector controls into the record; the effect on raw task success is **UNVERIFIED and must be measured as a separate E1/E3 outcome rather than inferred from verification metrics**.

The most important negative conclusion is equally firm: **do not treat multi-agent agreement as epidemiological confirmation**. Without an independent reference standard it is comparative agreement, and without probability auditing of apparent negatives it cannot establish sensitivity.
