# A139 — coherence audit: commands vs contracts / stale-reference

## Verdict

The 71 personal command files and both behavior-contract files are not fully coherent. The exhaustive scan found:

1. **One confirmed stale CLI form** in the contract: `claude skills` is not the documented Claude Code CLI inventory command; `/skills` is the current in-session command.
2. **One confirmed Windows detector conflict**: `metaswarm-setup.md` explicitly requires Bash `which`, while the contract's mandatory Windows rule requires PowerShell `Get-Command` because `which` misses `.cmd` shims.
3. **One confirmed five-file command-identity family defect**: the filenames create `/multi-plan`, `/multi-execute`, `/multi-workflow`, `/multi-backend`, and `/multi-frontend`, but their bodies tell the user to invoke `/ccg:plan`, `/ccg:execute`, `/workflow`, `/backend`, and `/frontend`.
4. **One UNVERIFIED current-Windows transport candidate with strong historical evidence**: the same five `multi-*` commands require a legacy `~/.claude/bin/codeagent-wrapper` and `.ccg/prompts/**`; the pinned earlier audit records direct Windows `Test-Path=False` for all three roots, while the current contract and settings select native Codex MCP. The remote bundle is partial and cannot independently prove that those Windows-only paths are still absent today.
5. **One UNVERIFIED current-Windows stale-environment candidate with corpus-proven historical failures**: both contract and commands prescribe `tmux` on a Windows PowerShell/Git-Bash box; the corpus contains eight Agent failures saying WSL/tmux was required. The bundle cannot prove whether WSL/tmux was installed after those failures.

The confirmed fixes are small command/contract text edits. No new runtime, daemon, memory system, critic, observability service, durable-execution engine, or guardrail framework is warranted. Every proposed edit rides Claude Code's existing command/skill or native tool bus and passes the anti-overfit gate.
