# X052 — Control theory → cross-session agent memory

**Unit:** X052  
**Lens:** control-theory observability/controllability, innovation feedback, anti-windup, and dead-band design  
**Target:** what an agent should remember across sessions, when it should forget, and how it can detect staleness  
**Date:** 2026-07-19

## Scope and verdict

This is deliberately an external-research and ideation unit. Per the unit instruction, I did **not** inspect or make claims about the local harness implementation. The proposals below therefore describe a harness-independent design and experiments, not a finding that a particular component is currently absent or broken.

The borrow transfers, but only at the level of four mechanisms and their failure disciplines:

1. **Observability:** a hidden state is useful to estimate only to the extent that available outputs can distinguish it.
2. **Innovations/residual monitoring:** predict an observation from the current state estimate, compare the real observation with that prediction, and treat persistent, statistically surprising residuals as model mismatch or a fault.
3. **Anti-windup:** when the actuator cannot apply a controller's requested action, stop or unwind accumulated integral state rather than allowing hidden error to grow.
4. **Event thresholds, hysteresis, and targeted forgetting:** update only on informative changes, use different thresholds for entering and leaving a state, and forget only the parameters meant to track change.

The literal mathematics does **not** transfer wholesale. An agent memory is not generally a linear dynamical state; text observations are not Gaussian sensor readings; facts have heterogeneous change rates; source dependence is difficult to measure; and an agent usually cannot excite its environment arbitrarily just to identify it. A numerical “memory Kalman filter” would therefore manufacture precision. The defensible product is a small, provenance-aware memory state machine inspired by control theory—not a generic estimator runtime.

**Overall judgment:** it is **very likely (80-90%)** that innovation-triggered revalidation plus anti-windup deduplication is a useful transfer, because the structural requirements it needs—an expectation, a later observation, provenance, and a corrective update—exist for many operational memories, while the cited fault-detection and anti-windup mechanisms address the same shapes of mismatch. This remains **UNVERIFIED; the settling experiment is the mutation-and-replay study in “Evaluation plan,” comparing stale-memory use and false invalidation against timestamp-only and append-only baselines.**

It is **unlikely (20-45%)** that a literal Kalman filter or observability/controllability matrix would improve a general agent memory, because those constructs require a specified state-transition and observation model that free-form tasks do not supply. The settling experiment would fit such a model to one narrowly typed memory class and test out-of-sample residual calibration; absent calibration, it should not ship.

## What control theory solved in its own field

### 1. Observability and controllability are structural tests, not confidence scores

For the linear discrete system

```text
x(k+1) = A x(k) + B u(k)
y(k)   = C x(k)
```

the internal state is observable over a finite horizon when distinct initial states produce distinguishable output histories. In the standard finite-dimensional linear test, the stacked observability matrix `[C; CA; ...; CA^(n-1)]` must have full column rank. Controllability is the dual reachability question: can admissible inputs drive the state where it must go? Its standard matrix `[B, AB, ... A^(n-1)B]` must have full row rank. Kalman's foundational treatment made these state-space properties central and explicitly connected state reconstruction, feedback, and canonical decomposition ([Kalman, “On the General Theory of Control Systems,” 1960](https://doi.org/10.1016/S1474-6670(17)70094-8)).

Two distinctions matter for memory:

- Observability is not “we logged something.” It asks whether the measurements contain enough independent information to distinguish hidden alternatives.
- Controllability is not “we can write the database.” It asks whether available actions can actually change the relevant state, subject to constraints.

An unobservable mode can evolve without appearing in the measured outputs. No observer algorithm can reconstruct that mode from the same inadequate measurements. Likewise, a state component outside the controllable subspace cannot be steered merely by selecting a more sophisticated controller. These are impossibility diagnostics: improve sensing/actuation or narrow the claim.

### 2. The innovation sequence turns expectations into fault evidence

Kalman's filtering formulation recursively predicts state, predicts an observation, and then corrects the state estimate from the discrepancy between predicted and observed measurements ([Kalman, “A New Approach to Linear Filtering and Prediction Problems,” 1960](https://doi.org/10.1115/1.3662552)). In common notation:

```text
innovation:       v(k) = y(k) - H x_hat(k|k-1)
innovation cov.:  S(k) = H P(k|k-1) H' + R
normalized score: NIS  = v(k)' S(k)^(-1) v(k)
```

Under the assumed linear-Gaussian model, the innovation is the new information not predicted by prior measurements, and its covariance states how surprising that discrepancy should be. A large normalized innovation is evidence that a measurement, noise model, or system model is inconsistent with expectation—not automatic proof of which one failed.

Mehra and Peschon translated this innovation view directly into dynamic-system fault detection and diagnosis: model-consistent residual behavior is the baseline; changes in innovation statistics are evidence of abnormality ([“An innovations approach to fault detection and diagnosis in dynamic systems,” 1971](https://doi.org/10.1016/0005-1098(71)90028-8)). Persistent small shifts can be accumulated rather than requiring a single extreme sample. Page's sequential change-detection work and the later CUSUM formulation implement this by accumulating one-sided deviations, resetting accumulation when evidence points back toward normal ([Page, “Continuous Inspection Schemes,” 1954](https://doi.org/10.1093/biomet/41.1-2.100); [NIST CUSUM description](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc323.htm)).

The important control-theory lesson is not “use a magic threshold.” It is:

1. make the current state predict something checkable;
2. retain expected uncertainty;
3. compare the prediction with later evidence;
4. accumulate coherent discrepancies;
5. distinguish detection from diagnosis.

### 3. Anti-windup prevents hidden accumulation when the loop is constrained

Integral control accumulates error so that persistent offset is eventually removed. But when an actuator saturates, the requested control and the applied control diverge. A naïve integrator continues accumulating error even though additional requested action cannot be applied. When the plant finally re-enters the controllable region, the oversized integral state produces overshoot and slow recovery: integrator windup.

Classical anti-windup remedies include **conditional integration** (freeze or limit the integrator while saturated in the harmful direction) and **back-calculation** (feed the difference between requested and applied control back into the integrator so its internal state tracks what the actuator could actually do). Åström and Rundqwist analyze this failure and practical avoidance methods in [“Integrator Windup and How to Avoid It” (1989)](https://doi.org/10.23919/ACC.1989.4790464).

The transferable invariant is exact: internal accumulated belief must not continue increasing when the external channel cannot supply new corrective information. Ten repetitions of one copied assertion are not ten independent measurements. If a memory's confidence or salience “integrates” every mention, retrieval repetition and copied sources can wind it up.

### 4. Event-triggering and dead bands trade chatter for delayed response

Event-triggered control does not run a controller or transmit a sample solely because a clock tick occurred. It evaluates a state-dependent condition and triggers when the error threatens a bound. Tabuada provides conditions under which event-triggered executions retain stability while reducing executions/communications ([“Event-Triggered Real-Time Scheduling of Stabilizing Control Tasks,” 2007](https://doi.org/10.1109/TAC.2007.904277)).

A dead band suppresses action for deviations smaller than a threshold. Hysteresis uses different transition thresholds in opposite directions, preventing noisy measurements near one boundary from switching a controller rapidly back and forth. These devices reduce chatter and cost, but deliberately make the system insensitive to small changes. They are appropriate only when the tolerated error is explicit.

### 5. Forgetting factors support tracking, but blunt decay is structurally dangerous

Recursive identification commonly discounts old observations so an estimator can track changing parameters. With exponential forgetting, an observation's weight decreases geometrically; this improves adaptation to drift but discards information even when a parameter has not changed. Johnstone and Anderson analyze recursive least squares with an exponential forgetting factor in an adaptive-control setting ([1982 paper](https://doi.org/10.1016/S0167-6911(82)80013-3)). Later work proposes **targeted** forgetting rather than inflating uncertainty in all parameter directions ([Goel and Bernstein, “A Targeted Forgetting Factor for Recursive Least Squares,” 2018](https://doi.org/10.1109/CDC.2018.8619181)).

The transferable lesson is not “delete after N days.” It is “attach forgetting to the dimensions that can change and to evidence of insufficient excitation.” A compiler flag, current service endpoint, and owner's enduring preference do not share one half-life.

## Structural transfer test: where the analogy holds and where it breaks

| Control-loop assumption | Agent-memory analogue | Transfer verdict |
|---|---|---|
| There is hidden state that affects future outputs. | A durable assertion influences later plans, tool choices, and answers. | Holds for memories that actually change behavior. |
| The estimator can predict an observation distribution. | A memory can declare what later evidence would confirm or contradict it. | Holds for typed operational facts; it is **unlikely (20-45%)** to be dependable for vague summaries and interpretations because they lack a typed comparator. **UNVERIFIED; settle with reviewer-labeled prediction/observation pairs by memory type.** |
| Measurements have known noise statistics. | Sources have reliability, independence, and authority. | Only ordinally. Exact covariance is generally unavailable; do not emit pseudo-probabilities. |
| Dynamics are specified and reasonably stationary. | A fact has a change model or hazard class. | Partial. External facts drift discontinuously and user intent can change without warning. |
| Inputs are known; applied action is measurable. | The harness knows which memory it retrieved and what action actually occurred. | **Likely (55-80%)** to be instrumentable for tool-mediated actions because retrieval and result events can share a record ID, but **UNVERIFIED; settle by tracing memory IDs from retrieval through tool/action results in a shadow run.** |
| The system can be persistently excited. | The agent can query/check a fact often enough to identify change. | **Unlikely (20-45%)** to hold across all memory types because checks have cost, permissions, side effects, or no authoritative endpoint. **UNVERIFIED; settle by measuring validator availability and safe-call coverage in a stratified memory sample.** |
| Residual means a fault exists somewhere in model/sensor/plant. | Contradiction means memory, source, scope, or interpretation may be wrong. | Holds. It does not identify the guilty element without diagnosis. |
| State/action spaces are numeric and closed. | Natural-language claims have ambiguous scope and entailment. | Does not hold generally. Typed records and explicit comparators are required. |

The analogy therefore transfers for **typed, operational, re-observable memories**, such as a command's supported option, a project convention, a service endpoint, a user preference with explicit scope, or an environment capability. It does not cleanly transfer to autobiographical summaries, speculative intentions, aesthetic judgments, or facts with no accessible validator.

Most importantly, control theory predicts a hard limit: a stale memory that is never exercised and has no independent observation is unobservable. No scoring rule can detect its staleness. The honest response is to mark it “age-unknown / unobservable,” avoid high-impact autonomous use, or acquire a new observation.

## Recommendation — UNVERIFIED: build a small innovation-gated memory observer

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

The recommendation is **UNVERIFIED; settle it with the mutation-and-replay experiment below before enabling automatic demotion.** It is **likely (55-80%)** to catch stale operational memories earlier than TTL-only expiry, because it reacts to semantic mismatch at use time while retaining stable old facts; the evidence is the successful use of innovation residuals for model/fault mismatch and the structural availability of predictions and later observations in the typed subset. The wide confidence band reflects unknown comparator accuracy and unknown frequency of re-observation.

Do not build a daemon, vector database, knowledge graph, second orchestrator, durable-execution engine, trained critic, observability SaaS, or guardrail framework. Implement one deterministic library plus existing-bus hooks around the current memory write/retrieve path. Storage can remain the harness's existing durable text/JSON mechanism.

### A. UNVERIFIED — require a memory contract at promotion time

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

A durable record should contain at least:

```json
{
  "id": "stable-id",
  "claim_type": "preference|capability|location|procedure|constraint|fact",
  "scope": "where/when/for-whom this claim applies",
  "value": "typed value or concise assertion",
  "provenance": [{"source_id": "...", "observed_at": "...", "family": "..."}],
  "hazard": "stable|session|release-bound|externally-volatile|unknown",
  "expected_observation": "what should be seen if still true",
  "comparator": "exact|set|version|exit-status|human-confirmation|semantic-review",
  "revalidate": "on-use|on-boundary|manual|cannot-observe",
  "state": "candidate|active|suspect|quarantined|superseded",
  "supersedes": [],
  "contradiction_score": 0
}
```

Promotion from a session note to durable memory requires scope, provenance, hazard class, and either a validator or an explicit `cannot-observe`. The latter is not banned; it is prevented from masquerading as current knowledge.

This gate is **very likely (80-90%)** to reduce scope-free memories, because required structural fields make omission mechanically detectable. It is **UNVERIFIED; settle by applying the schema to a stratified sample of historical candidate memories and measuring reject rate, reviewer agreement, and lost-useful-memory rate.** Increased write friction is **likely (55-80%)** because promotion requires more fields; **UNVERIFIED; settle by measuring completion time and abandonment against the current write flow.** The hook should offer defaults but must never invent a validator.

### B. UNVERIFIED — treat retrieval as a prediction and tool results as observations

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

When an active memory affects a plan, emit its `id` with the action trace. If a later result is comparable, create an innovation event:

```text
match              -> residual 0
ambiguous/noisy     -> residual unknown; do not update
scoped contradiction-> residual 1 for that scope
authoritative change-> residual 1 plus candidate replacement
```

Do not calculate NIS unless a particular memory type has empirically calibrated error probabilities. Use ordinal evidence by default. A contradiction opens diagnosis: was the old record wrong, did its scope not match, did the environment change, or is the new source unreliable?

A one-off weak contradiction moves `active → suspect`; a repeated or authoritative contradiction moves `suspect → quarantined`; independently corroborated new evidence creates a replacement and moves the old record to `superseded`. Retrieval should disclose suspect status and exclude quarantined records from autonomous high-impact actions.

This mechanism is **likely (55-80%)** to catch endpoint drift, renamed commands/paths, changed capabilities, release-bound procedures, and updated preferences when they are next used, because each creates an observable mismatch between the remembered expectation and a current result. This is **UNVERIFIED; settle by injecting those mutations into replay tasks and measuring detection before harmful reuse.** It is **very unlikely (5-20%)** to detect a stale record that is never retrieved or has no observable consequence, because that mode supplies no residual; the evidence is the observability disanalogy above.

### C. UNVERIFIED — add anti-windup to confidence and salience

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Count evidence families, not mentions. Repeated retrieval, the model restating its own memory, duplicated pages, and retry-loop outputs from one underlying source must not raise confidence. Cap the contribution from one family. When a write is rejected by the durable-memory gate, feed that rejection back to the candidate accumulator so repeated attempts do not make the candidate more salient. Allow confidence to rise only on a new independently acquired source family or explicit owner confirmation.

This is the direct anti-windup mapping:

```text
control request       = candidate confidence increment
actuator saturation   = no independent evidence / write gate refuses promotion
actual applied control= accepted independent evidence
back-calculation      = subtract or freeze the unsupported increment
```

This proposal is **very likely (80-90%)** to prevent confidence inflation caused by exact retries and self-citation, because those cases can be deduplicated with stable source/event IDs rather than semantic judgment. It is **UNVERIFIED; settle by replaying retry loops and self-referential summaries, asserting that confidence and salience remain invariant under duplicated events while rising for a separately acquired source.** Detecting subtly dependent web sources is only **unlikely (20-45%)** to be reliable, because syndication and shared upstream sources may not be visible; settle that premise with a labeled source-dependence set. Unknown dependence should not be represented as independence.

### D. UNVERIFIED — use hysteresis for state transitions, not for truth

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Configure distinct promotion and demotion thresholds. For example, an experimental policy can require two independent positive observations for `candidate → active`, while one strong contradiction produces `active → suspect` and a fresh confirming observation is required for the reverse transition. Exact thresholds must be learned per memory class; these numbers are illustrative, not defaults.

Hysteresis is **likely (55-80%)** to reduce active/suspect flapping around ambiguous evidence, based on its control role in suppressing chatter. This is **UNVERIFIED; settle by replaying alternating weak supports/contradictions and comparing transition count and final classification to expert labels.** It can delay recognition of a true change, so high-authority explicit corrections must bypass the dead band and create a scoped supersession immediately.

### E. UNVERIFIED — prefer targeted expiry to global forgetting

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Map hazard class to behavior rather than one TTL:

| Hazard class | Memory behavior |
|---|---|
| `session` | Do not promote unless explicitly converted. |
| `release-bound` | Revalidate when the relevant version boundary changes. |
| `externally-volatile` | Revalidate on first consequential use after a bounded age. |
| `stable` | Retain; demote on innovation, not age alone. |
| `unknown` | Surface uncertainty and require validation for consequential use. |
| `cannot-observe` | Retain provenance but never imply freshness. |

Targeted expiry is **likely (55-80%)** to preserve stable useful memories better than universal time decay while still challenging volatile ones, because adaptive-control research shows both the value of forgetting for tracking and the motivation for applying it selectively. This is **UNVERIFIED; settle by backtesting multiple hazard policies on time-sliced memory records with later ground truth, optimizing stale-use and needless-revalidation costs separately.**

## What the design catches—and what it intentionally does not

### Expected catches (all prospective)

- **Contradiction at point of use:** remembered tool capability predicts success; current structured result says unsupported.
- **Scope drift:** a convention remembered globally conflicts only in a particular repository/version, prompting scope split rather than global deletion.
- **Copied-error amplification:** retry loops and self-summaries cannot turn one bad source into apparently strong consensus.
- **Change hidden by timeless wording:** “the endpoint is X” becomes a volatile, observed-at claim with an on-use check.
- **Memory flapping:** one noisy result makes a claim suspect without immediately erasing it; a later clean result does not silently toggle it repeatedly.
- **Unmaintainable memory:** a record with no possible observation or correction path is labeled as such before high-impact reliance.

These catches are collectively **likely (55-80%)** for typed operational memories, based on the mechanism match, but **UNVERIFIED; the mutation-and-replay experiment below settles each failure class separately.**

### Non-goals and unavoidable misses

- It cannot detect silent staleness without a new observation.
- It cannot infer source independence perfectly.
- It cannot decide whether a contradiction indicts the memory, the observation, the scope, or the comparator without diagnostic evidence.
- It should not automatically erase disputed human preferences or autobiographical facts.
- It does not make a free-form semantic claim numerically calibrated merely by assigning a score.
- It does not solve retrieval ranking in general; it only supplies freshness/provenance state that a retriever can use.

## Evaluation plan: the experiment that settles the recommendation

Run in shadow mode; no automatic memory mutation during evaluation.

### Dataset and baselines

1. Sample historical cross-session memories by type and hazard, preserving time order.
2. Create controlled mutations: endpoint/path rename, capability removal, version boundary, preference correction, scope exception, transient tool failure, duplicated retry evidence, and mutually dependent copied sources.
3. Compare:
   - append-only memory;
   - age/TTL-only memory;
   - the proposed contract + innovation + anti-windup state machine;
   - an oracle using known mutation times and expert scope labels.

### Primary measures

- stale-memory uses before detection;
- detection delay measured in **opportunities to observe**, not wall-clock time;
- false quarantine and false supersession rates;
- needless revalidation calls and latency;
- useful-memory rejection at promotion;
- transition chatter per record;
- confidence change under duplicated versus independent evidence;
- fraction of records classified `cannot-observe` or `unknown`;
- inter-reviewer agreement on contradiction and scope labels.

### Two-signal acceptance rule

Do not claim the mechanism catches a failure class from its own state transition alone. Require two mechanically independent signals:

1. the deterministic state-machine trace identifies the injected mutation or labeled contradiction; and
2. an outcome-level replay shows that the stale memory is withheld/disclosed before the formerly harmful action, or an independent reviewer confirms the correct scoped replacement.

Validate the detector with known-present controls before measuring absence: every test batch must contain injected contradictions, duplicated evidence, and stable unchanged memories. A run reporting no contradictions is invalid unless it detects the injected controls. Likewise, do not declare anti-windup done merely because duplicate IDs are ignored; independently verify that confidence remains unchanged in the externally recorded memory state while a genuinely independent observation raises it.

### Shipping gates

Permit the state machine to mark `suspect` automatically only after replay demonstrates lower stale-memory use without an unacceptable false-suspect rate chosen by the owner. Automatic quarantine/supersession needs a stricter, separately measured gate. Thresholds are per memory type; there is no global magic number.

The proposal would be **very likely (80-90%)** safe to trial in shadow/read-only mode because it makes no durable decisions, while benefit remains **roughly even (45-55%)** until replay establishes how often current tool results provide reliable comparators. The safety judgment is supported by the non-mutating experiment design; the benefit uncertainty is settled by comparator coverage and labeled outcome measures in that same experiment.

## Alternatives considered and rejected

### Full Kalman filter over all memories — reject

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification).**

This would violate the anti-overfit gate by adding a second state-estimation runtime and would require invented dynamics, covariances, and numeric encodings for text claims. It is **unlikely (20-45%)** to be calibrated enough to justify its complexity, because the core linear-Gaussian and known-model assumptions fail. Reconsider it only for a narrowly typed subsystem after out-of-sample calibration.

### Vector database or knowledge graph as “state space” — reject

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification).**

Neither storage topology provides observations, validators, or update reachability. This explicitly reintroduces components barred by the anti-overfit gate and does not solve the target mechanism. Similarity is not freshness; edges are not independent evidence.

### Universal TTL / exponential decay — reject

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

It is simple but forgets timeless truths merely because time passed. It is **likely (55-80%)** to preserve at least some fast-changing facts until after they become stale whenever the configured TTL exceeds their change interval; that follows directly from timer-only detection, and **UNVERIFIED; settle by comparing fact-change times with TTL firing times in replay.** Use hazard-targeted revalidation instead. TTL remains suitable for explicitly session-scoped or lease-like facts.

### Proactive universal refresh daemon — reject

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification).**

It violates the anti-overfit gate, consumes permissions and external calls, and still cannot validate unobservable claims. Boundary- or use-triggered checks ride existing activity and are enough for the proposed experiment.

### LLM-only semantic contradiction judge — reject as sole detector

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

An LLM is **likely (55-80%)** to help triage ambiguous records because it can compare natural-language scope and entailment, but this is **UNVERIFIED; settle with a blinded labeled contradiction set and report calibration by claim type.** Automatic state transitions still need typed comparators or explicit human confirmation. Otherwise the same model can generate, restate, and “independently” validate its own error. Semantic review should return `ambiguous` freely and must preserve both sources.

## Gaps and boundaries

- No local harness or repository was examined, by explicit unit instruction. Therefore this artifact does not claim which memory bus, hooks, schemas, or stores exist.
- Source literature establishes mechanisms in control and estimation, not their empirical effectiveness for agent memory. Every recommended transfer is marked **UNVERIFIED** with its settling experiment inline.
- Exact false-positive costs, comparator coverage, source-family identifiers, and memory-type distribution are unknown. They must be measured before choosing thresholds.
- The term “confidence” here means an ordinal operational evidence state unless a typed domain supplies calibrated probabilities. It must not be presented as a general probability of truth.
- The design intentionally does not attempt to remember everything. A record that cannot predict any future decision or observation may still be valuable narrative context, but it is outside the control-theoretic freshness mechanism.

## Final design rule

Remember a claim across sessions only with its scope, provenance, change hazard, and a declared route for observation or explicit unobservability. On consequential use, let the memory predict what current evidence should look like. Treat surprising evidence as a residual requiring diagnosis, accumulate only independent residuals, and prevent repeated unsupported mentions from winding up confidence. Forget selectively by hazard or supersession—not by undifferentiated age. If a claim is neither observable nor correctable, lower autonomous reliance rather than pretending a better estimator can rescue it.
