# X013 — Cross-domain borrow: intelligence tradecraft → agent-harness reliability

**Unit:** X013  
**Lens:** IDEATION, deliberately not grounded in the local subject/repository  
**Date:** 2026-07-18  
**Target failure:** an agent confidently reports an absence, breakage, or completion from one unvalidated probe. The supplied X013 brief says this occurred at least six times in one session; that count is treated as pinned ground truth, not independently re-measured here.

## Executive judgment

The analogy transfers, but only in a narrow form. The useful borrow is a compound proof discipline already present in intelligence tradecraft:

1. **Separate the reliability of the collector/source from the credibility of this particular report.** A reliable sensor can produce a bad observation; a poorly characterized sensor can produce a true one.
2. **Corroborate consequential reporting with genuinely independent sources while detecting circular reporting.** Two displays backed by the same collection path are one signal, not two.
3. **Evaluate the live conclusion against a small set of competing explanations, including collection failure, and prefer diagnostic/disconfirming evidence.** “I found nothing” must compete with “my detector could not see it.”
4. **Communicate proposition likelihood separately from the soundness of the evidentiary foundation, and state what observation would change the judgment.**

This is not a recommendation to import intelligence bureaucracy, an A–F/1–6 score, or the full Analysis of Competing Hypotheses (ACH) matrix into every agent turn. It is a recommendation to install a small **Agent Analytic Proof Gate** only at high-risk epistemic boundaries: claims that something is absent, broken, or done, and other claims that authorize destructive or externally consequential actions.

**Transfer judgment: very likely (80-90%).** Evidence: UK defence doctrine explicitly identifies technical constraints, sensor artefacts, human error, and interpretation bias as reasons collection can be inaccurate; requires source reliability and report credibility to be evaluated separately; prefers corroboration; and warns about circular reporting ([JDP 2-00, 4th ed., §§3.39–3.40, pp. 59–60](https://assets.publishing.service.gov.uk/government/uploads/system/uploads/attachment_data/file/311572/20110830_jdp2_00_ed3_with_change1.pdf)). Those are structurally the same failure classes as a scoped, misconfigured, stale, truncated, or misinterpreted software probe. The remaining uncertainty is implementation behavior: whether a lightweight gate changes agent conduct without excessive bypass or latency. That premise is **UNVERIFIED; the settling experiment is the shadow-mode/replay A/B evaluation specified below.**

**Expected defect reduction: likely (55-80%).** Evidence: every target error definition supplied in the brief contains the precise preconditions the gate checks—single probe, unvalidated detector, and overconfident conclusion—while intelligence doctrine supplies the corresponding controls. This is not a measured effect size for an agent harness. It is **UNVERIFIED; replay the known correction cases and a held-out set, scoring caught false conclusions and nuisance interventions, to settle it.**

## What intelligence tradecraft solved in its own field

### 1. The Admiralty/NATO two-axis evaluation: source reliability is not report credibility

The NATO Intelligence Grading System, often called the Admiralty Code, records two distinct judgments in one digraph. UK doctrine gives source reliability as A–F and information credibility as 1–6. It explicitly notes that the ratings need not match: a usually reliable source can provide improbable information (B5), while an unreliable source can provide confirmed information (E1). “Cannot be judged” does not mean useless; it means the evaluator lacks enough evidence to make that judgment ([JDP 2-00, 4th ed., §3.40 and Table 3.1, pp. 60–61](https://assets.publishing.service.gov.uk/government/uploads/system/uploads/attachment_data/file/311572/20110830_jdp2_00_ed3_with_change1.pdf)).

The field-level reason is important. Source reliability is a property inferred from access, capability, limitations, motivation, and reporting history. Information credibility is a property of the specific report, assessed internally for factual/logical problems and externally through corroboration. Doctrine says to revisit both over time because a previously reliable source can be wrong and a usually unreliable source can sometimes be right ([JDP 2-00, 4th ed., §3.39, pp. 59–60](https://assets.publishing.service.gov.uk/government/uploads/system/uploads/attachment_data/file/311572/20110830_jdp2_00_ed3_with_change1.pdf)).

This distinction prevents a common category error: “the sensor/tool usually works” is not evidence that this output is correct. Conversely, “this tool has failed before” does not disprove a result independently confirmed elsewhere.

The code itself is not sacred. A 2025 experimental paper describes a known tendency for evaluators to collapse the two dimensions onto matching diagonal ratings and reports that professional analysts and nonexperts showed similar consistency patterns. The authors question whether evaluators can treat the dimensions as fully independent ([Mandel et al., *Judgment and Decision Making*, 2025, §§2 and discussion](https://www.cambridge.org/core/journals/judgment-and-decision-making/article/effect-of-source-reliability-and-information-credibility-on-judgments-of-information-quality-in-intelligence-analysis/E67548E8010A47345C3439D45D9EC6B3)). Therefore the transferable object is the **separation of questions and preservation of provenance**, not an alphanumeric grade.

### 2. Corroboration plus circular-reporting control

UK doctrine states that report credibility is usually best assessed by corroboration from sources that can confirm or disconfirm it. In the same paragraph it warns analysts not to discard contradictions and to remain alert to circular reporting ([JDP 2-00, 4th ed., §3.39(b), p. 60](https://assets.publishing.service.gov.uk/government/uploads/system/uploads/attachment_data/file/311572/20110830_jdp2_00_ed3_with_change1.pdf)). The mechanism is not “count agreeing reports.” It is “seek another collection lineage and ask whether it could fail for the same reason.”

This matters because apparent multiplicity can be fake. A newspaper, briefing, and database entry may all descend from one witness. Agreement then adds presentation layers, not evidence. Intelligence tradecraft preserves source lineage precisely so an analyst can discount this false corroboration.

### 3. ACH’s useful kernel: make collector failure a competing hypothesis and seek diagnostic evidence

Richards Heuer’s ACH procedure asks the analyst to enumerate plausible hypotheses, list evidence for and against them, assess which evidence discriminates among them, try to disprove hypotheses rather than prove a favorite, test sensitivity to critical evidence, report relative likelihood, and identify future indicators ([Heuer, *Psychology of Intelligence Analysis*, Chapter 8, especially the step-by-step outline on pp. 96–97](https://www.cia.gov/resources/csi/static/9a5f1162fd0932c29bfed1c030edf4ae/Pyschology-of-Intelligence-Analysis.pdf)).

Heuer’s key concept is **diagnosticity**: evidence is valuable to the extent that it changes the relative likelihood of competing explanations. Evidence compatible with every hypothesis adds little. He uses fever as an example: it indicates illness but poorly distinguishes which illness. He also argues for seeking refutation because people naturally look for confirming evidence and discount disconfirmation ([Heuer, Chapter 4, pp. 44–46](https://www.cia.gov/resources/csi/static/9a5f1162fd0932c29bfed1c030edf4ae/Pyschology-of-Intelligence-Analysis.pdf)).

For the target harness failure, the decisive change is to stop treating a null tool result as a conclusion. It is evidence to compare against at least these hypotheses:

- H1: the target is genuinely absent/broken/incomplete;
- H2: the detector is invalid for this environment or target;
- H3: the detector’s scope is wrong (directory, branch, account, namespace, time window, hidden/ignored files);
- H4: the acquisition/output path lost information (permissions, truncation, parsing, cache, timeout, transport error);
- H5: the target exists under a different representation (renamed item, generated state, remote-only path, alias, shim, indirection).

A known-present control is highly diagnostic between H1 and H2/H3/H4. A second probe with an independent acquisition and interpretation path is diagnostic between “target state” and “shared detector failure.” Re-running the same command is normally weak because it is consistent with both a real absence and a deterministic detector defect.

### 4. Sherman-Kent/modern analytic standards: calibrated conclusion plus foundation quality

Sherman Kent argued for a small, consistent vocabulary that maps estimative words to understood odds, because readers otherwise assign different meanings to words such as “probable” ([Kent, “Words of Estimative Probability”](https://www.cia.gov/resources/csi/static/Words-of-Estimative-Probability.pdf)). Modern ODNI standards require analysts to explain uncertainty, its causes, the quality and quantity of sources, assumptions, and indicators that would alter the judgment. They also require facts, assumptions, and analytic judgments to be distinguished and plausible alternatives to be assessed ([ODNI ICD 203, 21 December 2022, Analytic Tradecraft Standards 1–4, pp. 3–5](https://www.odni.gov/files/documents/ICD/ICD-203_TA_Analytic_Standards_21_Dec_2022.pdf)).

The UK’s current public explanation makes the second distinction especially clear: probability is the likelihood that a statement is true, while analytical confidence is the soundness and stability of the foundation. Its confidence statement names the source and effect of remaining uncertainty and, where appropriate, how confidence could be increased ([UK PHIA, “Explaining uncertainty in UK intelligence assessment,” 2025](https://www.gov.uk/government/publications/explaining-uncertainty-in-uk-intelligence-assessment/explaining-uncertainty-in-uk-intelligence-assessment)).

For the harness, a conclusion can therefore be “likely absent” while the foundation remains weak because the detector was not validated. The correct outward behavior is not to suppress the best current judgment; it is to label it **UNVERIFIED** inline and name the next discriminating experiment.

## Concrete translation to an agent harness

## Proposal — UNVERIFIED pending replay/shadow experiment: Agent Analytic Proof Gate

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Implement one small pre-response validator on the existing hook bus. It consumes a compact evidence ledger emitted by the agent/tool wrapper; it does not orchestrate tasks, store semantic memory, call another model, or run tools itself. It returns either `pass`, `warn`, or `block-and-request-evidence` for a narrow class of claims.

### Trigger boundary

Run the gate only when the draft contains a consequential epistemic predicate, initially:

- absence: `absent`, `does not exist`, `no`, `none`, `zero`, `not found`, `not installed`, `not configured`;
- failure: `broken`, `dead`, `disabled`, `never fired`, `unreachable`;
- completion: `done`, `complete`, `fixed`, `verified`, `all tests pass`, `successfully deployed`;
- destructive authorization based on state: `safe to delete`, `unused`, `orphaned`, `duplicate`.

Lexical matching alone is intentionally not the decision procedure. The agent marks a claim as `observation`, `assumption`, or `judgment` in a tiny structured block; the hook checks only marked judgments plus high-risk phrases as a backstop. This avoids turning normal prose containing “no” into constant friction.

### Evidence ledger schema

For every triggered claim, retain only turn-local or session-local structured records:

```yaml
claim_id: c17
claim: "No live skill uses directory D"
claim_type: absence
likelihood_band: likely
evidence:
  - probe_id: p1
    collector: rg
    acquisition: filesystem-content
    parser: ripgrep
    scope: "/explicit/root, tracked+untracked, hidden policy stated"
    result: "0 references"
    exit_status: 1
    control:
      target: "/known/present/reference"
      expected: present
      observed: present
  - probe_id: p2
    collector: manifest-enumerator
    acquisition: manifest-graph
    parser: json
    scope: "/explicit/manifests"
    result: "0 edges to D"
independence:
  shared_acquisition: false
  shared_parser: false
  shared_cache: false
  shared_scope_derivation: false
alternatives_checked:
  - "reference exists outside searched content"
  - "runtime resolves D through alias/indirection"
settling_observation: "instrument one live resolution pass and record resolved paths"
```

Do not assign a single numeric “reliability score.” Store inspectable attributes: collector identity/version, acquisition path, parser, scope, exit status, truncation/error flags, freshness, and control outcome. This retains the Admiralty distinction without recreating its diagonal-rating problem.

### Mechanical proof obligations

For an `absence`, `broken`, or `done` judgment to pass unqualified, require all of the following:

1. **Detector control:** the same detector invocation pattern finds a known-present item within the claimed scope, or an equivalent positive control proves the relevant capability. A control outside the relevant scope does not count.
2. **Two mechanically independent signals:** independence must differ at a failure-bearing layer, such as acquisition path, underlying data field, parser, environment, or consumer behavior. A different textual command over the same cached index is not independent. Repeating the same probe is not independent.
3. **No silent tool degradation:** no unhandled timeout, truncation, permission denial, parse error, transport failure, stale snapshot, or ambiguous exit status in either evidence record.
4. **Collector-failure alternative addressed:** the ledger must state at least one plausible way the primary detector could produce the observed result and which evidence discriminates it from the target-state hypothesis.
5. **Claim/foundation separation:** the response carries the mandated likelihood band. If any proof obligation is unmet, the qualifying sentence itself must include **UNVERIFIED** and the concrete experiment that would settle it.

For `done`, the second signal must observe the requested outcome from a consumer-facing boundary when practical, not merely repeat the producer’s success signal. Examples: parse the written artifact after the write; query the deployed endpoint rather than trusting the deploy CLI; run the targeted regression plus an independently relevant invariant. These are design examples, not claims about the present local harness.

### Minimal decision logic

```text
if claim is not high-risk: PASS
if claim has tool-error/truncation/permission ambiguity: BLOCK or force UNVERIFIED
if no validated positive control: BLOCK or force UNVERIFIED
if fewer than two provenance-independent signals: BLOCK or force UNVERIFIED
if collector-failure alternative is not addressed: WARN and force UNVERIFIED
else: PASS, preserving evidence references and likelihood band
```

The gate should fail open for low-impact prose but fail closed before destructive action or external side effects. For an ordinary final answer it should rewrite the epistemic status, not trap the agent in an endless retry loop: “UNVERIFIED; probe P1 returned no matches, but detector coverage is not validated. Experiment: enumerate the authoritative manifest with parser Q.”

### What this catches that a normal retry misses

| Failure pattern | Why ordinary agent reasoning can accept it | Gate intervention |
|---|---|---|
| Search returns zero because the working directory or branch is wrong | A clean null result looks definitive | Positive control fails in that scope; scope provenance is exposed |
| Two commands agree because both read the same stale index/cache | Surface syntax looks independent | Independence fields reveal a shared acquisition lineage |
| A detector reports zero capabilities because its parser/schema broke | “Zero” is treated as target state | Known-present capability control fails; tool degradation blocks the conclusion |
| A command exits successfully but output was truncated or filtered | Exit status is over-weighted | Truncation/filter metadata invalidates report credibility |
| Local worktree lacks a path that exists in a remote tree or generated representation | “Not on disk” is generalized to “does not exist” | H3/H5 force explicit scope and a second representation-level probe |
| A write/deploy tool says success while the consumer cannot read/use the result | Producer acknowledgment is mistaken for outcome | Completion requires a consumer-boundary observation |
| Several reports all originate from one failed collector | Agreement is counted rather than traced | Circular-reporting check collapses them to one signal |

**Coverage judgment: likely (55-80%).** Evidence: the table maps each target failure class to a mandatory proof obligation, and the supplied brief specifically reports a known control catching one detector that returned zeros. The proportion of real errors falling into these classes is **UNVERIFIED; the settling experiment is to label the causal lineage of all known correction candidates in a held-out sample and compute recall.**

## Adversarial transfer analysis

### Structural similarities that support transfer

1. **Both domains infer hidden state through fallible collectors.** Intelligence sensors have coverage, opportunity, technical, and interpretation limits; software tools have scope, permission, parser, cache, transport, and platform limits. The UK doctrine explicitly lists the former failure modes and mandates validation ([JDP 2-00, 4th ed., §3.39](https://assets.publishing.service.gov.uk/government/uploads/system/uploads/attachment_data/file/311572/20110830_jdp2_00_ed3_with_change1.pdf)).
2. **Null observations are underdetermined in both domains.** No observed activity can mean no activity or failed coverage. No search result can mean no target or failed search scope. Competing hypotheses and positive controls discriminate those explanations.
3. **Evidence dependence is hidden by presentation layers in both domains.** Multiple reports/tools can share one upstream source. Provenance, not count, determines corroborative value.
4. **The decision-maker needs both a best judgment and its fragility.** ODNI and PHIA standards distinguish judgments from assumptions and ask analysts to explain source quality and remaining uncertainty ([ICD 203](https://www.odni.gov/files/documents/ICD/ICD-203_TA_Analytic_Standards_21_Dec_2022.pdf); [PHIA uncertainty framework](https://www.gov.uk/government/publications/explaining-uncertainty-in-uk-intelligence-assessment/explaining-uncertainty-in-uk-intelligence-assessment)). An agent user has the same need before acting on a diagnosis.

### Disanalogies and design consequences

1. **Software state is often directly testable; geopolitical state often is not.** A full subjective ACH exercise is wasteful when an authoritative API, filesystem tree, or executable acceptance test exists. Consequence: prefer a cheap mechanical control and consumer-level test; use the mini alternative set only to choose the second probe.
2. **Agent probes are reproducible and cheap relative to intelligence collection.** This makes a two-signal gate more feasible, but also makes retry loops tempting. Consequence: cap the gate at one discriminating follow-up; if uncertainty remains, report it rather than recurse.
3. **Tool failures are frequently correlated by shared infrastructure.** Two shell commands on the same filesystem view can be less independent than two human sources. Consequence: independence is a provenance property, not a tool-name property.
4. **A known-present control proves sensitivity only locally.** It does not prove complete coverage, correct authorization, temporal freshness, or the absence of a target elsewhere. Consequence: a control is necessary for a negative claim but never sufficient by itself.
5. **Adversarial deception is not the default in local tooling.** Importing motivation/deception scoring would add ceremony without matching most failures. Consequence: omit source motivation from the minimal schema unless the source is external or potentially adversarial.
6. **Intelligence scales are human communication devices, not calibrated software probabilities.** The Admiralty categories and confidence labels can be collapsed or misused, as the 2025 experiments indicate ([Mandel et al., 2025](https://www.cambridge.org/core/journals/judgment-and-decision-making/article/effect-of-source-reliability-and-information-credibility-on-judgments-of-information-quality-in-intelligence-analysis/E67548E8010A47345C3439D45D9EC6B3)). Consequence: do not compute arithmetic over ordinal grades or use an opaque trust score.

### Why full ACH does **not** transfer

The full ACH matrix is rejected for routine harness use. A 2024 experiment with 161 participants found the classic hypotheses-as-columns ACH layout did not reduce confirmation bias or improve sensitivity to evidence credibility; the transposed layout performed better on the tested bias measure. The authors caution that further replication is needed ([Dhami et al., *Cognitive Research*, 2024](https://link.springer.com/article/10.1186/s41235-024-00560-y)). A 2019 study of 50 intelligence analysts found mixed evidence and reported that only 20% of ACH-trained analysts used solely the prescribed inconsistent-evidence integration rule; the paper concludes that ACH’s efficacy has little empirical support ([Dhami et al., *Applied Cognitive Psychology*, 2019](https://onlinelibrary.wiley.com/doi/full/10.1002/acp.3550)).

**Rejection judgment: almost certain (90-99%)** that a mandatory full ACH matrix on every tool-derived conclusion would violate this program’s anti-overfit gate. Evidence: it adds cognitive and token overhead to directly testable software states, the 2024 study found no benefit from the classic matrix orientation on its tested outcomes, and the target defect can be intercepted with five mechanical fields and two proof obligations. This judgment concerns routine harness use, not rare strategic investigations.

## Anti-overfit gate

The Agent Analytic Proof Gate rides the existing hook/skill/MCP bus and is explicitly bounded to fewer than roughly 200 lines. It introduces none of the rejected components:

- no second orchestration runtime;
- no vector database or knowledge graph;
- no durable-execution engine;
- no trained critic or second-model judge;
- no observability SaaS;
- no guardrail framework.

Turn-local JSON/YAML evidence is enough. Any aggregate evaluation can use ordinary offline files produced by the existing harness. If the implementation grows beyond a compact deterministic validator, the proposal has failed its own design constraint and should be reduced rather than promoted to a service.

**Complexity judgment: very likely (80-90%)** that the validator logic fits under approximately 200 lines, because it performs schema checks, a small phrase/claim trigger, independence comparisons over enumerated fields, and deterministic status selection. This size estimate is **UNVERIFIED; the settling experiment is a spike implementation against the proposed schema with tests, counting non-generated source lines.**

## Evaluation plan and kill criteria

### Phase 1 — replay, no runtime behavior change

Create a labeled set with:

- all supplied known single-probe false conclusions available to the evaluation unit;
- a held-out random sample of correct negative and completion claims;
- difficult correlated-probe cases where two outputs share one upstream source;
- positive-control failures and tool-output truncation/permission errors;
- benign prose that contains trigger words but makes no epistemic judgment.

Replay draft claims plus their tool ledgers through the gate. Measure:

- recall on known false conclusions;
- false-intervention rate on correct claims;
- rate at which “two signals” are incorrectly accepted despite shared lineage;
- added tool calls, tokens, and wall time;
- proportion of blocked claims converted to an honest inline **UNVERIFIED** statement with a settling experiment;
- retry-loop incidence.

### Phase 2 — shadow mode

Run the hook without changing output. Compare its alerts with later owner corrections, downstream test failures, and contradictions from subsequent tool calls. Stratify by claim type and detector family; do not tune only on the six motivating cases.

### Phase 3 — narrow enforcement

Enforce first for destructive authorization and externally consequential actions. For ordinary answers, warn and force epistemic labeling before blocking. Expand only if shadow precision and net utility remain acceptable on held-out work.

### Proposed preregistered acceptance and kill criteria

These thresholds are design choices, not researched facts:

- accept a pilot if replay catches at least 5 of the 6 motivating false conclusions, catches at least 80% of held-out single-probe false conclusions, and intervenes on no more than 5% of correct ordinary claims;
- require 100% detection of deliberately planted failed positive controls;
- require the provenance test suite to reject all planted same-lineage “independent” pairs;
- kill or redesign if median routine-turn latency rises more than 3%, if retry-loop incidence increases, or if agents satisfy the schema with boilerplate that does not change probe selection;
- do not claim success from replay alone; require shadow-mode correlation with later independent outcomes.

**Pilot-value judgment: likely (55-80%).** Evidence: the mechanism is narrow, deterministic, replayable, and directly aligned with the specified error. Net benefit in live use is **UNVERIFIED; the phased experiment above settles whether caught errors outweigh friction and gaming.**

## Alternatives considered

### Prompt-only instruction — rejected as sole control

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

A short rule—“validate the detector on a known-present control and obtain two independent signals before absence/broken/done claims”—is useful as the agent-facing specification. It is not sufficient as the only mechanism because the target is a reliability lapse during reasoning; asking the same reasoner to remember an unobserved obligation provides no mechanical audit or enforcement. **Likely (55-80%)** that config-only wording improves some cases but misses a material fraction, based on the supplied fact that repeated single-probe errors occurred despite an existing harness and on the general need for review/evaluation in ICD 203 ([ODNI objectivity and review standards](https://www.odni.gov/index.php/how-we-work/objectivity)). The effect is **UNVERIFIED; a prompt-only arm in the replay/live A/B experiment would settle it.** Use the text as configuration paired with the small gate, not as a standalone fix.

### Always spawn an independent critic/agent — rejected

**NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime -- needs its own justification).**

This violates the anti-overfit gate if implemented as a standing second orchestration path, increases cost, and does not guarantee mechanical independence: two agents can read the same faulty output and agree. It is unnecessary for validating most software state. No justification survives against the smaller deterministic gate, so this proposal is rejected.

### Numeric Bayesian reliability model — rejected for the initial design

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Bayesian updating could in principle represent correlated evidence, but the required priors and conditional failure rates are not available for most tools and environments. Invented numbers would add false precision, and the Admiralty literature shows even categorical dimensions are cognitively entangled. Preserve provenance and enforce proof obligations first. Consider quantitative calibration only after enough labeled outcomes exist, and only if it beats the deterministic rule on held-out utility.

## Exact recommended harness rule — UNVERIFIED pending replay/shadow experiment

> Before asserting that something is absent, broken, unused, safe to delete, or done, treat the first probe as evidence rather than a conclusion. Validate that detector on a known-present control in the relevant scope. Obtain a second signal whose acquisition path or data field can fail independently; a rerun, rephrasing, or second view of the same cache is not independent. Explicitly test the alternative that the detector, scope, parser, permissions, cache, transport, or representation caused the result. If any obligation is unmet, write **UNVERIFIED** in the claim sentence and name the experiment that would settle it. State proposition likelihood separately from the strength of its evidentiary foundation.

This rule is the compact cross-domain borrow. The hook is its mechanical enforcement layer.
