2. Three multi-model commands require `run_in_background: true` for work whose results they immediately place behind a `TaskOutput` barrier, while the newer cross-vendor rule expressly bans that exact combination.

The important runtime conclusion is that rule text does **not** mechanically override command text. Anthropic’s current documentation says memory/rules are context rather than enforced configuration and that Claude may choose arbitrarily between conflicting instructions. Unconditional rules load at session start; path-scoped rules load only after a matching file is opened. Invoked legacy commands continue to work as prompt-based skills. Consequently, conflicts 2–5 have no deterministic behavioral winner; conflict 1 is command-winning when no matching source file has yet caused the path-scoped git rule to load; conflict 6 is command-winning until a matching source file loads the testing rule and nondeterministic thereafter. Sources: [Claude Code memory and rules](https://code.claude.com/docs/en/memory) (especially the “context, not enforced configuration,” load timing, and conflict guidance) and [Claude Code skills/custom commands](https://code.claude.com/docs/en/slash-commands) (legacy `.claude/commands` remains supported and command bodies are prompt workflows).

All proposed repairs are small Markdown changes on the existing rule/command bus. None introduces a second orchestrator, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. They pass the anti-overfit gate.

The command’s own first executable sequence calls `gh pr view`; if no PR exists, it prints “No PR found” and exits 1. This is not a hypothetical name collision: the rule routes precisely the pre-PR situation into a command whose contract begins after PR creation.

The absence of creation behavior has two mechanically different signals. Structural signal: the command’s state machine starts with retrieval of an existing PR and then monitors CI/comments (`commands/pr-shepherd.md:28-54`). Lexical/operation signal: the complete 76-line command contains no `git diff`, `git push`, `gh pr create`, “test plan,” or “draft summary”; the detector control finds known-present `gh pr view` at line 31 and monitoring operations at lines 41–54.

### Runtime winner

The **command wins mechanically in the fresh pre-PR case**. `common/git-workflow.md` is path-scoped (`rules/common/git-workflow.md:1-20`), so it is not loaded until Claude opens a matching source file. Invoking `/pr-shepherd` before such a read loads the command but not this rule. If the rule has already loaded, neither prompt instruction has formal precedence; Claude may reconcile arbitrarily, but executing the command’s literal shell block still exits when no PR exists.

Edit `rules/common/git-workflow.md:36-37` to name the behavior the command actually provides:

It does not restore PR creation functionality, which is intentionally outside this coherence repair.
