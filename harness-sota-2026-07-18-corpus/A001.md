## Executive verdict

The three-line rule is not a coherent orchestration contract. It is a thin routing pointer with four assertions: a live roster is injected, static rosters are forbidden, work should route through `/start-task`, and independent/high-stakes work should use parallel/split-role agents; it then delegates handoffs to `AGENTS.md §5` (`claude/rules/common/agents.md:1-3`). Three of those assertions are either not mechanically supported or are contradicted by the destination to which the rule routes.

The highest-confidence defects are:

1. `/start-task` contains mutually incompatible routing generations. Its deterministic router says trivial work gets “no gates” and that a scoped `*` prompt skips directly to work (`claude/commands/start-task.md:11-23`), while its legacy body says every new task runs BEADS priming, offers a PR-comment detour, and asks the user to confirm complexity (`claude/commands/start-task.md:35-55,76-90`). This conflicts with the higher-precedence clarification contract (`claude/AGENTS.md:7-12`).
2. The active subagent lifecycle hook reminds workers to return a structured summary but accepts every output of at least 20 characters, or any `SUCCESS:`/`FAILED:` prefix, without checking structure (`agents/harness/modules.py:2331-2396`). Thus the handoff rule is UNENFORCED, not enforced.
3. The same active module injects a four-field I-PASS read-back and diagnoses a subagent as likely dead after one transcript-mtime signal (`agents/harness/modules.py:2370-2382,2398-2420`). Neither behavior is stated in `agents.md`; the latter directly violates the mechanically-independent two-signal rule (`claude/rules/common/single-signal-verification.md:20-37`).
4. A separately wired file-scope hook blocks out-of-scope writes with exit 2 (`claude/hooks/file-scope/check.py:2-10,116-139`), although the higher-precedence contract reserves blocking for irreversible/dangerous actions (`claude/AGENTS.md:64-70`). This is both UNRULED in `agents.md` and a direct contract CONTRADICTION.
5. “Do NOT keep a static list” is contradicted by a static four-agent table (`claude/rules/common/code-review.md:80-89`) and by a router source comment claiming “the 16 agents” while the snapshot contains 18 agent definition files (`claude/hooks/skill-router/route.py:2-7`; enumerated by `find .../claude/agents -name '*.md'`, which returned 18).

The corpus strongly suggests that `/start-task` is not the normal delegation gateway: it records 1,745 `Agent` calls (`inputs/corpus.json:119-124`) but only one `start-task` and one `metaswarm:start-task` Skill invocation (`inputs/corpus.json:13338-13339`). This behavioral conclusion is **UNVERIFIED** because the two fields are not guaranteed to count slash-command expansion the same way; the settling experiment is to scan raw parent turns for the `/start-task` expansion marker immediately preceding each `Agent` call. On the evidence available, it is **likely (55-80%)** that the routing rule is not followed: the ratio is 2 recorded skill invocations to 1,745 agent calls, and no hook routes an `Agent`/`Task` invocation through `/start-task`.

The bundle does not include `~/.claude/skills/` or `~/.agents/skills/`. I therefore make no claim that the requested skill surfaces are coherent. The known-positive control was successful—`claude/hooks/no-force-push/SKILL.md` is present—while `find` found no other `SKILL.md` beneath the bundle. A Windows-host scan of the two live skill roots is required to close that part of the assignment.
