# P1C24 — Normalized audit findings: D13–D16

## Scope and method

This unit normalizes the 33 discrete findings in `D13.md`, `D14.md`, `D15.md`, and `D16.md`. It does **not** verify cited paths, commands, URLs, runtime behavior, or the subject harness. `SUPPORTED`, `PARTIAL`, and `UNSUPPORTED` answer only this question: if the evidence text is accepted at face value, does it logically support the normalized one-sentence claim?

Evidence strings below are copied verbatim from each finding `- evidence:` field. Claimed severity normalizes the finding `value x effort` value (`high` or `med`) while preserving the original value in the adjacent field. Proposal implementation tags are normalized to the required values `NATIVE`, `CONFIG`, `BUILD-SMALL`, or `BUILD-LARGE`; these are classification metadata, not implementation endorsements.

Duplicate marking is conservative. Two reciprocal duplicate pairs were found: structured handoff enforcement (`P1C24-D15-F05` / `P1C24-D16-F01`) and pinned MCP admission (`P1C24-D13-F09` / `P1C24-D16-F06`). Related teardown themes that recommend retaining native planning, skills, or subagent planes were not marked duplicates because their concrete mechanisms and evidence differ.

The one `BUILD-LARGE` normalization (`P1C24-D15-F06`) rides the existing map/handoff bus and explicitly rejects a vector store, knowledge graph, daemon, and new MCP. It therefore does not reintroduce a previously rejected component, although its cited evidence does not prove local value; that is why its support judgment is `PARTIAL`.
