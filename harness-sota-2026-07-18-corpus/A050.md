# A050 — Coherence audit: `~/.claude/rules/perl/testing.md`

## Scope, evidence basis, and verdict

This unit audited the unpacked, read-only subject at `/local_disk0/codexwork/bundle`; the only write was this artifact. The target is `/local_disk0/codexwork/bundle/claude/rules/perl/testing.md` (937 bytes; SHA-256 `4e8377928b5da585aebeaa278e3f293365d84df7819cb44d8efb1b5dc4631e68`). I read the target in full (`testing.md:1-54`), all 83 Markdown rule files by focused and whole-tree searches, all four sibling Perl rules, `settings.json`, `CLAUDE.md`, `AGENTS.md`, the hook registrations and relevant hook implementations, the shared harness receipt/claim gate, and the measured corpus. Paths below are rooted at `/local_disk0/codexwork/bundle` unless stated otherwise.

Overall verdict: the Perl testing rule is coherent in its basic tool choices, but it is operationally disconnected. It says it extends the common testing contract even though the common contract's path selector excludes all Perl file types; none of the Perl-specific mandates is checked by an edit or completion hook; and the active evidence ledger does not recognize `prove` at all and classifies `cover -test` as a **test**, not **coverage**. The fixed `80%+` statement also collides with the common `.coverage-thresholds.json` single source of truth. These are degrading coherence defects, not evidence that Test2::V0, `prove`, or Devel::Cover are intrinsically wrong.

The recommendations below are all `CONFIG` or `BUILD-SMALL`; they ride the existing rules/settings/hook bus. They do not add a second orchestrator, vector/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework, and therefore pass the anti-overfit gate.

## Precedence applied

`claude/AGENTS.md:115-131` defines the applicable order: user/permissions, safety, the cross-tool contract, project governance, then skill/plugin defaults. In particular, the cross-tool contract is above these rule files (`AGENTS.md:121-127`), and same-level conflicts must be surfaced (`AGENTS.md:129-131`). `claude/rules/README.md:93-98` additionally gives a rule-subsystem-specific tie-break: language-specific rules override common rules.

Consequences:

* The conditional long-operation requirement in `AGENTS.md:41-48` wins over the target's bare foreground runner examples.
* For the coverage-threshold collision, AGENTS §10 does **not** itself choose between two rule files at the same harness layer. The narrower rule-subsystem policy at `rules/README.md:93-98` says Perl wins. That makes the current effective intended threshold `80%+`, even on a metaswarm project, but it contradicts the common file's declaration that `.coverage-thresholds.json` is the SSOT. The resolution must remove the duplicate fixed threshold rather than silently relying on specificity.
* Skills would be lower-precedence defaults (`AGENTS.md:127`), but the requested skill sources were not included in this bundle. No skill collision is inferred.

## Collision register

### C01 — CONTRADICTION: fixed Perl threshold versus coverage SSOT

**Artifacts and exact lines**

* `claude/rules/perl/testing.md:34-40`: “Use Devel::Cover — target 80%+” and `cover -test`.
* `claude/rules/common/testing.md:21-38`: coverage is per `.coverage-thresholds.json`, is `100% on metaswarm`, and falls back to `80%+` only when no threshold is defined.
* The same SSOT is repeated at `claude/rules/common/code-review.md:47-57,91-99` and `claude/rules/common/development-workflow.md:43-48`.

**Conflict and precedence.** A Perl file in a project whose threshold file says 90% or 100% receives incompatible numbers. The README's same-subsystem priority rule (`rules/README.md:93-98`) technically selects the language-specific `80%+`; AGENTS §10 does not independently resolve this same-level collision. That selection defeats the explicitly named SSOT and is therefore bad configuration, even though precedence is determinable.

**Resolution — CONFIG.** Replace “target 80%+” with “meet `.coverage-thresholds.json`; use 80%+ only when none is defined,” leaving Devel::Cover as the Perl implementation. Remove numeric policy from language files entirely if possible. It is almost certain (90-99%) this eliminates the threshold split because the three common consumers already use the identical SSOT wording (`common/testing.md:23,38`, `common/code-review.md:57,98`, `common/development-workflow.md:48`).

### C02 — STALE: the declared common-rule extension cannot load for Perl paths

**Artifacts and exact lines**

* `claude/rules/README.md:8-29,55-64` says common is the required universal layer and language directories extend it.

**Conflict.** Path-scoped rule loading cannot realize the documented extension when the active file is Perl. The same omission exists in the front matter of `common/development-workflow.md:1-20` and `common/code-review.md:1-20`, so Perl also misses their TDD and review coverage gates (`development-workflow.md:43-48`; `code-review.md:47-57,91-99`). This is a badly wired rule, not evidence that TDD is wrong. AGENTS §10 does not resolve a selector omission: there are not two loaded instructions to rank.

**Resolution — CONFIG.** Add the five Perl globs to the relevant common rule front matter, or make genuinely universal common rules unscoped and retain file globs only on language addenda. The latter is cleaner but must be tested against Claude Code's actual rule-loader semantics. **UNVERIFIED:** whether an unscoped common file auto-loads in the owner's installed Claude Code build; settle with a disposable session whose prompt edits a known `.t` file and inspect the loaded-instruction diagnostic. The narrower add-five-globs change is very likely (80-90%) to restore the intended inheritance because the target and common file use the same documented `paths` mechanism (`perl/testing.md:1-8`; `common/testing.md:1-20`).

### C03 — CONTRADICTION: foreground test examples omit the cross-tool longrun condition

**Artifacts and exact lines**

* `claude/rules/perl/testing.md:25-32` gives direct foreground `prove -l t/` and `prove -lr -j8 t/` commands and says always use `-l`.
* `claude/AGENTS.md:41-49` requires **any** test/coverage operation expected to exceed 60 seconds to run through `longrun` in background/Monitor, never as a blocking foreground call.

**Conflict and precedence.** The commands are fine for short suites, but presented without the >60-second branch they are incomplete and can direct forbidden behavior for a large suite. This is conditional rather than an unconditional command contradiction. AGENTS §10 resolves it: the cross-tool contract is higher (`AGENTS.md:123`) and wins.

**Resolution — CONFIG.** Add: “Run these directly only when expected under 60s; otherwise wrap the same argv with the AGENTS §4a `longrun` stub.” It is almost certain (90-99%) this reconciles the texts because it preserves the Perl argv while explicitly applying the higher rule's existing condition (`AGENTS.md:43-48`).

### C04 — UNENFORCED: Test2::V0-for-new-projects and `done_testing`

It is very likely (80-90%) that syntax checking provides useful low-cost coverage because it uses the already registered per-edit path (`settings.json:333-342`) and the existing 8-second subprocess pattern (`per-edit-check/check.py:37-39,42-90`).

A reliable “new project” signal is not present in the inspected rule/settings/hook sources; settle by defining and testing a marker (for example a project config field) before automating the framework ban.

Keep default behavior as injection, consistent with `AGENTS.md:64-70`; do not enable blocking for ordinary test edits without revisiting the security-only block rule.

**Resolution — BUILD-SMALL.** Extend `_TEST_FILE_PATS` with Perl `.t` and add Test2 assertion/skip forms. It is very likely (80-90%) the `.t` pattern addition fixes conventional Perl test discovery because the current pure detector probe provides a deterministic failing control, while `tests/foo.t` provides a known-positive control.
