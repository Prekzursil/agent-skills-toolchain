# P2A03 — Agent memory systems: evidence review and harness recommendation

**Unit:** P2A03  
**Date:** 2026-07-18  
**Lens:** external research only  
**Question:** Re-examine the use of basic-memory and the earlier rejection of mem0/OpenMemory at a 3B model size, focusing on episodic/semantic separation, consolidation, forgetting, and temporal validity.

## Executive verdict

**Do not replace basic-memory with mem0 or OpenMemory now.** The previous rejection remains **very likely (80-90%) correct for this owner**, but the best current rationale is different and more precise: mem0/OpenMemory are no longer toy projects, yet their automatic LLM-mediated extraction, consolidation, and mutation pipeline puts an unreliable model in the write path of durable memory. Mem0's own algorithm lets an LLM choose `ADD`, `UPDATE`, `DELETE`, or `NOOP`, and its paper deletes contradicted information in the flat store; current independent benchmarks find that extraction/update stages generate and accumulate hallucinations, that memory agents frequently reuse invalidated facts, and that repeated LLM consolidation can make useful memories harmful. Evidence: [Mem0 architecture and update algorithm](https://arxiv.org/pdf/2504.19413), [HaluMem](https://arxiv.org/abs/2511.03506), [Memora/FAMA](https://arxiv.org/abs/2604.20006), and [Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/abs/2605.12978).

The owner should **evolve the existing transparent Markdown-first store**, not replace it: retain immutable or append-only episodic evidence; derive smaller semantic notes that cite their source episodes; add explicit valid-time and supersession metadata; exclude superseded facts by default; consolidate only when recurrence or a milestone provides sufficient evidence; and evaluate memory on owner-derived mutations, contradictions, abstention, and post-compaction tasks. This is **very likely (80-90%) the highest-value, lowest-overfit direction**, because it preserves the current MCP/Markdown bus while adopting the mechanisms supported across independent benchmark families without adding a second runtime. Evidence: LongMemEval's gains from session decomposition, fact-augmented keys, and time-aware query expansion; the ACL 2026 controlled graph-vs-flat analysis; HaluMem's operation-level failure localization; and the raw-episode control in the consolidation study ([LongMemEval](https://arxiv.org/abs/2410.10813), [ACL 2026 unified analysis](https://aclanthology.org/2026.acl-long.1232.pdf), [HaluMem](https://arxiv.org/abs/2511.03506), [consolidation study](https://arxiv.org/abs/2605.12978)).

The earlier “rejected at 3B” boundary should become a stronger design constraint: **a 3B model must not be the sole authority for durable mutation or deletion.** This conclusion is **likely (55-80%)**, supported directly by known extraction/update hallucinations and indirectly by an **UNVERIFIED** 2026 mechanistic preprint reporting that Qwen-family memory-routing signals appear before reliable memory-content signals and that content circuitry was not detected until 4B; settle that premise by replaying a fixed owner-derived write/update set through the exact local 3B model and manually scoring extraction, contradiction resolution, and provenance preservation ([mechanistic preprint](https://arxiv.org/abs/2605.03354), [HaluMem](https://arxiv.org/abs/2511.03506)). Even if that preprint fails to replicate, the independent operation-level evidence still argues against destructive autonomous writes.

## 1. What is actually established

### 1.1 “Memory” is a pipeline, not a database feature

CoALA provides a useful architecture-level decomposition of language agents into working memory plus long-term episodic, semantic, and procedural memory, with explicit internal actions for reading and writing memory. This is a framework and taxonomy, not proof that mirroring human cognitive labels improves an agent ([CoALA](https://arxiv.org/abs/2309.02427)).

The ACL 2026 controlled analysis gives a more operational decomposition: memory extraction creates keys and values; indexing organizes and maintains them; retrieval maps queries to keys and evidence values; answering consumes that evidence. Its experiments show that representation, key/value choices, maintenance operations, retrieval, and answering strategy materially affect the result, making “uses a vector DB” or “uses a graph” radically incomplete descriptions ([Does Memory Need Graphs?](https://aclanthology.org/2026.acl-long.1232.pdf)).

LongMemEval independently decomposes system design across indexing, retrieval, and reading, and reports improvements from session decomposition, fact-augmented key expansion, and time-aware query expansion. Its 500 questions cover information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention, and it reports an approximately 30% accuracy drop for commercial assistants and long-context models in sustained-interaction settings ([LongMemEval](https://arxiv.org/abs/2410.10813)).

**Established implication:** the harness must distinguish write quality, retrieval quality, and use/answer quality. A single end-to-end “did the model remember?” score cannot tell whether the memory was never captured, was captured incorrectly, was not retrieved, or was retrieved and ignored. HaluMem directly validates this need by defining separate extraction, updating, and question-answering tasks and observing error propagation across stages ([HaluMem](https://arxiv.org/abs/2511.03506)).

### 1.2 Raw episodes and semantic abstractions are complementary, not substitutes

Generative Agents stored a complete natural-language record of experiences, synthesized higher-level reflections, and retrieved memories using recency, importance, and relevance. Ablations found that observation, planning, and reflection each contributed to perceived behavioral believability in its 25-agent simulation. This establishes that raw experience plus derived reflection can be useful in that environment; it does not establish a universal human-like memory architecture ([Generative Agents](https://arxiv.org/abs/2304.03442)).

The strongest current evidence for retaining both layers is more direct. The 2026 continuous-consolidation study compares raw episodic traces with repeatedly rewritten consolidated abstractions in ARC-AGI Stream. It reports that memory utility can rise and then fall below the no-memory baseline; an episodic-only control remained competitive; and agents that could choose among retain/delete/consolidate preserved raw episodes by default and doubled the accuracy of forced-consolidation agents ([Useful Memories Become Faulty When Continuously Updated by LLMs](https://arxiv.org/abs/2605.12978)).

The ACL 2026 controlled analysis reaches a compatible conclusion from dialogue memory: raw sessions preserve contextual continuity, while derived summaries/facts/keywords compress information at a risk of information loss. Across LongMemEval, retaining session evidence while merging derived summary/fact/keyword keys produced the strongest tested flat configuration; graph retrieval sometimes improved retrieval scores without improving downstream QA because fragmented nodes or distracting time metadata harmed the answer model ([ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)).

**Established implication:** a durable semantic note must not overwrite or become the only copy of the episode from which it was derived. Semantic memory is an index/abstraction over evidence, not a license to discard evidence.

### 1.3 Consolidation is useful, but eager consolidation is not established

The evidence supports selective consolidation, not automatic rewriting after every interaction. Generative Agents used reflection after accumulated importance crossed a threshold rather than rewriting every memory immediately ([Generative Agents](https://arxiv.org/abs/2304.03442)). RecMem reports that delaying LLM extraction until semantically similar interactions recur reduced construction token cost by up to 87% while improving accuracy over the three systems it tested; because this is one recent preprint, its exact magnitude is **UNVERIFIED** until the released implementation is rerun on an owner-derived event stream, but it supplies a concrete gating mechanism rather than a cognitive metaphor ([RecMem](https://arxiv.org/abs/2605.16045)).

The continuous-consolidation study supplies the negative control: consolidation schedules changed the resulting memory even when source trajectories were identical, and repeated rewriting corrupted useful experience ([continuous-consolidation study](https://arxiv.org/abs/2605.12978)). HaluMem independently finds that updating itself is a hallucination source ([HaluMem](https://arxiv.org/abs/2511.03506)).

**Established implication:** consolidation should be a derived, auditable operation with a trigger and source links. “Every turn,” “every session,” and “whenever the LLM feels like it” are not evidence-based defaults.

### 1.4 Forgetting means suppressing obsolete or low-value retrieval, not destroying history

MemoryAgentBench, accepted at ICLR 2026, evaluates accurate retrieval, test-time learning, long-range understanding, and selective forgetting in incremental multi-turn settings. Its public repository includes EventQA and FactConsolidation datasets and converts long-context sources into an ingest-once/query-many interaction form ([ICLR page](https://iclr.cc/virtual/2026/poster/10010781), [official repository](https://github.com/HUST-AI-HYZ/MemoryAgentBench)).

Memora goes further by evaluating changing information over weeks to months and introducing Forgetting-Aware Memory Accuracy, which penalizes using obsolete or invalidated memory. It reports frequent reuse of invalid memories and large score reductions when forgetting-aware penalties are applied ([Memora](https://arxiv.org/abs/2604.20006)). LongMemEval separately includes knowledge updates and abstention, while LoCoMo exposes long-range temporal and causal failures across conversations of up to 35 sessions ([LongMemEval](https://arxiv.org/abs/2410.10813), [LoCoMo](https://arxiv.org/abs/2402.17753)).

The ACL 2026 analysis notes that direct deletion may be undesirable because an old fact can remain relevant historically—for example, a former occupation—and it models add/update/no-op without requiring destructive deletion ([ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)). Graphiti similarly keeps validity windows and source episodes so facts can be invalidated without removing history; these are implemented product properties, while its superiority claims remain vendor-authored ([Graphiti repository](https://github.com/getzep/graphiti), [Zep paper](https://arxiv.org/abs/2501.13956)).

**Established implication:** the default “forget” operation for durable harness knowledge should be `inactive/superseded/archived and excluded from current retrieval`, not physical deletion. Physical deletion remains appropriate for privacy, user request, secrets, or retention policy, but not ordinary epistemic change.

### 1.5 Temporal validity is different from recency

A creation timestamp says when the store learned a fact. It does not necessarily say when the fact was true, when it ceased to be true, or which later fact superseded it. Graphiti explicitly distinguishes valid time from ingestion/provenance time and retains the source episode for derived facts ([Graphiti repository](https://github.com/getzep/graphiti), [Zep temporal graph explanation](https://www.getzep.com/ai-agents/temporal-knowledge-graph/)).

Memora shows why that distinction matters: systems that retrieve something remembered may still be wrong if the fact was later updated or withdrawn, and standard presence-based scoring hides this misuse ([Memora](https://arxiv.org/abs/2604.20006)). Mem0's answer prompt tells the model to prioritize the most recent memory when contradictions occur, but “most recently stored/observed” is only a heuristic and does not express retroactive corrections, scheduled future validity, or delayed ingestion ([Mem0 paper appendix](https://arxiv.org/pdf/2504.19413)).

MemStrata reports that deterministic subject-relation-object supersession plus a bi-temporal ledger eliminates stale-fact errors on its evolving-knowledge datasets, whereas RAG serves superseded values 15-40% of the time. This exact performance is **UNVERIFIED** because it is a very recent single-author preprint; settle it by running its released harness against owner-derived facts with backdated corrections, future-effective changes, and same-day contradictions ([MemStrata](https://arxiv.org/abs/2606.26511)). Its structural point—that similarity alone does not encode validity—is consistent with Memora and Graphiti.

### 1.6 Current benchmarks establish failure modes, not a universal winner

LoCoMo contains long conversations averaging about 300 turns and 9K tokens across up to 35 sessions and finds that long context and RAG improve results but remain below human performance on temporal and causal dialogue tasks ([LoCoMo](https://arxiv.org/abs/2402.17753)). LongMemEval scales histories and tests five abilities, while ACL 2025 MemBench adds factual versus reflective memory, participation versus observation scenarios, and effectiveness/efficiency/capacity metrics ([LongMemEval](https://arxiv.org/abs/2410.10813), [MemBench](https://aclanthology.org/2025.findings-acl.989/)). ICLR 2026 MemoryAgentBench adds test-time learning, long-range understanding, and selective forgetting ([MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)). HaluMem localizes extraction, update, and QA hallucinations ([HaluMem](https://arxiv.org/abs/2511.03506)). Memora stresses mutation and obsolete-memory use ([Memora](https://arxiv.org/abs/2604.20006)).

These benchmarks have materially different tasks, models, retrieval budgets, judges, and memory representations. The ACL 2026 controlled study explicitly finds cross-paper comparison difficult because extraction models, embedding models, top-k settings, values, and evaluation environments differ, and its own graph-versus-flat results change with dataset and answer context ([ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)). Therefore, no published leaderboard establishes that one general-purpose memory product is best for this owner's coding/research harness.

## 2. What is promising but unproven

### 2.1 Recurrence-gated consolidation

Recurrence is a plausible proxy for importance: retain raw interactions cheaply, and pay for semantic abstraction only when a theme repeats. This is **likely (55-80%) useful for this harness**, supported by RecMem's reported cost/accuracy results and by the independent finding that eager consolidation corrupts memory. It remains **UNVERIFIED** for heterogeneous coding sessions; settle it by comparing per-session consolidation, milestone-only consolidation, and recurrence-gated consolidation on 100 owner-derived episodes, scoring durable-fact recall, false abstraction, token cost, and source traceability ([RecMem](https://arxiv.org/abs/2605.16045), [continuous-consolidation study](https://arxiv.org/abs/2605.12978)).

### 2.2 Event-boundary episodes rather than fixed chunks

Semantic episode boundaries are **likely (55-80%) better than arbitrary token chunks** for tasks with identifiable goals and terminal outcomes. Evidence includes LongMemEval's session decomposition gains, Nemori's reported advantage from event segmentation, and ReadAgent/Generative Agents patterns; however, Nemori's claimed superiority is **UNVERIFIED** outside its LoCoMo/LongMemEval setup. Settle it by segmenting the same owner sessions by fixed tokens, turns, tool-result terminal markers, and explicit goal/milestone boundaries, then compare evidence recall and contamination ([LongMemEval](https://arxiv.org/abs/2410.10813), [Nemori](https://arxiv.org/abs/2508.03341), [Generative Agents](https://arxiv.org/abs/2304.03442)).

### 2.3 Hybrid lexical + semantic retrieval with structured filters

Hybrid retrieval is **very likely (80-90%) preferable to vector-only retrieval** for this owner's mixture of exact error strings, identifiers, paths, and conceptual queries. Evidence: basic-memory officially supports full-text, vector, hybrid, and frontmatter-filtered search; Graphiti combines semantic, BM25, and graph retrieval; the ACL 2026 analysis shows that keys and retained contextual values materially affect retrieval and QA ([Basic Memory semantic search](https://docs.basicmemory.com/concepts/semantic-search), [Graphiti](https://github.com/getzep/graphiti), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)). The owner-specific effect size is **UNVERIFIED**; settle it with a query set split into exact fingerprint/path/ref, paraphrase, temporal, and multi-hop classes.

### 2.4 Agent-controlled sleep-time/dreaming

Background reflection that edits labeled memory blocks is **roughly even (45-55%) for net benefit** in this harness. Letta now ships sleep-time agents, inspectable memory blocks, message search, and Git-backed memory files, demonstrating a real implementation rather than a concept ([Letta AI Memory SDK](https://github.com/letta-ai/ai-memory-sdk), [Letta Code](https://github.com/letta-ai/letta-code)). The benefit is **UNVERIFIED**, because no independent evidence found here shows that Letta's background rewriter improves owner-like coding outcomes more than milestone-triggered explicit notes; settle it with a shadow run that forbids the background agent from overwriting source episodes and compares post-compaction task success and false-memory rate. It also risks introducing a second orchestration runtime, so it fails this program's anti-overfit gate as a production recommendation.

### 2.5 Temporal knowledge graphs

Bi-temporal facts plus episode provenance are **likely (55-80%) useful as a data model**, supported by Memora's mutation failures and Graphiti's concrete validity-window design ([Memora](https://arxiv.org/abs/2604.20006), [Graphiti](https://github.com/getzep/graphiti)). A graph database and graph traversal are only **unlikely (20-45%) to justify their operational cost for this owner now**: the ACL 2026 controlled study finds graph advantages depend on representation and answer context, reports much higher graph extraction time, and shows graph retrieval gains can fail to improve or can reduce QA accuracy ([ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)). The schema should be borrowed; the daemon should not.

### 2.6 Automatic memory evolution à la A-MEM

A-MEM's Zettelkasten-style notes, tags, contextual descriptions, and dynamic links are **likely (55-80%) helpful for discovery**, supported by its multi-model benchmark and convergent implementation in Markdown/linked-note systems ([A-MEM](https://arxiv.org/abs/2502.12110)). Automatically rewriting existing notes when new notes arrive is **unlikely (20-45%) safe enough for durable harness truth**, supported by HaluMem and the continuous-consolidation study. The automatic-evolution premise is **UNVERIFIED** on owner data; settle it by requiring every proposed rewrite to include a diff, source episode IDs, and an independently checkable entailment label, then measuring accepted versus rejected rewrites ([HaluMem](https://arxiv.org/abs/2511.03506), [continuous-consolidation study](https://arxiv.org/abs/2605.12978)).

## 3. What is hype, and how to tell

### 3.1 “Human-like memory” is usually an analogy, not an evaluation

Episodic, semantic, working, reflection, sleep, and forgetting labels can organize design space, but a cognitive analogy does not establish computational benefit. CoALA explicitly offers an organizing framework; Generative Agents tests believability in a simulation; newer systems often promote the analogy beyond the measured task ([CoALA](https://arxiv.org/abs/2309.02427), [Generative Agents](https://arxiv.org/abs/2304.03442)). **Hype detector:** ask for an ablation against raw episodes plus a simple flat/hybrid index, using identical backbone, evidence budget, and judge.

### 3.2 “SOTA agent memory” based on one dialogue benchmark is not a replacement case

Mem0 reports a 26% relative LLM-judge gain over an OpenAI baseline and 91% lower p95 latency than full context on LoCoMo, but all authors use a `research@mem0.ai` affiliation, the comparison uses product-specific adaptations, and the judge prompt explicitly says to be generous and count an answer correct if it merely touches the same topic. Its graph variant improves the overall judge score only modestly and underperforms flat Mem0 in some categories ([Mem0 paper](https://arxiv.org/pdf/2504.19413)). Later independent benchmark families expose extraction, update, invalid-memory, and selective-forgetting failures that LoCoMo end-to-end QA does not isolate ([HaluMem](https://arxiv.org/abs/2511.03506), [Memora](https://arxiv.org/abs/2604.20006), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench)). **Hype detector:** require owner-domain shadow evaluation, exact judge prompt disclosure, negative scoring for stale facts, and stage-level error counts.

### 3.3 “Graph” is not a quality guarantee

Mem0's paper describes graphs as enabling advanced interconnected reasoning, and Zep/Graphiti market temporal graphs as state of the art ([Mem0](https://arxiv.org/pdf/2504.19413), [Graphiti](https://github.com/getzep/graphiti)). The controlled ACL 2026 study finds inconsistent graph benefits, fragmented-node failures, distracting timestamp failures, and large graph construction overhead; retained, cohesive flat memory notes can outperform graph answer contexts ([ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)). **Hype detector:** compare end-to-end answer accuracy—not only retrieval recall—against a strong flat baseline with the same extraction model, evidence values, top-k, and token budget.

### 3.4 “Automatic forgetting” via time decay confuses age with invalidity

An old invariant can remain correct; a frequently accessed fact can become false today. Memora's forgetting-aware metric targets obsolete/invalidated use, while bi-temporal systems track validity windows rather than treating elapsed time as truth ([Memora](https://arxiv.org/abs/2604.20006), [Graphiti temporal model](https://github.com/getzep/graphiti)). **Hype detector:** test retroactive corrections, future-effective changes, former roles, and explicit withdrawals. A recency-decay curve alone cannot represent these cases.

### 3.5 “Automatic consolidation makes the agent learn” hides lossy rewriting

Consolidation may produce reusable abstractions, but repeated LLM rewriting can drift, omit exceptions, and overwrite source distinctions. Controlled 2026 results show useful memory becoming harmful and raw episodic controls remaining competitive ([continuous-consolidation study](https://arxiv.org/abs/2605.12978)). **Hype detector:** require immutable source episodes, deterministic provenance, a consolidation diff, and an ablation with consolidation disabled.

### 3.6 “Local and secure” can describe storage while inference leaves the machine

OpenMemory's official architecture uses a local FastAPI/MCP service, relational metadata, Qdrant, dashboard, ACLs, and audit logs, but its memory intelligence is Mem0 and an LLM/embedder configuration; local storage does not by itself imply local inference ([OpenMemory architecture](https://mem0.ai/blog/how-to-make-your-clients-more-context-aware-with-openmemory-mcp), [Mem0 repository guide](https://github.com/mem0ai/mem0/blob/main/AGENTS.md)). **Hype detector:** inventory every network egress path for extraction, embedding, reranking, telemetry, and UI authentication, not only the database location.

## 4. Re-examining basic-memory versus mem0/OpenMemory

### 4.1 What basic-memory now demonstrably provides

Basic Memory is file-first: Markdown is authoritative, while its database is a secondary index; it exposes MCP content, search, graph/context, project, and schema tools ([technical architecture](https://docs.basicmemory.com/reference/technical-information), [repository](https://github.com/basicmachines-co/basic-memory)). Its current search supports exact/full-text, vector/semantic, hybrid retrieval, and frontmatter filters, with chunk-level indexing and incremental updates ([semantic-search documentation](https://docs.basicmemory.com/concepts/semantic-search)). Its schema system can validate frontmatter fields and allowed values ([schema documentation](https://docs.basicmemory.com/concepts/schema-system)).

These properties matter because durable memory stays inspectable, diffable, editable, exportable, and recoverable independently of a model or vector index. The repository has also had serious faults—the changelog documents a fixed permalink-collision bug that could overwrite a similarly named file—so transparency is not the same as infallibility ([Basic Memory changelog](https://github.com/basicmachines-co/basic-memory/blob/main/CHANGELOG.md)).

I could not establish from official external documentation that Basic Memory natively enforces valid-time intervals, supersession semantics, episodic-to-semantic provenance, or current-only retrieval. Two mechanically independent probes were used: documentation/source-domain searches for temporal fields and inspection of the official architecture/tool/schema descriptions; both did find known-present controls such as hybrid search, schemas, CRUD, and timestamps, proving the detector was not generally blind ([technical architecture](https://docs.basicmemory.com/reference/technical-information), [semantic search](https://docs.basicmemory.com/concepts/semantic-search), [schema system](https://docs.basicmemory.com/concepts/schema-system)). Because absence from indexed docs is not proof of code absence, this remains a **GAP**, not a claim that the features do not exist.

### 4.2 What mem0 now demonstrably provides

Mem0 is materially stronger than a simplistic “vector memory” description. It extracts candidate facts with an LLM, retrieves similar memories, and asks an LLM to choose add/update/delete/no-op; it exposes history and CRUD APIs, supports numerous LLM/embedder/vector/graph backends, has an optional graph layer, and now ships CLI, MCP, editor-plugin, and official benchmark surfaces ([paper architecture](https://arxiv.org/pdf/2504.19413), [current source prompt](https://github.com/mem0ai/mem0/blob/main/mem0/configs/prompts.py), [current core source](https://github.com/mem0ai/mem0/blob/main/mem0/memory/main.py), [repository guide](https://github.com/mem0ai/mem0/blob/main/AGENTS.md), [memory evaluation docs](https://docs.mem0.ai/core-concepts/memory-evaluation)).

The risks are also concrete. The durable write path depends on model extraction and model-selected mutation. Current source contains exact-hash deduplication and fallbacks, but operational reports include silent memory loss after partial batch-embedding failure, delayed visibility after writes, indiscriminate auto-capture, and stacked self-hosted OpenMemory regressions. These reports establish observed failure modes, not population rates ([open issues list](https://github.com/mem0ai/mem0/issues), [delayed retrieval issue](https://github.com/mem0ai/mem0/issues/2386), [indiscriminate capture discussion](https://github.com/mem0ai/mem0/discussions/4289)).

For a 3B local model, automatic extraction and contradiction resolution are **likely (55-80%) less reliable than with the GPT-4o-mini used in Mem0's paper**, based on model-capacity sensitivity reported in a mem0 issue and the **UNVERIFIED** mechanistic preprint; settle this by running the exact local 3B model through HaluMem extraction/update subsets and an owner-derived contradiction suite ([retrieval issue discussion](https://github.com/mem0ai/mem0/issues/2386), [mechanistic preprint](https://arxiv.org/abs/2605.03354)). This premise is why replacement would be especially risky at 3B.

### 4.3 What OpenMemory is—and is not

OpenMemory is a self-hosted memory platform around Mem0: FastAPI plus MCP, relational metadata, Qdrant semantic storage, app/user access control, audit logging, and a Next.js dashboard. The current monorepo describes FastAPI/Alembic/MCP and Next.js/React components; the official architecture describes SQLite or Postgres metadata plus Qdrant and client-scoped controls ([repository guide](https://github.com/mem0ai/mem0/blob/main/AGENTS.md), [OpenMemory architecture](https://mem0.ai/blog/how-to-make-your-clients-more-context-aware-with-openmemory-mcp)).

OpenMemory therefore improves administration, sharing, access control, and observability; it does not supply independent evidence that Mem0's extraction/consolidation/update decisions are more accurate. For a single-owner harness already using MCP and an inspectable store, its extra services are **unlikely (20-45%) to outweigh their operational and epistemic cost**, supported by the overlap in bus capabilities and issue reports but **UNVERIFIED** until a shadow deployment measures task success, memory error rate, maintenance time, startup reliability, and resource use on this machine ([OpenMemory architecture](https://mem0.ai/blog/how-to-make-your-clients-more-context-aware-with-openmemory-mcp), [mem0 issues](https://github.com/mem0ai/mem0/issues)).

### 4.4 Revised verdict on the earlier rejection

The honest revision is:

- **Do not reverse the rejection.** Replacement is **very unlikely (5-20%) to be net-positive now**, because no independent owner-domain evidence offsets the risks of lossy autonomous writes and a larger service surface. Evidence: [HaluMem](https://arxiv.org/abs/2511.03506), [Memora](https://arxiv.org/abs/2604.20006), [continuous-consolidation study](https://arxiv.org/abs/2605.12978), [OpenMemory architecture](https://mem0.ai/blog/how-to-make-your-clients-more-context-aware-with-openmemory-mcp).
- **Do update the reason.** “Mem0 is merely hype” would be false: it has a large active repository, many backends, current plugins/MCP, self-hosting, and an evaluation suite ([repository guide](https://github.com/mem0ai/mem0/blob/main/AGENTS.md), [evaluation docs](https://docs.mem0.ai/core-concepts/memory-evaluation)). The evidence-based objection is misaligned authority and complexity, not nonexistence.
- **Borrow mechanisms, not runtime.** Candidate extraction, update/no-op classification, structured memory types, temporal metadata, and benchmark tooling are useful design references. Their mutations should become proposals or derived notes over immutable evidence rather than silent authoritative edits.
- **Revisit only after a shadow trial.** A replacement case requires owner-domain wins on stale-fact rate, provenance, post-compaction task success, write precision/recall, latency, token cost, and operational reliability—not LoCoMo score alone.

## 5. Specific things this harness should adopt

### 5.1 CONFIG — Define an episodic/semantic/procedural note contract

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Use existing Markdown/frontmatter/schema facilities to define three explicit note kinds:

- `episode`: append-only evidence about a bounded goal, attempt, decision, failure, or milestone; includes source/session identifier, observed time, outcome, and links to artifacts.
- `semantic`: a durable fact, preference, constraint, or generalized lesson; includes one or more `derived_from` episode permalinks.
- `procedure`: an executable or checkable workflow; includes preconditions, validation command, failure modes, and the evidence episodes that justified it.

This is **very likely (80-90%) useful**, because it operationalizes the CoALA distinction while preserving the raw/derived separation supported by the consolidation and ACL 2026 evidence ([CoALA](https://arxiv.org/abs/2309.02427), [continuous-consolidation study](https://arxiv.org/abs/2605.12978), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)).

**Anti-overfit gate:** passes. It uses the existing Markdown/schema/MCP bus and adds no runtime, database, trained critic, or second orchestrator.

### 5.2 BUILD-SMALL — Add temporal-validity and supersession validation

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add a validator invoked at memory write/edit boundaries or as a small skill command. Recommended fields:

```yaml
memory_type: semantic
observed_at: 2026-07-18T10:00:00+03:00
valid_from: 2026-07-18
valid_to: null
status: active          # active | superseded | retracted | archived | disputed
supersedes: []          # permalinks
superseded_by: null     # permalink
derived_from: []        # episode permalinks
confidence: verified    # verified | inferred | unverified
```

The validator should reject neither ordinary prose nor missing optional validity dates. It should flag, with a terminal result, only structural contradictions such as `status: superseded` without `superseded_by`, an active note pointing to a later active value for the same declared subject/key, or a semantic note with no evidence link when the schema marks one required. Retrieval instructions should prefer `status: active`, but historical queries should include superseded records.

This is **very likely (80-90%) useful**, supported independently by Memora's stale-memory penalties, Graphiti's validity-window/provenance data model, and the ACL 2026 argument against deleting historically useful facts ([Memora](https://arxiv.org/abs/2604.20006), [Graphiti](https://github.com/getzep/graphiti), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)).

**Anti-overfit gate:** passes. It borrows bi-temporal semantics without introducing a graph database or durable-execution engine.

### 5.3 CONFIG — Make consolidation milestone/recurrence-gated and provenance-preserving

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Change the memory-writing rule from “summarize the session” to:

1. Always retain the terminal episode/milestone evidence.
2. Create or update a semantic note only when a fact is explicitly corrected, a goal reaches a terminal state, the same lesson recurs in at least two independent episodes, or the owner explicitly asks to persist it.
3. Never overwrite source episodes.
4. Any semantic rewrite must cite the old note, new evidence episodes, and supersession relation.
5. If evidence conflicts and no deterministic rule resolves it, mark `disputed`; do not let the model silently choose.

This is **very likely (80-90%) safer than eager consolidation**, based on independent negative evidence for continuous rewriting and positive but still emerging recurrence-gating evidence ([continuous-consolidation study](https://arxiv.org/abs/2605.12978), [RecMem](https://arxiv.org/abs/2605.16045)).

**Anti-overfit gate:** passes. It changes policy on the existing memory bus and adds no daemon.

### 5.4 CONFIG — Treat forgetting as retrieval policy with explicit exceptions

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Current-answer retrieval should exclude `superseded`, `retracted`, and `archived` notes unless the query is historical or asks for prior attempts. Do not apply global time decay to verified constraints, decisions, procedures, or invariants. Time/usage decay may rank transient conversational preferences or low-confidence inferred notes, but it must not determine truth. Physical deletion should be reserved for user request, secrets, legal retention, or corrupt duplicates after provenance is preserved elsewhere.

This is **very likely (80-90%) useful**, supported by Memora's invalid-memory penalty, MemoryAgentBench's selective-forgetting competency, and the need to preserve former facts for historical questions ([Memora](https://arxiv.org/abs/2604.20006), [MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)).

**Anti-overfit gate:** passes. It is query/filter policy over the current store.

### 5.5 CONFIG — Use dual-channel retrieval: derived keys, original evidence values

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Search semantic summaries, exact fingerprints, keywords, tags, and episode titles as keys; when a result affects an action or conclusion, retrieve the linked original episode/artifact as the evidence value. For temporal questions, expand the query with the relevant observed/valid interval. For exact identifiers and error strings, force lexical/hybrid search before vector-only search.

This is **very likely (80-90%) useful**, because LongMemEval finds fact-augmented keys and time-aware query expansion beneficial, and the ACL 2026 study finds derived keys plus retained raw sessions stronger than isolated derived fragments in important settings ([LongMemEval](https://arxiv.org/abs/2410.10813), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf), [Basic Memory hybrid search](https://docs.basicmemory.com/concepts/semantic-search)).

**Anti-overfit gate:** passes. It uses the existing hybrid index and Markdown links.

### 5.6 BUILD-SMALL — Add stage-level memory evaluation on owner-derived cases

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Create a small deterministic fixture runner, not a full benchmark platform. Start with 30-50 cases sampled from real owner corrections and failures, each containing an input episode stream and expected:

- captured evidence facts;
- rejected non-durable trivia;
- active versus superseded fact at query time;
- historical answer;
- abstention when evidence is missing;
- source episode permalink;
- post-compaction task action or answer.

Score stages separately: write precision/recall, mutation correctness, retrieval recall@k, stale-fact rate, provenance coverage, abstention, answer/action correctness, tokens, latency, and tool failures. Include exact-path/error-string cases, paraphrases, corrections, retroactive corrections, future-effective changes, recurring lessons, and conflicting sources. Use a deterministic exact/structured scorer where possible; if an LLM judge is necessary, disclose its prompt and audit a random sample manually.

This is **almost certain (90-99%) necessary before changing memory runtimes**, supported by the benchmark fragmentation and operation-level failures documented across LongMemEval, HaluMem, Memora, and ACL 2026 ([LongMemEval](https://arxiv.org/abs/2410.10813), [HaluMem](https://arxiv.org/abs/2511.03506), [Memora](https://arxiv.org/abs/2604.20006), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf)).

**Anti-overfit gate:** passes if kept as fixtures plus a thin runner. It fails if expanded into a new evaluation service, observability SaaS, or trained critic; do not do that.

### 5.7 CONFIG — Require proposal mode for 3B-authored durable mutations

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).** A 3B model may propose `ADD`, `UPDATE`, `SUPERSEDE`, or `NOOP`, but durable changes must either be directly entailed by quoted/source-linked evidence or be approved by a stronger verification pass or the owner. It must never physically delete or silently rewrite an episode. For explicit owner statements such as “my preference is now X,” deterministic field-level supersession can proceed without a second model if both old and new notes remain linked.

This is **very likely (80-90%) prudent**, supported by HaluMem's write-stage hallucinations, mem0's LLM-authoritative mutation design, and the continuous-consolidation regression; the added 3B-specific capacity premise remains **UNVERIFIED** until the local experiment described above ([HaluMem](https://arxiv.org/abs/2511.03506), [Mem0 architecture](https://arxiv.org/pdf/2504.19413), [continuous-consolidation study](https://arxiv.org/abs/2605.12978)).

**Anti-overfit gate:** passes. This is an authority rule, not a trained critic or guardrail framework.

### 5.8 BUILD-SMALL — Run a bounded mem0/OpenMemory shadow trial, not a migration

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Export a fixed, non-sensitive set of owner-derived episodes to both systems; prevent either from becoming authoritative; replay the same queries; and capture outputs in the fixture schema above. Run three arms: basic-memory current behavior, basic-memory with the proposed temporal/provenance policy, and mem0 flat memory. Add OpenMemory only if ACL/audit/dashboard behavior itself is under evaluation; it does not need a separate accuracy arm because it uses Mem0 underneath.

Replacement becomes eligible only if mem0 wins materially on owner-task success and stale-fact/provenance metrics without unacceptable resource, network, or maintenance cost. A suggested decision rule is **UNVERIFIED** until baseline variance is measured: at least a 10 percentage-point absolute improvement in post-compaction task success, no increase in stale-fact rate, at least 95% provenance coverage, and no new recurring service failures; settle the threshold by repeating the baseline arm and estimating run-to-run variance.

This trial is **likely (55-80%) worth doing after the smaller policy changes**, because mem0 has advanced enough to deserve measurement but not enough to justify blind replacement ([Mem0 repository guide](https://github.com/mem0ai/mem0/blob/main/AGENTS.md), [Mem0 evaluation docs](https://docs.mem0.ai/core-concepts/memory-evaluation)).

**Anti-overfit gate:** passes only as an offline, bounded adapter/fixture run. A permanent sidecar, second orchestration runtime, or dual-write production path would fail the gate absent measured superiority.

## 6. Concrete target architecture

The minimal target is not a new “memory OS.” It is a disciplined projection over the current store:

```text
tool/session events
      |
      v
append-only episodic note --------------> exact/hybrid searchable evidence
      |                                      ^
      | terminal milestone / recurrence      |
      v                                      |
proposed semantic/procedural note --derived_from--+
      |
      | deterministic validity/supersession validator
      v
active semantic view ----hybrid retrieval----> query
      |                                          |
      +-- linked original evidence values -------+
```

This target is **very likely (80-90%) sufficient for the next harness generation**, because every component rides existing Markdown, schema, search, skill, and hook surfaces; it adds evidence preservation and temporal correctness without a second runtime. Evidence for the design primitives comes from [LongMemEval](https://arxiv.org/abs/2410.10813), [HaluMem](https://arxiv.org/abs/2511.03506), [Memora](https://arxiv.org/abs/2604.20006), [ACL 2026 analysis](https://aclanthology.org/2026.acl-long.1232.pdf), and [continuous-consolidation study](https://arxiv.org/abs/2605.12978).
