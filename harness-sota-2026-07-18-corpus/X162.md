# X162 — Military doctrine → agent-claim verification

## Executive judgment

Military doctrine has **not** solved “truth without trust.” It has solved a narrower and highly relevant problem: how a commander can act on reports from distributed actors, under time pressure and uncertainty, without personally observing every action. The transferable mechanism is not any one slogan such as OODA or commander’s intent. It is a layered control pattern:

1. state the desired end state and essential tasks;
2. make the subordinate restate the task and intended method before execution;
3. decide in advance what observable indicators will count as task performance and real-world effect;
4. assign observation and collection responsibility to actors other than the performer where practical;
5. reconstruct intended versus actual events against standards after execution; and
6. deliberately challenge the assumptions and rival explanations that could make an apparently successful report false.

This pattern transfers because both military command and an agent harness have distributed execution, partial observability, asymmetric information, costly comprehensive review, and a need to reserve scarce scrutiny for consequential uncertainty. It does **not** transfer as proof merely by analogy: military assessment tolerates ambiguity, judgment, hierarchy, and trust, while many software claims admit exact machine checks. An agent harness should borrow the control structure but replace oral reports and commander judgment with provenance-bearing machine observations whenever possible.

The central recommendation is a small “verification order” protocol riding the existing hook/tool/agent bus. It would turn consequential claims into typed assertions, predeclare their acceptance evidence, collect observations from the execution substrate rather than from the claimant’s prose, require independent corroboration for absence and completion claims, and invoke bounded adversarial review only where risk or conflicting evidence warrants it. **This recommendation is UNVERIFIED; the settling experiment is the stratified replay benchmark specified in §11.** It is **likely (55-80%)** to reduce accepted false-completion and false-absence claims materially, because the doctrine independently supports predeclared standards, assigned observers, multiple perspectives, and assumption challenge, while the actual effect size in an agent harness has not yet been measured.

## 2. What the source field actually does

### 2.1 Commander’s intent: define success without prescribing every action

In Army mission command, a commander gives subordinates the purpose, key tasks, and desired end state, enabling disciplined initiative when events depart from the plan. ADRP 6-0 describes mission command as a response to uncertainty and decentralizes decisions to the point of action; its principles include shared understanding, clear commander’s intent, mission orders, disciplined initiative, and prudent risk (ADRP 6-0, paras. 2-1–2-3, pp. 2-1–2-2, source above). The same doctrine defines commander’s intent as a clear, concise statement of purpose and desired military end state, with key tasks that must be performed to achieve that end state.

This is not a verification mechanism by itself. It is the **reference state** against which later evidence can be assessed. Without it, a subordinate can report impressive activity that does not accomplish the mission. In verification terms, intent separates “the agent did work” from “the owner’s required outcome exists.”

The transfer is strong for goal alignment and weak for factual proof. A concise end-state contract gives a verifier the proposition to test, but it supplies no observation that the proposition is true.

### 2.2 Confirmation brief and backbrief: test understanding before action

The Army’s confirmation brief occurs immediately after an operations order. The commander requires subordinate commanders to restate what they are intended to do and why. The published agenda includes specified, implied, and essential tasks, a draft mission statement, and “war stoppers.” A later backbrief explains how the subordinate will accomplish the mission within the commander’s intent (*Commander and Staff Guide to Rehearsals*, pp. 73–74 / PDF pp. 80–81).

This mechanism catches a different error from post-hoc testing: a subordinate may execute competently against a misunderstood task. Restatement exposes semantic divergence before resources are spent. It is closer to a protocol handshake than to an audit.

The transfer is structurally sound when the restatement is not a paraphrase exercise. An agent should have to emit testable end-state propositions and identify ambiguous acceptance criteria. A second language model merely saying “I agree” would add almost no evidence.

### 2.3 Assessment planning: distinguish activity from effect and precommit indicators

Joint assessment doctrine separates a measure of performance (MOP)—whether friendly actions or assigned tasks were performed—from a measure of effectiveness (MOE)—whether behavior, capability, the environment, an objective, or an end state changed. The assessment process is monitoring, evaluating, and directing/recommending, and the assessment components include objectives, effects, tasks, MOPs, MOEs, and indicators (*Commander’s Handbook for Assessment Planning and Execution*, pp. I-6–I-7 / PDF pp. 19–20; pp. II-5 onward).

This distinction is the strongest direct mapping to agent verification:

- MOP analogue: “the patch command returned success,” “the file was written,” or “the test runner executed.”
- MOE analogue: “the defect no longer reproduces,” “the requested behavior is observable from the public interface,” or “the deployed system serves the new behavior.”

The handbook says assessment planning identifies potential data sources, including external civilian and academic sources; identifies current and desired conditions; explicitly acknowledges underlying assumptions; and continually challenges those assumptions during evaluation (pp. IV-4–IV-5 / PDF pp. 61–62). It also warns against assuming causality merely because all assigned actions completed: actions may fail to create the desired effect because of unknown actors, unknown linkages, or an incomplete plan (Appendix F, pp. F-9–F-10 / PDF pp. 126–127).

That warning maps exactly onto a common class of agent claim: “all commands succeeded, therefore the task is done.” Execution success is a performance observation, not proof of user-visible effect.

### 2.4 After-action review: reconstruct intended versus actual from multiple perspectives

TC 25-20 defines an AAR as a professional discussion focused on performance standards that lets participants discover what happened, why it happened, and how to sustain strengths or improve weaknesses. It says no commander sees as much as all the participants and that an AAR supplies details often missing from evaluation reports (chapter 1, “Definition and Purpose”). Its formal format explicitly compares commander’s mission and intent—“what was supposed to happen”—with the summary of events—“what happened”—then asks why and how to improve (chapter 1, figure 1-2; chapter 4, figure 4-1).

More importantly for verification, the AAR is planned before the exercise. The plan identifies critical places and events to observe, assigns observation responsibilities, and uses external observers/controllers for formal reviews. TC 25-20 advises observers to avoid evaluating their own duties where possible because objectivity about one’s own performance is difficult (chapter 2, “Selecting and Training Observers and Controllers”).

The transferable mechanism is therefore not “have the agent reflect.” It is **pre-position independent observation around critical events, then reconcile the observations with the claim and standard**. Self-reflection alone preserves the original epistemic dependency and is not an independent signal.

### 2.5 Red teaming: falsify assumptions and seek rival explanations

The TRADOC Red Team Handbook supplies techniques for challenging facts and assumptions, identifying omitted information, asking whether evidence supports another reasonable conclusion, and constructing rival hypotheses. Its argument-evaluation checklist asks whether an analogy is appropriate, whether another plausible hypothesis explains what happened, whether vital information is omitted, and whether the evidence is open to another conclusion (pp. 103–105 / PDF pp. 115–118). Its assumption sensitivity analysis uses anonymous confidence estimates to focus effort on assumptions with the least confidence (pp. 105–107 / PDF pp. 118–120). Scenario analysis also produces indicators that reveal whether a future is becoming more or less likely (p. 89 / PDF p. 102).

This maps to a bounded falsification step: for a consequential claim, enumerate the cheapest alternative explanations and run discriminating probes. Example: “tests pass” might also be explained by zero tests discovered, a filtered test selection, cached results, or testing the wrong artifact. The verifier should choose probes that distinguish these hypotheses, not ask another model for a generic critique.

Red teaming does not create truth. It increases the chance of finding a counterexample. Agreement by an adversarially prompted copy of the claimant is still correlated evidence.

### 2.6 OODA: continuous feedback, not a four-box checklist

Boyd’s observe–orient–decide–act loop is cyclic: after action, the actor observes consequences and begins again; orientation incorporates experience, culture, new information, and feedback. Air University’s history emphasizes both the renewed observation after action and the centrality of orientation (*Airmen and Air Theory*, Boyd discussion in the John Boyd chapter, source above). An Air & Space Power Journal treatment reproduces Boyd’s richer loop with feedback paths and “unfolding environmental interaction,” while warning that the familiar “get inside the opponent’s OODA loop” shorthand can be overly simplistic: <https://www.airuniversity.af.mil/Portals/10/ASPJ/journals/Volume-28_Issue-2/ASPJ-Mar-Apr-2014.pdf>, pp. 31–33.

The mapping is a **verification cadence**: act, observe the actual environment, update the hypothesis, and reverify when the environment or artifact changes. It rejects a one-time “verified” label detached from artifact version, time, or deployment state.

OODA contributes timing and feedback, not independence. If observation is just the agent rereading its own output, the loop can converge quickly on a false belief.

## 3. The combined mechanism: a verification order

The proposal is not to simulate a headquarters. It is to encode six doctrinal controls in a compact protocol.

### 3.1 Claim types

Every consequential terminal claim should be typed because the proof obligation differs:

| Claim type | Example | Minimum acceptable observation |
|---|---|---|
| Presence | “Configuration contains X” | Direct read of the authoritative artifact at a named version/path |
| Absence | “No references to X remain” | Validated detector with a known-positive control plus a mechanically independent search/measurement |
| Completion | “Feature is done” | MOP evidence for required actions **and** MOE evidence for user-visible end state |
| Correctness | “Function handles case Y” | Executed discriminating test or formal/static predicate tied to Y |
| Causality | “Change A fixed failure B” | Before/after or intervention evidence that distinguishes A from rival causes |
| Freshness | “This is the current value” | Authoritative source observation with timestamp/version and expiry rule |
| External side effect | “Message sent / deployment live” | Receipt from the destination/control plane, not merely a local command exit |
| Interpretation | “Document requires X” | Source span plus an explicit inference; adversarial check if consequential |

The table is a proposed taxonomy, not a military doctrinal taxonomy.

### 3.2 Intent/acceptance contract

Before execution, derive:

- purpose: why the owner wants the work;
- end state: externally observable conditions that mean success;
- essential tasks: actions that must occur;
- constraints: actions that must not occur;
- critical uncertainties and stop conditions;
- acceptance probes: observations that can discriminate success from plausible false-success states.

The agent then gives a machine-readable confirmation brief: it restates these fields and flags ambiguity. The harness compares this brief against the owner request with deterministic presence/constraint checks and, only where semantics require it, a separate review pass.

### 3.3 Evidence collection plan

For each end-state condition, bind in advance:

- a predicate;
- an authoritative observation source;
- collector identity and trust domain;
- artifact version, path, environment, and time window;
- known-positive control where the claim is absence;
- one or two rival explanations to exclude;
- required independence level;
- cost ceiling and timeout;
- result state: verified, contradicted, indeterminate, or expired.

This makes verification prospective rather than allowing an agent to select flattering evidence after seeing the result.

### 3.4 Evidence receipt

The execution substrate—not the claimant’s narrative—should produce a compact receipt for relevant observations:

```json
{
  "claim_id": "C17",
  "predicate": "public_endpoint_returns_expected_schema",
  "collector": "http_probe_hook",
  "trust_domain": "destination",
  "subject": {"url": "...", "deploy_id": "..."},
  "observed_at": "...",
  "exit_status": 0,
  "result_digest": "sha256:...",
  "control": {"name": "known_present_field", "passed": true},
  "outcome": "supports"
}
```

The prose answer may cite the receipt, but cannot mint it. A receipt proves only its stated predicate, against its named subject and time; it is not a universal “done” token.

### 3.5 Verification rule

For a material claim:

1. Reject evidence generated only from the claimant’s prose.
2. Validate the detector on a known-present control before accepting absence.
3. Require a second mechanically independent signal for absence, brokenness, or completion.
4. Separate task execution evidence (MOP) from outcome evidence (MOE).
5. If signals disagree, mark the claim indeterminate and run a discriminating probe; do not average them into confidence.
6. Bind all verified claims to artifact identity and freshness.
7. Sample some apparently low-risk claims unpredictably so the claimant cannot optimize only for known gates.

“Mechanically independent” means a different failure mode, not a rerun of the same command. Examples include filesystem enumeration plus application-level import, source search plus runtime query, local deployment command plus destination receipt, or test-runner result plus direct behavior probe.

### 3.6 Bounded red-team trigger

Invoke adversarial review when any of these holds:

- the claim is irreversible or externally consequential;
- it is an absence, universal, causal, security, or freshness claim;
- evidence comes from one trust domain;
- a detector control fails;
- the agent retried the same action repeatedly;
- the claim’s evidence is indirect or proxy-only;
- two observations conflict;
- the claimed end state differs from the original intent contract.

The red-team output must be operational: a ranked list of rival hypotheses and the cheapest probe that discriminates each one. Free-form criticism without a probe is commentary, not verification.

## 4. Concrete harness changes

### UNVERIFIED proposal A — claim/intent schema (**CONFIG (settings/JSON only)**)

Add a compact schema for purpose, end-state predicates, essential tasks, constraints, claim type, criticality, freshness, and evidence requirements. **UNVERIFIED premise:** a schema this small can cover most consequential terminal claims without creating schema-fragility; settle it by manually labeling a stratified sample of 300 historical terminal claims and measuring coverage, ambiguity, inter-rater agreement, and parse failure.

This is **very likely (80-90%)** to catch goal drift and activity-as-outcome errors, because the confirmation-brief and MOP/MOE distinctions force the task’s purpose, end state, and performed actions into separate fields; the remaining uncertainty is whether agents populate those fields faithfully.

Keep optional fields optional and allow `unknown`/`not_applicable`. Do not make final response generation depend on a large, deeply nested schema. The schema is a verification index, not the full answer.

### UNVERIFIED proposal B — substrate evidence receipts (**BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**)

Add a hook-side receipt generator for tool completion events. It records command/tool identity, subject identity, timestamp, exit state, bounded output digest, and any applicable detector control. **UNVERIFIED premise:** the existing event bus exposes enough tool inputs and results to generate trustworthy receipts without a daemon; settle it with a hook-spike that produces receipts for file read/write, search, test, HTTP, and external side-effect calls and then attempts tampering from the agent channel.

This is **likely (55-80%)** to catch fabricated or scope-shifted evidence, because the receipt is emitted by a component outside the prose-generation path and binds the result to a subject and time. It will not catch a compromised tool, a dishonest external service, or a semantically irrelevant but genuine result.

### UNVERIFIED proposal C — deterministic claim gate (**BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**)

Implement a small rule evaluator that checks receipt coverage, detector controls, independence, MOP/MOE separation, contradictions, artifact version, and expiry. It returns `verified`, `contradicted`, `indeterminate`, or `expired`, plus missing predicates. **UNVERIFIED premise:** deterministic rules can decide enough high-value cases to justify their maintenance burden; settle it by replaying labeled true/false claims and comparing precision, recall, abstention, and latency against ungated answers.

This is **very likely (80-90%)** to prevent at least some single-probe absence claims from being labeled verified, because the rule can mechanically require both a passing known-positive control and a second signal. It is **likely (55-80%)** to improve completion-claim precision, because completion predicates vary and some outcomes are inherently semantic.

The gate should abstain aggressively. “Indeterminate” is an honest state and must not be silently rendered as “done.”

### UNVERIFIED proposal D — discriminating-probe red team (**BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**)

Use an already available isolated model/agent invocation, if present on the existing bus, to receive only the claim, intent contract, evidence receipts, and trust-domain map. It must emit rival hypotheses and executable probes under a strict call/time budget. A deterministic wrapper executes approved read-only probes and feeds receipts back to the gate. **UNVERIFIED premise:** isolation plus evidence-only context produces useful failure-mode diversity rather than correlated paraphrase; settle it with seeded deceptive-evidence cases and compare counterexample discovery against self-critique and random extra testing.

This is **roughly even (45-55%)** to add net value on ordinary low-risk claims, because model correlation and extra cost may dominate. It is **likely (55-80%)** to add value on ambiguous high-risk claims, based on the Red Team Handbook’s explicit rival-hypothesis and omitted-evidence techniques, but this remains an analogy until benchmarked.

Do not let the critic issue a truth verdict. Only executed probes produce new evidence.

### UNVERIFIED proposal E — sampled micro-AAR (**BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**)

On contradictions, false-completion discoveries, repeated retries, or a small random sample, generate a compact record: intended outcome, actual event timeline from receipts, divergence point, failed assumption, corrective rule/probe, and whether that correction generalized on replay. **UNVERIFIED premise:** sampled micro-AARs can yield reusable rules without becoming noisy narrative memory; settle it by measuring how often proposed corrections prevent a separate held-out recurrence and deleting records that fail to generalize.

This is **likely (55-80%)** to expose masked intermediate failures and stale assumptions, because it reconstructs a timeline from substrate observations rather than asking the performer to remember. It is **unlikely (20-45%)** to be worth running on every successful task, because exhaustive reviews add cost and can overfit incidental details.

Store only compact rules and benchmark outcomes through the harness’s existing configuration/artifact mechanisms. Do not create a vector database, knowledge graph, or durable-execution service.

### UNVERIFIED proposal F — OODA-style expiry and re-observation (**CONFIG (settings/JSON only)**)

Assign freshness classes to claims: immutable artifact, workspace state, process state, deployment state, and external/current fact. Verification expires when its bound subject changes or its time-to-live ends. **UNVERIFIED premise:** practical subject/version identifiers are available for most relevant observations; settle it by instrumenting 100 mixed tasks and measuring the fraction of receipts that can be invalidated precisely rather than globally.

This is **very likely (80-90%)** to catch some stale-verification errors for deployments and external state, because a timestamped, subject-bound result can be invalidated mechanically. The value for immutable local artifacts is lower because content digests already provide stable identity.

## 5. What this catches that self-reporting misses

The following are predicted catches, not claims about the local harness:

1. **Successful action, failed outcome.** A build or deploy command exits zero, but the public behavior is unchanged. MOP passes; destination MOE fails. The protocol would catch this **very likely (80-90%)** when a direct outcome probe exists, because the gate requires both classes of evidence.
2. **Empty or mis-scoped test run.** “Tests pass” results from zero discovery, filters, wrong directory, or wrong artifact. A red-team rival-hypothesis probe checks discovery count and runs a targeted behavior case. This catch is **likely (55-80%)**, because the alternatives are cheaply testable but framework-specific.
3. **False absence.** Search returns no hits because the detector used the wrong root, ignored files, failed, or could not spawn. Known-positive validation plus an independent enumeration/runtime probe would catch this **very likely (80-90%)** when a suitable control is available.
4. **Evidence laundering.** The answer asserts a command output that was never observed, or cites output from a different subject/version. Substrate receipts would catch this **likely (55-80%)**, because genuine-but-irrelevant evidence still requires semantic predicates.
5. **Semantic task drift.** The agent completes a technically coherent task that does not satisfy the owner’s purpose. The confirmation brief and end-state contract would catch this **likely (55-80%)** before execution when the owner request is sufficiently explicit.
6. **Masked intermediate failure.** A later successful retry hides that prerequisite state was never established. Timeline reconstruction and dependency predicates would catch this **likely (55-80%)**, depending on event completeness.
7. **Stale truth.** A verified deployment or current fact changes before the terminal answer. Expiry and final re-observation would catch this **likely (55-80%)** when an authoritative cheap probe exists.
8. **Causal overclaim.** Behavior changes after a patch, but cache expiry, service restart, or unrelated state caused it. Before/after and rival-hypothesis probes would catch some cases **roughly even (45-55%)**, because causal identification is intrinsically harder than state verification and Joint assessment doctrine itself warns against casual attribution.

## 6. Why the analogy transfers

### Shared structural properties

- **Distributed action:** the evaluator is not at every point of execution.
- **Partial observability:** reports summarize far more events than a superior can inspect.
- **Costly scrutiny:** observation and review resources must be assigned to critical events.
- **Uncertain environment:** the state can change between order, action, and report.
- **Activity/outcome gap:** completing assigned actions does not ensure the intended effect.
- **Correlated human or model error:** participants can share assumptions and blind spots.
- **Need for graceful initiative:** verification cannot prescribe every implementation move without destroying useful autonomy.

These properties are directly addressed by intent, confirmation, assessment indicators, assigned observers, AAR reconstruction, and red-team assumption challenge in the cited doctrine.

### The transferable invariant

The invariant is: **define the desired state, assign observations before action, keep the observer’s evidence path distinct from the performer’s report, and revisit the model when observations conflict.** This statement is a synthesis of the cited mechanisms, not a quotation from doctrine.

## 7. Why the analogy can fail

### 7.1 The military often seeks decision advantage, not mathematical truth

Commanders routinely act with incomplete and probabilistic information. An assessment can be useful even if it is not proof. Software artifacts often permit exact predicates. Importing military ambiguity where deterministic tests exist would reduce rigor.

**Design consequence:** use machine predicates first; use confidence and commander-like judgment only for genuinely uncertain semantic or external claims.

### 7.2 Military “independence” is imperfect

An observer/controller may share doctrine, incentives, communications, and institutional blind spots with the unit. Multiple people are not automatically mechanically independent.

**Design consequence:** define independence by failure mode and trust domain, not by agent count. Two model calls using the same context and source are one epistemic signal unless they execute different probes.

### 7.3 Deception differs

Military doctrine assumes a strategic adversary who may conceal or spoof. Most coding agents are not strategically deceptive; they are error-prone optimizers producing plausible language. Heavy adversarial machinery can waste effort or encourage reward hacking.

**Design consequence:** adversarial review is risk-triggered and probe-producing, not universal debate.

### 7.4 Physical effects and software state have different observability

Battle damage, political sentiment, and population behavior may require proxy indicators and subjective synthesis. File contents, exit codes, hashes, and endpoint responses can often be directly observed. Copying elaborate campaign-assessment dashboards would be needless complexity.

**Design consequence:** receipts stay predicate-sized; there is no universal score or dashboard requirement.

### 7.5 Hierarchical authority does not establish truth

Rank resolves decisions, not factual contradictions. A “commander agent” choosing between disagreeing agents would merely add another model opinion.

**Design consequence:** disagreement triggers a discriminating observation or an indeterminate result, not authority-based arbitration.

### 7.6 AAR culture does not emerge from a template

TC 25-20 depends on candid participation and an environment in which disagreement is permissible. Agents have no social courage to cultivate, but they do have correlated prompts and reward incentives. A narrative retrospective can become post-hoc rationalization.

**Design consequence:** build the event timeline from receipts first, then allow interpretation; keep only corrections that pass held-out replay.

## 8. Rejected borrows

### Rejected: “run an OODA loop until confident”

This has no stop rule, no independent evidence, and no protection against observing the same faulty source repeatedly. Faster looping can accelerate error. OODA is retained only as feedback/expiry logic.

### Rejected: a standing AI red-team council

Multiple critics can be correlated, expensive, and verbose while producing no new observations. This also trends toward a second orchestration runtime. The retained form is one bounded, evidence-only rival-hypothesis pass triggered by risk, with deterministic probe execution.

### Rejected: universal confidence scores

Combining heterogeneous evidence into one number hides contradiction and invites false precision. The gate uses categorical states—verified, contradicted, indeterminate, expired—and preserves individual predicates.

### Rejected: full military staff emulation

Roles such as commander, intelligence, operations, plans, assessment, and red team are organizational answers to human scale and specialization. Reifying each as an agent would increase coordination surfaces without showing independent information gain.

### Rejected: AARs as durable narrative memory

Narrative archives accumulate local anecdotes and can overfit future behavior. Only compact, replay-tested rules or probes merit retention.

## 9. Anti-overfit gate

All retained proposals ride the existing settings/hook/tool/skill/agent bus. None requires:

- a second orchestration runtime;
- a vector database or knowledge graph;
- a durable-execution engine;
- a trained critic;
- an observability SaaS;
- a guardrail framework; or
- a new daemon/service/runtime.

The design is intentionally subtractable. Each claim rule must demonstrate incremental false-claim detection on held-out tasks at an acceptable abstention and latency cost. Rules that merely restate model judgment, do not cause a discriminating probe, or fail to generalize are removed. This gate is **likely (55-80%)** to limit overfitting if benchmark ownership is separate from rule authorship, because held-out replay penalizes anecdote-specific rules; it is **unlikely (20-45%)** to prevent all overfitting, because the benchmark itself may not represent future task distributions.

## 10. Minimal end-to-end flow

```text
Owner request
    |
    v
Intent + acceptance contract  <-- confirmation brief catches misunderstanding
    |
    v
Agent acts through existing tools
    |
    +--> hook/tool substrate emits scoped evidence receipts
    |
    v
Claim gate compares MOP + MOE + controls + independent signals
    |
    +--> sufficient and current ----------> verified claim
    |
    +--> direct contradiction ------------> contradicted claim
    |
    +--> gap/conflict/high risk
             |
             v
       rival hypotheses + cheapest discriminating probes
             |
             v
       new receipts -> gate
             |
             +--> still unresolved -------> indeterminate claim
    |
    v
Sampled micro-AAR updates only replay-validated rules
```

This flow verifies propositions, not agents. Trust may determine how much sampling is needed, but past reliability never substitutes for evidence on a consequential current claim.

## 11. Settling experiment

The recommendations remain UNVERIFIED until tested. The decisive experiment is a stratified replay benchmark with injected and naturally occurring false claims.

### Dataset

Build a blinded set of at least 400 completed tasks stratified across presence, absence, completion, correctness, causality, freshness, external side effect, and interpretation claims. Include:

- genuine successes;
- genuine failures honestly reported;
- plausible false-success narratives;
- wrong-root and ignored-file absences;
- detector spawn/failure cases;
- zero-test and filtered-test passes;
- stale deployment/current-state receipts;
- genuine but wrong-subject evidence;
- correlated duplicate probes;
- conflicting evidence;
- activity complete but end state unmet;
- causal confounds.

Ground truth must come from benchmark fixtures and independent destination/artifact inspection, not the claimant’s answer.

### Arms

1. baseline self-report;
2. self-report plus generic self-critique;
3. claim schema plus deterministic gate;
4. schema, gate, and substrate receipts;
5. full bounded protocol including red-team discriminating probes and sampled micro-AAR.

### Primary metrics

- false verified rate, with special reporting for absence and completion;
- true verified rate;
- abstention/indeterminate rate;
- time and tool-call overhead;
- verifier-induced task failures;
- number of genuinely independent observations per accepted claim;
- counterexample yield per red-team call;
- stale-verification detection;
- schema/parse failure rate;
- held-out recurrence prevention from AAR-derived rules.

### Acceptance thresholds

Pre-register thresholds before replay. A reasonable initial research target—**UNVERIFIED; settle with the replay itself**—is at least a 50% relative reduction in false verified claims, no more than a 10% relative loss in true verified claims, median latency overhead below 10% on low-risk tasks, and red-team invocation below 15% of tasks. These numbers are engineering hypotheses, not doctrine-derived facts.

### Independence audit

For every accepted “independent” evidence pair, label failure modes and trust domains. Randomly audit at least 50 pairs. If two signals fail under the same seeded defect, reclassify them as one signal and recompute results. This prevents agent count or repeated commands from masquerading as independence.

### Kill criteria

Remove or redesign the mechanism if:

- most gains come from benchmark-specific rules;
- receipts can be forged or rebound to another subject by the claimant;
- schema failures create more false negatives than the gate prevents false positives;
- red-team calls mostly paraphrase concerns without producing successful discriminating probes;
- the system learns to optimize receipt production rather than user-visible outcomes; or
- operational complexity approaches a second runtime.

## 12. Final assessment

The analogy transfers, but the popular components have unequal value:

- **Commander’s intent:** useful for defining the end state; insufficient as proof.
- **Confirmation/backbrief:** useful for catching misunderstood acceptance criteria before action.
- **Operations assessment:** the strongest mapping; it separates performed actions from achieved effects and preplans indicators and sources.
- **AAR:** useful only when grounded in preassigned observation and actual event records; self-reflection alone does not transfer.
- **Red teaming:** useful as bounded rival-hypothesis generation that leads to executable probes; model debate alone does not verify.
- **OODA:** useful for feedback, expiry, and re-observation; it supplies neither independence nor a truth criterion.

The most defensible borrow is therefore not “military-style agents.” It is a compact verification doctrine: **intent before action, observation independent of narration, effect separate from activity, contradiction preserved rather than averaged, and learning admitted only after replay.** Building this as small hooks, receipts, rules, and optional probe generation satisfies the anti-overfit gate. Whether it is better than a simpler deterministic-test-only baseline is **roughly even (45-55%)** until the stratified replay measures the semantic and external claims for which deterministic tests alone are insufficient; the evidence for optimism is the strong structural match, while the evidence for caution is the military system’s dependence on human judgment, imperfect observer independence, and tolerance for uncertainty.
