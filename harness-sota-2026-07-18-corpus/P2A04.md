# P2A04 — Self-improving agent systems: evidence, limits, and a minimum viable closed loop

**Unit:** P2A04  
**Date:** 2026-07-18  
**Lens:** External research only. This unit intentionally did not inspect or infer the owner's current local implementation.  
**Question:** Which ideas behind ACE, GEPA, agent-as-a-judge, Reflexion-style loops, and automatic prompt/skill synthesis have real evidence; which are demonstrations; and what is the smallest defensible closed loop for an agent harness?

## Executive conclusion

The defensible core is much smaller than the phrase “self-improving agent” suggests. The established result is **test-time or offline adaptation of external artifacts**—prompts, demonstrations, procedural memories, or executable skills—when a loop receives a sufficiently reliable outcome signal and evaluates candidate changes. It is not established that an ungrounded model can repeatedly critique itself into correctness, safely rewrite its own harness, or improve indefinitely.

The strongest evidence in this review is:

1. **External feedback beats introspection alone.** The 2024 TACL critical survey found that prompted self-correction was not successfully demonstrated except on tasks unusually suited to it, whereas reliable external feedback made correction work well ([Kamoi et al., 2024](https://aclanthology.org/2024.tacl-1.78/)). ICLR 2024 experiments independently found that intrinsic reasoning self-correction could degrade performance ([Huang et al., 2024](https://openreview.net/forum?id=IkmD3fKBPQ)).
2. **Prompt/context search can produce real, held-out benchmark gains.** OPRO, DSPy/MIPRO, GEPA, and ACE each report gains over non-optimized or competing baselines, with GEPA and ACE accepted at ICLR 2026 ([OPRO](https://arxiv.org/abs/2309.03409), [MIPRO](https://arxiv.org/abs/2406.11695), [GEPA](https://arxiv.org/abs/2507.19457), [ACE](https://openreview.net/pdf?id=eC4ygDs02R)). This establishes bounded optimization, not general recursive improvement.
3. **Procedural memory and skill reuse can transfer within structured domains.** Agent Workflow Memory, accepted at ICML 2025, reports gains across more than 1,000 web tasks and cross-task/domain evaluations ([AWM](https://proceedings.mlr.press/v267/wang25bx.html)); Voyager, accepted by TMLR, reports transfer of executable Minecraft skills to a new world ([TMLR record](https://openreview.net/submissions?page=233&venue=TMLR), [paper](https://arxiv.org/abs/2305.16291)). A 2026 comparison of 15 memory methods nevertheless finds no universally best memory and says long-context baselines remain competitive ([EvoMemBench](https://arxiv.org/abs/2605.18421)).
4. **An agentic evaluator can gather evidence better than a single-pass judge in some settings, but it is not a truth oracle.** The original Agent-as-a-Judge work reported 90.44% black-box alignment with human consensus for OpenHands versus 60.38% for an LLM judge on its 55-task DevAI benchmark ([Zhuge et al., 2024](https://arxiv.org/abs/2410.10934)). The later 155-task AJ-Bench found consistent gains over LLM-as-a-judge but “substantial open challenges” ([Shi et al., 2026](https://arxiv.org/abs/2604.18240)). On evidence-based research traces, the best judges in REFLECT remained below 55% overall accuracy ([REFLECT](https://arxiv.org/abs/2605.19196)).

Therefore the minimum viable closed loop is not “agent reflects, edits itself, and continues.” It is:

> **Observe a terminal outcome → attribute a narrow, evidence-cited failure or reusable success → propose one bounded textual artifact change → replay on a disjoint validation/canary set → promote only on measured improvement with no critical regression → retain provenance and automatic rollback.**

This can ride the existing hook/skill bus as a small batch process. It does not need a second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

## Method and evidence grading

I prioritized peer-reviewed conference/journal pages, arXiv papers linked to official code, official project documentation, and repository issue/release records. A paper’s own benchmark is evidence that its reported method worked under that experiment; it is not independent replication. “Accepted” means venue acceptance could be corroborated from an official venue/project record. “Demo” means a proof of concept or narrow experiment without evidence sufficient for the owner’s broad harness claim.

The web search detector was validated against known-present items: it found the official GEPA paper and repository ([paper](https://arxiv.org/abs/2507.19457), [repo](https://github.com/gepa-ai/gepa)), ACE’s ICLR paper and repository ([paper](https://openreview.net/pdf?id=eC4ygDs02R), [repo](https://github.com/ace-agent/ace)), and Reflexion’s paper and repository ([paper](https://openreview.net/pdf?id=vAElhFcKW6), [repo](https://github.com/noahshinn024/reflexion)). A separate venue-index signal verified ACE’s ICLR 2026 status through the official project acceptance notice ([ACE notice](https://ace-agent.github.io/blogs/2026-01-30-iclr-acceptance/)), GEPA’s through the arXiv metadata naming ICLR 2026 Oral ([GEPA metadata](https://arxiv.org/abs/2507.19457)), AWM’s through PMLR ([ICML proceedings](https://proceedings.mlr.press/v267/wang25bx.html)), and Voyager’s through OpenReview’s TMLR record ([TMLR submissions](https://openreview.net/submissions?page=233&venue=TMLR)).

No claim of independent replication is made unless explicitly stated. Where I did not find enough evidence, I report a gap rather than an absence.

## 1. What is actually established

### 1.1 “Self-improvement” here usually means artifact optimization, not model improvement

ACE explicitly modifies contexts rather than model weights, maintaining an evolving playbook through generator, reflector, and curator roles; its merger of itemized deltas is deterministic rather than another generative rewrite ([ACE paper, §§1 and 3](https://arxiv.org/abs/2510.04618)). GEPA evolves textual components by sampling trajectories, reflecting on failures and feedback, proposing prompt mutations, and retaining candidates on a Pareto frontier ([GEPA paper](https://arxiv.org/abs/2507.19457), [official algorithm overview](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/api/optimizers/GEPA/overview.md)). DSPy describes optimizers as tuning prompt instructions, demonstrations, or weights against a user-supplied metric ([official optimizer documentation](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/learn/optimization/optimizers.md)). Reflexion stores verbal feedback in episodic context and does not update weights ([Reflexion](https://openreview.net/pdf?id=vAElhFcKW6)).

This distinction matters. The evidence supports **non-parametric adaptation under an objective**, not an agent increasing the underlying model’s general intelligence. Calling both “self-improvement” without naming the optimized artifact and the evaluator is category inflation.

### 1.2 Reflexion-style correction works when the environment contributes information

Reflexion’s NeurIPS 2023 experiments reported improvements in sequential decision-making, coding, and language reasoning. Its coding loop used compiler/test feedback, and its design permits external scalar or textual feedback ([Reflexion paper](https://openreview.net/pdf?id=vAElhFcKW6)). The original 91% HumanEval result is therefore evidence for a **generate–execute/evaluate–reflect–retry** loop, not evidence that a model can discover its own mistakes without an oracle.

Two independent research signals constrain the broader interpretation:

- ICLR 2024’s *Large Language Models Cannot Self-Correct Reasoning Yet* found that models often failed to improve and sometimes degraded when asked to self-correct reasoning without external feedback ([paper and reviews](https://openreview.net/forum?id=IkmD3fKBPQ)).
- The 2024 TACL critical survey concluded that prompted self-feedback had not demonstrated successful correction except on unusually suitable tasks, while reliable external feedback worked and fine-tuning could train correction behavior ([Kamoi et al.](https://aclanthology.org/2024.tacl-1.78/)).

The result is not “reflection is useless.” It is that reflection is best treated as an **attribution and proposal mechanism after new evidence arrives**, not as evidence itself. A specialized counterexample, ProCo, improved reasoning by constructing a key-condition verification task rather than merely asking the model to reconsider; it reported average gains of 6.8 exact match on open-domain QA, 14.1 accuracy on arithmetic, and 9.6 accuracy on commonsense over a simple self-correct baseline ([Wu et al., EMNLP 2024](https://aclanthology.org/2024.emnlp-main.714/)). That reinforces the same principle: make verification structurally different from generation.

### 1.3 Automatic prompt optimization has repeated, peer-reviewed evidence—within a fixed objective

Several lines of work independently establish that language models can search over prompt strings:

- **OPRO:** an optimizer model receives prior solutions and their scores, proposes new solutions, and repeats. It reported best-prompt gains up to 8% on GSM8K and 50% on Big-Bench Hard over human-designed prompts; DeepMind released code ([paper](https://arxiv.org/abs/2309.03409), [official repository](https://github.com/google-deepmind/opro)).
- **Promptbreeder:** an evolutionary population mutates both task prompts and the mutation prompts themselves, outperforming named hand-designed prompt strategies on arithmetic, commonsense, and hate-speech experiments ([paper](https://arxiv.org/abs/2309.16797)). This is genuine self-referential search, but the fitness function and task domain remain externally fixed.
- **DSPy/MIPRO:** MIPRO jointly optimizes instructions and few-shot demonstrations for multi-stage programs. It beat baseline optimizers on five of seven programs with gains up to 13% using Llama-3-8B ([paper](https://arxiv.org/abs/2406.11695)). The underlying DSPy paper reported that compiled pipelines outperformed standard few-shot and expert demonstration baselines across its case studies ([DSPy](https://arxiv.org/abs/2310.03714)).
- **TextGrad:** textual feedback is propagated through a compound system to revise textual variables. The Nature-published work reported GPT-4o GPQA improvement from 51% to 55% and a 20% relative gain on LeetCode-Hard, plus domain experiments in molecules and radiotherapy ([paper](https://arxiv.org/abs/2406.07496), [official repository](https://github.com/zou-group/textgrad)). The “gradient” is a useful software abstraction, not a mathematical gradient guarantee.
- **GEPA:** accepted as an ICLR 2026 Oral, it reported an average 6% advantage over GRPO across six tasks, up to 20%, using up to 35 times fewer rollouts; it also beat MIPROv2 by more than 10% in reported comparisons ([paper](https://arxiv.org/abs/2507.19457)). Its official implementation exposes held-out validation, strict-improvement acceptance, metric-call budgets, cached evaluation, and stop callbacks ([API](https://gepa-ai.github.io/gepa/api/core/optimize/)).

What this establishes is **black-box textual optimization when there is a stable metric and a representative evaluation set**. It does not establish that the optimized prompt will remain superior after model upgrades, tool/API changes, or a shift in owner tasks. GEPA’s own documentation explicitly distinguishes a held-out validation set for generalization and notes training overfit as a common problem ([generalization API](https://gepa-ai.github.io/gepa/api/optimize_anything/optimize_anything/), [FAQ](https://gepa-ai.github.io/gepa/guides/faq/)).

### 1.4 ACE establishes structured, incremental context evolution on its evaluated domains

ACE is more relevant to an agent harness than a monolithic prompt optimizer because it separates generation, reflection, and curation, and applies small deltas to an itemized playbook. Its bullets carry identifiers and helpful/harmful counters; the model proposes entries, while lightweight deterministic logic merges them ([ACE HTML paper](https://arxiv.org/abs/2510.04618)). The ICLR 2026 paper reports +10.6% on agent benchmarks and +8.6% on finance benchmarks, matching the top AppWorld production agent overall and exceeding it on the challenge split with a smaller open model ([paper](https://arxiv.org/abs/2510.04618)). Official code is public ([repository](https://github.com/ace-agent/ace)).

This is real evidence, not merely a landing-page demo: accepted paper, ablations, benchmark results, and code. It remains evidence from the authors’ chosen AppWorld and financial tasks. **UNVERIFIED—whether ACE improves a heterogeneous coding/research harness with noisy owner corrections would be settled by a preregistered replay experiment comparing static rules, append-only lessons, ACE-style deltas, and no-memory controls on a chronological held-out corpus.**

### 1.5 Procedural memory and executable skills can transfer, but matching matters

Three independent results support procedural reuse:

- Voyager stores successful executable Minecraft programs, retrieves them for new tasks, and uses execution errors plus self-verification to refine candidates. It reported 3.3× more unique items, 2.3× longer travel, and milestones up to 15.3× faster than prior methods, including transfer to a fresh Minecraft world ([paper](https://arxiv.org/abs/2305.16291)). Its later TMLR acceptance provides peer-review evidence ([OpenReview venue record](https://openreview.net/submissions?page=233&venue=TMLR)).
- Agent Workflow Memory induces reusable routines from web-agent traces. Across Mind2Web and WebArena it reported 24.6% and 51.1% relative success improvements, with 8.9–14.0 absolute-point gains under widening train/test distribution gaps ([ICML 2025 proceedings](https://proceedings.mlr.press/v267/wang25bx.html)).
- Agentic Plan Caching extracts and adapts structured planning templates; NeurIPS 2025 reports 50.31% average cost reduction and 27.28% latency reduction while maintaining task performance ([NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2025/hash/9549f7d06700f0966d5f938f1d11022a-Abstract-Conference.html)). This is efficiency learning more than capability learning, but it validates reusable procedure artifacts.

The limiting signal is equally important. EvoMemBench’s standardized comparison of 15 memory methods reports that long-context baselines remain competitive, no memory form wins consistently, and procedural memory helps when stored experience matches task structure ([EvoMemBench](https://arxiv.org/abs/2605.18421)). Thus “more memory” and “more skills” are not monotonic improvements.

### 1.6 Agent-as-a-judge is established as evidence-gathering evaluation, not authoritative reward

The original Agent-as-a-Judge system evaluated files, code, and trajectories instead of reading only the final answer. On 365 annotated requirements across 55 DevAI tasks, it reached 92.07% gray-box and 90.44% black-box alignment with human consensus for OpenHands, compared with 70.76% and 60.38% for a single-pass LLM judge. It also cost $30.58 and 118.43 minutes versus the authors’ estimate of 86.5 human hours ([paper](https://arxiv.org/abs/2410.10934)). Its own ablation is revealing: adding active read/locate capabilities raised alignment, while retrieval slightly reduced OpenHands alignment from 90.44% to 90.16%; the authors report that erroneous historical memory could cause chains of judge errors ([paper, agent ablations](https://arxiv.org/abs/2410.10934)).

AJ-Bench provides a second benchmark signal across search, data systems, and GUI tasks: agentic judges consistently beat LLM-as-a-judge baselines, but the accepted ACL 2026 Findings paper explicitly reports substantial remaining challenges ([AJ-Bench](https://arxiv.org/abs/2604.18240)).

There are also two mechanically independent failure signals for treating model judges as ground truth:

- A 150,000-instance study across 15 judges found systematic position bias varying by judge and task ([Shi et al., 2025](https://aclanthology.org/2025.ijcnlp-long.18/)); a separate EMNLP study found misinformation, gender, authority, and beauty biases and demonstrated attacks on judges ([Chen et al., 2024](https://aclanthology.org/2024.emnlp-main.474/)).
- REFLECT’s controlled interventions into research-agent traces found even its best judges below 55% overall accuracy, especially weak at evidence verification ([REFLECT](https://arxiv.org/abs/2605.19196)).

The established pattern is: **give a judge tools to collect evidence, but anchor acceptance in deterministic checks whenever those exist and calibrate the judge against human labels for subjective residuals.**

## 2. What is promising but not yet proven

### 2.1 ACE-style playbooks for a general harness

It is **likely (55-80%)** that itemized, provenance-bearing lessons with localized updates will outperform repeated monolithic rewrites for this owner’s harness, because ACE’s generator/reflector/curator separation and deterministic delta merge specifically target context collapse and produced ablation-supported gains on AppWorld and finance ([ACE](https://arxiv.org/abs/2510.04618)). The uncertainty is domain transfer: those experiments do not represent a years-long, heterogeneous coding/research workload. **UNVERIFIED—the chronological replay experiment described in §1.4 would settle this premise.**

It is **very likely (80-90%)** that unconstrained accumulation will eventually create redundant, conflicting, or stale lessons, based on ACE’s explicit need for helpful/harmful counters and refinement ([ACE](https://arxiv.org/abs/2510.04618)) plus EvoMemBench’s finding that no memory scheme is consistently superior and relevance to task structure controls benefit ([EvoMemBench](https://arxiv.org/abs/2605.18421)).

### 2.2 GEPA for periodic harness prompt optimization

It is **likely (55-80%)** that GEPA can find locally better prompts for a narrow harness behavior with a clean scorer, because its ICLR 2026 results span six tasks, outperform GRPO and MIPROv2 in the reported comparisons, and its implementation explicitly accepts execution traces and textual side information ([paper](https://arxiv.org/abs/2507.19457), [DSPy overview](https://github.com/stanfordnlp/dspy/blob/main/docs/docs/api/optimizers/GEPA/overview.md)). **UNVERIFIED—for this harness, a frozen 100–300-case behavior suite with chronological test cases would settle the premise.**

It is **unlikely (20-45%)** that continuously running GEPA over live owner traffic without a frozen test gate would produce sustained general improvement. Evidence: GEPA’s documentation warns about training overfit and distinguishes validation/generalization mode ([FAQ](https://gepa-ai.github.io/gepa/guides/faq/), [API](https://gepa-ai.github.io/gepa/api/optimize_anything/optimize_anything/)); prompt-search literature also recognizes validation overfit ([Hyperband prompt-selection paper](https://openreview.net/pdf?id=Lm9DXFrcHD)).

Operational maturity is **likely (55-80%)** sufficient for a sandboxed experiment but not for unattended mutation of a production harness. The code is integrated into DSPy and actively released, but recent official release notes include GEPA result-shape changes and temporarily removed tool optimization, while an open issue reports a multimodal memory run halting with large memory growth ([DSPy releases](https://github.com/stanfordnlp/dspy/releases), [issue #8848](https://github.com/stanfordnlp/dspy/issues/8848)).

### 2.3 Tool-grounded agent judges as a second signal

It is **very likely (80-90%)** that an evaluator allowed to inspect files, run targeted checks, and cite its evidence will outperform a final-answer-only judge on multi-artifact tasks, because Agent-as-a-Judge’s read/locate ablations and AJ-Bench’s cross-domain comparison both favor environment interaction ([Zhuge et al.](https://arxiv.org/abs/2410.10934), [AJ-Bench](https://arxiv.org/abs/2604.18240)).

It is **very unlikely (5-20%)** that such a judge is safe as the sole promotion gate for self-generated prompt or skill changes. Independent judge-bias studies, REFLECT’s below-55% result, and Agent-as-a-Judge’s own memory-chain-error observation all contradict that use ([position bias](https://aclanthology.org/2025.ijcnlp-long.18/), [REFLECT](https://arxiv.org/abs/2605.19196), [Agent-as-a-Judge](https://arxiv.org/abs/2410.10934)).

### 2.4 Automatic skill synthesis beyond narrow environments

It is **likely (55-80%)** that extracting short, executable, verifier-backed procedures from repeated successful traces can reduce future steps or failures when the new task structurally matches the old task. AWM, Voyager, and Agentic Plan Caching are three different domains/mechanisms supporting reuse ([AWM](https://proceedings.mlr.press/v267/wang25bx.html), [Voyager](https://arxiv.org/abs/2305.16291), [APC](https://proceedings.neurips.cc/paper_files/paper/2025/hash/9549f7d06700f0966d5f938f1d11022a-Abstract-Conference.html)).

It is **roughly even (45-55%)** that fully automatic synthesis of natural-language `SKILL.md`-style artifacts from arbitrary session history would improve a general harness after accounting for retrieval errors, duplication, and maintenance. AutoSkills proposes hierarchical generation/refinement/expansion and reports AppWorld/BFCL/τ²-Bench experiments, but as of the cited record it is an ICML 2026 submission rather than accepted work ([OpenReview submission](https://openreview.net/forum?id=rJS7Z3Oaw1)). **UNVERIFIED—a shadow-mode experiment must compare candidate-skill retrieval and success on chronological holdout tasks against no skill and long-context baselines.**

### 2.5 Automatic agent architecture search

It is **unlikely (20-45%)** that open-ended agent-code search is currently a better harness investment than narrow prompt/playbook optimization. Meta Agent Search reports improvements and cross-domain transfer on benchmark tasks, but the work frames Automated Design of Agentic Systems as a newly forming area and evaluates a search archive over generated agent code ([ADAS](https://openreview.net/forum?id=Joc8ecV2im)). It expands the mutation surface, executes generated code, and creates a second optimization runtime—the precise complexity the anti-overfit gate rejects absent extraordinary evidence. **UNVERIFIED—a compute-matched, held-out comparison against a simple single-agent loop would be required before reconsideration.**

## 3. What is hype, and how to tell

### 3.1 “Recursive self-improvement” when only the prompt changed

If the base model, objective, evaluator, tools, and search algorithm are fixed while an instruction string changes, the system is doing prompt optimization. Promptbreeder is genuinely self-referential in that mutation prompts evolve, but its fitness set remains externally supplied ([Promptbreeder](https://arxiv.org/abs/2309.16797)). GEPA and ACE clearly describe prompt/context artifacts rather than weight updates ([GEPA](https://arxiv.org/abs/2507.19457), [ACE](https://arxiv.org/abs/2510.04618)). Calling this unqualified recursive self-improvement is hype because it hides the fixed outer loop and bounded search space.

**Detection test:** ask “what variable changed, who defined the score, and was the final score measured on unseen examples?” If those answers are “a prompt,” “the developer,” and “no,” the claim is optimization on a training surface, not autonomous general improvement.

### 3.2 “Reflection” with no new information

Repeatedly asking the same model to reconsider is not a learning signal. The intrinsic-self-correction evidence includes degradation ([ICLR 2024](https://openreview.net/forum?id=IkmD3fKBPQ)) and the TACL review finds success primarily when reliable feedback exists ([TACL 2024](https://aclanthology.org/2024.tacl-1.78/)). Reflexion’s successful examples are frequently described without emphasizing their evaluators, compiler/test feedback, or oracle termination, which changes the interpretation.

**Detection test:** inspect whether iteration two receives a test failure, environment state change, retrieved source, counterexample, human correction, or independent verifier output. If not, “reflection” is resampling with correlated prose.

### 3.3 “Agent-as-a-judge is as good as humans” generalized from one benchmark

The original result is impressive but specific: 55 code-development tasks and 365 requirements ([Agent-as-a-Judge](https://arxiv.org/abs/2410.10934)). AJ-Bench broadens the domains and still reports major open challenges ([AJ-Bench](https://arxiv.org/abs/2604.18240)); REFLECT finds severe weaknesses on research-agent evidence checking ([REFLECT](https://arxiv.org/abs/2605.19196)). A judge that agrees on one class distribution can fail on subtle, adversarial, or evidence-dependent defects.

**Detection test:** require per-slice precision/recall, calibration against human consensus, swapped candidate order, adversarial style controls, and controlled injected defects—not only overall agreement.

### 3.4 “Lifelong learning” inferred from accumulation

An ever-growing skill or memory store is not evidence of lifelong learning. It may accumulate stale or conflicting artifacts, and retrieval may select a mismatched routine. EvoMemBench finds no consistently superior memory and emphasizes task-structure match ([EvoMemBench](https://arxiv.org/abs/2605.18421)). ACE itself introduces counters and refinement because monolithic or indiscriminate context evolution collapses or bloats ([ACE](https://arxiv.org/abs/2510.04618)).

**Detection test:** look for chronological held-out evaluation, negative transfer, deletion/decay, contradiction resolution, retrieval precision, context/token cost, and performance after distribution shift. A rising training curve alone is insufficient.

### 3.5 Best-of-many results presented without compute matching

Evolutionary prompt and architecture systems evaluate many candidates. Their best candidate should be compared against baselines with equivalent rollout or token budgets. GEPA explicitly reports rollout efficiency against GRPO, which strengthens its claim ([GEPA](https://arxiv.org/abs/2507.19457)). Any system reporting only the best discovered result without search cost, number of candidates, or a compute-matched sampling baseline is a demo-level claim.

### 3.6 Generated code or skills accepted by the same model that authored them

This creates correlated failure and reward hacking. Judge studies document self-preference, position, style, and authority biases ([self-preference](https://aclanthology.org/2025.emnlp-main.86/), [position bias](https://aclanthology.org/2025.ijcnlp-long.18/), [judgment-bias attacks](https://aclanthology.org/2024.emnlp-main.474/)).

**Detection test:** promotion must depend first on deterministic tests/environment effects and then, only for residual subjective criteria, an independently prompted/modelled judge calibrated on gold cases. Same-model self-approval is not a verifier.

## 4. Specific, concrete things this owner’s harness should adopt

Because this unit is externally scoped, these tags classify the proposed mechanism rather than asserting what is already present locally. No proposal requires a second runtime or prohibited infrastructure.

### 4.1 Adopt the minimum viable evidence-gated lesson loop — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

**Recommendation:** implement a batch command or hook-adjacent script that turns completed runs into *candidate* lessons and promotes only replay-validated lessons. It is **very likely (80-90%)** to be safer and more useful than unconditional reflection memory, based on the external-feedback boundary in TACL/ICLR self-correction studies and the localized-delta design in ACE ([TACL](https://aclanthology.org/2024.tacl-1.78/), [ICLR](https://openreview.net/forum?id=IkmD3fKBPQ), [ACE](https://arxiv.org/abs/2510.04618)). **UNVERIFIED—its net benefit for this owner must be settled by chronological replay and shadow deployment.**

Minimum record schema:

```text
lesson_id
scope                 # tool, task family, provider, OS, repository, etc.
trigger_fingerprint   # observable condition, never a vague theme
evidence_refs         # terminal output IDs, test failures, owner correction IDs
proposed_action       # one imperative, bounded behavior change
preconditions         # when the lesson applies
counterexamples       # cases where it must not apply
created_at / last_hit
helpful_count / harmful_count
status                # candidate | shadow | active | retired
artifact_version
```

Closed-loop state machine:

1. **Observe:** accept only terminal outcome markers, deterministic test/tool output, or explicit owner correction as seed evidence.
2. **Attribute:** have a model produce one falsifiable failure hypothesis or reusable success rule, citing exact evidence IDs. No citation means no candidate.
3. **Propose:** emit one small delta. Do not rewrite the whole ruleset.
4. **Replay:** run baseline and candidate against (a) cases that exhibit the fingerprint, (b) nearby successful controls, and (c) unrelated canaries.
5. **Gate:** require a predeclared minimum improvement and zero critical regressions. Use paired outcomes, not the candidate author’s narrative.
6. **Shadow:** inject the candidate into non-authoritative evaluation or selected low-risk sessions while continuing to record baseline-counterfactual outcomes where feasible.
7. **Promote or retire:** promotion records the score, dataset hash, model/tool versions, and rollback pointer. Harmful hits or expiry retire the lesson.

Stop conditions: one proposal round per evidence cluster; a fixed token/cost budget; no mutation when validation count is below a minimum; no promotion if the only positive signal is an LLM judge.

**Anti-overfit gate:** passes. It is a thin script over existing events, hooks, skills, and tests; no daemon, vector DB, KG, trained critic, SaaS, or second orchestrator.

### 4.2 Bound Reflexion to evidence-changing retries — **CONFIG (settings/JSON only)**

**Recommendation:** permit at most one automatic reflective retry when the retry receives new machine-readable information: a nonzero exit, failing assertion, schema error, environment observation, or explicit user correction. Forbid generic “review your answer and try again” loops after an unverified subjective failure.

It is **very likely (80-90%)** that this rule preserves most useful Reflexion behavior while cutting correlated retry loops, because reliable external feedback is the consistent success condition across Reflexion, the TACL survey, and ProCo ([Reflexion](https://openreview.net/pdf?id=vAElhFcKW6), [TACL](https://aclanthology.org/2024.tacl-1.78/), [ProCo](https://aclanthology.org/2024.emnlp-main.714/)). **UNVERIFIED—a randomized replay comparing zero, one, and multiple evidence-conditioned retries would settle the optimal retry cap.**

Suggested rule text:

```text
Reflect only after new external evidence. Quote the evidence, state one falsifiable cause,
change one tactic, and retry once. If the retry returns the same terminal fingerprint, stop
and report it; do not generate a second reflection from unchanged evidence.
```

**Anti-overfit gate:** passes. This is a bounded policy on the existing execution loop.

### 4.3 Run prompt evolution offline, per narrow behavior, never continuously — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

**Recommendation:** build a small adapter that exports a versioned prompt/rule component plus a frozen behavior suite to GEPA or a simpler generate-and-test optimizer. Optimize one component at a time: for example, error attribution, clarification policy, or final-answer evidence checks. Do not optimize the entire harness prompt jointly.

It is **likely (55-80%)** to find improvements where the scorer is deterministic or calibrated, because OPRO, MIPRO, and GEPA independently show prompt-search gains ([OPRO](https://arxiv.org/abs/2309.03409), [MIPRO](https://arxiv.org/abs/2406.11695), [GEPA](https://arxiv.org/abs/2507.19457)). **UNVERIFIED—the experiment is a three-way comparison of the incumbent, a hand-edited candidate, and the optimizer winner on a chronological untouched test set with equal rollout budgets.**

Required protocol:

- training cases generate textual failure feedback;
- validation cases select candidates;
- a locked chronological test set is opened once;
- scores include task success, critical regression count, tool calls, tokens, and wall time;
- model/provider/tool versions are fixed during the run;
- prompts that win only by verbosity, refusing more tasks, or exploiting the judge are rejected;
- promotion is a human-reviewed diff with a rollback pointer.

Prefer a simple local adapter over importing DSPy into the live runtime. If GEPA is used, pin versions: its official releases document changing result shapes and tool-optimization churn ([DSPy releases](https://github.com/stanfordnlp/dspy/releases)).

**Anti-overfit gate:** passes only as an offline tool invoked by the existing harness. A persistent optimization service would fail the gate and is not recommended.

### 4.4 Add an evidence-gathering judge only for non-deterministic residuals — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

**Recommendation:** define an evaluator role that can inspect artifacts and run read-only checks, but force it to return a claim-evidence matrix rather than a scalar alone:

```text
criterion | pass/fail/unknown | evidence URI or command output | confidence | missing check
```

Evaluation priority:

1. deterministic verifier/test;
2. state inspection or source retrieval;
3. agent judge for residual semantic criteria;
4. human decision for safety-critical or low-confidence cases.

It is **very likely (80-90%)** to outperform final-answer-only judging on multi-file work, based on Agent-as-a-Judge’s tool ablations and AJ-Bench ([Agent-as-a-Judge](https://arxiv.org/abs/2410.10934), [AJ-Bench](https://arxiv.org/abs/2604.18240)). It is **unlikely (20-45%)** to be reliable enough for sole autonomous promotion, based on REFLECT and independent bias studies ([REFLECT](https://arxiv.org/abs/2605.19196), [position bias](https://aclanthology.org/2025.ijcnlp-long.18/)).

Calibration suite: known-pass, known-fail, injected subtle defect, swapped presentation order, verbosity/style perturbation, and missing-evidence case. Promotion authority remains disabled until precision on critical failures reaches a predeclared threshold.

**Anti-overfit gate:** passes. It reuses current tools and does not introduce a trained critic or guardrail framework.

It is **likely (55-80%)** that this will identify useful procedural artifacts in recurring task families, based on AWM, Voyager, and APC ([AWM](https://proceedings.mlr.press/v267/wang25bx.html), [Voyager](https://arxiv.org/abs/2305.16291), [APC](https://proceedings.neurips.cc/paper_files/paper/2025/hash/9549f7d06700f0966d5f938f1d11022a-Abstract-Conference.html)). **Recommendation:** require `valid_from`, environment/model/tool version scope, evidence IDs, last successful use, harmful count, and `superseded_by` on every adaptive lesson, prompt, or skill. A version change or repeated harmful hit moves the artifact to shadow/retired, not deletion.

It is **very likely (80-90%)** that explicit validity and rollback reduce negative transfer, because ACE’s counters/refinement exist to control evolving context and EvoMemBench shows that benefit depends on matching task structure ([ACE](https://arxiv.org/abs/2510.04618), [EvoMemBench](https://arxiv.org/abs/2605.18421)). **UNVERIFIED—the owner-specific threshold for harmful hits and expiry requires shadow-mode calibration.**

## 5. Minimum viable closed loop: reference specification

The following is the smallest loop justified by the evidence.

### Inputs

- A versioned artifact `A0` (one prompt fragment, rule bundle, or skill).
- A narrow task slice and a frozen baseline.
- A training set for diagnosis, validation set for selection, untouched chronological test set for final decision, and a small unrelated canary set.
- A scorer hierarchy: deterministic checks first; environment evidence second; calibrated judge only for residuals.
- A fixed rollout/token/time budget.

### One iteration

```text
for failure_cluster in terminal_outcomes:
    evidence = collect_external_evidence(failure_cluster)
    if evidence is unchanged or non-falsifiable: continue

    hypothesis = attribute_one_cause(evidence)
    candidate = propose_one_delta(A0, hypothesis)

    baseline = replay(A0, validation + controls + canaries)
    trial     = replay(candidate, validation + controls + canaries)

    if critical_regression(trial, baseline): reject
    elif improvement(trial, baseline) < predeclared_margin: reject
    else: shadow(candidate)

    if shadow_evidence_confirms(candidate):
        promote_with_version_and_rollback(candidate)
    else:
        retire(candidate)
```

### Required invariants

1. **No feedback, no learning.** A model’s unsupported critique cannot seed promotion.
2. **One delta, one causal claim.** This makes rollback and attribution possible.
3. **Candidate author cannot be sole judge.** Deterministic effects dominate prose judgments.
4. **Selection data is not final evidence.** Open the chronological test set once.
5. **Success includes cost and reliability.** Track tokens, tool calls, time, variance, and critical failures, not only mean task score.
6. **No live self-deployment.** Promotion is versioned, reversible, and initially human-reviewed.
7. **Memory has a lifecycle.** Every artifact can be contradicted, superseded, shadowed, or retired.

### Minimum experiment that would justify activation

Randomly select a sufficiently populated recurring failure class. Freeze model, tools, and corpus window. Compare four arms under equal budgets:

1. incumbent harness;
2. one evidence-conditioned retry only;
3. append-only lesson;
4. evidence-gated delta with replay selection.

Evaluate on later chronological cases never shown during lesson creation. Primary metric: terminal success or owner-correction avoidance. Secondary metrics: unrelated regression rate, tool calls, tokens, elapsed time, and variance across repeated runs. The delta loop graduates only if it improves the primary metric by a predeclared margin, creates no critical regression, and remains positive after cost adjustment.

It is **likely (55-80%)** that arm 4 will beat append-only memory on reliability because it combines the feedback condition established by self-correction research with ACE-style localized updates and held-out selection ([TACL](https://aclanthology.org/2024.tacl-1.78/), [ACE](https://arxiv.org/abs/2510.04618), [GEPA generalization API](https://gepa-ai.github.io/gepa/api/optimize_anything/optimize_anything/)). **UNVERIFIED—this exact four-arm owner-corpus experiment is what would settle the claim.**

## 6. What I could not determine

1. **Independent replications of ACE and GEPA on heterogeneous personal coding-agent histories:** I found accepted papers, official code, documentation, and downstream tutorials, but not enough clearly independent, preregistered replications to claim broad transfer. **UNVERIFIED—a third-party reproduction using a chronological mixed-task corpus would settle it.**
2. **Long-duration stability:** published evaluations generally cover benchmark runs, not months of evolving prompts, owner preferences, provider changes, and tool drift. **UNVERIFIED—a six-to-twelve-week shadow deployment with frozen counterfactual replay would settle whether gains persist.**
3. **Optimal promotion thresholds:** the literature supports held-out gating but does not provide universal minimum sample size, improvement margin, harmful-hit count, or TTL for this owner. **UNVERIFIED—power analysis on the owner’s task frequency and a shadow calibration phase would settle these values.**
4. **Cross-model portability of learned artifacts:** ACE argues contexts can be shared and GEPA optimizes textual components, but prompt behavior is model-dependent. I did not find sufficient evidence to state that a lesson or evolved prompt remains beneficial after a frontier-model upgrade. **UNVERIFIED—run the frozen test suite on both old and new models before migrating any adaptive artifact.**
5. **Security of automatically synthesized skills:** formal-verification work exists for constrained embodied skills, but it does not establish safety for arbitrary shell, credential, web, or repository operations. **UNVERIFIED—a capability-specific sandbox and adversarial test suite would be required.** The relevant early formal-synthesis result is VASO’s 2026 robotics workshop paper, which reports 97.2% specification compliance under temporal-logic constraints, not general software-agent safety ([VASO](https://openreview.net/forum?id=TxGsSn4nrZ)).
6. **True net cost:** GEPA reports rollout efficiency and APC reports serving savings, but API prices, caching, owner correction cost, and harness-specific task mix change the economics. **UNVERIFIED—instrument a shadow trial with actual token, tool, latency, and human-review costs.**
7. **Whether current vendor-native agent products already expose sufficient optimization hooks:** this unit deliberately avoided local/vendor configuration analysis because its assigned lens was external research. A neighboring unit should map the reference specification to native capabilities before any build decision.

## Bottom line

The frontier supports a disciplined conclusion: **self-improvement is an evaluation problem before it is a reflection problem.** ACE and GEPA are credible advances in structured context and prompt optimization; Reflexion is useful when an environment supplies new evidence; agentic judges are useful evidence collectors but unsafe reward oracles; automatic skills work best when they are executable, narrowly scoped, and externally verified. The best first build is a small, reversible, evidence-gated delta loop—not a self-rewriting autonomous runtime.
