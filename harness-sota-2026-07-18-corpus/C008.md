# C008 — Context lifecycle: long-horizon drift

**Unit:** `C008`  
**Context:** `long-horizon-drift`  
**Date:** 2026-07-19  
**Mode:** read-only against the unpacked subject; the only write is this artifact  
**Remote constraint:** this unit ran on Linux against `/local_disk0/codexwork/bundle`. The Windows live-state trees named in the brief do not exist on this node.

## Executive verdict

Yes: the available corpus contains concrete cases in which an earlier persistence constraint was followed later by an attempted stop. The clearest case is one 4,392.11 MB, 261,708-line session spanning 2026-04-04 through 2026-06-25. In it, the owner requested an autonomous Ralph loop, later asked “why did you stop?”, and the transcript distillation then recorded sixteen sampled Stop-hook continuations over 6 hours 17 minutes, followed by another “why did you stop” that night. A later instruction in the same session said “continue with all Units until done do not stop run it autonomously”; the first sampled Stop-hook continuation appeared 2 hours 9 minutes 42 seconds later. The corpus's normalized pattern count for that latter continuation is 524. Evidence: `/local_disk0/codexwork/bundle/inputs/corpus.json:12239-12254`, `:12263-12361`, `:12401-12421`, `:10377-10378`, and the session dimensions at `:29878-29883`.

This establishes **behavioral non-retention**, but not its cause. It is **likely (55-80%)** that context lifecycle contributes, because the observed session is exceptionally long, the owner explicitly warned not to trust the compaction summary in the same session (`corpus.json:12197-12203`), and the live code replaces the active root goal with any ordinary prompt of 12 or more characters (`modules.py:1318-1338`). It is not possible to raise that causal confidence further from this bundle: the distilled corpus does not retain complete assistant turns or compact-boundary events, and the actual Windows event-ledger and terminal telemetry were not packaged.

The most important mechanism finding is deterministic, not speculative: the current continuity rail stores history but re-anchors to the wrong abstraction. It has a single mutable `goal`; ordinary follow-ups overwrite it. It does not retain a distinct root objective, additive steering, and invariant constraints. A direct read-only code probe reproduced that overwrite exactly. Post-compaction re-anchoring exists, but the dedicated `PostCompact` path is a heuristic gate and therefore returns a host no-op in its default shadow mode (`modules.py:138-143`, `:389-417`, `:1362-1378`). PreCompact writes a sanitized checkpoint (`modules.py:1458-1528`), but normal lexical recall explicitly excludes `compaction-checkpoints` (`modules.py:1632-1643`), so the checkpoint is an archive/recovery artifact rather than an automatic constraint-restoration path.

The best replacement is not a new memory service. It is a small change on the existing dispatcher/event-ledger bus: a session-scoped **continuity envelope** with immutable `root_goal`, append-only `steering`, explicit/high-precision `constraints`, completion criteria, and a version/digest. Inject that envelope deterministically after compaction and at parent-turn boundaries. Keep basic-memory as durable semantic knowledge, not as the immediate control plane. This passes the anti-overfit gate: no second runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

## 3. Mechanism assessment

## 3.1 PreCompact: captures a checkpoint, not a live control envelope

The deployed Claude registration has one shared dispatcher hook for `PreCompact`, matcher `.*`, five-second timeout (`settings.json:380-390`). The shared `SanitizedCheckpointModule`:

- runs only for `PreCompact` (`modules.py:1458-1460`);
- reads the event-ledger state and current session goal (`:1462-1464`);
- reads at most 32,768 characters of `.remember/now.md` and redacts it to 4,096 (`:1464-1471`);
- captures at most ten decisions and ten unresolved failures (`:1475-1482`);
- writes a sanitized Markdown checkpoint with ledger pointer and goal (`:1488-1517`);
- retains the newest 100 (`:1518-1527`).

The legacy `precompact-basicmemory/capture.ps1` is explicitly only a compatibility wrapper and forwards to the shared dispatcher (`capture.ps1:3-15`). The older snapshot script would append a compaction breadcrumb and copy `.remember/now.md`, retaining 40 snapshots (`precompact-snapshot/snapshot.ps1:26-48`), but it is not the live registration in the packaged `settings.json`.

The bundled basic-memory recall index proves that checkpoint material has existed: it contains 621 notes total and 104 paths containing `compaction-checkpoints`; examples run from `checkpoint-20260621-213223` (`recall_index.json:3639-3642`) through `checkpoint-20260710-191240` (`:4728-4735`). This is an index snapshot, not current live inventory.

However, the shared recall module explicitly skips any note path containing `compaction-checkpoints` (`modules.py:1632-1643`), and the shared SessionStart replay reads the event ledger rather than these checkpoint files (`modules.py:973-1003`). Thus PreCompact persistence and automatic restoration are decoupled. It is **very likely (80-90%)** that the checkpoints remain valuable for forensic/manual recovery, because indexed examples exist and carry recovery material. It is **very unlikely (5-20%)** that the current automatic lexical rail restores constraints from them, because the exclusion is explicit.

Health verdict: **degrading for long-horizon constraint retention**. Capture exists and is bounded/redacted, but it captures only the current mutable goal, which may already be a follow-up, and the dedicated automatic recall path excludes the checkpoint class.

## 3.2 Event ledger: durable history, lossy selection

The shared event ledger is a real append/replay substrate:

- `LedgerModule` handles SessionStart, PostToolUse, failures/denials, instructions, tasks, Stop, and subagent lifecycle (`modules.py:933-962`).
- Tool results and mutation receipts are appended (`:1037-1077`, `:1103-1142`).
- `InstructionsLoaded` records only a digest/summary and source, not instruction content (`:1196-1216`).
- Goals are appended durably and also written into a strict per-session goal file (`ledger.py:1019-1028`).
- A session-specific goal lookup returns only that session's one stored goal (`ledger.py:1030-1043`).

Two selection defects directly affect drift:

1. Recovery calls `replay(..., limit=20)` and only then filters for decision/failure/milestone (`modules.py:973-987`). Twenty recent tool/mutation/turn events can therefore hide older durable rationale even though it remains on disk.
2. Any non-system prompt at least 12 characters long replaces the session goal (`modules.py:1318-1338`). The previous root remains as a historical goal event, but re-injection calls `ledger.goal(cwd, session_id)` and receives only the latest session-goal record (`:1345-1359`; `ledger.py:1030-1039`).

### Direct reproduction of goal overwrite

This is mechanically independent from static reading and reproduces the defect: history preserves both strings, while the authoritative active goal becomes the follow-up.

Health verdict: **breaking for root-goal semantics, healthy as an append-only event substrate**. The bus and storage need evolution, not replacement.

## 3.3 Goal reinjection: wrong cadence and disabled compact rail

The reinjection module counts only write-capable PreToolUse calls: Bash, PowerShell, Edit, Write, MultiEdit, and apply_patch (`modules.py:1279-1281`, `:1310-1316`, `:1345-1360`). Claude's deployed shared PreToolUse matcher likewise omits native Read/Grep/Glob (`settings.json:139-147`). A research-heavy session can therefore consume many model turns without advancing the anti-drift counter.

The module does implement `PostCompact` re-anchoring (`modules.py:1362-1378`), and Claude registers `PostCompact` with a three-second timeout (`settings.json:393-403`). But `postcompact_reanchor` is passed through `stage(..., TIER_HEURISTIC)`, heuristic defaults to shadow, and shadow returns success with no injection (`modules.py:138-143`, `:389-417`). Unless an unavailable live override promotes it, the packaged default does not deliver the re-anchor.

The prior E03 audit claimed 78 live PostCompact events and zero delivered re-anchors (`audit-findings/E03.md:18-24`). This unit independently verified the code path and default, but the 78/0 live count is **UNVERIFIED; the settling experiment is to count the Windows terminal and shadow logs while also reading `module-modes.json` and relevant environment overrides**.

Health verdict: **breaking at the compact boundary under packaged defaults; degrading between compactions**.

## 4. Root cause model

The smallest model consistent with the evidence is:

```text
long root prompt
  -> stored as one mutable, prefix-bounded session goal
  -> ordinary follow-up >=12 chars overwrites authoritative goal
  -> write-tool-only cadence reinjects latest follow-up, not root constraints
  -> PreCompact snapshots that already-overwritten goal
  -> PostCompact dedicated re-anchor is shadow/no-op by default
  -> recovery takes last 20 events before semantic filtering
  -> model continues with partial/latest steering
  -> Stop hook returns the missing finish condition
  -> repeated continuation can become a recursive Stop loop
```

The first four arrows are directly established by code and the isolated probe. The final behavioral pattern is established by the corpus. The exact causal link across a native compact boundary is **UNVERIFIED; the settling experiment is the compact canary in §8.1 with native event and delivered-context receipts**.

This explains why adding more semantic memory would not solve the primary defect. The system does not lack storage; it lacks correct state semantics and deterministic boundary restoration.

## 5. Design: continuity envelope on the existing bus

### 5.1 Root goal + steering + invariants — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Replace the single session-goal JSON value with a versioned continuity envelope, while retaining the existing append-only goal events for audit:

```json
{
  "schema_version": 2,
  "session_hash": "...",
  "root_goal": "bounded sanitized original objective",
  "steering": [
    {"seq": 41, "text": "continue monitoring the workers"}
  ],
  "constraints": [
    {"id": "c-...", "text": "do not stop until all receipts exist", "source_seq": 1, "status": "active"}
  ],
  "completion": ["all backlog items terminal", "verification receipts present"],
  "root_version": 1,
  "updated_seq": 41,
  "digest": "sha256:..."
}
```

Deterministic transition rules:

1. First substantial user prompt in a session becomes `root_goal`.
2. Ordinary later prompts append `steering`; they never replace root.
3. Leading `*` (already recognized as force in `modules.py:1322-1325`) or an explicit `/goal replace` command replaces root and increments `root_version`.
4. Explicit `/constraint add|retire` is authoritative. A conservative extractor may additionally capture exact sentences containing high-precision modal phrases such as “do not”, “never”, “must”, “only”, “until”, and “before”; auto-captured constraints remain source-linked and bounded.
5. TaskCompleted/owner-confirmed terminal completion closes the envelope; a later substantial prompt can then establish a new root.
6. Never summarize constraints with a model in the control path. Store exact redacted text, source sequence, status, and digest.

It is **very likely (80-90%)** this will prevent the demonstrated follow-up overwrite, because the transition is deterministic and directly removes the reproduced state mutation. The remaining uncertainty is whether conservative automatic constraint extraction captures every natural-language invariant; explicit `/constraint` plus retaining a bounded root prompt reduces that dependence.

The first implementation target is `GoalModule._on_prompt`, `EventLedger.set_goal/goal`, and session-goal serialization. Existing callers can keep `goal()` as a compatibility projection of `root_goal + latest steering`; new `continuity()` returns structured state.

### 5.2 Deterministic compact re-anchor — **CONFIG (settings/JSON only)**

After the envelope lands, promote `postcompact_reanchor` from shadow to `advise` or deterministic delivery through the existing module-mode JSON. Do not promote it first: under current semantics it can confidently re-anchor to “Continue monitoring” instead of the root objective.

Inject, in order:

1. root goal and root version;
2. active invariant constraints;
3. latest one or two steering events;
4. completion criteria;
5. ledger/checkpoint pointer and digest.

Cap the envelope by fields, not a blind prefix. Preserve the head and tail of a long root if needed, but never truncate away the constraints/output section without an explicit `TRUNCATED_FIELDS` marker.

It is **very likely (80-90%)** this will restore the correct control state after native PostCompact, because the event is already registered and the only packaged suppression is gate mode. Actual provider delivery remains **UNVERIFIED; the settling experiment is §8.1, which must correlate dispatcher output, next-turn injected context, and sentinel behavior**.

### 5.3 Semantic-first recovery replay — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Change recovery from “take last 20, then filter” to:

- read structured envelope directly;
- obtain the newest bounded decisions, open failures, and milestones by kind before applying limits;
- include a tail of operational events only after durable state;
- de-duplicate against the PostCompact envelope by `(session_hash, root_version, updated_seq, digest)`.

This is **very likely (80-90%)** to preserve durable rationale in tool-dense sessions, because filtering before limiting makes irrelevant tool traffic unable to evict all decisions. Evidence is the current reversed selection order at `modules.py:979-987`.

### 5.4 Parent-turn cadence, not write-call cadence — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Advance the re-anchor counter on a native parent-turn lifecycle event or UserPromptSubmit, not only on write-capable PreToolUse. Continue to inject through the dispatcher. Subagents should receive their delegated task envelope, not the parent root; the current `_is_subagent` isolation at `modules.py:1312-1315` should remain.

A low-noise policy is:

- full envelope on PostCompact/resume/clear;
- constraint digest plus one-line root on every owner steering prompt;
- full envelope every N parent turns, where N is measured rather than assumed;
- immediate full envelope when a constraint is added/retired or root version changes.

It is **likely (55-80%)** that this improves research/monitoring continuity without excessive prompt tax, because those workloads use many reads/searches that the present counter ignores. The exact N is **UNVERIFIED; the settling experiment is a shadow replay over raw sessions comparing injected bytes and later correction incidence for N in {4, 8, 12}**.

### 5.5 Boundary receipts and one-shot degraded advisory — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Every continuity boundary should emit a small receipt into the existing terminal/event ledger:

```json
{
  "kind": "continuity_receipt",
  "event": "PostCompact",
  "session_hash": "...",
  "root_version": 3,
  "constraint_count": 5,
  "digest": "...",
  "action": "inject",
  "elapsed_ms": 17,
  "exception_class": null
}
```

Remain fail-open, but if capture/replay fails, surface one de-duplicated `HARNESS CONTINUITY DEGRADED` advisory on the next viable event. Do not silently record only `allow`. Record a sanitized exception class, never raw secret-bearing payloads.

It is **very likely (80-90%)** that this makes future drift diagnosis materially more conclusive, because it adds the currently missing correlation keys without a new telemetry service. A receipt proves the harness produced an injection; the compact canary must still prove the host/model received and honored it.

### 5.6 Basic-memory remains the durable semantic plane — **CONFIG (settings/JSON only)**

Keep basic-memory and the memory spool, but define its role explicitly:

- event ledger/envelope: active goal, constraints, steering, failures, completion state;
- basic-memory: curated decisions, reusable rationale, project knowledge, forensic checkpoints;
- `.remember/now.md`: volatile operator scratchpad, snapshotted but not authoritative;
- raw transcript: audit source of truth for question-led historical retrieval.

Do not make immediate post-compact recovery depend on an MCP round trip. It is **very likely (80-90%)** that this split is more reliable than basic-memory-only control, because corpus write/edit errors are 4.41%/11.54% while the local ledger is synchronous and already wired.

## 6. Anti-overfit gate and alternatives rejected

### Rejected: another orchestration or durable-execution runtime

It would violate the explicit anti-overfit gate and would not fix the state-model defect. The current dispatcher already receives UserPromptSubmit, PreCompact, PostCompact, SessionStart, PreToolUse, Stop, and task lifecycle events (`registration.py:17-34`). A second runtime adds scheduling and reconciliation failure modes.

### Rejected: vector database or knowledge graph memory

The defect is not semantic retrieval recall; it is that `Continue monitoring` overwrites the authoritative root. More retrieval could return more stale goals without defining which one is authoritative. This proposal intentionally uses no vector DB/KG.

### Rejected: model-generated rolling summaries as authority

The corpus includes an owner directive not to trust the compaction summary and to read actual files (`corpus.json:12197-12203`). A model summary may be useful orientation but cannot be the state transition record. Exact constraint text plus versioned status is smaller and mechanically auditable.

### Rejected: more Stop-hook recursion

The corpus's dense 524-pattern sequence shows that stop blocking can keep a process moving while still producing pathological repetition. Stop should enforce a terminal predicate once, then direct the next action from the envelope. It should de-duplicate repeated feedback by `(constraint_digest, completion_state)` and escalate a stalled loop rather than replay the same message hundreds of times.

### Considered: no change, relying on stronger models

This is not adequate. The overwrite is deterministic code outside the model: the stronger model is given the wrong “authoritative” goal after a normal follow-up. Minimal harness code is justified precisely because it removes lossy scaffolding rather than adding reasoning machinery.

## 7. Implementation order and acceptance criteria

1. **Envelope schema and compatibility projection — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add schema-v2 session state, migration from the existing string goal, root/steering transitions, and exact constraint storage. Acceptance: an ordinary follow-up does not change `root_version` or remove constraints; explicit replace does.
2. **Semantic-first replay — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Select envelope/state before bounded event tails. Acceptance: 100 later tool events cannot evict root, active constraints, or open failures from recovery.
3. **Promote PostCompact — CONFIG (settings/JSON only).** Enable only after steps 1-2. Acceptance: exactly one continuity envelope per compact boundary, de-duplicated if SessionStart(source=compact) also fires.
4. **Parent-turn cadence — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Acceptance: a read/search-only synthetic session reaches the configured cadence; subagents remain isolated.

## 10. Final decision

Evolve the shared harness, do not replace it. Replace its **single mutable goal abstraction** with a **versioned continuity envelope** and make compact-boundary delivery deterministic. Keep the event ledger as the active state plane, basic-memory as durable semantic knowledge, `.remember` as volatile scratch, and raw transcripts as audit evidence. Add receipts and a raw-session evaluator, not a daemon.

This is ambitious where the evidence supports ambition: it changes the authoritative context model rather than patching individual reminder text. It is minimal where overfitting would be costly: the entire design rides existing native lifecycle events, dispatcher modules, JSON/JSONL state, and current hook injection.
