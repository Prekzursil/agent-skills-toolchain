# G001 — Failure-mode inventory and ranked structural taxonomy

## Scope, method, and evidence status

This unit inventories failures measured in the supplied transcript corpus, the four live-operated defect classes, and claims in the 136 supplied mega-audit reports. It does **not** treat audit prose as established fact merely because it is detailed. I use three evidence grades:

1. **C — corpus-confirmed occurrence.** Counts are exact within 11,633 parsed files; the corpus reports zero failed files, one bad line, and 32 oversized lines, and warns that samples are capped at 12 (`/local_disk0/codexwork/bundle/inputs/corpus.json:2-11`). The error corpus therefore measures occurrence well but often cannot identify root cause.
2. **L — live-confirmed defect.** `INPUT-known-harness-defects.md` says each of its four defects fired in real operation and was diagnosed with two independent signals (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:1-5`).
3. **A — audit claim.** The supplied audit reports contain static inspection, bounded probes, and sometimes live-state checks, but the program brief explicitly calls them claims rather than facts. Each audit-derived entry below therefore remains **UNVERIFIED in this unit** unless independently corroborated by C or L evidence; the settling experiment is named inline.

Input completeness was itself controlled. `rg --files .../audit-findings | wc -l` and an independent `find ... -type f -name '*.md' | wc -l` both returned 136. Known-present controls found `corpus.json` (1,381,873 bytes), the defects file (10,984 bytes), and expected audit files A01/F11. Thus four of the brief's claimed 140 audit outputs are unavailable. I make no claims about those four. The available set is exactly A01–A40, B01–B20, C01–C20, D01–D30, E01–E15, and F01–F11.

The corpus `hooks` object is **NO DATA**, not zero use: it explicitly says its detector failed a known-positive control (`/local_disk0/codexwork/bundle/inputs/corpus.json:13260-13264`). The independent live defect report observed hooks firing while the miner found no hook fields (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:133-146`). No hook-frequency conclusion below uses the broken corpus field.

### Expected-damage ordering

Ranking is impact × exposure × invisibility × persistence, not raw frequency. A silent, durable false proof can corrupt many downstream choices and therefore outranks a loud shell parse error. Exact monetary or task-loss estimates are unavailable. Relative ordering is **likely (55-80%)**, based on confirmed secret persistence and false-success mechanisms at the top, confirmed high-frequency tool interruption in the middle, and loud/recoverable parse errors at the bottom; a prospective incident ledger recording task loss, recovery minutes, and downstream decisions would settle the ordering quantitatively.

## Ranked taxonomy

### 1. Silent false success, forged proof, and skipped verification

**Expected damage: catastrophic. Evidence: L + A, with individual audit claims UNVERIFIED.**

**Mechanism.** Success is inferred from a transport property (exit 0, HTTP 200, an `ok` alias, a file existing, a terminal marker) before contradictory application failure is examined. Other paths convert crashes, timeouts, quarantine, unsupported files, or audit inability into an empty/green result. Receipts are then too broad, stale, self-minted, or not bound to the claimed workspace state, so one green event can substantiate several unrelated conclusions.

**Observed instances.** The live defects show the reverse polarity as well: `tool-sentinel` matched `timedout` in a JSON field name whose value was false, despite `ok:true`, and told the agent to discard a successful result; a prior version classified every WebFetch 200 as failed (`INPUT-known-harness-defects.md:63-76`). The audit reports: exit 0 dominates explicit error in the deployed sentinel (`F08.md:7-13`); the shared adapter drops sibling error fields and creates a contradictory verified/pass/failure envelope (`F08.md:15-21`); a weekly router benchmark returns green when it cannot parse its evaluator (`F08.md:23-29`); all 24 staged gates default to shadow and suppressed same-day fires were counted (`F08.md:31-37`); module crashes/quarantine remain allow/success (`F08.md:39-45`); the consolidated dispatcher discards child block exits/crashes/timeouts (`F08.md:47-53`); `--fail-on-drift` exits 0 on `status=blocked` (`F08.md:63-69`); per-edit validation collapses unsupported, missing, oversized, checker-crashed, and clean into exit 0 (`F08.md:71-77`); the memory regression suite reports 13/16 but returns 0 (`F08.md:79-85`). A10 adds one receipt substantiating multiple claims and inert gates (`A10.md:7-94`); A11 adds spoofable/stale receipts and unrecorded native failures (`A11.md:8-80`); A16 shows production composition and hollow terminal markers can fail green (`A16.md:15-79`); C02/C03 show saved workflows declaring FINAL/PASS without receipts or reviewers (`C02.md:31-79`; `C03.md:7-47`); C11/C20 show compound or independent claims cleared by one receipt and file existence used as completion (`C11.md:10-82`; `C20.md:71-79`); D30 says the claimant can mint its own receipt and freshness is not workspace-bound (`D30.md:7-55`). These audit instances are **UNVERIFIED in this unit**; run the cited pure-function canaries plus twelve golden lifecycle traces with contradictory envelopes, missing verifiers, changed workspace state, crash, timeout, and quarantine to settle them.

**Preconditions.** Multiple untyped result envelopes; fail-last parsing; exit-code-only callers; receipts without claim/workspace/actor identity; shadow as default without a health surface; wrappers that always return zero; gates keyed to file existence or unvalidated terminal strings.

**Detection signal.** A record containing both success and failure fields; green scheduler status with missing/invalid evaluator output; `verified=true` and `failure=true`; a completion claim with no task-scoped fresh receipt; unsupported/checker-error lanes rendered identically to clean; any gate fire present only in shadow telemetry.

**Structural fix — UNVERIFIED — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Implement one fail-dominant typed verdict normalizer on the existing dispatcher: explicit error/timeout/cancel/skipped/degraded outranks transport success; unknown is never pass. Mint receipts only after a separately identified verifier binds exact claim ID, actor, command, changed-tree digest, exit/output classification, and freshness. Require all claimed invariants to have separate coverage or an explicit compound verifier. Preserve measurement-only mode but make CI/enforcement callers select an enforcing profile explicitly. This rides the ledger/receipt/hook bus and adds no critic or runtime. It is **very likely (80-90%)** to eliminate the demonstrated contradictory-envelope and swallowed-exit classes because the proposed branch ordering directly covers every cited canary; the golden-trace experiment above determines the residual effect.

**Detection signal.** Equality-only hit of a current secret in any durable non-secret store; sandbox identity can read an auth file; synthetic honeytoken exits through shell/web/MCP; package registration lacks immutable digest; fetched/subagent content lacks provenance/taint; keyring configuration rejected or ignored by strict validation.

**Structural fix — UNVERIFIED — CONFIG (settings/JSON only).** First rotate confirmed-exposed credentials outside this unit, then enable native keyrings/history limits, native sandbox/approval modes, least-privilege MCP environment maps, and deny-by-default egress for code-changing/untrusted-repository runs. **Structural fix — UNVERIFIED — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add a shared provenance/taint classifier at ingress and a synthetic-honeytoken egress regression suite; never scan or log real secret bytes. It is **likely (55-80%)** to catch remaining bypasses because F02/F04 enumerate current source/sink omissions, but semantic prompt injection cannot be completely detected; the honeytoken matrix settles actual channel coverage.

**Detection signal.** Mutation target differs from delegated workspace; dirty worktree scheduled for deletion; destructive capability invoked without approval receipt; deployment writes begin without lock/CAS/backup manifest; cleanup sees unowned changes; alternate history-rewrite verbs evade the canonical canary.

### 6. Guard semantic confusion: use-versus-mention, false alarms, and detector epistemics

**Expected damage: high. Evidence: L.**

**Mechanism.** Guards pattern-match untyped payload text without knowing whether a token is an executable verb, source code, prose mention, negation, JSON field name, or false-valued field. Agents then trust a single detector without a known-positive control, turning detector failure into confident subsystem claims.

**Observed instances.** Four implementations share the defect: destructive-command guard flagged Markdown written by `Set-Content`; stub-ledger flagged “stub,” “test double,” “placeholder,” and a negated “extension point”; marker scanner flagged discussion of markers; tool-sentinel flagged `user_cancelled_or_timedout:false` (`INPUT-known-harness-defects.md:9-22`, `:52-76`). Six single-probe conclusions were wrong in one session; a seventh detector said skills=0/agents=0/hooks=0, while known-positive controls found skills and agents and isolated only hooks as broken (`INPUT-known-harness-defects.md:111-129`).

**Preconditions.** Raw substring/regex scanning; no AST/fence/path/field/value context; no known-positive detector test; detector verdict rendered as fact; per-hook reimplementations.

**Detection signal.** Match occurs only in Markdown prose/blockquote/table, a negation, a JSON key with benign value, or a write body whose tool verb is safe; detector misses a known-present skill/agent/hook; repeated rewording moves rather than removes the alert.

**Structural fix — UNVERIFIED — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** One shared `classify_occurrence(tool, verb, target, media_type, syntax_region, field_path, typed_value)` discriminator; command guards inspect operation and resolved target, prose scanners restrict executable claims to code regions/source files, structured output uses parsed keys and values. ### 10. Dead, stale, unavailable, or misrouted tools and MCPs

### 11. Shell quoting, language-boundary, path, and command construction errors

**Expected damage: medium to low per event, high aggregate waste. Evidence: C + L.**

**Mechanism.** Agents embed one shell language inside another, interpolate large/quoted content into inline commands, confuse PowerShell and Bash escape rules, depend on current working directory/casing, or use a detector (`which`) that cannot see Windows `.cmd` shims.

**Observed instances.** Bash produced 6,461/108,121 errors; its dominant fingerprint is 1,631 unmatched single-quote EOF plus 128 unmatched double-quote EOF, 49 PowerShell empty-pipe parser errors, and path-not-found cases (`corpus.json:8840-8869`; fingerprints `corpus.json:4281-4297`, `corpus.json:4533-4549`). PowerShell produced 2,031/19,181 errors (10.6%), though its capped top fingerprints do not identify most mechanisms (`corpus.json:8871-8900`). Read recorded 229 missing files from the home CWD, 162/115 from differently cased Reframe paths, and 84 from the GitHub parent (`corpus.json:8902-8931`). The live D2 incident confirms Git Bash `which` missed a `.cmd` shim and a PowerShell regex with `\c` invalidated a liveness conclusion (`INPUT-known-harness-defects.md:111-118`). The corpus cannot distinguish heredoc, inline, and nested-shell shares from normalized fingerprints; any stronger attribution is a gap.

**Preconditions.** Long inline `-c`/`-Command`; dynamic text interpolation; shell nesting; implicit CWD; Windows shim lookup via POSIX `which`; cross-shell copy/paste.

**Detection signal.** unmatched-quote EOF; empty pipe after variable loss; command contains nested shell and dynamic payload; relative path with unexpected CWD; `which` negative while PowerShell `Get-Command` positive.

**Structural fix — UNVERIFIED — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add a command-construction helper that passes code/data separately (argv, stdin, or temporary script), labels the target shell, rejects nested interpolation of multiline payload, and requires absolute paths at client boundaries. On Windows, executable discovery uses `Get-Command`. It is **likely (55-80%)** to remove most of the 1,759 quoted-EOF errors because balanced script files/stdin avoid the observed inline parser boundary; classify and replay 100 raw samples to settle effect.

### 12. File-read/write protocol, concurrency, and oversized-input failures

**Expected damage: medium to low. Evidence: C.**

**Mechanism.** Write/Edit require a fresh read token, but agents skip the read or race user/linter/peer modification. Reads exceed token/256-KB limits. Edits use non-unique anchors, stale strings, wrong shared/worktree paths, or no-op replacements.

**Observed instances.** Edit failed 919/28,964: 568 unread, 125 modified-since-read, 14 ambiguous match, eight no-op, and six stale-string cases (`corpus.json:8933-8962`). Write failed 439/12,845: 366 unread, seven modified-since-read, nine wrong shared-checkout target from isolated worktrees, and two `mkdir D:\` permission errors (`corpus.json:9057-9086`). The global unread fingerprint count is 939 (`corpus.json:4299-4315`). Read failed 1,912/61,165, including 384 token-limit and at least 119 generic 256-KB-limit cases plus specific oversized variants (`corpus.json:8902-8931`; precise oversized-read fingerprints also occur at `corpus.json:4461-4477`).

**Preconditions.** No automatic pre-read; read capability scoped to agent; concurrent formatter/user/peer; whole-file read request; weak edit anchor; worktree mapping not propagated.

**Detection signal.** unread/stale-read token; mtime/hash changes between read and write; edit match count ≠1; file size/token estimate above limit; target path outside assigned worktree.

**Structural fix — UNVERIFIED — NATIVE (Claude Code already does this; we just enable it).** Preserve native optimistic-concurrency/read-before-write protection; do not bypass it with shell writes. Add prompt-visible recovery: on unread read exact range, on stale re-read/rebase, on oversized search then bounded ranges, on worktree error remap target. It is **very likely (80-90%)** to eliminate the 934 Edit+Write unread top-failure instances if wrappers perform the required read, directly supported by the error contract; replay verifies no lost-update regression.

### 13. Retry loops, non-termination, stale liveness, and premature completion

**Expected damage: medium. Evidence: C + A.**

**Mechanism.** Failures are retried without a fingerprinted state machine; exact-repeat detectors fire late, are shadowed, or mix sibling state. Conversely file existence/early partial output is treated as completion. Liveness uses mtime/silence rather than process/task terminal state, hides old sessions, and may kill the wrong population.

**Observed instances.** Corpus detects consecutive same-tool runs: Read 53, Bash 14, TaskOutput 6, deep-research check 3, ToolSearch 2, and one each for PowerShell/StructuredOutput/probes (`corpus.json:10297-10369`). It counts runs, not whether each was erroneous, so calling all loops failures would be unsupported. C12 reports five retained runs over 70 calls without terminal state and file-existence poisoning (`C12.md:6-63`). A38–A40/C19 claim terminal results misclassified stalled, false-positive/negative watchdogs, global kill targeting, status from recency, late-session invisibility, non-persistent watches, and quiet failures aging to invisible (`A38.md:10-82`; `A39.md:8-72`; `A40.md:10-91`; `C19.md:7-71`). E10 says the active detector fires on the third repeated result and sibling state can mix (`E10.md:8-72`). Audit claims are **UNVERIFIED**; settle by deterministic tasks that succeed, fail, hang, go quiet, emit an early file, restart, and run as siblings.

**Preconditions.** No fingerprinted retry state; unlimited loops; failure events bypass observer; mtime conflated with lifecycle; partial artifact used as terminal; registry follows newest writer only.

**Detection signal.** same failure fingerprint twice without changed diagnostic; retry without pivot; iteration count lacks cap; process alive but progress state unchanged; terminal receipt absent; artifact exists before finalized receipt; monitor status disagrees with native task/process state.

**Structural fix — UNVERIFIED — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** One deterministic retry → diagnostic pivot → human escalation state machine keyed by session/worker/tool/fingerprint, with bounded attempts and native failure events. Completion requires terminal receipt, never file existence. Monitor activity, progress, process health, and lifecycle as separate fields. It is **likely (55-80%)** to reduce repeated failure and false completion; the deterministic task matrix settles both false-positive and false-negative rates.

## Cross-cutting detection contract

All structural fixes share five invariants:

1. **Typed state, fail-dominant classification.** `failed`, `blocked`, `skipped`, `degraded`, and `unknown` cannot be rendered as pass.
2. **Identity and provenance.** Session, parent, worker, work unit, claim, verifier, workspace digest, and artifact reference survive every fan-out/fan-in boundary.
3. **Known-positive controls and independent corroboration.** Before an absence/broken claim, the detector finds a known-present peer and a mechanically independent signal agrees.
4. **Bounded operation.** Every retry, loop, barrier, hook, child, and process cohort has a finite budget and a typed terminal outcome.
5. **One existing bus.** Hooks, skills, MCP health, native profiles, ledger, receipts, and CI are extended or consolidated. No second orchestration runtime, vector DB/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed.

## Gaps and non-conclusions

- Four expected audit reports were not supplied. Their absence is supported by two independent enumerations after known-present controls, but their IDs/titles cannot be inferred.
- Raw 10.62-GB transcripts are not in the Linux bundle. The corpus `seen_in` samples name source JSONL files, but their decisive command payloads cannot be read here. Shell construct shares, precise retry causality, and per-task recovery cost remain unknown.
- PowerShell's 2,031 errors are real, but capped fingerprints expose only a small fraction of mechanisms; no honest complete PowerShell root-cause distribution is possible from this bundle.
- Audit claims are not promoted to facts. Each category names the experiment needed. A later verification wave should prioritize §§1–5 because they combine silent corruption, persistence, and wide authority.
- Capability-use counts prove invocation, not utility or non-utility. The broken hook detector proves nothing about hook frequency.
- Error count is not damage count. User rejection may be correct safety behavior, retries may be intentional polling, and network failure may be an external environment defect. The taxonomy classifies mechanisms and preconditions rather than blaming every nonzero result on the harness.
