# AS01 — coherence sweep: hook-vs-hook

Date: 2026-07-19  
Subject snapshot: `/local_disk0/codexwork/bundle/claude` (read-only)  
Unit boundary: hooks physically under `~/.claude/hooks`, their active registrations in `~/.claude/settings.json`, the local `_dispatch` expansion, and the shared harness hook only where it co-fires with those local hooks. I did not audit neighboring skills, MCPs, rules, or plugin implementations.

## Executive result

The configured order is visible, but it is **not an execution order**. `settings.json` lists matching hook groups in array order; current Claude Code runs all matching hook handlers in parallel and merges their results after they finish. A denial therefore cannot suppress a sibling's side effect, and two mutation outputs race. This is documented by Anthropic in [Automate workflows with hooks](https://code.claude.com/docs/en/hooks-guide): all matching hooks run in parallel; one denial does not stop siblings; multiple `updatedInput` results are last-finish-wins and therefore nondeterministic. The local `_dispatch` adds a second parallel layer: it starts one thread per selected check (`_dispatch/dispatch.py:256-265`) and joins/collects output in manifest order (`:267-283`). Consequently:

1. **Critical collision — Stop can record false completion.** `bg-registry/done_marker` writes `done` at the first Stop while either shared `claim_warning` or local `journey-coverage` can prevent that Stop. The done marker explicitly equates a synchronous task with "turn ended" (`bg-registry/done_marker.py:4-17,52-59,64-77`), but sibling decisions do not prevent its write.
2. **High collision — `_dispatch` masks journey-coverage block mode.** `journey-coverage` returns `2` in block mode (`journey-coverage/check.py:225-245`), but `_dispatch` calls `main()` and discards its return (`_dispatch/dispatch.py:167-179`); the outer dispatcher always exits 0 and advertises itself as inject-only (`:41-45,286-320`). The configured guard can therefore say "block" internally and still let Stop complete.
3. **High collision — SessionStart gives mutually stale memory-spool advice.** `memory-spool/replay --spawn` launches replay from the same snapshot of spool files (`memory-spool/replay.py:136-177`) while `flush_check sessionstart` concurrently marks those files reported and says they were lost and should be re-attempted (`memory-spool/flush_check.py:91-130`). Replay may save and delete an entry after the warning was constructed.
4. **High collision — successful PostToolUse evidence can be contradicted by tool-result-sentinel.** The shared event ledger processes every successful `PostToolUse` (`agents/harness/modules.py:944-949`), while the local sentinel independently classifies the same raw result by structure and MCP failure-text (`tool-result-sentinel/sentinel.py:218-278`). The live defect record reports a successful `ok:true` Databricks result mislabeled failed and a prior history of every WebFetch 200 being mislabeled (`inputs/INPUT-known-harness-defects.md:63-76`). This is two mechanically independent signals: executable classifier structure plus observed production incidents.
5. **Medium conditional collision — credential blocking is duplicated behind one toggle.** On Bash, PowerShell, Edit, and MultiEdit, the shared `SecretGuardModule` and local `deny-credential-reads` can both deny when `HARNESS_CREDENTIAL_GUARD=1`. They do not implement the same predicate: the local hook checks target paths/read verbs (`deny-credential-reads/deny.py:19-55,86-101`); the shared hook searches flattened input, including Edit payload text (`agents/harness/modules.py:735-798`). The production defect record confirms payload mention/use confusion (`INPUT-known-harness-defects.md:9-50`). Default-off prevents this collision in the default environment, but enabling the advertised control enables both.
6. **Medium conditional collision — RE autolaunch can spawn a backend for a call that stale-anchor denies.** Both match IDA/Ghidra/Binary Ninja calls (`settings.json:196-215`). Autolaunch is intentionally side-effecting (`re-autolaunch/autolaunch.py:14-33`), while stale-anchor can exit 2 (`tms/stale_anchor.py:258-310`). Parallel hook semantics mean denial does not cancel the launch.
7. **Safe intentional overlaps exist.** The Bash no-pager rewriter is the only active Bash `updatedInput` writer; its `allow` cannot override a sibling deny because deny has higher merge precedence. The test-tamper, no-force-push, Ulysses, file-scope, and credential hooks enforce different predicates. The PostToolUse ledger, per-edit validation, and stub record are respectively evidence, validation, and durable placeholder tracking. These overlaps are safe subject to the defects above.

The collision count is not derived from the corpus `hooks` section, because the brief marks that detector broken. The corpus itself says absence is trustworthy only under its stated parse conditions (`inputs/corpus.json` `_meta`), and the known-defects input independently states hook telemetry is currently unmeasurable (`INPUT-known-harness-defects.md:133-147`).

## Collision findings and resolutions

### C1 — Stop writes “done” before the stop decision is known (critical)

**Evidence.** Settings launches shared and local Stop handlers together (`settings.json:484-504`). Native semantics run them in parallel. Inside local dispatch, done-marker is the first manifest check (`manifest.json:76-84`), but all checks are threaded concurrently. Done-marker appends `done` for a synchronous running record because the “turn has ended” (`bg-registry/done_marker.py:4-17,41-77`). Shared ClaimWarning can block Stop when `HARNESS_CLAIM_GATE=block` (`agents/harness/modules.py:2054-2067,2111-2137`). Journey coverage can also request a block (`journey-coverage/check.py:204-245`). A sibling block does not roll back the append.

**Effect.** Registry state can say a synchronous subagent completed even though the host continued the same turn. A later SessionStart reconcile then trusts a false terminal state. This is **almost certain (90-99%)** whenever a synchronous running record and an effective Stop block coincide, because the append is unconditional on the merged host decision and native docs explicitly say siblings still execute. The remaining uncertainty is filesystem failure or an opt-out.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Move synchronous completion marking from Stop to the native `TaskCompleted`/`SubagentStop` event, and reserve Stop for inject-only/read-only checks. Keep artifact-based reconciliation at SessionStart as a fallback. This is **very likely (80-90%)** to remove the false terminal transition because those events represent the completed object directly; evidence is the already registered native events (`settings.json:419-469`) and the record IDs already stored by `register.py:67-107`. **UNVERIFIED:** whether every legacy synchronous `Task` payload produces `TaskCompleted` with a correlatable `tool_use_id`; settle by capturing one TaskCreated/TaskCompleted payload pair and comparing it to the registry ID before migration. Until that experiment passes, retain artifact reconciliation and do not delete the Stop path outright—gate it behind a correlation marker.

Anti-overfit gate: this changes event placement on the existing native hook bus; it adds no runtime, database, critic, SaaS, or durable-execution engine.

### C2 — local dispatcher masks journey-coverage block mode (high)

**Evidence.** Journey coverage returns integer 2 on missing journeys in block mode (`journey-coverage/check.py:225-245`). The dispatcher imports the module and calls `main()` but ignores its return (`_dispatch/dispatch.py:167-179`). `_worker` catches `BaseException` (`:182-189`), the dispatcher only extracts JSON `additionalContext` from stdout (`:192-212`), and the outer command always returns 0 (`:286-320`). Its own contract says consolidated checks are inject-only and none returns exit 2 (`:41-45`), contradicted by the currently listed journey script. The independent wiring test states mutation/enforcement handlers must remain standalone until explicit merge semantics exist (`test_wiring.py:128-163`).

**Effect.** `JOURNEY_COVERAGE_MODE=block` is functionally converted to silence: the script writes its reason to real stderr and returns 2, but no host-level blocking decision is produced. This is **almost certain (90-99%)** from the call path; the only uncertainty is whether block mode is enabled on the Windows host.

**Resolution — CONFIG (settings/JSON only).** Register `journey-coverage/check.py` as its own Stop command and remove it from `_dispatch` whenever block mode is supported. This preserves its existing `__main__ -> sys.exit(main())` path (`journey-coverage/check.py:250-251`) with no new component. It is **almost certain (90-99%)** to restore native exit-2 handling because the official hook contract consumes a standalone command's exit code and the same standalone pattern is already used for enforcement hooks. If only advisory behavior is desired, delete block mode and keep it consolidated; do not advertise both contracts.

Anti-overfit gate: pure registration change on the existing hook bus.

### C3 — spool replay races the unflushed warning (high)

**Evidence.** SessionStart selects replay with `--spawn` immediately before flush-check in the manifest (`manifest.json:19-40`), but the dispatcher starts every selected module concurrently (`dispatch.py:256-265`). Replay snapshots spool entries, spawns detached work, then later saves/deletes idempotent writes (`memory-spool/replay.py:136-177`). Flush-check independently snapshots those entries, marks them reported, and emits “were lost mid-write—re-attempt” (`memory-spool/flush_check.py:91-130`). Manifest order only determines concatenation order after completion, not the side-effect sequence.

**Effect.** A warning can instruct a duplicate re-attempt for an entry that replay is simultaneously persisting; after the warning, the file may disappear. The race is **very likely (80-90%)** when a pending idempotent `write_note` exists at SessionStart, because detached replay necessarily outlives its quick launcher while flush-check runs immediately. Exact frequency is **UNVERIFIED**; settle with a test spool plus a fake slow successful basic-memory CLI, invoke the SessionStart dispatcher 100 times, and compare warning text, replay count, and final spool/vault state.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Replace the two SessionStart entries with one `memory-spool/recover.py` check that (1) synchronously attempts safe idempotent `write_note` replay under a spool lock, (2) refreshes the directory, and (3) reports only entries still present; keep non-idempotent `edit_note` report-only. It is **very likely (80-90%)** to eliminate contradictory advice because the decision is made from one post-replay snapshot. Keep the PostToolUse flush-check separate.

Anti-overfit gate: one small local hook on the current dispatcher; no new memory system or durable runtime.

### C4 — sentinel can contradict successful-result evidence (high)

**Evidence.** Shared Ledger sees every successful PostToolUse and records tool result/mutation evidence (`agents/harness/modules.py:944-960,1036-1168`). Local sentinel sees the same raw payload on every PostToolUse (`manifest.json:160-169`) and treats MCP failure-looking text as FAILED after checking only negative structural flags; `success:true`/`ok:true` is not an explicit terminal success in `_structural_failed` (`tool-result-sentinel/sentinel.py:218-278`). The observed defect says a response with `"user_cancelled_or_timedout": false` and `ok:true` was labeled failed, and cites an earlier every-WebFetch-200 regression (`INPUT-known-harness-defects.md:63-76`).

**Effect.** One hook records/usefully exposes successful evidence while another tells the agent not to build on it. Both additional contexts survive because cross-process outputs have no common arbiter. This is a confirmed collision class from live evidence; whether the exact current source still reproduces that exact Databricks shape is **UNVERIFIED**. Settle with the recorded payload as a fixture passed to both `LedgerModule` and `sentinel.classify`, asserting a single shared verdict.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Extract one structural result classifier used by both shared Ledger receipt creation and sentinel. Give explicit, correctly typed success fields (`ok is True`, `success is True`, HTTP 2xx, exit code 0) precedence over failure substrings in keys or values; apply text heuristics only when structure is absent/ambiguous. Include all nine recorded mention-vs-use false positives from `INPUT-known-harness-defects.md:9-91` as regression fixtures. It is **very likely (80-90%)** to prevent contradictory verdicts because both consumers will receive one classification; evidence is the common raw PostToolUse envelope and the small existing Python implementations.

Anti-overfit gate: shared library on the existing hook bus, explicitly not a trained critic or guardrail framework.

### C5 — two credential gates share a toggle but not semantics (medium, conditional)

**Evidence.** Shared SecretGuard runs on PreToolUse and can return a credential-read block (`agents/harness/modules.py:725-798`). Local deny hook matches Bash, PowerShell, Edit, MultiEdit (among others) in settings (`settings.json:239-248`) and denies based on target/read verb (`deny.py:19-63,86-101`). Both read the identical `HARNESS_CREDENTIAL_GUARD` toggle (`deny.py:73-89`; shared branch described at `modules.py:791-798`). Both default off. The live defect record shows payload prose was treated as an executable destructive command (`INPUT-known-harness-defects.md:9-50`), establishing the general discriminator failure.

**Effect.** When enabled, the two gates can both deny a real credential read (duplicate message), or the broad shared payload scan can deny while the local use/target-aware hook allows. Deny precedence makes the broader false positive win. It is **likely (55-80%)** that enabling the toggle produces materially different decisions for prose-heavy Edit inputs; evidence is the predicate difference and the observed class, but the exact current fixture has not been replayed.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Make the path/verb-aware local predicate the sole classifier and call it from the shared module; remove the second independent predicate. Preserve one shared toggle and one reason. This is **very likely (80-90%)** to eliminate hook-vs-hook disagreement because both routes reduce to one pure function. **UNVERIFIED:** the desired policy for editing a sensitive file versus reading it; settle with owner-approved fixtures for Read, Grep, Bash `cat`, Edit target, and prose mentioning `.env` before enabling enforcement.

Anti-overfit gate: a small shared predicate, no new policy framework.

### C6 — RE launch side effect survives stale-anchor denial (medium, conditional)

**Evidence.** The two hooks have overlapping MCP matchers (`settings.json:196-215`). Autolaunch probes and may spawn a detached backend before denying/retrying (`re-autolaunch/autolaunch.py:14-33,219-280`); stale-anchor may hard-block based on an OUT belief (`tms/stale_anchor.py:258-310`). Native docs explicitly state a deny does not suppress sibling side effects.

**Effect.** The expensive GUI/headless backend may launch even though the intended operation is rejected for stale evidence. The launch is idempotent and RAM-gated (`autolaunch.py:23-26`), limiting damage, so this is not a safety contradiction. It is **likely (55-80%)** when a relevant OUT anchor and a down launchable backend coincide; evidence establishes the branches but no runtime coincidence rate exists.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add a shared pure `stale_anchor_verdict(payload)` preflight and make autolaunch return silently on a hard stale verdict; keep the authoritative TMS hook as the sole denial emitter. It is **very likely (80-90%)** to prevent unwanted launches if both import the same pure verdict. Do not try to fix this by reordering `settings.json`; native execution is parallel.

Anti-overfit gate: shared pure helper on existing hooks.

### C7 — output compression races analysis and currently uses the wrong native shape (medium)

**Evidence.** Bash PostToolUse launches shared analysis, compressor, and local sentinel in parallel (`settings.json:310-354`). Each receives the original result; the compressor cannot make the other hooks analyze its replacement. It emits `updatedToolOutput` as a string (`cmd-rewrite/compress-output.py:239-298`). Current official [Hooks reference](https://code.claude.com/docs/en/hooks) says built-in Bash output replacement must match the structured `{stdout, stderr, interrupted, isImage}` shape or it is ignored.

**Effect.** The internal ledger/sentinel view and the model-visible view are designed to diverge if compression works; in the present shape the replacement is **very likely (80-90%)** ignored by current Claude Code, based on the official schema plus source. **UNVERIFIED:** installed Windows Claude Code version and whether it retains a legacy string compatibility path; settle by a >30k-character Bash output fixture plus transcript/debug inspection.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Return the complete structured Bash output with only `stdout` compressed, preserving stderr/status fields; record both raw-output digest and delivered-output digest in the ledger. It is **very likely (80-90%)** to make the mutation effective and auditable under the current documented contract. No serialization with sibling analysis is required if the ledger deliberately records raw evidence.

Anti-overfit gate: schema correction in one hook.

### C8 — shared injection mixer cannot arbitrate local sibling output (medium)

**Evidence.** The shared dispatcher deduplicates exact strings and optionally prioritizes/caps only contexts collected from its own modules (`agents/harness/dispatcher.py:255-285,314-372`). SessionStart can independently emit shared replay context, six local-dispatch contexts, and the TUI reminder (`settings.json:82-115`). Stop can independently emit shared claim context and up to six local advisory contexts. Native host merge keeps context from every hook; there is no cross-process total cap.

**Effect.** Concurrent hooks cannot logically mask a denial because native precedence handles that, but advisory volume can mask important text in the model's attention. It is **likely (55-80%)** that multi-inject SessionStart/Stop events exceed the intended shared 6,000-character cap because local contexts are excluded; evidence establishes bypass, not production length distribution. Hook telemetry is unavailable (`INPUT-known-harness-defects.md:133-147`), so frequency is **UNVERIFIED**; settle by logging per-hook output lengths and merged event length for 100 live events.

**Resolution — CONFIG (settings/JSON only).** Consolidate inject-only local checks behind one dispatcher per event (already mostly done), set explicit per-check maximum context lengths, and cap the local aggregate. Do **not** introduce a second global orchestration runtime. This is **likely (55-80%)** to control volume because it covers the proven local fan-in, but a true global cap remains **UNVERIFIED** until the host exposes a post-merge hook; the settling experiment is the live merged-length capture above.

Anti-overfit gate: existing dispatcher and JSON limits only.

## Intentional overlaps judged safe

### Bash rewriter plus guards

`inject-nopager` explicitly warns that it must be the sole Bash `updatedInput` writer (`cmd-rewrite/inject-nopager.py:26-32`) and is the only such writer found in the active user wire. It rewrites only pager-prone Git subcommands and returns `allow` with the replacement (`:183-219`). The no-force gate blocks force-push via exit 2 (`no-force-push/hook.py:35-59`), test-tamper inspects `git commit` and may warn/block (`test-tamper-guard/guard.py:213-336`), and Ulysses evaluates armed tripwires (`ulysses/enforce.py:53-74`). These predicates do not depend on the inserted `--no-pager` for the commands they protect. Native deny precedence means the rewriter's `allow` cannot override a denial. This overlap is **very likely (80-90%)** safe; evidence is one rewriter, non-overlapping rewrite targets, and native merge precedence. The residual uncertainty is an enabled plugin rewriter, covered by the `/hooks` gap above.

### Multiple PreToolUse blockers

No-force-push, test-tamper, Ulysses, TMS, file-scope, and credential deny can pairwise co-fire in the cliques above. Multiple denials may produce redundant explanations, but the strictest native result wins. Their side effects are limited except test-tamper failure-ledger writes and TMS throttle state. This is intentional defense by predicate, not contradictory permission. The exception is the RE-launch side effect in C6.

The shared SecretGuard also contains a force-push predicate (`agents/harness/modules.py:684-696`) but its lifecycle gate is default-off (`:764-783`), while the standalone no-force-push gate is active unless explicitly disabled (`no-force-push/hook.py:29-38`). If lifecycle enforcement is enabled, both may deny force-push. This conditional duplication is **likely (55-80%)** harmless but noisy: deny agrees with deny, and both are fail-open. **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** make the standalone forged gate the single force-push policy owner and remove that predicate from the shared branch after parity fixtures pass.

### Task registry plus monitor launch

For `Task`, local dispatch runs bg-registry/register and monitor-autolaunch concurrently (`manifest.json:186-225`). Register appends a task record (`bg-registry/register.py:67-108`); monitor merely launches/reminds and writes a per-session lock (`monitor-autolaunch/check.py:81-145`). Neither consumes the other's output or state, so the overlap is intentional and safe. Their only shared fact is the input Task payload.

### Post-edit evidence, validation, and stub tracking

For Edit/Write/MultiEdit, shared Ledger records mutation/evidence, per-edit-check reads the resulting file and reports syntax/lint findings (`per-edit-check/check.py:176-247`), sentinel classifies the tool result, and stub-ledger records markers from the written input (`stub-ledger/record.py:50-121`). These are distinct layers. The stub detector's prose false positives are a confirmed detector defect (`INPUT-known-harness-defects.md:9-98`), but it does not race per-edit-check or mutate the source. The overlap becomes harmful later at Stop through excess/incorrect warnings, not through contradictory tool control.
