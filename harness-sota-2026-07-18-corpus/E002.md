# E002 — Ergonomics / friction: Bash quoting failures

## Executive verdict

The brief's “1,631 unmatched-quote Bash failures” is accurate but incomplete. The number 1,631 is one exact, dominant fingerprint: a shell parser reporting `-c: ... unexpected EOF while looking for matching \`''` (`corpus.json:4281-4282`, independently repeated under Bash's top failures at `corpus.json:8840-8847`). Across the retained fingerprint table, five matching-quote EOF fingerprints sum to **at least 1,785 occurrences**: 1,636 single-quote reports, 138 double-quote reports, and 11 backtick reports (`corpus.json:4281-4295,4533-4548,5760-5771,5878-5891,7249-7254`). Thus the observed retained mix is 91.65% single quote, 7.73% double quote, and 0.62% backtick.

The corpus does **not** preserve the failed command string, interpreter path, adjacent agent reasoning, or whether the command used a heredoc. Consequently, attributing these failures to heredocs, inline commands, nested PowerShell, agent-authored bad syntax, or Claude Code's command transport would be fabrication. The decisive raw transcripts are not present in the job-node bundle. This absence was checked with two mechanically independent signals and known-positive controls in §2.

The data does support an exact ceiling. Removing the dominant 1,631 failures would remove **25.24% of all 6,461 Bash errors**, lower Bash's measured error rate from 5.98% to **4.47%**, and raise measured Bash reliability from 94.02% to **95.53%** (`corpus.json:15-20`; arithmetic reproduced in §1.4). Removing all 1,785 retained matching-quote occurrences, if all belong to Bash, would lower the rate to **4.32%**; that is a conditional upper bound, not an achieved or fully attributable result.

The best design is therefore a two-stage, existing-bus intervention:

1. Extend the already registered, sole Bash `updatedInput` pre-tool hook with a shadow-only quote classifier. It must record whether the exact command passes the target Git Bash parser when supplied as an argument vector, plus bounded structural features (heredoc, nested `bash -c`, nested PowerShell, multiline, quote kinds), without retaining command content. Proposal 1 gives the required BUILD-SMALL tag and scope.
2. Immediately remove any false “Write cannot write under `~/.claude`” instruction and tell agents to use the native Write tool for content and the native PowerShell tool for PowerShell. This direction is independently supported by the live-defects input's measured Write 0.0% versus here-string 13.6% failure comparison (`INPUT-known-harness-defects.md:100-107,151-160`) and by the native PowerShell tool already being enabled (`claude/settings.json:4-11`). Proposal 2 gives the required CONFIG tag. The fraction of the 1,631 it removes is **UNVERIFIED; the settling experiment is the shadow classifier joined to the next 200 matching-quote failures**.
3. Only after classification, promote either (a) syntax feedback for truly invalid commands or (b) encoded/file transport for commands that parse cleanly out of band but fail in the tool. Automatically “balancing” quotes is rejected because it can silently change command meaning.

This is **likely (55-80%)** to produce a material reduction in quote-error friction, because one single-quote/`-c` subtype accounts for 91.6% of the retained quote population and 25.24% of all Bash errors, while the existing harness already exposes a Bash PreToolUse boundary (`claude/settings.json:139-180`). The exact reduction is **UNVERIFIED; the experiment is a 200-event shadow baseline followed by a 200-event staged intervention with the same fingerprint detector and command-family strata**. Until that experiment, the only honest effect-size statement is the scenario table in §5, not a point estimate.

## 3. Construct characterization: measured versus open

### 3.1 Quote kind — measured

Single-quote failures dominate the retained population (1,636/1,785). The dominance is not subtle: the main direct-`-c` single-quote fingerprint alone is 11.8 times the next fingerprint and comprises 25.24% of all Bash errors. A fix that ignores single quotes cannot materially solve this measured class.

### 3.2 `-c` versus `eval` — measured output locus, not root cause

The normalized output assigns 1,641 events to a `-c` line and 144 to an `eval` line. This describes where the parser complained. It does not prove that an agent explicitly wrote `bash -c` or `eval`; the Bash tool or shell initialization can invoke those paths internally. “Agents overused nested `bash -c`” is **UNVERIFIED; the settling experiment is raw-command extraction counting explicit `bash|sh -c` tokens independently of the result text**.

### 3.3 Heredoc versus inline — not measurable from this corpus

There is no command payload or structural feature table. A matching-quote EOF can arise before a heredoc, inside a command substitution surrounding one, or in an ordinary one-line command. Quotes in a correctly opened heredoc body may also be literal, which makes guessing from delimiter type especially unsafe. “Most failures are heredocs” and “most failures are inline” are both **UNVERIFIED; the settling experiment is to classify the raw `tool_input.command` with a shell-aware tokenizer and manually adjudicate a stratified sample of 50**.

The existing Windows rule documents a different but relevant here-string failure mode: PowerShell here-string bodies are scanned as commands and the route measured 8/59 failures versus 0/40 for Write (`claude/rules/common/windows-shell.md:85-102`). That evidence supports avoiding shell-as-file-transport, but it does not identify these matching-quote events.

### 3.4 Agent behavior versus transport — the decisive unknown

Two causal classes produce the same final fingerprint:

1. **Agent-syntax defect:** the exact `tool_input.command` is already unbalanced. Replaying it by passing it as a single argument to the target shell's `-n -c` also fails.
2. **Transport defect:** the exact command parses when passed as an argument vector, but the Bash tool invocation fails because an intermediate string wrapper re-quotes it.

The intervention differs radically. Syntax defects need command shaping and fast parser feedback. Transport defects need an opaque transport (argument vector, encoded payload, or temporary script), not better prompting. The split is **UNVERIFIED; the settling experiment is the shadow classifier in §4.1**.

One measured behavior is relevant as a plausible upstream amplifier: a fabricated instruction told roughly 15 agents that Write was blocked under `~/.claude`, pushing them to PowerShell here-strings that failed 13.6% versus Write's 0.0% (`INPUT-known-harness-defects.md:151-160`; the measured route table is also at `claude/rules/common/windows-shell.md:85-102`). Whether those agents account for any of the 1,631 is **UNVERIFIED; the settling experiment is to join transcript timestamps/agent IDs for that fan-out to quote-failure tool calls**. It is **likely (55-80%)** that removing the false instruction reduces general quoting exposure, because it removes a measured high-failure shell-content route, but the quote-fingerprint-specific effect cannot be inferred without the join.

## 4. Proposed design

### 4.1 Proposal 1 — shadow quote classifier at the existing Bash boundary

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Extend the existing `cmd-rewrite/inject-nopager.py` hook rather than register a second Bash rewriter. It is already wired on Bash PreToolUse (`claude/settings.json:173-180`) and explicitly states that it must remain the sole `updatedInput` writer because matching hooks run in parallel and last-writer behavior can be nondeterministic (`claude/hooks/cmd-rewrite/inject-nopager.py:26-38`). Its current command input is `tool_input.command` (`inject-nopager.py:40-49,183-213`), exactly the field needed.

Shadow record per Bash command:

* keyed command hash and session/tool ID, never raw command text;
* target-shell `bash -n -c <command>` result, invoked with an argument vector and `shell=False` so the classifier does not reproduce string-wrapper quoting;
* interpreter path/version obtained once per session;
* bounded booleans/counts: newline, heredoc operator and quoted/unquoted delimiter, explicit `bash|sh -c`, explicit `eval`, `powershell|pwsh -Command`, command substitution, backticks, single/double quote count, command length bucket;
* subsequent PostToolUse structural status and normalized failure fingerprint;
* classifier disagreement: preflight pass + real quote EOF versus preflight quote EOF + real quote EOF.

Do not deny or rewrite during shadow. Validate with known positives: a balanced command, an intentionally unmatched single quote, an intentionally unmatched double quote, a backtick case, a quoted heredoc, and an unquoted heredoc. Run under the exact Git Bash executable used by Claude Code on Windows, not Linux bash; the existing rules explicitly warn that Git Bash and real Linux/WSL bash can disagree (`claude/rules/common/windows-shell.md:33-43`).

This classifier is **very likely (80-90%)** to separate agent-syntax from transport failures for ordinary Bash grammar because it compares the same command under a no-string-interpolation argv path and the actual tool path. Evidence: the existing hook sees the raw command field and can execute Python logic at PreToolUse (`inject-nopager.py:40-49,183-213`). It may misclassify environment-dependent parser startup behavior, aliases, or shell-mode differences; logging the exact interpreter/version and validating known controls bounds that risk. The remaining effectiveness claim is **UNVERIFIED; the settling experiment is 200 observed matching-quote failures or 30 days, whichever comes first, with manual review of every disagreement**.

Anti-overfit gate: **passes**. This adds bounded classification to an existing hook and ledger path. It adds no orchestration runtime, vector DB/KG, durable-execution engine, trained critic, SaaS, or guardrail framework.

### 4.2 Proposal 2 — eliminate shell-as-content transport and shell nesting

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Add a concise, high-priority command-construction rule:

> Use Write/Edit for file content. Use the native PowerShell tool for PowerShell. Do not embed PowerShell here-strings, JSON/document bodies, or a second `bash -c '…'` inside Bash. For complex multiline Bash, Write a temporary `.sh`, validate it with the target interpreter, then execute the file. Never repair an unmatched quote by guessing a delimiter.

This rule is consistent with the existing native PowerShell enablement (`claude/settings.json:4-11`), the existing permission for Write and Bash (`settings.json:26-36`), and the measured Write-versus-here-string route (`windows-shell.md:85-102`). It also corrects the fabricated Write restriction documented in the live defects (`INPUT-known-harness-defects.md:151-160`).

Its quote-specific recommendation is **UNVERIFIED because the raw failed constructs are absent; the settling experiment is to apply the rule only after the shadow baseline and compare matching-quote incidence per 1,000 Bash calls within the same command-family strata**. It is **likely (55-80%)** to lower overall quoting friction because it removes nested language boundaries and a measured 13.6%-failure content route, but a numeric quote-error reduction is not justified yet.

Anti-overfit gate: **passes**. It uses native tools and configuration; no new runtime or memory system is introduced.

### 4.3 Proposal 3 — conditional syntax denial after shadow precision is established — UNVERIFIED

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

If shadow data shows the raw command itself fails target-shell parsing, promote only the narrow, high-precision delimiter cases to PreToolUse denial with actionable context:

* “Target Git Bash parser reports an unmatched single quote before execution.”
* Recommend Write for content, native PowerShell for PowerShell, or a validated script file for multiline Bash.
* Include no automatic quote insertion.
* Fail open on timeout, missing interpreter, parser ambiguity, or commands whose syntax validity depends on runtime input.

This proposal is **UNVERIFIED; the settling experiment is a shadow confusion matrix with at least 200 real quote outcomes and a manually reviewed precision lower bound of 95% before enforcement**. It is **very likely (80-90%)** that narrow parser-confirmed denial prevents the original shell process from emitting the matching-quote fingerprint, because denial occurs at the registered PreToolUse boundary (`settings.json:139-180`). It is only **roughly even (45-55%)** that corpus-level “Bash errors” fall by the same amount, because Claude Code may count a denied Bash tool call as a Bash failure under a different fingerprint. The experiment must therefore measure both original-fingerprint removal and total failed tool attempts, plus turns-to-success.

Anti-overfit gate: **passes** if implemented in the existing sole rewriter/dispatcher path. A second independent updatedInput hook fails the gate because the current rewriter documents nondeterministic last-writer collision (`inject-nopager.py:26-32`).

### 4.4 Proposal 4 — conditional opaque transport for transport-only failures — UNVERIFIED

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

If commands pass exact-interpreter `bash -n -c` via argv but fail through the Bash tool with quote EOF, extend the sole rewriter to put the exact UTF-8 command in a per-session temporary `.sh` under harness state and replace tool input with an explicit, simply quoted `bash <safe-path>`. Requirements:

* atomic creation with a random filename and owner-only permissions where supported;
* LF endings (the existing Windows rule documents CRLF scripts breaking real bash at `windows-shell.md:33-43`);
* no interpolation or normalization of content;
* command-length threshold to avoid Windows CreateProcess limits;
* deletion after PostToolUse, with bounded stale-file cleanup;
* hash-only telemetry and regression fixtures containing apostrophes, double quotes, backticks, heredocs, Unicode, CRLF, and nested substitutions.

This is **UNVERIFIED; the settling experiment is replaying 50 raw commands that passed argv preflight but failed actual transport, first through the current tool and then through temporary-file transport in a copied test environment**. It is **very likely (80-90%)** to eliminate transport-introduced quote corruption if such a class exists, because the outer tool command no longer contains the original quote-bearing payload. It will not fix genuinely invalid shell syntax, which is why classification must precede activation.

Anti-overfit gate: **passes conditionally**. It is a small transport adapter on the existing hook bus, not a second shell runtime or durable execution system. If it grows into a general job daemon, it fails the gate and must be rejected.

### 4.5 Proposal 5 — record the counterfactual metric, not merely the fingerprint

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

For each staged intervention, record:

* quote EOFs per 1,000 Bash calls;
* all Bash failures per 1,000 calls;
* denial/rewrite counts and false-positive adjudications;
* tool attempts and wall time from first failed/blocked command to first successful equivalent;
* command-family stratum;
* successful final outcome or abandonment.

This prevents a cosmetic win where the original fingerprint becomes a denial fingerprint while user friction stays constant. It is **very likely (80-90%)** that the paired metric detects such displacement because it explicitly counts total failed attempts and time-to-success in addition to the normalized error. Evidence for the need is the corpus's separate `failures_by_tool` fingerprints, including 230 user/tool rejections under Bash (`corpus.json:8849-8855`). The exact ledger schema availability is **UNVERIFIED; the settling experiment is one sanitized PreToolUse/PostToolUse payload capture and a no-write schema check before implementation**.

Anti-overfit gate: **passes**. These are additive bounded fields on the existing event path, not an observability SaaS or new database.

### 5.2 Forecast

It is **likely (55-80%)** that the combined classify→route design will prevent at least half of the dominant fingerprint after tuning, corresponding to roughly 816 avoided occurrences over an equally sized workload and an error-rate movement from 5.98% to about 5.22%. Evidence: the population is highly concentrated in one reported delimiter/locus (1,631/1,785), and the existing hook sees the raw command before execution (`inject-nopager.py:40-49,183-213`). This forecast remains **UNVERIFIED; the settling experiment is the staged 200-event baseline/intervention described in §4, and success requires both ≥50% fingerprint reduction and no increase in all-failure attempts per 1,000 Bash calls**.

It is **unlikely (20-45%)** that a prompt/config rule alone reaches the full 1.508-point ceiling, because the data cannot establish that all failures are agent-authored and prompt-sensitive; some may be transport failures or repeated command families. Evidence: the normalized population contains both `-c` and `eval` loci and three delimiter types, while raw commands are absent. The same staged experiment settles this.

It is **very unlikely (5-20%)** that automatic delimiter insertion is safe enough to deploy, because a syntactically balancing quote can change argument boundaries, expansion, redirection, or payload content while still parsing. This is a semantic safety judgment grounded in shell grammar, not a measured corpus claim; a fuzz suite could estimate parse preservation but cannot prove intended semantics. Therefore the design rejects auto-balancing regardless of apparent error-count benefit.

### 5.3 Acceptance gate

Promote an intervention only when all are true:

1. At least 200 baseline and 200 intervention quote outcomes, or a predeclared 30-day window with all outcomes retained.
2. Same detector and target interpreter in both periods.
3. Results stratified by command family and agent/session class, preventing one audit burst from masquerading as general improvement.
4. At least 50% reduction in the target fingerprint's rate per 1,000 Bash calls.
5. No increase in all Bash failures/denials per 1,000 calls.
6. Lower median attempts-to-success and no material wall-time regression.
7. For enforcement, manually reviewed precision at least 95% with a reported binomial confidence interval.

The thresholds are policy choices, not corpus facts. They are **UNVERIFIED; the settling experiment is the staged trial itself**. It is **likely (55-80%)** that 200 events per arm are sufficient to detect a 50% reduction in a concentrated failure class, but formal power depends on clustering by session and the post-change Bash call denominator; compute cluster-aware power from the shadow baseline before activation.

## 6. Alternatives considered and rejected

### “Just add a quoting tip to CLAUDE.md”

Rejected as the only fix. It is cheap and can accompany the intervention, but it neither distinguishes transport from syntax nor measures compliance. The existing harness already has extensive Windows shell rules (`windows-shell.md:1-102`), yet the corpus still contains the failures. Whether those rules existed for the entire corpus period is **UNVERIFIED; the settling experiment is repository/config history aligned to failure timestamps**.

### “Automatically add the missing quote”

Rejected. The result can parse and execute the wrong command. A harness optimizing error rate at the cost of command semantics is worse than the visible failure.

### “Register a second Bash rewrite hook”

Rejected. The existing rewriter explicitly says only one updatedInput writer may target Bash because the last writer wins nondeterministically (`inject-nopager.py:26-32`). Extend that hook or move all rewriting into one dispatcher module.

### “Replace Bash with PowerShell everywhere”

Rejected. The corpus reports PowerShell at 19,181 calls and 10.6% errors in the pinned measured ground truth, versus Bash at 5.98%; wholesale replacement is not supported by this reliability axis. Native PowerShell is appropriate for PowerShell semantics and Windows operations, not as a universal substitute.

### “Build a shell daemon / durable command runner”

Rejected by the anti-overfit gate. It is BUILD-LARGE, duplicates orchestration/runtime responsibility, and is unnecessary before a <200-line existing-hook classifier establishes the causal split.

### “Use an LLM critic to repair commands”

Rejected by the anti-overfit gate and semantic risk. It introduces the previously rejected trained-critic pattern and adds probabilistic mutation where a deterministic parser can provide the required first discriminator.
