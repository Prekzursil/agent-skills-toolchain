# A087 — coherence audit: hooks versus settings / silent override

## Verdict

I found **two mechanically established silent-override conflicts** between the local hook tree and the active user settings:

1. The outer `PreToolUse` matcher in `settings.json` prevents the local dispatcher from receiving `Workflow`, even though the dispatch manifest and the generalized monitor hook both say that it does. On a `Workflow` call, the old standalone workflow monitor runs and the generalized successor does not. The settings-side native matcher wins.
2. `~/.claude/hooks/hooks.json` is a 26-command plugin manifest stranded at a location Claude Code does not load as a user configuration source, while `settings.json` explicitly disables the Everything Claude Code (`ecc`) plugin whose runtime and documentation that file describes. The active settings/plugin loader wins; all 26 records in the standalone copy are dead text.

I also found one real textual policy collision that I do **not** promote to a fully verified runtime finding: the credential hook says its credential-file block is off by default, while `settings.json` retains unconditional native `Read` deny rules for part of the same file set. Current official documentation says deny rules still win over hook decisions, but another current official permission-mode page describes `bypassPermissions` as skipping the permission layer. This Linux bundle has no Claude executable and no Windows environment, so the exact behavior of installed Claude Code 2.1.214 cannot be run here. That item is therefore headed and handled as **UNVERIFIED** below, including the experiment that settles it.

The two established findings are **almost certain (90-99%)**, based on two independent signals in each case: the literal active configuration plus the relevant local routing implementation/test contract, and Claude Code's current official hook/plugin loading semantics. The residual 1-10% is because the remote bundle cannot expose the Windows host's live `/hooks` browser or execute its installed Claude binary.

No replacement runtime, daemon, vector store, guardrail framework, or other rejected component is warranted. Every resolution below is **CONFIG (settings/JSON only)** and stays on Claude Code's native hook loader plus the already-existing local dispatcher bus.

## Examined collisions that are not findings

Therefore later groups are not dead merely because earlier groups match.

Confidence: **almost certain (90-99%)**, from the current hook reference and the distinct active commands. No edit is recommended solely because groups overlap.
