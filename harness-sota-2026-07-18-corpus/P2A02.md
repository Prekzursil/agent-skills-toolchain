# P2A02 — State of the art in context engineering for long-horizon agents

**Unit:** P2A02  
**Research date:** 2026-07-18  
**Lens:** external evidence only; no claims below are derived from the owner's local harness or repository  
**Question:** What is established, promising, and fashionable in compaction, retrieval, working memory, attention budgeting, and context rot—and what should this harness adopt?

## Executive conclusion

The strongest conclusion is almost certain (90-99%): a model's advertised context-window size is a capacity limit, not a reliable effective working-memory size. This is supported by mechanically independent evaluations with different task constructions: position-controlled multi-document QA and key-value retrieval in *Lost in the Middle*; multi-needle, multi-hop, and aggregation tasks in RULER; low-lexical-overlap retrieval in NoLiMa; realistic code tasks in LongCodeU; and experiments where performance falls even after the relevant evidence has been perfectly retrieved. The measured degradation varies by model and task, so “context rot” is a useful name for a family of effects, not a universal decay curve ([Liu et al., TACL 2024](https://aclanthology.org/2024.tacl-1.9/), [Hsieh et al., RULER](https://arxiv.org/abs/2404.06654), [Modarressi et al., NoLiMa](https://arxiv.org/abs/2502.05167), [Li et al., LongCodeU](https://aclanthology.org/2025.acl-long.1324/), [Du et al., EMNLP Findings 2025](https://aclanthology.org/2025.findings-emnlp.1264/)).

Compaction, retrieval, and external memory are established as necessary *resource-management primitives*, but no one of them is established as a generally lossless substitute for the original trajectory. Summarization can omit details; retrieval can miss, fragment, or mis-rank them; and full context can dilute or fail to use them. The best current design is therefore very likely (80-90%) to be a small hybrid: pinned invariants plus a compact current-state checkpoint, a short recent transcript tail, recoverable pointers to full-fidelity evidence, and query-time retrieval. Evidence comes from the complementary failure modes measured by long-context-versus-RAG studies, LongMemEval, MemoryArena, and official production primitives from Anthropic and OpenAI ([Li et al., EMNLP Industry 2024](https://aclanthology.org/2024.emnlp-industry.66/), [Wu et al., LongMemEval](https://arxiv.org/abs/2410.10813), [MemoryArena](https://arxiv.org/abs/2602.16313), [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction)).

What is *not* established is a universal memory architecture, optimal compaction threshold, scalar “attention budget,” or evidence that vector databases, knowledge graphs, reflection loops, learned memory controllers, or multi-agent context managers improve this owner's workloads enough to justify their complexity. Two mechanically independent signals support that boundary: a 2026 rate–distortion survey finds repeated agent compaction rarely measured under comparable budgets, while MemoryArena finds that near-saturated recall-benchmark performance does not transfer to interdependent multi-session action ([rate–distortion survey](https://arxiv.org/abs/2607.08032), [MemoryArena](https://arxiv.org/abs/2602.16313)). Several 2025–2026 systems report large gains, but most are single-paper results on narrow benchmarks, often with custom training. They are promising experiments, not defaults.

The recommendation is deliberately minimal: retain native compaction, add deterministic checkpointing and post-compaction validation on the existing hook bus, prune replaceable tool payloads before summarizing semantic state, keep raw evidence recoverable by stable pointers, and evaluate repeated compaction on real trajectories. Those primitives are supported by native lifecycle hooks, selective context editing, and file-backed memory rather than a replacement runtime ([Claude Code hooks](https://code.claude.com/docs/en/hooks), [Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Anthropic memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). This does not add a second orchestration runtime, vector/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

## Method and evidence standard

I decomposed the question into five evidence tracks: (1) whether long context degrades task performance; (2) whether compaction preserves long-horizon task state; (3) whether retrieval and persistent memory outperform full context; (4) what “attention budgeting” means operationally; and (5) whether headline memory benchmarks predict agentic performance. I searched academic indexes and the public web, then deep-read primary papers, official documentation, and official repositories. The source set contains peer-reviewed ACL-family papers, arXiv/OpenReview preprints, official vendor documentation, and real issue trackers. Vendor engineering posts and issue reports are treated as operational evidence, not controlled science.

The detector control for “research availability” was known-present work: searches recovered the canonical *Lost in the Middle*, RULER, NoLiMa, LongMemEval, and official Anthropic/OpenAI compaction documents. Claims that something has *not* been established require two independent signals: a literature/review limitation and a benchmark/evaluation limitation. A failed search alone is never treated as evidence of absence.

Confidence bands follow the mandated vocabulary. “UNVERIFIED” is written inline whenever a premise or owner-specific effect has not been directly tested; each such statement names the experiment that would settle it.

## 1. What is actually established

### 1.1 Advertised window length is not effective task length

This is almost certain (90-99%). The evidence is broad and mechanically independent:

* *Lost in the Middle* changes the position of relevant evidence while holding the task substantially fixed. Performance is often U-shaped: strongest at the beginning or end and weaker in the middle, including for explicitly long-context models ([paper and data/code links](https://aclanthology.org/2024.tacl-1.9/)).
* RULER expands simple needle-in-a-haystack tests into multiple needles, variable types, multi-hop tracing, and aggregation. Of 17 models advertising at least 32K context, only about half maintained satisfactory performance at 32K; nearly perfect vanilla needle retrieval therefore did not imply broader long-context competence ([paper](https://arxiv.org/abs/2404.06654), [official repository](https://github.com/NVIDIA/RULER)).
* NoLiMa removes the literal word overlap that lets a model locate a “needle” through shallow matching. Ten of twelve evaluated long-context models fell below half of their short-context baseline at 32K; GPT-4o fell from 99.3% to 69.7% ([paper](https://arxiv.org/abs/2502.05167), [official repository](https://github.com/adobe-research/NoLiMa)).
* LongCodeU tests code-unit perception, intra- and inter-unit relations, and documentation over long code. The authors report dramatic drops beyond 32K despite claimed windows of 128K–1M, with inter-unit relations hardest ([ACL 2025 paper](https://aclanthology.org/2025.acl-long.1324/)). This is more relevant to coding agents than synthetic retrieval alone.
* Du et al. remove retrieval as the explanation: across five open and closed models, math, QA, and code performance fell 13.9%–85% as input length increased even when relevant information was perfectly retrieved, positioned immediately before the question, or irrelevant positions were masked. Their “recite the evidence first” mitigation improved GPT-4o by up to 4% on RULER ([EMNLP Findings 2025](https://aclanthology.org/2025.findings-emnlp.1264/)).

These studies do **not** prove a single monotonic decay law. Position, lexical overlap, evidence density, task dependency, model, and reasoning procedure all change the curve. Chroma's “context rot” report is useful because its repository releases code for semantic needle, repeated-word, and LongMemEval experiments, but it is an industry technical report rather than peer-reviewed evidence ([report](https://research.trychroma.com/context-rot), [reproduction repository](https://github.com/chroma-core/context-rot)). The defensible claim is “performance is task- and model-dependent and often degrades as irrelevant or difficult-to-use context grows,” not “every extra token always harms every model.”

### 1.2 More context can harm utilization even after retrieval succeeds

This is very likely (80-90%), with the range below “almost certain” because the most direct causal study covers five models and three task families rather than every modern model. Du et al.'s masked/whitespace controls distinguish retrieval failure, distraction, and raw input-length effects, and their evidence-recitation result suggests that isolating the evidence into a short local reasoning context can help ([paper](https://aclanthology.org/2025.findings-emnlp.1264/)). *When Transformers Know but Don't Tell* independently finds a retrieval–utilization gap by probing hidden representations: models can encode target position yet fail to produce the answer ([EMNLP Findings 2024](https://aclanthology.org/2024.findings-emnlp.447/)).

Operational consequence: a harness should not equate “the evidence is somewhere in the prompt” with “the agent can use it.” Evidence should be re-localized near the decision point, preferably in a small cited bundle.

### 1.3 Compaction is useful, lossy state transfer—not durable truth

It is almost certain (90-99%) that summarization compaction can free enough tokens for a conversation to continue. OpenAI's Responses API supports threshold-triggered server compaction and a stateless compact endpoint; Anthropic supports server-side compaction, selective context editing, and SDK compaction; Claude Code auto-compacts and exposes `PreCompact` and `PostCompact` lifecycle events ([OpenAI guide](https://developers.openai.com/api/docs/guides/compaction), [Anthropic guide](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Claude Code hooks](https://code.claude.com/docs/en/hooks)).

It is also almost certain (90-99%) that natural-language compaction is lossy. GitHub's official Copilot CLI documentation explicitly states that exact wording, full command output, and minor early decisions may not survive ([GitHub context-management documentation](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/context-management)). Anthropic warns that overly aggressive compaction can lose subtle details whose importance becomes clear only later ([Anthropic context-engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). OpenAI's server-side compaction item is intentionally opaque and not human-interpretable, which makes external verification impossible unless a separate inspectable checkpoint exists ([OpenAI compaction guide](https://developers.openai.com/api/docs/guides/compaction)).

Real issue reports show operational failure modes, though they are not prevalence estimates: Codex users have reported lost framing after compaction, compaction loops, and a current request for visible summaries ([discussion #5799](https://github.com/openai/codex/discussions/5799), [issue #8481](https://github.com/openai/codex/issues/8481), [issue #21468](https://github.com/openai/codex/issues/21468)). These reports corroborate plausibility, not population frequency.

Repeated compaction is particularly under-measured. The 2026 rate–distortion survey states that repeated agent compaction is rarely evaluated and that no benchmark holds a common budget axis across the stack ([Colaco and Lahjouji](https://arxiv.org/abs/2607.08032)). Independently, MemoryArena shows that strong scores on recall-style memory benchmarks do not transfer to interdependent multi-session action tasks ([paper](https://arxiv.org/abs/2602.16313)). Therefore the claim “our summary looks complete” is not evidence that a long-horizon agent remains competent after several compactions.

### 1.4 Selective pruning and semantic compaction solve different problems

This distinction is established at the mechanism level and likely (55-80%) to matter materially in agent workloads. Anthropic's context editing removes old tool results while preserving conversational structure; compaction replaces history with a summary. Its API exposes thresholds, a recent-tool-use keep count, a minimum clear amount, protected tool names, and whether tool inputs are removed ([context editing configuration](https://platform.claude.com/docs/en/build-with-claude/context-editing)). OpenClaw and GitHub Copilot independently document the same architectural distinction: pruning discards replaceable tool payloads; compaction summarizes semantic history ([OpenClaw documentation](https://github.com/openclaw/openclaw/blob/main/docs/concepts/compaction.md), [GitHub documentation](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/context-management)).

The established engineering inference is that a 30,000-token file dump and a 30-token owner constraint should not compete under the same eviction policy. Large deterministic/re-readable outputs are good pruning candidates; goals, constraints, decisions, failures, unresolved questions, and evidence pointers need explicit preservation.

### 1.5 Retrieval is a cost/attention control, not a universal accuracy win

This is almost certain (90-99%). A direct RAG-versus-long-context comparison across public datasets and three models found that sufficiently resourced full long context had higher average accuracy, while RAG was much cheaper; a simple route between them preserved near-long-context performance at lower cost ([Li et al., EMNLP Industry 2024](https://aclanthology.org/2024.emnlp-industry.66/)). Conversely, RAG can win where irrelevant context dominates, but it fails when evidence is fragmented or every document matters. Loong deliberately constructs tasks where every document is relevant and reports poor RAG performance ([Wang et al., EMNLP 2024](https://aclanthology.org/2024.emnlp-main.322/)). ACL 2026 work independently finds that decomposing context can harm documents with strong cross-part dependency and recommends routing rather than indiscriminate decomposition ([Guo et al.](https://aclanthology.org/2026.findings-acl.2097/)).

LongMemEval demonstrates that retrieval design details matter: session decomposition, fact-augmented keys, time-aware query expansion, and reading strategy improve different memory abilities, but long-context systems and commercial assistants still show substantial drops on information extraction, cross-session reasoning, temporal reasoning, updates, and abstention ([paper](https://arxiv.org/abs/2410.10813), [official repository](https://github.com/xiaowu0162/LongMemEval)).

The correct conclusion is hybrid routing. Use exact/full context when dependency is dense or exactness matters; retrieve when the corpus is much larger than the active task and relevance is sparse; retain a way to widen the search when retrieval confidence is low.

### 1.6 Persistent memory must support update, provenance, abstention, and forgetting

This is very likely (80-90%). LongMemEval's task taxonomy includes temporal reasoning, knowledge updates, and abstention rather than recall alone ([paper](https://arxiv.org/abs/2410.10813)). Memora reports frequent reuse of invalid memories and only marginal aggregate improvements from six tested memory agents, motivating a metric that penalizes obsolete-memory use ([Memora preprint](https://arxiv.org/abs/2604.20006)). MemEvoBench finds that noisy tool outputs, adversarial injection, and biased feedback can contaminate accumulated memory ([preprint](https://arxiv.org/abs/2604.15774)). These are independent signals that “store and retrieve facts” is incomplete.

Official Anthropic documentation also places security and lifecycle obligations on the implementer: strip sensitive material, cap file size, expire stale files, and prevent path traversal ([memory-tool security guidance](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). A memory without source, timestamp, scope, supersession, and deletion semantics is a liability disguised as recall.

### 1.7 File-backed checkpoints are a strong simple baseline

It is very likely (80-90%) that inspectable files are an essential baseline before a specialized memory service. Anthropic's documented multi-session development pattern uses a progress log, feature checklist, startup reference, session-start read, and end-of-session update, with completion recorded only after end-to-end verification ([memory-tool pattern](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool), [long-running harness case study](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). LongMemEval-V2's AgentRunbook-C stores trajectories as files and uses a coding agent to gather evidence; it reports 72.5% average accuracy versus 48.5% for its strongest RAG baseline and 69.3% for an off-the-shelf coding-agent baseline, at higher latency ([paper](https://arxiv.org/abs/2605.12493), [official repository](https://github.com/xiaowu0162/LongMemEval-V2)).

This does not prove files always beat embeddings. It establishes that transparent, grep-able, agent-navigable storage is a competitive baseline and often easier to audit than an opaque memory graph.

### 1.8 “Attention budget” is a metaphor; token accounting is measurable

The phrase is useful but not a standardized scalar. Anthropic describes context as a finite resource with diminishing marginal returns and calls model focus an “attention budget” ([engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). The benchmark evidence above validates the practical warning, but no cited API exposes a model-independent remaining-attention meter. What systems can measure are rendered input tokens, category-level context usage, cleared tokens, cache effects, retrieval size, latency, and task success. Anthropic exposes original and post-edit token counts; Claude Code exposes `/context`; OpenAI exposes token thresholds for compaction ([Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Claude Code context window](https://code.claude.com/docs/en/context-window), [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction)).

Therefore “budget attention” should mean: minimize low-utility tokens, preserve high-value invariants, monitor actual token categories, and validate task outcomes—not estimate a fictional percentage of cognition remaining.

## 2. Promising but unproven

### 2.1 Learned context folding — likely (55-80%) within trained distributions

Context-Folding branches into a sub-trajectory and collapses it to a result; its authors report matching or beating ReAct on deep-research and SWE tasks with a 10× smaller active context, and beating summary-based management ([paper](https://arxiv.org/abs/2510.11967)). AgentFold reports strong BrowseComp results using learned granular and deep consolidation ([paper](https://arxiv.org/abs/2510.24699)). The shared result makes active, hierarchical consolidation promising.

General portability is **UNVERIFIED**; an evaluation that trains on one model family and tests unchanged folding tools/prompts across at least three proprietary and open models on held-out coding, research, and GUI tasks would settle it. Both approaches add learned policies or custom models, so they are not justified as this owner's default harness layer under the anti-overfit gate.

### 2.2 RL-trained compaction — very likely (80-90%) to help the trained model, portability unlikely (20-45%)

CompactionRL jointly optimizes task execution and summary generation and reports +7.0 SWE-bench Verified and +3.1 Terminal-Bench 2.0 points for GLM-4.5-Air, with gains on a second backbone ([preprint](https://arxiv.org/abs/2607.05378)). Two backbones and two benchmarks are stronger than a one-cell ablation. However, it is one very recent preprint tied to model training.

Transfer to an external harness using Claude/Codex is **UNVERIFIED**; the settling experiment is a frozen-agent comparison of the published compactor versus each provider's native compaction on identical trajectories, including two or more repeated compactions and exact-constraint retention. Building a training pipeline would violate the minimal-architecture preference and would introduce a trained context controller without owner-specific evidence.

### 2.3 Indexed summaries with recoverable raw evidence — likely (55-80%)

Memex(RL) proposes compact structured summaries containing stable indices that dereference full-fidelity past interactions, avoiding summary-only irreversibility ([preprint](https://arxiv.org/abs/2603.04257)). This matches the independent rate–distortion critique that early irreversible eviction fails when a later query needs discarded evidence ([survey](https://arxiv.org/abs/2607.08032)). The *architecture* is promising even without adopting its RL training: short pointers plus raw archive are compatible with files and existing tools.

Its reported end-to-end gains are **UNVERIFIED** outside the authors' tasks; replaying the owner's long trajectories with summary-only versus summary-plus-dereference under equal token budgets would settle the premise.

### 2.4 Proactive, selective memory reminders — likely (55-80%)

A very recent preprint reports that a separate memory agent which sometimes injects a reminder and sometimes stays silent improves Terminal-Bench 2.0 by 8.3 points and tau2-Bench by 6.8 points; selective intervention beats passive exposure and always-on injection in its ablations ([Wu et al.](https://arxiv.org/abs/2607.08716)). This aligns with the established finding that relevant evidence should be localized near use.

The general result is **UNVERIFIED** because it is a one-week-old preprint and adds another agent. A no-new-agent experiment—deterministic hook reminder versus always-on context versus no reminder, using the same retriever and equal token budget—would settle whether the selection benefit survives in this harness. Until then, use event-triggered deterministic reminders, not a parallel memory agent.

### 2.5 Context-dependency-aware routing — likely (55-80%)

Both Self-Route and CoDaR report that choosing between full context and retrieval/decomposition improves the accuracy–cost or robustness frontier ([Self-Route](https://aclanthology.org/2024.emnlp-industry.66/), [CoDaR](https://aclanthology.org/2026.findings-acl.2097/)). This is promising because independent studies identify opposite failure modes for full context and RAG.

A robust automatic classifier is **UNVERIFIED** for tool-agent trajectories; settle it by labeling a replay set for sparse versus dense dependency, comparing a simple deterministic rule against model self-routing, and reporting regret relative to an oracle. The minimal first version should be rules, not a learned router.

### 2.6 Visible block-level context dashboards — likely (55-80%) as an interface, not yet a standard

VISTA exposes typed addressable context blocks, token use, recency, access history, and recoverable archives; its preprint reports large gains across LOCA-Bench, BrowseComp-Plus, and GAIA without training ([paper](https://arxiv.org/abs/2606.30005)). The interface is attractive because it turns “attention budget” into observable token/accounting data.

The magnitude is **UNVERIFIED** until independent reproduction; a settling experiment would expose the same dashboard to unchanged models while ablating token counts, access history, archive/recover, and self-management independently. The owner should borrow only cheap telemetry, not reproduce the entire proposed runtime.

### 2.7 Constraint pinning across compaction — likely (55-80%) but evidence is immature

ConstraintRot reports 1,323 episodes across seven model families where violations rose after compaction and returned to zero when constraints were pinned outside lossy summaries ([preprint](https://arxiv.org/abs/2606.22528)). The causal story is plausible and consistent with official documentation that root instructions persist differently from path-scoped rules during Claude Code compaction ([Claude Code context documentation](https://code.claude.com/docs/en/context-window)).

The exact violation rates and universal mitigation are **UNVERIFIED** because this is a single-author recent preprint; reproduce seeded safety and owner constraints across Claude, Codex, and at least one open model, with the detector first validated on a known-present constraint, to settle it.

## 3. What is hype, and how to tell

### 3.1 “A million-token window means a million-token working memory”

This is almost certainly not (1-5%) true as a general claim. RULER, NoLiMa, LongCodeU, LongBench v2, and the perfect-retrieval experiments use different constructions yet all show a gap between accepted length and reliable use ([RULER](https://arxiv.org/abs/2404.06654), [NoLiMa](https://arxiv.org/abs/2502.05167), [LongCodeU](https://aclanthology.org/2025.acl-long.1324/), [LongBench v2](https://arxiv.org/abs/2412.15204), [Du et al.](https://aclanthology.org/2025.findings-emnlp.1264/)).

**Hype detector:** the demonstration reports acceptance/no-overflow or vanilla needle accuracy, but not semantic retrieval, multi-evidence integration, code relations, exact constraint retention, and task success as length grows.

### 3.2 “Context rot is one universal law or one benchmark number”

This is very unlikely (5-20%). The family of degradation effects is real, but the slope and even shape depend on evidence position, literal overlap, information coverage, dependency strength, task, and model. *Lost in the Middle* finds positional effects; NoLiMa changes lexical overlap; Loong makes all documents necessary; Du et al. isolate length from retrieval ([TACL 2024](https://aclanthology.org/2024.tacl-1.9/), [NoLiMa](https://arxiv.org/abs/2502.05167), [Loong](https://aclanthology.org/2024.emnlp-main.322/), [EMNLP Findings 2025](https://aclanthology.org/2025.findings-emnlp.1264/)).

**Hype detector:** a vendor plots a single task/model curve, names the phenomenon, then markets one retrieval or memory product as the cure without cross-model, cross-task, cost-matched ablations.

### 3.3 “RAG solves long context” or “full context makes RAG obsolete”

Both universal claims are almost certainly not (1-5%). Full context wins average accuracy in one broad comparison while RAG wins cost; RAG fails when all documents or strong cross-document dependencies matter; long context fails under noise and difficult utilization ([RAG vs LC](https://aclanthology.org/2024.emnlp-industry.66/), [Loong](https://aclanthology.org/2024.emnlp-main.322/), [CoDaR analysis](https://aclanthology.org/2026.findings-acl.2097/)).

**Hype detector:** no oracle-retrieval upper bound, no full-context baseline, no failure analysis by evidence density/dependency, or accuracy is reported without token/latency cost.

### 3.4 “Compaction is high-fidelity/lossless”

Lossless natural-language summary is almost certainly not (1-5%) for arbitrary future queries. Official GitHub documentation says fine details may be lost; Anthropic warns of subtle omissions; OpenAI compaction can be opaque ([GitHub](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/context-management), [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [OpenAI](https://developers.openai.com/api/docs/guides/compaction)). New compression papers can be near-lossless *on their evaluated query distribution* without preserving arbitrary future-use details.

**Hype detector:** “quality preserved” means one compaction, one downstream benchmark, or judge-rated summary similarity; there is no repeated-compaction test, exact identifier/constraint recall, adversarial future query, or ability to dereference raw evidence.

### 3.5 “A high memory-benchmark score proves a good long-horizon agent”

This is very unlikely (5-20%). MemoryArena explicitly finds agents that nearly saturate LoCoMo still perform poorly when memory acquisition and action are coupled across interdependent subtasks ([paper](https://arxiv.org/abs/2602.16313)). LongMemEval-V2 likewise expands evaluation from conversational recall to workflow knowledge, environment gotchas, dynamic state, and premise awareness ([paper](https://arxiv.org/abs/2605.12493)).

**Hype detector:** the benchmark is offline QA over a supplied memory corpus, the question itself is an ideal retrieval query, the reader sees gold timestamps, or success never requires acting correctly after updating memory.

### 3.6 “Vector or graph memory is the default state of the art”

This is unlikely (20-45%). Mem0 reports large savings and accuracy gains on LoCoMo, but its graph variant adds only about two percentage points over its base memory in that study ([Mem0 preprint](https://arxiv.org/abs/2504.19413)). AgentRunbook-C's file-and-coding-agent approach beats its RAG baseline on LongMemEval-V2, while MemoryArena warns that recall benchmarks poorly predict action ([LongMemEval-V2](https://arxiv.org/abs/2605.12493), [MemoryArena](https://arxiv.org/abs/2602.16313)).

**Hype detector:** architecture diagrams substitute for cost-matched baselines; there is no exact-search/file baseline, no stale-memory test, no deletion/supersession semantics, and no end-to-end action metric. Under this program's anti-overfit gate, a new vector DB or KG is rejected absent a demonstrated owner-specific win.

### 3.7 “Human cognitive labels validate an architecture”

Claims that a system has “episodic,” “semantic,” or “working” memory are very unlikely (5-20%) to establish effectiveness by themselves. Those labels are taxonomies, not measurements. What matters is whether the system preserves constraints, tracks updates, retrieves exact evidence, abstains on missing evidence, lowers cost, and improves task completion.

**Hype detector:** biological analogy is prominent but benchmark coverage, ablations, and failure cases are missing. The “attention budget” metaphor should be converted into measured token categories and task curves before it influences policy.

## 4. Specific concrete adoptions for this owner's harness

Every item below uses the required tag value and applies the anti-overfit gate explicitly. Because no local workload experiment was run in this external-research unit, every owner-specific uplift is **UNVERIFIED** and names its settling experiment.

### 4.1 NATIVE (Claude Code already does this; we just enable it) — Keep native auto-compaction, but trigger it at phase boundaries with focus instructions [UNVERIFIED: replay A/B]

**Action:** retain Claude Code's built-in auto-compaction and `/compact`; teach long tasks to compact immediately after a verified milestone or before a major phase transition, with a focus string naming the active goal, constraints, changed artifacts, failures, evidence pointers, and next step. Use `/context` before compaction to inspect category pressure. Claude Code officially supports auto-compaction, focus instructions for `/compact`, and live context inspection ([cloud/CLI context management](https://code.claude.com/docs/en/claude-code-on-the-web), [context-window documentation](https://code.claude.com/docs/en/context-window)).

**Expected effect:** likely (55-80%) to reduce emergency near-limit compaction and improve summary relevance, because compaction has more response headroom and a semantically clean boundary. The owner-specific effect is **UNVERIFIED**; settle it by replaying at least 30 matched long trajectories with default near-limit compaction versus milestone-triggered focused compaction, measuring task completion, repeated work, lost constraints, tokens, and latency.

**Anti-overfit gate:** passes. It enables a native primitive and adds no runtime or storage component.

### 4.2 BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — Add deterministic pre/post-compaction checkpoints [UNVERIFIED: seeded-retention test]

**Action:** on `PreCompact`, write one inspectable Markdown/JSON checkpoint with typed fields: immutable owner goal; success criteria; safety/authorization constraints; completed milestones with verification evidence; current state; changed artifact paths; decisions and rationale; known failures with falsifiable preconditions; open questions; exact commands/results that matter; raw-evidence pointers; and next action. On `PostCompact`, compare the exposed `compact_summary` against required checkpoint keys and inject only missing critical fields. Claude Code exposes both hooks and the post-compaction summary ([hooks reference](https://code.claude.com/docs/en/hooks)).

Do not make the hook another LLM critic. Deterministic key/identifier checks and an optional human-readable diff are enough. Keep the checkpoint outside the compacted transcript so recursive summarization cannot erase it.

**Expected effect:** very likely (80-90%) to make compaction loss visible and recoverable; task-success uplift is **UNVERIFIED**. Settle it with trajectories seeded with known constraints, identifiers, rejected approaches, and verified milestones; force two and four compactions; validate the detector on a known-present key before measuring omissions; compare continuation correctness with and without reinjection.

**Anti-overfit gate:** passes. It uses native lifecycle hooks and plain files, not a daemon, durable-execution engine, or trained critic.

### 4.3 CONFIG (settings/JSON only) — Prune stale tool results before semantic compaction where provider APIs support it [UNVERIFIED: equal-budget replay]

**Action:** for Anthropic API agents, enable server-side tool-result clearing at a conservative token threshold; retain the recent 3–5 tool interactions, require a worthwhile minimum clear amount, and exclude memory/checkpoint/evidence tools. Do not clear tool inputs initially. Anthropic exposes exactly these controls and reports cleared-token counts ([official configuration](https://platform.claude.com/docs/en/build-with-claude/context-editing)). For OpenAI Responses agents, use native compaction thresholds, but do not invent unsupported selective-pruning semantics ([OpenAI guide](https://developers.openai.com/api/docs/guides/compaction)).

Prune only payloads that are deterministic or re-readable: whole file contents, directory listings, search result bodies, compiler logs already reduced to a cited failure, and superseded duplicate reads. Never prune the only copy of an external result unless it has first been archived with a stable pointer.

**Expected effect:** very likely (80-90%) to lower input tokens in tool-heavy loops; preservation of task quality is **UNVERIFIED**. Settle it via equal-budget replay comparing no pruning, old-tool pruning, and full semantic compaction across file-editing, research, and debugging traces, measuring exact-evidence recovery and cache cost as well as task success.

**Anti-overfit gate:** passes. Configuration only; no replacement runtime.

### 4.4 BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — Standardize a four-part working-context envelope [UNVERIFIED: component ablation]

**Action:** construct each resumed/compacted turn from four explicit blocks:

1. **Pinned invariants:** owner goal, authorization/safety constraints, acceptance criteria. Never summarized or retrieved probabilistically.
2. **Current state:** compact typed checkpoint of verified progress, failures, decisions, open subgoals, and next action.
3. **Recent tail:** the last few intact turns/tool interactions for local coherence.
4. **Retrieved evidence:** a small query-specific bundle with stable source pointers and confidence; raw full-fidelity payload remains outside active context.

This combines the complementary primitives documented by Anthropic—compaction, context editing, and just-in-time file memory—without assuming any is sufficient alone ([context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), [memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)).

**Expected effect:** likely (55-80%) to improve signal density and recovery after compaction. Owner-specific benefit is **UNVERIFIED**; settle it with component ablation over full context, summary only, summary+tail, summary+retrieval, and all four blocks under equal rendered-token budgets.

**Anti-overfit gate:** passes. This is message assembly on existing buses with plain records, not a second orchestrator or memory service.

### 4.5 BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — Use exact-first hybrid retrieval with widening, not a new vector/KG store [UNVERIFIED: retrieval recall/action test]

**Action:** query inspectable checkpoint and memory files in this order: typed metadata filters (project, scope, status, valid-as-of), exact identifiers/path/command/error fingerprints, lexical search, then any already-available semantic search. Return source path/permalink, timestamp, validity/supersession status, and a short excerpt. This implements the routing lesson from RAG-versus-long-context and strong-dependency failures ([Self-Route study](https://aclanthology.org/2024.emnlp-industry.66/), [CoDaR study](https://aclanthology.org/2026.findings-acl.2097/)) and uses the competitive file baseline from LongMemEval-V2 ([paper](https://arxiv.org/abs/2605.12493)).

**Expected effect:** likely (55-80%) to outperform semantic-only retrieval on exact coding facts while retaining semantic recall for paraphrases. The owner-specific result is **UNVERIFIED**; settle it with a labeled set containing exact identifiers, paraphrases, temporal updates, missing-answer cases, and multi-artifact dependencies, then score retrieval recall *and downstream action correctness*.

**Anti-overfit gate:** passes specifically because it rejects a new vector DB/KG. It reuses plain files and any already-running memory/search capability.

### 4.6 BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus) — Make memory records temporal, falsifiable, and retractable [UNVERIFIED: stale-memory challenge]

**Action:** require durable records to carry `claim`, `source/evidence`, `project/scope`, `recorded_at`, `valid_as_of`, `status`, and `supersedes/superseded_by`. Failure memories additionally carry a falsifiable precondition; success evidence may retire them. Retrieval must prefer current records and surface contradictions rather than silently choose one. **Anti-overfit gate:** passes. This is a small schema/validation rule on the existing memory bus, not a memory runtime.

## 5. Rejected or deferred architectures under the anti-overfit gate

* **Second orchestration runtime:** rejected. Context folding and proactive memory agents are promising, but existing hook events and provider primitives can test their core ideas without another scheduler. Evidence is not yet sufficient for BUILD-LARGE.
* **New vector database or knowledge graph:** rejected. RAG is not a universal accuracy win; file-based retrieval is competitive; stale/update semantics are more urgent than another index. The Mem0 graph uplift reported on LoCoMo is modest relative to its base system ([Mem0](https://arxiv.org/abs/2504.19413)).
* **Durable-execution engine:** rejected. Context continuity is not equivalent to workflow durability, and the brief explicitly warns against importing such a runtime without evidence. Plain verified checkpoints meet the context need.
* **Trained critic or learned compaction controller:** deferred. CompactionRL, Context-Folding, and AgentFold need frozen-model, repeated-compaction, cross-provider reproduction before their training complexity is justified.
* **Observability SaaS:** rejected. Token, compaction, retrieval, and terminal-state telemetry can be recorded on the existing hook/log bus.
* **Guardrail framework:** rejected. Pinning immutable constraints and deterministically validating them across compaction is smaller and directly testable.

## 6. What could not be determined

1. **No universal optimal compaction threshold.** This absence claim has two independent signals: official products choose materially different defaults/controls (Anthropic SDK documentation lists 100K while GitHub Copilot compacts around 80% and Claude Code defaults near capacity), and the rate–distortion survey reports no benchmark holding budget axes constant across layers ([Anthropic](https://platform.claude.com/docs/en/build-with-claude/context-editing), [GitHub](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/context-management), [Claude Code](https://code.claude.com/docs/en/claude-code-on-the-web), [survey](https://arxiv.org/abs/2607.08032)). The owner-specific optimum is **UNVERIFIED**; threshold sweeps on the replay lane would settle it.

2. **No reliable prevalence estimate for real-world compaction failure.** Official issue trackers prove failure modes exist but are selection-biased and lack denominators; academic benchmarks rarely force repeated compaction. These are mechanically independent limitations ([Codex issues](https://github.com/openai/codex/issues?q=is%3Aissue%20compaction), [rate–distortion survey](https://arxiv.org/abs/2607.08032)). Instrumented aggregate telemetry with opt-in task outcome labels would settle prevalence.

3. **No provider-independent scalar “attention remaining.”** The known-present controls are token-count and context-category APIs, which were found; the independent absence signals are that vendor APIs expose tokens/edits rather than attention capacity, and benchmark performance varies by task at the same length ([Anthropic token counting](https://platform.claude.com/docs/en/build-with-claude/context-editing), [Claude Code context categories](https://code.claude.com/docs/en/context-window), [NoLiMa](https://arxiv.org/abs/2502.05167)). A standardized multi-task calibration study could create an empirical risk score, but it would still be model/version specific.

4. **No proof that any public memory leaderboard predicts this owner's coding/research workload.** LongMemEval-V2 and MemoryArena improve ecological validity, but both are new and use their own environments; MemoryArena explicitly shows prior recall benchmarks fail to transfer to action ([LongMemEval-V2](https://arxiv.org/abs/2605.12493), [MemoryArena](https://arxiv.org/abs/2602.16313)). Replaying sanitized owner trajectories is required.

5. **No independent reproduction found for the newest July 2026 preprints** (CompactionRL, proactive memory intervention, rate–distortion framework). This is not inferred from one failed query: the papers are one to two weeks old and their claims are not yet accompanied by a peer-reviewed venue or independent replication in the sources located ([CompactionRL](https://arxiv.org/abs/2607.05378), [proactive memory](https://arxiv.org/abs/2607.08716), [rate–distortion](https://arxiv.org/abs/2607.08032)). Treat their reported numbers as author results until reproduction.

6. **Could not compare current Claude, Codex, and Gemini compaction quality head-to-head.** OpenAI's compaction object can be opaque; provider implementations and models change; no current primary-source benchmark located evaluates equal trajectories, equal token budgets, repeated compactions, and downstream action across all three ([OpenAI](https://developers.openai.com/api/docs/guides/compaction), [Anthropic](https://platform.claude.com/docs/en/build-with-claude/context-editing)). The regression lane in §4.8 is the settling experiment.

7. **Could not establish that context editing itself improves task accuracy.** The mechanism and token accounting are officially documented, and pruning stale payloads is plausible, but official docs are product documentation rather than a controlled accuracy evaluation. An equal-budget replay with task outcomes, exact-evidence recovery, and cache costs would settle it ([Anthropic context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)).

## Bottom line

The frontier is not “store everything” and not “summarize everything.” It is reversible selectivity: pin what must never be lost, compact the current semantic state, preserve a short intact tail, archive raw evidence behind stable pointers, retrieve narrowly at the moment of use, widen when dependencies are dense, and test repeated compaction on actions rather than summary aesthetics.

The harness should adopt the eight small/native/config changes above before considering any BUILD-LARGE memory architecture. That ordering is very likely (80-90%) to capture most available value at far lower complexity, based on the convergence of long-context benchmarks, memory benchmarks, and official production primitives. The exact owner-specific gain remains **UNVERIFIED** until the repeated-compaction replay lane in §4.8 is run.
