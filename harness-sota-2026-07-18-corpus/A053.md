## Collision register

### C1 — CONTRADICTION: DTO applicability threshold

**Artifacts and exact lines**

- `claude/rules/php/patterns.md:17`: “Replace **shape-heavy associative arrays** with DTOs for requests, commands, and external API payloads.”
- `claude/rules/php/coding-style.md:18-20`: prefer immutable DTOs/value objects across service boundaries; keep arrays for simple maps; promote business-critical structures.
- `claude/rules/php/coding-style.md:35-36`: “Convert framework/request input into validated DTOs before it reaches domain logic.”

**Why this collides**

The first two statements permit simple maps and condition DTO promotion on shape/criticality. Line 36 is categorical for framework/request input. A simple, validated two-field request can therefore be allowed to remain an array by `patterns.md:17` and `coding-style.md:20` yet required to become a DTO by `coding-style.md:36`. This is a different threshold, not merely different wording.

**Precedence**

Unresolved. Both are same-level PHP rules. README's language-specific-over-common rule is irrelevant, and AGENTS §10 requires the collision to be surfaced (`AGENTS.md:129-131`).

**Specific resolution — NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

Choose one threshold and state it once in `php/patterns.md`; make `coding-style.md` describe only PHP mechanics (`readonly`, constructor promotion, serialization). Recommended canonical wording: “Convert validated request data to a DTO when it crosses into application/domain code; simple transport-local maps may remain arrays.” That preserves boundary validation while avoiding ceremonial DTOs that never cross a boundary. Change `coding-style.md:36` to point to the canonical rule rather than re-legislate it.

This resolution is **very likely (80-90%)** to eliminate divergent agent interpretations because both conflicting clauses become one explicit boundary test; evidence is the present three-way threshold drift at `coding-style.md:18-20,36` versus `patterns.md:17`. It rides the existing path-scoped rule bus and adds no runtime.
