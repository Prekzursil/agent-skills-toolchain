# A120 — Coherence audit: agents vs. behavior contracts / silent override

## Executive conclusion

This unit found **five runtime-relevant conflict families** in the 18 agent definitions actually present in the supplied read-only bundle. The most consequential defect is architectural: the behavior contract declares itself above provider/agent addenda, but Claude Code places each custom agent body in the **system prompt** and injects `CLAUDE.md`/project memory as conversation context. Therefore, when an agent body and the imported contract disagree, the agent body has the stronger runtime instruction channel. The contract's stated precedence is not executable precedence.

The five conflict families are:

1. nine agents require `high | medium | low` as the final confidence value while the contract requires a Sherman–Kent band on every uncertain or forward-looking claim;
2. `intent-drift-sentinel` explicitly permits mid-task questions while the contract says never ask mid-task;
3. `codex` explicitly permits a direct foreground operation lasting up to 30 minutes while the contract requires every expected-over-60-second operation to use `longrun` in background/Monitor mode;
4. `codex` mandates bypassing all Codex approvals and sandboxing even though the contract reserves blocking/permission protection for dangerous operations;
5. `chief-of-staff` and `refactor-cleaner` mandate commit/push behavior that can contradict an explicit user prohibition, although the contract says the user's explicit in-session instruction is highest.

I also found one **dead-text claim** rather than an active prompt collision: `chief-of-staff` says a PostToolUse hook blocks completion on a seven-item, mostly non-dangerous checklist. No such hook behavior exists in the supplied hook tree or shared dispatcher; the only matching text is the agent's own prose. This conflicts with the contract's “inject, do not block” rule, but at runtime the claimed blocker does not fire.

Confidence in the structural precedence conclusion is **almost certain (90-99%)**, based on two mechanically independent signals: (1) Anthropic's current subagent documentation says the custom agent body is its system prompt and `CLAUDE.md` is separately loaded through normal message flow; Anthropic's system-prompt documentation explicitly says `CLAUDE.md` is injected into the conversation, not the system prompt ([custom subagents](https://code.claude.com/docs/en/sub-agents), [modifying system prompts](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts)); and (2) the supplied runtime configuration enables named agents and `SubagentStart`, while the local hook only adds handoff/read-back context and does not re-inject or elevate the contract (`C:\Users\Prekzursil\.claude\settings.json:419-430`, represented by `/local_disk0/codexwork/bundle/claude/settings.json:419-430`; `/local_disk0/codexwork/bundle/agents/harness/modules.py:2338-2382`). Model compliance with any particular conflicting sentence remains stochastic; the architectural winner is verified, but an exact per-model compliance rate is **UNVERIFIED; a controlled two-arm invocation of each named agent with an intentionally contradictory task prompt would settle it**.

The contract says, verbatim:

> “Authoritative behavior contract for Claude Code · Codex CLI · Antigravity (agy); provider addenda defer to it.” — `C:\Users\Prekzursil\.claude\AGENTS.md:3-4` (`/local_disk0/codexwork/bundle/claude/AGENTS.md:3-4`)

That is a desired policy, not Claude Code's prompt hierarchy. Current native behavior is:

- a named custom subagent starts with its own definition body as its system prompt;
- `CLAUDE.md` and memory are loaded separately as project/conversation context;
- the task/delegation is a task message, not a system instruction;
- a teammate using an agent type gets the agent body appended to its system prompt;
- a fork is different: it inherits the parent's system prompt rather than using a named definition.

Sources: [Create custom subagents](https://code.claude.com/docs/en/sub-agents), [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents), and [Agent teams](https://code.claude.com/docs/en/agent-teams). On the named-subagent, `--agent`, and agent-typed teammate paths, the agent definition wins a direct contradiction because it occupies the system channel. On a pure fork, the named agent definition is not the applicable text, so no agents-vs-contract collision arises.

The local permission layer makes the consequences concrete: Bash, Edit, Write, and Task are pre-allowed, `ask` is empty, and `defaultMode` is `bypassPermissions` (`/local_disk0/codexwork/bundle/claude/settings.json:26-75`). Anthropic documents that a parent in `bypassPermissions` takes precedence for subagents and skips permission prompts ([custom subagents, Permission modes](https://code.claude.com/docs/en/sub-agents)). Thus the user does not reliably get an interactive permission prompt that could repair a losing contract instruction.

### F1 — Nine handoff schemas silently replace the contract's calibrated confidence lexicon

**Contract text, verbatim:**

**Agent texts, verbatim:** each required JSON envelope contains:

at:

- `C:\Users\Prekzursil\.claude\agents\build-error-resolver.md:133`
- `...\code-reviewer.md:278`
- `...\doc-updater.md:126`
- `...\e2e-runner.md:126`
- `...\harness-optimizer.md:65`
- `...\python-reviewer.md:139`

- `...\security-reviewer.md:151`
- `...\typescript-reviewer.md:153`

Bundle equivalents are `/local_disk0/codexwork/bundle/claude/agents/<file>:<line>`.

**Collision situation.** Any of these agents emits its mandatory final envelope containing an uncertain overall completion/review assessment. The agent says its final message “MUST” be exactly the schema; the schema does not admit `likely (55-80%)`, `very likely (80-90%)`, etc. The model cannot obey both without either violating the schema or violating the confidence contract. `keyAssumptions[].confidence` is not a finding: AGENTS.md §1b itself asks assumption confidence to be high/medium/low (`AGENTS.md:14-20`). The conflict is specifically the top-level confidence value used for uncertain outcome claims.

**Runtime winner.** The agent schema wins on named-agent paths because it is in the agent's system prompt and the contract arrives as `CLAUDE.md` conversation context. The final output can therefore be schema-valid but contract-invalid. Confidence is **almost certain (90-99%)**, based on the official prompt-channel documentation plus the nine literal `MUST` schemas. Exact adherence frequency is **UNVERIFIED; invoke each named agent on the same deliberately uncertain fixture and validate its output against both enums to settle it**.

**Minimal resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Change only the top-level envelope field in the shared source/template and its nine projections to an enum of the exact seven contract bands, for example `"confidenceBand": "likely (55-80%)"`, and require `"confidenceEvidence": "..."`. Keep `keyAssumptions[].confidence` as high/medium/low because §1b explicitly requires that scale. This is a prompt/schema projection edit, not a second runtime, memory store, or critic.

## Cross-cutting design conclusion

The contract cannot make itself “authoritative” over custom-agent bodies merely by saying so. A user-context document cannot outrank a custom system prompt. The minimal coherent architecture is to treat the contract as a source file whose non-negotiable clauses are **projected into every agent system prompt**, with a mechanical parity check over the projections. This is **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**: extend the existing agent-generation or audit script to (a) inject a short immutable contract preamble into every agent body, (b) validate prohibited opposites such as `mid-task AskUserQuestion`, foreground `>60s`, unconditional commit/push, bypass flags, and incompatible confidence enums, and (c) fail the config check on drift. It adds no runtime, vector store, durable engine, trained critic, SaaS, or guardrail framework and therefore passes the anti-overfit gate.

This projection is **very likely (80-90%)** to eliminate structural silent override because both role instructions and shared floor would occupy the same agent system prompt; evidence is Claude Code's documented prompt placement and the small finite set of conflicts above. Behavioral compliance is still probabilistic and **UNVERIFIED; an agent-fixture conformance suite with one adversarial collision prompt per rule would settle the residual rate**.
