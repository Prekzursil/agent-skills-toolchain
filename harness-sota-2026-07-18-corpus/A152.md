I found **two confirmed stale references and one runtime conflict that remains UNVERIFIED on the Windows host**:

The first two findings are narrow coherence defects. They do not justify replacing the harness. The existing native MCP bus and shared dispatcher/ledger bus are the minimal architecture to retain.

The audit record is supporting evidence, not treated as independently re-executed fact.

### Which side wins at runtime

The native MCP scope mechanism wins. Anthropic's current MCP documentation states that both local- and user-scoped MCP servers are stored in `~/.claude.json`, whereas project-scoped servers are stored in `.mcp.json`; it also gives MCP source precedence as local, project, user, plugin, then claude.ai connector. The settings file controls permissions and enabled plugins, but it is not the native storage plane for a user-scoped `claude mcp add` registration.

This conclusion is **almost certain (90-99%)**, supported by the current primary documentation, complete settings parse, observed corpus calls, and the earlier live registration evidence. The residual uncertainty is version skew between the remote packet and the Windows binary.
