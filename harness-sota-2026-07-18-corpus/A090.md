# A090 — coherence audit: hooks versus MCP, direct contradiction

## Verdict

This unit cannot honestly complete the requested two-sided coherence audit from the remote bundle. The hook side is present: `/local_disk0/codexwork/bundle/claude/hooks` contains exactly 164 Python files. The MCP side named by the unit is not packaged: there is no `managed-mcp.json`, root `.mcp.json`, root `.claude.json`, or plugin tree under `/local_disk0/codexwork/bundle`. Because a direct-contradiction finding requires both texts verbatim, a concrete shared situation, and a verified runtime winner, I report **zero adjudicated findings, not “zero contradictions.”** The distinction matters: the former is an incomplete comparison; the latter would be an unsupported absence claim.

This is the Windows-only-input case anticipated by the remote override. The missing inputs exist, if at all, only on the Windows subject paths named in the brief. I did not fabricate their contents from older audit claims, the Codex parity configuration, or hook comments.

Confidence: it is **almost certain (90-99%)** that no sound full-audit verdict can be derived from this bundle, because (1) two independent, known-positive-controlled filesystem detectors find the hook/config controls but not any named MCP authority, and (2) the supplied prior audits conflict on whether the machine-managed authority was installed, as detailed below. The remaining 1-10% accounts for an opaque encoding of those files somewhere not discoverable as files or textual content; the settling experiment is to provide a manifest-addressed snapshot of the four MCP source classes and compare its hashes with the Windows originals.

## Scope and strict finding rule

I used the unit's narrow definition of direct contradiction:

1. Hook text or executable behavior says **X**.
2. MCP configuration text or effective loader behavior says **NOT X**.
3. Both apply to the same server/tool/session/project situation.
4. The situation can actually arise in the effective configuration.
5. Runtime precedence is verified rather than inferred.

A stale comment, a difference in inventory, a redundant definition, or a policy that is never wired is not by itself a finding. A prior audit's paraphrase is also not one of the required verbatim source texts; the brief explicitly classifies those audit findings as claims rather than facts.
