# P2A11 — Agent skills in the wild: what exists, what is high quality, and what to adopt

**Unit:** P2A11  
**Date:** 2026-07-18  
**Lens:** external research only. Per the unit boundary, this report does not inspect or characterize the owner's local skills, repositories, configuration, or session corpus.  
**Research question:** Agent skills in the wild: what exists, what is high quality, what should this owner's harness adopt or steal? Include Anthropic's own and the best community sets.

## Executive judgment

Agent Skills have crossed the line from an Anthropic-specific convention into a small, real interoperability standard. The standard is deliberately thin: a directory, a required `SKILL.md`, required `name` and `description` frontmatter, and optional scripts/references/assets. Discovery loads metadata; activation loads the instructions; execution reads additional resources on demand. That progressive-disclosure design is established in the specification and is implemented by Anthropic, OpenAI/Codex, Microsoft Agent Framework, GitHub Copilot, and other clients ([Agent Skills specification](https://openagentskills.dev/docs/specification), [Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills), [OpenAI skills catalog](https://github.com/openai/skills), [Microsoft Agent Framework docs](https://github.com/MicrosoftDocs/semantic-kernel-docs/blob/main/agent-framework/agents/skills.md), [GitHub Copilot docs](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills)).

The strongest currently available effectiveness evidence is SkillsBench, a preprint plus open benchmark with deterministic verifiers. In its original 86-task/11-domain study, curated skills improved mean pass rate by 16.2 percentage points, but effects ranged from +4.5 points in software engineering to +51.9 in healthcare and 16 of 84 measured tasks regressed. Self-generated skills averaged no benefit; focused skills with 2–3 modules beat comprehensive documentation ([paper summary and results](https://huggingface.co/papers/2602.12670), [current benchmark and paired leaderboard](https://www.skillsbench.ai/)). This is exactly the anti-overfit result the harness brief should care about: skills are useful, but “more skills,” “larger skills,” and “let the agent write its own skills” are not supported shortcuts.

The best ecosystem assets are not the largest collections. They are the sources with one or more of: production provenance, executable deterministic helpers, task-level evals, coexistence tests, explicit licenses, pinned provenance, narrowly scoped subject expertise, and evidence-bearing completion gates. Anthropic's production-used document skills, OpenAI's curated/system skills, Microsoft's scenario-tested SDK skills, NVIDIA's signed/eval-bearing skill program, Hugging Face's CLI-generated/current documentation approach, Vercel's domain-authored React guidance, and selected Superpowers workflows are the strongest sources to adopt or mine. Broad community catalogs are discovery indexes, not trust stores.

The security conclusion is equally firm. A skill is executable supply-chain input, not benign documentation. Anthropic's enterprise guide says to treat skill installation with the rigor of production software and requires per-skill security review and evaluations ([Anthropic enterprise guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)). Research has demonstrated attacks using only `SKILL.md` text, including selection manipulation and guardrail bypass; a large empirical study found at least one flagged vulnerability in 26.1% of 31,132 analyzed marketplace skills, with its detector reporting 86.7% precision and 82.5% recall ([semantic supply-chain study](https://arxiv.org/abs/2605.11418), [prompt-injection study and code](https://arxiv.org/abs/2510.26328), [large-scale security study](https://huggingface.co/papers/2601.10338)). Consequently, this owner should import ideas liberally but install third-party skill bundles sparingly, pinned, reviewed, and evaluated.

## Method and evidence discipline

I searched official specifications, official product documentation, first-party repositories, issue trackers, open benchmarks, and research papers. I deep-read the Agent Skills specification; Anthropic's architecture, authoring, enterprise, and official repository materials; OpenAI's skills catalog and product descriptions; Microsoft, NVIDIA, Hugging Face, Vercel, GitHub, and community repositories; SkillsBench; and primary security papers. Repository self-descriptions establish what a project publishes, not whether its quality claims are true. Stars, install counts, and marketing labels are reported only as adoption signals, never as correctness evidence.

Most 2026 agent-skill papers cited here are recent preprints rather than replicated, peer-reviewed consensus. Findings from them are scoped to the evaluated dataset and labeled with confidence bands where they support an inference or forward recommendation. The benchmark is open and has deterministic verifiers, but its skills are curated specifically for its tasks and its domains are uneven; it does not prove that an arbitrary marketplace skill helps an arbitrary owner workflow ([SkillsBench paper](https://www.skillsbench.ai/skillsbench.pdf), [SkillsBench repository-linked project](https://www.skillsbench.ai/)).

## 1. What is actually established

### 1.1 The standard is intentionally a packaging and disclosure format, not a capability runtime

The normative core is small. A skill is a directory containing `SKILL.md`; the file has YAML frontmatter and Markdown instructions; `name` and `description` are required; `scripts/`, `references/`, and `assets/` are optional. The reference specification recommends keeping the main instructions below 5,000 tokens/500 lines and loading referenced material only when needed ([specification](https://openagentskills.dev/docs/specification)). The reference implementation provides validation through `skills-ref` ([Agent Skills repository](https://github.com/agentskills/agentskills)).

Anthropic explains three disclosure levels: all installed skills contribute name/description metadata at startup; the full `SKILL.md` loads when the agent judges it relevant; linked files load as needed. Anthropic explicitly frames this as a way to package procedural knowledge and organizational context without creating a separate specialized agent for every task ([Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)). OpenAI describes the same object as instructions, resources, and optional scripts for repeatable work and catalogs `.system`, `.curated`, and `.experimental` skills separately ([OpenAI skills catalog](https://github.com/openai/skills)).

This establishes syntactic portability and a common discovery model. It does **not** establish identical behavior across harnesses. SkillsBench documents different injection mechanisms—Claude Code and Codex discover from frontmatter while Gemini CLI exposes an explicit activation tool—and a 2026 compilation preprint reports substantial cross-framework performance differences from formatting alone ([SkillsBench appendix](https://www.skillsbench.ai/skillsbench.pdf), [SkCC preprint](https://arxiv.org/abs/2605.03353)). “Write once, performs the same everywhere” is therefore not established.

### 1.2 Curated procedural knowledge can improve agent performance; benefit is heterogeneous

SkillsBench paired curated skills with 86 tasks in 11 domains and deterministic verifiers, running 7,308 trajectories under no-skill, curated-skill, and self-generated-skill conditions. Curated skills increased mean pass rate by 16.2 percentage points. The effect varied sharply by domain, and 16 of 84 tasks had negative deltas. Focused 2–3-module skills outperformed comprehensive documentation; self-generated skills averaged -1.3 percentage points in the reported ablation ([SkillsBench results](https://huggingface.co/papers/2602.12670)). The current v1.1 site exposes 87 tasks and paired results across 24 agent/model configurations; for example, its 2026-07-16 recomputation reports GPT-5.5/Codex moving from 46.8% without skills to 66.5% with skills, and Opus 4.7/Claude Code from 43.0% to 61.2% ([current leaderboard](https://www.skillsbench.ai/)).

What this establishes is limited but important: a well-curated skill can supply procedural knowledge that a strong model does not reliably reconstruct during the task; a skill can also hurt; and efficacy must be measured per task/harness/model. It does not establish that SkillsBench-authored skills generalize to this owner's workload.

### 1.3 Anthropic's own repository is the reference architecture, not a blanket production guarantee

Anthropic publishes document skills for PDF, DOCX, PPTX, and XLSX that it says power Claude's document capabilities “under the hood.” It identifies those four as source-available rather than open source, while many example skills are Apache-2.0. The same README warns that the public implementations and observed Claude behavior may differ and tells users to test in their own environments ([Anthropic skills repository](https://github.com/anthropics/skills)).

These document skills are especially valuable as architecture exemplars because they combine instructions, supporting references, scripts, output validation, and domain-specific rendering workflows. They are stronger evidence than a prompt collection because Anthropic identifies them as actively used in a production application. Their license, platform assumptions, and task behavior still require per-skill review.

Anthropic's authoring guide says to build evaluations before extensive documentation, baseline the task without a skill, write minimal instructions that address observed gaps, keep the main file concise, use scripts to solve deterministic work rather than make the model reproduce it, and include verifiable intermediate outputs for quality-critical tasks ([authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). Its enterprise guide requires triggering, isolation, coexistence, instruction-following, and output-quality evaluations; 3–5 representative positive/negative/ambiguous queries; testing across the models in use; an owner/version/dependency/evaluation registry; and separation of author and reviewer ([enterprise guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)). These are the most mature general governance rules found.

### 1.4 OpenAI/Codex treats skills as native reusable playbooks and separates maturity tiers

OpenAI's public catalog distinguishes automatically installed `.system` skills from curated and experimental skills, installs curated skills through the native skill installer, and gives each skill its own license file ([OpenAI skills catalog](https://github.com/openai/skills)). OpenAI says it has built hundreds of skills internally for evals, training-run supervision, documentation, and growth experiments, and exposes skills across the Codex app, CLI, and IDE; this is first-party operational experience but not a public comparative evaluation ([Codex app announcement](https://openai.com/index/introducing-the-codex-app/)). OpenAI also describes skills as team-specific playbooks, distinct from plugins/apps that provide data or actions ([OpenAI Academy](https://openai.com/academy/codex-plugins-and-skills/)).

The strongest reusable OpenAI pattern is the maturity split itself: system/curated/experimental is more honest and operable than one flat “installed” pool. The public `skill-creator` also explicitly separates instructions, references, scripts, and output assets and treats the description as the activation surface ([OpenAI skill creator](https://github.com/openai/skills/blob/main/skills/.system/skill-creator/SKILL.md)).

### 1.5 The strongest vendor/community sets and what each contributes

#### Microsoft skills: strongest public example of task-fixture governance

Microsoft's public collection has language- and service-specific Azure/Foundry skills and warns not to load everything because context dilution and pattern conflation follow. Its contribution workflow requires acceptance criteria, correct/incorrect patterns, YAML scenarios, basic/error/advanced cases, mocked responses, and a test harness invocation before catalog inclusion ([Microsoft skills repository](https://github.com/microsoft/skills)). This is a high-quality *process signal*. It does not prove every one of the 170+ skills currently passes an independent real-world benchmark.

Steal: acceptance-criteria files beside each skill; executable scenario fixtures; correct-versus-incorrect API patterns; language/service-specific scoping; selective installation.

#### NVIDIA skills: strongest public provenance/evaluation packaging model

NVIDIA's official program only syncs a skill after confirming a detached signature, a governance/identity `skill-card.md`, and a Tier-3 evaluation dataset. When benchmark runs exist, it publishes `BENCHMARK.md` beside the skill. It also validates against the open specification ([NVIDIA skills repository](https://github.com/NVIDIA/skills)). This is the best discovered design for making provenance and claimed uplift inspectable at the package boundary.

Steal: signed/hash-pinned origin; human-readable skill card; mandatory eval artifact; optional benchmark-uplift report. Do not copy NVIDIA's entire governance stack if a commit hash, local review record, and eval fixture provide the needed control for one owner.

#### Hugging Face skills: strongest pattern for keeping CLI knowledge current

Hugging Face publishes official cross-client skills for Hub, datasets, Gradio, training, evaluation, and related workflows. Its recommended first skill, `hf-cli`, is generated from the locally installed CLI so command knowledge stays aligned with the actual binary; publishing regenerates and validates manifests, and CI checks skill/marketplace name and path consistency ([Hugging Face skills repository](https://github.com/huggingface/skills)).

Steal: generate volatile command/reference surfaces from `--help` or official machine-readable docs; keep the skill about workflow order, safety, and decision points. This is superior to hand-copying a fast-changing CLI manual into `SKILL.md`.

#### Vercel Agent Skills: strongest narrow vendor-authored frontend knowledge pack

Vercel's official set includes React/Next.js performance rules prioritized by impact, web-interface audit guidance, React Native guidance, composition patterns, and deployment workflows. The React skill covers 40+ rules across 8 categories; the web-design skill covers 100+ accessibility/performance/UX rules ([Vercel Agent Skills](https://github.com/vercel-labs/agent-skills)). This has strong subject provenance and good modular rule structure. The repository page showed no published releases and the public README did not expose task-level eval results at research time, so provenance is stronger than efficacy evidence.

Steal: severity-ranked rules, one problem/rationale/example per reference file, domain-specific activation descriptions. Adopt only in React/Next/Vercel projects and require local baseline-versus-skill evaluation.

#### Superpowers: strongest community software-workflow discipline, with behavioral evals

Jesse Vincent's Superpowers packages brainstorming, planning, execution, debugging, test-driven development, review, and branch-finishing workflows. Its contribution process requires skill behavior tests through a separate eval harness, while infrastructure tests live in the plugin repository. It emphasizes systematic process, simplicity, and evidence before completion ([Superpowers repository](https://github.com/obra/superpowers)). It is available through official Claude and Codex plugin marketplaces, which is a distribution/adoption signal, not proof of universal efficacy.

Steal selectively: systematic debugging; verification-before-completion; receiving/requesting code review; plan execution checkpoints; skill-writing test methodology. Do not automatically import its complete end-to-end development doctrine, worktree policy, subagent policy, or mandatory TDD semantics; those are opinionated and can conflict with the owner's cross-tool contract or task context.

#### Addy Osmani's Agent Skills: strong pattern library, weaker public efficacy evidence

This community set uses a consistent anatomy: explicit triggers and exclusions, stepwise process, “common rationalizations,” red flags, and evidence-based exit criteria. Its authoring guide says descriptions should explain both what and when, should not summarize the workflow, and should remove content that does not change behavior ([repository](https://github.com/addyosmani/agent-skills), [skill anatomy](https://github.com/addyosmani/agent-skills/blob/main/docs/skill-anatomy.md)). The collection labels itself production-grade, but the inspected public materials did not expose task-level comparative eval results.

Steal the anatomy, especially negative triggers, observable red flags, and falsifiable completion evidence. Do not install it alongside overlapping Superpowers workflows without coexistence tests; duplication can create conflicting triggers and competing policy.

#### GitHub Awesome Copilot: broad, useful discovery catalog—not a uniform quality tier

GitHub's community collection contains skills, instructions, agents, hooks, and configurations, including narrow assets with scripts/references and many prompt conversions. Its skill index exposes bundled assets and supports targeted installation ([GitHub Awesome Copilot skills index](https://github.com/github/awesome-copilot/blob/main/docs/README.skills.md)). Because entries are community-contributed and range from narrow executable utilities to generic “comprehensive” prompts, collection membership is not a reliable quality signal.

Use it to discover narrowly scoped candidates such as MCP configuration audit, Microsoft documentation lookup, migration test generation, or platform API lookup. Evaluate the individual skill, not the GitHub namespace or catalog badge.

#### K-Dense Scientific Agent Skills: uniquely broad scientific coverage, explicitly mixed assurance

K-Dense publishes 138 scientific/research skills spanning scientific libraries, databases, analysis, and communication. The repository says contributions are manually reviewed and scanned approximately weekly, but also warns that community contributions may not have been exhaustively reviewed and says not to install everything ([K-Dense repository](https://github.com/K-Dense-AI/scientific-agent-skills)). This candor is a positive governance signal. No independent per-skill efficacy results for the catalog were found.

Use it as a source of candidates for a specific scientific workflow, never as a bundle. Prefer skills authored by the relevant domain maintainer, inspect citations/API versions, and benchmark against direct official docs or a purpose-built skill.

### 1.6 Large active skill pools have a measured attention cost and an observed quality problem

Anthropic's enterprise guide states that each skill's metadata competes in the system prompt, too many active skills can lower recall, and teams should stop adding skills when measured recall degrades ([Anthropic enterprise guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)). Microsoft independently warns that loading all its skills causes diluted attention, wasted tokens, and conflated patterns ([Microsoft skills repository](https://github.com/microsoft/skills)). These are mechanically independent signals: product guidance based on Claude deployment and a separate vendor's repository operating rule.

A July 2026 empirical preprint sampled 238 skills from a much larger public dump and found only one sampled file free of its defined “skill smells,” with an average 10.5 smells per skill. The detector combined static rules and an LLM judge; several “smells” reflect authors' best-practice synthesis rather than proven causal defects, so the exact 99% headline should not be read as “99% of skills are bad.” The useful established observation is that public `SKILL.md` authoring is inconsistent and deficiencies persist in version history ([study](https://arxiv.org/abs/2607.01456)).

### 1.7 Skills are a software supply chain, including when they contain no executable code

Anthropic warns that a malicious skill can direct arbitrary code execution, file access, and exfiltration; it requires review of scripts, network calls, external URLs, credentials, tool combinations, and adversarial instructions ([Anthropic overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview), [enterprise checklist](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)).

Three independent research signals reinforce this:

1. A 2025 study demonstrated hidden skill instructions and referenced scripts exfiltrating files/passwords and exploiting persistent tool approval; its code is public ([paper](https://arxiv.org/abs/2510.26328)).
2. A 2026 University of Maryland study changed only `SKILL.md` text and achieved up to 86% discovery pairwise wins, 77.6% selection of adversarial descriptions in paired trials, and 36.5–100% governance-evasion rates depending on strategy ([paper and code link](https://arxiv.org/abs/2605.11418)).
3. A large-scale study analyzed 31,132 skills and flagged at least one vulnerability in 26.1%; script-bearing skills had 2.12× higher odds of a flagged vulnerability. Its reported detector precision/recall was 86.7%/82.5%, so these percentages are estimates with both false positives and false negatives, not ground truth counts ([study](https://huggingface.co/papers/2601.10338)).

Static scanning is therefore useful triage but not an authorization boundary. NVIDIA's open SkillSpector covers prompt injection, exfiltration, privilege escalation, dangerous code, taint, YARA, and MCP risks, but a semantic attack study shows registry governance can itself be evaded ([SkillSpector](https://github.com/nvidia/skillspector), [semantic attack study](https://arxiv.org/abs/2605.11418)).

## 2. Promising but unproven

### 2.1 Eval-bearing skill packages as the ecosystem's real quality unit

**very likely (80-90%)** that a skill package containing baseline results, positive/negative activation cases, deterministic task checks, coexistence tests, provenance, and a maintainer will outperform selection by stars or prose review alone. Evidence: Anthropic requires those evaluation dimensions; Microsoft requires acceptance/scenario fixtures; NVIDIA requires eval datasets and skill cards; SkillsBench shows average gains but task-specific regressions ([Anthropic enterprise guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise), [Microsoft repository](https://github.com/microsoft/skills), [NVIDIA repository](https://github.com/NVIDIA/skills), [SkillsBench](https://huggingface.co/papers/2602.12670)). The remaining uncertainty is whether a lightweight local harness can predict long-run owner value from small eval sets.

### 2.2 Small workflow skills plus deterministic helpers

**very likely (80-90%)** that focused skills which encode decision points and delegate exact transformations to small scripts are more robust than comprehensive prose handbooks. Evidence: focused 2–3-module skills beat comprehensive documentation in SkillsBench; Anthropic recommends scripts that solve deterministic work without consuming model context; Hugging Face generates CLI guidance from the installed tool ([SkillsBench](https://huggingface.co/papers/2602.12670), [Anthropic best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Hugging Face skills](https://github.com/huggingface/skills)). The claim remains probabilistic because the optimal boundary depends on task and model.

### 2.3 Cross-client source skills with harness-specific compiled views — UNVERIFIED

**likely (55-80%)** that one canonical semantic source plus small generated Claude/Codex/Gemini views can reduce portability failures without maintaining unrelated forks. Evidence: clients expose different activation mechanisms in SkillsBench, and the SkCC preprint reports pass-rate gains and token savings from platform-specific compilation ([SkillsBench appendix](https://www.skillsbench.ai/skillsbench.pdf), [SkCC](https://arxiv.org/abs/2605.03353)). **UNVERIFIED: settle with an experiment that runs 20 owner-derived tasks across Claude Code, Codex, and Antigravity using (a) one raw `SKILL.md` and (b) three generated adapters, then compares trigger precision, task pass rate, and tokens.** Do not adopt SkCC's new intermediate representation now; that would add architecture before this owner has demonstrated a portability defect that a small template cannot solve.

### 2.4 Signed origin plus human-readable skill cards

**likely (55-80%)** that commit pinning/hash verification plus an owner/reviewer/dependency/permission/eval card will prevent more practical supply-chain mistakes than installing a large semantic scanner alone. Evidence: NVIDIA requires signatures and skill cards; Anthropic requires an internal registry and separation of author/reviewer; semantic attacks evade automated governance ([NVIDIA skills](https://github.com/NVIDIA/skills), [Anthropic enterprise guidance](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise), [semantic supply-chain study](https://arxiv.org/abs/2605.11418)). Cryptographic signing beyond commit/hash pinning is **UNVERIFIED: settle by threat-modeling the owner's actual update paths and simulating publisher compromise, registry substitution, and local tampering.**

### 2.5 Scientific skill libraries as expert-context accelerators — UNVERIFIED

**likely (55-80%)** that narrowly selected K-Dense or official Hugging Face skills improve unfamiliar scientific/API workflows by supplying command and domain context. Evidence: K-Dense offers unusually broad, structured scientific coverage; Hugging Face maintains first-party skills; SkillsBench recorded its largest domain uplift in healthcare ([K-Dense](https://github.com/K-Dense-AI/scientific-agent-skills), [Hugging Face](https://github.com/huggingface/skills), [SkillsBench](https://huggingface.co/papers/2602.12670)). **UNVERIFIED: settle per candidate with five owner-relevant tasks, deterministic scientific checks, citation/API-version checks, and a no-skill/direct-official-docs baseline.**

### 2.6 Automated skill “smell” linting

**roughly even (45-55%)** that semantic smell linting materially predicts task performance rather than merely enforcing a preferred writing style. Evidence: the July 2026 study built a labeled detector and found widespread smells, but explicitly relies on analogous context literature to argue downstream impact; it does not establish a causal pass-rate effect for each smell ([study](https://arxiv.org/abs/2607.01456)). Static checks for frontmatter, length, missing references, and broken paths are useful now; semantic smell scores should remain advisory until correlated with this owner's evals.

### 2.7 Self-evolving or automatically mined skills

**unlikely (20-45%)** that unrestricted automatic skill creation/evolution is ready for this owner's production harness. Evidence against readiness: self-generated skills averaged no benefit in SkillsBench; public smells persist; semantic instructions create a supply-chain/authorization surface ([SkillsBench](https://huggingface.co/papers/2602.12670), [skill-smell study](https://arxiv.org/abs/2607.01456), [SkillInject](https://arxiv.org/abs/2602.20156)). A constrained system that proposes diffs from repeated failures and requires held-out eval improvement plus human review is more plausible, but remains **UNVERIFIED: settle with a shadow-mode trial on 30 repeated failure clusters, no automatic promotion, and held-out regression tests.**

## 3. What is hype, and how to tell

### 3.1 “Thousands of skills” as a quality claim

Collection size is inventory, not evidence. GitHub Awesome Copilot spans narrow executable assets and generic prompt conversions; K-Dense itself says not to install everything and cannot guarantee exhaustive review; Anthropic and Microsoft warn about recall/context degradation from too many active skills ([GitHub index](https://github.com/github/awesome-copilot/blob/main/docs/README.skills.md), [K-Dense security disclaimer](https://github.com/K-Dense-AI/scientific-agent-skills), [Anthropic enterprise guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise), [Microsoft skills](https://github.com/microsoft/skills)).

**Hype detector:** the catalog leads with count, stars, or installs but has no per-skill maintainer, version pin, license, positive/negative trigger cases, baseline comparison, deterministic verifier, or deprecation policy.

### 3.2 “Production-grade” without comparative evaluation

Vercel and Addy Osmani publish credible domain/workflow material, but the inspected public landing materials did not provide per-skill baseline-versus-enabled results. “Production-grade” can mean author experience or code style, not measured agent uplift ([Vercel](https://github.com/vercel-labs/agent-skills), [Addy Osmani](https://github.com/addyosmani/agent-skills)). Anthropic's own production-derived repository still says to test skills in the user's environment ([Anthropic skills](https://github.com/anthropics/skills)).

**Hype detector:** assertions about reliability without task definition, model/harness/version, trial count, verifier, baseline, confidence interval, and negative results.

### 3.3 “Write once, use everywhere” interpreted as semantic equivalence

The open format is portable at the file level. Runtime selection, tool names, path rules, permission semantics, and prompt formatting differ. SkillsBench documents different activation mechanisms, and SkCC reports large measured variation across frameworks ([SkillsBench appendix](https://www.skillsbench.ai/skillsbench.pdf), [SkCC](https://arxiv.org/abs/2605.03353)).

**Hype detector:** a repository lists many compatible clients but has no per-client smoke test or adapter, and the skill hardcodes tool names or platform-specific paths.

### 3.4 “The agent can generate the skill it needs”

SkillsBench's self-generated condition averaged -1.3 percentage points while curated skills gained 16.2 points ([SkillsBench](https://huggingface.co/papers/2602.12670)). That result does not prove autonomous authoring can never work after trajectory feedback, but it directly refutes treating one-shot self-generation as equivalent to curated procedural knowledge.

**Hype detector:** a meta-skill generates or rewrites skills and declares success from syntax validation or an LLM's self-review, without held-out task improvement and coexistence regression tests.

### 3.5 “Security scanned” interpreted as safe

Static/semantic scanning reduces review load; it does not prove safety. The large-scale detector itself reports imperfect precision/recall, and SKILL.md-only attacks evade realistic governance classifiers ([large-scale security study](https://huggingface.co/papers/2601.10338), [semantic supply-chain study](https://arxiv.org/abs/2605.11418)). OpenAI similarly says its upload scan does not replace review, policy, or judgment ([OpenAI Skills help](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)).

**Hype detector:** a green badge lacks scanner version, ruleset, scan timestamp, scope, findings, false-negative statement, provenance pin, and runtime permission boundary.

### 3.6 “More orchestration makes skills reliable”

The most credible evidence favors focused skills, progressive disclosure, scripts, evals, and existing native activation—not a second agent runtime. SkillsBench found focused modules better than comprehensive documentation; Anthropic's architecture uses the existing filesystem and execution tools; the open standard is intentionally thin ([SkillsBench](https://huggingface.co/papers/2602.12670), [Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills), [specification](https://openagentskills.dev/docs/specification)).

**Hype detector:** a “skill platform” adds a daemon, vector database, planner graph, durable workflow engine, trained critic, or SaaS observability before demonstrating that the native skills bus plus small scripts cannot solve the measured failure.

## 4. Specific concrete things this owner's harness should adopt

Every proposal below uses exactly one required implementation tag and explicitly applies the anti-overfit gate. None introduces a second orchestration runtime, vector/KG memory, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

### 4.1 Adopt one canonical skill package contract — **CONFIG (settings/JSON only)**

**almost certain (90-99%)** that this contract will improve inspectability and cross-client syntactic compatibility because every named field is either in the open specification or in independent Anthropic/NVIDIA lifecycle guidance; the remaining uncertainty is implementation discipline rather than architecture.

Define the accepted package shape as the open Agent Skills core plus an owner-side convention:

- required `SKILL.md` with spec-valid `name` and `description`;
- optional `scripts/`, `references/`, and `assets/` only;
- local companion metadata (outside normative frontmatter if cross-client parsers disagree): source URL, immutable commit/hash, license, owner, reviewer, supported clients/models, dependencies, network/filesystem/tool needs, last eval date, and maturity `experimental|curated|core|deprecated`;
- no unexplained files, install-time downloads, hardcoded credentials, or mutable `@latest` dependencies.

Evidence: the open spec defines the portable core; OpenAI separates maturity tiers; Anthropic requires owner/version/dependency/eval registry fields; NVIDIA ships skill cards and signatures ([spec](https://openagentskills.dev/docs/specification), [OpenAI catalog](https://github.com/openai/skills), [Anthropic enterprise guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise), [NVIDIA skills](https://github.com/NVIDIA/skills)).

**Anti-overfit gate:** passes. This is metadata on the existing skill bus, not a runtime. Keep the companion record as plain YAML/JSON/Markdown and do not build a registry service.

### 4.2 Add a sub-200-line skill admission check — **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**

**very likely (80-90%)** that this check will catch malformed packages, broken references, missing provenance, and obvious dangerous behavior before activation, based on the reference validator, Anthropic's review checklist, and observed marketplace vulnerability classes. It is not claimed to establish safety.

2. rejects broken relative paths and references deeper than the local policy allows;
3. inventories executable files, shell commands, URLs, package installs, environment variables, tool names, write/delete operations, and network access;

Evidence: Anthropic's security checklist covers these exact categories; the spec has a reference validator; security research shows both executable and instruction-only attacks; OpenAI says scanning is not a substitute for review ([Anthropic enterprise guide](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise), [Agent Skills reference repo](https://github.com/agentskills/agentskills), [prompt-injection study](https://arxiv.org/abs/2510.26328), [OpenAI help](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)).

## 6. What I could not determine (GAPS)

1. **No independent, owner-relevant ranking of public skill repositories exists.** SkillsBench evaluates curated task-paired skills, not the major repositories as installable products. Stars and installs are not substitutes. An experiment would need a common owner-derived task suite, pinned skill versions, multiple harnesses/models, and deterministic verifiers.
2. **Anthropic's complete internal production evaluation results are not public.** The repository identifies four document skills as production-used and provides guidance, but does not publish their internal pass rates, regressions, or model matrix ([Anthropic repository](https://github.com/anthropics/skills)).
3. **OpenAI's hundreds of internal skills are not publicly benchmarked skill by skill.** The public statement establishes operational use, not comparative efficacy ([Codex app announcement](https://openai.com/index/introducing-the-codex-app/)).
4. **Vercel's public landing materials did not expose task-level eval results.** Domain provenance is strong; agent uplift remains unverified. Settle with component-generation, review, bundle, and accessibility tasks against no-skill baselines.
5. **Superpowers' public eval harness exists, but I did not find a published aggregate effect size across models and real repositories.** Settle with owner-derived behavior/task runs rather than accepting methodology as outcome evidence.
6. **NVIDIA's signature/eval requirements do not by themselves establish that every published skill improves every supported client.** Inspect each skill's actual eval and benchmark artifact; signatures prove origin/integrity, not correctness.
7. **K-Dense's 138 skills were not independently validated one by one.** Its own security disclaimer says review depth varies. Each scientific candidate needs API-version, citation, numerical, and reproducibility checks.
8. **Semantic portability remains unsettled.** The SkCC results are promising but recent and introduce an intermediate representation. A three-client owner task experiment is needed before adding a compiler layer.
9. **The causal value of “rationalization tables” and semantic skill-smell linting is not established.** They are plausible authoring devices with observational support, but only ablation tests can show whether they improve owner task outcomes.
10. **No scanner can establish skill safety.** Existing empirical detectors have imperfect precision/recall, and semantic attacks can evade governance. The settling mechanism is layered: immutable provenance, manual review, least privilege/sandboxing supplied by the host, deterministic scans, and adversarial task tests.
11. **I did not inspect the owner's current installed set, overlaps, or capability gaps.** That omission is intentional under this unit's external-only boundary. A neighboring grounding unit must map these recommendations to local reality before any install or removal.
12. **Recent-paper status:** SkillsBench, SkCC, the semantic supply-chain studies, SkillInject, and the skill-smell study are recent research/preprints. Their exact effect sizes may change under replication. Recommendations above rely on convergent design implications where possible, not one headline number.

## Bottom line

The ecosystem's genuinely valuable innovation is not “a marketplace of prompts.” It is a low-complexity packaging primitive for procedural knowledge, deterministic helpers, references, and testable workflows, activated through an existing agent bus. The frontier pattern is already visible: progressive disclosure from Anthropic; maturity tiers from OpenAI; scenario fixtures from Microsoft; signatures, skill cards, and eval artifacts from NVIDIA; current-machine generation from Hugging Face; subject-matter rules from Vercel; and behavior-test discipline from Superpowers.

The owner should steal those mechanisms, not the catalogs wholesale. The winning harness is a small active set of pinned, reviewed, owner-evaluated skills with explicit negative triggers, deterministic terminal checks, and retirement rules. That recommendation rides the existing skill/hook/CLI buses and satisfies the anti-overfit gate. A new runtime, self-evolving skill daemon, vector registry, or giant universal bundle would add complexity precisely where the strongest current evidence says focused curation matters more.
