# T005 — Competitive teardown: Windsurf (now Devin Desktop)

**Unit:** T005  
**Research date:** 2026-07-19 UTC  
**Scope:** agent loop; context management; memory; tools/MCP; permissions; rules/skills/workflows/hooks; multi-agent; verification/self-check; concrete ports to the owner's Claude/Codex harness.  
**Subject write policy:** read-only. This unit wrote only this artifact.

## 0. Executive verdict

Windsurf's most important architectural idea is not a new autonomous loop. It is a **productized control surface around an otherwise conventional tool-using coding agent**: a long-horizon planner, specialized retrieval, explicit modes, scoped customization, bounded MCP exposure, pre/post hooks, reversible edits, parallel worktrees, and a review agent are presented coherently in the IDE. The current official documentation calls the product **Devin Desktop**: the official changelog says “Windsurf is now Devin Desktop” in v3.0.12 on 2026-06-02, and the former Windsurf documentation URLs redirect to `docs.devin.ai` ([official changelog](https://docs.devin.ai/desktop/changelog)). I therefore use “Windsurf/Cascade” for the historical product and “current Devin Desktop docs” where the post-rebrand documentation is the evidence.

The owner should **not replace the existing harness with Windsurf's architecture wholesale**. That conclusion is **very likely (80-90%)**, because the supplied subject already has most of the deep mechanisms Windsurf advertises—planner, subagents, scoped rules, skills, pre/post hooks, persistent memory, checkpoints, deterministic verification, and a reviewer—while the observed damage is reliability and fleet hygiene, not missing orchestration primitives. Concrete evidence: the subject has a planner definition at `/local_disk0/codexwork/bundle/claude/agents/planner.md:1-5`, a provider-neutral lifecycle pipeline at `/local_disk0/codexwork/bundle/agents/harness/README.md:3-15`, checkpoint/recall/anti-degeneration modules at that file's lines 19-29, and native subagent lifecycle wiring at `/local_disk0/codexwork/bundle/claude/settings.json:419-443`. Meanwhile the corpus records 22.9% StructuredOutput failure and 13.3% Glob failure, including 592 `ENAMETOOLONG` failures (`/local_disk0/codexwork/bundle/inputs/corpus.json:8964-9006`). Replacing working mechanisms would not directly address those measured failures.

The best ports, in priority order, are:

1. **MCP fleet admission, tool-budgeting, and recovery UX** — one registry/canonical catalogue, default-disabled servers, per-tool enablement, a hard exposed-tool budget, state/refresh controls, secret interpolation, and an allowlist. This directly attacks the dead-Tavily class. **CONFIG (settings/JSON only)** for allowlisting/default-disable/secret indirection; **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)** for a preflight that enforces the tool budget and quarantines repeated connection failures.
2. **Permission posture repair** — stop running the owner profile in blanket `bypassPermissions`; use the native permission engine for ordinary approvals and retain hooks only for non-negotiable semantic blocks. **NATIVE (Claude Code already does this; we just enable it)**. The current configuration explicitly has an empty `ask` set and `defaultMode: "bypassPermissions"` at `/local_disk0/codexwork/bundle/claude/settings.json:64-75`.
3. **Blind, worktree-isolated two-candidate evaluation for high-uncertainty tasks** — port the useful core of Arena Mode without building an IDE or second runtime. **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)** as one skill/command that launches exactly two native agents in separate existing worktrees, normalizes their evidence packets, and asks the owner or existing advisory judge to choose. Do not make it the default.
4. **First-class hook execution receipts correlated to transcripts** — Windsurf exposes trajectory ID, execution ID, event, model, tool data, and a transcript callback; ours has transcript access but its current corpus detector cannot measure hook behavior. **UNVERIFIED — experiment: run the D3 two-probe event-ledger/transcript search and a synthetic known-positive hook before choosing the sink. BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**.

The strongest “do not copy” findings are equally important:

- Do not copy automatic opaque Memories. Windsurf itself tells users to prefer Rules or `AGENTS.md` for durable knowledge ([Memories & Rules](https://docs.devin.ai/desktop/cascade/memories)). Our explicit Basic Memory plus event-ledger split is more auditable (`/local_disk0/codexwork/bundle/claude/AGENTS.md:28-34,85-91`).
- Do not copy a generic knowledge-graph memory MCP. It violates this program's anti-overfit gate, and Windsurf removed its own Knowledge Base feature in v1.12.31 ([official changelog](https://docs.devin.ai/desktop/changelog)).
- Do not copy Turbo permission mode, broad prefix allowlists, a second command-center runtime, or default multi-model fan-out.
- Do not mistake Windsurf's “up to 20 tool calls per prompt” plus paid Auto-Continue for superior persistence. It is a billing/trajectory boundary, not a correctness mechanism ([Cascade overview](https://docs.devin.ai/desktop/cascade/cascade)).

## 3. Agent loop teardown

### 3.1 Observable loop

Officially, Cascade exposes three modes:

- **Code:** all tools, file create/edit/delete, terminal, search, dependency install, autonomous multi-step execution.
- **Plan:** all tools for exploration, clarifying multiple-choice questions, alternatives, and an external Markdown plan; “Implement” switches to Code. Plans persist under `~/.windsurf/plans` and can be mentioned into a fresh session.
- **Ask:** search tools only; read-only.

Source: [Cascade Modes](https://docs.devin.ai/desktop/cascade/modes).

The main loop adds a specialized planning agent that continuously refines the long-term plan while the selected model executes near-term actions. It maintains an in-conversation Todo, accepts queued user messages, offers Search/Analyze/Web/MCP/terminal tools, stops after at most 20 tool calls per prompt, and can Auto-Continue at additional prompt cost ([Cascade overview](https://docs.devin.ai/desktop/cascade/cascade)).

Mechanically, the observable trajectory is:

```text
user prompt / queued correction
  -> mode constrains available actions
  -> planner maintains long-horizon Todo
  -> selected model performs short-horizon tool loop
  -> linter/problems feedback may re-enter loop
  -> checkpoint / response / 20-tool boundary
  -> user Continue or paid Auto-Continue
```

The claim that the planning agent improves long-task completion is **UNVERIFIED — experiment: randomized paired tasks with planning agent on/off, fixed model and context, scoring completion, tool calls, regressions, and owner corrections**. The docs assert the mechanism, not outcome data.

### 3.2 What is genuinely good

1. **Mode-level capability separation.** Ask is structurally read-only, not merely prompted to avoid edits. Plan produces a durable plan artifact, and Code is explicitly mutating. That reduces accidental authority ambiguity.
2. **A plan is external state.** The user can repair a plan and retry implementation in fresh context instead of trusting a degraded conversation summary. This is a useful separation of deliberation from execution.
3. **Queued steering is first-class.** The owner can add or delete follow-ups while the agent works without interrupting the current tool call.
4. **The loop admits its trajectory boundary.** A visible 20-call cap and context indicator make hidden truncation less surprising, even if they do not solve it.

### 3.3 Where ours already equals or exceeds it

The subject has a dedicated `planner` agent restricted to `Read`, `Grep`, and `Glob`, automatically described for planning tasks (`/local_disk0/codexwork/bundle/claude/agents/planner.md:1-5`), and its plan template requires dependencies, risks, test strategy, and success criteria (`:46-88`). The cross-tool contract requires an assumption ledger, goal re-reading, terminal-state results, background handling, and a two-strikes pivot (`/local_disk0/codexwork/bundle/claude/AGENTS.md:14-57`). Those are deeper loop invariants than Windsurf documents.

Therefore a new background planning runtime would duplicate an existing agent and violate the anti-overfit gate. A UI affordance that makes Plan/Implement easier might be pleasant, but it is not the reliability bottleneck identified by the corpus.

### 3.4 What is worse in Windsurf

- **Twenty tools per prompt is arbitrary.** It can interrupt a coherent unit of work and converts persistence into another billable prompt. It does not detect no-progress loops or validate terminal state.
- **Auto-Continue is not verification.** It extends the trajectory without independently checking that the last action advanced the goal.
- **Documentation does not expose a two-strikes pivot, error-fingerprint recovery, terminal receipts, or independent completion proof.** Absence from docs is not proof of runtime absence: **UNVERIFIED — experiment: induce two identical failures and observe whether Cascade changes hypothesis/tool, then inspect the transcript**.
- **Plan Mode can automatically switch into Code Mode.** Convenient, but authority changes should remain legible. The current docs say the agent may auto-switch when it detects readiness. For destructive or high-stakes work, explicit owner transition is safer.

## 4. Context management teardown

### 4.1 Windsurf mechanism

The current context engine indexes the entire local codebase, combines current/open files, retrieves relevant snippets, supports remote repository indexing for Teams/Enterprise, and allows context pinning. It describes itself as RAG-based ([Context Awareness](https://docs.devin.ai/desktop/context-awareness/overview)). Previous conversations can be `@`-mentioned; Cascade retrieves summaries, checkpoints, and relevant excerpts instead of the whole conversation ([Cascade overview](https://docs.devin.ai/desktop/cascade/cascade)).

Fast Context is a separate specialized retrieval subagent. Official docs say it triggers automatically for code search, uses SWE-grep/SWE-grep-mini, performs parallel searches, conserves the main model's context, and is limited to grep/read/glob. The published operational envelope is up to eight parallel tool calls per turn for four turns ([Fast Context](https://docs.devin.ai/desktop/context-awareness/fast-context)). The changelog introduced it on 2025-10-16 and later added ignore-file support ([official changelog](https://docs.devin.ai/desktop/changelog)).

Windsurf also summarizes older messages and clears history as the window grows, and Wave 13 added a visible context-window indicator ([official changelog](https://docs.devin.ai/desktop/changelog)). A November 2025 release notes that summarization had previously been too aggressive and dropped important context, then was adjusted—useful evidence that context compression is a real failure surface, not solved magic.

### 4.2 Comparative judgment

Windsurf's retrieval is **likely (55-80%)** faster and less context-polluting than asking a frontier agent to roam large repositories, because it uses a constrained retrieval worker with parallel calls and the vendor reports a 20× speed claim. That band is deliberately below “very likely”: the only performance evidence inspected is vendor documentation and release notes, not an independent benchmark on the owner's repositories. The settling experiment is a 30-query paired retrieval benchmark over three owner repos, blind-scored for relevant-file recall@k, irrelevant bytes injected, latency, and downstream patch correctness.

Our subject explicitly keeps lifecycle recall local and lexical; hooks never perform vector, semantic, network, or model search (`/local_disk0/codexwork/bundle/agents/harness/README.md:25-29`). It also has a skill router and a memory recall index. That is more deterministic and privacy-friendly, but probably less semantically flexible on vague codebase questions.

### 4.3 Port decision: do not prematurely copy Fast Context

**UNVERIFIED — specialized retrieval bake-off. BUILD-LARGE (new daemon/service/runtime -- needs its own justification).** A faithful port would require a trained SWE-grep-like model or external service, query orchestration, indexing, evaluation, and lifecycle management. That is a trained retrieval component and risks reintroducing a rejected vector/search memory architecture. It fails the anti-overfit gate until the paired benchmark shows that native `rg`/Read plus the existing router materially loses owner task correctness, not just latency. Recommendation: run the benchmark; do not build before it.

A smaller alternative is **CONFIG (settings/JSON only)**: keep capability descriptions terse and progressively disclose skill/rule bodies. The subject already does semantic routing; tune the catalogue rather than introduce another retrieval runtime. This is **likely (55-80%)** to reduce context overhead because Windsurf's own Skills design shows only name/description until invocation, and our corpus shows only 78 of roughly 355 installed skills invoked (owner-pinned measured ground truth; detailed observed invocations begin at `corpus.json:13265`). The settling experiment is prompt-token and correct-routing A/B measurement over the existing skill-router eval set.

### 4.4 Worse than ours

- Vendor-managed indexing is less inspectable than explicit `rg`/Read receipts.
- Context pinning can itself degrade model performance; the official docs warn against pinning too much.
- Remote indexing and shared Google Docs knowledge create access-control complexity. The current context page warns that team-added Google Docs do not preserve individual Drive ACLs; all team users receive the imported context. That is a governance regression relative to per-user source authorization.
- Aggressive summarization has a documented history of dropping continuity. Our objective event ledger plus sanitized checkpoints is a stronger ground-truth separation.

## 5. Memory teardown

### 5.1 Windsurf mechanism

Windsurf distinguishes:

- **Memories:** Cascade-generated local facts, workspace-scoped, stored under `~/.codeium/windsurf/memories/`, automatically retrieved when judged relevant; users can request, edit, search, and disable auto-generation.
- **Rules:** explicit durable instructions at global, workspace, or enterprise system scope.
- **`AGENTS.md`:** location-scoped rules.
- **Workflows:** manual slash-invoked prompt trajectories.
- **Skills:** progressively disclosed multi-step packages.

Source: [Memories & Rules](https://docs.devin.ai/desktop/cascade/memories) and the [2025-04-02 memory release entry](https://docs.devin.ai/desktop/changelog).

Crucially, the vendor documentation tells users to put durable reusable knowledge in a Rule or `AGENTS.md` rather than trust auto-generated Memories. Memories are local, workspace-bound, not committed, and not shared.

### 5.2 Our design is stronger

Our contract deliberately separates semantic durable memory (`basic-memory`) from objective turn history (event ledger), and replays the ledger after resume/compact/clear (`/local_disk0/codexwork/bundle/claude/AGENTS.md:28-34,85-91`). The shared lifecycle layer uses bounded lexical recall and sanitized checkpoints without raw transcript paths or session identifiers (`/local_disk0/codexwork/bundle/agents/harness/README.md:19-29`). This is more explicit about provenance and temporal roles than Windsurf Memories.

The conclusion “do not replace ours with Windsurf Memories” is **almost certain (90-99%)**, because (a) the vendor recommends explicit Rules/`AGENTS.md` for durable knowledge, and (b) the owner's harness already separates semantic and objective stores with sanitization. The remaining 1-10% uncertainty is whether auto-capture substantially reduces owner effort without injecting false memories; settle it with a shadow-only trial that proposes memories for human approval and scores precision over 100 proposals.

### 5.3 Do not copy

**Automatic memory promotion: CONFIG (settings/JSON only) — reject/leave disabled.** Automatic model-selected facts are easy to create and hard to invalidate. The owner's D4 shows how a fabricated constraint propagated through about 15 agent prompts (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:151-160`). Auto-memory would widen exactly that attack surface.

**Knowledge-graph Memory MCP: BUILD-LARGE (new daemon/service/runtime -- needs its own justification) — reject.** The current MCP docs list an optional graph-based memory server, but this program explicitly rejects vector-DB/KG memory absent extraordinary evidence. It would duplicate Basic Memory, add another truth store, and fail the anti-overfit gate.

## 6. Tools and MCP teardown

### 6.1 Windsurf mechanism

The MCP client supports:

- Marketplace installation and `windsurf://` one-click deep links.
- Manual `mcp_config.json`.
- stdio, Streamable HTTP, and SSE; OAuth for all three.
- Per-MCP, per-tool enable/disable controls and a hard limit of 100 exposed tools at once.
- `${env:VAR}` and `${file:/path}` interpolation in commands, args, env, URLs, and headers.
- Enterprise custom registries and allowlists. Once any server is allowlisted, non-allowlisted servers are blocked; configuration can match by plugin-store ID, exact command/args, or regex.
- Pre/post MCP hooks containing server name, tool name, arguments, and result.

Source: [Cascade MCP integration](https://docs.devin.ai/desktop/cascade/mcp) and [Cascade Hooks](https://docs.devin.ai/desktop/cascade/hooks). The changelog also documents per-server loading indicators, refreshing only edited servers, a 60-second initialization timeout, and a manual refresh button for error states in v1.12.31, plus later OAuth/Windows fixes ([official changelog](https://docs.devin.ai/desktop/changelog)).

### 6.2 Why this is the highest-value port

The owner has the opposite of Windsurf's bounded-admission posture: settings allow broad MCP prefixes (`/local_disk0/codexwork/bundle/claude/settings.json:47-60`), while the corpus shows a dead Tavily connection repeatedly called. The pinned measurement is 532 extract calls with 25.8% error and 135 “not connected” instances; the corpus locates the tool records at `corpus.json:175,319,1615,2647,3831` and aggregates MCP capability usage at `:13377-13483`. This is not a hypothetical architectural preference; it is the top measured reliability defect.

**MCP canonical registry and allowlist: CONFIG (settings/JSON only).** Maintain one generated server catalogue with fields `id`, `transport`, `command/url`, `enabled`, `criticality`, `owner`, `credential_ref`, and `last_verified`. Default new/unverified servers to disabled. Generate provider configs from it. Use environment/file references, never literal secrets. ### 6.3 What not to copy

- A marketplace blue check is publisher identity, not safety. Never auto-trust based on UI badge.
- Regex allowlisting of executable commands is brittle; exact argv and content hashes are safer where feasible.
- A 100-tool ceiling is still large and may overload selection. It is a maximum, not a target.
- The official docs show examples with literal token placeholders inside JSON. Our policy should retain secret references and validate presence at startup.
- Windsurf has repeatedly shipped MCP fixes—scope/OAuth, loading, Windows parsing, resource handling, tolerant schema parsing—so “native MCP” does not imply reliability. Changelog evidence is valuable negative evidence.

## 7. Permission model teardown

### 7.1 Windsurf mechanism

Terminal execution has four levels ([Terminal](https://docs.devin.ai/desktop/terminal)):

1. Disabled: every command requires approval.
2. Allowlist Only: matching commands auto-run; everything else asks.
3. Auto: model judges safety; risky commands ask.
4. Turbo: everything auto-runs except denylisted commands.

Teams/Enterprise can cap the maximum level and merge team/user command lists; deny takes precedence. The docs' examples reveal prefix semantics: allowing `git` allows `git add -A`; denying `rm` forces approval for `rm index.py`. Separately, Ask Mode is read-only, `.codeiumignore` prevents viewing/editing/creating in matched paths, MCP access can be administratively disabled/allowlisted, and pre-hooks can block reads, writes, commands, MCP calls, or user prompts with exit code 2.

### 7.2 Port

**Restore native approvals: NATIVE (Claude Code already does this; we just enable it).** Change ordinary operation away from blanket `bypassPermissions`, populate `ask`, and constrain `additionalDirectories`; retain semantic hooks for irreversible operations, literal secrets, and credential paths. Current evidence is direct: `/local_disk0/codexwork/bundle/claude/settings.json:64-75` sets credential read denials but `ask: []`, `defaultMode: bypassPermissions`, and grants both `C:` and `D:` as additional directories.

This change is **very likely (80-90%)** to reduce accidental broad execution authority because the native engine will mediate operations now globally bypassed. It may increase prompt fatigue; settle the exact allow/ask split with a two-week shadow log of commands classified by the proposed policy before enforcement.

**Permission precedence contract: CONFIG (settings/JSON only).** Encode: hard deny > explicit per-operation approval > narrow allow > ask. Never let a model safety classifier override a hard deny. Publish the merged effective policy at session start.

### 7.3 Where Windsurf is worse

- Turbo is unsafe as a general default. A denylist cannot enumerate novel dangerous compositions.
- Prefix lists are too coarse: allowing `git` also covers destructive subcommands unless another layer catches them.
- “Auto” delegates authorization to the same model proposing the action, a correlated evaluator.
- Hooks execute with the user's full permissions. The official Hooks docs explicitly warn that malicious hooks can delete data or expose credentials ([Cascade Hooks](https://docs.devin.ai/desktop/cascade/hooks)).
- Windsurf's pre-hook exit semantics allow any non-2 error to proceed. That fail-open choice is reasonable for availability but must not silently disable a mandatory security hook; our terminal receipt should surface `FAILED:hook-<event>` as the shared harness already specifies (`/local_disk0/codexwork/bundle/agents/harness/README.md:21-25`).

## 8. Customization surface teardown

### 8.1 Rules and `AGENTS.md`

Windsurf Rules have four activation modes:

- `always_on`: full content every message.
- `model_decision`: only description is always visible; full file is model-loaded on relevance.
- `glob`: loaded when matching files are read/edited.
- `manual`: loaded by `@rule-name`.

Workspace rules are individual Markdown files; root `AGENTS.md` is always-on and subdirectory `AGENTS.md` becomes an automatically scoped glob rule. Global, workspace, and read-only enterprise system scopes exist. Sources: [Memories & Rules](https://docs.devin.ai/desktop/cascade/memories) and [`AGENTS.md`](https://docs.devin.ai/desktop/cascade/agents-md).

This taxonomy is excellent documentation, but not a large capability gap. The owner already has many path-frontmatter rules and a cross-tool `AGENTS.md`. The useful port is organizational:

**Customization taxonomy manifest: CONFIG (settings/JSON only).** Require every customization entry to declare one of `behavioral rule | procedure skill | manual workflow | agent role | lifecycle hook`, plus scope, trigger, owner, evidence of use, and retirement condition. Generate the capability catalogue from this manifest. This is **likely (55-80%)** to reduce routing ambiguity because the current corpus shows a very large installed surface with sparse actual invocation; settle via before/after router precision and token cost.

### 8.2 Skills

Windsurf Skills use the Agent Skills format: a directory with `SKILL.md`, `name`, `description`, and supporting scripts/templates. Only name/description are exposed until model invocation or explicit `@mention`. Scopes are workspace, global, and enterprise system. Current docs also scan `.agents/skills`; optionally `.claude/skills` when Claude config reading is enabled ([Skills](https://docs.devin.ai/desktop/cascade/skills)). The changelog introduced Skills in January 2026 and cross-agent `.agents/skills` reading in February 2026.

This is parity with the owner's direction and validates the cross-tool `.agents/skills` standard. Do not create Windsurf-specific duplicates. **CONFIG (settings/JSON only):** make `.agents/skills` canonical, generate provider mirrors, and enforce progressive disclosure. The Windsurf docs explicitly demonstrate that cross-agent compatibility is possible without a new runtime.

### 8.3 Workflows

Workflows are Markdown step sequences invoked only through `/name`; they can call other workflows. They are trajectory-level prompt templates, not model-selected capabilities ([Workflows](https://docs.devin.ai/desktop/cascade/workflows)). This maps directly to our commands/manual skills.

Windsurf's distinction is worth preserving: model-selected procedure = Skill; user-selected runbook = Workflow; behavior = Rule. But recursive workflow calls can hide control flow and recreate orchestration complexity. Set a depth limit and require terminal outputs.

### 8.4 Hooks

Windsurf documents 12 events: pre/post read, pre/post write, pre/post command, pre/post MCP, pre-user-prompt, post-response, post-response-with-transcript, and post-worktree-setup. Each receives JSON with `trajectory_id`, `execution_id`, timestamp, model, and tool-specific information. Pre-hooks block with exit 2. Config merges cloud/system/user/workspace in a defined order. Hooks can be cross-platform through separate Bash and PowerShell commands. Sources: [Cascade Hooks](https://docs.devin.ai/desktop/cascade/hooks).

Our hook bus is broader: it includes SessionStart, Pre/PostToolUse, failure, ConfigChange, SubagentStart/Stop, TaskCreated, Stop, and more in `/local_disk0/codexwork/bundle/claude/settings.json:81-455`. The local hook README also documents PreCompact and SessionEnd (`/local_disk0/codexwork/bundle/claude/hooks/README.md:5-15`). Windsurf wins on normalized action-specific payloads and transcript correlation; ours wins on lifecycle breadth and provider-neutral dispatch.

**UNVERIFIED — hook receipt bridge. BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add one append-only normalized receipt per invocation: session hash, execution ID, event, matcher/module ID, start/end, exit, block/warn/inject, reason code, and transcript correlation. Do not log payload bodies by default. The recommendation inherits UNVERIFIED because D3's root cause is unresolved: the corpus saw zero hook fields even though hooks demonstrably fire (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:133-147`). Settling experiment: (1) prove a known-positive synthetic hook appears in the event ledger; (2) independently prove it appears or does not appear in transcript system-reminder blocks.

Do not copy Windsurf's example substring command blocker. The owner's D1/D1a/D1b proves prose/payload substring matching causes false blocks and even discards successful results (`INPUT-known-harness-defects.md:9-87`). Our fix must discriminate verb, semantic field, target path, and code/prose context.

## 9. Multi-agent teardown

### 9.1 Windsurf/Cascade layers

There are four distinct mechanisms:

1. **Simultaneous Cascades:** independent sessions; edits can race if they touch one file.
2. **Worktree mode:** a conversation starts in an isolated git worktree, can build/test independently, and can merge back. Worktrees live under `~/.windsurf/worktrees/<repo>`, cap at 20 per workspace, prune oldest on creation, and delete with the conversation ([Worktrees](https://docs.devin.ai/desktop/cascade/worktrees)).
3. **Arena Mode:** the same prompt runs independently through multiple models in separate worktrees; users can continue branches and choose a winner. Battle groups hide model names until voting, reducing brand bias ([Arena Mode](https://docs.devin.ai/desktop/cascade/arena)).
4. **Agent Command Center + Spaces:** a Kanban surface unifies local Cascade and cloud Devin sessions; a Space groups agents, PRs, files, and inherited context ([Agent Command Center](https://docs.devin.ai/desktop/agent-command-center), [Spaces](https://docs.devin.ai/desktop/spaces)).

Wave 13 introduced first-class parallel sessions, worktrees, side-by-side panes, and a dedicated terminal in December 2025; Wave 14 introduced Arena in January 2026 ([official changelog](https://docs.devin.ai/desktop/changelog)).

### 9.2 What we should port

**Bounded blind Arena: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Implement as a native skill/command, not a service:

1. Admission only when the decision is reversible but high-uncertainty and candidate diversity has value.
2. Create exactly two existing git worktrees from the same clean base.
3. Send the same typed task contract, acceptance checks, and evidence requirements to two native agents/models.
4. Strip model identity and normalize outputs into `{patch, test_receipts, assumptions, unresolved}`.
5. Run deterministic checks in each worktree.
6. Present blind packets to the owner; the existing `agent-as-judge` may annotate but never grant done.
7. Merge only the chosen patch through the existing review path; remove both worktrees with verified cleanup.

This is **likely (55-80%)** to improve decisions on ambiguous architectural work because it creates independent candidates and reduces model-name bias, but it doubles compute and can produce correlated failures. Evidence: Windsurf's isolated Arena mechanism and our existing cross-vendor advisory reviewer (`/local_disk0/codexwork/bundle/claude/agents/agent-as-judge.md:15-41`). Settle with 20 eligible tasks, measuring owner preference, post-merge defects, time, and cost against single-agent control.

**Bounded worktree lifecycle: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Port the cap, age-based cleanup, conversation/task ownership, and verified deletion receipt. This matters because lifecycle leakage is already a first-order owner problem, even though the pinned 1,293 orphaned directories are plugin directories rather than worktrees. The mechanism should never bulk-delete merely by suffix: the pinned ground truth says one orphan-marked directory was serving a live skill. Require two independent liveness signals before cleanup.

### 9.3 What not to port

**Agent Command Center clone: BUILD-LARGE (new daemon/service/runtime -- needs its own justification) — reject.** A faithful local/cloud Kanban, shared Spaces context, session cache, PR/file aggregation, and status synchronization is a second orchestration product. It violates the anti-overfit gate and does not address the measured error leaders. A generated read-only task digest on the existing Task/Agent bus is enough.

**Default Arena fan-out: CONFIG (settings/JSON only) — reject/disabled.** Multi-model execution for every task doubles cost and latency and invites selection overfit. Use only through explicit admission.

Windsurf is also weaker than ours in structured delegation. Its public Cascade docs describe parallel independent sessions, not typed parent/child handoffs, a no-raw-output contract, error-fingerprint pivots, or subagent lifecycle receipts. This absence is **UNVERIFIED — experiment: run a parent task that delegates two dependent subtasks and inspect whether handoffs preserve typed goal/evidence/failure state**. ## 12. Recommended experiments, with falsifiers

### E1 — MCP quarantine canary

Create one healthy and one deliberately dead stdio MCP. Confirm the detector finds the healthy known-positive. Then produce two mechanically independent dead signals: failed startup probe and a real tool call with the same connection fingerprint. Expected: dead server disappears from the next session catalogue; healthy remains; explicit re-probe can restore it. Falsifier: either a healthy server is quarantined or the dead tool remains model-visible.

### E2 — Permission shadow classification

For two weeks, log what the proposed native policy would `allow/ask/deny` without changing execution. Sample high-frequency Bash/PowerShell/MCP calls and all destructive/security hooks. Expected: hard blocks remain rare/high-precision, ordinary asks remain tolerable, no credential/destructive case auto-allows. Falsifier: material prompt fatigue or a dangerous false allow.

### E3 — Blind Arena value

Select 20 reversible, architecturally ambiguous tasks. Randomize single-agent versus two-candidate blind Arena. Use identical budgets and deterministic checks. Score owner preference, defects after merge, elapsed time, tokens, and conflict cleanup. Expected: enough defect/preference benefit to justify doubled cost on admitted tasks. Falsifier: no material quality gain or cleanup failures.

### E4 — Hook telemetry D3 settlement

Install no new telemetry first. Trigger a named synthetic hook with a unique nonce. Probe event ledger for module/event/nonce, then independently probe transcript system-reminder blocks. Validate each detector against a known-present non-hook record. Only if both sinks lack execution identity should the receipt bridge be built. Falsifier for “missing telemetry”: either sink already contains sufficient correlated receipts.

### E5 — Retrieval bake-off

Thirty queries across three large owner repositories: exact-symbol, behavioral, cross-module, and vague architectural. Compare native `rg`/Read + existing router against any candidate Fast Context service. Measure relevant-file recall@k, irrelevant injected bytes, latency, total tokens, and downstream patch pass rate. Falsifier for BUILD-LARGE: latency improves but correctness/context pollution does not.

### E6 — Memory shadow precision

Allow an automatic memory proposer to write only to a review queue, never active memory. Owner labels 100 proposals: durable/useful, transient, wrong, sensitive, superseded. Expected threshold before any automation: near-perfect safety and high precision. The recommendation to keep auto-memory disabled remains **almost certain (90-99%)** unless this held-out experiment shows both ≥95% precision and zero sensitive/wrong promotions; those numeric thresholds are design proposals, not vendor claims.

## 14. Bottom line for the next design unit

Evolve, do not replace. The owner already possesses the mechanisms Windsurf uses to look advanced; they are simply fragmented and, in several cases, unreliable. Copy Windsurf's **boundedness and product discipline**:

- expose fewer live tools;
- make dead integrations visibly dead and automatically absent from the next model context;
- restore a graded permission posture;
- isolate the rare parallel comparison in worktrees and clean it up;
- correlate hooks with executions and transcripts;
- classify customization primitives by role and trigger.

The likely winning harness is the owner's current provider-neutral hook/skill/agent bus made smaller, measurable, and admission-controlled—not a new platform beside it. That outcome is **very likely (80-90%)**, grounded in the direct parity evidence above and the corpus showing reliability failures in existing primitives rather than absence of primitives.
