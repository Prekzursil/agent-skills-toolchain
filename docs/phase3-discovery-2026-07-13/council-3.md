## Council voice — MAINTAINABILITY lens (doc hygiene · anti-drift · superseded-detection · future-proofing)

### Framing thesis (read first)
The debt this program is fighting was **not caused by a missing tool. It was caused by a missing lifecycle convention and a missing single index.** The harness ALREADY has 68 hooks, an event ledger, and a basic-memory vault with working supersede chains — and it *still* accumulated 606 loose md files, ~10 un-marked superseded root plans, 3 stale snapshot trees, and a self-contradicting `MEM0-PILOT-PLAN`. So the naive "add 7 more shadow-mode enforcement hooks + adopt chezmoi and it self-heals" answer is **building more of the exact machinery that already failed to prevent this.** From my lens the load-bearing fixes are: (1) collapse to ONE source-of-truth root, (2) a one-time librarian sweep that actually tombstones the dead docs, (3) a cheap authoring-time convention (frontmatter status + near-dup nudge + one index) — and only THEN a thin runtime gate to stop *new* accumulation. Conventions + one index + a periodic human sweep beat N runtime gates for doc hygiene.

A drift check that may never fire is theater. Make it a SessionStart + scheduled `diff(live user-scope, canonical)` that *actually runs*, and widen its baseline to `enabledPlugins`/`plugin:local-mcp-bridge` (the layer codacy/deepsource actually resurfaced through — the drop operated on the wrong layer).

**Thread 4 — cleanup-after-work.** `artifact_hygiene` Stop hook that reuses the *existing mutation ledger* (not a full-tree scan) to flag session-created untracked-and-not-ignored-and-not-scratchpad files is elegant and near-free — endorse. **Keep advisory, never auto-delete** — the `rules/common/windows-shell.md` `New-Item -Force`/`rm -rf`/MSYS-truncation footguns make auto-deletion a §9 hazard. But note: a hook stops *future* mess; it does nothing for the current 25 momentstudio worktree copies + 3 snapshot trees + D: mirror clones. **Thread 5 — stale-branch reconciliation.** `git merge-base --is-ancestor` classification (handles squash/rebase merges — `git branch --merged` does not) is the correct SOTA primitive. Advisory SessionStart reminder, dedup'd, never auto-`-D`. **But from my lens this is LOW priority** — stale branches are clutter, not truth-corruption; they don't make a fresh session re-walk a retired decision the way a loose superseded *plan* does. **Cut the elaborate tooling:** a one-time triage pass (salvage the real unpushed work first — battlecats +142/+29, ToolUniverse +34, Reframe uncommitted sidecar features, insta-mcp 2FA) plus the thin advisory reminder is sufficient. Do not build a branch-classification framework.

**Thread 6 — doc-reconciliation enforcement.** This is my core lens and where I most disagree with the obvious build. **The heavy `doc_drift` AST-fingerprint binding hook solves the WRONG half of the problem.** It binds docs to *code symbols* — but the actual debt here is plan/audit/recommendation docs that bind to nothing and supersede *each other* (SOTA-HARNESS-RECS v1→v2→REMEDIATION→…). doc_drift would never fire on any of them. Plus it over-fires (the `_stripped_signature` tree-sitter stand-in) and must ship SHADOW indefinitely to prove precision. **Ship instead:** (a) `kb_supersede` — near-dup detection via the existing `recall_index.py` at note/MEMORY authoring time, injecting the AGENTS.md §8 `superseded_by:`/`valid_as_of:` reminder (this is genuinely SOTA and cheap); (b) a **frontmatter-status convention** — every analysis/plan/audit doc carries `status: active|superseded|archived`, `superseded_by:`, `valid_as_of:`, enforced by a trivial `Write(*.md)` lint. That's the ADR immutable-supersede discipline applied to plan docs. **Honesty caveat:** neither detects *semantic contradiction* (MEM0-PILOT vs the later NO-GO) — contradiction-detection is hard; don't over-promise it. That one is caught by the human sweep, not a hook.

**Thread 7 — scattered-harness-doc reconciliation. THIS is where the program earns its keep, and it is a one-time librarian job, not a hook.** Concrete: (a) declare canonical roots — basic-memory vault = the decision ledger (it already has the healthy supersede chains), repo `docs/` = design/plan, `rules/` = contract; (b) for each of the ~10 loose root plans, the Area-6 design-research corpus (superseded by shipped skills), and the Area-2 workspace-arch docs, apply a **tombstone**: move to a dated `_archive/` with a one-line status marker, OR fold into basic-memory with a supersede link — do not leave them loose competing as apparent guidance; (c) tombstone `MEM0-PILOT-PLAN` immediately (actively contradicted). **Do not let this be replaced by "a hook will self-heal it"** — the existing 606-file mess must be manually retired; hooks only stop new accumulation. If the program ships only ONE thing on the doc side, ship this sweep.

**Thread 8 — change-must-be-documented+committed.** `uncommitted_change` + `doc_required` Stop hooks (advisory, per §6 inject-not-block) are fine as a nicety. **My maintainability point:** the CI `no-runtime-junk.yml` guard "only runs on push, and the branch is UNPUSHED — so it has never run." Enforcement that lives only in unpushed CI is fiction. Put the hard doc-required + uncommitted-check in a **pre-commit hook** (local, fires every commit) — that is the real boundary. Also: the `basic_memory_nudge` (modules) requires `canonical_tree` stamping (ledger) — **deploy them atomically or the nudge is a silent dead gate**, which is the exact current failure mode.

**Thread 9 — harness-works-perfectly verification. The single most important finding in the whole program lives here** and it is a maintainability finding: task-8 is *committed but not deployed*, and `install.py --check` structurally cannot see it because it only reconciles `settings.json` hooks, never the live `~/.agents/harness` **tree** vs `ci/harness`. A verification layer that can't detect a repo-vs-live tree divergence is worthless — it is silently failing right now. **Build ONE thing here: a live↔repo tree-parity check** (hash the deployed harness tree against `ci/harness`, report drift), wired to SessionStart + a scheduled cron (NOT a may-never-fire event). Coverage≠integration: also assert each gate is DEPLOYED and FIRING, not merely test-green. This is the anti-drift keystone — it would have caught the current three-way HEAD≠working-tree≠live split.

### Where I disagree with the obvious/naive approach (summary)
1. **Shadow-mode-forever gates do not prevent drift.** 68 existing hooks + a ledger already failed. Seven more observe-only gates that "never block, never nag" will mostly get sunset by the GATE_CONTRACTS anti-zombie scorer for never firing usefully. Ship the 2-3 cheap ones (`kb_supersede`, `artifact_hygiene`, tree-parity) and put the real teeth in **pre-commit**, not more interactive shadow injects.
2. **chezmoi is right SOTA, wrong time.** Adopting a dotfile manager NOW introduces a *fourth* source-of-truth root (chezmoi repo) while `ast-harness-reconcile` + `agent-skills-toolchain` + live `~/.agents` are still unreconciled to ONE. You cannot end drift by adding a truth root mid-consolidation. And chezmoi solves *config* portability — it does nothing for the *doc sprawl* that is 80% of the actual debt. **Defer chezmoi to a Phase-4 migration** once SSoT is provably singular; use plain git + the idempotent `install.py --deploy` render you already have.
3. **doc_drift (code↔doc AST binding) solves the wrong half** (see Thread 6) — the debt is doc-supersedes-doc, not doc-lags-code.
4. **The one-time sweep is not optional and not automatable.** Every "the hook will handle it" framing quietly defers the actual retirement of the 606-file mess.

### Top maintainability risks (ranked)
1. **Three→four SSoT roots.** `ast-harness-reconcile` + `agent-skills-toolchain` + live `~/.agents` + (proposed chezmoi). Every additional root is a drift multiplier. Collapse to ONE before adding any tooling — this is a governance decision, not a tooling one.
2. **The SSoT repo ships stale governance.** `ast-harness-reconcile/CLAUDE.md` still cites retired AgentBridge/`get_budget` as the live mechanism. If the repo-meant-to-end-drift carries the single most out-of-date claim, the "repo is truth" premise is poisoned on day one. **Rewrite before push — non-negotiable, and blast-radius-check (§9b) for other AgentBridge references in the repo.**
3. **Lane-coupling silent-dead gates.** `basic_memory_nudge`→ledger `canonical_tree` stamp; deploy half and the gate is inert *and undetected* — the current failure, re-created.
4. **Sweep deferral.** The librarian sweep (Thread 7) gets postponed behind hook-building; the mess persists and hooks only fence new mess.
5. **Verification blind to its own target.** If Thread 9's parity check isn't built, the whole program can ship "green" while live sessions run the pre-task-8 tree — exactly today's state.

### Cut as over-engineering (for THIS program's scope)
- **chezmoi adoption** → defer to Phase-4 post-consolidation.
- **doc_drift AST-fingerprint binding hook** → defer; ship `kb_supersede` + frontmatter-status lint instead.
- **Elaborate stale-branch classification tooling** → one-time triage script + advisory reminder only.
- **MCP HTTP-gateway migration** (from the concurrency research) → genuinely good for RAM/N×M process explosion, but it's a *separate program*; folding it in bloats scope and couples doc-hygiene delivery to a per-server migration. Keep lean-catalog + `.mcp-disabled-defaults.json` masking; defer the gateway.
- **SessionEnd scratchpad auto-sweep** → §9 rm-rf/New-Item footgun; advisory-only or cut.

### Future-proofing (why this won't decay again)
Institute three durable, low-cost anti-decay controls, in priority order: (1) **basic-memory vault is THE decision ledger** — on-disk docs are either current-and-registered or archived-with-tombstone, nothing loose; (2) **frontmatter-status convention** on every plan/audit/analysis doc, lint-enforced at write time; (3) **one reconciliation ritual on an existing cadence** (fold it into the recurring gem-hunt sweep) that runs the tree-parity check, the merged-branch triage, and a stale-doc scan, and tombstones what it finds. That is convention + one index + periodic human sweep — the combination that actually holds, versus a pile of shadow gates that log into the void.
