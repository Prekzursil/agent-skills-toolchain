## D. Instruction files, rules and context size: nuanced evidence
- ETH Zurich SRI Lab + LogicStar, "Evaluating AGENTS.md" (ICLR 2026 MemAgents workshop, Feb 2026): context files "do not generally improve task success rates, while increasing inference cost by over 20% on average" (generated and developer-written; multiple agents/models). Instructions ARE followed well -> stale instructions are followed too.
- Factorial study, 1,650 Claude Code sessions (via devventa.com 2026-07-27): no detectable adherence effect from file size/position/architecture/contradictions; adherence decays WITHIN a session (~5.6% lower odds per additional function generated).
- IFScale (arXiv:2507.11538): 20 models; best ~68% at 500 instructions; claude-sonnet-4 linear decay; bias toward earlier instructions. Practitioner "instruction budget" ~150-200 instructions (modernweblabs 2026-07-05); Claude Code's own system prompt already carries ~50 instructions (jyoung.dev 2026-05-18).
- Anthropic docs (code.claude.com/docs/en/best-practices): "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"; per-line test "Would removing this cause Claude to make mistakes? If not, cut it."; "If Claude already does something correctly without the instruction, delete it or convert it to a hook."; /doctor proposes cuts; "Use hooks for actions that must happen every time with zero exceptions" (hooks deterministic, CLAUDE.md advisory).
- Anthropic context engineering (2025-09-29): "smallest possible set of high-signal tokens"; context rot; "minimal viable set of tools"; progressive disclosure.
- Chroma context-rot study (2025): all 18 models degrade as input grows.
- Reddit r/ClaudeAI (~2 months ago): Anthropic cut ~80% of Claude Code's system prompt for Claude 5 models; /doctor audits rules written for models that no longer exist; user: "too many rules and infrastructure collapsing under their own weight ... had Claude rip it all out".
- MindStudio 2026: config written to correct older-model behaviors interferes after upgrades; re-test config at every major model release.
- GitHub anthropics/claude-code#80873: adherence decays mid-session (rules "fade" after 5-10 turns) even when short; #85477 request for rules-governance diagnostics (instruction budget, duplication/conflict detection); #86359 compaction summary overrides CLAUDE.md; #82184 enforcement hooks self-neutralize, auto-memory outranks project instructions; #48680 marketplace MCP server instructions inject 30-55% of a fresh context regardless of Tool Search.

## E2. Primary sources confirmed (2026-09-24)
- arXiv:2605.24050 Song & Wei (Databricks), "More Skills, Worse Agents? Skill Shadowing Degrades Performance When Expanding Skill Libraries" (Agent Skills '26 workshop). SkillsBench, Haiku 4.5 + Sonnet 4.6, libraries 52/102/202, 2,545 trajectories. Pass rate drops up to 21 points vs oracle-only; skill shadowing (wrong selection on name+description alone) accounts for up to 68% and is the only statistically significant effect; oracle-only invocations fall 88% -> 52.6%; skill abandonment rises 12% -> 38.5%; a distractor "video-frame-extraction" beat the correct skill 26/26 times. Haiku degrades already at 52 skills. Selection happens BEFORE the body loads. Mitigations: retrieval pre-filtering, description disambiguation, learned routing. Limits: 2 models, one provider, 202 max. (The audited repo exposes 425 skill descriptions.)
- Google Research / DeepMind (Kim et al., Dec 2025; InfoQ 2026-02; techstrong.ai): 180 configurations, 5 architectures, 3 LLM families, 4 benchmarks. Mean multi-agent improvement -3.5%; independent agents amplify errors 17.2x, centralized coordination 4.4x; sequential/constraint tasks degrade 39-70% under every multi-agent variant; centralized coordination +80.9% on parallelizable financial reasoning; gains plateau beyond ~4 agents; predictive model picks the right architecture ~87% of the time.
- arXiv:2602.11988 Gloaguen, Mundler, Muller, Raychev, Vechev (ETH SRI Lab + LogicStar), "Evaluating AGENTS.md" (MemAgents @ ICLR 2026, oral, runner-up best paper). 4 agents (Claude Code, Codex GPT-5.2, GPT-5.1 mini, Qwen Code), SWE-bench Lite + AGENTbench (138 tasks). LLM-generated context files: -0.5% / -2% success, +20% / +23% cost; developer-written: +4% avg (no gain for Claude Code), up to +19% cost; instructions are followed and cause more exploration/testing; context files "do not function as effective repository overviews"; recommendation: "human-written context files should describe only minimal requirements (e.g., specific tooling)".

## G. Refutation sweep (queries designed to overturn my own conclusions), 2026-09-24

G1. "Prune skills to a small core" -> PARTLY REFUTED, revised to "expose a small core, route the rest".
- SkillRouter (arXiv:2603.22455): ~80K skills; name+description-only routing loses 37-44 pp vs body-aware; compact 1.2B retrieve-and-rerank reaches 74.0% Hit@1; end-to-end across four coding agents inside Claude Code, routing gains transfer to task success (+1.78 pp top-1, +2.33 pp top-10; +3.22 pp for Sonnet/Opus 4.6); top-1 vs top-10 shortlist similar (~27.6-27.8% success) => diminishing returns beyond a quality threshold.
- UCSB Skill-Usage (arXiv:2604.04323): 34K real skills; Claude Opus 4.6 on SkillsBench: curated skills 51.2%, no skills 35.4%, retrieved (curated present) 40.1%, retrieved + query-specific refinement 48.2%; retrieved with curated skills removed 38.4%; best retrieval Recall@5 only 65.5%; Terminal-Bench 2.0 retrieval+refinement 57.7% -> 65.5%.
- "When Single-Agent with Skills Replace Multi-Agent" (OpenReview kym0qvjrvm): flat selection accuracy >90% at <=20 skills, ~20% at 200; fitted capacity threshold 83.5 (GPT-4o) to 91.8 (GPT-4o-mini); one competitor skill costs 7-30%, two cost 17-63%; hierarchical routing recovers +37-40 pp (mini) / +9-10 pp (4o) at >=60 skills, stable to 120. Descriptor uniqueness matters as much as count.
- Klymentiev (2026-05-23) semantic router over 686 skills: top-5 cluster 87.5%, strict top-1 62.5%; catalog of 4,556 skills = ~228K tokens; "with under 30 skills there is no point; past 100 the math matters".
- arXiv:2608.06196 (690 skills): hybrid ranker hit@5 73.5% on non-echo queries, 62.8% when users describe a symptom; ~25% unserved; graph structure adds nothing; author-written queries overstate hit@5 by up to 44 points.
=> Routing is necessary at this repo's scale and recovers a lot, but it is bounded (~65-87% recall) and the repo's three routers are unwired and unmeasured. Core-set exposure + router + description disambiguation + measurement.

G2. "Orchestration is the bottleneck / LangGraph is not the winner" -> SCOPED, not reversed.
- LangGraph beats CrewAI/AutoGen on structured multi-step pipeline tasks: 107 data-engineering tasks, GPT-4o: LangGraph 94.4% vs CrewAI 71.0% vs AutoGen 64.5% (dev.to, single author, 2026-09-22); JATIR 80-task benchmark: LangGraph 81.6% overall vs AutoGen 81.3% vs CrewAI 79.5% (near tie; LangGraph best fault tolerance, AutoGen best code gen 88.1%).
- arXiv:2607.19297 practitioner guide: "LangGraph is positioned by workflow-complexity fit, not as a universal default: simpler ReAct-style or plain SDK loops may be better for basic tool use".
- Unsourced marketing numbers seen (axiomlogica "70% fewer catastrophic loops", "94%"; johal.in "22% higher success", contains an anachronistic citation) - discount.
=> Correct statement: LangGraph is a reasonable choice for pre-definable, branching business workflows with durable state and human gates. It is not what any production coding harness uses (2609.00006) and it lost to in-context procedures on the same model (2604.27891). The transcript's error is claiming it as the winner for harness engineering / coding agents.

G3. "Multi-agent fleets hurt" -> SCOPED: fleets work under strict conditions.
- Anthropic "Building a C compiler with a team of parallel Claudes": 16 agents, ~2,000 Claude Code sessions, ~$20K, 100K-line Rust C compiler that builds Linux 6.9 on x86/ARM/RISC-V. Conditions: independent tasks (hundreds of failing tests), git-mediated task locks, "the task verifier is nearly perfect, otherwise Claude will solve the wrong problem", CI enforcement added when agents began breaking existing features, GCC oracle to decompose the kernel task when all agents converged on the same bug; specialist agents for de-duplication, performance, code quality, documentation.
- OpenAI harness-engineering post: ~1M lines, ~1,500 PRs, 3 -> 7 engineers, 3.5 PRs/engineer/day in 5 months; mechanisms: ~100-line AGENTS.md as a table of contents; docs/ as the map; mechanical cross-link consistency via linters and CI; architectural boundary linters; agent-to-agent review loop until reviewers are satisfied; periodic garbage-collection agents that fix doc inconsistencies and entropy; app bootable per worktree; logs/metrics legible to the agent. Limits noted: greenfield; scale threshold.
- OpenAI "The Shift to Agentic AI: Evidence from Codex" (arXiv:2606.26959): 28.6% of OpenAI users manage >=5 concurrent agents; 26.6% of users use skills; median OpenAI employee 2.5 h/day of agent turns; 99th percentile ~71 h/day.
- arXiv:2609.17598 (37,623 PRs): agent PRs not a uniform liability; Codex PRs reverted 6.1% vs humans 11.5%; Claude Code PRs lowest churn per changed line.
- Anthropic "How Claude Code is used in practice" (2026-06-16, ~400K sessions): verified success 15% (novice) vs 28-33% (intermediate+); novices abandon 19% vs 5-7%; domain expertise, not coding skill, predicts success.
=> Fleets converge only with near-perfect verifiers, one lineage, CI gates and garbage collection. The audited P2 program has parallelism without any of these (task success NOT-CHECKED; three lineages; no GC).
