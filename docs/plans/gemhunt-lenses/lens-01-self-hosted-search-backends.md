# Gem-hunt lens report — self-hosted, keyless Tavily/Firecrawl-compatible search+extract backends (2025–2026), beyond TrailSearch / OrioSearch / fastCRW

Research window: 2026-09-02 02:00–05:30 UTC. Read-only; scratch under `/tmp` only. All GitHub numbers are live API reads on 2026-09-02 (post-cutoff, primary source). RAM numbers marked **measured** were run by me on this Linux box (Python 3.12, x86-64); everything else is self-reported by the project and marked as such.

## 0. Bottom line

- **Nothing found beats TrailSearch for the Tavily slot.** TrailSearch is the only candidate with native `/tavily/search` + `/tavily/extract` routes *and* a clean license *and* trafilatura/crawl4ai-grade extraction. Every other Tavily-shaped candidate is either AGPL (Searcharvester), unlicensed (OrioSearch-class: Draco, searxng-docker-tavily-adapter, UltraSearch, SearchMind-API, rootfetch, agent-web-stack), keyed (tavily-hikari, kagi-tavily-bridge), or far weaker at extraction (WebSearchFree). Keep TrailSearch as `native`.
- **Two concrete upgrades are real:**
  1. **trafilatura-scrape** (MIT, stdlib HTTP server, Firecrawl v1+v2 shape, reuses your SearXNG, **60 MB idle measured**) can take over fastCRW's *emulated Firecrawl fallback* slot with a clean license and no Docker on Windows (pure Python + wheels). Trade: no JS rendering (fastCRW has none in the minimal profile either).
  2. **WebSearchFree** (MIT, 1 MB static binary, **9.7 MB idle measured**, Tavily-shaped `/search` + `/extract`, native Windows .exe) is a credible *always-on standby* for Tavily-shaped search when TrailSearch's ~300 MB is not affordable. Extraction is plain-text and basic, so use it for search only.
- **One JS-render candidate worth a trial off-box:** AginxBrowser (Apache-2.0, V8 + own renderer, no Chromium, Firecrawl `/v1/scrape`, ~227 MB self-reported, 73 MiB image) — but Linux/macOS only, so on the Windows box it is Docker/WSL2, and its rendering engine is unproven.
- **Correction to a stack assumption:** fastCRW v0.33.0 (2026-09-02) *does* ship `crw-win32-x64.zip`, `crw-server-win32-x64.zip` and `crw-mcp-win32-x64.zip` (README still says "macOS and Linux"); releases carry sigstore-signed `SHA256SUMS`. Its own `COMPATIBILITY.md` rates Tavily parity as **"adapter required"** (no `/tavily/*`, no `search_depth`, extract is single-URL). So fastCRW can run natively on Windows, but it is not a Tavily-shape peer of TrailSearch.
- Ranking rule applied: (clean license) × (low RAM) × (Tavily/Firecrawl-shaped). Rank order: trafilatura-scrape → WebSearchFree → Markdown Crawler (watch) → AginxBrowser (trial off-box) → everything else BORROW/SKIP.

## 2. Finds — gem-hunt cards (ranked)

### Find 1 — trafilatura-scrape (MIT Firecrawl-shaped shim over your SearXNG)
- **What:** ~30 KB of Python: stdlib `ThreadingHTTPServer` + `requests` + `trafilatura` + `pypdf`. Speaks Firecrawl v2 (`/v2/scrape`, `/v2/batch/scrape` up to 50 URLs, `/v2/map` sitemap+links, `/v2/parse` PDF, `/v2/search` web/news with optional inline scrape) and keeps `/v1/scrape`, `/v1/search`. Search is a thin proxy to a SearXNG instance (`SEARXNG_URL`); returns 503 when unset. Unsupported formats are reported in `data.warning` rather than faked.
- **Why this user:** it is the one Firecrawl-class backend that is MIT, keyless, reuses `:8890`, has no Redis/Postgres/browser, and installs natively on Windows (pure-Python deps with wheels). fastCRW is AGPL; everything else Firecrawl-shaped is heavier or unlicensed. Idle cost is a tenth of TrailSearch.
- **How to adopt:** `pip install git+https://github.com/DaRacci/trafilatura_scrape` (PyPI claim in README is **false** — `pypi.org/pypi/trafilatura-scrape/json` returns nothing); run `SEARXNG_URL=http://127.0.0.1:8890 trafilatura-scrape` on `127.0.0.1:8766`; front it with the hub's existing Firecrawl adapter (`/v1/scrape`). Wrap calls with the hub's timeout: when SearXNG is unreachable the handler thread dies with a traceback and the client gets no HTTP response (observed). Also observed: title metadata mojibake (`http.server â HTTP servers &#8212;` — bad decode + unescaped entity); markdown body was fine.
- **Source:** https://github.com/DaRacci/trafilatura_scrape · canonical https://codeberg.org/racci/trafilatura_scrape
- **License:** MIT — `LICENSE` file present in tree; GitHub API `license.spdx_id = MIT`; `pyproject.toml` `license = { text = "MIT" }`.
- **Value × effort:** H × L. **Novelty:** high (nothing MIT + Firecrawl-shaped + SearXNG-reusing exists on the branch). **Verb:** ADOPT (vendor it — 30 KB, 8 test files; single-author risk is mitigated by size). **Confidence:** high on measurements (I ran it); medium on maintenance (0★, 26 commits, but active on 2026-09-01).

### Find 2 — WebSearchFree (1 MB Tavily-shaped keyless search daemon)
- **What:** C++ single binary (`cpp-httplib` + `nlohmann/json` + libcurl). `POST /search` fans out to DuckDuckGo HTML, Brave HTML, Wikipedia opensearch, DDG news, optional SearXNG (`WSF_SEARX_URL`), dedupes and scores, returns Tavily-shaped JSON incl. extractive (non-LLM) `answer`, per-engine `ok/error/hit_count`, `warnings`, `response_time`. `POST /extract` fetches URLs and returns `results[].raw_content` (plain text). `GET /health`, `/openapi.json`, embedded UI; MCP via a stdlib Python shim (`web_search`, `web_extract`); robots.txt module present.
- **Why this user:** the only Tavily-shaped candidate that is MIT + native Windows + ~10 MB. It is the right shape for an *always-on* standby lane (or for laptops/VMs where TrailSearch's ~300 MB is unaffordable). Honest non-goals in its README match the hub's truthful-degradation stance (no JS, extractive answer, upstream HTML fragility).
- **How to adopt:** `irm …/scripts/install.ps1 | iex` or drop `wsf-windows-amd64.exe` (0.9 MB); `wsf serve --port 8080 --searx-url http://127.0.0.1:8890`. If the hub adapter calls unprefixed `/search`+`/extract` with Tavily bodies it can point at it unchanged; if it calls `/tavily/*`, add a 2-line route alias in the adapter. Register capability as `emulated` for extract (plain text, no markdown, no `failed_results`) and `probed` for search.
- **Source:** https://github.com/drmikecrypto/WebSearchFree · image `ghcr.io/drmikecrypto/websearchfree:latest`
- **License:** MIT — README links `LICENSE`; API spdx MIT.
- **Value × effort:** M × L. **Novelty:** high for RAM class. **Verb:** ADOPT-as-standby after trial. **Confidence:** high on RAM/shape (measured); **low on durability** — 6 commits, 5★, created 2026-08-03; Brave returned HTTP 429 on my first query (engine scrapers will break).

### Find 3 — Markdown Crawler / microcrawl (Rust Firecrawl v2 + MCP, watch-list)
- **What:** axum server; `/v2/scrape|map|crawl|search` + unversioned aliases; Streamable-HTTP MCP at `/mcp` and `/v2/mcp` with five `firecrawl_*` tools; `renderMode=auto|http|browser`; Lightpanda started only for sparse SPA shells or 403/429/503; search providers SearXNG (recommended), Exa hosted MCP (claimed keyless-limited default), Brave, Google CSE; SSRF defence, size/timeout/redirect/concurrency caps. `COMPATIBILITY.md` lists what is *not* implemented (PDF, LLM extract, screenshots, batch jobs, cache, proxies).
- **Why this user:** exactly the anti-overfit shape — one small process, no queue/DB, rides MCP, reuses SearXNG, self-reported 15–32 MiB RSS and 7.4 MiB binary. Verified SDK interop claims (`firecrawl-py 4.32.1`, `@mendable/firecrawl-js`).
- **How to adopt:** not yet — 2 commits, 0 releases, 0★; build from source. Put on the OSSInsight watch list; adopt only if it gets a release cadence. JS tier is AGPL Lightpanda and Linux-only → OVH.
- **Source:** https://github.com/Atipico1/microcrawl · **License:** MIT core (`LICENSE` in tree; API MIT); Lightpanda AGPL disclosed in `THIRD_PARTY_NOTICES.md`.
- **Value × effort:** H × M (build + maturity risk). **Novelty:** high. **Verb:** DEFER (BORROW the SPA-shell gating). **Confidence:** medium (numbers self-reported in `BENCHMARK.md`; not run).

### Find 4 — AginxBrowser (JS rendering without Chromium)
- **What:** single Rust binary embedding V8 + a custom CSS/layout/paint engine ("diting", Blitz/Stylo/Taffy lineage). HTTP API + native MCP (17 tools) + CDP bridge; Firecrawl-compatible `/v1/scrape`; multi-engine `/search` (Baidu/Bing/Sogou/WeChat/Google/DDG, Bing News, StackOverflow/GitHub, npm/PyPI, arXiv, images); TLS handshake replication (Chrome145/Firefox133/Safari/Edge via BoringSSL); stateful sessions; SQLite FTS5 fetch/search cache; screenshots (opt-in feature); streaming downloads with SHA-256.
- **Why this user:** the extract lane has no JS tier on the box (TrailSearch minimal profile drops Browserless/Reader; fastCRW self-host has none). This is the only renderer found that claims to fit under ~250 MB, and it has real TLS fingerprints, which SearXNG→httpx lacks.
- **How to adopt:** `docker run -p 8089:8089 yinnho/aginxbrowser:latest` (73 MiB) on OVH or WSL2; front `/v1/scrape` through the Firecrawl adapter as a `probed` JS tier behind trafilatura. No Windows asset in any of 7 releases (v0.2.6 = darwin + linux musl/gnu).
- **Source:** https://github.com/yinnho/aginxbrowser · **License:** Apache-2.0 (`LICENSE` badge/file; API Apache-2.0).
- **Value × effort:** M × M. **Novelty:** high. **Verb:** TRIAL (off-box). **Confidence:** low-medium — 12★, novel engine, bench is the author's (20 pages, 2026-08-28); 227 MB is process RSS under load, idle not stated.

## 3. Techniques worth borrowing (mapped to the hub's capability lattice)

| Technique | From | What it is | Lattice mapping |
|---|---|---|---|
| **Per-domain capability database** | TadMSTR/searxng-mcp | Valkey record per hostname (90-day TTL): `tier_stats_30d.{tier}.{attempts,ok,fail,last_fail_reason}`; before a fetch, skip any tier with <30% success over ≥10 attempts; cold-start keeps default cascade; `domain_stats` MCP tool exposes it; snapshot/restore CLIs so learning survives cache flushes | Makes `probed` *per-domain and time-decayed* instead of per-provider; a tier that keeps failing for a host degrades to `absent` for that host without a global flip |
| **`llms-full.txt` fast path** | TadMSTR/searxng-mcp | For whitelisted doc domains, try `<origin>/llms-full.txt` first and slice the section for the requested URL before any fetch tier | A new `native` extraction tier for docs sites that costs one GET and zero rendering |
| **JSON-LD Article / og:title fast path** | TadMSTR/searxng-mcp; Draco (`__NEXT_DATA__`, JSON-LD, `window.__NUXT__`) | Prefer Schema.org `articleBody/headline` or framework-embedded state over scraped chrome | `native`-grade structured content when present; record presence in the domain DB (`capabilities.json_ld_article.sampled/present`) |

| **Site-specific handlers before generic extraction** | Kindly (StackExchange API, GitHub Issues/Discussions, Wikipedia, arXiv), webclaw (Reddit, YouTube), GroktoCrawl (GitHub, YouTube, Bluesky, Substack, Gutenberg) | Use the source's API/structured endpoint when the URL matches; fall back to generic | `native` for those hosts; the hub already has scholarly-access/huggingface — same pattern for GitHub/StackExchange |
