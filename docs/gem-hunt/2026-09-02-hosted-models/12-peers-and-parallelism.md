## 2. agent-mail as the peer bus: registration, contact gating, leases

**Upstream state, checked 2026-09-02.**

- **[FACT, A, corroborated]** `Dicklesworthstone/mcp_agent_mail` describes itself as "Asynchronous coordination layer for AI coding agents: identities, inboxes, searchable threads, and advisory file leases over FastMCP + Git + SQLite"; supported agents "Claude Code, Codex CLI, Gemini CLI, GitHub Copilot CLI, any MCP client". Source: <https://github.com/Dicklesworthstone/mcp_agent_mail> (README), corroborated by `repo:skills/multi-ai-mingle/MCP_AGENT_MAIL.md` (author recorded 2021 stars, last push 2026-06-27, on 2026-07-11).
- **[FACT, A, corroborated by local doctrine]** The identity model is per-*program*: `register_agent(project_key, program, model, name?)`. `program` is free text (the estate uses the role there), `model` is free text. Nothing in the tool surface restricts `program` to a CLI - a value such as `program="hosted-model-adapter", model="Qwen3-Coder-480B@hf-router"` is legal. Source: `repo:skills/multi-ai-mingle/MCP_AGENT_MAIL.md` tool surface; README as above.
- **[FACT, A, local]** First contact is gated: `request_contact(from_agent, to_agent, registration_token)` then `respond_contact(to_agent, from_agent, accept=true, registration_token)`. Source: `repo:skills/multi-ai-mingle/SKILL.md` ("Real mcp_agent_mail API sequence, VERIFIED 2026-07-11").
- **[FACT, A, local]** Leases are **advisory**: `file_reservation_paths(... exclusive?, ttl_seconds?, reason?)`; nothing in the OS enforces them; `force_release_file_reservation` exists for stale holders. Source: `repo:skills/multi-ai-mingle/MCP_AGENT_MAIL.md`.
- **[FACT, B, UNVERIFIED this run]** A Rust rewrite `mcp_agent_mail_rust` (34 tools, TUI console) exists and was active on 2026-07-11; the estate decided to stay on the Python original. Source: `repo:skills/multi-ai-mingle/MCP_AGENT_MAIL.md` (recorded ~100 stars, pushed 2026-07-11). Not re-checked upstream in this run.

**[INFERENCE] What a hosted model needs to be a peer on this bus.** The bus is agent-agnostic by construction; the *only* thing missing for a hosted model is a long-lived local process that (1) holds one registration (codename + token) per hosted persona, (2) polls `fetch_inbox` (there is no push; `crcp/bus.py` polls), (3) turns each inbox message into a chat turn on the runtime (`/v1/chat/completions` with the profile's `tools`), (4) executes allowlisted tool calls locally, (5) replies with `reply_message` and takes/releases leases around any file it writes. That process is the adapter of section 6. It is a **client** of :8812 (owned port, unchanged), so it violates no lock.

**[INFERENCE] Contact gating is a feature, not friction, for hosted peers.** A hosted model that runs 24/7 on a Space could spam the inbox; the `request_contact`/`respond_contact` gate means the human's Claude or Codex session explicitly admits each hosted persona once. Keep it; do not auto-accept in the adapter.

**[RECOMMENDATION]** Register hosted personas with `program=<persona>` (e.g. `redteam-reporter`, `lit-learner`, `coder-worker`) and `model=<checkpoint@environment>` so `list_agents`/`whois` show at a glance which weights are behind a codename. Persist `(codename, token)` next to `.agents/local.json` by *name only* (the token is a secret; never in the repo), reusing `crcp/bus.py`'s sqlite read-only recovery when the tool result omits the token.

## 3. Codex `mcp-server` fan-out - and the fact that changes this section

**The fan-out rail's transport was deprecated on 2026-08-24.**

- **[FACT, A, corroborated]** OpenAI's Codex docs page "Running Codex as an MCP server" now opens: "`codex mcp-server` is deprecated. Use the Codex app server instead. To call Codex from Claude Code, use the Codex plugin for Claude Code, which uses the app server. This page documents the deprecated command for existing integrations." The deprecated server still lists two tools, `codex` (start; params `prompt`, `approval-policy` ∈ {`untrusted`,`on-request`,`never`}, `base-instructions`, `compact-prompt`, `config`, `cwd`, `developer-instructions`, `model`, `sandbox` ∈ {`read-only`,`workspace-write`,`danger-full-access`}) and `codex-reply` (`prompt`, `threadId`; `conversationId` deprecated alias). Sources: <https://learn.chatgpt.com/docs/mcp-server.md> (official mirror of developers.openai.com), <https://developers.openai.com/codex/cli/reference.md> ("`codex mcp-server` ... is deprecated. Use the Codex app server instead"), both read 2026-09-02; date of the change from <https://ccleaks.com/news/codex-mcp-server-deprecated-app-server-aug-2026> (tier C, "August 24") corroborated by a LinkedIn post dated 2026-08-26 <https://www.linkedin.com/posts/designly_openai-deprecated-codex-mcp-server-on-august-activity-7498439988993392640-OhVT> (tier C). No removal date is published.
- **[FACT, A, corroborated]** The replacement `codex app-server` speaks JSON-RPC 2.0 as JSONL over stdio by default (`codex app-server --listen stdio://`, alias `--stdio`), with `--listen ws://IP:PORT` (WebSocket, experimental) and `--listen unix:///absolute/path.sock`. Source: <https://learn.chatgpt.com/docs/developer-commands.md?surface=cli> (read 2026-09-02). The Claude Code plugin `openai/codex-plugin-cc` (`/plugin marketplace add openai/codex-plugin-cc`, `/plugin install codex@openai-codex`, `/codex:setup`) "delegates through the local Codex CLI and Codex app server ... same local auth, config, environment, and MCP setup ... not a separate runtime". Sources: <https://community.openai.com/t/introducing-codex-plugin-for-claude-code/1378186> (tier B, OpenAI staff post), <https://codex.danielvaughan.com/2026/04/18/codex-cli-claude-code-working-together/> (tier C, 2026-04-18).
- **[FACT, A]** Known defect in the deprecated path: `codex mcp-server` accepts `resources/list` / `resources/templates/list` and never replies, so any client that snapshots tools+resources together wedges until timeout. Source: <https://github.com/openai/codex/issues/6664> (maintainer-grade repro on codex-cli 0.114.0).

**[INFERENCE] Consequences for this estate.**
1. `CLAUDE.md` and `AGENTS.md` on main, and `multi-ai-mingle/SKILL.md` + `MOUNT.md` on live-capture, all describe the fan-out rail as "the official `codex mcp-server` mounted at user scope". That statement is now "a deprecated command kept for existing integrations". Nothing breaks today; the doc is stale and the migration target (app-server JSONL, or the `codex-plugin-cc` slash commands) is not the same shape: the plugin gives *slash commands*, not native tool calls a Claude subagent can invoke autonomously. The autonomous fan-out that `CODEX_FANOUT.md` depends on would need either the deprecated MCP surface (until removed) or a thin app-server client.
2. **Where a hosted model slots in.** The fan-out rail is command-and-control: orchestrator -> N worker threads -> push-watcher. A hosted model worker fits the *same* slot as a Codex thread if it is driven through a uniform protocol. That protocol should not be "one more bespoke MCP server per model" (rule 2 of `hosted-model-agents`), and it cannot be Codex's app-server (Codex-specific). The neutral candidate that already has an ecosystem is ACP (section 4): Codex itself is exposed as an ACP agent by Zed's `codex-acp`, Claude Code by `claude-code-acp`, so "N workers behind ACP" can mix Codex, Claude and a hosted model without the orchestrator caring.
3. The `CODEX_FANOUT.md` cap of 3 is a *Codex* cost (full MCP fleet + clone per thread). A hosted-model worker's per-process cost is a Python process with an HTTP client and a tool allowlist; its context window lives on the GPU box. **[INFERENCE, needs measurement]** several hosted workers should fit inside the RAM budget of one Codex thread; section 7 sizes this.

**[RECOMMENDATION]** Do not re-plumb the fan-out rail to the deprecated command in any new doc. Record the deprecation in `multi-ai-mingle` (a one-paragraph "as of 2026-08-24" note, no code change), keep the mounted server until OpenAI publishes a removal date (no feature removed for reliability - lock), and let the ACP adapter of section 6 be the *new* worker shape so Codex-vs-hosted becomes a per-worker choice.
