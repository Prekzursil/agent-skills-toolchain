### A. Contract and plan shape

#### D-1 — Every work unit is a cold-executable brief: exact files, complete code intent, exact commands with expected output, full text embedded in the prompt (never "read the plan")
- **Source:** `skills/writing-plans/SKILL.md:10` ("assuming the engineer has zero context … questionable taste"), `:20-27` (one action per 2-5 min step), `:91-95` (exact paths, complete code, exact commands + expected output); `skills/subagent-driven-development/SKILL.md:206` ("Never … make subagent read plan file (provide full text instead)"), `:207` (scene-setting context); `skills/blueprint/SKILL.md:26,57` ("self-contained context brief so a fresh agent can execute it cold"); `skills/dispatching-parallel-agents/SKILL.md:56-62,84-87` (focused, self-contained, specific about output).
- **Apply:** hold the work-unit registry as a JS `const WUS = [...]` literal in the script; each entry carries `{id, title, goal, files_owned[], files_read[], acceptance[], commands[], depends_on[], tier}`. Build every implementer prompt by string-concatenating the full WU entry plus the frozen `CONTEXT` prefix (D-2/D-4). A WU with an empty `acceptance[]` or `commands[]` must throw at script start (`bp-arc-02…json:384-389`-style: "a spec entry with no acceptance check must FAIL validation, since the editor could not tell success from failure").

#### D-2 — Freeze the contract (GOAL, DoD rows, rubric, schemas, shared prompt prefix, artifact root) and hash it BEFORE the first agent launches; never edit mid-run
- **Source:** `rules/common/fan-out-contract.md:54-57` §A10 ("Editing mid-run leaves contradictory instructions live … To revise: kill cleanly, delete partials, restart"); `platform/workflows/bp-arc-01…json:183-190` (`rubric-frozen` gate: `rubric_hash_recorded == true AND rubric_changed_after_generation == false`, blocking) and `:236-251` (S0 "FIX the rubric and weights, and hash them"); `skills/workflow-authoring/SKILL.md:441-442` (freeze GOAL/DoD/artifact root/schemas/prompt hashes before first unit) and `:256-265` (editing a shared schema const busts the whole resume cache — "ALL agents re-run live"); `templates/governed-run-orchestrator.md:19` ("No enhancer, planner, worker, reviewer, or synthesizer may rewrite, weaken, replace, or silently omit either block").
- **Apply:** `const GOAL`, `const DOD = [{id:'DOD-01', state, evidence_a, evidence_b}, …]`, `const SCHEMAS`, `const CONTEXT` are top-level literals. Phase 0 spawns one Bash-capable agent to compute `sha256` of the concatenated frozen blocks and write `<root>/CONTRACT-HASH.txt`; `log('contract frozen sha256=…')`. Every agent prompt starts with the byte-identical `CONTEXT` (cache prefix, `workflow-authoring:267-276`). A mid-run schema fix is done as a one-off standalone `agent()` for the single failed unit writing the same artifact path (`workflow-authoring:262-265`), never by editing the shared const and resuming.

#### D-3 — Ground first: verified ground-truth block with `[probe: …]` tags and timestamps, access methods for every non-literal path, a pinned artifact root, the snapshot SHA, and an assumption ledger with adverse inference
- **Source:** `rules/common/fan-out-contract.md:8-10` ("nothing is inherited from the global contract" — 8 lens docs with no honesty block scored 0 UNVERIFIED tags), `:24-31` §A4 (briefed fact needs probe tag + timestamp + mechanically different re-probe rule; 4 briefed "ground truth" facts were false in one run), `:32-35` §A5 (a path carries its access method; `tools/monitorcore` cost 7 agents rediscovery), `:47-48` §A8 (~1,100-word ground-truth block correlates with 18-44 tool calls and 2-49 citations; a 3.8 KB prompt with none → zero citations), `:58-69` §A11 (shared grounding pack removes 60-90 tool calls; kills mid-flight split-brain), `:70-71` §A12 (pin the artifact root and `ls` it — 10 Read failures were cwd confusion); `agent-self/config/AGENTS.md:32-38` §1b (assumption ledger, LOW-confidence load-bearing = verify trigger; "A required-but-blank field defaults to worst-case"); `WORKFLOW_TOOL_REFERENCE.md:45` (snapshot the exact revision agents read; re-map lines before acting); `skills/workflow-authoring/SKILL.md:315-327` (the REQUIRED VERIFIED-GROUND-TRUTH and ACCESS-METHODS blocks of the spawn template).
- **Apply:** Phase 0 "GROUND" = one `agent()` (read-only, `effort:'high'`) that returns `{base_sha, facts:[{claim, probe, ts}], access_methods:[], assumptions:[{text, confidence:'high|medium|low', load_bearing:bool}], grounding_pack_path}` and writes `<root>/GROUNDING-PACK.md`. The script asserts `base_sha === args.base_sha` (pass the SHA via `args`, never derive it at runtime). Any `assumption` with `load_bearing && confidence==='low'` spawns a **verify** agent before implementation (D-14). The pack is inlined verbatim into `CONTEXT` and frozen (D-2).

#### D-4 — Research-and-reuse and the simplest probe come before any expensive lane
- **Source:** `rules/common/development-workflow.md:66-72` ("Research & Reuse (mandatory before any new implementation)": GitHub code search, primary docs, registries; "Prefer adopting or porting a proven approach over writing net-new code"); `skills/simplest-probe-first/SKILL.md:9-12` ("Before any approach that costs more than a few minutes or spawns agents: name the cheapest falsifiable probe, RUN it, and let its result choose the path"); `skills/gem-hunt/SKILL.md:21-27` (build the dedup-set first or 80% of finds are duplicates).
- **Apply:** a `scout:reuse` agent per WU *family* (pipeline, core split, backends, gateway, hardening, harness) returning `{reusable:[{what, where, licence, fit}], probe:{cmd, result, decision}}`; its `decision` field is read by the script to choose a lane (e.g. "stub engine boots in <10 s locally" is the cheap probe that must pass before any Space-side work is scheduled — `workflow-findings.md:43-48` critic-5). Log the probe result on the narrator line.

#### D-5 — Work units are file-disjoint, one writer per file or code path, tests live WITH the implementation, ordered by a real dependency DAG; mutating agents run in isolated worktrees
- **Source:** `skills/autonomous-loops/SKILL.md:445-456` (decomposition rules: fewer cohesive units, minimise cross-unit file overlap, keep tests WITH implementation, dependencies only where real; DAG layers), `:490-518` (merge queue with eviction carrying full conflict context), `:615` (ignoring file overlap is an anti-pattern); `.agents/workflows/lifecycle.yaml:42` ("Keep one writer per file or code path"); `skills/workflow-authoring/SKILL.md:140-154` §4 (parallel subagents share ONE index; any WRITING agent needs `isolation:'worktree'` + disjoint file scopes), `:222-230` §6 (per-WU pipelines, not one fat barrier); `skills/subagent-driven-development/SKILL.md:205` ("Never dispatch multiple implementation subagents in parallel (conflicts)" — see conflict C-1 for how this reconciles); `skills/using-git-worktrees/SKILL.md:120-132` (verify a clean test baseline before implementing in the worktree).
- **Apply:** script-level deterministic check before dispatch: pairwise intersection of `files_owned` across WUs in the same DAG layer must be empty, else `throw` (code, not an agent — D-19). Each WU runs as its own `pipeline()` chain `impl → verify → spec-review → quality-review → integrate` with `isolation:'worktree'` on the implementer and fixer only; reviewers/verifiers are read-only, no worktree. Layer ordering: `for (const layer of dagLayers(WUS)) await pipeline(layer, …)`. Concurrency is 2 on this box, so keep layers small and homogeneous (`workflow-authoring:229-230`). The core split is layer 0 by owner decision (`DECISION-QUEUE.md:96-99,146`).

### B. Execution discipline

#### D-6 — TDD red-proof: no production code without a failing test first; RED and GREEN are each *watched*; a regression test is proven by revert-fix → must fail → restore → pass
- **Source:** `skills/test-driven-development/SKILL.md:33-45` (Iron Law), `:113-128` (Verify RED: fails for the expected reason, not an error), `:168-183` (Verify GREEN; output pristine), `:351-355` ("Never fix bugs without a test"), `:327-340` (checklist); `skills/verification-before-completion/SKILL.md:111-114` ("Write → Run (pass) → Revert fix → Run (MUST FAIL) → Restore → Run (pass)"); `rules/common/development-workflow.md:80-85`; `command-center/COMPLETION-GATES.json` gate A condition 7 ("required tests ran and passed") and 8 ("negative controls or mutations fail as expected").
- **Apply:** implementer schema requires `red_run:{cmd, exit_code, excerpt}` and `green_run:{cmd, exit_code, excerpt}` per behaviour, plus `test_files[]`. The **verify** agent (different `agent()` call, D-15) re-executes: `git stash`/revert the implementation hunk, run the named tests, require non-zero exit, restore, run again, require zero — and returns `revert_proof:{failed_when_reverted:bool, excerpt}`. A `false` there fails the unit's completion predicate (D-12) and routes to the fix loop with the excerpt attached.

#### D-7 — Run the smallest check that could still falsify the change, name the rung you reached, and never let an empty check set count as a pass
- **Source:** `skills/smallest-check-ladder/SKILL.md:22-31` (L0 lint edited files → L1 impacted tests → L2 full suite via longrun → L3 e2e on the packaged artifact), `:96-103` (report the highest rung + real output as `SUCCESS:<id> L1 12 passed`; "Never claim 'tests pass' from L0 alone"), `:107-113` ("A green rung is not a green suite"; "an empty L1 selection means seed the db … never 'there's nothing to run, ship it'"); `skills/orchestration-patterns/SKILL.md:157-171` pattern 5 (per-edit L0, ladder up only at WU boundaries, reflection cap 3); `platform/workflows/bp-arc-02…json:437` ("a lint over an EMPTY changed-file set must FAIL closed, because a lint that examined nothing is not a pass"); `agent-self/config/AGENTS.md:59-67` §4a (>60 s ops run under `longrun`, backgrounded and monitored).
- **Apply:** implementer prompt: L0+L1 after every edit; WU boundary: L2 (`python -m pytest -q` for this repo; the suite is 73 tests, `DECISION-QUEUE.md:15`) under `longrun`; L3 (stub-engine smoke, `/v1` stream + disconnect, MCP tool list) whenever `files_owned` intersects the wiring set. Schema fields `highest_rung: enum['L0','L1','L2','L3']`, `selected_count:int`, `output_excerpt`. Script rule: `if (r.selected_count === 0) → FAILED:<id> empty-check-set`.

#### D-8 — Root cause before fix; one hypothesis at a time; two strikes then pivot; three failed fixes → re-decompose or escalate; never an identical fourth attempt
- **Source:** `skills/systematic-debugging/SKILL.md:18-22` (Iron Law: no fixes without root-cause investigation), `:192-217` (single hypothesis, smallest change, don't stack fixes), `:241-262` ("If >= 3: STOP and question the architecture … This is NOT a failed hypothesis — this is a wrong architecture"); `agent-self/config/AGENTS.md:69-75` §4b (two-strikes: after the SECOND failed attempt on the same hypothesis enumerate ≥2 alternatives or escalate; tie-break with a fresh-context re-derivation); `skills/orchestration-patterns/SKILL.md:136-153` pattern 4 (Nth failure → lead re-decomposes / re-routes cross-vendor / asks owner; escalation carries a structured summary, not the transcript); `platform/workflows/bp-arc-02…json:5,175-181,391,485` (lint ladder capped at `max_reflections`; "the attempt after the cap ESCALATES to the lead for re-decomposition; it never becomes a further retry"); `bp-arc-01…json:559-577` (`two-strikes-then-pivot`, `enumerate_alternatives_min: 2`, `no_retry_on: spec-underspecified`); `skills/autonomous-loops/SKILL.md:609` ("Retrying the same failure … Capture the error context and feed it to the next attempt").
- **Apply:** per-WU `attempts` and `error_fingerprint` (a stable hash of the failing test names + first error line, computed in JS from the verifier's typed return). Loop: `attempt 1-2` → fixer agent gets the verifier's full artifact path + the previous fingerprint; if `attempt === 2 && fingerprint === prev` → spawn a **pivot** agent whose schema requires `alternatives: minItems 2` and a chosen one; `attempt === 3` still failing → spawn a **re-decompose** agent (splits the WU; new sub-WUs re-enter the DAG) and `log('escalated WU… after 3 strikes')`; never call the fixer a 4th time on the same fingerprint. Root-cause first is encoded as a required schema field on the fixer: `root_cause:{statement, evidence_anchor}` plus `hypothesis` — the script rejects a return whose `root_cause.evidence_anchor` is empty.

#### D-9 — The pipeline itself must be proven not to lie: write to the gate thresholds up front, lint the CI workflows for silent-pass shapes, and cross-check finding counts at HEAD before any "gates green" claim
- **Source:** `gate-zero-enforcer/SKILL.md:10` ("Write code that passes all quality gates on the first push … check constraints BEFORE writing"), `:67-74` (pre-write checklist: complexity budget, test plan, security surface, import hygiene), `:156-161` (on a gate failure fix the root cause, "don't just suppress the warning"); `skills/ci-silent-pass-lint/SKILL.md:9-18` (run before any PR or "gates green" claim), `:24-38` (Part A: 11 silent-pass shapes; HIGH → gate fails), `:40-49` (Part B: finding counts at the exact HEAD SHA; any `SILENT PASS` refutes "green"), `:120` (a red gate under-reports — a defect count read off a CI log is a floor, never a census); `skills/verification-before-completion/SKILL.md:44-45,53-77` ("Commit is green" requires a suite run from a FRESH CLONE of that commit; working-tree green ≠ clone green; CRLF flips verdicts — directly relevant: `DECISION-QUEUE.md:212` records `08af7ea` flipping `app.py` to CRLF).
- **Apply:** the "pipeline" WU (G-1a/G-28) has as acceptance: (a) `python skills/ci-silent-pass-lint/lint_workflows.py <repo>` exit 0 with zero HIGH, run by a Bash agent and returned as `{exit_code, high_count, findings[]}`; (b) a both-states proof (D-13) that the undefined-name lint **fails on `f88b120`** and **passes on `17dce0c`** (`DECISION-QUEUE.md:210-211`: `py_compile` passes on the broken HEAD; ruff F821 finds exactly the three missing functions); (c) `* text=auto eol=lf` present in `.gitattributes`; (d) the L2 suite run from a fresh clone of the commit, not the worktree. Reviewer/critic prompts state explicitly that "CI green" is not admissible evidence until (a)-(d) hold.

#### D-10 — Use a separate cleanup ("de-sloppify") pass rather than negative instructions in the implementer prompt
- **Source:** `skills/autonomous-loops/SKILL.md:346-352` (negative instructions make the model hesitant about ALL testing; quality degrades unpredictably), `:353-369` (the fix: let the implementer be thorough, then a focused cleanup agent), `:390-392` ("Two focused agents outperform one constrained agent"), `:611` (anti-pattern 4); `skills/receiving-code-review/SKILL.md:89-98` (YAGNI check: grep for actual usage before "implementing properly").
- **Apply:** per-WU pipeline stage `cleanup` between `impl` and `spec-review`: read-only-on-tests-of-framework-behaviour agent with a schema `{removed:[{path, reason}], kept_business_tests:int, suite_after:{cmd, exit_code}}`; the script asserts `suite_after.exit_code === 0` before continuing. Implementer prompts contain no "do not" lists beyond the safety non-negotiables.

#### D-11 — Write as you go: any agent expected to run >10 min writes a truthful skeleton immediately, rewrites at milestones, and a transcript-only result counts as NOT-RUN
- **Source:** `skills/dispatching-parallel-agents/SKILL.md:110-137` (measured: 70 min, 691 KB, froze, wrote nothing; relaunched unit produced a truthful artifact in 3 min; the three-part mandate; the self-labelling sentence "If it still reads this way, the unit died before measuring anything and no verdict here may be cited"); `rules/common/fan-out-contract.md:96-113` §C1; `platform/workflows/_shared/shared.write-as-you-go-artifact.subworkflow.json` (stages `write-skeleton` → `rewrite-at-milestone` → `postcondition`: "an artifact still carrying UNKNOWN is NOT complete"); `platform/workflows/bp-cnc-04…json:482,520` ("a transcript-only review is treated as NOT-RUN"; 540,583 tokens of review once left zero artifacts, `rules/common/fan-out-contract.md:87-88`); `skills/gem-hunt/SKILL.md:48-52` (resume from partial via SendMessage; don't redo).
- **Apply:** every implementer/verifier/reviewer prompt carries the OUTPUT CONTRACT (`workflow-authoring:360-368`): write the full deliverable to `<root>/<phase>/<wu>/<role>.md` with the skeleton first, return a ≤400-word digest, an `EVIDENCE:` block, and a final line `DELIVERED: <abs path> (<n> bytes)`. ## 5. Where two skills conflict, and which wins for this program

**C-1. `subagent-driven-development:205` "Never dispatch multiple implementation subagents in parallel (conflicts)" vs `workflow-authoring:140-154,222-230` (isolate mutators in worktrees, per-WU pipelines) and `autonomous-loops:445-456,490-518` (parallel units + merge queue) and `dispatching-parallel-agents:12`.**
Winner: **workflow-authoring + autonomous-loops**, because sdd's rule assumes one shared working tree with the Task tool, which is exactly the hazard `isolation:'worktree'` removes. Conditions: disjoint `files_owned`, JS overlap check, DAG layers, concurrency of 2 on this box, and the core split as layer 0 (`DECISION-QUEUE.md:146`). Where two WUs *must* touch the same file (e.g. `app.py` during the split), they are serialised in one pipeline chain, honouring `lifecycle.yaml:42`.

**C-2. `agent-as-judge:56-66` "opinion never gates" vs `acceptance-review:76-90,103-106` SHIP/BLOCK that fails toward BLOCK, vs `COMPLETION-GATES.json` gate A condition 9 "independent reviewer status is PASS", vs `sdd:209,213` "spec reviewer found issues = not done".**
Resolution (all four are satisfied): reviewers may **veto**, never **grant**. A reviewer BLOCK counts only when cited and reproduced (`agent-as-judge:76-77` execute-to-confirm); an un-reproduced BLOCK is a note. SHIP is computed by the deterministic predicate plus "no open reproduced blocking finding" (D-24). Condition 9 is then read as "no reviewer holds a reproduced veto", not "a reviewer said yes".

**C-3. `test-driven-development:33-45` Iron Law ("Write code before the test? Delete it") vs the reality of a refactor of an existing 1,158-line `app.py` (`DECISION-QUEUE.md:306`) and `autonomous-loops:346-369` de-sloppify (trims tests).**
Winner: **TDD for every new or changed behaviour**, adapted for extraction: characterization tests are written first against the *existing* behaviour, then code is moved (the Iron Law's delete rule applies to net-new code an implementer writes before its test, not to pre-existing code being relocated). De-sloppify runs after and may remove only framework-behaviour tests, never business tests (`autonomous-loops:362-369`). `mutation-check` proves the characterization tests bite. (Gap: TDD skill lacks this case — §6 item 6.)

**C-4. `executing-plans:24-37` (batches of 3 with a human "Ready for feedback" pause) vs `sdd:33-36` (no human between tasks) vs the owner's mandate for an autonomous loop until satisfied then a synthesizer (`DECISION-QUEUE.md:154-157`).**
Winner: **sdd-style autonomy inside the Workflow**, with human checkpoints only at the phase boundaries a script can actually honour: plan/DoD approval before launch and the promotion decision after (D-28). executing-plans' mid-run pauses are unreachable from a Workflow script; its "STOP when blocked, don't guess" (`:52-60`) is preserved as `FAILED:<wf> <blocker>` with a resumable next action.

**C-5. `fan-out-contract.md:41-46` (≤400-word digest) vs the owner's "keep every subagent's full report, not just digests" (`DECISION-QUEUE.md:148-149`).**
Not a real conflict: the digest is the *return value*; the full report is the on-disk artifact (`workflow-authoring:360-368`). Both are required (D-11, D-27).

**C-6. `gem-hunt:85-88` "loose schema or plain-text agents, not strict StructuredOutput" vs `workflow-authoring:238-242` "schema on EVERY fan-in".**
Winner for an implementation loop: **schema on every fan-in** (typed verdicts are what the gates reduce over), reconciled by `workflow-authoring:243-255`: floor-only `required`, long-form prose in a single string field, deliverable on disk. gem-hunt's rule is for wide ideation lenses with shape-varying output, which this workflow has few of.

**C-7. `AGENTS.md:59-67` §4a (anything >60 s must be backgrounded under `longrun`) vs `cross-vendor-dispatch.md:7-8` (fire-and-forget banned).**
Already reconciled by the doctrine itself (`cross-vendor-dispatch.md:9-25,91-96`): background the *process*, never the *obligation* — launch under `longrun`, block on `Monitor` until terminal, hold the payload before returning. Encode as: Bash agents running L2/L3 use `run_in_background` + Monitor and return only after the terminal marker.

**C-8. `agent-as-judge:62,285` and `acceptance-review:56-63` prefer a cross-vendor Codex judge vs the environment: `codex` CLI/MCP availability in this Codespace is UNVERIFIED (settling experiment in D-15).**
Winner: the doctrine's own degradation ladder (`acceptance-review:56-63`): Codex → Gemini → fresh Claude subagent whose ONLY input is the review prompt. The workflow probes availability once at GROUND (ToolSearch for `mcp__codex__codex`) and logs which reviewer rail is in use.

**C-9. `AGENTS.md:113-122` §9 "NEVER … rotate … any API key" vs the security review's "Rotate the pasted token today" (`workflow-findings.md:151,156`) and `DECISION-QUEUE.md:123`.**
Winner: **§9 with §9b** — the workflow reports the exposure, its blast radius and the recommendation under `owner_actions`; no agent revokes, and the hardening WU removes the `or HF_TOKEN` fallback and token files from the *consumer* side (`AGENTS.md:121-122`: "prefer fixing the CONSUMER so a bad credential cannot break it").

Minor: `using-git-worktrees:3` says "NOT for parallel agents (use dispatching-parallel-agents)" while dispatching-parallel-agents never mentions worktrees — neither covers the Workflow tool's `isolation:'worktree'`; `workflow-authoring:140-154` wins (§6 item 15).
