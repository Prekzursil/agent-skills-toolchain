## 0. Verdict in one paragraph

**A3 wins (4.20/5), A2 second (3.95), A1 last (2.90).** All three carry a run-killing bug that a smoke run would surface in the first agent call — A3 and A1 assert `repo_toplevel === args.build_repo` strictly although every authoring/verifying agent works in a sibling worktree whose toplevel is a different path (A3 line 1030; A1 line 738 + `unitDone` ok[3] line 770); A2 requires the verifier's re-run gate hash to equal the implementer's although its own ledger hashes `started_at`, `duration_s`, the tree path and mktemp log paths (A2 gate lines 569-578 vs `reduceVerdicts` line 1306). A1 additionally cannot get past preflight (`green_on_base` demanded before any card can have cleaned the base, line 798) and its gate is RED-by-construction on every card (`import worker.app`, tools and tests that only card `c01c`/`c08b` create, `tests/acceptance` counted as a locked-path violation on every card — lines 233, 236, 238, 255-263). A2 and A1 both crash on a literal `null` from `agent()` (the F-41 contract) because they route it through `withTimeout` and then dereference it; only A3's `run()` guards `r &&` first (line 1053). What separates A3 is that its gate is **complete from card 01** — claim lint, apicheck, scope/protected/tamper, secrets scan and the oracle lock are inline in `gate.sh` (lines 447-564) rather than deliverables of a card the same workflow must first build — and that its owner checkpoint object and per-card status rows are computed in JS, not by an LLM (lines 1245-1257). What A3 lacks and must graft is A1's timestamp-free gate digest with two-execution equality (A1 lines 272-277, ok[4]) and A1's state probe before any cached sha is consumed (A1 lines 865, 936).

## 2. Blocking defects per design (things that would make the run fail or lie, as written)

### A2 — throughput-first
1. **Unsatisfiable verification predicate (F-12).** `reduceVerdicts` fails a task unless `verify.ledger_hash_observed === impl.ledger_hash` (1306), and `pVerify` tells the verifier to re-run the gate and compare its own `ledger_sha256` (1261). The ledger hashes `started_at`, `duration_s`, `tree` (the implementer's `impl-…` worktree vs the verifier's `clean-<sha>` worktree), and per-step `seconds` and mktemp log paths (569-578). Two honest runs never match → every task exhausts `MAX_FIX` → `blocked:verify-exhausted`. The only way through is a verifier that reads the implementer's `.gate/last_run.json` and reports *that* hash, which makes "never trusts the implementer's ledger" (592) prose and the check void. Caught by the smoke run; fix = hash a canonical subset (A1's digest).
2. **Literal `null` from `agent()` crashes `safeAgent` (F-41).** `withTimeout` passes `null` through; `h6IsDrop(null)` is false; line 1175 reads `r.status` → TypeError. The task chain has no `catch` (1430-1437), so the rejection reaches `await tail` (1443) → outer `catch` → `RUN ABORTED` after one user skip or terminal API error anywhere in the build. Not silent (logged, synthesizer runs) but the opposite of the typed-null contract the design claims (791).
3. **Gate pre-step kills other agents' servers (F-26 guard vs concurrency).** Lines 381-383 kill every listener whose cwd is under `$BUILD_ROOT`; at cap 2 the second chain's `gradio_client` journey server (J1/J4) is a legitimate listener under `$BUILD_ROOT/wt/…` and dies when the first chain runs its gate → spurious red → fix loop on a phantom failure.
4. **Secrets step copies the secret.** `git diff | grep -E "$SECRET_RE"` and `grep -rE … $LOGDIR` (486-487) run without `-q`, so a matched token line is written to `$LOGDIR/secrets.log`, which is never deleted (582 removes only `$SAFEHOME` and `$STEPS`).
5. **Fail-open guards.** The test-count floor is skipped when `$BUILD_ROOT/.gate-baseline.json` is absent (439); `$BUILD_ROOT/gate.sh` and that baseline file are agent-writable and never pinned to an `args` hash (step 14 only compares the two writable copies to each other, 540-544); the self-test's "GREEN on the cleaned base" boolean `ok3` is computed and never used (559-560).
6. Minor: `STAGING_RE` is applied only to `notes` (1183), not to `dod[].line`/`claims`; idiom-warning clearance is required in §5b(3) but absent from `reduceVerdicts`; lens receipts are dropped without a count in `reviewDelta` (1474); `blockedRows` severity is a regex on the id (1531).

### A3 — minimal scaffold
1. **`assertCommon` nulls every worktree agent (F-1 guard misfires).** `r.repo_toplevel !== R` (1030) with `WT = R + '-wt'` (955): authors, builders, verifiers, conflict and clean-gate calls all run in `$WT/<kind>-<id>-<nonce>` whose `git rev-parse --show-toplevel` is that path → `{status:'null', reason:'wrong-repo'}` → `buildTask` returns `blocked:'agent-null:author'` for every card (1108). If instead agents follow the preamble's `git -C "R"` literally (969) they report `R` from any worktree and the check is vacuous. Either way the invariant does not measure what it claims. Caught by the smoke run; fix = prefix test on `WT`, or compare `git rev-parse --git-common-dir`.
2. **Test-count and skip floors are inert or spuriously red in every authoritative run (F-18).** `gate.sh` reads `$REPO/.gate/base.json` (474) where `$REPO` is the current checkout (331); setup writes it only in the main checkout (1070); verifiers run in detached worktrees where `.gate/` is untracked → `except: base = {0, 0}` (477-478). Consequences: `collected ≥ 0 − removed` always passes (the deletion guard is gone), and `skipped + xfailed > 0 + skip_added` fails the gate the moment any xfail exists (card 04's tool_parse known-bads, 177) unless every builder adds `Skip-Added:` trailers — which they will learn to do, eroding the signal. Silent; the smoke run (card 01, no xfails) does not surface it.
3. **Mutants are optional (F-20, SD/AP-3).** `written == 0 → exit 0` (418) and `okSemantics` accepts `mutants.written === 0` (1121); a verifier that writes no mutants passes the sufficiency check.
4. **Two matrix rows are prose only.** F-11: "UNVERIFIED findings routed to `verifier mode:'evidence'` before any card cites them" (810) has no call in the plan stage (1269-1281). F-10: "`warnings_cleared` covers every idiom hit" (693) is not in `okSemantics` (1121) and the script cannot read the ledger's hit count.
5. **Stale re-drive replays the stale result (F-43).** `integrate → missing-ref → buildTask(r.card, head)` (1173) rebuilds with byte-identical prompts (the `attempt` suffix exists only on the null-retry path, 1051) → same cache → parked with `reason: undefined` (1175).
6. Minor: external `gate.sh` copy unpinned (setup reports `gate_sha256`, 706, nothing compares it); `judged.filter(Boolean)` unlogged (1224); the on-disk `RUN-REPORT` is not rewritten when its rows differ from the script's (1306, only logged); `pgrep -f "python.*$REPO"` (360) matches almost nothing, so the stray-listener guard is inert.

### A1 — reliability-first
1. **Preflight cannot pass.** `preflight()` returns `ok:false` unless `setup.redproof.green_on_base` (798); at P0 the base is `f88b120` itself (three F821 names) and nothing has cleaned it — `c01a`-`c01c` are cards of this very run. Every stage therefore ends `FAILED:preflight` (1070).
2. **Gate RED-by-construction on every card.** No existence guards: step 4 needs `$TREE/tools/apicheck.py` and `$TREE/plan/api-ledger.json` (the ledger lives in `$RUN_DIR/plan/`, never in the tree — 236 vs 50), step 5 `tools/tamper_scan.py`, step 7 `import worker.app` unconditionally (255) plus `tests/test_import_contract.py` (256), step 8 `tools/claim_lint.py`, step 10 `tools/render_readme.py` and three test files (262-263), step 12 `tools/gate_redproof.sh` in merged/clean mode (267). All are deliverables of `c01c` (or `c08b`), all blocking. A2 has a recorded `--profile bootstrap`; A3 inlines the tools; A1 has neither.
3. **Locked-paths step fails every card.** `git diff --name-only "$BASE"..HEAD -- … tests/acceptance …` (233) with `BASE` = the card base (845, 853): the test author's `tests/acceptance/test_<card>.py` merged into the card branch is inside the range → "locked paths modified" → exit 1. The intended check (diff against `$ORACLE`) is one token away, but as written `unitDone` ok[5] is never true.
4. **Strict `repo_toplevel` (F-1).** Line 738 marks any worktree-based return `FAILED: wrong repo`; `unitDone` ok[3] repeats it (770). Same failure shape as A3.
5. **Literal `null` crashes `safeAgent` (F-41).** Line 736 dereferences `r`. Inside `pipeline` the card becomes `blocked:'chain-threw'` (982) — logged, misattributed; in preflight/plan/integration/review it ends the run through the dispatcher `catch`.
6. **No environment scrub in the gate (F-7).** `run_pytest` (240) runs tests under the agent's own environment, which holds `GITHUB_TOKEN` and `ANTHROPIC_API_KEY` (red-team §0); the `python_eval` red-proofs ("child cannot read `/proc/<ppid>/environ`") then execute against real secrets, and any failing assertion message can carry them into `commands_run[].output_tail` → the fixer prompt (848) → the transcript. The secrets step itself writes its match into the ledger summary (214, 265).
7. **Concurrency:** the pre-step kills any listener whose cmdline mentions `dirname $TREE` = `$WT_ROOT` (220-221) → the other chain's local test server dies at cap ≥ 2 (same class as A2).
8. Minor: `CRITIC.hunks_cited` has no `minItems` and `unitDone` does not check it (409, 779) although F-30 claims it; `--baseline <from AGENTS.md>` placeholder in the verifier command (853); `fnv` multiplies past 2^53 (690; deterministic, just not FNV); the per-wave review round of §6 (`MAX_WAVE_ROUNDS = 2`) has no counterpart in `build()` (974-997).

## 4. Pairwise comparisons

**A1 vs A2.** The decisive difference is whether the gate can ever be green. A2's gate is written to bootstrap itself: tool-missing is RED only for ruff (413), every tool that a later card creates is guarded by `-f` or by the recorded `--profile bootstrap` that the reducer rejects for any non-bootstrap card (346, 597, 1307), and the setup self-test asks only for RED on the broken tree and RED on the false-claim fixture (546-561). A1's gate assumes the finished repository from the first card (§2 A1-2) and its preflight demands a green base that the run itself is supposed to produce (798), so the reliability-first design never reaches its own `unitDone`. Where A1 is better it is decisively better: the timestamp-free digest (272-277) is the correct form of A2's broken ledger-hash equality, the state probes (865, 936) close A2's F-43 hole, and `unitDone` checks every acceptance id on both sides (773) where A2 checks lengths (1317). But those are graftable ideas; A2's script would run past the smoke task after two one-line fixes (hash subset; null guard), A1's would not run past preflight after five. A2 > A1.

**A2 vs A3.** Both would stop in the smoke run on a one-line bug (A2's ledger-hash equality; A3's strict `repo_toplevel`), so the comparison is about what is real after that. A3's gate is complete from card 01 — claim lint, apicheck, scope/protected/tamper/deps and secrets are inline (447-564) — whereas A2's claim lint, apicheck, idiom AST scan and catalog check are T01b deliverables that the same workflow must first write, with a bootstrap window in which the T01b implementer's own claims are LLM-checked only (§3a). A3 handles the F-41 null contract correctly (1046-1058); A2 aborts the whole DAG on one null. A3's owner checkpoint and status rows are JS (1245-1257); A2's are an LLM's rendering of `nextAction` (1627-1638), cross-checked by a second LLM. Against that, A2 is stronger on F-20/F-18 sufficiency (mutants mandatory and all killed, 1310; `dod.length === card.dod.length`, 1317; expansion guard, 1318), on F-12 intent, and on cost at cap 14. A3's silent defect (the baseline file absent in worktrees, §2 A3-2) is the one thing here a smoke run would not catch, and it costs A3 the F-18 row; A2's silent defects are smaller (secret line in a kept log; fail-open baseline; unused `ok3`). Net: A3 has more mechanisms that are real on day one and the fewest run-shape risks; A2 has more mechanisms on paper and the more ambitious scheduler whose replay behaviour is admittedly unverified (785). A3 > A2, narrowly.

**A1 vs A3.** Same decisive difference as A1 vs A2 — A3's gate and script run from the first card (after the toplevel fix); A1's do not run at all — plus the secrets gap: A3 scrubs the test environment (367-369), A1 does not (240). A1's coverage is broader in intent (held-out seams, tamper judge, arbiter, 12-condition predicate) and its digest/state-probe pair is the best F-12/F-43 mechanism in the set; A3 deliberately cut most of that and proves each cut against a remaining mechanism (§1.4), which the red-team lens can mostly confirm (the cuts that are NOT covered are F-11's evidence routing and the optional mutants). A3 > A1, by the widest margin of the three pairs.

## 7. What none of them handles (common gaps)

- **CG1. The gate binary is writable by every agent and pinned to nothing.** All three install `gate.sh` outside the repo (A2 `$BUILD_ROOT/gate.sh`, A3 `/workspaces/space-build-tools/gate.sh`, A1 `$DURABLE/gate.sh`) and protect only the in-repo copy. A2's step 14 compares two writable files to each other; A3's setup reports a `gate_sha256` nobody checks (706); A1 has no check. F-28 is therefore closed for `tools/gate.sh` and open for the copy every verifier actually runs. Fix: `args.gate_sha256` + verifier-reported `sha256sum` (G10).
- **CG2. Stray-listener killing breaks concurrency or does nothing.** A2 kills any listener with cwd under `$BUILD_ROOT` (381-383) and A1 any whose cmdline mentions `$WT_ROOT` (220-221): at cap ≥ 2 the other chain's `gradio_client` journey server is exactly such a listener → phantom red. A3's `pgrep -f "python.*$REPO"` (360) matches almost no real process → inert. None scopes the kill to the current tree, and none makes the harness own its server lifecycle so the kill becomes unnecessary.
- **CG3. Secrets in structured returns are never scanned.** The gate scans diffs/logs (A2/A3/A1) and the orchestrator scans the journal after the run, but `failures[]`, `output_tail`, `reason`, `notes` flow verbatim from a verifier into the fixer prompt (A2 1256, A3 1084, A1 848) and from the ledger into the synthesizer prompt with no regex in between. A failing hardening test that prints a captured child environment is the natural producer.
- **CG4. Persona history access is a prompt rule everywhere (F-17).** Every worktree is a full clone with `17dce0c` in history; "no `git log/show` on `system_prompt.py`" is a sentence in all three (A2 184, A3 167, A1 1132). A shallow or grafted clone for the persona card's worktree (`git clone --depth 1` / `git replace --graft <base>`) would make it mechanical; none does it.
- **CG5. Outward-action detection is self-report only (F-35).** `outward_actions_taken` is filled in by the agent that acted. None runs a mechanical post-check at the end of a run: `git -C $BUILD_REPO remote -v` empty unless approved, `gh repo list --json name` unchanged vs a launch snapshot, `hf_fs ls` of the owner's namespace unchanged. Resume admissibility is orchestrator discipline, not a script invariant (F-43).** "Resume only if the live integration head equals `integration_sha_at_launch`" appears in all three (A2 1675, A3 734, A1 451) but no script's first call compares the live head to `args` and refuses; A1's preflight state probe checks only `base_sha` (792-793).
