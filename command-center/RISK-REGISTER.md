# RISK-REGISTER

Risks to *this* command center and to the programs it tracks. Each row names the failure, the
signal that would show it happening, and the control that exists today. A risk with no control
says so rather than borrowing one.

Bands: almost-certain 90-99% · likely 55-80% · uncertain 30-55%.

## 1. Risks to the command center itself

| # | risk | likelihood if uncontrolled | control in place | residual |
|---|---|---|---|---|
| RK-1 | **The catalog goes stale exactly as `RESUME.json` did** — work continues, nothing updates it. | almost-certain (it already happened once, measured: 15 days) | The register gate resurfaces matching open items at the moment a prompt touches that area; closing is one command; every mutation is event-logged. | The gate ships in SHADOW, so for now it observes and does not surface. **Until it is promoted to `advise`, the resurfacing control is NOT ACTIVE.** Stated plainly rather than counted as mitigation. |
| RK-2 | **The derived files drift from the catalog** and a reader trusts the stale one. | likely | `render.py --check` fails on any drift; `DEPENDENCY-GRAPH.json` is regenerated by every mutation; the validator asserts committed graph == derived graph. | Only holds if the check runs in CI. A CI step is added in this PR; if it is ever removed the control is silently gone. |
| RK-3 | **The gate becomes wallpaper** — fires so often the reader learns to ignore it. This is a measured, named failure on this estate: `ipass_readback` at 19.0 fires/session was held in shadow for precisely this reason. | likely for a keyword gate with no ceiling | Selectivity ceiling (>8 matches ⇒ silent), cap of 3 items shown, one fire per item per session, and a measured firing rate on the real 375-prompt corpus. Auto-demote at >6.0 fires/session. | The rate is measured on a corpus replay, which applies no session cooldown — so the measured number is an UPPER bound. |
| RK-4 | **The gate loops.** A Stop-family inject re-triggers the host re-entrancy counter; two trivial probes cost 62,155 and 63,222 tokens on 2026-08-08 from exactly this bug. | almost-certain if a Stop-family event were used | The module returns `allow` for every event outside `{UserPromptSubmit, SessionStart}`, plus a `stop_hook_active` re-entrancy guard, plus a fixed-point test feeding the gate its own output, plus a 50-event loop-bound test. | None known. The chosen events cannot re-enter by construction. |
| RK-5 | **An advisory with no legal next move** deadlocks the reader — the other half of the same 2026-08-08 bug, where the only satisfying action was forbidden by AGENTS.md §9. | almost-certain if the text only says "you have open items" | Every injection names three legal moves, one of which (`defer`) is always available, and states that doing nothing is also fine. | RK-6 | **Closing is dearer than opening**, so the open set only grows. | almost-certain (the generic failure mode of every register) | Both verbs are one command with the same shape; asserted by a test, not by prose. | A close requires evidence, which is *deliberately* more expensive than an evidence-free close. That asymmetry is intended. |
| RK-7 | **A pre-existing violation blocks every unrelated close**, which would make the tool unusable and get it abandoned. | likely | `close.py` compares violations before and after and refuses only the ones the change introduces. Covered by a test. | None known. |
