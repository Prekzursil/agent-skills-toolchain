**UNVERIFIED:** the actual plugin MCP inventory and whether managed MCP suppresses it on this host would be settled by (a) exporting enabled plugin IDs plus each resolved plugin MCP manifest without executing servers and (b) comparing their endpoints to a fresh-session names-only `claude mcp list`. No finding is claimed.

### 3. MCP-tool hooks versus connection timing

This is lifecycle timing, not authority precedence. Official hook documentation says MCP tool hooks require an already-connected server and that SessionStart commonly runs before connection completes. The supplied user hooks are command hooks, and the active tool-name hooks only run after a tool call is proposed. [Official hooks reference](https://code.claude.com/docs/en/hooks).

No supplied active command hook claims it can change the current session's loaded MCP set. ### 4. Shared config-drift sentinel versus MCP authority

The shared sentinel is advisory and compares only three keys in `~/.claude/settings.json`: `hooks`, `mcpServers`, and `disabledMcpServers` (`/local_disk0/codexwork/bundle/agents/harness/modules.py:864-909`). It does not select a server definition, so it cannot win an MCP loader collision.
