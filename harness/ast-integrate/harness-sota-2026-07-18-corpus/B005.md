# B005 — Groundedness engineering for external facts

**Unit:** B005  
**Date:** 2026-07-19  
**Scope:** Claims about the world outside the local subject tree: library/API behavior, vulnerabilities and CVEs, benchmark results, standards, papers, product behavior, and other mutable public facts.  
**Write scope:** This artifact only. The unpacked subject at `/local_disk0/codexwork/bundle` was inspected read-only.

## Executive verdict

Hallucination cannot be eliminated. A harness that promises elimination is making an external-fact claim it cannot support. The achievable target is narrower and operational: make important unsupported claims visible, give each visible claim a source passage that can be checked cheaply, detect when that passage or source has gone stale, and abstain cleanly when evidence cannot be obtained.

The best design for this harness is **not** a global text-matching “fact detector.” It is an evidence contract at the point where research answers are authored, plus a small receipt validator on the existing skill/hook/ledger bus:

1. Every material external factual claim gets a stable claim ID and one or more evidence receipts.
2. The minimum human-visible citation is **canonical URL + UTC retrieval date/time + short exact supporting span**.
3. The machine receipt additionally records source type/authority, locator, version or temporal scope, final URL, content hash, and HTTP validators when available.
4. Deterministic checks enforce only facts they can know: receipt presence for explicitly marked claims, URL syntax, successful retrieval state, quote presence in the captured representation, temporal-scope fields, and TTL status.
5. Claim-to-span entailment is a separate verdict (`supported`, `partial`, `contradicted`, `not-in-source`, `unclear`). It begins advisory and sampled because semantic judgments can false-fire.
6. Freshness is based on the claim’s volatility and decision harm, not one universal age. “Retrieved today” proves when evidence was observed, not that the underlying fact is true.
7. High-harm claims require a second, genuinely independent authority or human review; two pages repeating the same upstream record are not independent.

This design rides the current bus, adds no orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, SaaS observability, or guardrail framework. It therefore passes the anti-overfit gate.

The main effectiveness numbers are intentionally not invented. **UNVERIFIED — the experiment that settles them is the paired groundedness benchmark in §11:** the fraction of false claims caught, false-positive rate, latency, and cost per claim are not measured for this owner’s workloads. It is **very likely (80-90%)**, based on the deterministic nature of URL/quote/TTL validation and the confirmed local false-fire history, that structural enforcement will have a materially lower false-positive rate than a semantic prose scanner; the benchmark in §11 must establish the actual rates before any Stop-time enforcement.

## 2. What “grounded” means—and does not mean

An external claim is **receipt-grounded** when all of these hold:

1. **Identity:** the cited source has a canonical URL and the retrieved representation is identified.
2. **Recoverability:** the exact quoted span can be found in the captured normalized representation, with a locator and surrounding selector context.
3. **Support:** the span entails the atomic claim at the claim’s stated scope; it is not merely topically related.
4. **Authority:** the source type is fit for the claim type (for example, official versioned API docs for an API signature).
5. **Time:** the evidence was fresh enough when the answer was emitted, and the claim says whether it is historical, version-pinned, or current.
6. **Independence when required:** corroborating sources do not merely copy the same upstream source.

Grounding does **not** prove truth. A primary source may be wrong, outdated, compromised, ambiguous, or silent about an edge case. A correctly located quote may contradict the claim. Two sources may share one upstream error. A current page may describe a staged release not available to the user. The receipt makes these failure modes inspectable; it does not abolish them.

ALCE separates citation correctness from citation completeness and reports that even its best ELI5 systems lacked complete citation support 50% of the time [E2]. FActScore evaluates long text by decomposing it into atomic facts and checking each against a knowledge source [E3]. Those results support two design choices: score support and coverage separately, and make the unit of evaluation an atomic claim rather than a whole paragraph. They do not establish this harness’s future performance.

## 3. The external-fact citation standard

### 3.1 Human-visible minimum: URL + retrieval time + quoted span

Every material external factual claim must have an adjacent reference ID. The evidence appendix renders at least:

```text
[S1] https://canonical.example/versioned/page
     Retrieved: 2026-07-19T14:22:31Z
     Quote: “The exact, short passage that supports the claim.”
     Locator: §Heading / page 7 / lines 110-116 / JSON pointer
```

Rules:

- Use the final canonical `https` URL after redirects, not a search-result URL. Preserve the requested URL separately in the machine receipt when redirects matter.
- Retrieval time is RFC 3339 UTC to seconds (`YYYY-MM-DDTHH:MM:SSZ`). A date alone is acceptable only in human-constrained prose; the receipt retains the timestamp.
- Quote the shortest span sufficient to support the claim. Default maximum: 25 words per source in user-visible output, both to reduce review cost and to remain conservative around source rights. If a longer private span is needed for machine checking, store only what source terms allow and render a short excerpt.
- The quote is verbatim after declared normalization: Unicode NFC, HTML entities decoded, tags removed, line endings normalized, and whitespace runs collapsed. Preserve raw-content hash separately.
- Prefer a stable native locator: section anchor, paragraph ID, page, table/figure and row, API JSON pointer, repository path plus commit and lines. Character offsets alone are brittle; W3C’s TextQuoteSelector model uses an exact quote plus optional prefix/suffix to disambiguate [E1].
- One citation may support several adjacent atomic claims only if its span entails every one. Otherwise split the claims or add receipts.
- A URL without a quote is a **pointer**, not evidence. A quote without a URL is an **orphan**. A URL and quote without retrieval time are **temporally unscoped**.

### 3.2 Machine receipt

Use append-only JSONL, one record per claim-source pair. Avoid the measured over-strict StructuredOutput path. Required fields are few; optional fields remain optional.

```json
{
  "schema": "external-claim-receipt/v1",
  "claim_id": "xf-01HV...",
  "claim_text": "Library X version 4.2 exposes method Y.",
  "claim_kind": "api_behavior",
  "temporal_scope": {"mode": "version_pinned", "value": "4.2"},
  "importance": "material",
  "source": {
    "requested_url": "https://...",
    "final_url": "https://...",
    "title": "...",
    "publisher": "...",
    "authority": "official_versioned_docs",
    "published_at": null,
    "source_updated_at": "2026-07-17T00:00:00Z"
  },
  "retrieval": {
    "retrieved_at": "2026-07-19T14:22:31Z",
    "status": 200,
    "media_type": "text/html",
    "etag": "...",
    "last_modified": "...",
    "raw_sha256": "...",
    "normalized_sha256": "..."
  },
  "selector": {
    "exact": "short supporting span",
    "prefix": "short preceding context",
    "suffix": "short following context",
    "locator": "#section-name"
  },
  "support": {
    "verdict": "supported",
    "method": "author",
    "checked_at": "2026-07-19T14:24:00Z"
  },
  "freshness": {"class": "api_current", "ttl_seconds": 1209600, "verdict": "fresh"},
  "upstream_id": null
}
```

Additional rules:

- `claim_text` is atomic: one subject, one predicate, qualifiers included. Numbers, model names, dataset subsets, versions, and “as of” dates stay in the atom.
- `temporal_scope.mode` is one of `historical_snapshot`, `version_pinned`, `current_as_of`, or `timeless_definition`. “Latest,” “currently,” and “now” require `current_as_of`.
- `source.authority` is a controlled label, not an automatic truth score.
- `upstream_id` records common provenance when multiple pages copy one advisory, paper, press release, or dataset. Equal `upstream_id` values count as one source for independence.
- `support.verdict` is never inferred from HTTP success. The verdict vocabulary is `supported`, `partial`, `contradicted`, `not_in_source`, `unclear`, or `unchecked`.
- Search snippets may discover sources but cannot be the final evidence unless the claim is specifically about the search response. Fetch the source page.
- When access is blocked, record `unreachable`; do not manufacture the quote from a snippet or training memory.

### 3.3 Claim materiality

Require receipts for claims whose falsity would change a decision, implementation, risk posture, expenditure, or reported result. Examples: API names and parameter behavior; availability/version claims; CVE affected/fixed versions and exploitation status; benchmark scores, rank, dataset/subset, evaluation mode, and date; legal or pricing claims; quantitative comparisons; direct quotations; and claims framed as current.

Do not burden ordinary conversational glue, clearly labeled opinion, the user’s own stated preference, or local facts already cited as `path:line` with an external receipt. If a sentence mixes opinion and fact, split it.

**UNVERIFIED — the experiment that settles the boundary is §11’s annotation study:** author agreement on “material external claim” is unknown. It is **likely (55-80%)**, based on the explicit categories above and atomic-claim methods in ALCE/FActScore [E2-E3], that a short examples-first rubric will reduce ambiguity enough for useful coverage scoring; measure inter-annotator agreement before enforcing coverage.

## 4. Authority policy by claim type

Source authority is claim-relative. The harness should encode the following preference order as policy, while allowing a documented exception.

| Claim type | Preferred evidence | Corroboration / rejection rule |
|---|---|---|
| Library/API signature or behavior | Official, version-matched reference docs; then tagged source/release notes; then maintainer issue for undocumented behavior | Reject unversioned aggregator summaries when the user names a version. For observed undocumented behavior, pair source code/commit with a reproducible probe. |
| Product limits, price, retention, feature availability | Official product/API docs or contractual page retrieved current-as-of | Community posts may identify the issue but do not establish current limits. Region/account rollout qualifiers must remain in the claim. |
| CVE existence, description, affected/fixed versions | Vendor/CNA advisory plus current CVE Record; NVD for enrichment/status fields | A CVE ID alone does not prove exploitability or that the user’s version is affected. For remediation, require vendor fixed-version guidance. CVE rules identify CNAs as publishers of CVE Records [E6]; NVD exposes `lastModified` and `vulnStatus` [E5]. |
| Known exploitation | CISA KEV entry or vendor incident statement, current-as-of | Do not infer exploitation from severity or proof-of-concept availability. |
| Benchmark score from a paper | Original paper/table, exact version, task, subset, metric, and evaluation date | A later leaderboard must not silently replace a paper result. Record whether result is self-reported, checked, or independently verified. |
| Current benchmark leader | Official leaderboard snapshot/API plus evaluation commit/rules and retrieval time | “SOTA” expires quickly and must identify track, date, and verification status. A score with different scaffolding or test set is not directly comparable. |
| Standard/protocol behavior | Versioned standards body publication or RFC number/section | Draft and final standard are distinct temporal/version scopes. |
| Scientific conclusion | Original paper and, for decision-critical claims, independent replication/review | A paper supports “the study reported X,” not automatically “X is universally true.” |

For CVEs, two public databases that ingest the same CNA record are not mechanically independent. The vendor advisory and a CVE/NVD record supply different signals only to the extent that their specific fields or analysis are independently authored. Record `upstream_id` and field provenance.

## 5. Staleness policy

### 5.1 Principles

1. TTL is the maximum evidence age at answer emission, not a deletion time.
2. Historical and version-pinned claims do not become false merely because a current page changes; they become unverifiable if the pinned representation cannot be recovered.
3. Current claims expire according to volatility and harm.
4. `ETag` and `Last-Modified` make conditional revalidation cheap, but absence of change at one URL does not prove the outside world is unchanged. HTTP defines validators for conditional requests [E7].
5. A changed hash invalidates the saved quote/support verdict until the quote is relocated and entailment rechecked.
6. A `304 Not Modified` refreshes retrieval/revalidation time while retaining the original content hash and quote.
7. If a source supplies its own `updated_at`, preserve it but do not substitute it for retrieval time.
8. Stale evidence is not automatically false. The output verdict is `fresh`, `stale-needs-refresh`, `changed-needs-review`, `unreachable`, or `superseded`.

### 5.2 Default TTL matrix

These are policy defaults, not empirical laws:

| Evidence/claim class | Default maximum age | Emission behavior when expired |
|---|---:|---|
| Immutable, content-addressed commit; versioned RFC; archived release artifact | No routine expiry for the pinned historical assertion | Keep; recheck reachability annually for durable reports. Current/retraction status is a separate claim. |
| Published paper result tied to paper version/table | No routine expiry for “paper reported X” | Keep exact version. Refresh if claiming present consensus, validity, or current rank. |
| Version-pinned library/API docs | 90 days | Revalidate conditionally; require exact requested version. |
| Current library/API behavior, release support, product feature | 14 days | Refresh before answering; 24 hours when wording says latest/today/current rollout. |
| Current benchmark score/rank/leaderboard | 7 days | Refresh and retain snapshot date, track, harness, and verification status. |
| CVE affected/fixed versions or vulnerability status for an operational decision | 24 hours | Refresh vendor advisory and CVE/NVD status; abstain from remediation claim if either required source is unavailable. |
| CVE description in a non-operational historical report | 7 days | Refresh status and last-modified fields; label snapshot date. |
| KEV/exploitation status | 24 hours | Refresh authoritative catalog; never infer from stale absence. |
| Price, service status, active incident, availability | 1 hour (status/incident) or 24 hours (price) | Refresh; include region/account qualifiers. |
| Law, regulation, medical or financial action guidance | 24 hours and human/professional review as appropriate | Refresh primary authority; do not emit action guidance solely from the automated verifier. |

**UNVERIFIED — the experiment that settles these TTLs is a 90-day source-change replay:** the optimum TTLs and network cost for this owner are unknown. It is **roughly even (45-55%)**, because source volatility varies greatly and the bundle has no historical source-change telemetry, that the proposed 14-day API and 7-day leaderboard defaults minimize combined stale misses and refresh cost. Log ETag/hash changes and answer reuse, then tune per domain/class rather than globally.

### 5.3 Negative claims and absence

Claims such as “there is no CVE,” “the library has no method X,” or “no benchmark exceeds Y” are open-world absence claims. One search result cannot establish them. Before emitting one:

1. Prove the detector can find a known-present control in the same source/API.
2. Use a second mechanically independent query or data field.
3. State the bounded universe and time: “No matching record was returned by CVE API query Q as of T,” not “no vulnerability exists.”
4. Preserve query parameters, result count, pagination completion, and API timestamp in the receipt.

This directly applies the confirmed known-positive-control defect (`INPUT-known-harness-defects.md:111-129`).

## 6. Proposals

### P1 — Adopt the citation/receipt contract

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Add the standard in §3 and source/TTL policy in §§4-5 to the existing research/docs skill instructions. Make “URL + retrieved-at + exact span” the minimum evidence interface shared across providers. Keep the visible format simple and the machine receipt permissive.

Expected catch surface: missing citations on explicitly marked material claims; orphan URLs; missing retrieval time; missing temporal/version scope. Cost: authoring metadata from the fetch already made plus a short quote. False-positive exposure: low for explicit receipt fields, but coverage remains incomplete when the author fails to mark a claim.

It is **very likely (80-90%)**, because this changes author-time output shape and does not classify arbitrary prose, that P1 avoids the known use-versus-mention false-fire class. Evidence is the explicit record boundary and the measured failure of payload scanning (`INPUT-known-harness-defects.md:9-82`). §11 must verify actual false positives.

### P2 — Capture evidence receipts on the existing ingest/ledger bus — UNVERIFIED payload premise

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Extend the existing external-ingest observation path to accept an explicit `claim_id`/capture action from research skills and append a sanitized JSONL receipt. Hash and normalize once per distinct fetched representation; deduplicate subsequent claims by content hash. Do not retain entire copyrighted pages by default. Retain the minimal exact/prefix/suffix selector and hashes; for sources whose terms permit caching, optionally retain a bounded evidence snapshot.

This proposal assumes the authoring skill can pass source metadata or a capture envelope to the ledger. **UNVERIFIED — experiment: record a redacted PostToolUse payload for WebFetch, WebSearch, Context7, one MCP search result, and native Claude citation output on the Windows host and map which URL/status/body/header fields survive normalization.** It is **likely (55-80%)**, because the existing bus already sees result strings and tool names (`modules.py:1144-1158`) but headers and native citation structure were not verified in the remote bundle, that most receipt fields can be captured without provider-specific fetch wrappers.

Do not ship a second crawler, proxy, or evidence service. If headers are unavailable, record them as absent; do not expand this into BUILD-LARGE merely to obtain them.

### P3 — Enable provider-native citations for evidence collection

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

For Claude API document/search-result evidence calls, enable native citations and map page/character/block pointers into the common receipt. Anthropic states that extracted cited text has valid pointers to provided documents [E4]. Treat pointer validity as recoverability only; run the same support and freshness policy afterward. Do not combine citations with a strict structured-output fan-out path where the provider declares them incompatible; the local corpus already shows a 22.9% StructuredOutput error rate.

Expected catch surface: fabricated pointers outside provided documents and quote-location drift. Cost: Anthropic says cited text does not count toward output tokens [E4], though enabling citations adds some input processing. False-positive exposure: pointer validation is provider-parsed, but semantic support can still be wrong.

It is **very likely (80-90%)**, based on Anthropic’s official valid-pointer guarantee [E4], that this reduces nonexistent-document/location citations on eligible Claude calls. The size of the improvement over current prompting is **UNVERIFIED — experiment: paired native-vs-prompt citation evaluation in §11.**

### P4 — Add a deterministic receipt linter and conditional refresher

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

At research-answer finalization—not every arbitrary Stop—parse explicit claim markers/native citation blocks and validate:

- required fields and URL scheme;
- unique claim IDs and resolvable receipt IDs;
- quote exact/prefix/suffix found once in the normalized captured representation;
- content hash consistency;
- temporal-scope and version qualifiers;
- TTL status;
- conditional GET result when refresh is due, using ETag/Last-Modified when available;
- no two “independent” sources sharing the same `upstream_id`.

Enforce only deterministic failures inside an explicitly declared research artifact. If the source is unreachable, do not call the claim false; return `unreachable` and apply claim-class policy (abstain for high harm, label for lower harm). Never scan quoted prose examples for factual-looking words.

Cost per claim: local parsing and quote matching; at most one conditional request per distinct expired source, amortized across all claims citing it. Network calls are source-deduplicated, not claim-multiplied. False positives should arise only from normalization/selector bugs or an incorrectly assigned TTL, both testable with fixtures.

It is **very likely (80-90%)**, because exact-field checks have deterministic oracles and the current harness already distinguishes deterministic from heuristic tiers (`modules.py:130-143`), that P4 can safely enforce structural failures after shadow calibration. **UNVERIFIED — experiment: §11 must meet the promotion thresholds before enforcement.**

### P5 — Semantic support checking stays advisory and sampled — UNVERIFIED effectiveness

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Batch atomic `claim_text + quote + qualifiers` tuples into one existing-model call per answer. Require one of the six support verdicts and a brief mismatch label (wrong number, entity, polarity, scope, time, version, or not stated). Surface findings to the author for repair. Do not block completion solely on a model verdict. Escalate high-harm `contradicted`/`not_in_source` cases to direct human/source inspection.

This catches the central gap left by valid pointers: a real quote can fail to entail the claim. It also introduces the largest false-positive risk, especially with negation, tables, code, and multi-hop claims. Same-model self-check is not mechanically independent evidence; it is triage.

The semantic verifier’s recall and false-positive rate are **UNVERIFIED — experiment: §11’s blind human-labeled set.** It is **likely (55-80%)**, based on ALCE’s citation-correctness framing and FActScore’s atomic-fact approach [E2-E3], that atomic claim/span pairs are easier to judge than whole reports, but neither paper establishes performance on this owner’s heterogeneous tasks or on current models.

### P6 — Require independent corroboration only where harm earns the cost — UNVERIFIED net benefit

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Require two mechanically independent signals for security remediation, legal/medical/financial action, current benchmark-leader claims used for investment, and consequential absence claims. Ordinary API syntax from official versioned docs needs one primary source; demanding two sources for every claim would add cost and often create fake independence through copied aggregators.

Cost: one additional authority lookup only for high-harm classes. False-positive exposure: source conflicts should produce `disputed`, not an automatic block or majority vote. The expected net benefit is **UNVERIFIED — experiment: stratify §11 by harm and compare one-source versus two-source adjudication.** It is **likely (55-80%)**, based on the confirmed local requirement for independent signals before absence/broken claims and CVE’s distinct CNA/NVD roles [E5-E6], that targeted corroboration catches consequential source errors without taxing routine facts excessively.

## 7. What not to build

1. **No universal regex fact detector.** Percentages, names, CVEs, URLs, and modal verbs occur in quotations, examples, negations, and bug reports. This would recreate the confirmed semantic-role defect.
2. **No Stop hook that blocks on a semantic model verdict.** The workspace already recorded a detector telling an agent to discard a successful result (`INPUT-known-harness-defects.md:65-76`). Semantic verification remains advisory until measured and should still not be the sole blocker afterward.
3. **No vector database or knowledge graph of world facts.** It would add a stale truth store and is explicitly rejected by the anti-overfit gate. Receipts are append-only provenance, not memory retrieval infrastructure.
4. **No second research orchestrator, crawler daemon, or durable workflow engine.** Existing Web/MCP tools and the hook/skill/ledger bus already provide acquisition and lifecycle surfaces.
5. **No trained critic.** It is a previously rejected component and unnecessary for a small claim/span advisory check.
6. **No observability SaaS or guardrail framework.** JSONL metrics on the current shadow/eval bus are sufficient.
7. **No blanket archive of full webpages.** It creates rights, secret, and storage risks. Prefer hashes and bounded selectors; archive only when policy and source terms permit.
8. **No “two URLs means two sources” rule.** Track upstream provenance.
9. **No silent repair of claims.** A verifier may suggest a narrower sentence, but the author or human accepts it and a new receipt records the changed atom.

## 8. Detection economics

The owner’s required decision frame is catch fraction, cost per claim, and false-positive rate. The design should report these separately by detector; an aggregate can hide a noisy semantic component behind a precise structural one.

| Detector | False-claim classes it can catch | Unit cost | Expected false-positive source | Enforcement |
|---|---|---|---|---|
| Receipt presence/shape | Explicitly marked claim lacks URL/time/span/scope | One local parse per answer | Parser/marker bug | Enforce after shadow test |
| URL/retrieval status | Fabricated/malformed URL; failed acquisition represented as success | Existing fetch metadata; no extra call when captured | Redirect/login/interstitial ambiguity | Enforce clear failures; label ambiguity |
| Quote/selector match | Invented quote; quote not in captured representation; ambiguous repeated quote | One normalized exact match per source | Normalization or dynamic-page mismatch | Enforce against captured representation |
| Hash/change check | Source representation changed after capture | Hash locally; one conditional request per expired source | Benign dynamic content | `changed-needs-review`, not “false” |
| TTL | Evidence older than policy | Constant-time timestamp comparison | Bad class/TTL assignment | Enforce freshness for high harm; label otherwise |
| Authority/version check | Wrong source class/version or unscoped “current” claim | Policy lookup | Legitimate undocumented/secondary evidence | Require exception, not categorical rejection |
| Semantic support | Real source does not entail claim; wrong number/entity/polarity/scope | One batched model call per answer plus sampled human review | Model misunderstanding, tables/code/negation | Advisory |
| Independent corroboration | Source itself wrong, copied, or insufficient for high-harm action | One extra source fetch per high-harm claim | Mistaken provenance/conflict | Human/disputed outcome |

No catch percentages are asserted because none were measured. §11 defines the experiment. Resource cost should be reported as: local milliseconds, network requests per distinct source, verifier input/output tokens per answer, human-review minutes per flagged claim, and added answer latency. Dollar conversion is provider- and date-dependent and belongs in the benchmark run, not this design.

Promotion targets are acceptance criteria, not predictions:

- Structural validator: at least 99% precision on the labeled suite, no false block in a 500-answer shadow burn-in, and at least 95% recall on synthetically missing/altered receipt fields.
- Quote validator: 100% on deterministic normalization fixtures and at least 99% precision on live captured-source fixtures.
- TTL/refresher: no fresh receipt labeled stale in fixtures; every deliberately expired fixture detected.
- Semantic advisory: report precision/recall by mismatch type; do not promote to blocking based on a single aggregate score.
- End-to-end: report unsupported-claim catch rate, supported-claim false-flag rate, fraction of material claims with receipts, median/p95 added latency, requests per distinct source, tokens, and human minutes.

## 9. Failure behavior and user-facing states

The system must distinguish these states:

- **SUPPORTED:** quote exists, source is in policy, entailment accepted, evidence fresh.
- **RECEIPT-VALID / SUPPORT-UNCHECKED:** structural evidence is recoverable; semantics not yet reviewed.
- **PARTIAL:** source supports only a narrower claim. Offer the narrower wording.
- **CONTRADICTED:** source states the opposite or incompatible value. Do not emit the claim as fact.
- **NOT-IN-SOURCE:** citation is topical but does not state the claim.
- **STALE-NEEDS-REFRESH:** TTL expired; not automatically false.
- **CHANGED-NEEDS-REVIEW:** hash/ETag indicates a new representation; old support verdict is invalidated.
- **UNREACHABLE:** evidence cannot currently be revalidated. Preserve last-known retrieval date and abstain according to harm.
- **DISPUTED:** independent authorities disagree. Show both and do not collapse disagreement.
- **UNSUPPORTED:** no admissible receipt. Remove, research, or label as an unverified hypothesis.

The user-facing response should not dump machine fields by default. Show concise inline citations and an evidence appendix when the task is research-heavy. Always make retrieval date visible for mutable facts.

## 10. Concrete examples

### Library API claim

Bad:

> Framework X supports `foo()` now. [Framework docs]

Good:

> Framework X 4.2 documents `foo()` on `Client` [S1].

Receipt S1 pins the 4.2 docs URL, retrieval timestamp, exact method-signature span, section anchor, and version. If only latest docs exist, the claim becomes “the current docs retrieved at T document…” rather than silently applying to 4.2.

### CVE claim

Bad:

> CVE-YYYY-NNNN affects all versions before 3.1 and is actively exploited.

Good requires separate atoms and receipts:

1. The vendor advisory lists versions `<3.1` as affected/fixed by 3.1.
2. The current CVE Record has status and description X.
3. A current KEV record or vendor statement establishes known exploitation.

Severity, affected range, fixed version, and exploitation are different predicates and may come from different authorities. A high CVSS score does not support atom 3.

### Benchmark claim

Bad:

> Agent Y gets 74% on SWE-bench, proving a 100-line loop is best.

Good:

> In benchmark version V, track T, subset S, and evaluation dated D, the identified submission/paper reports score M under harness H [S1]. This does not by itself establish superiority on this owner’s tasks.

The receipt must capture benchmark version, score metric, subset, model, harness/scaffolding, verification status, evaluation date, and exact table/row. “Best” is a second claim requiring a contemporaneous leaderboard snapshot and comparability analysis.

## 11. The experiment that settles effectiveness

### 11.1 Dataset

Build a read-only evaluation set outside the subject from 200-300 atomic external claims, stratified across:

- library/API docs and code examples;
- CVE/vulnerability status, affected/fixed version, severity, and exploitation;
- benchmark numbers/rankings and paper claims;
- product feature/price/limit claims;
- standards and scientific papers;
- negative/absence claims;
- tables, PDFs, JSON APIs, dynamically rendered pages, and ordinary HTML.

Seed half from owner-correction candidates involving external claims, after human confirmation; the corpus candidate list is only a candidate source, not ground truth. Seed the rest from fresh research tasks.

For each supported atom, create controlled corruptions with deterministic labels:

- wrong number, version, date, model, dataset, or entity;
- inverted polarity/negation;
- removed qualifier (“beta,” region, plan, subset, self-reported);
- citation swap to a topically related passage;
- fabricated URL and fabricated quote;
- stale snapshot followed by source change;
- two URLs with a common upstream source;
- absence query with incomplete pagination or broken detector;
- quote in prose that merely mentions or refutes the claim.

### 11.2 Independent ground truth

Two human annotators independently label materiality, atomicity, authority, entailment, and freshness. Resolve disagreements against the fetched source snapshot. For deterministic mutations, preserve the transformation record as a second signal. For absence cases, include known-present controls and a second query/data field. Report agreement; do not silently majority-vote.

### 11.3 Arms

Run matched prompts with the same model/settings:

1. Current baseline docs/research instructions.
2. Citation contract only (P1).
3. Contract + deterministic receipt/TTL validation (P1/P2/P4).
4. Contract + native citations where eligible (P1/P3/P4).
5. Full design with semantic advisory and targeted corroboration (P1-P6).

Repeat enough cases across providers to keep one model/tool from dominating. Web failures remain outcomes, not discarded trials.

### 11.4 Metrics

For each detector and end-to-end arm:

```text
unsupported_claim_recall = false_or_unsupported_claims_flagged / all_false_or_unsupported_claims
supported_claim_false_positive_rate = supported_claims_flagged / all_supported_claims
citation_coverage = material_claims_with_valid_receipts / all_material_claims
quote_recoverability = receipts_whose_span_resolves / all_receipts
freshness_recall = stale_receipts_flagged / all_stale_receipts
review_yield = confirmed_bad_flags / all_flags_reviewed
cost_per_claim = (tokens + requests + human_seconds + added_latency) / material_claims
```

Also report p50/p95 latency, requests per distinct source, source-deduplication ratio, abstention rate, false blocks per answer, and mismatch-type confusion matrices. A detector that raises coverage but produces frequent false accusations fails.

### 11.5 Rollout

1. Offline fixtures only.
2. Shadow mode, no user-visible nags.
3. Advisory mode for receipt repair and all semantic results.
4. Enforce only deterministic receipt/quote/freshness failures after targets in §8 are met.
5. Monthly sample of “passed” claims to estimate missed unsupported claims; reviewing only flags cannot measure recall.
6. Sunset or retune a detector when review yield drops, cost rises above benefit, or source formats change.

It is **very likely (80-90%)**, based on the existing OFF/SHADOW/ADVISE/ENFORCE stage ladder (`modules.py:130-143,389-417`), that rollout can occur without a new runtime. Whether the existing event payload contains all receipt fields is the UNVERIFIED P2 premise and must be tested first.
