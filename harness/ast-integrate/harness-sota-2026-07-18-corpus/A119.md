### What “runtime precedence” means here

The contract declares its own hierarchy at `AGENTS.md:115-131`, but that hierarchy omits custom-agent system prompts. In particular it ranks user instructions, safety, the contract, project governance, and plugins; it never says where `~/.claude/agents/*.md` bodies sit. The runtime does.

Anthropic's current custom-subagent documentation says a non-fork custom subagent receives its own prompt as its **system prompt**, plus the delegation task, while also loading `CLAUDE.md` and memory. Anthropic's memory documentation separately says `CLAUDE.md` content is delivered as a **user message after the system prompt**. These are mechanically different data positions, not two phrasings of one precedence claim. Consequently, an irreconcilable custom-agent-body instruction occupies the higher message tier. This also explains why writing “this contract is authoritative” inside `AGENTS.md` cannot make that text outrank the agent system prompt: prose cannot promote its own protocol level.

The result is **very likely (80-90%)** that agent text wins a direct model-level collision, supported by those two official runtime descriptions. **UNVERIFIED: the harmless collision smoke test described above would measure the installed runtime/model rather than merely its documented assembly.** A permission rule or blocking hook can still beat both because it is enforced outside model choice; no such enforcement was demonstrated for the finding below.

### Concrete collision

The `codex` agent is expressly a work-unit executor (`codex.md:8-11`) whose subprocess timeout is 30 minutes (`codex.md:50`). For any dispatched Codex unit expected to take more than 60 seconds:

- the contract says it **MUST** use `longrun` plus `run_in_background`/Monitor and must **never** block in the foreground;
- the agent says it must invoke **foreground**, block until completion, and **never** use `run_in_background`, `&`, `nohup`, detached execution, or background mode.

This is not reconciled by `codex.md:52-54`. Those lines correctly identify a possible runner-script transport and even say to put stdin redirection inside a runner that `longrun` calls, but the final `NEVER` at line 101 still bans the background mode the contract requires. “Or invoke directly” also restores the forbidden foreground branch. Both procedures cannot be obeyed for the same >60-second invocation.

The conflict is operationally reachable, not merely theoretical: `inputs/corpus.json:13344-13369` lists custom agents actually invoked and records `"codex": 1` at line 13367. The corpus is distilled and does not preserve enough of that invocation to establish its duration or chosen transport. **UNVERIFIED: inspect the raw transcript corresponding to the sole `agents_invoked.codex` event, or run the harmless >60-second smoke experiment, to determine whether this exact invocation crossed the 60-second threshold and which branch it followed.**

## Root cause and architecture recommendation

The root cause is not the number of rules; it is that `AGENTS.md:115-131` presents an “highest first” table while omitting the one instruction tier that custom agents actually occupy: the custom agent system prompt. That makes a lower-protocol contract describe itself as authoritative over a higher-protocol prompt. The ambiguity stays invisible until two texts disagree.

**Proposal — CONFIG (settings/JSON only):** no JSON-only setting can rewrite this precedence. Therefore CONFIG is insufficient as the sole fix.

**Proposal — NATIVE (Claude Code already does this; we just enable it):** add one short “custom agents” clause to contract §10 and make each custom agent import or restate only the relevant contract invariants without contradicting them. Suggested contract text after `AGENTS.md:123`:

> Custom agent bodies are injected as subagent system prompts and therefore outrank this CLAUDE.md-imported contract at the model message layer. Agent definitions MUST NOT weaken this contract. When an exception is intentional, encode the same explicit predicate and exception on both sides; do not rely on this table to reverse protocol-level precedence.

Then apply the F1 two-line agent edit. This is **very likely (80-90%)** to prevent silent future mis-resolution because it describes the native runtime honestly and puts the actionable invariant in the higher-tier prompt; evidence is Anthropic's subagent/memory documentation and the sole confirmed conflict's shape. **UNVERIFIED: a contract test should synthesize one harmless opposing instruction per relevant tier (agent system, imported CLAUDE memory, delegation prompt), record the chosen marker, and fail when an agent definition weakens a safety/operations invariant.**

This proposal passes the anti-overfit gate. It is prose plus a small contract test riding the existing agent/config path. It does not create a second orchestrator, vector store/KG, durable runtime, trained critic, SaaS, or guardrail framework. A BUILD-LARGE solution is unjustified: native prompt assembly already supplies the mechanism; the defect is contradictory content and a false internal precedence model.
