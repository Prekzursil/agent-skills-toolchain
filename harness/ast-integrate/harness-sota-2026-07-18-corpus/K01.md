# K01 — Per-project context models that grow with the owner

## Executive conclusion

The right design is **not** seven long project summaries and **not** a new memory service. It is a small, typed **project-context protocol** layered onto the canonical stores already in the harness:

1. `basic-memory` remains the canonical semantic store.
2. The event ledger remains the objective, append-only history.
3. A project model is assembled from a stable project identity, explicit cross-project relations, verified beliefs/preferences, and an obligation ledger.
4. Retrieval composes only the relevant slices under a fixed token budget, with a special path for terse prompts.
5. Currency is driven by external receipts (git state, tests, tool output, a second context, or the owner), never by the model deciding that its own summary is correct.
6. Evaluation happens in fresh contexts against gold context packets, so the same model/context that wrote a memory never certifies it.

This is a deliberate evolution of the current minimal architecture, not replacement. The corpus shows that `basic-memory` is already heavily used (`1,332` server touches; `408` writes, `357` searches, `353` reads), while `recent_activity` is used only `30` times (`/local_disk0/codexwork/bundle/inputs/corpus.json:13370-13373`, `:13476-13485`, `:13535`). The deployed rules already define basic-memory as canonical semantic memory and the ledger as objective history (`/local_disk0/codexwork/bundle/claude/AGENTS.md:85-91`). The missing layer is a typed contract for *what a project model means*, how related projects compose, how terse prompts retrieve it, and how external evidence updates it.

The expected overall benefit is **very likely (80-90%)**, based on (a) repeated corpus examples where the owner supplies relationship/state context the agent lacked, (b) a current recall implementation that explicitly ignores prompts shorter than 40 characters, and (c) long-memory research showing that temporal updates and stale-memory rejection remain difficult. The exact reduction in owner corrections is **UNVERIFIED; the settling experiment is Finding 8's fresh-context replay A/B on validated corpus prompts**.

## Architecture constraints and anti-overfit gate

All eight findings use Markdown/JSONL, the existing ledger/basic-memory/recall/skill buses, and deterministic repository/tool receipts. There is **no second orchestration runtime, new vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework**. Basic-memory's already-existing semantic index may be queried, but no new vector/KG system is proposed. Hook accounting is **zero net-new hooks**: changes fold into the existing bounded-recall, event-ledger, and persist-nudge modules or run as explicit skills/offline evaluation commands. Every hook path must wrap its top-level handler in `try/except`, emit nothing on internal error, and exit `0`.

## Finding 1 — Project constellations, not project silos

**Improvement:** Model a project as a stable identity plus explicit, directional relations to other projects and artifacts. Retrieval composes a *constellation* appropriate to the task rather than loading one folder's summary.

**What it is:** A small `project-context/v1` record per stable project ID with:

```yaml
schema: project-context/v1
project_id: git:<normalized-host>/<owner>/<repo>   # fallback: existing projid
aliases: [swfoc_memory, SWFOC editor]
mission: <one durable sentence>
relations:
  - type: produces_for
    target: git:github.com/Prekzursil/SWFOC-Mod-Menu
    artifact_contract: [alamo_engine_kb.json, signatures_phase2.json, lua_binding_map.json]
    status: active
    evidence: <ledger receipt or repository path>
facets: [reverse-engineering, editor-integration, runtime-validation]
valid_as_of: <timestamp>
```

The relation vocabulary stays intentionally small: `produces_for`, `consumes`, `shares_design_system`, `supersedes`, and `independent_of`. This is **not** a knowledge graph: it is a bounded adjacency list embedded in ordinary Markdown front matter.

**Why inferred:** The corpus contains a concrete cross-repository relationship: the owner says the `swfoc_memory` reverse-engineering work “feeds directly” into the separate SWFOC Editor/Mod Menu and names the intelligence artifacts the editor consumes (`/local_disk0/codexwork/bundle/inputs/corpus.json:11831-11834`); a later prompt explicitly switches to the editor repo while requiring the prior RE layer (`:11849-11852`). Independently, the ledger code already solves stable identity across worktrees/subdirectories/case variants (`/local_disk0/codexwork/bundle/claude/hooks/event-ledger/ledger.py:77-84`). The inferred-surprise is that “per-project” isolation would itself lose intent.

**How to build:**

1. Add a `project_context` note type and schema validator to the existing basic-memory capture skill, not a new service.
2. Resolve the active stable ID with the existing `projid`; read at most one direct relation hop. Never recursively traverse relations.
3. Store relations only after an external receipt: matching git remote/path, a referenced artifact that exists, a dependency/config entry, or explicit owner confirmation.
4. At recall, emit a compact `ACTIVE PROJECT / LINKED CONTEXT` packet capped at 500 tokens. Include the relation's evidence pointer so an agent can re-probe it.
5. If two candidate constellations fit, do not guess: use AskUserQuestion once with two concrete interpretations. Cache the answer as an owner-confirmed relation, so the question is not repeated.

**External signal that verifies it:** A deterministic resolver test checks git remote + repository root + named artifact existence; a fresh-context agent receives only “continue the editor integration” and must name both the editor and the upstream RE artifacts. Correct project selection and artifact existence are scored by a separate test runner. Owner confirmation is required only for unresolved aliases or materially different project relations.

**SOTA:** LaMP formalizes personalization as query-specific retrieval from a larger user profile rather than injecting the entire profile ([ACL paper](https://aclanthology.org/2024.acl-long.399.pdf)). LongMemEval separately tests multi-session reasoning, temporal reasoning, updates, and abstention, supporting relational and validity-aware recall rather than a flat summary ([ICLR 2025 paper](https://openreview.net/pdf?id=pZiyCaVuti)).

**Confidence:** This will prevent a meaningful class of wrong-repository/wrong-layer assumptions **very likely (80-90%)**, because the corpus provides a direct cross-repo case and the identity resolver already exists; the magnitude across all seven domains is **UNVERIFIED; replay the cross-project subset in Finding 8 to settle it**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** transformative × medium

**Novelty:** inferred-surprise

**Autonomy:** confirm-first for creating/changing relations; just-do-it for deterministic retrieval of confirmed relations.

## Finding 2 — Correction shadows: remember boundaries, not merely preferences

**Improvement:** Store explicit corrections as scoped, evidence-bearing *negative constraints* alongside positive preferences: “not this mode,” “do not use that repo,” “not later,” “do not stop between tiers.” This prevents the agent from repeatedly falling into the same attractive but wrong interpretation.

**What it is:** A `context_delta/v1` record with `old_assumption`, `corrected_to`, `scope`, `strength`, `evidence`, `valid_as_of`, and optional `expires_when`. Call it a correction shadow because retrieval should surface the disallowed interpretation only as a warning next to the current intent, never as free-standing context that could prime the wrong action.

**Why inferred:** Candidate patterns include “no wrong, I'm in galactic view” and “why did you stop proceed until you finish everything” (`/local_disk0/codexwork/bundle/inputs/corpus.json:10565-10574`), while a full sampled prompt says “now? why would I want it later” (`:11284-11288`). Because the corpus warns that correction candidates are noisy, these are not accepted as corrections automatically. The independent signal is the existing guidance that failure entries must carry falsifiable preconditions and be superseded by contradictory milestones (`/local_disk0/codexwork/bundle/claude/AGENTS.md:28-34`). The owner appears to care as much about remembered boundaries and tempo as about remembered facts.

**How to build:**

1. Extend the existing note/capture schema with `kind: correction_delta`; do not create a new correction detector hook.
2. Accept a correction only from (a) an actual owner-authored turn established by transcript role metadata, (b) AskUserQuestion confirmation, or (c) a deterministic external state contradiction such as the active game mode/tool output. Never ingest the corpus candidate classifier's label as truth.
3. Scope each delta to `owner-global`, `project`, `facet`, or `task`. Default to the narrowest observed scope.
4. Retrieve only if the current candidate action overlaps `old_assumption`; inject one line: `BOUNDARY: not <old>; use <new> [receipt]`.
5. Repeated matching corrections may increase retrieval priority, but never widen scope without owner confirmation.
6. Expire situational corrections automatically when an external state predicate changes; durable taste/tempo changes require the owner to supersede them.

**External signal that verifies it:** A transcript-role parser proves the source was the owner, then a fresh-context model is given a terse prompt whose tempting default matches `old_assumption`. A separate evaluator checks the chosen mode/repo/action against the owner-confirmed `corrected_to` record. For runtime state such as game mode, the tool-reported live state is the deciding signal, not memory.

**SOTA:** Microsoft’s human-AI guidelines explicitly call for learning from user behavior, supporting efficient invocation/dismissal/correction, and maintaining user control; the guidelines were validated with 49 practitioners over 20 AI products ([CHI 2019 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf)). Memora's 2026 benchmark reports frequent reuse of invalid memories and evaluates forgetting-aware accuracy, directly motivating scoped correction and invalidation ([paper](https://arxiv.org/abs/2604.20006)).

**Confidence:** Scoped correction shadows will reduce repeated wrong-default behavior **likely (55-80%)**, supported by the sampled correction-like language and stale-memory research. Automatic extraction quality is **UNVERIFIED; the settling experiment is a 100-item role-validated precision audit, and extraction stays shadow-only until precision reaches the predeclared threshold**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** high × medium

**Novelty:** inferred-surprise

**Autonomy:** confirm-first to persist or broaden a human preference; just-do-it to apply an already owner-confirmed scoped boundary.

## Finding 3 — Obligation escrow: compile OPEN-THREADS into verifiable commitments

**Improvement:** Turn discussed-but-not-finished items into typed obligations with a closure receipt. OPEN-THREADS remains the human-readable surface; the event ledger becomes its objective input. This goes beyond “remembering a topic”: it makes forgetting mechanically detectable.

**What it is:** An `obligation/v1` projection with `thread_id`, `project_id`, `promised_outcome`, `origin_receipt`, `status`, `blocked_on`, `next_external_check`, `children`, and `closure_receipt`. Status is only `open`, `blocked`, or `closed`. “Discussed,” “planned,” and “deferred” remain open states with annotations, never euphemisms for completion.

**Why inferred:** The corpus records a handoff question asking whether work should go to another session while listing a self-contained prompt and scoped-but-not-built follow-ups (`/local_disk0/codexwork/bundle/inputs/corpus.json:11321-11324`). Independently, corpus patterns include requests to continue until finished (`:10565-10570`). The current event ledger already captures goal/decision/failure/milestone types (`/local_disk0/codexwork/bundle/claude/hooks/event-ledger/ledger.py:61-65`), but its compaction checkpoint includes only ten decisions and ten unresolved failures plus `.remember/now.md` (`/local_disk0/codexwork/bundle/agents/harness/modules.py:1475-1512`). A thread can therefore be semantically important without being a failure or one of the last ten decisions.

**How to build:**

1. Extend `note.py` with `--kind obligation` and `--closes <thread_id>`; append to the existing ledger.
2. Generate, never hand-maintain, the machine section of OPEN-THREADS from open obligations. Preserve any existing owner-authored prose section verbatim.
3. A thread closes only with an external receipt type: artifact exists and validates, test/CI terminal success, merged/committed state when requested, owner cancellation, or a successor thread explicitly superseding it.
4. On resume/compact, fold the five highest-priority open obligations into the existing ledger replay packet. Priority is deterministic: explicit owner priority, dependency blockers, oldest unacknowledged, then recency.
5. On Stop, fold a one-line “open obligations remain” notice into **persist-nudge's existing once-per-session lane** only when a newly promised thread lacks a ledger record. No additional hook and no repeated nag.
6. Child tasks cannot close the parent; the parent closes only when its own acceptance receipt exists.

**External signal that verifies it:** A separate projection command recomputes OPEN-THREADS from JSONL and compares IDs/counts both ways. Closure tests deliberately feed prose claims such as “done” without a receipt and require the thread to remain open; then feed a test result/artifact hash/owner cancellation and require closure. A fresh context must list all gold open IDs after compaction.

**SOTA:** Anthropic's long-running-agent harness uses durable progress artifacts so each fresh session can recover what remains, rather than relying on conversational memory ([engineering report](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). After-action review research frames shared human-AI mental-model alignment around replayable episode evidence, consistent with receipt-backed closure rather than self-assessment ([paper](https://arxiv.org/abs/2503.19607)).

**Confidence:** Receipt-backed obligation escrow will materially reduce discussed-then-forgotten work **very likely (80-90%)**, because it closes the exact representation gap between general events and explicit commitments. Its effect on owner stress is **UNVERIFIED; settle it with a four-week count of owner thread-reinstatement corrections versus the prior four-week baseline**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** transformative × medium

**Novelty:** inferred-surprise

**Autonomy:** just-do-it for recording/closing against deterministic receipts; confirm-first for interpreting ambiguous discussion as a promise or treating owner silence as cancellation.

## Finding 4 — Terse-prompt recall lane with facet-conditioned packets

**Improvement:** Make prompts like “continue,” “now?”, “fix this too,” or “switch back” load the active project/task model, rather than being excluded from recall precisely because they are terse.

**What it is:** A second branch inside the existing `RecallModule`, not a new hook. Long prompts continue through lexical retrieval. Short/deictic prompts use session/project state: active project ID, current goal, last unresolved obligation, current facet, and the most recent externally verified context deltas. The packet is capped at 700 tokens and contains receipts.

**Why inferred:** The current recall code returns immediately when a prompt is under 40 characters and also requires at least four non-stopword tokens (`/local_disk0/codexwork/bundle/agents/harness/modules.py:1608-1614`). Yet corpus candidate patterns include very short continuation/correction forms (`/local_disk0/codexwork/bundle/inputs/corpus.json:10565-10574`), and the unit's stated objective is for terse prompts to carry full intent. Separately, basic-memory does not auto-load and current rules rely on the model deciding to query it (`/local_disk0/codexwork/bundle/claude/CLAUDE.md:5-9`). This is the clearest direct functional gap.

**How to build:**

1. In `RecallModule.run`, classify prompts below 40 characters with deterministic shapes only: continuation (`continue`, `proceed`, `now`), deictic repair (`this`, `that`, `again`), context switch (`back`, `switch`), or status (`done?`, `what remains`).
2. For those shapes, load only the current session goal, active project constellation, top open obligation, and latest owner-confirmed correction shadows. Do not semantic-search a one-word prompt.
3. Resolve “this/that” from the last objective ledger turn and tool result, not from an LLM summary.
4. If two referents remain roughly even, ask one two-choice question via AskUserQuestion. This is the only owner interruption; the answer becomes a session-scoped referent receipt.
5. Keep the existing injected-permalink suppression and contradiction-first ranking.
6. Include `context_packet_id` in the ledger so later evaluation can reconstruct exactly what was injected.

**External signal that verifies it:** Replay a role-validated set of terse corpus prompts in fresh sessions. A deterministic scorer checks project ID, active thread ID, linked artifact IDs, and stale-fact rejection against gold records. Compare current recall versus the new lane; promotion requires a preregistered gain with no increase in wrong-project selection and a bounded question rate.

**SOTA:** Anthropic describes context as a finite attention budget and recommends curating the highest-utility context rather than accumulating prose ([context-engineering report](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). LaMP's query-generation → profile retrieval → prompt-construction pipeline is directly analogous to facet-conditioned context packets ([ACL paper](https://aclanthology.org/2024.acl-long.399.pdf)).

**Confidence:** This will improve intent recovery for terse continuation prompts **almost certain (90-99%)**, because the existing implementation deterministically excludes them and the proposed gold replay directly measures the gap. Whether 700 tokens is the best cap is **UNVERIFIED; sweep 300/500/700/1,000 tokens in Finding 8 and select by accuracy/latency, not intuition**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** transformative × low

**Novelty:** user-asked

**Autonomy:** just-do-it, except AskUserQuestion when external state leaves two materially different referents.

## Finding 5 — Evidence-backed belief lifecycle with freshness predicates

**Improvement:** Store project context as beliefs with provenance and expiry conditions, not timeless facts. On retrieval, verify load-bearing volatile beliefs against a different tool before using them.

**What it is:** A `belief/v1` schema:

```yaml
claim: <atomic statement>
kind: fact | owner_preference | hypothesis | decision | constraint
scope: <project/facet/task/global>
confidence_band: <mandated Sherman-Kent phrase>
evidence:
  - type: git | test | tool | owner | file
    receipt: <pointer/hash/command result>
valid_as_of: <UTC>
freshness: immutable | session | until_git_head_changes | until_tool_state_changes | 7d
superseded_by: <permalink or null>
```

**Why inferred:** Current guidance already supports `valid_as_of` and `superseded_by` (`/local_disk0/codexwork/bundle/claude/CLAUDE.md:11`) and current recall boosts contradictions (`/local_disk0/codexwork/bundle/agents/harness/modules.py:1666-1673`, `:1693-1710`), but it does not show a required freshness predicate or external receipt. The corpus contains basic-memory connectivity failures (`/local_disk0/codexwork/bundle/inputs/corpus.json:7490`, `:9633`) and path failures spanning Reframe/momentstudio/SWFOC (`:4497`, `:5553`, `:9556`), so remembered tool/path availability cannot be treated as timeless. Memora independently finds stale-memory reuse to be a current weakness.

**How to build:**

1. Add schema validation to basic-memory capture/edit commands. Old notes remain readable with `freshness: unknown` and rank below receipt-backed notes.
2. Give immutable decisions no time decay but still allow explicit supersession. Give environment/tool/repo facts predicate-based freshness.
3. Before a volatile belief controls an action, execute its named probe through a different tool: `git rev-parse`, file existence, MCP health, test command, process/game state, or owner confirmation.
4. Probe failure does not delete memory; it appends a contradiction event and marks the belief stale. A successful independent probe refreshes `valid_as_of`.
5. If basic-memory is unavailable, fail open to the objective ledger/current repository and label semantic context unavailable. Never ask the owner to reconstruct context until those local sources are exhausted.

**External signal that verifies it:** Mutation tests alter git HEAD, rename a referenced file, disconnect a test MCP, and supersede a decision. A different process runs the freshness probes and verifies that stale beliefs are rejected or downgraded. A second model receives the packet and must abstain from using expired facts.

**SOTA:** LongMemEval explicitly evaluates knowledge updates and abstention ([ICLR paper](https://openreview.net/pdf?id=pZiyCaVuti)); Memora adds Forgetting-Aware Memory Accuracy to penalize obsolete memories ([paper](https://arxiv.org/abs/2604.20006)). Microsoft’s mixed-initiative principles require reasoning about uncertainty and the costs of erroneous action rather than treating inferred goals as certain ([CHI 1999 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)).

**Confidence:** Freshness predicates will reduce stale-context errors **very likely (80-90%)**, supported by existing supersession machinery, concrete volatile-path/tool failures, and two memory benchmarks. The best default TTL by belief kind is **UNVERIFIED; settle it by replaying historical changes and selecting the TTL with the lowest combined stale-use and needless-reprobe rate**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** high × medium

**Novelty:** inferred-surprise

**Autonomy:** just-do-it for cheap read-only freshness probes and deterministic supersession; confirm-first for changing owner preferences or durable architectural decisions.

## Finding 6 — Attention-aware proactive prefetch, silent by default

**Improvement:** Anticipate the next likely context need during natural idle points, but prefetch silently and surface nothing unless it changes a decision or prevents a concrete failure. Proactivity should reduce prompting, not create notifications.

**What it is:** A bounded prefetch queue attached to the existing session/project state. After an external milestone, context switch, or tool completion, it may prepare at most two likely next packets: linked project context, the next unblocked obligation, or freshness probes for the next acceptance check. Prefetched data has a short TTL and is never treated as instruction.

**Why inferred:** The owner repeatedly supplies ordered phase transitions in the SWFOC corpus, including an explicit “Phase 2 delivered. Now switch context to the editor repo” transition (`/local_disk0/codexwork/bundle/inputs/corpus.json:11849-11852`) and sequential tier execution without check-ins (`:11837-11840`). Independently, the corpus shows only 30 `recent_activity` uses despite 1,332 basic-memory server uses (`:13370-13373`, `:13535`), suggesting current memory use is mostly reactive. This proposal addresses prompt fatigue: it does not ask the owner to restate the next phase and does not emit routine alerts.

**How to build:**

1. Implement an explicit `/context-prefetch` skill plus an optional asynchronous branch **folded into the existing event-ledger/persist-nudge dispatch**, not a seventh hook.
2. Trigger only from external events: terminal milestone receipt, owner-confirmed context switch, completed workflow step, or tool result that unblocks a typed obligation.
3. Use declared project relations and obligation dependencies, not model free-association, to choose at most two packets.
4. Store prefetch results in session-local cache with source receipts and 30-minute/default-until-HEAD-change expiry.
5. Surface only when a packet exposes a contradiction, missing dependency, or imminent destructive mismatch. Otherwise it is consumed silently by the next prompt.
6. Apply an expected-utility threshold: act silently for reversible reads, ask for materially divergent choices, never pre-emptively mutate.

**External signal that verifies it:** The next actual owner prompt is held out. Measure whether the prefetched packet matches its gold project/facet and whether time-to-first-correct-action improves. Wrong prefetches must be harmless because they are cache-only. Track notification count and AskUserQuestion count; promotion requires no increase in interruptions per session.

**SOTA:** Horvitz's mixed-initiative work explicitly models goal uncertainty, attention, timing, and the utility of action versus dialog ([Microsoft Research publication](https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/)). ProAct proposes using idle-time compute with dialogue history and persistent memory to prepare evidence for predictable future needs, while also introducing a proactive-agent benchmark ([paper](https://arxiv.org/abs/2605.25971)).

**Confidence:** Silent deterministic prefetch will reduce context-recovery latency **likely (55-80%)**, based on observed phase chains and the mixed-initiative literature. Prediction hit rate and latency on this workspace are **UNVERIFIED; the settling experiment is a shadow-mode next-prompt hit-rate study over 200 project transitions with zero user-visible output**.

**NATIVE-vs-BUILD:** BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

**Value × effort:** high × medium

**Novelty:** inferred-surprise

**Autonomy:** just-do-it for read-only cache preparation; confirm-first for any mutation or materially divergent branch.

## Finding 7 — Per-project autonomy and trust contract

**Improvement:** Store how the owner wants the partnership to behave *by project and action class*, not merely what the project contains. Terse prompts then inherit calibrated autonomy without repeated permission menus.

**What it is:** A small `autonomy_contract/v1` matrix with rows such as `read/research`, `local reversible edit`, `run tests`, `launch app/game`, `external write/PR`, `destructive/irreversible`, and columns `just_do_it`, `confirm_first`, `external_check`, `attention_cost`, `scope`, `owner_receipt`. Global hard safety rules always dominate; a project contract can narrow authority but never grant authority forbidden by the current request or system.

**Why inferred:** The corpus includes both a request for immediate work rather than deferral (`/local_disk0/codexwork/bundle/inputs/corpus.json:11285-11288`) and careful constraints around process cleanup (“be careful not kill active sessions… no hard kill,” `:11291-11294`). The distinction is not simply “autonomous versus cautious”; it is action- and context-dependent. The existing persist-nudge already demonstrates a calibrated-silence, once-per-session design (`/local_disk0/codexwork/bundle/claude/hooks/persist-nudge/nudge.py:9-15`, `:156-171`), which should be reused for confirmation fatigue control.

**How to build:**

1. Capture a contract only from explicit owner choices already made in context or AskUserQuestion. Do not infer permission from enthusiasm, repetition, or historical broad authorization.
2. Start with defaults: read-only/reversible in-scope work = just-do-it; external/destructive/materially divergent action = confirm-first. Store only deviations.
3. Retrieval emits no matrix. It supplies a one-line internal policy receipt only when the candidate action crosses a row boundary.
4. Cache confirmations by exact action class + scope + project, with explicit expiry. Never ask the same settled question again within its validity window.
5. Record outcomes: owner approval/denial and terminal execution result. These external signals calibrate future question timing, but automatic widening of authority is prohibited.

**External signal that verifies it:** A policy test suite feeds action candidates and compares decisions against owner-confirmed rows plus global safety constraints. A separate audit counts unnecessary questions and unauthorized actions. Any unauthorized action is a hard failure; reduced question count is accepted only if hard failures remain zero.

**SOTA:** The 18 Microsoft human-AI guidelines emphasize setting expectations, supporting correction, remembering recent interactions, and providing controls ([CHI 2019 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf)). Beyond Accuracy shows that team performance depends on the human's mental model of where AI succeeds and fails, not accuracy alone ([HCOMP 2019 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2020/01/HCOMP19_mental_models_team_performance.pdf)).

**Confidence:** A scoped autonomy contract will reduce repetitive confirmation while preserving control **likely (55-80%)**, because the corpus shows both urgency and context-specific caution. The optimal expiry policy is **UNVERIFIED; settle it with shadow logs of repeated questions and owner reversals before enabling cached confirmations**.

## Finding 8 — Memory CI: fresh-context, counterfactual evaluation of the project model

**Improvement:** Treat context quality as a tested interface. Every schema/retrieval/update change runs against fresh-context cases, including stale and adversarial memories, before promotion.

**What it is:** A local `context-eval` suite with 100-200 gold cases sampled across BC modding, RE/Hitman/SWFOC, Reframe, momentstudio, WebCoder, drug discovery, and media. Each case contains a terse prompt, allowable project packet, gold active project/facet/threads, forbidden stale beliefs, expected autonomy class, and external receipts. The evaluator runs in a context that did not write the memory.

**Why inferred:** Same-context self-correction is forbidden by this unit's law. Locally, six wrong conclusions came from unvalidated probes, and a seventh was caught only by a known-positive control (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:111-129`). The correction-candidate detector's 41/41 false-positive smoke sample (`/local_disk0/codexwork/bundle/inputs/corpus.json:10371-10374`) is a second, mechanically independent demonstration that attractive mined labels cannot be trusted without controls. The corpus does show broad domain activity—SWFOC/RE and Battle Cats skills appear repeatedly (`:13273-13283`)—so evaluation must be stratified rather than tuned only to Reframe.

**How to build:**

1. Manually validate the first gold set from transcript role + surrounding turns; preserve raw line/file pointers. Include known-positive and known-negative controls for every detector.
2. Metrics: project accuracy, facet accuracy, open-thread recall, stale-belief rejection, correction-shadow precision, unnecessary-question rate, packet tokens, p50/p95 latency, and downstream task receipt success.
3. Run each case in a fresh model context or independent model. The generating context may propose a memory but cannot score it.
4. Add counterfactuals: swap a project alias, supersede a fact, disconnect an MCP, change git HEAD, close one child but not its parent, and inject an agent-authored pseudo-owner message.
5. Require two independent completion signals: structured evaluator fields and deterministic receipt checks. A model judge may be a secondary signal, never the sole oracle.
6. Shadow-test on real sessions before enabling injection. Roll back via existing checkpoint/rollback if wrong-project selection, prompt interruptions, or latency regress.
7. Publish a compact local scorecard; do not add observability SaaS.

**External signal that verifies it:** This finding *is* the external loop: fresh context/different model plus deterministic tool receipts. The suite also proves its detectors on known-present and known-absent controls before making absence claims.

**SOTA:** LongMemEval provides a five-capability long-term memory benchmark and reports a substantial sustained-interaction accuracy drop, supporting task-specific memory evaluation rather than anecdotal recall ([paper](https://arxiv.org/abs/2410.10813)). Memora extends evaluation to consolidation and forgetting/stale-use ([paper](https://arxiv.org/abs/2604.20006)). Microsoft’s guidelines were themselves developed through multiple rounds of expert and practitioner evaluation, reinforcing evaluation of interaction behavior rather than implementation existence ([publication](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/)).

**Confidence:** Fresh-context Memory CI will catch regressions that same-context review misses **almost certain (90-99%)**, based on two independent local detector failures and benchmark precedent. The initial gold-set size needed for stable per-domain estimates is **UNVERIFIED; settle it with bootstrap confidence intervals and expand domains until the interval meets a preregistered width**.

## Quality bar / Definition of Done

The feature is not done because schemas or files exist. It is done only when all of these external conditions hold:

- Every one of the seven named project families has at least two known-positive context cases and one wrong-project counterfactual.
- Every stored project relation has an owner, repo, artifact, or dependency receipt.
- Every closed thread has a closure receipt; a prose “done” cannot close one.
- Every volatile belief has a freshness predicate and a working known-positive probe.
- Terse prompts are no longer dropped solely for being under 40 characters.

## Alternatives rejected

1. **One giant owner profile:** rejected because relevance differs by project/facet and stale facts would contaminate unrelated tasks. LaMP supports query-specific retrieval; local SWFOC evidence shows context composition must be relational.
2. **One summary file per repo:** rejected because SWFOC RE and editor are separate repositories in one intent chain, while worktrees already collapse under stable repo identity.
3. **A new vector DB or knowledge graph:** rejected by the anti-overfit gate and because basic-memory already supplies semantic storage. The proposed adjacency list is bounded metadata, not a graph runtime.
4. **Model-written auto-summary as truth:** rejected by construction. Only external receipts can validate or close beliefs/threads.
5. **Ask the owner at every transition:** rejected as prompt-fatigue regression. Ask only for materially divergent interpretations; cache the confirmed answer in scope.
6. **A seventh proactive hook:** rejected. Prefetch folds into an existing dispatcher or stays explicit.
7. **Mine all 2,268 correction candidates directly:** rejected because the corpus's own controlled smoke sample found 41/41 false positives.
