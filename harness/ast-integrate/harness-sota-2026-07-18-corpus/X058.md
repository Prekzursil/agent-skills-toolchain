# X058 — Cross-domain borrow: control theory → harness observability without a baseline

## Executive judgment

The useful control-theory borrow is **active system identification by persistent excitation, followed by innovation-residual monitoring**. In its own field, this is the answer to a precise problem: passive closed-loop operation often does not excite enough independent dynamics to identify a plant, so the experimenter injects a known, sufficiently rich input, estimates an input/output model, and then tests new observations against that model. Observability analysis first asks whether the proposed measurements can distinguish the state at all; controllability/reachability analysis asks whether available inputs can move the state directions one wishes to learn about.

This transfers only partially. It is **very likely (80-90%)** to provide a defensible *prospective* baseline for harness mechanics, supported by the structural match between known harness interventions and repeated measurable responses, plus control theory's informative-experiment results. It is **almost certain (90-99%)** that it does not reconstruct a missing historical counterfactual or prove whole-task quality from passive telemetry, supported by the fundamental disanalogy that agent tasks, users, and model outputs are neither a known linear plant nor repeatable trajectories. The correct translation is therefore a small, randomized commissioning protocol—not a Kalman-filter-shaped claim that hidden “agent state” has been recovered.

The concrete proposal is a **diagnostic pulse lane**: on safe, pre-consented, replayable work, randomly interleave a small set of known harness perturbations or old/new variants; measure a fixed outcome vector; reject any evaluation whose design matrix is rank-deficient or badly conditioned; build a local reference response from paired observations; then alert on standardized one-step residuals using a dead band and bounded evidence accumulator. The old version is helpful but not required: repeated, known probes create a reference response prospectively. The protocol catches improvements that merely shift costs among retries, latency, correction rate, and tool errors; detectors blind to a changed failure mode; regressions hidden by task-mix drift; and metric controllers that repeatedly “turn the knob” after the harness has hit a constraint.

This proposal passes the anti-overfit gate. It rides existing task-routing, hook/event, and evaluation buses; it needs no second orchestrator, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework.

## 1. What control theory solved in its own field

### 1.1 Observability: distinguishability before estimation

For the continuous-time linear state-space model

\[
\dot{x}(t)=Ax(t)+Bu(t), \qquad y(t)=Cx(t)+Du(t),
\]

an initial state is unobservable over an interval when it produces the same output as the zero initial state for every input. The system is observable if no nonzero state has that property. Frazzoli gives this definition and the familiar finite-dimensional rank condition based on

\[
\mathcal{O}=\begin{bmatrix}C\\CA\\\cdots\\CA^{n-1}\end{bmatrix}.
\]

Full column rank means the output history can distinguish all state directions under the assumed model; a null-space direction is invisible to the sensors. The observability Gramian refines binary rank into practical sensitivity: small eigenvalues correspond to directions that are theoretically visible but require large signal-to-noise ratio to estimate reliably. Åström and Murray, chapter 7, develop observability, state estimation, and Kalman filtering as separate steps, which matters: an estimator does not repair an unobservable measurement design.

The lesson in its own field is not “collect more telemetry.” It is “state the dynamics and the state distinctions that matter, then prove the measurement map separates them.” Two sensors that are functions of the same underlying quantity can add volume without rank.

### 1.2 Controllability/reachability: can an intervention expose the direction?

For the same model, reachability asks whether some input can move the system from the origin to a desired state in finite time. Frazzoli shows that the reachable subspace equals the range of the reachability Gramian and, for the standard continuous-time linear setting, that full rank of

\[
\mathcal{R}=\begin{bmatrix}B&AB&\cdots&A^{n-1}B\end{bmatrix}
\]

is the finite-dimensional test. This is the actuation dual of the sensing question: even a perfect sensor cannot teach the response to a direction the available actuator never excites.

This distinction is critical for evaluation. “We measured no effect” is not interpretable when the treatment did not materially alter the mechanism under test. Control theory forces an **intervention authority audit** before a result is called negative.

### 1.3 Persistent excitation: normal operation is often deliberately uninformative

Closed-loop controllers try to hold a set point and suppress deviations. That very success can destroy information needed to identify the plant. Asada's lecture 17 says this explicitly: real-time input/output data may not uniquely identify a plant because the controlled trajectory may not be rich enough to excite it. The lecture defines an input persistently exciting of order \(n\), gives the equivalent nonsingularity condition for an autocorrelation matrix, and states consistency conditions relating excitation order to the number of model parameters.

The mechanism is:

1. Choose a model class and the parameters/directions that must be distinguished.
2. Design a bounded input with enough independent temporal/frequency content that the regressor covariance is nonsingular and acceptably conditioned.
3. Record both commanded input and actual applied input, plus outputs.
4. Estimate the response and its uncertainty.
5. Refuse identification when excitation or signal-to-noise is inadequate.

This solves a form of “no baseline” by **commissioning one**. It does not infer what an unprobed plant would have done; it creates informative contrast now.

### 1.4 Innovation monitoring: compare observations to conditional predictions

Kalman's 1960 paper formulates recursive filtering and propagates the covariance of optimal linear estimation error under its assumptions. At each update, the estimator forms a prediction from the prior state and known input and corrects it with the new measurement. The difference

\[
\nu_t=y_t-\hat{y}_{t|t-1}
\]

is the innovation or one-step prediction residual. Under a correct linear-Gaussian model, its covariance is computable and the normalized innovations have a specified reference behavior. Persistent bias, excess variance, or serial structure is therefore evidence that the assumed plant, noise, or sensor behavior has changed.

This is stronger than comparing today's global mean with an arbitrary historical mean. It compares each observation with the output predicted for its known input and estimated context. Page's 1954 cumulative inspection scheme provides the adjacent idea of accumulating small, same-direction deviations for sequential change detection instead of requiring one huge excursion. NIST's control-chart discussion makes the design trade-off explicit: tighter limits detect more but also increase false searches for assignable causes; the limit is a decision about risk, not a natural constant.

### 1.5 Stability, anti-windup, and dead bands: the measurement loop can damage what it measures

A performance monitor becomes part of a feedback controller once its output triggers automatic harness changes. The controlled quantity then depends on the monitor's previous decisions. Åström and Murray separate stability analysis, stability margins, and integrator windup because a controller that performs acceptably in a nominal model can oscillate or behave badly under delay, uncertainty, and actuator saturation.

Integrator windup occurs when integral error keeps accumulating even though the actuator is saturated and cannot deliver the requested action; when the system re-enters the controllable region, stored integral state drives overshoot and slow recovery (§10.4). Anti-windup implementations clamp the integrator or feed back the gap between requested and applied control. A dead band or hysteretic decision region suppresses reaction to changes too small to distinguish from noise, at the cost of reduced sensitivity. These are not measurement tricks; they are protections against a noisy, delayed, constrained feedback loop.

## 2. The concrete translation: an actively commissioned harness monitor

### 2.1 Translation table

| Control-theory object | Harness analogue | Required record |
|---|---|---|
| Plant | model + tools + harness + task/user environment | versioned environment fingerprint |
| Latent state \(x_t\) | task difficulty, context pressure, tool health, provider drift, policy mode | explicit state hypothesis; never a generic “agent quality” scalar |
| Input \(u_t\) | harness variant, feature toggle, retry budget, prompt/rule treatment, injected safe fault/probe | commanded and actually applied treatment |
| Output \(y_t\) | completion/acceptance, owner correction, retry count, tool-error vector, latency, tokens/cost, invariant-test result | raw event plus derived metric provenance |
| Disturbance \(w_t\) | task mix, service incidents, user interruption, external data changes | task strata and incident/context covariates |
| Sensor noise \(v_t\) | stochastic sampling, judge disagreement, incomplete labels | repeated runs or label reliability estimate |
| Observability | outcomes can distinguish the failure/state hypotheses | rank/conditioning or empirical sensitivity audit |
| Controllability | safe treatments can actually perturb the mechanism | treatment compliance/effect-on-mediator check |
| Persistent excitation | randomized, bounded, sufficiently diverse diagnostic treatments | assignment seed, probabilities, coverage matrix |
| Innovation | observed outcome minus context-conditional prediction | residual and predicted covariance |
| Saturation | rate/cost/risk ceiling; no more treatment can be applied | requested-versus-applied action and constraint reason |
| Anti-windup | stop accumulating “need to intervene” while constrained | clamped evidence state or back-calculation |
| Dead band | no rollout/rollback for effects inside practical + statistical indifference zone | predeclared thresholds and hysteresis state |

The mapping should use a **vector outcome**, not a single score. A scalar reward makes latency savings, tool reliability, correctness, and owner burden commensurable only by hidden weights; it also makes compensating regressions invisible.

### 2.2 Commissioning sequence

#### UNVERIFIED — Proposal A: diagnostic pulse lane — NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

Add a thin experiment-assignment and event-annotation layer to an existing routing/evaluation path. It selects only replayable or explicitly safe tasks, hashes a task-family stratum plus a random seed, and assigns one of a small number of bounded treatments. Examples include old versus candidate harness policy, feature off versus on, or a no-op control versus a known harmless probe. It records assignment, actual exposure, and outcome vector in an append-only evaluation record.

The recommendation is **very likely (80-90%)** to reduce false before/after conclusions when candidate and control can be interleaved, supported by random assignment balancing time-varying task mix in expectation and by persistent-excitation theory's insistence on informative inputs. The exact magnitude is **UNVERIFIED; settle it with Experiment E1**, a retrospective synthetic-drift simulation followed by a prospective shadow/canary trial measuring bias and interval coverage.

The lane must have four gates:

1. **Safety/reversibility:** no random perturbation on irreversible external writes, security decisions, financial/legal/medical outputs, or unconsented user-visible behavior. Prefer shadow replay, duplicated read-only execution, fixtures, or sandbox tasks.
2. **Treatment compliance:** log requested and actual treatment. If a feature flag is bypassed, an old-version runner fails, or a policy does not reach the relevant code path, the observation cannot estimate that treatment.
3. **Coverage:** before evaluating, require each important task stratum and treatment to have minimum support.
4. **Information:** compute singular values or condition number of the treatment/context design matrix. Mark an effect non-identifiable when columns are aliased or weak; do not convert it to “no effect.”

“Persistent excitation” does **not** mean adding arbitrary noise to production prompts. It means maintaining independent, bounded contrasts sufficient for the explicitly chosen effect model. A two-arm randomized variant may be sufficient for a single average treatment effect; temporal pseudo-random patterns are relevant only when estimating lag or carryover.

#### UNVERIFIED — Proposal B: empirical observability/controllability certificate — NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

For each claimed improvement, require a machine-readable certificate:

```yaml
hypothesis: candidate reduces quote-related shell failures without raising task failure
treatment: quote_policy_v2
actual_exposure_field: policy_version_seen_at_shell_call
task_strata: [shell, platform, command_length_bucket]

```

The certificate uses an empirical sensitivity matrix rather than pretending a trustworthy global \(A,B,C,D\) model exists. Rows are measured outcomes; columns are controlled treatments or known diagnostic fixtures; entries are estimated local response contrasts. A zero/near-zero column means the treatment failed to move measured mediators (weak controllability or noncompliance). Nearly collinear columns mean the outcomes cannot distinguish two hypotheses (weak observability). Small singular values warn that noise will be greatly amplified.

It is **likely (55-80%)** that this certificate will catch “telemetry-rich but inference-poor” evaluations, supported by the exact rank/conditioning analogy and common aliasing in multivariate designs. That harness-frequency claim is **UNVERIFIED; settle it with Experiment E2**, independently label 50 prior evaluation proposals for identifiability, run the certificate rules blind, and report precision/recall plus adjudicated misses.

This is intentionally a gate, not a dashboard. Its valuable output can be “not identifiable under this experiment.”

#### UNVERIFIED — Proposal C: innovation chart with dead band and bounded accumulator — NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

Fit the smallest adequate conditional reference on commissioned data, for example:

\[
y_t = \beta_0 + \beta_1\,\text{candidate}_t + \gamma^T\text{stratum}_t + \delta^T\text{time-block}_t + \epsilon_t.
\]

For count/binary/heavy-tailed outcomes, use a distribution appropriate to the data or distribution-free randomization/bootstrap intervals; do not force a Gaussian Kalman filter. Produce cross-fitted or held-out predictions and standardized residuals. Monitor residual vectors separately by task family and treatment. Accumulate only deviations outside both:

* a statistical uncertainty boundary, and
* a predeclared practical-effect dead band.

Use two-sided accumulation because improvement in one direction can accompany regression in another. Reset or decay evidence after an adjudicated regime change; never silently merge pre- and post-change reference periods.

The alerting rule is **likely (55-80%)** to detect small persistent regressions earlier than isolated threshold alarms at a matched false-alarm budget, supported by Page's sequential accumulation mechanism. Its calibration on autocorrelated, nonstationary harness data is **UNVERIFIED; settle it with Experiment E3**, inject known mean/variance/tail changes into block-resampled traces and compare delay at fixed empirical false alarms against static thresholds.

#### UNVERIFIED — Proposal D: anti-windup rollout controller — NATIVE-vs-BUILD: CONFIG (settings/JSON only)

If alerts automatically change rollout share, impose:

* a maximum step size per review interval;
* a maximum cumulative rollout change without a fresh independent evaluation window;
* explicit saturation reasons (risk ceiling, insufficient sample, cost cap, unavailable control runner);
* integrator clamping while saturated or while treatment compliance is false;
* a cooldown at least as long as the measured response/carryover window;
* asymmetric hysteresis: stronger evidence to expand than to hold, and strong safety evidence to roll back quickly;
* manual approval for any new treatment class or outward-facing irreversible action.

The policy is **very likely (80-90%)** to prevent repeated automation actions caused solely by accumulated stale evidence when a rollout is capped, supported by the direct structural equivalence to actuator saturation and integral windup. Whether settings alone can express these states in the actual harness is **UNVERIFIED; settle it with Experiment E4**, map the current rollout interface and run a saturation simulation that asserts requested action, applied action, accumulator state, and release behavior.

### 2.3 How this creates a baseline when none exists

There are four cases, and the proposal is honest in only three:

1. **Old and candidate both runnable:** randomized concurrent paired/canary execution creates the strongest prospective control. Block by time and task family; where safe, replay the same fixture/task against both.
2. **Only candidate runnable, but known probes exist:** repeated no-op and diagnostic fixtures estimate noise, drift, and sensitivity. This baselines mechanics, not comparative quality.
3. **No old runner and no trusted probes, but rollout can be varied:** randomized rollout intensity can estimate local dose/response if exposure is logged and interference is limited.
4. **Only passive post-change logs, no controls/probes/variation:** control theory does not solve the counterfactual. One may describe levels and detect self-change after enough stable observations, but cannot attribute improvement to the harness change. The correct artifact is “effect not identified,” not a reconstructed baseline.

The method is **almost certain (90-99%)** to distinguish these cases mechanically if assignment, actual exposure, and probe identity are required fields, supported by direct field validation rather than model inference. It is **UNVERIFIED in this harness; settle it with Experiment E5**, create fixtures for all four cases and verify the evaluator emits comparative estimate, mechanical baseline, dose-response estimate, and non-identifiable respectively.

## 3. What it catches that ordinary telemetry misses

### 3.1 Task-mix Simpson effects

A global error rate can improve because easier tasks arrived after a rollout. Randomized concurrent assignment within task/time blocks estimates a contrast under the same mix. The design would catch a candidate that looks better globally but is worse within every stable stratum.

This catch is **very likely (80-90%)** when assignment is concurrent and treatment compliance is high, supported by the experimental contrast; it is **UNVERIFIED for the owner's traffic distribution; settle it with E1**, which explicitly injects composition drift.

### 3.2 “Sensor says fixed” while the failure migrates

A detector-specific metric may fall because errors changed form, moved to another tool, or were converted into extra retries. A vector output and diagnostic fixtures observe conservation-like displacement across error class, retries, task acceptance, latency, and owner correction. The observability certificate rejects an evaluation whose only sensor is the exact pattern the change suppresses.

It is **likely (55-80%)** to expose failure migration, supported by measuring multiple independent consequences rather than one signature. Coverage against novel failure modes is **UNVERIFIED; settle it with Experiment E6**, mutation-test detectors by generating semantically equivalent failures with changed surface forms and score end-to-end outcome detection.

### 3.3 Treatment did not reach the plant

A feature may be assigned but never exercised: the task never calls the tool, a cache serves the response, or the rollout flag fails to propagate. Requested-versus-applied input plus a mediator check marks this as noncompliance/weak controllability rather than “no benefit.”

This catch is **almost certain (90-99%)** for instrumented bypasses, supported by two directly compared fields (assignment and actual exposure). Completeness of exposure instrumentation is **UNVERIFIED; settle it with E5** by deliberately bypassing each treatment path and verifying the certificate refuses an effect.

### 3.4 Slow regression below per-event thresholds

A small persistent residual may never cross a static alert limit on one event. A bounded CUSUM-style accumulator can surface same-direction evidence over time. Conversely, a practical dead band prevents automation from chasing changes smaller than the owner cares about.

This catch is **likely (55-80%)** at a fixed false-alarm rate, supported by the sequential mechanism; realized benefit under dependence and seasonality is **UNVERIFIED and belongs to E3**.

### 3.5 Rollout windup and oscillation

If a monitor repeatedly asks for “more intervention” while cost/risk limits prevent further action, accumulated state can trigger a large overshoot when the constraint clears. Logging requested and applied actions, clamping evidence, cooldown, and hysteresis expose and prevent that loop pathology.

Prevention is **very likely (80-90%)** for the explicitly modeled saturation path, supported by anti-windup mechanics. Unmodeled alternate automation paths remain **UNVERIFIED; settle them with E4** by fault-injecting each rollout constraint and checking no accumulator grows while action authority is absent.

### 3.6 An observer that is confidently wrong

Innovation checks test model adequacy. Residual bias, serial correlation, stratum dependence, or variance inflation says the reference model no longer explains observations. The monitor then degrades to “model invalid / re-commission,” rather than emitting narrow confidence from a stale model.

This is **likely (55-80%)** to catch common mean/variance/dependence misspecification, supported by residual diagnostics. It is **almost certainly not (1-5%)** a guarantee against all shared-mode model and sensor failures, supported by the fact that residual tests see only recorded outputs. E3 settles power only for the injected fault family; no finite experiment proves universal detection.

## 4. Adversarial analysis of the analogy

### 4.1 Structural assumptions that do transfer

1. **Known interventions and measured responses:** feature toggles, policy variants, routing shares, and fixture faults are inputs; tool events and task outcomes are outputs. This is the strongest isomorphism.
2. **Dynamics and delay:** retries, context accumulation, caches, and rollout effects can create lag and carryover, so time ordering matters.
3. **Partial sensing:** latent task difficulty and provider health affect multiple observed metrics but are not directly observed.
4. **Constraints:** safety, cost, rate, and user-impact caps are real actuator saturation.
5. **Feedback:** once evaluation changes routing or configuration, observations are policy-dependent; passive data are no longer exogenous.

The overall claim that these similarities are sufficient for a bounded commissioning protocol is **very likely (80-90%)**, supported by the explicit input/output/intervention structure. They are insufficient for literal linear-state recovery, as discussed next.

### 4.2 Disanalogies that prohibit a literal observer

1. **No stable plant boundary.** The “plant” includes a changing foundation model, provider, tools, network, task mix, and human owner. Its transition law is neither known nor stationary.
2. **State is constructed, not physical.** “Task difficulty” or “agent confusion” has no unique coordinate system. Different latent models can generate the same observations; state-space realizations are generally non-unique even in linear identification.
3. **Actions alter the data-generating policy.** A harness change changes which tools are attempted and which errors can appear. Missing errors may mean prevention, avoidance, or detector blindness.
4. **Tasks are heterogeneous and often non-repeatable.** A production task may involve external state and human judgment; replay can be contaminated or unsafe.
5. **Outputs are heavy-tailed, censored, delayed, and strategically optimized.** Owner corrections are selective; acceptance may arrive late; a scalar judge can be gamed.
6. **Interference violates unit independence.** Cache warming, shared quotas, provider incidents, and learned user behavior can make one assignment affect another.
7. **The counterfactual is causal, not merely state-estimation.** Observability says whether a state is distinguishable under an assumed model. It does not identify what the same task would have done under a treatment not received without experimental or causal assumptions.

Therefore, the literal proposal “fit a Kalman filter to telemetry and call its hidden vector agent health” **almost certainly does not transfer (90-99%)**, supported by violations of known dynamics, linearity/Gaussianity, stable state semantics, and sensor completeness. It should be rejected.

### 4.3 Where persistent excitation can itself be harmful

Persistent excitation trades performance for information in physical control too; in a harness it can expose users to worse variants or consume duplicated compute. A diagnostic pulse must be bounded, pre-consented where user-visible, and restricted to safe strata. If no safe intervention can excite a claim-relevant mechanism, that claim is not controllable in production and must be tested in replay/sandbox or remain unverified.

It is **roughly even (45-55%)** that shadow replay alone predicts live user-visible benefit for semantically complex tasks; evidence for this exact transfer is absent by design in this ideation unit, and replay omits user interaction and live external state. This premise is **UNVERIFIED; settle it with Experiment E7**, correlate preregistered shadow effects with subsequent safe randomized canary effects across at least ten heterogeneous changes, reporting calibration rather than only correlation.

### 4.4 Why this is not “control theory cosplay”

The transfer retains three falsifiable constraints from the source field:

* no state/effect claim without a distinguishability/information test;
* no negative effect claim without proving that the applied input reached and excited the mechanism;
* no automatic feedback without modeling delay, constraint saturation, and noise.

It deliberately discards the source field's unjustified assumptions: no global linear state model, no Gaussian-optimality claim, no universal state observer, and no promise that residual whiteness proves task quality.

### 5.2 Refusal-oriented decision states

The evaluator should emit one of these states before any “better/worse” label:

1. `NO_SAFE_EXCITATION` — claim cannot be probed in scope.
2. `TREATMENT_NOT_APPLIED` — assignment/exposure mismatch.
3. `INSUFFICIENT_SUPPORT` — too few observations in relevant cells.
4. `RANK_DEFICIENT` — effects/hypotheses aliased.
5. `WEAK_INFORMATION` — conditioning or signal-to-noise below threshold.
6. `MODEL_INVALID` — residual diagnostics fail.
7. `PRACTICALLY_EQUIVALENT` — interval lies inside the practical dead band.
8. `EVIDENCE_OF_BENEFIT`, `EVIDENCE_OF_HARM`, or `MIXED_TRADEOFF` — vector result with uncertainty.

`PRACTICALLY_EQUIVALENT` is not the same as failure to reject. It requires an equivalence margin chosen before observing results and enough precision for the effect interval to lie inside it.

## 6. Verification program

All forward claims above name a settling experiment. This section makes those experiments executable in sequence.

### E1 — synthetic drift plus prospective canary

Create block-resampled task streams, inject a known treatment effect and independently vary task-family proportions over time. Compare naive pre/post, concurrent randomized, and paired-replay estimators on bias, root-mean-square error, and interval coverage. Then run one safe real candidate/control canary. Acceptance: the chosen estimator has preregistered coverage near its nominal target and does not reverse the injected effect under composition drift. This settles baseline and Simpson-effect claims, not external validity to all task types.

### E2 — identifiability certificate audit

Two reviewers independently label 50 historical *evaluation designs* (not their results) for assignment validity, exposure evidence, rank aliasing, and measurable claim scope. Resolve disagreements without showing certificate output. Compare tool decisions against adjudication; publish false positives and false negatives. Include known-present positive controls: a fully randomized two-arm fixture with logged exposure and a deliberately aliased design. These controls validate the detector before any absence conclusion.

### E3 — sequential-monitor calibration

Block-bootstrap commissioned residuals to preserve short-range dependence. Inject mean shifts, variance shifts, heavy-tail bursts, and seasonal drift at preregistered points. Compare static limits, bounded CUSUM/Page-style accumulation, and a no-alert control at the same empirical false alerts per 1,000 tasks. Report detection-delay distributions and missed-change rates. Separately test model-invalid transitions; do not score every shift as a rollout regression.

### E4 — saturation and anti-windup fault injection

In a sandbox, drive an alert while imposing each constraint: rollout ceiling, cost cap, disabled variant, failed exposure, and review cooldown. Assert two mechanically independent signals for constraint behavior: (a) requested-versus-applied action records and (b) independent configuration/runner state. The evidence accumulator must clamp or back-calculate and must not release a stored surge after the constraint clears.

### E5 — four-case identifiability fixture

Construct: dual runnable variants; candidate plus trusted probe; varied rollout dose; and passive-only post-change logs. Verify outputs are respectively comparative estimate, mechanics-only reference, local dose-response estimate, and non-identifiable. Add deliberate flag bypasses to validate exposure checks.

### E6 — detector mutation test

Seed semantically equivalent failures with altered strings, tool surfaces, retry paths, and terminal manifestations. Compare fingerprint-only metrics with the vector outcome and fixture invariant. This tests migration detection without assuming every novel failure can be enumerated.

### E7 — replay-to-live transport study

Across at least ten heterogeneous, preregistered changes, estimate effect in shadow replay before looking at live outcomes, then run safe randomized canaries. Assess sign agreement, calibration slope, and interval coverage by task family. A weak relationship limits replay claims; it does not justify increasing live excitation.

## 7. Alternatives considered and rejected

### Rejected: reconstruct a synthetic historical baseline from current telemetry

Without overlap, probes, or stable causal assumptions, this creates a model-dependent counterfactual that cannot be validated from the same post-change data. It is **almost certainly not (1-5%)** a defensible attribution method in the general harness setting, supported by nonstationarity and no untreated contrast. Narrow interrupted-time-series use could be valid with long stable prehistory, but that contradicts the “no baseline” case.

### Rejected: one global “harness health” Kalman filter

The scalar/vector hidden state would be semantically arbitrary, and changing task mix or policy changes the observation equation. A filter can smooth metrics; it cannot make the state identifiable. Rejection confidence is **almost certain (90-99%)**, supported by the observability/model-boundary disanalogy.

### Rejected: dashboard-first observability platform

More charts do not create intervention contrast or rank. It also risks the explicitly rejected observability-SaaS/second-runtime class. The proposed certificate and evaluator should emit small files/events on existing buses.

### Rejected: permanently inject random prompt noise

It has weak semantic control, can degrade user outcomes, and does not necessarily excite the mechanism of interest. Use explicit bounded variants or fixtures whose causal target is known.

### Rejected: auto-tune dozens of harness knobs online

This creates a high-dimensional adaptive controller with interference, delayed labels, and weak identifiability. It violates the minimal-architecture intent even if built on the event bus. Start with one factor or a small orthogonal design and human-reviewed decisions.

### Rejected: dead band alone

A dead band suppresses chatter but cannot distinguish noise from bias, create a baseline, or detect cumulative small harm. It belongs after commissioning and uncertainty estimation.

## Bottom line

Control theory's valuable answer is not a fancier dashboard or a magical observer. It is a discipline: **first make the system informative by safe, known excitation; prove the interventions and measurements span the claim; estimate a local response with uncertainty; monitor innovations; and constrain the feedback loop with dead bands and anti-windup.** This gives a harness a prospective baseline where passive history has none.
