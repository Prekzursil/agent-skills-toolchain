# X112 — Cross-domain borrow: reliability engineering → synthesis

## Executive verdict

**The borrow transfers, but only qualitatively and only as a two-direction analysis.** The useful reliability-engineering mechanism is a **top-down fault tree reduced to minimal cut sets, audited by a bottom-up FMEA-style coverage pass, with explicit common-cause groups and sensitivity analysis**. In its native field, this converts a large component/failure inventory into the smallest combinations that can cause a specified top event. In an agent harness, it can convert thousands of findings into a small set of decision-failure paths while retaining links back to every atomic claim and its evidence.

The proposed harness version must **not** multiply “confidence” numbers or report a synthetic probability of making the wrong decision. Physical component failures can sometimes be treated as repeated stochastic events with calibrated rates; audit claims are correlated, defeasible epistemic objects. The Boolean structure transfers; the usual probability arithmetic generally does not.

My confidence that this **bounded qualitative transfer** is useful is **very likely (80-90%)**, based on three mechanically different signals: (1) NASA describes fault-tree analysis (FTA) as a top-down Boolean decomposition that exposes multiple-failure combinations and minimal cut sets; (2) NASA describes FMEA/FMECA as a bottom-up analysis of failure modes, effects, detection, propagation, and mitigation; and (3) IAEA common-cause guidance requires shared-root dependencies to be modeled rather than silently treated as independent. The remaining uncertainty is whether agent-produced findings can be normalized into stable enough predicates without excessive human adjudication. That premise is **UNVERIFIED; the settling experiment is the shadow evaluation in “Validation experiment,” using a held-out completed audit and blinded decision review**.

This is not a proposal for another orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework. It is a bounded transformation and report on the existing artifact/hook/skill bus.

## 1. The reliability-engineering mechanism in its own field

### 1.1 FTA starts with the loss that matters, not the document pile

Fault-tree analysis begins with a precisely defined undesired **top event**, defines the system and analytical boundaries, and works downward through intermediate events to basic events connected by Boolean AND/OR logic. NASA’s PRA procedure describes the same three layers—top event, intermediate faults, and basic events—and says the model is simplified with Boolean reduction rules before quantification ([NASA NPR 8705.5, §2.6](https://nodis3.gsfc.nasa.gov/displayAll.cfm?Internal_ID=N_PR_8705_0005_&page_name=ALL)). The NRC’s canonical *Fault Tree Handbook*, NUREG-0492, presents FTA as a deductive method for complex-system reliability analysis and covers construction, Boolean algebra, and qualitative and quantitative evaluation ([NRC NUREG-0492 landing page](https://www.nrc.gov/reading-rm/doc-collections/nuregs/staff/sr0492/index); [OSTI bibliographic record](https://www.osti.gov/biblio/5762464)).

That direction matters. FTA does not ask a decision maker to read every failure report and intuit an aggregate conclusion. It asks, for example, “What combinations can cause loss of thrust termination?” and only expands branches causally relevant to that top event.

### 1.2 Minimal cut sets are the compression operator

A **cut set** is a set of basic events sufficient to produce the top event. A **minimal cut set** (MCS) is sufficient but contains no removable member: if any event is removed, that particular route no longer guarantees the top event. NASA states that MCSs identify all distinct ways the top event can occur in terms of basic events ([NASA *Fault Tree Handbook with Aerospace Applications*, Chapter 3 and Appendix A](https://extapps.ksc.nasa.gov/reliability/Documents/Fault_Tree_Handbook_with_Aerospace_Applications_August_2002.pdf)). NASA’s system-engineering reference says cut-set analysis supports structural significance, item significance, and qualitative common-cause vulnerability, even if the analyst stops before probability determination ([NASA, *System Engineering Tools and Techniques*, §3.6.3](https://extapps.ksc.nasa.gov/Reliability/Documents/SystemEngineeringTools_and_Techniques.pdf)).

This is the specific answer to “how can a decision be made without reading 12 MB?” Reliability engineering does not compress by summarizing every sentence equally. It first defines the adverse outcome, then performs Boolean reduction so that a large tree becomes a set of irreducible causal combinations. The decision-facing view is the set of dominant/singleton/low-order cut sets; the full tree and basic-event evidence remain drill-down material.

The compression is not magically bounded. NASA warns that a fault tree with more than 100 events and mixed AND/OR structure can produce more than one million MCSs; production tools therefore use bounds or cutoffs ([NASA aerospace FTA handbook, discussion of large-tree truncation](https://extapps.ksc.nasa.gov/reliability/Documents/Fault_Tree_Handbook_with_Aerospace_Applications_August_2002.pdf)). This warning transfers directly: an unrestricted “finding graph” can be larger and less legible than its source corpus.

### 1.3 FMEA supplies the opposite-direction completeness challenge

FMEA/FMECA works bottom-up. NASA defines FMEA as a systematic inductive analysis that identifies failure modes at a prescribed level and traces their effects; FMECA adds relative mission risk/criticality ([NASA-HDBK-8709.22, definitions](https://ntrs.nasa.gov/api/citations/20180004878/downloads/20180004878.pdf?attachment=true)). NASA Goddard’s active 2024 guideline treats FMECA as a living risk assessment updated as design, operations, and knowledge change ([GSFC-HDBK-8004](https://standards.nasa.gov/standard/GSFC/GSFC-HDBK-8004)). NASA training material describes its purposes as identifying failures, propagation, detection/isolation/mitigation, and tracking corrective actions ([NASA GSFC FMECA slides](https://extapps.ksc.nasa.gov/reliability/Documents/FMECA_slides.pdf)).

FTA and FMEA therefore cover different failure directions:

| Native method | Starts from | Follows | Main synthesis value |
|---|---|---|---|
| FTA | specified system-level loss | backward to contributing combinations | focuses the decision and produces irreducible paths |
| FMEA/FMECA | component/function failure modes | forward to local, subsystem, and mission effects | challenges whether the top-down tree omitted an initiating mode |

NASA’s software engineering handbook explicitly contrasts bottom-up SFMEA with top-down software FTA ([NASA Software Engineering Handbook, §8.05](https://swehb.nasa.gov/spaces/SWEHBVD/pages/102695706/8.05%2B-%2BSW%2BFailure%2BModes%2Band%2BEffects%2BAnalysis)). The combination is important because FTA alone only explores top events and contributors that analysts foresee.

### 1.4 Common-cause analysis prevents fake redundancy

Reliability engineers do not assume that two nominally separate protections are independent. The IAEA defines common-cause failures as multiple failures from shared root causes and recommends four stages: logic-model development, identification of common-cause component groups, common-cause modeling/data analysis, then quantification and interpretation with uncertainty and sensitivity analysis ([IAEA-TECDOC-648, §2](https://www-pub.iaea.org/MTCD/Publications/PDF/te_648_web.pdf)). NRC analysis notes that dependent failures defeat both redundancy and diversity, can be subtle, and are sparsely observed ([NUREG-1150, Vol. 2, Appendix C](https://www.nrc.gov/sites/default/files/doc_library/cdn/legacy/reading-rm/doc-collections/nuregs/staff/sr1150/v2/sr1150v2appc.pdf)).

The practical rule is: model known shared dependencies explicitly; do not count them as independent basic events and also hide them inside an aggregate common-cause factor. IAEA guidance recommends a dependency matrix to make shared support systems and intersystem dependencies reviewable ([IAEA Safety Reports Series guidance](https://www-pub.iaea.org/MTCD/Publications/PDF/Pub1139_scr.pdf)).

For synthesis, this is at least as valuable as cut-set reduction. Ten agents repeating one claim from the same detector, prompt, source paragraph, or generated intermediate artifact are not ten independent confirmations. They are redundant channels with a common power supply.

## 2. Concrete translation to an agent harness

### 2.1 UNVERIFIED proposal — define decision failures as top events

Do not create one giant tree called “bad harness.” Define a small, explicit top-event set per decision. For a harness redesign decision, use:

1. **T1 — Adopt a change whose expected net value is negative.**
2. **T2 — Reject or omit a change whose expected net value is materially positive.**
3. **T3 — Select an architecture that contains a critical single point of failure.**
4. **T4 — Treat correlated evidence as independent corroboration.**
5. **T5 — Present a decision as supported when a decision-critical premise remains unverified.**

These are decision hazards, not probabilities. Each top event is decomposed into intermediate events such as wrong factual premise, missing relevant failure mode, invalid causal translation, unmodeled dependency, infeasible implementation, benefit/cost inversion, and evidence becoming stale.

This top-event set is **UNVERIFIED; the recommendation heading therefore is “BUILD-SMALL prototype — UNVERIFIED top-event coverage.” The settling experiment is to take 20 known decision errors/corrections from a held-out audit, blind the tree designers to 10, and test whether the frozen top-event taxonomy and decomposition represent at least 8 of those 10 without adding a new top event after seeing them**. The threshold is a proposed acceptance criterion, not a measured result.

### 2.2 UNVERIFIED proposal — normalize every finding as a typed basic event, not a prose summary

**Proposal — BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus):** add a post-audit `compile-decision-tree` step that reads agents’ existing Markdown/JSON artifacts and emits a typed JSONL inventory plus a compact Markdown decision packet. No daemon and no new database.

Each atomic finding becomes a record with at least:

```text
finding_id
claim (one falsifiable proposition)
claim_type: observed | inferred | forecast | recommendation
polarity: supports | contradicts
decision_node_ids
evidence_locator: path:line | command output id | URL
evidence_kind: runtime | static | corpus | external | experiment
source_agent / source_prompt_family / upstream_artifact_ids
detector_or_method
scope and boundary
confidence_band + evidence_for_band
verification_state + settling_experiment
native_build_tag
common_cause_domains[]
status: open | accepted | rejected | superseded
```

The compiler should reject records that lack a stable evidence locator, decision-node linkage, or required honesty fields; rejection means “not decision-admissible,” not deletion. The original artifact remains available.

It is **likely (55-80%)** that this typed boundary will expose claims that are rhetorically strong but decision-inadmissible, because required evidence, polarity, uncertainty, and lineage become machine-checkable. The evidence is structural: those fields are explicit inputs to the decision tree rather than optional prose. The realized catch rate is **UNVERIFIED; settle it by running the compiler over one completed audit and manually classifying a stratified sample of 200 accepted/rejected records for false rejection and false admission**.

### 2.3 UNVERIFIED proposal — compile qualitative gates and minimal decision cut sets

**Proposal — BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus):** compile a declarative YAML/JSON tree into reduced qualitative cut sets. The first version needs only AND, OR, and explicit `UNKNOWN` leaves. It must preserve provenance and polarity, and it must not calculate a top-event probability.

Example:

```text
T1 adopt harmful change
  OR
  ├─ A: benefit is overstated
  │    AND
  │    ├─ A1: claimed defect is not established
  │    └─ A2: proposal depends on that defect
  ├─ B: cost/risk is understated
  │    AND
  │    ├─ B1: proposal is BUILD-LARGE or creates a second runtime
  │    └─ B2: operational burden has no measured bound
  └─ C: mitigation is defeated by a shared cause
       AND
       ├─ C1: two checks are counted as diverse
       └─ C2: they share detector, evidence source, or model/prompt lineage
```

The decision packet should show, in this order:

- singleton and two-event cut sets;
- cut sets containing an `UNKNOWN` decision-critical leaf;
- cut sets whose apparent redundancy collapses after common-cause grouping;
- contradicted cut sets (supporting and defeating evidence side by side);
- structural importance: how many top-event paths contain a basic event;
- counterfactual leverage: which one experiment, if resolved, defeats or confirms the most live cut sets;
- the full provenance map as drill-down, not in the executive page.

It is **very likely (80-90%)** that singleton and low-order cut sets are more decision-actionable than a flat ranked list, because they state the smallest jointly sufficient failure arguments and directly identify single points. This follows from the definition and native use of minimal cut sets in the NASA and NRC handbooks. Whether the automatically compiled gates preserve the intended semantics is **UNVERIFIED; settle it with two independent human reviewers reconstructing 30 sampled cut sets from source evidence and scoring logical equivalence**.

### 2.4 UNVERIFIED proposal — add an evidence-dependency matrix, the synthesis equivalent of common-cause groups

**Proposal — BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus):** derive a dependency matrix from existing provenance fields and require explicit adjudication before multiple records may be called corroboration.

Candidate common-cause domains are:

- same raw source or same quoted passage;
- same intermediate summary or copied finding;
- same detector/query/regex/parser;
- same model family and materially identical prompt;
- same execution environment or unavailable dependency;
- same owner assertion used as premise;
- same unverified assumption;
- same clock/configuration snapshot;
- same evaluator or adjudicator.

Two findings sharing a domain remain useful, but the report labels them **replications**, not independent evidence. Diversity credit requires a different failure mechanism: for example, runtime observation plus static inspection, or independent data field plus a calibrated detector control.

It is **very likely (80-90%)** that explicit lineage grouping will prevent some false corroboration, because the IAEA/NRC common-cause principle directly matches the structure “multiple apparently redundant channels share one hidden upstream cause.” The strength of this match is causal, not metaphorical. The prevalence and decision impact in this harness are **UNVERIFIED; settle them by selecting 100 multi-agent agreement clusters, tracing their raw provenance, and measuring how often the effective independent-source count falls after grouping**.

### 2.5 UNVERIFIED proposal — use bottom-up failure modes as the coverage backstop

**Proposal — CONFIG (settings/JSON only):** require each domain unit to emit not only findings that support a proposal, but a short FMEA-style row for every in-scope mechanism:

```text
function → failure mode → local effect → decision-level effect
→ detection/control → residual unknown → corrective experiment
```

After the top-down tree is built, a separate coverage pass maps every bottom-up row to at least one tree node or records it as intentionally out of scope with rationale. This is not a second critic model; it is a different analysis direction on the existing agent bus.

It is **likely (55-80%)** that the two-direction pass will catch omissions that a pure top-down decomposition misses, because NASA explicitly identifies FMEA as bottom-up and FTA as top-down, and NASA’s FTA guidance says the method presumes analysts have foreseen the relevant undesirable events and contributors ([NASA FTA appendix, limitations and thoroughness](https://nodis3.gsfc.nasa.gov/displayCA.cfm?Internal_ID=N_PR_8621_0001_&page_name=AppdxI35)). The actual incremental recall is **UNVERIFIED; settle it by comparing blinded omission discovery for FTA-only versus FTA-plus-FMEA on the held-out correction set**.

### 2.6 UNVERIFIED proposal — rank experiments, not unsupported “risk probabilities”

**Proposal — BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus):** calculate only discrete structural measures in v1:

- cut-set order (number of required leaves);
- top-event coverage count;
- number of live cut sets removed if a premise is falsified;
- number of live cut sets confirmed if a premise is verified;
- evidence diversity count after common-cause collapse;
- staleness/verification state.

Do not compute `severity × occurrence × detectability`, MTBF, or a percentage “decision reliability.” NASA’s aerospace handbook’s probability examples explicitly rely on independence assumptions; audit claims usually violate them ([NASA aerospace FTA handbook, probability evaluation example](https://extapps.ksc.nasa.gov/reliability/Documents/Fault_Tree_Handbook_with_Aerospace_Applications_August_2002.pdf)). If later calibration data exist, use sensitivity ranges and show which decisions change over the range rather than one point estimate.

It is **almost certain (90-99%)** that omitting pseudo-probability avoids false numerical precision, because there is no identified repeatable event population or calibrated independent base rate for these epistemic claims, while the native multiplication rule assumes independence. It is only **likely (55-80%)** that structural leverage is the best replacement prioritizer; the evidence is its direct relationship to live decision paths, but human value/cost judgments still matter. This prioritization premise is **UNVERIFIED; settle it by comparing structural-leverage ordering with blinded expert ordering and subsequent experiment outcomes on at least 30 disputed premises**.

## 3. What this would catch that flat synthesis tends to miss

The following are **predicted catches, not claims that the present harness lacks all of them**. Their presence in the owner’s current workflow is **UNVERIFIED; the named experiment is a retrospective run over the current audit artifacts, with a human adjudicator checking each surfaced case against source evidence**.

1. **Critical single-premise decisions.** A one-leaf cut set shows that a recommendation fails if one unsupported premise is true. A prose executive summary can bury that premise among dozens of supporting observations. Catch confidence: **very likely (80-90%)**, because singleton cut sets are an explicit FTA output.

2. **Combinations of individually minor findings.** Two low-severity issues can jointly cross a decision boundary. FMEA row ranking may leave both low; an AND gate exposes the combination. Catch confidence: **likely (55-80%)**, because it depends on analysts encoding the correct interaction.

3. **False multi-agent consensus.** Five findings can collapse to one effective source when they share the same raw artifact, detector, or prompt-derived premise. Catch confidence: **very likely (80-90%)**, provided lineage is recorded; without lineage it is **unlikely (20-45%)**.

4. **A shared dependency defeating “diverse” checks.** A static check and a runtime check may both consume the same broken manifest or generated index. The dependency matrix exposes the shared support node. Catch confidence: **likely (55-80%)**, because explicit shared inputs are detectable; semantic shared assumptions are harder.

5. **Contradiction hidden by lossy summarization.** Supporting and defeating findings attach to the same leaf with polarity rather than being averaged into a vague paragraph. Catch confidence: **likely (55-80%)**, conditional on proposition normalization.

6. **Decision-critical unknowns.** An unverified premise remains an `UNKNOWN` leaf inside a live cut set and the packet names the experiment that resolves the most paths. Catch confidence: **very likely (80-90%)**, because the schema makes unknowns first-class and forbids silently treating them as false.

7. **Scope holes.** A bottom-up failure-mode row that maps to no top-down node signals either a missing branch or a documented exclusion. Catch confidence: **likely (55-80%)**, limited by the completeness of the FMEA pass itself.

8. **Mitigation that does not break the failure path.** A proposed control can be tested against cut sets: if every cut set remains live, it does not prevent the top event as modeled. Catch confidence: **very likely (80-90%)** for modeled paths, but it says nothing about omitted paths.

9. **Architecture burden masquerading as reliability.** A BUILD-LARGE proposal may add monitoring and recovery yet introduce a new single point or shared dependency. Modeling the proposal and baseline with the same top events exposes path substitution rather than counting features. Catch confidence: **likely (55-80%)**, because the result depends on honest boundary selection.

## 4. Adversarial transfer analysis

### 4.1 Structural similarities that make the borrow real

The analogy is structurally sound in four respects:

- Both domains contain many low-level observations but only a few decision-level losses.
- Both contain conjunctive causation: several conditions can be jointly sufficient even when none is sufficient alone.
- Both contain hidden dependencies that make nominal redundancy non-independent.
- Both need traceability from an executive decision back to atomic evidence.

These similarities support the Boolean/provenance transfer. Confidence: **very likely (80-90%)**, based on the direct mapping of top events, AND/OR combinations, shared upstream causes, and evidence leaves.

### 4.2 Disanalogies that prohibit a literal PRA transplant

**First, failures are events; findings are propositions.** A pump fails or does not fail during a defined mission. A claim can be partly scoped, ambiguous, superseded, contradicted, or true only under a configuration. Treating claim truth as a binary component state destroys semantics. The harness must normalize narrow propositions and preserve scope/time; unresolved cases remain `UNKNOWN`.

**Second, evidence is non-monotonic.** New evidence can retract or reinterpret an earlier finding. Classic static FTA usually assumes a fixed model for the analysis snapshot. The agent tree therefore needs versioned status and regeneration, not a durable “truth graph.”

**Third, probabilities are not portable.** Component reliability may be estimated from populations, tests, mission time, and failure-rate models. Agent confidence bands are judgments and are often correlated. Multiplying them would be unjustified. This is why the proposal is qualitative in v1.

**Fourth, the top event is value-laden.** “Core damage” is comparatively crisp. “Best harness” depends on owner goals, operating cost, latency, model evolution, and risk tolerance. Top events and decision thresholds must be owner-approved; the compiler cannot discover them objectively.

**Fifth, analyst omission dominates.** NASA explicitly says FTA presumes that relevant top events and contributors have been identified and cannot guarantee identification of all failures ([NASA FTA appendix](https://nodis3.gsfc.nasa.gov/displayCA.cfm?Internal_ID=N_PR_8621_0001_&page_name=AppdxI35)). A neat tree can create a dangerous illusion of completeness. The bottom-up coverage pass and out-of-scope register reduce but do not remove this risk.

**Sixth, cut-set explosion is severe.** The native method already exceeds a million MCSs in some trees. Natural-language propositions add aliases, contradictions, and context. The harness must cap depth/order for the executive view, expose truncation counts, and retain the unreduced model for audit. It must never imply “all paths” if a bound was applied.

**Seventh, causality is often disputable.** A physical schematic constrains which valves and power supplies connect. A synthesis tree can encode an analyst’s rhetoric as causality. Each gate therefore needs a plain-language rationale and an independently reviewable truth table/example.

These disanalogies mean a full probabilistic reliability model for synthesis is **very unlikely (5-20%)** to be valid without a long calibration program. Evidence: native quantification depends on defined event probabilities and independence, while agent findings lack those properties. A qualitative structural model is **very likely (80-90%)** to retain useful value because minimal sufficiency and shared dependency do not require numeric probabilities.

### 4.3 Failure modes introduced by the proposed borrow

The proposal itself needs an FMEA:

| New failure mode | Effect | Detection/control |
|---|---|---|
| Top events framed to favor a preferred architecture | dissent disappears from the tree | owner-approved top-event contract; red-team top-event review |
| One compound sentence becomes one “basic” event | hidden conjunction and weak evidence | atomicity lint; reviewer must be able to negate the claim cleanly |
| OR used where AND is required, or vice versa | false minimal cut sets | gate rationale plus two-reviewer logical-equivalence sample |
| Common-cause grouping too aggressive | genuinely diverse evidence discounted | keep raw records; report both raw and effective counts; allow reasoned override |
| Common-cause grouping too weak | fake corroboration | provenance-derived groups plus manual semantic audit |
| MCS explosion triggers silent truncation | decisive path omitted | hard failure unless the report names bound, omitted count/estimate, and coverage |
| Structural importance mistaken for owner value | wrong prioritization | keep consequence/value decision separate and human-owned |
| Schema rejection hides awkward findings | biased packet | rejected-record appendix and rejection-rate audit |
| Tree becomes a permanent knowledge system | stale model and operational burden | regenerate from source artifacts; no database; delete/rebuild output freely |

It is **likely (55-80%)** that gate-semantics errors and compound “basic” events will be the dominant prototype defects, based on the difference between crisp component states and natural-language findings. This forecast is **UNVERIFIED; settle it by coding every adjudicated prototype error and comparing category counts after the first held-out run**.

## 5. Minimal implementation design and anti-overfit gate

### 5.1 UNVERIFIED proposal — artifact contract

**Proposal — CONFIG (settings/JSON only):** add a small `decision-node` block to research-unit output templates and require stable finding IDs. Units continue writing normal artifacts. They do not call a new service.

**Proposal — BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus):** a stateless compiler performs:

1. parse frontmatter/JSONL finding blocks;
2. validate evidence and honesty fields;
3. resolve aliases only when explicitly declared;
4. create common-cause groups from provenance keys;
5. reduce declared AND/OR trees to bounded low-order MCSs;
6. render a decision packet and machine-readable appendix;
7. fail loudly on unknown gates, cycles, or unreported truncation.

If an exact MCS implementation cannot stay below roughly 200 lines, use an existing small Boolean-expression library already present in the environment or limit the prototype to order-3 enumeration. Do not build a solver service. Library availability is **UNVERIFIED; settle it with an environment inventory before implementation**.

### 5.2 UNVERIFIED proposal — decision packet constrained to what a human needs

**Proposal — CONFIG (settings/JSON only):** cap the executive packet at:

- one page: candidate decisions, top events, and owner thresholds;
- two pages: singleton/low-order cut sets and common-cause collapses;
- one page: highest-leverage settling experiments;
- one page: disagreements, unknowns, scope exclusions, and truncation disclosure;
- appendices: full tree, all findings, rejected records, provenance, and validation stats.

The page cap is **UNVERIFIED; the settling experiment is a timed blinded review comparing this packet with the existing long-form synthesis on decision accuracy, confidence calibration, and source-trace time**. The recommendation is **likely (55-80%)** to reduce reading burden because Boolean reduction removes supersets and the executive view limits itself to live low-order paths, but an exact reduction has not been measured here.

### 5.3 Anti-overfit judgment

The design passes the stated anti-overfit gate:

- It rides the existing artifact, prompt/template, skill, and hook bus.
- It is stateless and regenerated; it is not a second orchestration runtime.
- It stores no vector database, knowledge graph, or durable workflow state.
- It trains no critic and requires no always-on evaluator.
- It uses no observability SaaS or guardrail framework.
- Its compiler can be removed without changing the agents that produced the original evidence.

This assessment is **almost certain (90-99%)** for the design as specified, based on the explicit architecture above. Whether an implementation stays within these bounds is **UNVERIFIED; settle it by an implementation review that counts executable lines, dependencies, persistent processes, storage systems, and new lifecycle commands before adoption**.

## 6. Validation experiment

The recommendation should remain a shadow-mode prototype until it passes this test.

### Phase A — frozen retrospective design

1. Select one completed large audit with source artifacts, final decisions, and later owner corrections.
2. Split known corrections/decision errors into design and held-out halves.
3. Define top events and tree templates using only the design half.
4. Freeze taxonomy, gates, compiler, cut-set bound, and packet format.

### Phase B — independent construction and controls

5. Run the compiler on all audit artifacts.
6. Have Reviewer A inspect source-to-leaf atomicity/evidence.
7. Have Reviewer B independently inspect gate logic and common-cause grouping.
8. Include known-present detector controls before accepting any claim that a class of finding is absent.
9. Preserve all rejected and unparsed records so recall can be measured.

### Phase C — blinded decision comparison

10. Give one blinded panel the compact decision packet and another the baseline synthesis, with equal time.
11. Measure: held-out correction recall, false alarms, final decision agreement with later adjudication, time to first decision, time to trace a claim to evidence, number of false-independent corroborations, and number of decision-critical unknowns surfaced.
12. Swap materials after a washout period to reduce reviewer-skill confounding.

### Proposed acceptance rule

Adopt only if the packet is non-inferior on adjudicated decision accuracy and held-out correction recall, reduces median review time by at least 30%, introduces no silent truncation, and correctly labels at least 90% of sampled provenance dependencies. These thresholds are **UNVERIFIED design targets; the experiment above settles them and should report confidence intervals, not merely pass/fail**.

I assess the chance that the prototype clears all four thresholds on its first iteration as **roughly even (45-55%)**. Evidence for caution: the reliability mechanism is mature, but natural-language atomization, gate semantics, and provenance quality are novel bottlenecks. I assess the chance that the experiment produces useful diagnostic information even if the prototype fails as **very likely (80-90%)**, because every failure is classified at an explicit boundary: extraction, evidence admissibility, dependency grouping, gate logic, cut-set reduction, or human decision use.

## 7. Alternatives considered

### FMEA/RPN spreadsheet alone — reject

It is tempting to assign severity, occurrence, and detectability scores to every finding and sort. This preserves the thousands-of-rows problem, hides conjunctive causes, and invites false precision. FMEA is valuable here as the bottom-up coverage challenge, not the final compression operator. Rejection confidence: **very likely (80-90%)**, based on the mismatch between a flat row ranking and the target need to expose jointly sufficient combinations.

### Pure LLM “executive summary” — retain only as rendering, not decision logic

An LLM can phrase the final packet, but unconstrained summarization does not guarantee preservation of contradictions, dependencies, or minimal sufficient paths. Use it after the structured packet is compiled, with every sentence linked to node IDs. Confidence: **likely (55-80%)**, based on the structural requirements; comparative loss rates are **UNVERIFIED and should be measured in the blinded experiment**.

### Knowledge graph/vector database — reject under anti-overfit gate

Those systems may support retrieval, but retrieval is not the main unsolved operation here; deciding which combinations are sufficient for a decision failure is. They add a persistent subsystem and reintroduce explicitly rejected architecture. Rejection confidence: **very likely (80-90%)**, based on scope and the owner’s anti-overfit constraint, not a universal claim that such systems never help.

### Full probabilistic PRA / Bayesian network — reject for now

This would require calibrated priors/likelihoods, dependency structure, and a stable event population. Those prerequisites are absent from this unit’s evidence; I do **not** claim they are absent from every owner dataset. Their availability here is **UNVERIFIED; settle it by searching for calibration studies that map agent confidence and evidence classes to later adjudicated truth**. Until such data exist, numeric outputs would look more rigorous than they are. Rejection confidence for v1: **almost certain (90-99%)**.

### Multiple independent synthesizer agents voting — insufficient alone

Redundancy without causal diversity is vulnerable to common-mode error. Multiple agents remain useful if their source, detector, and reasoning method differ and lineage is visible; a vote count alone is not evidence independence. Confidence: **very likely (80-90%)**, supported by the native common-cause literature’s treatment of shared-root failure.

## 8. Final recommendation

### BUILD-SMALL (<~200 lines, rides the existing hook/skill/artifact bus) — UNVERIFIED shadow prototype

Build a stateless **qualitative fault-tree synthesis compiler** with four non-negotiable properties:

1. decision-level top events and explicit analytical boundaries;
2. atomic evidence-linked findings compiled through AND/OR/UNKNOWN gates into bounded minimal cut sets;
3. provenance-based common-cause grouping so replicated evidence is not counted as independent corroboration;
