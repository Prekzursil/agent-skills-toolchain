## Executive verdict

`performance.md` is not a coherent executable policy. Its build-recovery tail is mostly useful, but the file combines four unrelated control planes—model routing, context-window admission, reasoning configuration, and build recovery—under a code-file path filter. That makes the ostensibly global model and reasoning policy unavailable exactly when a research/orchestration dispatch occurs without a matching source file. The active agent roster also pins three agents to Sonnet while this rule assigns every substantive research/orchestration task to Opus and gives Sonnet no role at all. The active hook bus observes subagent identity and outcomes, but it does not carry selected-model or context-occupancy fields and therefore cannot enforce the rule's two central thresholds.

The high-confidence resolution is evolution, not a replacement runtime: split the file into an unscoped, single-source routing/admission rule and a code-scoped build rule; align the existing agent frontmatter and native settings; and extend the existing hook event envelope only if measurement proves valuable. This is **very likely (80-90%)**, because every proposed change rides the existing rule/settings/hook buses, the current bus is already wired for `SubagentStart`, `PostCompact`, and build-claim checks (`settings.json:419-440`; `agents/harness/modules.py:1302-1378,2000-2027,2331-2420`), and no second orchestration runtime is needed. The remaining uncertainty is whether Claude exposes the selected model and live context occupancy to hooks; that premise is **UNVERIFIED; the settling experiment is to capture redacted native payloads for one `SubagentStart`, one `PreCompact`, and one `PostCompact` event on the Windows host and inspect their documented fields**.

I found 13 reportable collisions: 2 CONTRADICTION, 4 REDUNDANCY, 4 UNENFORCED, 2 UNRULED, and 1 STALE. The count excludes skill-content collisions because the required live skill trees were not included in the remote bundle; treating the cached skill index as the skills themselves would violate the evidence standard.

This is a badly written rule, not evidence that the quality-first preference is wrong. It is **almost certain (90-99%)** that splitting scope will improve policy availability, because the mismatch is syntactic and visible in the same file (`performance.md:1-31`); the residual 1-10% is unknown Claude rule-loading behavior outside the unpacked snapshot.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing rule bus):** create an unscoped `model-and-reasoning-policy.md` containing routing, context admission, and critique thresholds; leave `performance.md` code-scoped with build recovery (or rename it `build-performance.md`). ### C02/C03/C04/C05 — three competing model policies and no enforcement field

The target establishes only two operational classes: Opus for all substantive work and Haiku for trivial mechanical steps (`performance.md:25-35`). * `docs-lookup` performs current-document research and returns code examples (`agents/docs-lookup.md:2-16`), squarely inside the target's “research” category.
* `loop-operator` monitors and intervenes in autonomous loops and has `Edit` permission (`agents/loop-operator.md:2-21`), squarely inside orchestration.
* `intent-drift-sentinel` is deliberately bounded, read-only, and isolated (`agents/intent-drift-sentinel.md:2-10`); it is a plausible Sonnet exception, but the policy never defines such an exception.

The cross-vendor rule repeats the Opus dispatch floor (`cross-vendor-dispatch.md:48-53`) and the Codex adapter repeats it a third time (`agents/codex.md:99-105`). Repetition is already drifting: a future edit can change one of three copies.

The shared event model cannot enforce routing. `AgentEnvelope` contains only `id`, `type`, and `transcript_path` (`agents/harness/models.py:18-22`); normalization pulls only those identity fields (`adapters.py:94-107,141-145`). A model argument may remain buried in raw `tool.input`, but no module shown interprets it. Thus the rule is enforceable statically in agent frontmatter but not dynamically through the present normalized hook bus.

This behavior indicates “badly written and partly unenforceable,” not “wrong.” The corpus has no model-choice or task-complexity field, so it cannot compare Sonnet vs Opus quality. Any claim that Opus caused better outcomes here would be **UNVERIFIED; the settling experiment is a blinded, repeated task set with objective postconditions and selected-model telemetry**.

**Resolution — CONFIG (settings/JSON only):** retain `settings.json:77` as the root default and define the Sonnet fallback at `:78-80` explicitly as availability fallback, not quality routing. This is **very likely (80-90%)** to eliminate ambiguity, because the current JSON already separates `model` and `fallbackModel`; evidence is `settings.json:77-80`.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing rule/agent bus):** store one routing matrix and lint/generate every first-party agent `model:` value. Use Opus for `docs-lookup` and `loop-operator` unless the owner explicitly accepts a bounded Sonnet exception; retain Sonnet for `intent-drift-sentinel` only if the matrix names the exception. This is **very likely (80-90%)** to prevent recurrence, because pinned frontmatter is the actual dispatch control and the roster is only 18 files; evidence is the complete anchored count above.

**UNVERIFIED resolution — BUILD-SMALL (<~200 lines, rides the existing hook bus):** if native `SubagentStart` payloads expose selected model and fallback reason, add them to `AgentEnvelope` and ledger them. ### C10/C11/C13 — build recovery has a correct router but an unbounded worker

The target's four-step sequence—use resolver, analyze, fix incrementally, verify after each fix (`performance.md:68-72`)—is concise. Section 10 resolves this one: AGENTS wins.

The resolver does contain useful boundaries: minimal diffs/no architecture changes (`build-error-resolver.md:11-20`), final success requires compiler/build/test evidence (`:97-103`), and test failures route to `tdd-guide` (`:105-111`). `testing.md` independently routes test failures to the same agent (`testing.md:40-49`). The unresolved boundary is a build command whose failure is actually a test assertion.

Hooks enforce only the terminal claim layer. `ClaimWarningModule` recognizes claims that builds compile/pass (`modules.py:2000-2027`), while no normalized event action can spawn `build-error-resolver` or verify each intermediate fix (`models.py:18-39`). This is not necessarily bad—routing is better kept advisory than hard-blocked—but the rule must not imply mechanical enforcement.

**Resolution — BUILD-SMALL (<~200 lines, rides the existing agent/rule bus):** amend the resolver workflow to fingerprint failures, apply the AGENTS two-strikes pivot, and return `FAILED:<id>` with alternatives when it cannot converge. Define compile/type/module/config failures as resolver-owned and assertion/isolation/mock failures as TDD-guide-owned. This is **almost certain (90-99%)** to eliminate the textual contradiction because the higher-precedence contract already specifies the exact stop condition (`AGENTS.md:51-57`).

**Resolution — NATIVE (Claude Code already does this; we just enable it):** keep hook checks at final-claim time and use ordinary agent routing for build ownership. Do not add a build daemon or durable-execution engine. This is **very likely (80-90%)** the minimal architecture because `ClaimWarningModule` and the specialized agents already exist (`modules.py:2000-2027`; `build-error-resolver.md:1-20`).

### C12 — performance-related hook thresholds have no policy owner

The subagent lifecycle hook injects a one-line I-PASS read-back (`modules.py:2370-2382`), treats output under 20 characters as hollow (`:2384-2396`), and declares a transcript stalled after 25 minutes (`:2398-2420`). These are unruled enforcements: the hook is the only place an operator can learn their thresholds.

The 20-character threshold is especially weak as a quality proxy: a 21-character non-evidentiary string passes, while a short terminal receipt can be meaningful. The module exempts `SUCCESS:`/`FAILED:` receipts first (`modules.py:2331-2334,2384-2387`), which mitigates but does not validate the residual heuristic. Its value is **UNVERIFIED; the settling experiment is to label a stratified sample of SubagentStop messages around 0-100 characters for substantive/evidentiary quality and compute precision/recall for the current predicate**.

**UNVERIFIED resolution — BUILD-SMALL (<~200 lines, rides the existing hook/rule bus):** expose the 25-minute stall timeout and hollow-output predicate as named policy values in the hook manifest/config, with prose in the canonical subagent contract. This is **likely (55-80%)** to improve coherence because it turns hidden constants into inspectable policy, but the best values remain unverified; settle them with the labeled-output study and frozen-transcript incident distribution before changing defaults.
