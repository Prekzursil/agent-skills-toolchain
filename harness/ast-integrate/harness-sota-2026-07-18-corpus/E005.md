# E005 — Ecosystem survey: Agent Skills published by Anthropic

Date of survey: 2026-07-19 UTC  
Unit: E005  
Scope: Anthropic-published Agent Skills, not the wider community ecosystem  
Subject policy: read-only; this unit changed no harness file or configuration

## Executive verdict

Anthropic's public `anthropics/skills` repository currently contains 17 top-level skills. It is not a uniformly maintained product catalog. It is three materially different things in one repository:

1. an actively maintained `claude-api` reference skill;
2. four source-available document skills (`docx`, `pdf`, `pptx`, `xlsx`) whose repository README says they power Claude's document capabilities in production; and
3. twelve examples, most of which are frozen demonstrations rather than maintained operational components.

The repository itself makes this distinction: it calls most entries demonstrations, warns users to test them, and labels the four document skills source-available rather than open source ([repository README](https://github.com/anthropics/skills#about-this-repository)). The current tree enumerates all 17 names ([skills tree](https://github.com/anthropics/skills/tree/main/skills)). The repo remains active: its main history shows repeated `claude-api` updates through 2026-07-01, and path histories show `docx`, `pptx`, and `xlsx` updates on 2026-07-17 ([repository commits](https://github.com/anthropics/skills/commits/main/), [docx history](https://github.com/anthropics/skills/commits/main/skills/docx), [pptx history](https://github.com/anthropics/skills/commits/main/skills/pptx), [xlsx history](https://github.com/anthropics/skills/commits/main/skills/xlsx)).

The adoption decision for this owner is narrow:

- Replace the owner's stale duplicated `claude-api` guidance with Anthropic's current single-purpose plugin. This is the strongest adoption.
- Keep the already-enabled official `skill-creator`, but use its paired evaluation loop—not its one-shot generation path. Independent SkillsBench evidence finds curated skills helpful and skill-creator-generated packs harmful on all three tested dedicated harnesses.
- Enable the official `frontend-design` skill selectively for real frontend work, with a local paired evaluation before making it globally active.
- Steal two small patterns into existing lanes: the `webapp-testing` reconnaissance-before-action protocol and the `mcp-builder` realistic-evaluation protocol. Do not install the entire 12-skill example bundle.
- Keep the proprietary document bundle disabled by default and enable it only for an actual Office/PDF deliverable. Do not fork, redistribute, or transplant its code as though it were Apache-licensed.

This selective plan is **very likely (80-90%)** to improve freshness and task-specific procedure without worsening catalog sprawl. Evidence: only 78 of roughly 355 installed skills were observed as invoked, the official marketplace is already registered, `skill-creator` is already enabled, `document-skills` and `frontend-design` are disabled, and `claude-api` was invoked only five times in the corpus (`/local_disk0/codexwork/bundle/inputs/corpus.json:13249-13320`; `/local_disk0/codexwork/bundle/claude/settings.json:586,605,614,665-669`). The remaining uncertainty is actual outcome delta on this owner's tasks; the settling experiment is the paired canary described in each recommendation.

### Quality rubric

“High quality” here means more than polished prose. I scored evidence in this order:

1. current substantive maintenance rather than a license-only touch;
2. narrow, discriminating trigger description;
3. executable helpers or references loaded progressively instead of one huge universal prompt;
4. deterministic verification of the produced artifact or behavior;
5. documented real failure modes and recovery paths;
6. an evaluation loop or production-use evidence;
7. licensing usable for the intended adoption mode.

Popularity was not a quality signal. GitHub stars describe repository attention, not task-level lift. SkillsBench is the stronger external signal: on 87 tasks and 18 model/harness configurations, curated skills raised mean pass rate from 33.9% to 50.5%, but the gain varied by stack; focused packs of at most three modules beat larger/exhaustive bundles ([paper abstract and results](https://arxiv.org/html/2602.12670#S5)). That directly supports selective adoption and directly opposes installing all examples.

## Which are high quality

### Tier 1: `claude-api`

This is the clearest operational-quality skill. Its current `SKILL.md` is 578 lines/73,938 bytes but routes into language-specific and topic-specific files rather than loading its entire reference set indiscriminately. It explicitly treats model/API memory as stale, requires documented SDK shapes, separates raw HTTP from official SDK usage, and points to live primary sources ([skill](https://github.com/anthropics/skills/blob/main/skills/claude-api/SKILL.md)). Its path history shows frequent substantive maintenance, including model updates, code-execution changes, platform availability, auth, token counting, and Managed Agents changes through July ([history](https://github.com/anthropics/skills/commits/main/skills/claude-api)).

For this owner, freshness matters more than breadth. The existing local copy was already audited as mislabeled and stale: it called a Messages API poll loop “Claude Agent SDK,” while the real Agent SDK imports `claude_agent_sdk.query` (`/local_disk0/codexwork/bundle/inputs/audit-findings/D26.md:41-43`). The corpus shows the skill was actually invoked five times (`corpus.json:13287`). That makes replacement concrete, not speculative.

Weakness: its trigger description is exceptionally broad and tells the agent to inspect provider markers before reading the target file. A 578-line router plus a large reference tree can still consume attention or collide with provider-neutral work. The skill also documents Anthropic Managed Agents, which this harness must not mistake for an architectural recommendation.

### Tier 1: `docx`, `pptx`, `xlsx`

These are the most mature executable skills. They encode concrete format footguns and require artifact-level verification. Examples:

- `docx` requires rendering and visual inspection and provides OOXML/package validators ([skill](https://github.com/anthropics/skills/blob/main/skills/docx/SKILL.md)).
- `pptx` requires content QA, package validation, and full-resolution visual QA, and documents corruption modes such as invalid color encodings and shared mutable option objects ([skill](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md)).
- `xlsx` requires recalculation, zero formula errors, formula rather than hardcoded result use, and visual review ([skill](https://github.com/anthropics/skills/blob/main/skills/xlsx/SKILL.md)).

The README says these skills power Claude's document capabilities in production, and three received updates two days before this survey. Those are independent production and maintenance signals. Their proprietary license prevents treating them as a general cross-provider harness library.

`pdf` belongs to the same production family but is a tier lower in the public repository. It is primarily a broad recipe guide, and its path history is older ([skill](https://github.com/anthropics/skills/blob/main/skills/pdf/SKILL.md), [history](https://github.com/anthropics/skills/commits/main/skills/pdf)). It is **likely (55-80%)** still useful for ordinary PDF operations because it covers pypdf, pdfplumber, ReportLab, command-line tools, OCR, forms, and encryption, but its local incremental value is UNVERIFIED; the settling experiment is a ten-task corpus with malformed, scanned, encrypted, form, and mixed-table PDFs, graded on content accuracy and file validity.

### Tier 1 for method, not autonomous output: `skill-creator`

The official skill has a real iterative workflow: baseline prompts, runs with the candidate, qualitative review, quantitative graders, variance analysis, a result viewer, revision, larger test sets, and description optimization ([skill tree](https://github.com/anthropics/skills/tree/main/skills/skill-creator), [skill](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)). This is much stronger than structural YAML validation.

However, the independent result is decisive: SkillsBench's self-generated condition first used Anthropic's `skill-creator`, then solved with the generated packs. It fell below no-skills by 8.1 percentage points on Claude Code + Opus 4.7, 11.3 on Codex + GPT-5.5, and 11.5 on Gemini CLI + Gemini 3.1 Pro. The audit attributed failures to nondiscovery, creation displacing solving, and confidently wrong content; the paper itself reports those trajectory findings ([SkillsBench result](https://arxiv.org/html/2602.12670#S5.SS1.SSS1.Px5)). Thus the evaluation loop is high quality, while one-shot generate-and-auto-enable is not.

### Tier 2: `frontend-design`

This is short, focused, and recently revised. It grounds design in a concrete subject/audience/job; asks for an explicit token system and memorable signature; uses two critique passes; and rejects generic visual defaults without importing a UI framework or agent runtime ([skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md), [history](https://github.com/anthropics/skills/commits/main/skills/frontend-design)). It is **likely (55-80%)** to improve distinctiveness on this owner's frontend tasks because its instructions target a common model failure and add little runtime machinery. The uncertainty is aesthetic and task-specific; a blinded comparison on ten existing frontend briefs, scored for brief fidelity, accessibility, maintainability, and owner preference, settles it.

### Tier 2: `webapp-testing`

Its strongest ideas are small: run bundled helpers as black boxes to protect context, inspect static HTML directly, and for dynamic apps perform reconnaissance before actions. The included `with_server.py` handles server lifecycle ([skill](https://github.com/anthropics/skills/blob/main/skills/webapp-testing/SKILL.md)). This is quality procedural compression, but it overlaps the owner's existing `e2e-runner`, which already prefers Agent Browser, falls back to Playwright, and defines execution and flake handling (`/local_disk0/codexwork/bundle/claude/agents/e2e-runner.md:9-104`). The right move is a tiny pattern transplant, not another trigger surface.

### Tier 2: `mcp-builder`

Its process covers research, tool naming and pagination, current-spec retrieval, implementation in TypeScript or Python, build/Inspector tests, and ten realistic evaluation questions with independently verified answers ([skill](https://github.com/anthropics/skills/blob/main/skills/mcp-builder/SKILL.md)). This is a good development checklist.

It is not a complete safety contract for this host. The local audit independently found that the existing MCP-maker guidance does not cover the full access-control, approval, isolation, drift, and supply-chain boundary, and recommended excluding MCP generation from the first foundry tier (`/local_disk0/codexwork/bundle/inputs/audit-findings/E09.md:54-63`). With 93 MCP servers touched historically and one dead MCP still called 532 times at 25.8% error, producing more servers without retirement/liveness policy would optimize the wrong quantity.

## Anti-overfit failures and explicit exclusions

### `claude-api/shared/managed-agents-*` as harness architecture — FAIL

The current `claude-api` skill includes Managed Agents material for agent creation, multi-agent operation, memory, scheduled deployments, outcomes, sandboxes, webhooks, and restartable sessions ([managed-agent files](https://github.com/anthropics/skills/tree/main/skills/claude-api/shared)). Adopting that runtime here would introduce a second orchestration/runtime plane and a durable-execution service, both explicitly rejected by the owner's anti-overfit gate. Its memory facility would also create another memory plane; whether it is vector-backed is irrelevant because the durable/runtime failures already settle the gate.

Do not adopt it. This exclusion is **almost certain (90-99%)** correct because the product boundary and the local rejected-component list match directly.
