### Concrete collision

Suppose the owner decides: “Use replacement architecture R because experiment E falsified evolution path Q.” This is simultaneously:

- a “durable decision” with rationale, matching `CLAUDE.md:11` and therefore requiring `mcp__basic-memory__write_note`; and
- a “durable decision” containing the *why* hooks cannot see, matching `AGENTS.md:30` and therefore requiring `note.py`.

Neither instruction says whether to:

1. write both stores,
2. put only semantic decisions in Basic Memory and only operational decisions in the ledger,
3. treat one as canonical and project into the other, or
4. use one writer as a fallback when the other is unavailable.

This is an actual action-selection collision even though dual-writing could satisfy both literal imperatives. The problem is not that dual-write is impossible; it is that two independently maintained texts each claim the same event class and give different writer commands, while the purported “objective vs. semantic” boundary does not classify decisions. An agent choosing either single writer can reasonably believe it complied and simultaneously omit the other prescribed write. An agent choosing both creates duplicate records with independently evolving supersession semantics.

Implementation is a second, mechanically independent signal that these are genuinely different authorities, not aliases:

- `C:\Users\Prekzursil\.claude\hooks\event-ledger\note.py:2-12` calls itself the agent-facing ledger annotator and explicitly accepts decisions, failures, goals, and milestones; `:25-42` parses the kind and appends through `ledger.append`.

## Alternatives considered

### Keep both texts and declare “later wins”

Rejected. Native documentation does not give prose conflicts deterministic last-write precedence; it says conflicting rules may be selected arbitrarily. This would document a guarantee the runtime does not provide.

### Require every decision to be written twice

Rejected as the default. Some decisions are purely ephemeral operational state and some are durable semantic policy. Mandatory unconditional dual-write would increase noise and divergence. The proposed edit requires dual-write only for an event explicitly classified as both, with cross-references.

### Delete the event ledger or Basic Memory

Rejected. The imported contract expressly distinguishes objective and semantic roles at `AGENTS.md:85-90`, and the subject implements both. This unit found a routing-boundary defect, not evidence that either capability is redundant.

### Add a routing daemon, synchronization service, or third memory store

Rejected by the anti-overfit gate. The defect is textual duplicate authority and is resolved on the existing import/tool/hook buses with instruction edits.

### Generate all provider files from a new templating runtime

Rejected for this internal unit. A generator may be appropriate in the separate cross-provider fork problem, but it is not minimal for the two-file Claude composition and would expand into neighboring work.
