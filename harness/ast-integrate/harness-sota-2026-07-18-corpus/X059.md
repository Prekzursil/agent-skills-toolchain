# X059 — Cross-domain borrow: control theory → compute and quota cost control

## Executive verdict

The useful borrow is **not** “treat an agent as a linear plant and install a PID controller.” That would be a category error. The useful borrow is a small set of resource-aware feedback mechanisms: (1) spend only when an event signal says the trajectory needs attention, (2) require an observation that can distinguish the live failure hypotheses before buying more reasoning, (3) require evidence that the proposed escalation can change the outcome, (4) use hysteresis so the allocator does not chatter between cheap and expensive modes, and (5) stop accumulated retry/escalation pressure from winding up against a hard quota limit.

My verdict is **likely (55-80%)** that this mechanism-level transfer can reduce compute at equal task quality in a heterogeneous agent workload. Evidence: event-triggered control was developed specifically to replace periodic sensing/computation/actuation with actions taken when a state deviation crosses a threshold ([Heemels, Johansson, and Tabuada, 2012](https://doi.org/10.1109/CDC.2012.6425820)); Tabuada shows that an event-triggered scheduler can retain a formal performance guarantee for its stated nonlinear-control assumptions while relaxing periodic execution ([Tabuada, 2007](http://www.seas.ucla.edu/~tabuada/Papers/EventTriggered.pdf)); and Snell et al. empirically find that the best use of LLM inference-time compute varies with problem difficulty and report more than 4× efficiency relative to their best-of-N baseline under their setup ([Snell et al., 2024](https://arxiv.org/abs/2408.03314)). The wide confidence interval is deliberate: none of those results evaluates this owner's workload or the governor below.

It is **almost certainly not (1-5%)** valid to import classical stability, observability, or controllability guarantees into an open-ended agent harness without a learned and validated task model. Evidence: the classical concepts assume a specified dynamical system with defined state, input, and output maps; here “answer quality” is generally latent, interventions are discrete and stochastic, tasks change between episodes, and the proposed residuals are proxies. The control literature supports the mechanisms in its field, not that cross-domain theorem.

The concrete recommendation is therefore an **event-triggered marginal-value governor**, explicitly an empirical budget policy rather than a control-theoretic proof.

**UNVERIFIED — the recommendation depends on the premise that cheap, externally grounded residuals predict the marginal value of another compute action; settle it with the preregistered randomized replay-and-live experiment in “Validation” below.**

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** One policy hook reads already-available run events and budget counters, emits `continue / observe / escalate / stop`, and records the decision. No second orchestration runtime, vector database, knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed.

## What the source field actually solved

### 1. Observability: can outputs distinguish internal state?

In a state-space system, controllability/reachability asks whether admissible inputs can move the state to the desired region; observability asks whether the internal state can be reconstructed or distinguished from the available output history. For a finite-dimensional linear time-invariant system, these properties can be tested with rank/Gramian conditions. They are properties of a specified model—not synonyms for “we logged a lot” or “the model sounds confident.” Åström and Murray give the state-space treatment and connect state estimation to output feedback in the cited open textbook.

The cost-control lesson is information-first: if two consequential hypotheses produce the same available observations, more feedback computation over those same observations cannot distinguish them. A controller needs another sensor or must accept ambiguity. In an agent, ten more samples that all reuse the same missing evidence are not equivalent to one discriminating test, file read, tool result, or authoritative source.

### 2. Controllability: can the available input change the state that matters?

Control effort is useful only through an input channel that can affect the target state. In its own field, an uncontrollable mode cannot be moved by the available actuator no matter how large the command becomes. This is a structural statement about the model and actuator, not a statement that “the actuator is expensive” or “it usually works.” The same textbook source treats reachability/controllability and feedback design.

The cost-control lesson is action-first: before paying for a larger model, another branch, a critic pass, or another retrieval, ask whether that action has an evidenced causal path to the live error. If the blocker is a missing credential, unavailable ground truth, or an ambiguous owner preference, additional token generation is not an effective actuator.

### 3. Event-triggered control: act on deviation, not on the clock

Periodic sampled-data control senses and acts at fixed intervals. Event-triggered control evaluates a condition tied to state/output error and acts when that condition crosses a threshold; self-triggered control predicts the next necessary action time in advance. Heemels et al. frame these methods around resource-constrained embedded and networked systems and explicitly motivate limiting sensing, computation, and communication to times when the system needs attention. Tabuada's paper is stronger than an analogy slogan: under its mathematical assumptions, an event-triggered implementation preserves a stated stabilizing performance objective while relaxing periodic execution.

The cost-control lesson is conditional allocation: do a cheap initial pass, then spend the next unit only when a measurable residual indicates that the answer trajectory is outside an acceptable tube. “Always use N samples,” “always run a critic,” and “always use the largest model” are the computational analogues of periodic actuation whether or not the task needs it.

### 4. Hysteresis/dead bands: do not switch on noise

A dead band suppresses action for small deviations; hysteresis uses different thresholds depending on the current mode. In the cited relay specification, the relay remains off until the input crosses the switch-on point, then remains on until it falls below a distinct switch-off point. That state dependence prevents rapid back-and-forth switching when a noisy signal sits near one threshold.

The cost-control lesson is to avoid allocator chatter. One uncertainty score just above/below a single cutoff should not alternately invoke a premium model and return to a cheap one. Escalate above a high threshold; remain escalated in the middle band; de-escalate only below a lower threshold after a grounding signal.

### 5. Anti-windup: saturation must feed back into controller state

A PID integrator can continue accumulating error while an actuator is saturated. The requested command then moves farther outside the actuator's feasible range. When the setpoint changes or saturation clears, the stored integral causes delay and overshoot. In MathWorks' worked example, increasing the controller output beyond the actuator limit has no effect, and recovery is delayed. Back-calculation feeds the discrepancy caused by saturation into an internal tracking loop to unwind the integrator; clamping conditionally stops integration during the relevant saturation condition.

The cost-control lesson is sharper than “have a budget cap.” A cap limits actual spend but does not necessarily clear queued retries, accumulated escalation debt, or a policy's belief that it must make up missed work later. The governor must feed the discrepancy between desired and permitted spend back into its state: cancel or decay pending escalation, freeze retry accumulation, and require new evidence before resuming.

### Objective

Treat cost allocation as a constrained decision problem, not “maximize reasoning.” At each decision point, select the cheapest action whose estimated reduction in expected task loss exceeds its incremental cost and whose evidence channel can actually reveal progress. In compact notation:

`take action a only if E[loss_now - loss_after(a) | signals] > shadow_price × incremental_cost(a)`

This is a policy heuristic, not a claim that expected loss is directly observable. The shadow price rises as the task or global quota is consumed. Safety- or owner-designated mandatory checks remain constraints, not items the cost optimizer may trade away.

### Inputs already available on an existing bus

The hook consumes only run events that an agent harness normally already has:

- cumulative tokens, wall time, tool calls, and monetary/quota estimate;
- action type and outcome (`success`, typed failure, timeout, no new evidence);
- whether a candidate answer changed materially after the last spend unit;
- external check outcomes such as test result, schema validation, cited-source agreement, or file diff;
- disagreement across independently produced candidates or between answer and check;
- repeated error fingerprints and repeated identical tool arguments;
- remaining task budget and shared quota pressure.

No semantic memory store is required. The per-run state can be a small record: mode, thresholds, last grounded progress event, retry count by fingerprint, budget used, and any pending escalation debt.

### Decision cycle

1. **Cheap proposal.** Produce the smallest plausible answer/action plus explicit uncertainty and the check most likely to falsify it.
2. **Observation gate.** Ask: is there a discriminating observation for the consequential uncertainty? A test, tool result, authoritative source, user choice, or independent execution path counts. Self-reported confidence alone does not. If no discriminating observation exists, do not buy repeated reasoning over identical evidence; either acquire a new observation, state the gap, or stop.
3. **Action gate.** Ask: does the contemplated spend have historical or local evidence of changing this failure mode? A larger model may help synthesis; it cannot repair an unavailable service. Another retry may help a transient timeout; it cannot help an identical deterministic schema rejection without changing the payload.
4. **Residual.** Compute a coarse, bounded need-for-attention score from grounded failure, unresolved high-impact disagreement, novelty/progress, and risk—not from verbosity or model confidence alone. Keep components inspectable instead of collapsing them into an opaque learned critic.
5. **Hysteretic trigger.** In cheap mode, escalate only when the residual exceeds `T_high`. In expensive mode, remain there until it falls below `T_low < T_high` and an external check supports the drop. In the band, preserve the current mode.
6. **One bounded spend quantum.** Grant one action: one retrieval, one test batch, one alternative branch, one stronger-model pass, or one repair attempt. Re-evaluate after its result. Do not allocate the entire remaining budget merely because the trigger fired once.
7. **Anti-windup.** If a task/global cap prevents the requested action, set actual grant to zero, clear or exponentially decay queued escalation, and clamp retries for the same fingerprint. When quota becomes available, require a new observation or changed input before action; do not discharge an old backlog automatically.
8. **Heartbeat.** Because a dead band can hide slow cumulative drift, force a cheap periodic check after a bounded number of no-op decisions or when risk is high. This is a measurement heartbeat, not an automatic expensive reasoning pass.
9. **Stop.** Stop when an external success signal is present, marginal actions have repeatedly produced no new evidence, the task is not observable with available tools, or the hard budget binds. Report which condition fired.

### Practical observability and controllability proxies

Calling these proxies matters. A harness cannot run a Kalman observability matrix on an undefined “answer-quality state.”

An **observation is discriminating** only if plausible competing hypotheses predict different outcomes. Example: “the implementation is correct” versus “the API contract is wrong” can be separated by an authoritative contract plus an execution test; asking the same model to reread its answer is correlated evidence. Before the harness claims “verified” or “no issue,” it should require two mechanically independent signals when the claim is consequential: for example, execution exit/result plus an independently parsed artifact, or authoritative specification plus a behavior test. A second invocation of the same detector is not independent.

An **action is locally effective** when a bounded trial changes either the grounded residual or an external outcome. Keep an online table keyed by broad task/risk/failure class: action, incremental cost, externally measured improvement, and uncertainty. Randomized exploration on a small safe fraction is necessary to avoid learning only from actions the old policy already selected.

It is **likely (55-80%)** that typed failure fingerprints plus externally grounded checks will outperform self-confidence as trigger inputs. Evidence: deterministic failures expose direct action mismatch, while self-evaluation samples share model and context errors; however, the exact lift on this workload is **UNVERIFIED — settle it by comparing AUROC/calibration for “next action changes external outcome” on a held-out randomized action log.**

It is **roughly even (45-55%)** that a useful per-task difficulty estimate can be made cheaply enough to pay for itself on arbitrary agent tasks. Evidence against confidence: Snell et al.'s model-predicted difficulty procedure used 2,048 samples per problem and a learned verifier, explicitly notes the added inference cost, and says its experiments omitted that cost. **UNVERIFIED — settle it by charging all probe tokens/tool calls to the governor arm and comparing total cost at fixed quality; if probe overhead erases savings, remove difficulty prediction and retain only direct residual triggers.**

## What this would catch that uniform cost control misses

These are design-level catch classes, not claims about local implementation:

1. **Easy-task overspend.** A grounded cheap answer passes its independent check, so no periodic critic/branch/premium pass fires. It is **very likely (80-90%)** that this saves compute when a workload contains many externally checkable easy tasks; evidence is the avoided fixed action by construction. Equal quality remains **UNVERIFIED — settle it with blinded quality and test outcomes in the experiment.**
2. **Unobservable uncertainty.** Repeated samples agree because all lack the same fact. The observation gate routes spend to retrieval/test/user clarification or stops with a gap instead of purchasing consensus.
3. **Uncontrollable blockers.** A missing permission, unavailable service, or unchanged deterministic payload cannot be repaired by more prose generation. The action gate rejects model escalation until the actuator/input changes.
4. **Retry windup at quota saturation.** A hard cap stops actual calls; back-calculation/clamping also removes retry debt, preventing a burst when capacity returns.
5. **Threshold chatter.** Slightly noisy uncertainty or verifier scores no longer alternate models on every step because on/off thresholds differ.
6. **Expensive action with zero measured marginal value.** A bounded escalation that changes neither evidence nor external outcome lowers that action's eligibility for the same failure class.
7. **Slow degradation hidden by a dead band.** The heartbeat detects accumulated drift that never crossed the high threshold in one jump.
8. **Premature “done” from one detector.** The observation rule requires a known-present control plus a mechanically independent outcome before consequential absence/broken/done claims; repeated identical probes do not buy confidence.

Items 2–8 are **likely (55-80%)** to be detected when their stipulated event fields are present, because the rules match those patterns directly. Whether they occur frequently enough to justify even a small governor is **UNVERIFIED — settle it by measuring eligible events and counterfactual avoided cost during shadow mode.**

## Adversarial transfer audit

### Where the structure matches

- **Scarce action resource:** control systems ration computation, communication, or actuator effort; harnesses ration tokens, calls, wall time, and quota.
- **Feedback after action:** both can observe consequences and revise the next action rather than committing the whole horizon upfront.
- **Saturation:** actuators have physical limits; compute systems have rate, context, monetary, and quota limits.
- **Switching cost:** both can suffer from rapid switching; hysteresis is mechanism-compatible.
- **Marginal ineffectiveness:** pushing a saturated actuator harder and retrying an unchanged deterministic failure both consume command effort without changing the controlled outcome.

These matches support mechanism transfer, not theorem transfer.

### Where the structure breaks

1. **No stable plant.** Each task may have different dynamics; a prompt or tool response changes the “plant” itself. There is no identified `A, B, C` model.
2. **Quality is latent and delayed.** A physical output can often be sensed continuously. Agent correctness may be known only after deployment or may be subjective.
3. **Actions and observations are coupled.** Asking a model to verify consumes the resource being controlled and may produce correlated error. A sensor in a textbook model is usually characterized separately.
4. **Discrete, stochastic actuators.** “One premium-model pass” has variable effect and cost. More compute can degrade an answer through overthinking or verifier over-optimization; Snell et al. report signs of over-optimization for some search/difficulty settings.
5. **Nonstationary shared budget.** Quota has opportunity cost across tasks and users, unlike a single fixed actuator bound.
6. **Adversarial inputs.** Prompts and retrieved content may manipulate the very signals used by the governor. Internal claims such as “test passed” cannot be trusted without bus-level outcomes.
7. **Dead-band risk.** Many small errors can accumulate without crossing a single event threshold; rare catastrophic errors make average-cost tuning unsafe.
8. **Anti-windup is conditional.** If the harness retains no retry/escalation state, there is no integral state to unwind. In that case the honest implementation is a clamp/circuit breaker, not “anti-windup.”

Accordingly, it is **almost certain (90-99%)** that a literal PID controller over model confidence would be unjustified. Evidence: confidence is neither a characterized state error nor a mechanically independent output, spend actions are discrete/saturating, and task dynamics change. It is **very likely (80-90%)** that any credible implementation needs conservative hard constraints outside the adaptive policy. Evidence: the policy's quality state is partially observed and its estimates can be wrong; hard limits bound the damage of that error.

### Failure conditions that should kill the proposal

Stop rather than force the analogy if any of these are observed:

- trigger computation plus probing costs as much as the actions it suppresses;
- residual calibration fails out of distribution or misses high-severity errors;
- independent quality at matched cost does not improve over a simple fixed budget;
- the policy learns to suppress costly checks that reveal its own errors;
- mode switching or delayed quota information creates more retries than baseline;
- operators cannot reconstruct why spend was granted or denied from the logged fields.

It is **roughly even (45-55%)** that the full four-gate policy beats a much simpler `hard cap + typed retry circuit breaker + mandatory verification` baseline after overhead. Evidence: adaptive LLM compute has empirical promise, but difficulty estimation is costly and task-specific; the simple baseline captures much of anti-windup with less estimation error. **UNVERIFIED — the same factorial experiment below settles whether observation/action/hysteresis gates add incremental value.**

## Validation: the experiment that settles the UNVERIFIED premises

### Phase 0 — detector controls

Before measuring absence, brokenness, or completion, validate each event detector with two signals:

1. Inject a known-present synthetic event (known retry fingerprint, known passed test, known quota cap) and prove the detector finds it.
2. Confirm via a mechanically independent field or measurement—for example, tool exit status versus parsed test report, budget ledger versus provider usage record, or emitted hook decision versus actual next call.

Failure of either signal invalidates that metric. Re-running the same query is not a second signal.

### Phase 1 — offline shadow replay

Replay a stratified held-out task set without allowing the policy to alter execution. At every original decision, log what the governor would have done and the signals available *at that time*. Do not let later outcomes leak into difficulty or residual features. Charge policy evaluation overhead.

This phase can estimate coverage, obvious false triggers, chatter, and hypothetical avoided calls. It cannot establish causal quality or savings because the unchosen trajectory is missing. Any offline “would have saved” statement remains **UNVERIFIED — only randomized execution in Phase 2 settles it.**

### Phase 2 — randomized bounded actions

Randomize eligible tasks among:

- simple baseline: fixed task budget, hard cap, typed retry circuit breaker, mandatory risk checks;
- event trigger only;
- event trigger + hysteresis;
- event trigger + hysteresis + anti-windup state;
- full policy with observation and action gates;
- full policy with a small randomized exploration rate for counterfactual learning.

Within safe, non-destructive tasks, randomize a bounded escalation at selected near-threshold points. This supplies a causal estimate of whether the extra action changed an external outcome. Keep owner-mandated and high-risk checks fixed across arms.

Primary outcome: independent task quality at total charged cost. Quality must use two mechanically independent signals where the task permits—for example, hidden tests plus blinded review, or specification conformance plus execution behavior. Secondary outcomes: tail cost, wall time, provider quota exhaustion, repeated identical failures, missed necessary escalations, unnecessary escalations, mode switches, and time-to-recovery after saturation.

Pre-register a non-inferiority margin for quality and a minimum meaningful cost reduction based on owner utility before seeing results. Do not invent universal percentages. Stratify by task type, external-check availability, risk, and baseline difficulty; report tails rather than only means.

### Phase 3 — stability and abuse tests

Feed the governor oscillating near-threshold signals, slow sub-threshold drift, delayed budget updates, identical deterministic failures, transient failures, prompt text falsely claiming that a test passed, and quota restoration after a long cap. Expected invariants:

- bounded switching rate;
- no automatic discharge of stale retry debt;
- external events outrank prompt claims;
- hard caps always dominate adaptive grants;
- heartbeat eventually samples slow drift;
- every decision is reconstructable from logged inputs and thresholds.

It is **very likely (80-90%)** that distinct on/off thresholds reduce synthetic near-threshold switching relative to one threshold; evidence is the relay state rule itself. Whether that reduces real cost without delaying necessary escalation is **UNVERIFIED — Phase 2 measures the trade-off.** It is **very likely (80-90%)** that clamping retry accumulation prevents a post-cap burst in the explicit quota-restoration test; evidence is the designed state transition. Whether real provider/client layers contain additional hidden retry queues is **UNVERIFIED — reconcile bus-level decisions with provider-call records during the test.**

## Minimal implementation sketch

The governor can remain below ~200 lines if it is a pure policy function plus a small per-run record:

```text
input: event, run_state, task_policy, shared_budget
update grounded_progress, repeated_fingerprint_count, spend, mode

if mandatory_safety_check_due: grant(check)
else if hard_cap_or_shared_quota_blocks:
    clamp retries; decay pending escalation; stop_or_wait_with_reason
else if deterministic_repeat_without_changed_input:
    stop_retry; request_new_observation_or_change
else:
    residual = inspectable_weighted_events(event, state)
    if heartbeat_due: grant(cheap_external_check)
    else if mode == CHEAP and residual >= T_high:
        grant(one_best_discriminating_or_effective_action); mode = EXPENSIVE
    else if mode == EXPENSIVE and residual <= T_low and grounded_success:
        mode = CHEAP; stop_or_continue_cheap
    else if in_dead_band:
        preserve_mode; grant_at_most_one_mode_appropriate_action
    else:
        stop_with_reason

record: inputs, rule, grant/deny, expected purpose, actual cost, external outcome
```

Thresholds should begin as conservative configuration by task/risk class, then be tuned only from randomized outcome data. It is **likely (55-80%)** that coarse classes and inspectable rules generalize better than a fitted scalar “quality controller” under task drift. Evidence: they make fewer stationarity assumptions and expose causal failure modes; this is still **UNVERIFIED — compare held-out and temporal-shift performance against a fitted policy.**

## Alternatives considered

### Uniform fixed budgets

This is the strongest simplicity baseline. It has minimal overhead and cannot be gamed through an adaptive residual. It wastes work on easy tasks and may starve hard tasks, but those costs must be measured, not assumed. The proposal should not ship unless it beats this baseline at matched quality.

### Confidence-only escalation

Rejected. Self-confidence is correlated with the generator, lacks a defined relationship to correctness across task types, and offers no mechanically independent observation. It may remain one low-weight feature but cannot be the trigger.

### Best-of-N or always-on debate/critic

Rejected as the default allocation policy, not as bounded actions. These are periodic spend patterns. They can be selected after a residual fires and evidence says they help the failure class. Snell et al. show that relative effectiveness depends on prompt difficulty and method; their result argues against a single uniform strategy.

### Model-predictive control / learned value model

Not proposed. A calibrated long-horizon task model would be BUILD-LARGE, its state is poorly observed, and model error would dominate the apparent optimization. It also risks becoming a second orchestration runtime or trained critic, both excluded by the anti-overfit gate.

### Bandit/router trained over all actions

Not proposed in the first version. A contextual bandit could estimate action value, but it needs safe exploration, stable rewards, delayed-credit handling, and distribution-shift controls. A tiny randomized action table is enough to test the controllability premise before building a learner.

### Pure hard caps and circuit breakers

Retain these regardless. They are the safe anti-windup floor and may win the experiment. Adaptive allocation is an addition only if it produces measured marginal value.

## Final recommendation

Build only a shadow-mode, inspectable event-trigger policy on the existing event bus, then promote it through the randomized gates above. Do not describe it as “PID for agents,” do not claim stability, and do not equate model confidence with observability. The transferable core is narrower and better: discriminate before reasoning, verify that an action can matter, trigger on grounded residuals, use hysteresis around noisy thresholds, and feed quota saturation back into retry state.

The build recommendation remains **likely (55-80%)** to yield net value because it is small, reversible, directly measures its premise, and can fall back to caps/circuit breakers; evidence is the control-field resource mechanisms and target-field adaptive-compute result cited above. Its actual savings and quality impact are **UNVERIFIED — Phase 2's fully charged randomized comparison is the deciding experiment, and a null result should terminate the adaptive portion rather than invite a larger controller.**

This passes the anti-overfit gate: it rides the existing hook/skill/MCP event bus, keeps only ephemeral per-run state, introduces none of the previously rejected platform components, and treats the simple baseline as a possible winner rather than assuming architectural complexity is progress.
