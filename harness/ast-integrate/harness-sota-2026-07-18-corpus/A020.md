## Executive verdict

This is **not** a clean coherence result. I found eight real conflict families in which a rule and a command can apply to the same operation and prescribe incompatible behavior. Three families affect the multi-model commands and are especially acute: the commands mandate background execution that the rule explicitly bans, send prompts through inline heredocs that the rule explicitly rejects, and request a 60-minute Bash timeout while the rule and live settings specify 30 minutes. The remaining families concern model choice, TDD order, coverage thresholds, code-review blocking semantics, and absence/liveness detection.

There is no native rules-versus-commands precedence resolver. This is the central runtime answer, not a hedge. Current official Claude Code documentation says that rule files are context rather than enforced configuration and warns that contradictory rules may be chosen arbitrarily; invoked command/skill content enters the conversation as a message and persists. It does not define “the invoked command wins” or “the rule wins.” See [How Claude remembers your project](https://code.claude.com/docs/en/memory) (especially “CLAUDE.md vs auto memory,” “Consistency,” and `.claude/rules`) and [Extend Claude with skills](https://code.claude.com/docs/en/skills) (“Skill content lifecycle” and the legacy `.claude/commands/` mapping). Therefore, for model-level conflicts below, the verified runtime winner is **neither deterministically**: the model may follow either text. A PreToolUse hook or a hard configuration cap can independently force an outcome, but prose order cannot.

Confidence in that architecture conclusion is **almost certain (90-99%)**, based on two independent signals: (1) the current official documentation explicitly describes instructions as context and contradictions as arbitrarily resolved; (2) a bounded scan of the live `hooks.json`, `settings.json`, and shared harness found no conflict resolver for these directives, while the same detector successfully found the known-present force-push enforcement at `/local_disk0/codexwork/bundle/claude/settings.json:156-158` and `/local_disk0/codexwork/bundle/agents/harness/modules.py:690`.
