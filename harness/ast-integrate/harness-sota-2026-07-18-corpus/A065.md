# A065 — coherence audit of `~/.claude/rules/rust/testing.md`

## Scope and verdict

I read the full Rust testing rule (`/local_disk0/codexwork/bundle/claude/rules/rust/testing.md`, lines 1–154), its declared parent (`rules/common/testing.md`, lines 1–49), all rule-file keyword matches relevant to testing and coverage, the effective hook wiring in `settings.json` and `_dispatch/manifest.json`, the relevant hook implementations, `CLAUDE.md`, both unpacked `AGENTS.md` files, the `tdd-guide` agent, the available skill indexes, and the measured corpus.

The result is **eight concrete collisions**: three contradictions, one redundancy, and four enforcement gaps. The highest-impact defect is not cosmetic: the Rust rule requires inline unit tests in ordinary `src/*.rs` files, while the test-tamper hook does not recognize those files as tests. A behavior-level probe showed that the hook warns for the same removed Rust assertion in `tests/api_test.rs` but stays silent in `src/lib.rs`.

I found no defensible `UNRULED` collision. The two testing-oriented enforcements I found are already ruled by the inherited common rule: test-tamper implements the “fix implementation, not tests unless tests are wrong” policy (`rules/common/testing.md:40-45`), and journey-coverage implements the common requirement for E2E tests (`rules/common/testing.md:25-29`). Their defects are incomplete Rust enforcement, not policy without a rule.

I do **not** claim that the live `~/.claude/skills` or `~/.agents/skills` trees are collision-free. Those directories are absent from the remote bundle. The bundle contains only derived skill indexes. Any finding about the actual text of `rust-testing`, `tdd-workflow`, or `test-driven-development` would therefore be fabricated; the exact settling experiment is listed under GAPS.

## Collision register

### A065-C01 — hard-coded Rust coverage defeats the declared SSOT

**Class:** CONTRADICTION

**Artifacts and exact lines**

- `claude/rules/rust/testing.md:129-138`: “Target 80%+ line coverage” and `cargo llvm-cov --fail-under-lines 80`.
- `claude/rules/common/testing.md:23-24,30-38`: coverage is per `.coverage-thresholds.json`, is 100% on metaswarm, and falls back to 80% only where no threshold exists.
- Corroborating restatements: `claude/rules/common/development-workflow.md:43-48` and `claude/rules/common/code-review.md:47-57,91-99` both call `.coverage-thresholds.json` the SSOT.

**Why this collides**

In a project whose threshold is 100, the Rust example’s explicit fail gate succeeds at 80. Under `rules/README.md:93-98`, the language-specific rule wins over the common rule, so the current precedence mechanism resolves the text in the wrong operational direction. `AGENTS.md` section 10 does not select a winner between these same-layer rule files.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Replace the Rust numeric requirement with: “Use the repository’s `.coverage-thresholds.json`; 80% line coverage is only the fallback when no repository threshold is defined.” Replace the literal fail command with a documented threshold placeholder or a tiny existing-bus resolver that supplies the repository value. It is **almost certain (90-99%)** this removes the contradiction because all three common governance locations already name the same SSOT; the settling experiment is a fixture with thresholds 100, 85, and absent, verifying that the resolved cargo command uses 100, 85, and 80 respectively.

**Why this collides**

The copies already drift in meaning: Rust presents 80 as the target and executable fail gate, while the common files present it only as a fallback. This is redundancy with demonstrated semantic drift, not harmless repetition.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Keep the policy and fallback in one common rule, and let Rust name only `cargo-llvm-cov` plus the way to pass the resolved threshold. Make development-workflow and code-review link to the SSOT rather than repeat its number. It is **very likely (80-90%)** this prevents future threshold drift because only one editable numeric default remains; evidence is the present four-way divergence, and the settling experiment is a repository-wide assertion that exactly one rule source contains the fallback literal.

### A065-C04 — coverage dimensions disagree across the Rust rule and mandated agent

**Class:** CONTRADICTION

**Artifacts and exact lines**

### A065-C05 — inline Rust unit tests are invisible to test-tamper enforcement

**Class:** UNENFORCED

**Artifacts and exact lines**

- `claude/rules/rust/testing.md:19-36` requires unit tests inside `#[cfg(test)]` modules in the same production source file; its examples are `src/lib.rs`, `src/auth/mod.rs`, and `src/orders/service.rs`.
- `claude/hooks/test-tamper-guard/guard.py:53-67` recognizes test directories, test-ish filenames, Python, Go, and capitalized JVM/C++ test names, but has no Rust inline-module rule.
- `claude/hooks/test-tamper-guard/guard.py:224-255` acts only after `_is_test_file` accepts a staged path.
- `claude/settings.json:163-171` wires this hook and labels it “TDD guard: protect test integrity.”

**Independent behavioral evidence**

Probe 1 returned: `tests/api_test.rs True`; `src/lib.rs False`; `src/auth/mod.rs False`; `src/orders/service.rs False`. Probe 2 drove `main()` with identical removed `assert_eq!` diffs: `tests/api_test.rs warning_emitted=True rc=0`; `src/lib.rs warning_emitted=False rc=0`.

This is a real blind spot, not an inference from “no regex found.” The rule deliberately puts most Rust unit tests in the exact path class the guard excludes.

**Specific resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** In staged `.rs` diffs, classify test code by Rust markers (`#[cfg(test)]`, `#[test]`, `#[tokio::test]`, `#[rstest]`, the surrounding `mod tests`, and removals of Rust assertion macros) rather than by filename alone. Add fixtures for inline deletion, assertion net drop, `#[ignore]`, production `assert!`, and a legitimate test refactor override. It is **very likely (80-90%)** this closes the demonstrated blind spot without treating every production `.rs` assertion as a test because classification can require test-context markers; evidence is the two successful controls above, and the settling experiment is the listed hook fixture matrix plus one real staged Rust repository probe.
