📝 Summary

Implements Redis operation timeout and circuit breaker pattern to prevent API hangs during Redis connectivity failures.

Problem: When Redis becomes unavailable, API requests hang indefinitely waiting for Redis operations to complete, causing poor user experience and potential service disruption.

Solution:

  • Added configurable 500ms timeout on all Redis operations
  • Implemented circuit breaker pattern (opens after 3 failures, 30s cooldown)
  • Graceful fallback to in-memory cache during Redis outage
  • Automatic reconnection when Redis becomes available
  • Circuit breaker state monitoring via stats endpoint

Follow-up to review findings on the circuit-breaker implementation:

- Catch redis.exceptions.ConnectionError / TimeoutError / RedisError in the
  breaker. These classes do NOT inherit from builtins.ConnectionError or
  asyncio.TimeoutError, so the prior narrow 'except (ConnectionError, OSError)'
  silently bypassed the breaker on real redis-py failures, leaving the
  circuit permanently closed while Redis was misbehaving.

- Implement true single-probe half-open via _half_open_probe_in_flight. Only
  one coroutine holds the probe slot per cooldown cycle; others see the flag
  and skip Redis until the probe resolves. Prevents thundering-herd on a
  still-down Redis when the 30s cooldown elapses.

- Apply an extended timeout (max(op_timeout*10, 5s)) to invalidate()'s
  scan_iter traversal so large keysets no longer cause the subsequent
  delete and publish steps to be silently dropped, which had been leaving
  stale registry data on peer workers until TTL expiry.

- Move logger.warning / logger.error calls outside the circuit-breaker
  lock to avoid serializing Redis operations behind synchronous log I/O
  during failure storms.

- Lazy-init the asyncio.Lock on first async use to avoid binding it to
  whichever event loop happens to exist at module-import time (singleton
  is created at import).

- Refresh .secrets.baseline line numbers post-rebase and apply black/isort
  auto-fixes to the touched test files.

- Add regression tests covering redis-py ConnectionError/TimeoutError/
  ResponseError trip paths, the single-probe half-open invariant, probe
  failure keeping the circuit open, and the scan_iter extended timeout.

Second-opinion review (Oracle, 9m deep pass) surfaced three Blocking
bugs that the prior circuit-breaker implementation introduced, plus
several performance and simplification opportunities. This commit lands
all of them.

Blocking correctness fixes
--------------------------
- B1: Drop the per-call ping from _get_redis_client. Wrapping ping in
  the circuit breaker on every operation let a 'half-up' Redis (PING ok
  but GET/SETEX timing out) oscillate failure_count between 0 and 1 so
  the breaker never opened. The actual command's success/failure is now
  the sole breaker signal; the factory still pings on initial client
  creation.

- B2: Release the half-open probe slot on asyncio.CancelledError.
  CancelledError is a BaseException (not Exception), so the prior
  'except Exception' left _half_open_probe_in_flight=True forever,
  permanently disabling the breaker. A finally block now releases the
  slot on cancellation and on any path that bypasses the record_* calls.

- B3: Distinguish scan failure from 'scan found zero keys' in
  invalidate(). Previously a scan_iter timeout returned None, was
  coerced to [] via 'or []', then redis.publish fired the invalidation
  anyway. Peer workers dropped L1 while stale L2 keys remained in this
  worker's Redis. Now a failed scan aborts both delete and publish.

High performance + correctness
------------------------------
- H1: Lock-free fast path in _acquire_probe_slot and _record_success.
  The steady-state happy case (circuit closed, failure_count==0) no
  longer acquires the asyncio.Lock at all. Lock acquisition is slow-path
  only, for state transitions.

- H2: Non-probe success must not zero the failure counter while the
  circuit is open. A stale slow success (e.g. from a pre-open request)
  could otherwise race against a just-opened circuit and reset
  failure_count to 0, obscuring cooldown progress to observers.

- H3: Batch invalidate()'s deletes into a single redis.delete(*keys)
  call. Previously N keys meant N round trips + N lock+timeout wrappers;
  now one variadic DEL regardless of keyset size.

- H4: Validate SCAN output types. Malformed or malicious SCAN replies
  used to be fed verbatim to redis.delete(); they now abort the
  invalidation with a warning instead.

A prior local fix attempt swapped the catches for
redis.exceptions.TimeoutError / redis.exceptions.ConnectionError
directly. That silenced E0712 but reintroduced a correctness regression
by dropping coverage of:
  - asyncio.TimeoutError (raised by asyncio.wait_for when a command hangs)
  - stdlib ConnectionError / OSError
  - redis.exceptions.RedisError (base; catches ResponseError etc.)
Seven regression tests failed under that approach.

This commit restores full coverage by going back to module-level tuple
literals, which pylint DOES statically resolve as except-clause types:

    _REDIS_TIMEOUT_EXCEPTIONS = (asyncio.TimeoutError, redis_exceptions.TimeoutError)
    _REDIS_CONNECTION_EXCEPTIONS = (
        ConnectionError, OSError,
        redis_exceptions.ConnectionError,
        redis_exceptions.RedisError,
    )

Other changes in this commit:
- Flatten the 'else' after try/except where all except branches return
  (R1705 no-else-return).
- Drop the _RedisExceptionBuckets dataclass and _build_redis_exception_types
  helper (no longer needed; module-level tuples are simpler and pylint-clean).
- Remove unused Tuple / Type typing imports (W0611).
- Import redis as 'redis_exceptions' alias to avoid shadowing the many
  'redis = await self._get_redis_client()' locals (W0621 redefined-outer-name).
- Place the redis import in a proper '# Third-Party' group (C0411
  wrong-import-order).

Results: pylint 8.47/10 (up from 8.26), all targeted findings at 10/10;
134 tests pass; interrogate 100%; ruff / black / isort clean.

The module-level 'from redis import exceptions' introduced in the
previous commit broke the playwright-ci-smoke job, whose environment
does not install the optional 'redis' extra (see
[project.optional-dependencies] redis in pyproject.toml). The worker
failed to boot with ModuleNotFoundError: No module named 'redis'.

Restore the try/except guard around the import while keeping the
properties pylint cares about:

- Fallback tuple contains stdlib-only types (asyncio.TimeoutError,
  ConnectionError, OSError); the redis-specific code paths that need
  redis-py exception matching are not reachable without redis installed
  anyway (_get_redis_client returns None).

installed' — the module imports cleanly and the fallback tuples are
