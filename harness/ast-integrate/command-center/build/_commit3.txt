most timid script in the repo.

THE SELF-TEST WAS A NO-OP AND MY OWN MUTATION HARNESS CAUGHT IT.
I wrote three mutants -- delete the P2 guard, widen the safe list to include needs_merge, add a
prune -- and required each to turn the self-test RED. Two died. **P2 SURVIVED.** The reason is
worth keeping: `safe_to_deploy` is built from SHARED skills only, so a repo-only skill never
reaches the P2 guard at all, and "no repo-only skill was copied" stayed true with the guard
deleted. That assertion was measuring the drift reporter, not this tool -- a probe silent in both
states. Fixed by extracting the guard into a callable `deployable()` seam and having the
self-test hand it the case the integration path structurally cannot produce, plus a control that
the guard still ACCEPTS a present skill (a guard that refuses everything would also have passed).
All three mutants now die: `SUCCESS:deploy-gate-mutation survivors=0/3`.

I DID NOT run the full 98-file deploy. That is an owner-gated action against a live tree during
an active session. I deployed exactly the three skills whose bodies this wave edited, so the

AND THE DEPLOY EXPOSED A TRAP I HAD WALKED INTO. two-tier-verify and rubric-verifier came back
DIVERGED for ONE reason: the live `description:` line is the LONGER variant and the repo holds a
shortened one (the never-deployed description cap). Deploying my body edit would therefore have
silently SHORTENED two descriptions by 282 and 307 characters as a side effect of a docs commit.
That is exactly backwards for this fleet: the description is always-loaded and is the entire
lexical recall surface, the body loads only on invocation, and 26 skills are already dark for
want of description budget. Trading trigger vocabulary for index budget may well be the right
call, but it is a deliberate budget decision needing the adversarial review that never ran -- not
a silent side effect. So the union was taken in the safe direction: keep the LIVE description,
keep the NEW body. Both roots now carry 671 and 714 characters, identical to live, and the repo
copy is a strict superset that deploys without shortening anything.
