## §1 — DESIGN

### §1.1 The thesis, and the measurement that produced it

The estate's dominant, *measured* failure class is **untyped silence** — doc 13 §0.1 records a live
`dup-guard` that answered a real symbol collision with nothing, and doc 13 registers it as hazard
**H-h**, the one hazard Layer A *introduced*. Every candidate in doc 13 attacks that at the
**detection** layer: type the verdict (MECH-03), type the fail-open cause (MECH-04), type the
truncation (MECH-09).

UX/product-first makes a different claim: **untyped silence is a perception failure before it is a
detection failure.** A verdict that is correctly computed, correctly typed, written to
`command-center/`, and never read is operationally identical to a verdict that never ran. So the
architecture's first-class object is not the schema, the hook, or the check — it is **the one surface
the owner reads at the end of a turn**, and a mechanism is admitted *only if it changes what that
surface says*.

That is normally where a product-first pitch turns into a dashboard fantasy. It does not here,
because of one measurement:

> **The projection plane already exists in this repo, is applied to 4.88% of the object graph, and
> is a valid both-states detector today.** `[M]`

- `tools/command-center/render.py::outputs()` (`:260-266`) renders exactly **two** files —
  `command-center/STATUS.md` and `command-center/OWNER-DECISIONS.md` — plus
  `ARTIFACT-MANIFEST.json`, all from the catalog.
- `STATUS.md:1` carries its own generation banner: `<!-- GENERATED by tools/command-center/render.py
  from WORK-UNIT-CATALOG.json. Do not hand-edit ... -->`.
- It reads **`items[]` only** — `catalog.py:130-131` `raw = catalog.get("items")`. `work_units[]`
  has **no projection at all**.
- Coverage: **103 of 2,110 objects = 4.88%** `[M]`.
- **Both-states proof of the drift detector, run by me** `[M]`:

```
$ python tools/command-center/render.py --check
SUCCESS:cc-render no drift                                            exit 0

$ (append "DRIFT-INJECTED-BY-UXPF-PROBE" to command-center/STATUS.md)
$ python tools/command-center/render.py --check
  STATUS.md differs from its rendering
  ARTIFACT-MANIFEST.json does not match the files on disk
FAILED:cc-render drift=2                                              exit 1

$ (restore) ; python tools/command-center/render.py --check                exit 0
$ python -m pytest -q tools/command-center/tests   ->  48 passed in 16.73s
```

A detector that fires on the known-broken state and is silent on the known-good state is a real
instrument, not a green light. That is the asset this architecture is built on, and it is why this
is *extension*, not invention.

### §1.2 Control planes — three, all pre-existing, all singular

The spec's convergence rule (`_USER-PROMPTS.md:10796`) permits a hybrid winner *only when its
control planes remain singular and understandable*. UX-first adds **no fourth plane**:

| # | plane | singular authority | status |
|---|---|---|---|
| 1 | **Data** | `command-center/WORK-UNIT-CATALOG.json` (`items[]` 103 + `work_units[]` 2,007) | exists |
| 2 | **Contract** | `platform/schema/` (9) + `platform/lib/schema_resolver.py` + `command-center/schema/` (233 shims) | exists, sibling-closed |
| 3 | **Projection** | `tools/command-center/render.py::outputs()` | exists, **4.88% applied** |

The whole architecture is: **grow plane 3 from 2 views to a hard-capped 5, and from 103 objects to
2,110.** Nothing else.

### §1.3 The five views, and the one owner question each answers

`outputs()` becomes a fixed, test-enforced enumeration. Each view answers exactly one question; a
view that cannot state its question does not ship.

| view | owner question | source | status |
|---|---|---|---|
| `command-center/STATUS.md` | *Where does the register stand?* | `items[]` | **exists** |
| `command-center/OWNER-DECISIONS.md` | *What is blocked on me?* | `items[]` `owner_gate` | **exists** |
| `command-center/PRODUCTION.md` | *Where does the 2,007-unit plane stand, per phase?* | `work_units[]` | NEW |
| `command-center/NOT-CHECKED.md` | *What is lying to me right now?* | `work_units[]` ∖ receipts, + `DEGRADED`, + truncated detectors | NEW — **load-bearing** |
| `command-center/NEXT.md` | *What do I do next?* (≤10 items, one screen) | dependency closure over both arrays | NEW |

`NOT-CHECKED.md` is the architecture. It is the H-h answer expressed as a *product*: a unit that
declared an output and produced none renders as the literal token `NOT-CHECKED`, never as absence.
Today's rendering would open with one line, and that line is the entire value proposition:

> **`NOT-CHECKED: 2006 of 2007`** — because **1 of 2,007 declared `output_path` files exists on
> disk** (`WFA-0001 → command-center/wfa/schema/wfa-schema-pack.json`), and **29 of 32 declared
> output directories do not exist**, including `command-center/receipts/` which **1,021 units
> target** `[M]`.

Nothing else in the tournament prints that sentence. Doc 13's typed-silence mechanisms would make
each *check* honest; only a projection makes the *program* honest.

### §1.4 The receipts index — the one place this needs new machinery

1,021 receipts are not human-readable, but a projection over them is. Two stages, deliberately split
so the purity property that makes the existing 48 tests cheap is not lost:

```
stage A (impure, cached)   platform/lib/receipt_index.py
                           walk command-center/receipts/** -> receipts/INDEX.json
                           typed fields ONLY: id, phase, verdict, output_path, sha256, ts
stage B (pure)             render.py::render_receipts(catalog, index) -> RECEIPTS.md
```

Stage B stays a pure `dict -> str` function, exactly like `render_status` (`render.py:68`), so it is
testable by byte-comparison with no filesystem. Stage A is the only impure addition in the
architecture, and §4 explains why its field list is an allowlist rather than a redactor.

### §1.5 Composition against doc 13's MECH-NN namespace

UX-first is not a new mechanism family; it is a **consumption harness over five existing ones**.
(`MECH-NN` per doc 13's fixed namespace; the old `M-NN` collision is settled and not re-litigated.)

| MECH | doc-13 role | what UX-first adds |
|---|---|---|
| **MECH-03** typed silence `FINDING/CLEAN/NOT-CHECKED/RAISED/DEGRADED` | doc 13's highest-EV mechanism | gives the vocabulary a **reader**. A `NOT-CHECKED` nobody renders is silence with extra steps. |
| **MECH-09** truncation-aware detector (`shown=N total=M`) | detector contract | the views render `total`, never a bare list — the failure that presented a floor as a total |
| **MECH-04** fail-open dependency receipts (`DEGRADED: <dep>`) | types the cause | `DEGRADED` gets a dedicated block in `NOT-CHECKED.md` |
| **MECH-38** provenance stamp (`generated_by`/`source_ref`/`built_at`) | pins origin | every view is stamped; `STATUS.md:1` already proves the pattern |
| **MECH-35** two-tier skill policy + measured router hit-rate | context budget | see §1.6 — adopted as a **separate axis**, not a core claim |

**Anchor compliance** (doc 13 §1): rides the existing bus — it is one Python module in
`tools/command-center/` invoked by CI and by hand. Reintroduces **none** of the six rejected
components: no second orchestration runtime, no vector-DB/KG memory, no durable-execution engine, no
trained critic, no observability SaaS, no guardrail framework. **PASS**, and it is the cheapest PASS
in the field because the bus is already carrying it.

## §2 — COST AND COMPLEXITY ANALYSIS

### §2.1 Code cost

| item | estimate | basis |
|---|---|---|
| `render_production` / `render_not_checked` / `render_next` | ~250-350 LOC | `render_status` is ~90 LOC (`render.py:68-155`) for a view of comparable shape |
| `platform/lib/receipt_index.py` (stage A) | ~120-180 LOC | walk + typed-field allowlist + cache |
| `render_receipts` (stage B) | ~60-90 LOC | pure, mirrors `render_status` |
| tests | ~350-500 LOC | existing ratio: 48 tests over 1,842 LOC |
| **total** | **~800-1,100 LOC incl. tests** | ~25-33% growth of `tools/command-center/` |

**New runtime dependencies: 0.** New processes: 0. New network egress: 0. New daemons: 0. The
existing tooling is stdlib + `jsonschema` (already required by `schema_resolver.py:42`).

Confidence in the LOC band: *likely* (55-80%). It is an analogy to `render_status`, not a
measurement, and the `NEXT.md` dependency closure is the term most likely to blow the estimate —
`dependencies` is populated on all 2,007 units but **41 dependency refs are unresolvable** `[B]`,
so the closure needs an error path the other views do not.

### §2.2 Complexity that is genuinely imported

Three honest costs, not one:

1. **Purity is broken once.** Every existing view is a pure `catalog dict -> str`, which is exactly
   why 48 tests cover 1,842 LOC cheaply. The receipts indexer must `stat` and hash up to 1,021
   files. I contain it (§1.4 two-stage split) rather than pretend it away, but the containment is a
   *design constraint a reviewer must enforce*, not a property the code gets for free.
2. **Marginal drift surface is O(views).** `check_all()` (`render.py:282-300`) byte-compares every
   rendered file. Going 2 → 5 views raises both CI wall time and the probability of a benign-looking
   red. §3.2 shows that is not hypothetical here.
3. **A view is a promise.** Each one commits the program to keeping a *human-legible* contract
   stable. Renaming a phase label becomes a documentation change. That is the real product tax and
   it is not measurable in LOC.

### §2.3 Cost of *not* doing it

2,007 units are scheduled to write into 32 directories. At the currently declared rate that is
**1,021 receipts into a single flat directory** (`command-center/receipts/`). With no projection the
only consumption tools are `ls` and `grep`. The cost of omission is not aesthetic: it is that the
program cannot answer *"which of my 2,007 units silently did not run"* without writing this code
later anyway, at a point when the answer matters more and the debris is deeper.

## §3 — FAILURE-MODE ANALYSIS

Ordered by severity. Two of the six have **already occurred in this repo's git history**, which is
why they are stated as measured rather than imagined.

### F1 — The projection is exactly as true as the catalog, and the catalog is measurably wrong. (severity: highest)

Measured catalog defects, from the DSL conformance run `[B]`, plus one I re-measured `[M]`:
**159 unloadable `output_schema` refs · 41 unresolvable dependency refs · 96 completion sentinels
that do not name their own unit · 128 non-canonical `assigned_model_vendor_role` shapes** `[B]`;
strict profile passes **1,679 of 2,007** `[B]`. And `[M]`: **71 of 305 distinct `output_schema`
values are prose, not paths** — e.g.
`"command-center/schema/receipt.schema.json (receipt) + tools/plugin/schema/payload-allowlist.schema.json (artifact authored here)"` —
covering **180 of 2,007 references**.

Render those and you get a *confident* dashboard with false values. That is **strictly worse than
silence**, because silence announces itself as absence while a rendered table does not. This failure
mode is the exact inversion of the benefit the architecture is sold on.

**Mitigation (mandatory, not optional):** every view renders `validate.py` output as a
`SOURCE-INTEGRITY` band above its data — the reader sees "1,679/2,007 strict" *on the same screen*
as any per-unit table. A view that renders data without its integrity band is a defect.

### F2 — The drift gate goes red for a benign reason and gets skipped. (severity: high; ALREADY OCCURRED ×2)

`git log` `[M]`:

```
36070a6f fix(ci): repair main - lint, format and command-center render drift
edcf9f5b fix(command-center): LF-normalise the REACH-6 register hash - it was poisoning STATUS.md
b68815fd fix(command-center): LF-normalise artifact hashes so the manifest is platform-independent
```

Render drift has already cost this repo two CI repairs, and a hash-normalisation bug **poisoned
STATUS.md** — the exact file this architecture makes load-bearing. Scaling 2 → 5 views scales that
exposure. Mitigation: views render **LF-normalised** content only (the `b68815fd` fix generalises);
no view may embed a hash of a file it does not itself normalise.

### F3 — CRLF / platform hash instability. (severity: high; ALREADY OCCURRED)

Same evidence as F2. On this box a working-tree file is CRLF while the stored blob is LF, so a
renderer that hashes the working tree produces a machine-dependent manifest. `b68815fd` already
fixed one instance. Any new view inherits the trap. Mitigation: hash `git cat-file -p` bytes or
LF-normalise before hashing — never `git archive`, which returns CRLF here.

### F4 — View inflation: the product answer to every question becomes "add a view". (severity: medium)

The failure ends with 15 generated files and an owner who reads none — i.e. exactly today's
hand-maintained `.md` situation (13 files) with a generator attached. **Mitigation is a test, not a
guideline:** `assert len(outputs(root, catalog)) <= 5`. A sixth view requires deleting one.

### F5 — `NOT-CHECKED` inflation. (severity: medium; TRUE TODAY)

MECH-03's own named risk is status inflation. At **2,006 of 2,007** the view is a wall of noise on
day one — that is not a hypothetical, it is the measured opening state. Mitigation: `NOT-CHECKED.md`
**ranks by blast radius** (phase depth × transitive dependents) and shows `shown=N total=M` per
MECH-09; it never emits a flat 2,006-row list.

### F6 — Receipt-index staleness and cost. (severity: low-medium)

Stage A caches; a stale cache renders a unit as `NOT-CHECKED` when a receipt exists (fails safe,
toward under-claiming) or as present when it was deleted (fails **unsafe**). Mitigation: the index
records `mtime + size + sha256` and stage B refuses to render an entry whose `stat` no longer
matches — a mismatch renders as `DEGRADED: index-stale`, never as success.

## §4 — SECURITY REVIEW

### §4.1 What this architecture does not add

No network egress, no new exec surface, no new credential path, no new marketplace or loader
coupling, no daemon. Contrast A3 marketplace-first, which by doc 13's own security paragraph makes a
plugin-cache surface *load-bearing* — this candidate's attack surface delta over HEAD is one Python
module and up to five generated markdown files under `command-center/`.

### §4.2 The one real new risk: a projection is an exfiltration funnel by construction

This is the finding I would want a reviewer to hold me to. A projection **reads N artifacts and
concatenates them into one committed, indexed, greppable file, then hashes it into
`ARTIFACT-MANIFEST.json`.** If any receipt among 1,021 embeds a secret, the naive renderer:

1. copies it into a committed doc — blast radius goes from one artifact to a doc **plus** a manifest
   entry **plus** every clone;
2. makes it *easier* to find, because the whole point of the view is discoverability;
3. makes it **tamper-evident, which is not the same as safe** — a manifest hash proves nobody
   altered the leak.

That the SAST rail already watches this tree is measurable: HEAD `9f2dac7a` is literally
`fix(sast): mark the corpus cluster-id sha1 as non-security` `[M]`.

**Control — deny-by-default, enforced by a test.** The renderer never reads an artifact **body**.
Stage A extracts a **closed allowlist of typed scalars** — `id`, `phase`, `verdict`, `output_path`,
`sha256`, `ts` — and stage B can only render fields present in the index. There is no
`open(receipt).read()` anywhere in the architecture, and no free-text passthrough. This is
deliberately an *allowlist of fields*, not a *redactor over free text*: an allowlist redactor over
free text is precisely the pattern that leaked 8 real values earlier in this program. Test in §6 T6.

### §4.3 `render.py` writes by default — the H-e class, and I am scaling the tool that has it

`render.py:302-329` `[M]`: `--check` is opt-**in**; a bare `python tools/command-center/render.py`
falls through to `write_all(root, catalog)` and rewrites `STATUS.md`, `OWNER-DECISIONS.md` and
`ARTIFACT-MANIFEST.json`.

That is the same shape as doc 13 hazard **H-e** (`sync-from-live.ps1 -Report json` alone WRITES).
I am proposing to grow this tool from 2 written files to 5, so I inherit and amplify it. Stating it
plainly: **this candidate imports an unfixed write-by-default hazard.** Required change, and it is
part of the architecture rather than a follow-up: invert the default so `--check` is implicit and
writing requires explicit `--write`. Cost is one `argparse` flag plus every call-site in CI. I have
**not** measured the call sites — **UNVERIFIED** how many exist; settling probe:
`grep -rn "render.py" --include=*.yml --include=*.yaml --include=*.py .`.

### §4.4 Reviewer's residual

The architecture has no authn/authz dimension (single-owner, single-machine, local filesystem), so
there is no privilege boundary to get wrong — which is a genuine security *advantage* over A3 and
A5. Residual risk concentrates entirely in §4.2, and §4.2's control is a test that must exist before
the first view ships, not after.

## §5 — MIGRATION DESIGN FROM TODAY'S MEASURED STATE

Sequenced so each stage is independently reversible and each ends in a terminal state. Stages S1-S3
each carry a **both-states** acceptance proof, because a probe silent in both states measures
nothing.

### S0 — Quarantine the scratch debris. No code, no risk, immediate.

**135 of 164** top-level `command-center/` files are `_*` agent probes `[M]`. Move them to
`command-center/.probes/` (a `git mv`, so history follows). The owner's primary directory goes from
**82.3% debris** to ~0. Reversible by one `git mv` back. This stage would be worth doing even if
this candidate loses the tournament.

### S1 — `PRODUCTION.md` + `NOT-CHECKED.md` over `work_units[]`.

Both are pure `render_*` functions consuming the array `catalog.py:130` already ignores.

**RED-first acceptance, both states:** on today's tree the view MUST print
`NOT-CHECKED: 2006 of 2007`. Then, in a scratch fixture where one unit's declared `output_path` is
created with a schema-valid receipt, the same view MUST print `2005` and move that unit into the
CLEAN block. Two different outputs from two different states, or the view is not measuring anything.

### S2 — Do **not** create the 29 missing output directories.

Explicit non-step, called out because it is the tempting one. `mkdir` on
`command-center/receipts/` makes a number go green while changing nothing real; the current
truthful state is "**29 of 32 declared output dirs absent, 1,021 units point at one of them**"
`[M]`, and the view's job is to *say* that. Directories get created by the units that write them.

### S3 — Receipts index + `RECEIPTS.md`, gated on real receipts existing.

Blocked until `command-center/receipts/` holds ≥1 schema-valid receipt. Today it holds zero and the
directory is absent, so S3 **cannot start** and the plan says so rather than scheduling work that
would run against emptiness. The sibling's four example receipts under
`platform/schema/examples/substrate/` `[S]` are fixtures for T-tests, not production input.

### S4 — Fold the mechanically-derivable hand-maintained docs.

Exactly **5 of the 13** hand-maintained `.md` files sit beside a machine-generated `.json` twin
`[M]`: `BASELINE-SNAPSHOT` · `CATALOG-INTEGRITY` · `OPTION-ID-RESOLUTION` ·
`PROMPT-ONE-FLOOR-AUDIT` · `WAVE1-FLOOR-AUDIT`. A hand-written `.md` beside a generated `.json` is
the canonical drift shape: the JSON advances, the prose does not, and the prose is what gets read.

Convert those five to generated views **only if** doing so respects the §F4 cap of 5 total views —
which it does **not** if they each become a view. So they are folded as *sections of*
`PRODUCTION.md`, or they stay hand-authored and gain a staleness stamp. **Deliberately unresolved
here — it is a product judgement, and I flag it rather than silently pick.** The other 8
(`PROGRAM-CHARTER`, `RUNBOOK`, `RISK-REGISTER`, `RELEASE-CHECKLIST`, `ROLLBACK-MANIFEST`,
`UNKNOWNS-REGISTER`, `OWNER-QUESTION-PACKET`, `CODEX-STUB-RETIREMENT-LANE`) are judgement, not data,
and must **stay hand-authored**. Generating a charter is how a program starts lying to itself.

### S5 — MECH-35 skill-router hit-rate. Separate axis, separate evidence.

Wire `semantic-router/observe`, collect ~7 days, then decide the 338/53-skill tier split. Not on this
architecture's critical path and **not claimed as a win** until measured (§1.6).

### Rollback

Every stage is `git revert` of one commit. The generated views are derived artifacts: deleting them
loses nothing but the rendering, and `render.py --write` regenerates. Under the owner's binding
**PR-ONLY** release mode, "release" here means a merged PR plus a local rollback rehearsal
(`git revert` the view commit, confirm `--check` returns to green) — and program stopping condition
13 ("release/canary succeeds") is treated that way, as the binding decision directs. I am saying so
explicitly rather than reporting a canary I did not run.

## §6 — TEST DESIGN

Built on the existing 48-test suite in `tools/command-center/tests` (measured green, `[M]`), same
style: fixture catalog in, exact bytes out.

| id | test | why it is the right test |
|---|---|---|
| **T1** | **Purity.** `outputs(root, catalog)` is a pure function: identical catalog dict → byte-identical output, twice, no filesystem reads. | Preserves the property that makes 48 tests cover 1,842 LOC. Guards §2.2(1). |
| **T2** | **Both-states, per view.** Every view has a fixture pair: one state where it emits `CLEAN`, one where it emits `NOT-CHECKED`/`FINDING`. A view that emits the same token in both states fails. | A probe silent in both states measures nothing. This is the single most important test in the set. |
| **T3** | **Mutation.** Flip one unit's `completion_sentinel`; `NOT-CHECKED.md` must change. Flip one `phase`; `PRODUCTION.md` must change. Each mutation must be **killed**. | Precedent in this repo: 12/12 predicate mutations killed with an independent control `[B]`. A suite that stays green under mutation is not protecting the behaviour. |
| **T4** | **Drift.** `render.py --check` byte-exact over all views. | Already exists and is already validated both-states by me (§1.1). Extend the assertion list to 5. |
| **T5** | **View cap.** `assert len(outputs(...)) <= 5`. | Makes §F4 mechanically impossible rather than a norm. |
| **T6** | **Secret containment (deny-by-default).** A fixture receipt whose free-text body contains a `sk-`-prefixed 40-char token must produce **zero** occurrences of that token across every rendered view **and** `receipts/INDEX.json`. Control: the same token placed in an **allowlisted** field must also be absent, proving the allowlist is on *fields*, not on *patterns*. | The §4.2 risk. The control arm is what distinguishes this from an allowlist-redactor, which is the pattern that already leaked 8 real values in this program. |
| **T7** | **Integrity band present.** No view may render a per-unit table without a `SOURCE-INTEGRITY` header derived from `validate.py`. | Makes §F1's mitigation structural. |
| **T8** | **Index staleness fails to `DEGRADED`.** Corrupt one indexed `sha256`; stage B must render `DEGRADED: index-stale`, never success. | §F6's unsafe direction. |
| **T9** | **LF normalisation.** A CRLF working-tree fixture and its LF twin must render byte-identically. | `b68815fd` / `edcf9f5b` already bit this repo. Regression lock. |

**Detector-discipline note carried into the suite:** T2, T3, T6 and T8 all specify the *failing*
arm, not only the passing one. The measured lesson this design is answering — a `--check` that
returns green tells you nothing until you have watched it return red — is encoded as a test
convention, not as advice in a doc nobody renders.

**Not covered, stated plainly:** no test here proves a human *reads* the view. The product claim
("this changes what the owner sees") is **NOT-CHECKED** and is not testable in CI. Settling
experiment: after S1, log which `command-center/*.md` files the owner opens over two weeks. Until
that runs, the readership claim is an assumption of the design, not a finding of it.

## §7 — THE STRONGEST ADVERSARIAL REFUTATION OF THIS ARCHITECTURE

Three blades. The first is the one that draws blood, and I concede the part of it that lands.

### §7.1 "A dashboard over an empty factory is theatre."

> UX/product-first optimises the *reporting* of work that does not exist. Measured on this very
> tree: **1 of 2,007 declared output files exists. 29 of 32 declared output directories are absent.
> `command-center/receipts/` — the target of 1,021 units — does not exist.** The production plane
> has produced essentially nothing. So this architecture proposes to build a typed, drift-checked,
> mutation-tested, LF-normalised, secret-contained view whose entire content today is
> `NOT-CHECKED: 2006`. That fact is already obtainable with one `ls`. A rational program builds the
> factory and then the dashboard; UX-first inverts the order and spends its budget rendering an
> emptiness that costs nothing to observe.

Every number in that paragraph is mine, measured this pass. It is the strongest argument against my
own design and I could not weaken it if I tried.

### §7.2 "The projection cannot be more correct than the catalog, and the catalog is measurably wrong."

> 159 unloadable schema refs · 41 unresolvable dependency refs · 96 sentinels that do not name their
> own unit · 128 non-canonical role shapes · strict profile 1,679/2,007 `[B]`; and **71 of 305
> distinct `output_schema` values are prose rather than paths, covering 180 references** `[M]`, whose
> tails `receipt_schema_gate.py::parse_schema_ref` drops **by design**
> (`head = text.split(" profile=")[0].split(" + ")[0].split(" (")[0]`) — a tail-drop a sibling unit
> already measured and recorded as `"tail_dropped"` in
> `platform/architecture/_probe_cf_compound.out.json:5` `[S]`, and whose second-half targets
> (`tools/plugin/schema/…`, `tools/marketplace/schema/…`, `.claude-plugin/…`) do not exist on disk —
> the directories `tools/plugin` and `tools/marketplace` are **absent entirely** `[M]`.
> Render that and the architecture's promise — *make silence typed* — inverts into its opposite:
> **make wrongness authoritative.** A confident false dashboard is worse than an honest blank.

### §7.3 "The headline benefit is not even unique, and doc 13 ranks the alternative first."

> Doc 13 §3's own hazard matrix scores **A10 falsification-plane ● on H-h** and **A9 hybrid ● on
> H-h** — the same hazard UX-first claims as its reason to exist. Doc 13's leverage ranking is
> **A10 > A9 > A2 > A7 > A6 > A4 > A11 > A8 > A3 > A5 > A1**, and UX/product-first **does not appear
> in doc 13's candidate set at all** (A1-A11 contain no UX candidate; the closest, A3, is
> marketplace-first and its own strongest-argument-against calls it *"a product answer to an estate
> problem"*). Arguing that the *perception* layer is the keystone, when a higher-ranked sibling
> closes the same hazard at the *contract* layer, is arguing for the softer of two available fixes.

### §7.4 Does it kill the design? Partially. Here is exactly which part.

**I concede §7.1 as CONFIRMED against the first-mover claim.** UX/product-first is **not** a winning
standalone architecture and must **not** be sequenced first. If this candidate were adopted as the
program's primary architecture, the honest prediction is that it would ship five beautiful views over
an empty factory, and the tournament should mark that down. I am not going to argue otherwise to win
a round.

**What survives, and why it is not theatre:**

1. **The mechanism is already built, green, and both-states-proven.** I did not propose a projection
   plane; I measured one — `render.py::outputs()`, 1,842 LOC of tooling, 48 tests, a `--check` that
   I watched fire on a corrupted state and go quiet on a clean one. Extending a working plane from
   **4.88% to 100%** of the object graph for ~800-1,100 LOC and **zero new control planes** is not
   invention-for-its-own-sake. §7.1 refutes *building the dashboard first*; it does not refute
   *finishing a plane the program already committed to and shipped half of*.
2. **§7.2 is an argument for ordering, not for abandonment** — and it is self-limiting. A projection
   that renders its `SOURCE-INTEGRITY` band (§F1) reports `1,679/2,007 strict` on the same screen as
   its data. That is not "confident wrongness"; that is the first artifact in the program that makes
   the catalog's own defect rate visible to the owner without running a conformance suite. The
   refutation lands hard against a *naive* renderer and is answered by T7.
3. **§7.3 is correct that A10 is the better keystone — which is my actual recommendation.** The two
   are complementary, not competing: A10 types the verdict at the contract layer; UX-first is what
   makes the typed verdict *arrive*. MECH-03 is doc 13's highest-EV mechanism precisely because
   `NOT-CHECKED` is a token a human is supposed to read, and doc 13 never specifies who renders it.

**The advocate's honest verdict.** UX/product-first should be committed to the tournament as **the
strongest single module of a hybrid, correctly sequenced third** — after a contract/falsification
plane (A10-shaped) and after the first real receipts exist. Its S0 (debris quarantine, 135 files, no
code) and its §4.3 finding (`render.py` writes by default) should be adopted **regardless of which
architecture wins**, because neither depends on this candidate winning anything.

A tournament entry that argues for its own third place is more useful than one that argues for a
first place the evidence will not carry. That is the honest reading, and it is the one I am
committing.
