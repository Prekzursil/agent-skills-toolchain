## Executive result

I found **four runtime-relevant coherence conflicts** in the supplied snapshot:

1. `intent-drift-sentinel` demands `AskUserQuestion`, but Claude Code does not make that UI/session-state tool available to subagents. The settings additionally force forked subagents. The native subagent capability restriction wins.
2. `security-reviewer` declares a per-agent `fallbacks` field that is not a supported subagent frontmatter field, while settings defines the real `fallbackModel` chain. The settings fallback chain wins after the agent's supported `model: opus` selection fails.
3. `chief-of-staff` claims Slack MCP operation, but its own exclusive tool allowlist has no Slack tool; settings also supplies no Slack permission/plugin entry. The agent allowlist wins, so the described Slack calls cannot occur in that subagent.
4. `chief-of-staff` promises a post-send follow-through hook that “blocks completion,” but neither configured `PostToolUse` dispatch path contains that check. The actual settings hook graph wins; no such completion block is configured in this snapshot.

The first, third, and fourth conflicts arise on ordinary advertised use cases. The second arises only when the security reviewer's primary model is overloaded or unavailable.

Confidence in findings 1, 3, and 4 is **almost certain (90-99%)**: each is supported by the agent text, a separate settings/runtime signal, and the current official Claude Code runtime contract. Confidence in finding 2 is **very likely (80-90%)**: the current official field list and fallback-chain documentation are clear, but the remote Linux job cannot execute the owner's installed Windows Claude binary to observe its exact version's diagnostic behavior. The settling experiment is given in finding 2.

This is not a complete audit of the stated 27-agent population. The bundle contains only 18 agent files. I audited all 18 supplied files and all 704 lines of settings; the unprovided nine are a GAPS item, never evidence that they are coherent or absent.

## Runtime rules used to adjudicate precedence

The relevant current Claude Code contracts are:

1. An agent `tools` field is an exclusive allowlist. Subagents inherit tools by default only when it is omitted. See [Create custom subagents — Available tools](https://code.claude.com/docs/en/sub-agents#available-tools), especially the documented statement that a `tools` list restricts the agent to the listed tools.
2. `AskUserQuestion` is explicitly among the UI/session-state tools unavailable to subagents even if named in `tools`. See [Create custom subagents, lines 356-365](https://code.claude.com/docs/en/sub-agents#available-tools).
3. Supported agent frontmatter includes singular `model`; it does not include `fallbacks`. Model resolution is environment override, per-invocation model, agent `model`, then main model. See [Create custom subagents — Choose a model](https://code.claude.com/docs/en/sub-agents#choose-a-model).
4. `settings.json` `fallbackModel` is the supported fallback chain for an overloaded or unavailable primary model; the highest-precedence settings source supplies the chain. See [Claude Code settings — `fallbackModel`](https://code.claude.com/docs/en/configuration#available-settings), documented at the page's settings table.
5. Settings hooks are the runtime registrations. The local `_dispatch/dispatch.py` confirms it loads only the checks in `manifest.json`: `_dispatch/dispatch.py:9-18,147-151,215-220`. Therefore a broad settings matcher is not evidence that an arbitrary unlisted communications check exists.

These are current documentation contracts, not claims from the earlier mega-audit.

## Finding 1 — sentinel's interactive question tool is impossible in a subagent

### Both sides, verbatim

Agent:

> `description: On-demand intent/drift guard — ask 1-3 EVPI-gated clarifying questions (ASK-GATE) and/or compare live event-ledger turns against the recorded goal to surface a goal-gap verdict (DRIFT-GATE); returns a compact structured verdict, never chain-of-thought; invoke via /sentinel before starting ambiguous tasks or mid-task drift checks; NOT for implementation, editing, or web access.`  
> `tools: ["AskUserQuestion", "Read", "Bash", "mcp__basic-memory__search_notes", "mcp__basic-memory__build_context", "mcp__basic-memory__read_note"]`

— `/local_disk0/codexwork/bundle/claude/agents/intent-drift-sentinel.md:3-4`

The body makes this operational, not decorative:

> `When you DO ask, ask at most 3 questions, ordered by impact. Use AskUserQuestion with a clear preamble:`

— `intent-drift-sentinel.md:24`

Settings:

> `"CLAUDE_CODE_FORK_SUBAGENT": "1",`

— `/local_disk0/codexwork/bundle/claude/settings.json:5`

Settings also declares the ordinary tools permission list at `settings.json:26-63` and `defaultMode: "bypassPermissions"` at line 71. `AskUserQuestion` is not in that allow array, but that omission is **not** the reason for the finding: the official tools reference says `AskUserQuestion` needs no permission. The decisive rule is that it is unavailable in a subagent even when listed.

### Concrete collision

The collision occurs whenever `/sentinel` is invoked on an ambiguous request and its EVPI gate decides one or more questions are material. The agent is instructed to make an interactive `AskUserQuestion` call, but Claude Code cannot attach that UI/session-state tool to a subagent. With fork mode set, the invocation is necessarily a forked subagent as well.

The agent already contains a degraded fallback:

> `If AskUserQuestion is not available in context, print the questions as plain text instead and note "AskUserQuestion unavailable — questions printed for manual response".`

— `intent-drift-sentinel.md:102`

That prevents a total failure, but it does not fulfill the advertised “questions asked via AskUserQuestion” behavior at lines 3, 24, and 82. Printing questions inside a subagent result also cannot synchronously pause the parent's work for answers.

### Runtime winner

**Native subagent capability restriction wins.** The string in agent frontmatter cannot manufacture a UI-only tool. Confidence is **almost certain (90-99%)**, based on the verbatim agent declaration, the fork setting, and the official current subagent tool exclusion.

### Minimal resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)

Remove `AskUserQuestion` from the agent's `tools` list and change ASK-GATE to return a small structured `questionsForParent` list. Instruct the parent `/sentinel` command or caller to ask those questions with its own native `AskUserQuestion` tool before continuing. This preserves isolation and makes ownership of the interactive UI explicit.

The truly smallest textual edit—merely deleting the tool and retaining line 102's plain-text fallback—would make the file internally truthful but would still not implement the advertised pause-for-answer gate. The parent-relay edit is the minimal functional resolution.

Anti-overfit gate: passes. It uses the existing subagent return path and native parent tool; it adds no runtime, memory service, critic, SaaS, or guardrail framework.
