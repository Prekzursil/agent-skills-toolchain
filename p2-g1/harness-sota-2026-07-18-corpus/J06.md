# J06 — Idle-time research on open threads: bounded anticipation, not autonomous wandering

## Executive verdict

Yes—but only for **explicitly active owner threads**, only as **bounded read-only evidence acquisition**, and only when a concrete external event makes new information likely. The harness should not interpret an idle clock as permission to invent priorities, execute changes, or start an unbounded “dreaming” loop.

The recommended operating model is:

> **Observe externally → select an owner-anchored thread → buy a small evidence packet → verify it outside the researching context → queue a concise delta → surface at a workflow boundary → keep the thread open until owner acknowledgement or an external completion signal.**

This conclusion is **very likely (80-90%)**, supported by (a) this corpus's strong owner preference for comprehensive, research-backed continuation, (b) repeated stop feedback asking the agent not to stop, (c) a recent field study in which proactive developer interventions were much better received at workflow boundaries than mid-task, and (d) the local history showing that learned suppression can silence useful routing. It is not “almost certain” because this corpus does not contain reliable hook telemetry or a controlled measurement of the owner's acceptance rate for background-research items; the corpus explicitly marks its hook detector broken (`/local_disk0/codexwork/bundle/inputs/corpus.json:13260-13263`).

The **UNVERIFIED** premise is that owner-anchored idle research has positive net value in this exact workspace. The settling experiment is a four-week shadow trial described under Finding 6: alternate eligible active threads between `research-shadow` and `no-research`, measure externally verified useful deltas, owner acknowledgement/action, later duplicated research avoided, cost, and correction burden. Until that trial, “yes” means a capped pilot, not a permanent license.

No second orchestration runtime, vector database/knowledge graph, durable-execution engine, trained critic, observability SaaS, or guardrail framework is proposed. Every proposal rides the existing event-ledger / `OPEN-THREADS.md` / Basic Memory / scheduled producer / background-digest / dispatcher bus. No proposal adds a seventh hook. The one hook-adjacent change folds into the existing `background-digest` reader already documented as folded into the dispatcher rather than registered as another raw SessionStart hook (`/local_disk0/codexwork/bundle/claude/hooks/background-digest/reader.py:2-6`).

## Findings — inferred surprises first

### Finding 1 — Replace “idle time” with “externally triggered research windows”

**Improvement:** Research on meaningful external change, not merely because the owner has stopped typing.

**What it is:** An eligibility function run by the existing scheduled producer selects a research window only when all of these hold:

1. a thread is explicitly `active` and has an owner-authored goal or acceptance criterion;
2. an external trigger exists—upstream release, failing CI/test, stale citation, changed dependency, approaching deadline, newly available tool, or a thread-specific `research_after` timestamp;
3. no active foreground session owns the same thread;
4. the thread's cost lease has budget remaining;
5. the task is read-only and produces an evidence packet, not a mutation.

Plain machine idleness is not evidence of owner priority. A scheduler can be idle while the owner has intentionally deferred a thread, changed focus elsewhere, or is resting. The anticipatory-computing literature frames the loop as sensing context, predicting it, deciding, then feeding results back—not as firing solely on elapsed inactivity ([Pejovic & Musolesi, ACM Computing Surveys 2015](https://cris.unibo.it/handle/11585/740686)). Horvitz likewise identifies uncertainty about goals, attention-aware timing, and expected costs/benefits as core mixed-initiative principles ([CHI 1999 paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)).

**Why-inferred:** The owner wants research by default and opportunistic improvements, but also has explicit archived and deferred items that must not be proactively re-suggested. The local index contains both a general archived-candidates record (“do not re-suggest”) and a specific deferred microVM decision (`recall_index.json:6725-6757`, `6857-6893`). That combination implies a desire for initiative constrained by durable priority state, not generic busyness.

**How-to-build:** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Extend the existing scheduled producer's input reader—not the hook roster—with a small eligibility function. Read a normalized thread row from `OPEN-THREADS.md` or a sidecar JSONL generated from it:

```text
thread_id, state(active|waiting|deferred|archived|done), owner_goal,
acceptance_signal, research_after, external_watch, max_minutes,
max_queries, spend_cap, foreground_lease_until
```

Only `active` rows pass. `waiting` rows pass only if their named external condition changes. `deferred`, `archived`, and `done` never pass. Acquire an atomic, expiring per-thread lease; invoke the already-installed deep-research route for at most the row's cap; emit a packet to the existing background digest. Wrap the producer in try/except and return success on its own error. Do not register a hook.

**External signal that verifies it:** A known-positive synthetic thread with a changed test fixture must produce exactly one packet; an otherwise identical `deferred` control must produce none; a live foreground lease must suppress the packet. Then, over four weeks, compare eligible-window packets with clock-idle controls on owner act/ack rate and externally verified novelty. These are execution and owner signals, not same-context reflection.

**Confidence:** **Very likely (80-90%)** that event-triggering will drift less than clock-idle triggering, based on explicit local deferred/archived states and mixed-initiative evidence on goal uncertainty and attention. **UNVERIFIED** in this workspace; the A/B shadow trial above settles the size of the gain.

**SOTA citation:** [Horvitz, “Principles of Mixed-Initiative User Interfaces,” CHI 1999](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf); [Pejovic & Musolesi, “Anticipatory Mobile Computing,” ACM CSUR 2015](https://cris.unibo.it/handle/11585/740686).

**Value x effort:** transformative x medium.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for eligible, owner-anchored, read-only packets; confirm-first for adding a new thread, expanding scope, spending beyond its lease, or any mutation.

### Finding 2 — Delivery is not closure: add acknowledgement escrow to the existing digest

**Improvement:** Prevent background findings from disappearing merely because they were injected into a session.

**What it is:** Change digest lifecycle from `pending → surfaced → archived/removed` to `pending → surfaced_unacked → acknowledged|snoozed|rejected`, with re-surfacing only at bounded workflow boundaries. A research packet retains its thread ID and remains linked to the open thread until acknowledgement or an external completion signal.

**Why-inferred:** “Never drop a thread” is a hard constraint, yet the current digest says it surfaces entries once and then truncates them (`background-digest/reader.py:7-10`). The implementation independently confirms that it emits, archives, and truncates immediately (`reader.py:216-220`). Injection into model context is not proof the owner saw, accepted, or acted on an item. That is a mechanically grounded mismatch, not an inference from silence.

**How-to-build:** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Fold the change into `background-digest/reader.py` and its existing dispatcher registration—no new hook. Store packet state in append-only JSONL beside the archive. Surface at most three unacknowledged packet titles plus a one-line delta; do not dump the current maximum of 12 full entries. The normal conversation parser can record explicit owner responses (`ack J06-…`, `snooze … until DATE`, `reject … because …`) through existing `note.py`/open-loop tooling. In the absence of acknowledgement, use bounded deferral: wait for a workflow boundary or a maximum age, then surface one compact reminder. Never let `calibrated-silence` permanently suppress an active never-drop thread; it may defer the display, not close the escrow.

The current FIFO behavior is explicit (`reader.py:138-158`). Preserve FIFO inside equal priority, but order the visible three by `urgent external deadline`, then `owner-pinned`, then `oldest unacknowledged`. This reduces prompt fatigue without silently discarding overflow.

**External signal that verifies it:** An end-to-end black-box test writes three packet IDs, invokes SessionStart, and verifies by a separate file reader that all three remain `surfaced_unacked`; a second invocation before the deferral bound emits none; an explicit ack written through `note.py` changes one packet to `acknowledged`; after the bound, only still-unacknowledged packets reappear. A second test kills the reader between emit and state write and verifies from the append-only file that the packet is recoverable. Owner “seen/acted/snoozed/rejected” is the production outcome signal.

**Confidence:** **Almost certain (90-99%)** that acknowledgement escrow reduces silent thread loss, because current documentation and code both consume at surface time while the governing requirement defines surfacing as insufficient. **UNVERIFIED** whether the owner prefers explicit textual ack commands over implicit next-turn inference; a two-interface usability trial—compact `ack/snooze/reject` text versus inferred reaction with correction affordance—settles it.

**SOTA citation:** Bounded deferral explicitly balances awareness against interruption rather than equating first delivery with completion: [Achlioptas & Horvitz, MSR-TR-2005-87](https://www.microsoft.com/en-us/research/publication/principles-of-bounded-deferral-for-balancing-information-awareness-with-interruption/). User control and easy correction are central in the empirically validated [Amershi et al. CHI 2019 guidelines](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/).

**Value x effort:** transformative x medium.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for state retention and bounded requeue; confirm-first before treating an ambiguous owner response as rejection or closure.

### Finding 3 — Use a falsification packet, not a self-authored research essay

**Improvement:** Make every background result a small claim bundle whose truth is decided outside the researching context.

**What it is:** Each packet contains: thread ID; the decision it could change; claim; counterclaim; source URLs and retrieval times; quoted-free paraphrase; confidence band; a cheapest falsifying experiment; cost spent; and one of `corroborated`, `contested`, or `unverified`. The agent that researched the claim cannot promote it using its own critique.

**Why-inferred:** The binding law says intrinsic same-context self-correction fails. Local operations independently substantiate the risk: the known-defects file records six confident wrong conclusions from unvalidated probes and a seventh capability-detector error caught by a known-positive control (`/local_disk0/codexwork/bundle/inputs/INPUT-known-harness-defects.md:119-138`). The corpus's own correction miner warns that 41/41 smoke-sampled candidates were false positives (`corpus.json:10371-10374`). A polished same-context digest would amplify, not solve, this failure mode.

**How-to-build:** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Add a packet schema to the existing deep-research output contract and background-digest producer configuration. Promotion requires one of these external closures:

- two primary sources with mechanically independent provenance that agree;
- one primary source plus an execution/test result;
- one source plus a fresh-context second model tasked specifically to refute, with disagreement preserved;
- explicit owner adjudication.

For absence/broken claims, require a known-positive control and a second measurement field/tool. A second model is an external signal only when it receives the evidence packet without the first model's chain of reasoning and is asked for a falsifying verdict. It is not ground truth; disagreement leaves the packet `contested`.

**External signal that verifies it:** Seed a packet set with known true, known false, and deliberately ambiguous claims. Run the producer and independent adjudicator; measure precision, false promotion, and unresolved-rate against the labeled fixtures. In production, measure subsequent test/source reversals and owner corrections per promoted packet. The test labels, execution results, second context, and owner are all external to the originating context.

**Confidence:** **Very likely (80-90%)** that structured external promotion reduces confidently wrong background suggestions, based on the seven local detector/probe failures and the correction-miner false positives. **UNVERIFIED** whether two-source corroboration is cost-effective for every domain; a stratified trial by software, research, and operations thread settles domain-specific gates.

**SOTA citation:** The proactive-agent benchmark itself labels proposed assistance with human accept/reject judgments rather than model self-approval ([Lu et al., ProactiveBench, 2024](https://arxiv.org/abs/2410.12361)). Appropriate reliance requires accepting correct and rejecting incorrect AI output, and a 2024 synthesis reviews roughly 50 studies rather than treating explanations as correctness ([Passi, Dhanorkar & Vorvoreanu, MSR-TR-2024-7](https://www.microsoft.com/en-us/research/publication/appropriate-reliance-on-generative-ai-research-synthesis/)).

**Value x effort:** high x low.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for read-only verification; confirm-first when only the owner can adjudicate priority or preference.

### Finding 4 — Give every open thread a revocable priority lease, not a permanent inferred preference

**Improvement:** Keep proactive research aligned as owner priorities evolve.

**What it is:** A thread's permission to receive background research expires unless renewed by an external signal: recent owner mention, a named deadline, changed watched artifact, failed acceptance test, or explicit recurring lease. Learned preferences may rank already eligible threads but may not create eligibility.

**Why-inferred:** The workspace contains explicit “do not proactively re-suggest” decisions (`recall_index.json:6725-6757`, `6857-6893`), while the behavior contract requests proactive suggestions and research (`recall_index.json:13211-13232`). Static personalization cannot reconcile these without state and expiry. The calibrated-silence history also records a behavior drift in which a learned route hit rate fell to 0.07 and suppressed the router (`recall_index.json:14044-14074`); this is a warning that implicit feedback can overgeneralize.

**How-to-build:** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Extend the thread row with `lease_source`, `lease_issued`, `lease_expires`, `negative_constraints`, and `renewal_event`. Default inferred-surprise threads to a short shadow lease that permits metadata-only scouting, not full research. Owner-pinned active threads may receive a longer read-only lease. Deferred/archived is a hard veto. Expose the lease reason in every packet: “researched because upstream X changed on DATE and thread Y is active.” Use the existing event ledger to append renewals/closures; do not infer permanent personality from terse prompts or repeated system-generated stop feedback.

**External signal that verifies it:** Replay a labeled timeline containing active, deferred, reactivated, and completed threads. A separate deterministic checker verifies zero research after deferral, zero resurrection after archive, and prompt-to-packet linkage for active leases. In production, owner rejections tagged “wrong priority” and reactivations settle calibration.

**Confidence:** **Very likely (80-90%)** that revocable leases reduce priority drift, supported by coexisting proactive preferences and explicit do-not-resuggest records. **UNVERIFIED** optimal lease durations; a survival analysis of time from owner mention to later action/rejection during the pilot settles duration by thread class.

**SOTA citation:** Mixed-initiative systems should model uncertainty about goals and allow easy invocation/termination ([Horvitz 1999](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)). User studies of steerable personalization report heterogeneous preferences around control, transparency, and usability, arguing against one opaque permanent profile ([Bo et al., 2025](https://research.google/pubs/personalizing-llms-with-preference-based-activation-steering/)).

**Value x effort:** high x medium.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for expiring existing leases and obeying vetoes; confirm-first to create or materially widen a lease.

### Finding 5 — Surface at workflow boundaries through a three-line “delta receipt”

**Improvement:** Protect owner focus by separating research production from notification timing and display volume.

**What it is:** Background work may finish at any time, but the owner sees it only at a natural boundary: new main session, post-commit, completed workflow, explicit “what changed?”, or approaching hard deadline. Each visible item is three lines: **what changed**, **why it matters to thread X**, **one reversible next action**. Full evidence remains in the artifact/packet, not prompt context.

**Why-inferred:** Prompt fatigue is a hard constraint. The existing digest can surface 12 oldest entries plus overflow (`background-digest/reader.py:67`, `138-158`), which is continuity-safe but potentially focus-expensive. Recent field evidence is unusually direct: in a five-day study with 15 developers, 229 interventions across 5,732 interaction points, post-commit interventions received 52% engagement while mid-task interventions were dismissed 62% of the time; well-timed proactive suggestions also took less interpretation time ([IUI 2026 field study](https://arxiv.org/abs/2601.10253)).

**How-to-build:** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Change the existing reader configuration and packet rendering: maximum three receipts, maximum roughly 80 words total, full packet path included, overflow counted rather than expanded. Define boundary events from already available ledger/tool results. Urgent safety/deadline items may bypass deferral but still use the compact receipt. The background producer never messages the owner directly.

**External signal that verifies it:** Randomize eligible packets between boundary delivery and next-arbitrary-turn delivery. Record owner open/ack/action/dismissal, time to action, and interruption correction (“not now,” “why are you telling me this”). The event ledger provides timing; owner behavior supplies utility. Also measure prompt-token injection and session abandonment.

**Confidence:** **Very likely (80-90%)** that boundary delivery reduces interruption cost, based on the 2026 in-the-wild developer study and the local focus constraint. **UNVERIFIED** whether three receipts/80 words is the owner's optimum; a within-owner dose trial of 1 versus 3 receipts settles the cap.

**SOTA citation:** [Shin et al., “Developer Interaction Patterns with Proactive AI,” IUI 2026](https://arxiv.org/abs/2601.10253); [Achlioptas & Horvitz, bounded deferral](https://www.microsoft.com/en-us/research/publication/principles-of-bounded-deferral-for-balancing-information-awareness-with-interruption/). A 2025 proactive AR study similarly found context-adapted, minimally intrusive delivery reduced perceived intrusiveness while retaining utility ([Sensible Agent](https://research.google/pubs/sensible-agent-a-framework-for-unobtrusive-interaction-with-proactive-ar-agent/)).

**Value x effort:** high x low.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for deferral and compact rendering; confirm-first for interrupting mid-task except a pre-authorized urgent condition.

### Finding 6 — Run a shadow-value trial before granting standing autonomy

**Improvement:** Decide whether idle research earns its cost with owner and execution outcomes, not enthusiasm or same-model scoring.

**What it is:** A four-week shadow experiment logs what the research producer *would* have surfaced. Half of eligible windows, stratified by thread type and trigger, get a capped research packet; half get metadata-only control. For the first two weeks, neither interrupts the owner. At the next owner-requested touch of that thread, a fresh context checks whether the packet contains a decision-changing delta not already discovered. Weeks three and four surface only the highest-scoring half at workflow boundaries.

**Why-inferred:** The corpus proves search is frequently used and reliable at the tool-call level, but not that unprompted research is valuable. Hook behavior is explicitly unmeasurable in this corpus because its detector failed a known-positive control (`corpus.json:13260-13263`). The owner-correction detector is also unsuitable as a raw success label (`corpus.json:10371-10374`). Standing autonomy without an experiment would therefore rest on missing telemetry.

**How-to-build:** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** Add experiment fields to background packet JSONL: `arm`, `eligible_ts`, `thread_type`, `trigger`, `queries`, `wall_seconds`, `estimated_cost`, `sources`, `external_verdict`, `surfaced_ts`, `owner_reaction`, `action_ts`, and `later_duplicate_avoided`. Use deterministic hashing of thread ID plus eligibility timestamp for assignment. A fresh-context verifier sees the packet and current thread artifacts but not the producer's reasoning. Promotion criteria should be fixed before looking at results:

- zero resurrected deferred/archived threads;
- zero unverified claims presented as facts;
- owner `acted + explicitly useful` rate materially above `annoyed + wrong priority`;
- at least one externally confirmed avoided duplicate search or earlier resolved blocker per bounded cost unit;
- no increase in mid-task interruption corrections;
- no open thread lost because a packet was surfaced.

Do not optimize against an LLM “quality score.” That would violate the external-signal law.

**External signal that verifies it:** Git/test outcomes, changed upstream artifacts, fresh-context adjudication, owner reactions, subsequent duplicate-search logs, and actual query/time/cost counters. The experiment itself is the verification mechanism.

**Confidence:** **Almost certain (90-99%)** that a shadow trial provides better calibration than immediately enabling standing background research, because current hook telemetry is explicitly invalid and tool reliability is not equivalent to usefulness. **UNVERIFIED** whether four weeks yields enough eligible events; pre-register a minimum of 30 eligible windows and extend duration, not scope, if fewer occur.

**SOTA citation:** ProactiveBench used human accepted/rejected labels over 6,790 events rather than self-evaluation ([Lu et al. 2024](https://arxiv.org/abs/2410.12361)). A newer multi-objective agent study argues productivity, proactivity, and personalization must be optimized jointly rather than collapsing everything into task success ([Sun et al., 2025](https://arxiv.org/abs/2511.02208)); its reported gains are research results, not yet evidence that this harness will reproduce them.

**Value x effort:** transformative x medium.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it for metadata-only shadowing and capped read-only randomized packets; confirm-first before moving from shadow to owner-visible standing delivery.

### Finding 7 — Budget by expected decision value, with hard stop rules and circuit breakers

**Improvement:** Prevent cheap curiosity from consuming expensive attention, tokens, or fragile tools.

**What it is:** Each research lease receives a tiny portfolio budget and a stopping rule. A default packet gets, for example, two search queries, up to three primary sources, one external verification, and ten wall-clock minutes. Continue only if the last step changed the likely decision or exposed a falsifiable blocker. Stop on repeated source convergence, no primary source, tool error loop, foreground contention, or budget exhaustion.

**Why-inferred:** WebSearch is reliable in this corpus (0.65% error), but WebFetch is materially noisier (5.57%) (`corpus.json:63-76`). The corpus also records retry loops across Read, Bash, background output, deep-research checking, PowerShell, and StructuredOutput (`corpus.json:10297-10368`). Unbounded “keep researching” can therefore turn low marginal value into retry cost. StructuredOutput's 22.9% error rate (`corpus.json:103-110`) argues for a small tolerant packet schema rather than a brittle, deeply nested mandatory fan-out schema.

**How-to-build:** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Put caps and stopping predicates in the scheduled producer configuration. Prefer WebSearch for discovery, then direct primary pages; do not call known-dead MCPs. After two failures with the same fingerprint, stop that route and leave a `verification_blocked` packet—do not let the researching model decide its workaround is equivalent. Estimate marginal decision value with an externally checkable question: “Which owner decision or acceptance test could this new source change?” If none is named, stop. Keep schema fields optional except thread ID, source, claim, status, and cost.

**External signal that verifies it:** Compare pilot arms with and without stop rules on queries, wall time, tool errors, promoted unique deltas, owner action, and later corrections. A deterministic cost collector and tool execution results supply the signal. Owner action/ack supplies value.

**Confidence:** **Very likely (80-90%)** that hard caps reduce waste and retry loops; the corpus directly shows differing tool error rates and recurring retry sequences. **UNVERIFIED** that the example cap (2 queries/3 sources/10 minutes) is optimal; sweep caps in shadow mode and choose the knee of externally verified useful deltas per cost.

**SOTA citation:** Horvitz's expected-utility formulation says autonomous action should exceed inaction after costs, benefits, and goal uncertainty are considered ([CHI 1999](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)). Recent risk-sensitive proactive-agent work similarly uses an acceptance threshold derived from asymmetric false-alarm and missed-help costs; this is **UNVERIFIED** for this owner until the shadow trial estimates those costs ([PRISM, 2026](https://arxiv.org/abs/2602.01532)).

**Value x effort:** high x low.

**Novelty:** inferred-surprise.

**Autonomy:** just-do-it within an existing lease; confirm-first to exceed any cap or switch to paid/high-impact resources.

### Finding 8 — Separate “research permission” from “action permission” with an autonomy ladder

**Improvement:** Gain anticipatory value without letting a plausible finding mutate the owner's systems or priorities.

**What it is:** Four explicit rungs:

0. **Watch:** compare external state, no model call if unchanged.
1. **Research:** read-only capped packet for an active thread.
2. **Prepare:** draft a command, patch, test plan, or decision memo in the packet; do not apply.
3. **Act:** only after explicit owner authority or a pre-authorized reversible action class with an external test and rollback.

An idle window may autonomously use rungs 0-1. Rung 2 requires the thread's lease to say `prepare_ok`. Rung 3 is not granted by idle time, model confidence, repeated prior approval, or a second model.

**Why-inferred:** The existing digest already follows “LOG + PROPOSE only” and says the agent/user runs proposed commands (`background-digest/reader.py:12-18`). The owner's corpus contains high autonomy language, but the known defects show orchestrator-authored false constraints can propagate to roughly 15 agents (`INPUT-known-harness-defects.md:147-161`). Separating knowledge acquisition from mutation contains such errors without discarding initiative.

**How-to-build:** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** Add `autonomy_rung` and `allowed_outputs` to the existing thread/packet schema. The producer rejects any tool outside the rung's allow-list. Prepared patches live only as artifacts and include base revision plus an external validation command. Existing edit checkpoints and rollback remain the mutation mechanism after approval; do not build another executor. ## Cost/value model

The cost ledger should distinguish:

- **Trust cost:** promoted claim later reversed, deferred item resurrected, mutation without authority, thread silently dropped, polished explanation without external proof.
