# X049 — Cross-domain borrow: control theory → reliability of agent conclusions

## Executive verdict

The analogy transfers, but only in a deliberately narrow form.

The useful control-theory mechanism is **fault detection and isolation (FDI) by analytical redundancy, observer residuals, and active test excitation**. A physical controller does not equate one sensor reading with the hidden plant state. It asks whether the state is observable from the available input/output history, compares measured output with independently predicted output, treats their difference as a residual, and—when ordinary operation is not diagnostic—injects a test input chosen to separate competing fault hypotheses. NASA's flight-control work adds two details that are directly valuable here: use like-signal differences to *detect* a problem but unlike analytical relationships to *isolate* the bad sensor, and use sensor self-test while a sequential test handles irreducible residual error [Deckert and Szalai, NASA NTRS 1983](https://ntrs.nasa.gov/citations/19830026629). A later NASA rocket-engine study states the crucial limit: with only two sensors, disagreement detects a fault but cannot identify which sensor is faulty; a model-based analytical relationship can provide the additional information needed for isolation [NASA/TM-20205000446, pp. 1–2](https://ntrs.nasa.gov/api/citations/20205000446/downloads/TM-20205000446.pdf?attachment=true).

Concrete translation: put a small **Claim FDIR gate** on the existing rule/hook bus. Before an agent may emit a high-confidence conclusion of `ABSENT`, `BROKEN`, or `DONE`, it must produce a transient evidence receipt containing:

1. the claim and its operational definition;
2. a known-present positive control passed through the same detector path;
3. two claim-bearing signals with distinct relevant failure domains, not merely two commands;
4. the expected observation and actual observation for each signal;
5. an explicit disagreement/ambiguity state; and
6. for `DONE`, a requirement-level check plus an outcome-level execution check.

If these conditions are not met, the permitted output is `UNKNOWN`, not a confident negative or completion claim. The key borrow is therefore not “add more checks.” It is **make diagnosability a precondition of conclusion**.

**Recommendation — Claim FDIR gate [UNVERIFIED: settle with the replay-and-seeded-fault experiment specified in §11].** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** It is **very likely (80-90%)** to catch the measured class of single-unvalidated-probe conclusions before they reach the owner, because the required receipt is structurally impossible to complete from one probe and because the positive control exposes a detector that cannot see a known-present object. This prediction remains **UNVERIFIED until the §11 replay-and-seeded-fault experiment measures catch rate and false blocks on real transcripts**.

This is not a proposal for a second orchestrator, model-based plant simulator, Kalman-filter service, vector database, trained critic, or generic guardrail framework. Those are unnecessary literalizations of the source field and fail the anti-overfit gate.

## 2. What control theory has already solved

### 2.1 Observability: do the outputs contain enough information to infer hidden state?

For a linear time-invariant system

\[
\dot{x}=Ax+Bu, \qquad y=Cx,
\]

the plant state `x` is generally not identical to the measured output `y`. Observability asks whether the initial hidden state can be determined from known inputs and measured outputs over a finite interval. For an `n`-state LTI system, the formal test is whether the observability matrix

\[
\mathcal O = [C^T,(CA)^T,\ldots,(CA^{n-1})^T]^T
\]

has full rank. The University of Michigan tutorial gives both this definition and the full-rank criterion [CTMS, lines under “Controllability and Observability”](https://ctms.engin.umich.edu/CTMS/index.php?example=Introduction&section=ControlStateSpace).

The important idea is epistemic, not the matrix calculation: **a measurement channel can be functioning and still be insufficient to distinguish hidden states**. If two candidate states generate the same observed output under the applied inputs, no estimator can truthfully select between them from those data. The correct result is unobservable/indeterminate, not a more confident guess.

Agent mapping:

| Control field | Agent reliability |
|---|---|
| hidden plant state `x` | actual proposition: item absent, subsystem broken, task complete |
| sensor output `y` | tool output, file listing, test result, API response, rendered behavior |
| known control input `u` | query, command, test fixture, sentinel, mutation-free diagnostic action |
| observability | whether available evidence can distinguish the relevant hypotheses |
| unobservable mode | two or more explanations remain compatible with all observations |

A zero-result search is compatible with at least two states: “target absent” and “detector failed or searched the wrong scope.” Therefore a single zero is not an observable absence. This is a structural statement, not a statistical one.

### 2.2 Observers and residuals: compare prediction with measurement

When not all states are measured, a state observer evolves a model-based estimate and corrects it using the innovation or residual between actual and predicted output:

\[
\dot{\hat{x}}=A\hat{x}+Bu+L(y-\hat y), \qquad \hat y=C\hat x.
\]

The CTMS tutorial explains that the extra term comparing `y` with `ŷ` corrects the estimated state, and gives the observer error dynamics as `ė=(A-LC)e` [CTMS, “Observer Design”](https://ctms.engin.umich.edu/CTMS/index.php?example=Introduction&section=ControlStateSpace). In FDI, that same mismatch becomes diagnostic: a residual near its expected range is compatible with the nominal model; a sufficiently inconsistent residual indicates some model, sensor, or actuator hypothesis is wrong.

Agent mapping:

- **Prediction:** “If this detector and scope are healthy, a known-present control should be returned.”
- **Measurement:** the actual tool output.
- **Residual:** expected-minus-observed, represented categorically (`match`, `mismatch`, `indeterminate`) rather than pretending agent evidence has a calibrated continuous model.
- **Innovation response:** do not reinforce the prior conclusion; change the diagnosis state and select a discriminating probe.

The proposal intentionally does not build a numeric observer. Agent tasks rarely supply a stable state-space model, calibrated noise covariance, or stationary dynamics. The transferable unit is the residual discipline: write down the expected observation before treating actual output as diagnostic.

### 2.3 Analytical redundancy: different relationships, not duplicated readings

Hardware redundancy repeats sensors. Analytical redundancy uses relationships among different measured quantities and a model to predict one from the others. NASA's flight-control implementation used differences between like signals for fault detection, then relationships among unlike quantities to isolate which sensor was faulty. It also used sensor self-test for immediate handling of hard faults while awaiting definitive analytical isolation [NASA NTRS 19830026629](https://ntrs.nasa.gov/citations/19830026629).

This distinction directly refines “two mechanically independent signals”:

- `rg` twice is one evidence channel repeated.
- If `rg` and `grep` read the same truncated/generated file, they are two executables but one upstream failure domain.
- a directory enumeration and a file-content lookup can still share a mount, permission boundary, or stale checkout.
- an API list operation and an independently authenticated object fetch have meaningfully different failure domains only when the target claim depends on the layers that differ.
- a source/config assertion and a runtime behavioral test provide analytical redundancy when an explicit behavior model relates the two quantities.

The relevant unit of independence is **failure-domain independence with respect to the claim**, not command-name diversity.

NASA's later rocket-engine paper supplies the adversarial warning. Three agreeing sensors can identify an outlier; with only two disagreeing sensors, a fault is detectable but the faulty sensor cannot be isolated. The paper uses a bank of Kalman filters and relationships among nonhomogeneous sensors to compare estimated and measured values [NASA/TM-20205000446](https://ntrs.nasa.gov/api/citations/20205000446/downloads/TM-20205000446.pdf?attachment=true). Thus:

> Two signals can establish inconsistency. They cannot, by count alone, establish which signal tells the truth.

For the harness, a passed positive control is the extra information that says the negative-result detector had sensitivity in the present context. It still does not prove the detector's full correctness. Therefore the conclusion records scope, and the proposed gate requires a third relationship whenever a high-consequence ambiguity remains.

### 2.4 Active fault diagnosis: choose an action that separates hypotheses

Passive diagnosis waits for ordinary input/output data. That data can be nondiagnostic: multiple healthy/faulty models predict the same observations. Active fault diagnosis designs a safe auxiliary input specifically to make candidate models produce separable outputs. The 2019 review states that nominal input/output data can contain insufficient diagnostic information and that active diagnosis injects signals designed to reveal fault status; the aim is maximal or full separation of predictions under different operating modes [Heirung et al. 2019](https://doi.org/10.1016/j.arcontrol.2019.03.002), [open manuscript](https://par.nsf.gov/servlets/purl/10180014).

This maps unusually cleanly to detector controls:

- Hypothesis H1: the queried target is absent.
- Hypothesis H2: the detector is broken, mis-scoped, permission-limited, or parsing the wrong representation.
- Passive observation: the target query returns zero; both H1 and H2 predict it.
- Active diagnostic input: query a known-present sentinel through the same detector path.
- Separated output: finding the sentinel is compatible with H1 and less compatible with the relevant forms of H2; missing the sentinel supports detector/path failure and forbids the absence conclusion.

The known-present control is therefore not generic “double checking.” It is an input deliberately selected to improve diagnosability.

### 2.5 Sequential decisions and deadbands: create an explicit uncertainty region

Physical residuals never equal exactly zero because of noise, bias, model mismatch, and disturbances. The NASA flight-control algorithm used a modified sequential probability ratio test that explicitly accommodated irreducible low-frequency errors in analytical-redundancy residuals [NASA NTRS 19830026629](https://ntrs.nasa.gov/citations/19830026629). Industrial controllers also use deadbands to suppress noise-driven oscillation of controller output [Siemens PID DEADBAND documentation](https://docs.tia.siemens.cloud/r/en-us/v20/modular-pid-control-s7-300-s7-400/deadband-s7-300-s7-400/description-deadband-s7-300-s7-400?contentId=vlGF_4TTqz7WhFHAyFLSkQ).

The safe agent translation is **not** to ignore inconvenient evidence. It is to define a middle state:

| Evidence state | Permitted conclusion |
|---|---|
| sufficiently consistent, healthy detector, independent corroboration | claim is eligible to pass with bounded scope |
| contradictory, incomplete, or within ambiguity band | `UNKNOWN`; gather discriminating evidence or disclose uncertainty |
| evidence supports counter-hypothesis | reject original claim |

This is a ternary decision boundary, not a time delay and not a numeric confidence theater. It prevents “zero result → absent” chatter when small changes in search scope flip the conclusion.

### 2.6 Anti-windup: a secondary, partial analogy

In PID control, an actuator can saturate while the internal integral term continues accumulating error. The visible output remains bounded, but the hidden integrator grows; after the error reverses, recovery can be slow. Back-calculation feeds the difference between saturated and unsaturated control signals back into the integrator; clamping conditionally stops integration while saturation and error direction would drive windup further [MathWorks PID Controller, “Anti-windup method”](https://www.mathworks.com/help/simulink/slref/pidcontroller.html).

There is a partial agent analogue: repeated retries or repeated same-channel observations can accumulate rhetorical confidence even after the information channel has saturated—no new information is entering. In the proposed anti-windup rule, a repeated failure fingerprint or shared upstream failure domain contributes no additional independent-evidence count.

This analogy is **likely (55-80%)** to be useful as a design explanation but **unlikely (20-45%)** to be sufficient as the primary reliability mechanism. Evidence: anti-windup addresses controller internal state under actuator saturation, whereas the target failure is incorrect inference under partial observability. The primary mechanism must therefore be diagnosability plus redundancy; anti-windup contributes only the rule “repetition without new information must not raise confidence.”

### 3.2 Gate state machine

```text
PROPOSED CLAIM
      |
      v
Is it ABSENT / BROKEN / DONE (or explicitly high consequence)?
      | no ------------------------------> ordinary answer path
      | yes
      v
Operational definition and bounded scope present?
      | no ------------------------------> UNKNOWN / ask or investigate
      | yes
      v
Positive control passes through the same relevant detector path?
      | no ------------------------------> DETECTOR INVALID -> UNKNOWN
      | yes
      v
At least two claim-bearing signals with an independence argument?
      | no ------------------------------> UNDERDETERMINED -> UNKNOWN
      | yes
      v
Signals agree and no unresolved disconfirming evidence?
      | no ------------------------------> AMBIGUOUS -> discriminate or disclose
      | yes
      v
Claim-specific sufficiency checks pass? ---- no --> UNKNOWN
      | yes
      v
PASS, with scope + evidence + confidence band
```

The gate's specified scope is assertive status, not useful work. The permitted fallback is to state the observation, describe unresolved hypotheses, and continue with an authorized safe discriminating test.

### 3.3 Claim-specific sufficiency profiles

#### `ABSENT`

Required:

1. explicit bounded search scope;
2. known-present positive control via the same detector path;
3. one enumeration/search signal;
4. one differently derived signal, such as direct lookup, source-of-truth query, or behavioral relationship;
5. representation alternatives considered when relevant (case, alias, branch, generated state, hidden/ignored files, pagination);
6. no unresolved contradictory evidence.

Example catch: a capability detector says zero skills. The positive control asks that same detector to find one known installed skill. If the control also returns zero, the absence claim is rejected as detector-invalid. This is **almost certain (90-99%)** to catch that exact failure shape because the gate's deterministic rule maps a failed control to `UNKNOWN`; the residual 1–10% covers failure of the agent/hook to classify the claim or faithfully emit the receipt. This remains **UNVERIFIED until E1 seeds that transcript shape through the actual gate**.

#### `BROKEN`

Required:

1. an operational contract (“input X under preconditions P must produce Y”);
2. a known-good control showing the test apparatus can observe Y;
3. a direct failure signal (error/incorrect behavior);
4. an independent signal tied to the same contract (health endpoint, alternative client, log-side outcome, minimal reproduction, or invariant violation);
5. separation of target fault from environment, permission, connectivity, and test-harness faults.

Example catch: one client reports “not connected.” A known-good endpoint or known-present server tested through the same client distinguishes client-wide failure from target-specific failure; a second channel such as server-side health or another authenticated protocol path helps isolate. The gate cannot conclude the target is broken if all evidence shares the same dead client.

#### `DONE`

Required:

1. a requirement-to-evidence checklist, not merely file existence;
2. an artifact-state signal (expected change exists in the intended scope);
3. an outcome signal (relevant test, render, execution, query, or acceptance check actually passes);
4. explicit accounting for skipped/unavailable checks;
5. no unresolved failing checks in scope.

Example catch: an edit tool reports success and the file exists, but no execution or requirement check occurred. The gate changes `DONE` to `IMPLEMENTED, VERIFICATION UNKNOWN`. It is **very likely (80-90%)** to catch completion claims whose only evidence is a write/edit success, because artifact-state and outcome evidence occupy separate mandatory fields. This remains **UNVERIFIED until E1 measures classifier coverage on real completion language**.

### 3.4 Mechanical independence test

For each pair of signals, ask:

> Name one plausible fault that could make both signals agree while the claim is false.

If a credible common cause exists and has not itself been checked, the pair is not independent enough for that claim. Examples:

| Pair | Independence judgment | Reason |
|---|---|---|
| same command rerun | no | identical code, scope, parser, source, permissions |
| two search binaries over same generated manifest | weak/no | manifest generation or staleness is common cause |
| filesystem enumeration + direct file read | partial | different operation, but shared mount/path/branch can fail both |
| config declaration + runtime behavior | analytically diverse when the contract links them | different layers connected by an explicit expected relationship |
| client response + server-side receipt/log | analytically diverse absent shared auth/routing | separates client interpretation from server observation |
| static code path + executed focused test | analytically diverse when the test reaches that path | source and behavior are different quantities, linked analytically |

Independence is claim-relative. The receipt must name the failure domains and common-cause analysis rather than select from a hard-coded tool-pair whitelist.

### 3.5 Active probe selector

**Proposal — a short rule library of discriminating probe patterns [UNVERIFIED: settle with Experiment E2 in §11].** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

The rule library should teach the agent to choose the cheapest safe input that makes live hypotheses predict different outputs:

| Ambiguity | Discriminating safe input |
|---|---|
| absent vs detector dead | query a known-present sentinel through same path |
| target broken vs all network unavailable | query known-good peer through same client, then target through independent channel |
| no matches vs wrong scope | enumerate scope boundary and query an exact known item in that boundary |
| code fixed vs test blind | deliberately exercise a known-failing fixture or known-positive assertion, then run target case |
| task done vs artifact merely written | execute the acceptance behavior or inspect rendered/consumed output |
| branch/path absent vs wrong revision | prove a known-present object in the intended revision, then direct-lookup target |

It is **likely (55-80%)** that a small curated pattern set improves probe choice without an optimizer, because the target errors recur in a few diagnosis shapes and active fault diagnosis establishes why discriminating inputs carry more information than passive repetition. ## 4. What this catches that a generic “double-check” misses

### 4.1 Broken detectors that return plausible zeroes

Two repeated zeroes look reassuring. A positive control makes the detector produce a prediction that differs between “target absent” and “detector blind.” This catches wrong-scope search, dead hooks, unsupported path semantics, empty indexes, auth-filtered enumeration, and parsers that silently discard all records—when those faults also affect the selected control.

The qualification matters: a control that exercises only a healthy subpath does not validate the target subpath. A top-level listing sentinel cannot validate pagination on a later page; a lowercase sentinel cannot validate case variants; a local-file sentinel cannot validate the remote branch. Controls must traverse the relevant path.

### 4.2 Correlated redundancy masquerading as confirmation

The independence argument exposes two different tools reading the same stale cache, two endpoints behind one dead proxy, or two tests sharing the same invalid fixture. A call count alone contains no field from which to detect those common causes.

### 4.3 Detection without isolation

When two probes disagree, naive majority logic either guesses or runs one of them again. The FDI framing explicitly distinguishes “a fault exists” from “this component is the fault.” The gate holds `UNKNOWN` until a self-test, third relationship, or authoritative source isolates the bad channel.

### 4.4 Confidence windup from retries

Repeated same-fingerprint failures add no new independent information. The anti-windup sub-rule prevents a fifth identical result from being represented as fivefold evidence. One observation plus four correlated retries remains one channel.

### 4.5 Premature completion

The `DONE` profile forces a separation between controllable action (“I wrote the change”) and observed plant outcome (“the intended consumer/test/render behaves correctly”). A successful actuator command is not proof the plant reached its target state.

## 5. Adversarial analysis: where the analogy breaks

### 5.1 There is usually no trustworthy plant model

Classical observability and observer convergence claims assume specified dynamics, measurement equations, and often linearity or a locally valid approximation. General agent work has shifting tools, hidden permissions, incomplete task definitions, nondeterministic services, and semantic propositions that do not form a stable vector state. Therefore the harness must not claim mathematical observability, observer convergence, or calibrated fault probabilities.

Design consequence: use **qualitative diagnosability**—explicit hypotheses and differing predicted observations—not an invented `A, B, C` model or fake Kalman covariance.

### 5.2 “Mechanical independence” is not statistical independence

Different commands can share operating system, credentials, workspace, cache, network, model assumptions, or a wrong user-specified premise. Independence is rarely provable from the transcript. The gate can require a failure-domain argument, but that argument can itself be wrong.

It is **roughly even (45-55%)** that an agent-generated independence explanation will catch subtle common-mode failures without an external taxonomy. Evidence for caution is the NASA two-sensor problem and the ubiquity of shared upstream dependencies; evidence for usefulness is that merely naming the source, parser, scope, auth, and representation makes obvious common causes inspectable. This remains **UNVERIFIED until E3 scores those explanations against seeded dependency graphs**.

### 5.3 Positive controls establish local sensitivity, not universal validity

Finding one known-present item proves only that the detector can find that item under that path and moment. It does not prove completeness, specificity, absence of pagination bugs, correct target spelling, equivalent permissions, or correct semantics. A control can also be mistakenly believed present.

Design consequence: record control provenance, scope equivalence, and why its path is relevant. For high-consequence claims, add a negative control or authoritative third relationship. Never phrase a passed positive control as proof of detector correctness.

### 5.4 The agent chooses both hypothesis and experiment

Engineered plants can have fault models specified in advance. If an agent omits the true hypothesis, its experiment separates only an incomplete set. For example, it considers `absent` versus `search broken` but not `present under alias`.

Design consequence: the receipt includes a small mandatory alternative-cause checklist for negative claims: scope, representation/alias, permissions/auth, freshness/revision, truncation/pagination, parser, and upstream availability. This checklist is a prompt aid, not a guarantee of completeness.

### 5.5 Active excitation can mutate or damage the system

Physical AFD trades diagnostic information against control cost. Agent probes also include potentially state-changing actions: creating a sentinel, sending a request, triggering a deployment, or modifying a database. Without task authority, those actions are unauthorized regardless of diagnostic value.

Design consequence: default to mutation-free controls already known present. Any state-changing diagnostic remains governed by ordinary user authorization and destructive-action policy. The reliability gate grants no new authority.

### 5.6 Human-language claim classification is porous

The same conclusion can be conveyed without exact words such as “absent,” “broken,” or “done” (“nothing there,” “all set,” “doesn't work”). A small deterministic hook cannot perfectly classify open-ended semantics.

It is **likely (55-80%)** that a compact phrase/structured-marker gate catches a substantial fraction but not all relevant conclusions, based on the narrow recurring claim classes and the ability to require the agent to self-mark them. It is **UNVERIFIED until E1 reports recall on manually labeled held-out transcripts**. This is the principal implementation risk.

### 5.7 Feedback stability is a metaphor unless the loop is bounded

A control loop has analyzable dynamics; a conversation is event-driven and model-mediated. Requiring ever more evidence can cause an investigation loop, higher cost, and delayed answers. No pole-placement or Lyapunov stability guarantee transfers.

Design consequence: bound the gate to high-risk status claims, cap discriminating probes, and allow a stable terminal state of `UNKNOWN with evidence`. Unknown is a successful epistemic outcome, not a reason to retry forever.

## 6. Deadband design without suppressing weak warning signals

A literal evidence deadband suppresses early weak evidence of a real failure. The correct mapping is asymmetric:

- weak or conflicting evidence is eligible to **lower confidence, warn, or investigate**;
- it is not enough to **raise confidence to ABSENT/BROKEN/DONE**;
- stronger evidence is required to cross the assertive conclusion threshold;
- once a claim is in `UNKNOWN`, small same-channel repetitions do not toggle it back and forth.

This resembles hysteretic decision thresholds more than a physical output dead zone, but numeric hysteresis requires calibration the harness does not have. Use categorical evidence sufficiency instead.

**Proposal — categorical `PASS / UNKNOWN / REJECT` decision state [UNVERIFIED: settle within E1].** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).** It is **very likely (80-90%)** to reduce confident unsupported conclusions if the final-answer policy enforces that only `PASS` receipts authorize the gated terms, because incomplete and contradictory evidence has an explicit non-assertive destination. It remains **UNVERIFIED until E1 measures whether agents comply and whether owner-rated usefulness declines**.

## 7. Anti-windup design without suppressing legitimate accumulation

Evidence accumulation should clamp only when new observations have no new information source. Legitimate sequential evidence remains allowed:

- same probe, same scope, same failure fingerprint: no confidence increment;
- same probe after a relevant environment repair: potentially new evidence, record changed condition;
- different probe with same upstream cache: no independent increment;
- different relationship with a new failure domain: eligible for an independent increment after the receipt's common-cause check;
- repeated stochastic samples: can accumulate only under an explicit sampling model; otherwise do not manufacture a probability.

**Proposal — evidence deduplication by normalized failure domain/fingerprint [UNVERIFIED: settle with Experiment E4 in §11].** **NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).** It is **likely (55-80%)** to reduce retry-driven confidence windup in repeated identical failures, because exact or normalized fingerprints are mechanically recognizable. It is **UNVERIFIED until E4 measures whether normalization collapses truly equivalent retries without merging independent observations**.

This component can be part of the same Claim FDIR script; it does not justify a separate service.

## 8. Feedback stability and stopping policy

The gate itself creates feedback: blocked claim → more probing → new evidence → reevaluation. Without an explicit terminal condition, that transition graph admits an endless tool-use path. A bounded policy is:

1. one positive control;
2. up to two claim-bearing independent probes;
3. at most one additional discriminating probe when signals conflict;
4. then emit `UNKNOWN`, name live hypotheses, and state what external fact would settle them.

The numbers are intentionally defaults rather than universal truths. **UNVERIFIED: Experiment E5 must compare these limits against 1/1/0 and 1/3/2 policies on accuracy, tool cost, latency, and unresolved rate.** It is **likely (55-80%)** that a finite probe budget prevents runaway diagnostic loops, because termination is explicit; the optimal budget is unknown.

**Proposal — bounded diagnostic loop with `UNKNOWN` as a terminal state [UNVERIFIED: settle with Experiment E5 in §11].** **NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

## 9. Anti-overfit gate

The proposal passes the requested anti-overfit gate:

- **Existing bus:** one small rule/schema plus a pre-final/stop hook check. No second orchestration runtime.
- **No vector DB or knowledge graph:** receipts are transient per-task JSON/text.
- **No durable-execution engine:** no workflow scheduler or replay service in production.
- **No trained critic:** deterministic required fields and state transitions; semantic self-marking remains the model's responsibility.
- **No observability SaaS:** optional local counters only for the experiment.
- **No guardrail framework:** this is one claim-specific contract on the existing hook/rule path.
- **Model-improvement robustness:** the mechanism states an invariant—do not assert a conclusion that the observations cannot distinguish. A stronger model can satisfy the receipt with fewer/better probes; the harness does not prescribe a large reasoning scaffold.

The design adds friction only at the high-damage boundary. It does not wrap every tool call, require a universal planner, or persist a world model.

## 10. Rejected literal borrows and dead ends

### 10.1 Full Kalman-filter confidence estimator — reject

A Kalman filter needs a dynamical model and noise assumptions. Mapping prose confidence to Gaussian state estimation creates unsupported numeric precision. The NASA Kalman work establishes analytical redundancy in a modeled engine; it does not license numeric probabilities for arbitrary tool reasoning.

### 10.2 Majority vote over agents or tools — reject

Two or more agents can share the same prompt error, model prior, source, or tool path. NASA's two-sensor ambiguity shows why a count detects disagreement but does not isolate truth. Majority vote without failure-domain diversity is correlated repetition.

### 10.3 Universal “always use three probes” rule — reject

Three probes can still share one common cause. Direct authoritative observations outside the gated claim classes do not automatically need three probes. The gate is claim- and consequence-specific; the mandatory minimum applies to the target classes, with independence analysis.

### 10.4 Numeric residual threshold or confidence score — reject for now

There is no calibrated residual distribution across heterogeneous agent tasks in the evidence reviewed for this unit. A score such as `0.82 reliable` is therefore unsupported. Use explicit evidence states and the owner's confidence vocabulary.

### 10.5 Global deadband that ignores weak evidence — reject

Weak anomalies lower confidence and are eligible to prompt investigation. Only assertive state transitions require stronger evidence. Suppressing anomaly signals reverses the safety objective.

### 10.6 Autonomous state-changing self-tests — reject

Active diagnosis does not expand authority. Mutation-free sentinels and read-only behavioral probes are the default. Creating/deleting test objects or triggering external actions still needs task authorization.

### 10.7 New diagnosis daemon — reject

A daemon is **almost certainly not (1-5%)** justified for this narrow mechanism, because a transient receipt validator and rule library fit the existing bus and the brief explicitly penalizes a second runtime. The 1–5% residual covers a future measured case where the existing hook cannot access the final claim or maintain even task-local state; that premise is currently UNVERIFIED and would require a hook-capability experiment before reconsideration.

## 11. Experiments that settle the UNVERIFIED premises

### E1 — transcript replay plus seeded-fault evaluation (primary go/no-go)

Build the <200-line validator and a minimal claim-marking rule in an isolated test harness, not in the subject configuration during this research unit.

Dataset:

1. all owner-confirmed single-probe wrong conclusions from the motivating session;
2. a stratified held-out sample of correct `ABSENT`, `BROKEN`, and `DONE` conclusions;
3. seeded variants: detector always returns empty, wrong scope, stale source, permission denial rendered as empty, pagination truncation, write-success-with-failing-runtime, and two correlated probes;
4. paraphrased claim language to test classifier recall.

Compare baseline against gate on:

- wrong confident conclusions reaching final output (primary);
- claim-classification recall and precision;
- false blocks of correct conclusions;
- fraction resolved by one discriminating probe;
- tool calls and latency added;
- final `UNKNOWN` rate;
- owner rating of usefulness and clarity.

Predeclare acceptance criteria before replay. Suggested starting criteria, explicitly not evidence-backed thresholds: catch every known motivating failure; at least 90% seeded-fault catch rate; under 5% false blocks on correct low-risk conclusions; median added probes ≤2. These numerical thresholds are **UNVERIFIED and must be accepted or changed by the owner before E1; E1 itself settles feasibility, not whether the owner's cost preference matches these defaults**.

### E2 — active-probe ablation

Randomly compare generic “verify with another method” wording against the hypothesis-separation pattern library. Score whether the selected next probe produces different predictions under the live hypotheses, whether it is read-only, and whether it resolves the claim. This settles whether control-theory-inspired active diagnosis improves probe selection beyond ordinary prompting.

### E3 — independence red team

Give the agent pairs of apparently different signals backed by a hidden dependency graph. Seed shared cache, auth, mount, parser, generated manifest, branch, and network gateway failures. Require the independence argument, then score whether it identifies the common cause. Compare free-form reasoning with a six-field failure-domain checklist (`source`, `scope`, `transport`, `auth`, `parser`, `freshness`).

### E4 — anti-windup deduplication test

Replay retry loops with identical, near-identical, and genuinely independent errors. Measure false merge and false split rates for fingerprint normalization. Reject this component if it collapses distinct evidence often enough to reduce fault isolation.

### E5 — loop-budget tuning

Compare diagnostic budgets `1 control / 1 corroboration / 0 conflict probe`, `1/2/1`, and `1/3/2`. Measure corrected conclusions, unresolved claims, tool calls, latency, and user interruption. Choose the smallest budget on the Pareto frontier; do not assume `1/2/1` is optimal.

### E6 — common-mode control failure

Seed a wrong premise shared by the target probe, positive control, and corroborating probe—for example, all read the wrong revision. Test whether explicit scope/revision fields and a third authoritative relationship catch it. This is the test most likely to falsify the analogy's practical sufficiency.

## 13. Minimal implementation sketch

This is illustrative, not code written into the subject:

```text
on pre-final/stop:
  claims = self-marked gated claims in final draft
  for claim in claims:
    receipt = task_local_receipt[claim.id]
    if missing operational_definition or scope:
      return revise_to_UNKNOWN("undefined or unbounded claim")

    if claim.type == ABSENT:
      require positive_control.same_detector_path
      require positive_control.result == PASS

    require len(receipt.signals) >= 2
    require all signal.expected and signal.actual
    require nonempty independence_argument
    require decision == PASS
    require no unresolved disconfirming_evidence

    if claim.type == DONE:
      require artifact_state_signal
      require outcome_signal
      require requirement_coverage

    if repeated_same_failure_domain(receipt.signals):
      return revise_to_UNKNOWN("correlated evidence")

  allow final
```

The hook need not decide truth. It decides only whether the agent has met the evidence contract for using an assertive status. This keeps the implementation small and avoids pretending a deterministic linter can perform semantic verification.

## 14. Gaps

1. **No local hook capability verification.** This unit intentionally did not inspect the subject. It is **roughly even (45-55%)** that the existing hook receives enough final-draft/transcript context to validate receipts; this estimate reflects complete absence of local inspection rather than balanced positive/negative evidence. This is **UNVERIFIED until a read-only hook-capability experiment traces the available event fields**. If that experiment is negative, self-marking plus a response-format validator is the next small alternative to test.
2. **No measured base rates by claim class.** The supplied prompt gives six-plus instances but not denominators for `ABSENT`, `BROKEN`, and `DONE`. Therefore expected absolute benefit and false-block budget cannot be calculated here.
3. **No validated claim-language classifier.** E1 must establish recall across paraphrases. Until then, enforcement coverage is unknown.
4. **No calibrated independence taxonomy.** The proposed six-field checklist is a hypothesis. E3 must test it.
5. **No owner cost function.** The acceptable trade between false certainty, `UNKNOWN`, added calls, and latency must be chosen after replay results.
6. **Positive-control provenance remains a human/model judgment.** A control falsely believed to be present can invert the diagnosis. High-consequence use should prefer an authoritative provenance source and record it.
7. **Common-mode wrong premises remain possible.** Analytical redundancy helps only when relationships do not share the same wrong assumption. E6 is mandatory before claiming robust coverage.

## 15. Final answer to the cross-domain question

Control theory has already solved the structurally matching problem of **not confusing an observation with the hidden state, and not diagnosing a failed component unless the available measurements make the fault isolable**. Its concrete tools are observability analysis, observer residuals, analytical redundancy, sensor self-test, sequential decisions with an uncertainty region, and active excitation designed to separate hypotheses.

The borrow survives adversarial scrutiny only as a qualitative protocol. The agent harness has no stable plant model, so mathematical observer guarantees do not transfer. What does transfer is the invariant:

> Before asserting `ABSENT`, `BROKEN`, or `DONE`, demonstrate that the evidence path can observe a known-present control, obtain claim-bearing evidence from distinct relevant failure domains, and move to `UNKNOWN` whenever competing explanations remain observationally equivalent.

That mechanism directly targets the supplied failure class and fits in a small rule/hook component on the existing bus. Its effectiveness is **very likely (80-90%)** for the narrow single-unvalidated-probe class, based on the deterministic evidence requirements and the control-theory/NASA diagnosis mechanisms cited above, but it is **UNVERIFIED until E1 replays the known failures and seeded controls through the actual harness**. The analogy should be rejected if E1 shows low semantic coverage or unacceptable false blocks, or if E6 shows that common-mode premises dominate despite scope and independence checks.
