## Verified non-findings: apparent overlaps that do not collide

### Permission allow entries versus MCP definitions

`settings.json` allows tools such as `"mcp__basic-memory"`, `"mcp__context7"`, and `"mcp__search-hub"` (`/local_disk0/codexwork/bundle/claude/settings.json:47-60`). An allow rule permits invocation after a tool exists; it does not instantiate a server or choose its command/URL. A missing, renamed, disabled, or managed-out server remains missing despite this list. These are different axes, so there is no duplicate-authority finding.

### Hook matchers versus server definitions

The active PreToolUse configuration matches `mcp__.*` and named RE/memory tool patterns (`/local_disk0/codexwork/bundle/claude/settings.json:139-278`). Matchers decide which hook sees a tool call; MCP configuration decides which tools exist. Name drift can make a hook miss its intended tool, but absent actual mismatched MCP text that is a compatibility risk, not two authorities fighting over a single runtime value.

### Static routing hints versus server definitions

`semantic-router/mcp_hints.py` describes capabilities, and `build_index.py` reads names from `~/.mcp.json` (`/local_disk0/codexwork/bundle/claude/hooks/semantic-router/build_index.py:196-213`). It neither writes MCP config nor controls connection precedence. Stale descriptions can misroute the model, but they cannot override a server definition.

### The three project-copy policies do not collide on their documented guards

On their own terms, `mcp-canonical-sync` overwrites only existing broad project files, skipping files with fewer than ten servers and named exclusions (`/local_disk0/codexwork/bundle/claude/hooks/mcp-canonical-sync/sync.py:23-31,48-67`). `mcp-userscope-sync/heal.py` is create-only and returns whenever any up-tree `.mcp.json` exists (`/local_disk0/codexwork/bundle/claude/hooks/mcp-userscope-sync/heal.py:124-150`). Thus, in a tree with an existing file, heal does nothing and sync updates it only on the code's drift and size conditions; in a true orphan, heal creates a copy only on its stated guards, after which later heal runs do nothing. Their write domains are intentionally disjoint. This is not a conflict unless external scheduling/wiring or an omitted path changes those preconditions; no such live evidence is packed.
