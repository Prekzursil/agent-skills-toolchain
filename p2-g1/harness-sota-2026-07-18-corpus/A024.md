I found no evidence that the security outcomes themselves are wrong. The dominant remedy is to make the prose accurately describe where enforcement exists and to add a small, C#-aware verification lane on the existing hook bus—not to replace the harness or add another runtime.

The central conclusions are:

1. That is broader than what the C# rule says and internally incoherent.
4. The corpus does **not** measure C# security compliance. This is **almost certain (90-99%)** because `_meta` says the corpus is distilled to counts and capped samples (`corpus.json:2-11`), its `sessions` entries contain only file/time/size metadata, and its `hooks.DETECTOR_STATUS` explicitly says the hook detector is broken (`corpus.json:13224-13228`; exact line numbers may move if the JSON is reformatted). ### C01 — base `appsettings.json` falls through the written prohibition

**Class: CONTRADICTION**

**Artifact A:** `claude/rules/csharp/security.md:2-6,14-16`

> paths include `**/appsettings*.json`  
> “Never hardcode API keys, tokens, or connection strings in source code”  
> “Keep `appsettings.*.json` free of real credentials”

**Artifact B:** `claude/rules/csharp/hooks.md:22-25`

> “Warn on modified `appsettings*.json` files so secrets do not get committed”

The rule is activated for base `appsettings.json`, but its explicit config prohibition names only `appsettings.*.json`, conventionally matching environment-qualified files such as `appsettings.Production.json`, not the base file. The hook rule uses the broader `appsettings*.json`. The “source code” sentence does not clearly cover JSON configuration. Precedence does not resolve this: both are same-level C# rules, so AGENTS §10 requires the conflict to be surfaced (`AGENTS.md:129-131`).

**Resolution — CONFIG (settings/JSON only):** Change line 16 to “Keep every `appsettings*.json` file—including base `appsettings.json`—free of real credentials.” Keep the frontmatter pattern unchanged. This is **almost certain (90-99%)** to remove the scope ambiguity because the target activation glob and obligation would then use the same spelling; evidence is the literal mismatch above. This is a prose-rule edit rather than actual settings JSON, but `CONFIG` is the closest mandated value because no runtime is added.
