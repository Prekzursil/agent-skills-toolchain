## Executive verdict

- Auto-formatting is **UNENFORCED**: the wired Python-aware hook invokes `ruff check`, not `black`, `ruff format`, or a project formatter (`per-edit-check/check.py:45-88`; registration at `settings.json:333-342`).
- Type checking is **UNENFORCED**: neither live PostToolUse registration invokes mypy/pyright, the dispatcher manifest contains no such check (`settings.json:310-355`; `_dispatch/manifest.json:144-180`), and the official pyright LSP plugin is explicitly disabled (`settings.json:552-554`).

Whether a particular repository's Ruff configuration happens to enable a print rule is **UNVERIFIED**; the settling experiment is to edit a controlled `.py` containing `print('control')` in a repository with the actual live Ruff configuration and capture the PostToolUse result.
- The harness instead enforces unruled behaviors: Ruff lint warnings and hard syntax blocks (`per-edit-check/check.py:18-24,45-88,211-244`). The hard block directly violates the higher-precedence cross-tool contract, which reserves blocking for irreversible/dangerous actions (`AGENTS.md:64-70`).
- Historical session data proves that a Stop-time Ruff validator did fire in earlier sessions (`corpus.json:11249-11275`), but the current snapshot does not wire its recorder or Stop validator. This is temporal drift, not evidence that current wiring works.

The best resolution is evolution of the existing hook bus, not a replacement runtime: rewrite this rule as a precise policy matched to project-local tools and move nontrivial validation to the turn boundary. This is **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)** plus **CONFIG (settings/JSON only)**. It passes the anti-overfit gate because it consolidates behavior into the existing PostToolUse/Stop bus and introduces none of the rejected orchestration, memory, durable-execution, critic, SaaS, or guardrail systems.

## Collision register

### C1 — `ruff` is assigned incompatible roles

- **Artifacts and exact lines:** `~/.claude/rules/python/hooks.md:12-15` says “black/ruff” auto-formats after edit. `~/.claude/rules/python/coding-style.md:34-38` assigns Black to formatting, isort to import sorting, and Ruff to linting.
- **Class:** CONTRADICTION.
- **Why this is a real collision:** The slash notation does not say whether Black and Ruff are alternatives, a pipeline, or two formatter commands. The sibling Python rule gives Ruff a different role and introduces isort, which the hook rule omits. Both are same-level language rules; AGENTS §10 does not pick a winner (`AGENTS.md:129-131`).
- **Resolution — CONFIG (settings/JSON only) + rule edit:** define roles by capability, not brand: “run the repository's configured formatter; run its configured linter separately.” If a repository declares Black, run Black; if it declares `ruff format`, run that; do not run both unless the repository config explicitly does. Keep import sorting in the repository's formatter/linter configuration rather than naming isort globally. This is **very likely (80-90%)** to remove cross-project tool conflict because the evidence is the current same-level disagreement at `python/hooks.md:14` versus `python/coding-style.md:36-38`; the remaining uncertainty is repositories with no declared tooling.

### C2 — per-edit heavy validation contradicts the harness's documented loop-avoidance design

- **Artifacts and exact lines:** `python/hooks.md:14-15` demands formatter and type checker after every edit. `~/.claude/hooks/edit-validate/README.md:3-7` records that the former per-Edit validator ran Ruff on every edit, caused thousands of wakes, and was replaced; `README.md:11-19,21-31` moves validation to one Stop-time pass specifically to avoid transient-WIP wake loops. `validate-stop.py:2-20` repeats the boundary/dedupe design.
- **Class:** STALE.
- **Why:** The rule still describes the pre-migration architecture. Formatting and full type checking on every edit reintroduce the same trigger cadence even if their exact subprocesses differ. It is **likely (55-80%)** that a full mypy/pyright pass after each edit would recreate material latency or wake noise; evidence is the recorded per-edit Ruff degeneration (`README.md:3-7`) and the current hook's explicit 8-second cap (`per-edit-check/check.py:37-39`), while the uncertainty is that no controlled mypy/pyright latency measurement is bundled.
- **Resolution — BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus):** retain only cheap, file-local syntax/lint feedback per edit; record edited paths; run project-scoped type checking once at Stop or an explicit verification milestone. Allow formatter mutation only when a project-local formatter is unambiguously configured. Do not restore an async per-edit rewake hook.
