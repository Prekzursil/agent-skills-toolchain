These rules are necessary to decide whether an apparent textual overlap is a real ambiguity.

1. Claude's current official subagent documentation says the `tools` field defines the tools the subagent can use; if omitted, tools are inherited. It also gives the explicit example that a `tools: Read, Glob, Grep, Bash` allowlist prevents the subagent from using any MCP tools. Source: <https://code.claude.com/docs/en/sub-agents> (sections “Supported frontmatter fields” and “Available tools”).

A named reference shares the parent's connection; an inline definition is connected for the subagent. Source: <https://code.claude.com/docs/en/sub-agents#scope-mcp-servers-to-a-subagent>.
3. Current official managed-MCP documentation says that when `managed-mcp.json` is deployed, Claude Code loads only servers defined there; user, project, plugin, and claude.ai connector MCPs cannot be added, modified, or used outside that set. `allowedMcpServers`/`deniedMcpServers` can filter the managed set further. Source: <https://code.claude.com/docs/en/managed-mcp#exclusive-control-with-managed-mcpjson>.
4. Current official MCP documentation says plugin MCP servers start automatically when the plugin is enabled and otherwise behave like user-configured MCP servers. It also documents local, project, and user MCP scopes. Source: <https://code.claude.com/docs/en/mcp#plugin-provided-mcp-servers> and <https://code.claude.com/docs/en/mcp#mcp-installation-scopes>.
5. The exact loaded tool surface is runtime state: official documentation directs users to `/mcp` for exact MCP tool names/status. Source: <https://code.claude.com/docs/en/tools-reference#check-which-tools-are-available>.

These documents define tie-breaks for the supplied apparent overlaps. They do not reveal which missing Windows configurations exist or which server definitions are healthy.
