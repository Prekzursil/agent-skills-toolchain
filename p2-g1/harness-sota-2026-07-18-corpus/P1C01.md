# P1C01 — Normalized audit findings from A01–A04

## Scope and method

This unit normalizes every finding under `## FINDINGS` in `A01.md`, `A02.md`, `A03.md`, and `A04.md`. There are eight source findings: two in each file (`A01.md:6-21`, `A02.md:6-21`, `A03.md:6-21`, and `A04.md:6-21`). The source verdicts and gaps are contextual material, not additional finding records.

The `support` judgment is deliberately narrow: it asks whether the evidence *as cited by the audit author*, taken at face value, is logically sufficient for the one-sentence claim. It does not test whether a cited file exists, whether the quoted line range says what the author reports, whether a command was actually run, or whether the live system behaves that way. Every normalized source claim below is therefore **UNVERIFIED against the subject files**; the settling experiment is the later verification phase opening each cited range and reproducing each cited command or probe. This limitation is inline here because it qualifies every record, rather than being deferred to a trailing limitations section.

Support labels:

- `SUPPORTED`: the cited material, if accurate, directly establishes all material parts of the normalized claim.
- `PARTIAL`: the cited material establishes the core issue but omits direct support for at least one material qualifier or inference.
- `UNSUPPORTED`: the evidence as written does not establish the claim even if accepted at face value.

The audit files do not contain a standalone `severity` field. `claimed severity` below preserves their `value x effort` value component and explicitly notes that provenance. Confidence bands apply to this unit's coherence judgments, not to the underlying live-system truth. There are no implementation proposals in this unit, so the NATIVE-vs-BUILD and anti-overfit proposal gates are not applicable.
