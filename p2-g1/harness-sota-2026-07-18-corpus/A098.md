## Apparent conflicts tested and rejected

### 1. Legacy event ledger versus shared runtime: not a stale split

Contract text, verbatim:

> `AGENTS.md:30-34` — “Record durable decisions / failures / milestones via `note.py` — the *why* hooks cannot see. Failure entries carry falsifiable preconditions; a milestone that contradicts a failure `--supersedes` it so the dead-end is retired, not re-walked. The Stop hook writes objective turn data automatically; SessionStart replays the ledger on resume/compact/clear — trust that replay as ground truth, not any in-context summary.”

Legacy hook text, verbatim:

> `event-ledger/ledger.py:10-11` — “Storage: ~/.claude/event-ledger/<project-slug>/events.jsonl (+ state.json projection). Events are one JSON object per line. Append-only; recovery = replay the tail.”

Shared runtime text, verbatim:

> `agents/harness/ledger.py:468-480` — `class EventLedger: """Append-only, secret-redacted event facts shared by both providers.""" ... self.root = ... / "ledger" ... self.legacy_root = ... Path.home() / ".claude" / "event-ledger"`.

At first glance, `note.py` writes `~/.claude/event-ledger` while the live dispatcher writes `~/.agents/state/harness/ledger`. The shared runtime explicitly merges `self._legacy_events(cwd)` with shared events at `agents/harness/ledger.py:882-907`, and merges legacy decisions/open failures into state at `:909-942`.

Output was `note_rc 0`, `shared_replay_canary True`, and `shared_state_canary True`. The detector control was also positive: the note CLI printed `ledger += #1 [decision] A098-CANARY`.

**Runtime winner:** the shared dispatcher wins because `settings.json:82-103,484-503` invokes it for SessionStart and Stop; its compatibility reader deliberately includes legacy `note.py` data. Minimal edit: none.

### 2. `--supersedes` across the two stores: theoretical collision, unreachable through the documented path
