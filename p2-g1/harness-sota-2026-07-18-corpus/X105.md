## Executive determination

The strongest transferable mechanism is not a generic “agent confidence score.” It is **metrological measurement assurance**: (1) define the measurand and operating conditions; (2) calibrate the indication against fit-for-purpose reference standards; (3) preserve a documented traceability chain; (4) carry an uncertainty budget with the result; (5) monitor stable check standards for drift; (6) use intercomparison to test equivalence; and (7) apply an explicit, risk-sensitive decision rule near an acceptance boundary.

The literal analogy fails for unrestricted natural-language output. There is no SI-like unit of “truth,” many answers have no unique reference value, an agent changes with prompt and context, and the artifact being judged is often creative or interactive. A single enduring trust number for “agent A” is therefore **almost certainly not (1–5%) defensible**, because the BIPM definition makes calibration conditional on specified conditions and relates an indication to a reference with associated uncertainty, while unrestricted agent tasks do not supply one stable measurand or reference ([VIM 2.39](https://jcgm.bipm.org/vim/en/2.39.html)).

The bounded analogy does transfer: treat a **versioned agent + harness + tools + task stratum + operating condition** as the measurement system; treat a raw evidence/verification signal as its indication; and estimate the observed probability of a predeclared, adjudicable outcome on reference and check tasks. This narrower transfer is **likely (55–80%) to improve routing and escalation decisions**, based on the close structural match to NIST measurement assurance—characterize influence factors, propagate uncertainty, and continuously monitor well-characterized check standards—and subject to the decisive experiment described below ([NIST Handbook 150, §1.5.16](https://nvlpubs.nist.gov/nistpubs/hb/2020/NIST.HB.150-2020-upd1.pdf)).

The recommendation is thus: **borrow the certificate, chain, check-standard, and decision-rule discipline; do not borrow the fiction that open-ended cognition is a scalar measuring instrument.**

## 1. The specific mechanism in its own field

### 1.1 Calibration is a relation under specified conditions, not a badge

The International Vocabulary of Metrology (VIM) defines calibration as a two-step operation. First, under specified conditions, it establishes a relation between reference values (with uncertainties) and instrument indications (also with uncertainties). Second, it uses that relation to obtain a measurement result from a later indication. The relation may be a function, curve, diagram, or table. VIM also warns that calibration is not adjustment and is not verification ([VIM 2.39](https://jcgm.bipm.org/vim/en/2.39.html)).

That distinction matters. Calibration does not pronounce an instrument “good.” It characterizes what its readings mean over a defined range and condition. Verification is the later question of whether a requirement is met. Adjustment changes the system. Conflating these actions hides both uncertainty and change.

### 1.2 Traceability attaches to a result, through an unbroken chain

VIM defines metrological traceability as a property of a measurement result: it can be related to a reference through a documented, unbroken chain of calibrations, each of which contributes uncertainty ([VIM 2.41](https://jcgm.bipm.org/vim/en/2.41.html)). A calibration hierarchy is a sequence from reference to final measuring system; VIM explicitly notes that uncertainty necessarily increases along that sequence ([VIM 2.40](https://jcgm.bipm.org/vim/en/2.40.html)).

NIST makes the non-transferable-badge point unusually clear: merely using an artifact calibrated by NIST is insufficient. The result, measurement process, calibration chain, uncertainty, references, dates, and measurement-assurance controls must be documented. NIST also says traceability is a property of a result, not an instrument, report, or laboratory ([NIST metrological traceability FAQ, §§5.1.1–5.2.1](https://www.nist.gov/metrology/metrological-traceability)).

Thus metrology’s trust object is not institutional reputation. It is a particular result plus inspectable evidence connecting that result to a stated reference under controlled conditions.

### 1.3 Reference standards are characterized and fit for intended use

A VIM reference material must be sufficiently homogeneous and stable for specified properties and fit for its intended measurement use. Materials without assigned values can control precision; only materials with assigned values can calibrate or control trueness ([VIM 5.13](https://jcgm.bipm.org/vim/en/5.13.html)). A certified reference material adds documentation from an authoritative body, specified property values, associated uncertainties, traceabilities, and valid procedures ([VIM 5.14](https://jcgm.bipm.org/vim/en/5.14.html)).

This is not “a benchmark everyone likes.” It is a stable artifact with a defined property, purpose, certificate, and uncertainty. NIST describes its Standard Reference Materials similarly: certified property values are accompanied by measurement uncertainties and a certificate of analysis ([NIST reference materials](https://www.nist.gov/reference-materials)).

### 1.4 Uncertainty is budgeted, propagated, and stated with the result

The Guide to the Expression of Uncertainty in Measurement (GUM) establishes general rules for evaluating and expressing uncertainty across calibration, testing, research, quality control, and conformity assessment ([JCGM 100:2008](https://www.bipm.org/documents/20126/2071204/JCGM_100_2008_E.pdf)). NIST’s operational definition of measurement assurance is particularly useful: characterize statistical variation and all known or suspected influence factors, include imported uncertainties, propagate uncertainties through the process, and continuously monitor statistical control with check standards and control charts ([NIST Handbook 150, §1.5.16](https://nvlpubs.nist.gov/nistpubs/hb/2020/NIST.HB.150-2020-upd1.pdf)).

The point is not ritualistically attaching “±” to a score. The uncertainty budget names why the result may be wrong and how much each source matters. Correlation and model inadequacy matter; a neat root-sum-of-squares computation is not justified merely because components have been listed.

### 1.5 Check standards and control charts detect drift between calibrations

NIST describes check standards as stable artifacts, of the same type and geometry as workload items, measured within calibration runs. Their history controls bias and long-term variability; short-term standard deviation controls precision. NIST recommends a check standard at each critical measurement level and records fields including date, standard, design, instrument, value, repeatability, operator, out-of-control flag, and relevant environment ([NIST Engineering Statistics Handbook, “Control of artifact calibration”](https://www.itl.nist.gov/div898/handbook/mpc/section3/mpc35.htm)).

Control charts distinguish a stable noisy process from a changed process. NIST says persistent shifts in a check standard can indicate changed/damaged references, changed/damaged check artifacts, or a procedural change that invalidates assumptions; changed variability can indicate environmental, handling, or instrument degradation ([NIST, “How are bias and variability controlled?”](https://www.itl.nist.gov/div898/handbook/mpc/section2/mpc22.htm)). It describes both Shewhart charts, which emphasize the current observation, and exponentially weighted moving average charts, which emphasize sustained smaller changes.

Recalibration is consequently evidence-driven, not purely calendrical. NIST does not prescribe one universal interval; it recommends cross-comparisons and control-chart histories to characterize short- and long-term behavior, then refine intervals using “as submitted” and post-calibration results ([NIST recommended calibration interval](https://www.nist.gov/calibrations/recommended-calibration-interval)).

### 1.6 Blind samples and interlaboratory/key comparisons test claimed capability

NIST lists blind samples, check standards, measurement-assurance programs, and interlaboratory comparisons as distinct controls on bias and accuracy. A blind sample has composition known to the submitter but not the analyst, while interlaboratory comparisons circulate reference standards or materials among laboratories ([NIST, “Bias and Accuracy”](https://www.itl.nist.gov/div898/handbook/mpc/section1/mpc113.htm); [NIST SP 260-100 glossary](https://www.nist.gov/system/files/documents/srm/SP260-100.pdf)).

At the international level, the BIPM’s CIPM Mutual Recognition Arrangement uses scientific comparisons and peer-reviewed Calibration and Measurement Capabilities. The KCDB exposes both the recognized capabilities and the comparison results underpinning them; participating institutes also operate reviewed quality systems ([BIPM KCDB overview](https://www.bipm.org/en/cipm-mra/kcdb)). The formal “degree of equivalence” is not just agreement: it is deviation from a key-comparison reference value plus uncertainty of that deviation ([CIPM MRA glossary](https://www.bipm.org/documents/20126/43742162/CIPM-MRA-2003.pdf)).

This protects against two errors: self-certification and mistaking pairwise agreement for correctness.

### 1.7 Guard bands convert uncertainty into a decision policy

JCGM 106 treats accept/reject decisions as inferences from observable measured values to an unobservable measurand. Measurement uncertainty creates both false acceptance (consumer risk) and false rejection (producer risk). Near a tolerance limit, simple acceptance can make the chance of an incorrect decision as large as 50% under the document’s symmetric example. Moving the acceptance boundary inside or outside the tolerance boundary creates a guard band, trading the two risks explicitly ([JCGM 106:2012, §§8.3 and 9](https://www.bipm.org/documents/20126/2071204/JCGM_106_2012_E.pdf)).

This is the final link: calibration does not itself decide whether an item is usable. A declared decision rule maps value and uncertainty to action according to consequences.

## 2. Structural translation to an agent harness

| Metrology object | Harness translation | Important constraint |
|---|---|---|
| Measurand | A predeclared task outcome, e.g. “patch passes hidden tests without prohibited changes,” “cited claim is entailed,” or “target is genuinely absent” | Not “quality” or “trust” in general |
| Measuring system | Exact model/version + system instructions + harness + enabled tools + relevant environment | Agent name alone is insufficient |
| Specified conditions | Task stratum, context-length band, tool availability, repository/language/domain, consequence class | Calibration is invalid outside this scope |
| Indication | Observable pre-outcome signals: evidence coverage, test result pattern, verifier result, provenance completeness, or a constrained confidence report | Free-form self-confidence is only one fallible input |
| Certified reference standard | Hidden, versioned task with adjudicated outcome, adjudication procedure, provenance, and disagreement/label uncertainty | Reference fitness and leakage must be tested |
| Working/check standard | Small hidden canary task repeatedly interleaved with real work | It detects process movement, not every failure |
| Calibration relation | Empirical mapping from indications to outcome frequencies within a task stratum and condition | Requires enough independent cases and interval estimates |
| Traceability chain | Output → captured evidence → evaluator procedure/version → reference task/adjudication → reference provenance | Every link can add uncertainty |
| Uncertainty budget | Sampling, label, evaluator, task-classification, temporal drift, environment, context, and dependence uncertainties | Do not collapse correlated terms naively |
| Interlaboratory comparison | Multiple agent systems independently solve the same hidden reference task, each reporting evidence and uncertainty | Agreement without an external reference is not equivalence |
| Guard band | Auto-accept, escalate/verify, or reject/redo thresholds chosen from consequence-weighted false-accept and false-reject costs | Thresholds differ by action risk |
| Calibration interval | Reassessment triggered by system change or check-standard drift, with time/count fallback | A fixed monthly badge is not enough |

The calibrated object must be named as a tuple, for example:

`(model build, system-prompt hash, harness version, tool manifest, task stratum, operating-condition band, reference-suite version, evaluation-procedure version, time window)`.

A result outside that tuple’s declared scope is **uncalibrated**, not low-confidence. This is the direct equivalent of using an instrument beyond its calibrated range.

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

The numbers above are illustrative only, not proposed defaults. In production, omit `observed_rate` when the sample or outcome definition cannot support it. Never replace a wide interval with a verbal “high confidence.”

It is **likely (55–80%) that this sidecar would expose stale, out-of-scope, or weakly supported trust claims**, because scope, reference version, interval, drift state, and evidence chain become machine-checkable; the evidence is the VIM/NIST requirement that traceability belongs to a result and includes specified conditions, references, dates, process, and uncertainty ([VIM 2.41](https://jcgm.bipm.org/vim/en/2.41.html); [NIST traceability FAQ](https://www.nist.gov/metrology/metrological-traceability)). This implementation claim is **UNVERIFIED**; settle it by replaying historical adjudicated work to measure detection precision/recall, then run 500 prospective cases in shadow mode and compare selective-risk curves against routing by raw agent confidence and by no certificate.

Do not ask the model to invent the certificate’s observed rate. A small evaluator reads a versioned calibration table keyed by the system/task tuple. The agent supplies evidence pointers and task classification; the harness supplies the empirical performance record.

### 3.2 UNVERIFIED — Establish a reference hierarchy and uncertainty budget (settling experiment: double-adjudicated pilot across five strata)

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Define three tiers:

1. **Certified references:** expensive, hidden cases with executable or independently adjudicated outcomes; a certificate records task definition, accepted outcome, adjudication method, provenance, ambiguity, known leakage, and applicable strata.
2. **Transfer references:** smaller subsets used to compare model/harness versions under identical conditions.
3. **Working/check standards:** cheap hidden canaries interleaved with routine executions for drift monitoring.

Start with task types that admit a crisp measurand: code changes with hidden tests and scope checks; exact extraction with source entailment; deterministic transformation; claims that a file/process/config key is present; and “done” claims with independently observable postconditions. Do not start with strategy quality, taste, broad research synthesis, or creative writing.

For every calibrated stratum, record at least these uncertainty components:

- **Reference uncertainty:** ambiguity or adjudicator disagreement about the correct outcome.
- **Sampling uncertainty:** finite and potentially unrepresentative cases.
- **Task-classification uncertainty:** the live task may belong to another stratum.
- **Evaluator uncertainty:** hidden tests or judges can miss valid solutions and accept invalid ones.
- **Condition uncertainty:** context, tools, environment, or user interaction differ from calibration.
- **Temporal uncertainty:** model, dependencies, web state, and task distribution drift.
- **Dependence uncertainty:** benchmark variants, repeated templates, and correlated agents reduce effective sample size.
- **Selection uncertainty:** only conveniently judgeable tasks receive labels.

It is **very likely (80–90%) that the budget will prevent unjustified precision if every certificate must surface its dominant component**, because NIST measurement assurance explicitly calls for statistical variation, all known or suspected influence factors, imported uncertainty, and propagation ([NIST Handbook 150, §1.5.16](https://nvlpubs.nist.gov/nistpubs/hb/2020/NIST.HB.150-2020-upd1.pdf)). It is only **roughly even (45–55%) that a useful quantitative combined uncertainty can be produced for all five pilot strata**, because evaluator error, selection bias, and dependence may resist credible scalar combination. This premise is **UNVERIFIED**; settle it with a five-stratum pilot in which every case is independently adjudicated twice, disagreements are resolved blind, and interval coverage is tested on a held-out temporal slice.

If the pilot cannot define a repeatable outcome or defensible interval for a stratum, label that stratum “not calibratable with current references.” That negative result is preferable to a cosmetic score.

### 3.3 UNVERIFIED — Run blind check tasks and drift charts (settling experiment: seeded-regression detection trial)

**NATIVE-vs-BUILD: BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus).**

Interleave a very small number of hidden, leakage-resistant canaries at the normal execution boundary. Maintain separate charts per task stratum and system tuple for at least outcome rate and one evidence-quality measure. Use a Shewhart-style signal for abrupt regressions and an EWMA-style signal for sustained smaller movement. Trigger recalibration on model, prompt, harness, evaluator, or tool-manifest changes regardless of the chart; allow the chart to lengthen or shorten time/count fallback intervals when the process is demonstrably stable or unstable.

Canaries must resemble the workload in structure, not merely be easy trivia. Rotate them before memorization becomes plausible, retain retired canaries for leak testing, and never expose their identity or expected value to the agent. Where safe, include negative controls designed to catch confident “absent,” “done,” or “verified” claims whose postconditions are false.

It is **likely (55–80%) that this catches regression sooner than periodic aggregate benchmarks**, because NIST’s check-standard method is specifically designed to detect persistent changes in bias/variability and to set recalibration intervals from observed time behavior ([NIST bias/variability control](https://www.itl.nist.gov/div898/handbook/mpc/section2/mpc22.htm); [NIST recalibration intervals](https://www.nist.gov/calibrations/recommended-calibration-interval)). The transfer is **UNVERIFIED** because agent canaries can be memorized and live-task distributions move. Settle it by deliberately seeding at least four regressions—prompt weakening, tool removal, evaluator change, and context inflation—then compare detection delay and false alarms for check charts versus a fixed weekly benchmark.

### 3.4 UNVERIFIED — Use reference-anchored agent intercomparisons, not majority vote (settling experiment: correlated-error comparison study)

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

For a narrow sample of high-value tasks, have candidate systems independently process the same hidden transfer reference. Publish each system’s deviation from the reference outcome, its interval, and condition tuple. Use these comparisons to support scoped capability claims. Do not treat two agents agreeing as evidence of truth unless the reference chain independently supports the outcome.

It is **likely (55–80%) that reference-anchored comparisons reveal common-mode error hidden by agent consensus**, because the CIPM MRA grounds equivalence in deviation from a comparison reference value and uncertainty, not mere peer agreement ([CIPM MRA glossary](https://www.bipm.org/documents/20126/43742162/CIPM-MRA-2003.pdf)). The harness effect is **UNVERIFIED**; settle it by measuring joint error correlations on hidden references across agents from the same and different model families, then compare majority-vote error with reference-anchored selection error.

This is an occasional calibration activity, not a second orchestration runtime. Live fan-out on every task would add cost, latency, and correlated confidence theatre without creating a reference.

### 3.5 UNVERIFIED — Route with consequence-specific guard bands (settling experiment: prospective decision-curve evaluation)

**NATIVE-vs-BUILD: CONFIG (settings/JSON only).**

Define three outcomes rather than pretending every task is pass/fail:

- **Auto-accept:** the conservative bound meets the declared risk target and no out-of-domain/drift flag is active.
- **Uncertain band:** require an independent tool check, human review, or a more capable agent.
- **Reject/rework:** observed evidence or conservative bound fails the minimum criterion.

Different actions need different guard bands. A reversible formatting edit may tolerate more false acceptance than a destructive database operation, security assertion, legal claim, or “nothing exists” conclusion. The rule must state whose loss is being controlled: false acceptance and false rejection have different costs.

It is **likely (55–80%) that guard-banded routing reduces high-cost false acceptance at a tolerable review rate**, based on JCGM 106’s explicit result that uncertainty near a tolerance boundary increases wrong-decision probability and that guard bands trade consumer and producer risks ([JCGM 106:2012, §§8.3–9](https://www.bipm.org/documents/20126/2071204/JCGM_106_2012_E.pdf)). It is **UNVERIFIED** for agent tasks; settle it prospectively by pre-registering cost weights and thresholds, then comparing realized false-accept cost, false-reject cost, and review volume against simple thresholds on a temporally held-out stream.

Never claim an individual output has “94% probability of correctness” solely because its stratum historically passed 94%. The honest certificate is a cohort estimate with an interval unless a separately validated per-instance mapping exists.

## 4. What this catches that aggregate trust currently misses

These are design-level failure classes, not assertions about the local subject:

1. **Task-conditional weakness hidden by an average.** An agent can be excellent at executable code patches and poor at absence claims. Stratified calibration prevents the strong class from subsidizing the weak one. It is **very likely (80–90%) that aggregation can conceal such heterogeneity**, by arithmetic whenever task-class rates differ; no behavioral premise beyond heterogeneous rates is needed.

2. **Out-of-range use.** A certificate calibrated for Python patches with tests does not authorize medical synthesis, web research, or a no-test refactor. It is **very likely (80–90%) that explicit condition tuples expose this category error**, because the calibration definition itself is condition-specific ([VIM 2.39](https://jcgm.bipm.org/vim/en/2.39.html)).

3. **Silent drift after a model, prompt, tool, evaluator, or environment change.** A versioned system tuple invalidates the old certificate; check tasks can detect unannounced movement. Detection sensitivity is **likely (55–80%)**, subject to the seeded-regression experiment in §3.3.

4. **Agreement without truth.** Multiple related agents may share a misconception, benchmark contamination, or evaluator exploit. A reference-anchored comparison distinguishes consensus from equivalence. Detection is **likely (55–80%)**, subject to the correlated-error study in §3.4.

5. **Reference/evaluator uncertainty laundered into agent error.** Double adjudication and a label-uncertainty component stop an ambiguous case from being treated as certain ground truth. It is **very likely (80–90%) that explicit disagreement recording exposes at least some label faults**, based on the direct observable of independent adjudicator disagreement; how many consequential faults it catches remains part of the §3.2 pilot.

6. **“Done,” “absent,” or “verified” assertions with no traceable postcondition.** A result certificate can require two mechanically independent evidence links for high-risk negative or completion claims. It is **likely (55–80%) that this detects unsupported declarations**, because the result-to-evidence chain becomes mandatory; actual precision/recall must be measured in the §3.1 replay.

7. **Confidence theatre.** A fluent self-rating cannot override a wide empirical interval, an out-of-domain flag, a stale reference, or an out-of-control chart. It is **very likely (80–90%) that the schema blocks self-rating as the sole authorization signal**, because the authorization fields come from harness-held calibration records rather than model-generated prose.

8. **Boundary-risk blindness.** A score just above a threshold is treated as decisive even when its uncertainty crosses the threshold. Guard bands create an explicit uncertain zone. It is **almost certain (90–99%) that the rule changes those boundary decisions when intervals overlap the threshold**, as a direct consequence of the rule; whether this improves utility is UNVERIFIED by the §3.5 experiment.

9. **Stale capability reputation.** “Agent X is reliable” persists after the operative system has changed. Identity by full system tuple and event-triggered recalibration prevents inheritance across an untested change. It is **very likely (80–90%) that version binding exposes stale claims**, provided versions are actually captured; test capture completeness during §3.1.

10. **Precision/trueness confusion.** Repeatedly producing the same answer demonstrates repeatability, not correctness. Check tasks with assigned reference outcomes separate consistency from reference deviation. It is **almost certain (90–99%) that repeated agreement alone cannot establish trueness**, which is the same distinction NIST draws between precision control materials and assigned-value calibration/trueness controls ([VIM 5.13](https://jcgm.bipm.org/vim/en/5.13.html)).

## 5. Adversarial analysis: where the analogy breaks

### 5.1 No universal measurand or unit

Physical metrology usually starts with a defined quantity and unit or conventional reference procedure. “How trustworthy is this answer?” mixes factual correctness, completeness, utility, harmlessness, style, scope adherence, and downstream consequence. Those dimensions need not move together. A scalar universal trust unit is **almost certainly not (1–5%) available**, because no common operation of comparison or stable reference spans these properties; the settling experiment for any contrary claim would require demonstrating cross-domain invariance and calibrated coverage on independently adjudicated, temporally held-out tasks.

**Consequence:** only calibrate narrowly declared outcomes. Keep multidimensional certificates multidimensional when the decision genuinely depends on several properties.

### 5.2 “Truth” may not be unique, observable, or stable

Many software designs have several valid implementations; forecasts have delayed outcomes; research conclusions depend on incomplete evidence; preferences are owner-specific; web facts change. Reference labels may be conventional values rather than truth, and some tasks cannot be adjudicated cheaply at all. It is **very likely (80–90%) that a substantial open-ended task fraction lacks a low-uncertainty reference**, evidenced by the lack of a unique predeclared outcome in those task forms; quantify the fraction by double-adjudicating a random live-task sample.

**Consequence:** report “not calibrated” instead of inventing a number. Calibrate observable subclaims (citation entailment, tests, stated constraints, provenance) without claiming they exhaust answer quality.

### 5.3 The system is stochastic and condition-sensitive

An instrument’s response can vary with environment; an agent’s output can vary radically with prompt wording, retrieved context, tool failures, token pressure, conversation history, sampling, and user feedback. This is not a fatal disanalogy—metrology already models influence quantities—but the condition space is far larger and more combinatorial. It is **likely (55–80%) that practical stratification leaves important interactions unmodeled**, because finite reference samples cannot densely cover that space; settle it with held-out interaction tests and coverage checks.

**Consequence:** use broad intervals, explicit out-of-distribution flags, and a short validity horizon. Do not silently extrapolate.

### 5.4 Reference tasks can leak and agents can game the measurement

Physical check artifacts do not read the test protocol. Agents may memorize benchmarks, infer a canary, optimize evaluator quirks, or strategically alter self-reports. A static public benchmark is therefore a poor certified reference for live trust. Leakage-resistant rotation makes gaming harder but cannot make it impossible. It is **likely (55–80%) that repeated static canaries become distinguishable or contaminated over time**, based on agents’ access to repeated contextual patterns; settle it with canary-identification red teams and performance gaps between fresh and retired items.

**Consequence:** hide, rotate, and generate isomorphic variants; record exposure; test fresh temporal holdouts; treat suspicious performance jumps as a control signal, not instant improvement.

### 5.5 Calibration may change the object being calibrated

If calibration results alter routing, prompts, or agent behavior, the deployed task mix changes. Easy cases may be auto-accepted while hard cases are escalated, making subsequent observed outcome rates selection-biased. Physical calibration also changes workflows, but agent policies can create a sharper feedback loop. It is **likely (55–80%) that naive online updating becomes selection-biased**, because outcomes are preferentially observed for escalated or judgeable cases; settle it with randomized audit sampling among auto-accepted cases.

**Consequence:** maintain a small randomized outcome-audit stream and separate pre-policy calibration data from post-policy monitoring.

### 5.6 Uncertainty components are not safely independent

Reference ambiguity, evaluator weakness, model family, benchmark template, and task classification can share a cause. Adding them as independent variances can understate uncertainty. It is **very likely (80–90%) that important correlations exist**, because cases share templates and agents/evaluators often share model families; measure cluster correlations and effective sample size before combining terms.

**Consequence:** prefer resampling by task family/time block, hierarchical or robust intervals, and explicit dominant-unknown fields over a cosmetically precise GUM-style total.

### 5.7 Intercomparison cannot manufacture a reference

In metrology, a key comparison is anchored to a comparison reference value with uncertainty and supported by peer-reviewed capabilities. Agent majority vote often lacks that anchor. Ten correlated agents can agree and all be wrong. This disanalogy is decisive for “ensemble consensus = calibrated trust.” That equation is **almost certainly not (1–5%) defensible** absent an external outcome or validated independence model, because agreement supplies no estimate of common-mode bias.

**Consequence:** use intercomparison to diagnose and compare systems, not as a substitute for truth.

## 6. Minimal architecture and anti-overfit gate

The proposal rides existing task hooks, skills, or MCP boundaries. Its state can be three small versioned artifacts:

1. a reference/check-task manifest;
2. an append-only outcome/control record;
3. a calibration/decision-rule table read by a completion hook.

No second orchestration runtime is required. No vector database or knowledge graph is required. No durable-execution engine, trained critic, observability SaaS, or guardrail framework is required. No proposal above reintroduces a previously rejected component. The only executable addition is a small certificate lookup/emitter and a small check-chart updater; both are **BUILD-SMALL (<~200 lines, rides the existing hook/skill/MCP bus)**, while reference definitions and decision thresholds are **CONFIG (settings/JSON only)**.

This minimal design is **likely (55–80%) to preserve most of the benefit of the metrology borrow without creating an overfitted runtime**, because the mechanism is data and decision discipline at existing boundaries, not an alternative agent loop. That implementation judgment is **UNVERIFIED**; the §3.1 and §3.3 shadow experiments must include added latency, token cost, maintenance time, false alarms, and operator override rate. If the certificate path cannot stay under a predeclared overhead budget, retain only offline calibration reports and high-consequence guard bands.

Explicit non-proposals:

- Do not build a universal “trust daemon.” **NATIVE-vs-BUILD: BUILD-LARGE (new daemon/service/runtime — needs its own justification)** would be required, and the evidence here does not justify it.
- Do not train a critic to imitate the reference suite. That creates a new measuring system needing its own calibration and invites correlated error.
- Do not store semantic memory of all prior outputs in a vector database. Traceability needs exact provenance and versioned records, not approximate retrieval.
- Do not fan out every task to many agents. Periodic reference-anchored comparison is sufficient for this mechanism.
- Do not expose a global leaderboard. It encourages aggregation across incompatible measurands and conditions.

## 7. Experiment program and decision gates

### Phase A — Feasibility, no routing changes

Select five narrow task strata and 100 temporally separated cases per stratum. Predeclare the measurand and acceptance rule. Double-adjudicate every reference case; retain disagreement rather than forcing false certainty. Capture the complete system tuple and influence factors. Fit only simple empirical calibration tables with conservative intervals.

**Advance criterion:** at least three strata have repeatable adjudication, adequate effective sample size, and held-out interval coverage close to the declared level. “Close” must be numerically predeclared before observing results. It is **roughly even (45–55%) that three of five arbitrary initial strata clear this bar**, because narrow executable tasks are promising but task/evaluator dependence is unknown; Phase A settles it.

### Phase B — Shadow certificates and seeded drift

Emit certificates without changing routing. Seed prompt, tool, evaluator, and context regressions. Compare the certificate’s selective-risk curve to raw self-confidence and a simple task-stratum base rate. Measure check-chart detection delay and false alarms.

**Advance criterion:** the certificate has lower held-out error at equal coverage, or equal error at higher coverage, and detects seeded regressions within the predeclared delay/false-alarm budget. Improvement is **likely (55–80%) for at least one narrow stratum**, based on the additional condition/evidence information, but remains **UNVERIFIED** until this experiment.

### Phase C — Guard-banded routing with randomized audit

Pre-register consequence weights and route only one reversible task class initially. Randomly audit a fraction of auto-accepted outputs to prevent selection blindness. Compare realized false-accept cost, false-reject cost, latency, human-review volume, and override rate against the existing routing baseline.

**Adopt criterion:** lower total predeclared decision cost with no unacceptable increase in severe false acceptance. Adoption is **likely (55–80%) only for strata that passed Phases A and B**, because those phases establish reference fitness and calibration stability; no claim is made for open-ended tasks.

### Kill criteria

Stop rather than force the analogy if any of these persists after one redesign:

- independent adjudicators cannot agree enough to define the measurand;
- fresh-reference performance differs materially from check-task performance, consistent with leakage or non-commutability;
- intervals fail temporal coverage;
- check tasks generate unacceptable false alarms or fail seeded regressions;
- certificate routing does not beat a task-stratum base-rate policy;
- maintenance and evaluation cost exceeds prevented-error value;
- operators interpret cohort frequencies as guaranteed per-output truth despite interface controls.

## 8. Final judgment

**Does the metrology mechanism transfer? Partially, and only with a hard scope boundary.**

It transfers where the harness can define a task-specific outcome, maintain a fit-for-purpose reference, capture operating conditions, observe adjudicated cases, and monitor drift. In that domain, the combination of result-level traceability, uncertainty budgets, blind check standards, reference-anchored comparisons, and guard-banded decisions is **likely (55–80%) to yield better-calibrated trust decisions**, supported by the structural correspondence to BIPM/NIST measurement assurance and conditional on the prospective experiments above.

It does not transfer as a universal agent reputation, a single scalar truth meter, or a claim that consensus creates correctness. Those stronger versions are **almost certainly not (1–5%) defensible**, because they lack a stable measurand, specified condition, reference hierarchy, and independently supported comparison value—the very elements that make metrological calibration meaningful.

The most valuable borrow is cultural as much as statistical: never say “this agent is calibrated.” Say **which result-producing system, for which task property, under which conditions, against which reference, with what uncertainty, observed when, and under which decision rule**. Anything less is reputation wearing a lab coat.
