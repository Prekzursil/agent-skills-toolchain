## Learned / current hypotheses
- Strongest surviving desktop replay path: cold/surgical restore of `cursorAuth/*` plus coherent `state.vscdb`/WAL/SHM set.
- `storage.json` is falsified as the main auth anchor.
- Synthetic `WorkosCursorSessionToken=<user>::<session JWT>` survives for lightweight `cursor.com/api/*` reads, proven by saved probe results.
- Dashboard likely fails because lightweight web API reads accept the synthetic cookie while dashboard hydration needs a genuine WorkOS-backed web session or callback/bootstrap state not represented by the synthetic session-token cookie.
- The workbench auth service explicitly prioritizes local override/env override over persisted `cursorAuth/accessToken`, so any offline or test launch using `override-cursor-auth-token` can mask persisted-state conclusions.
- MCP OAuth callback plumbing in the installed app reinforces the broader pattern that real browser callback state matters for higher-level authenticated flows.
- Falsified/dead paths so far: `storage.json` replay as auth, backup API-key replay (404/null), assuming HexStrike can execute RE right now.
