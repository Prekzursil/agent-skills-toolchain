Constraints learned while landing QZP changes autonomously (see [[quality-zero-autofix-fleet-solution]]). Future QZP commits MUST satisfy these up front or the push is blocked:

- **`attempt_1` artifacts are UNTRACKED in the QZP working tree** (`scripts/quality/ratchet_gate.py`, `scripts/quality/autofix/verify_formatter_only.py`, `scripts/quality/autofix/run_safe_sweep.sh`, `config/autofix/safe-class-allowlist.yaml`) — they are NOT on `main`; `main` is green. To land an *isolated* QZP PR, move the untracked `.py` OUTSIDE the repo (e.g. `../qzp-attempt1-wip/`), push, then restore. (They each need their own PR with tests + contract compliance.)
- **Pre-push hook runs `scripts/verify`** (full suite, ~1546 tests) — must be GREEN to push. NEVER `--no-verify`.
- **Codacy-py2-compat contract** (`tests/test_quality_codacy_compatibility.py`, scans `scripts/` + `tests/`): FORBIDS builtin generics matching the regex for dict/list/set/tuple followed by a bracket → use `typing.Dict/List/Set/Tuple/FrozenSet` (note `frozenset[` is regex-safe but prefer `FrozenSet`); FORBIDS `from __future__ import annotations`; REQUIRES `from __future__ import absolute_import` in every non-empty `.py`. (ruff config ignores UP006/UP007/UP035/UP045 for the same reason.)
- **Sonar coverage-scope contract** (`tests/test_sonar_coverage_exclusions_contract.py`): any `.py` outside `tool.coverage.run.source` (only ~5 modules) MUST appear in the Sonar coverage-scope key in `sonar-project.properties`. So committing `ratchet_gate.py`/`verify_formatter_only.py` needs either tests + coverage-source inclusion OR a coverage-scope entry.
- **LOCAL pre-push ≠ CLOUD gates (CRITICAL).** `scripts/verify` (the pre-push hook) only runs the unittest suite + ruff/mypy — it does NOT run the cloud quality-zero gates. A QZP PR must ALSO pass: **Codacy Static Analysis, DeepSource:Python, qlty check, Coverage-100 Gate, Semgrep/Sentry/QLTY-Zero, the aggregate Quality Zero Gate.** New `.py` modules WILL fail Codacy (bandit B603 on `subprocess` → use `# nosec B603` like `ratchet_gate.py`; high complexity → refactor) and may fail Coverage-100 (the cloud coverage command differs from `coverage run -m unittest`). BEFORE pushing, reproduce locally: `mcp__qlty__qlty_check`, codacy-cli, and the coverage command in `reusable-scanner-matrix.yml`'s coverage lane. (PRs #239/#240/#241 were pushed verify-green but cloud-red; a fix Workflow is repairing them.) Push from a git **worktree** (`git worktree add` = clean of untracked attempt_1 files → no move-aside needed, and the pre-push suite is green).

**LESSONS (apply to all future QZP agent work):** (1) git-fixture tests MUST isolate — set `GIT_DIR`/`GIT_WORK_TREE` to the tmp dir or clear `GIT_*` env; never inherit ambient. (3) Do NOT run git-fixture-heavy test suites in parallel worktrees of the real repo sharing one `.git` (cross-contamination). Prefer: fix+verify in isolation, stage named files, push once. (4) Always create a `backup/<pr>-fix-<sha>` branch at each verified fix before risky pushes.
